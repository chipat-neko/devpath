Module 01 · Les fondations de Node — Leçon 01

Découvrir Node.js

~26 min Intermédiaire Cours JavaScript recommandé

À la fin de cette leçon, tu sauras

  • Savoir expliquer ce qu'est Node.js — un environnement d'exécution JavaScript bâti sur le moteur V8 — et à quoi il sert ;
  • Savoir installer Node (LTS via nodejs.org ou nvm) et vérifier sa version avec node --version ;
  • Savoir exécuter du JavaScript dans le REPL et lancer un fichier avec node script.js ;
  • Savoir distinguer les globals Node (process, __dirname) du navigateur et lire les arguments via process.argv.
Sommaire de la leçon

Tu écris du JavaScript depuis un moment, mais toujours dans un navigateur : une balise <script>, la console des outils de développement, le document et le DOM. Node.js change la donne : il te permet d'exécuter exactement le même langage en dehors du navigateur — dans un terminal, sur ta machine ou sur un serveur. C'est ce qui transforme JavaScript d'un langage « de page web » en un langage à tout faire : serveurs, API, outils en ligne de commande, scripts d'automatisation.

Cette première leçon pose les fondations : comprendre ce qu'est ce runtime, l'installer correctement, et lancer ton tout premier programme JavaScript côté serveur. Tu connais déjà le langage ; ici, tu découvres l'environnement qui l'exécute.

Qu'est-ce que Node.js ?

Node.js n'est pas un langage ni un framework : c'est un environnement d'exécution (un runtime). Concrètement, il embarque V8, le moteur JavaScript ultra-rapide écrit par Google pour Chrome, et l'entoure de tout ce dont un programme a besoin hors du navigateur : accès aux fichiers, au réseau, aux processus du système d'exploitation.

Dans Chrome, V8 lit ton code et l'exécute, mais le navigateur lui donne accès au DOM et à window. Dans Node, c'est le même V8 — mais entouré d'API système à la place. Le langage est identique ; l'environnement, lui, est complètement différent.

L'option -p évalue une expression et imprime son résultat : ici, la version du moteur V8 que Node utilise sous le capot.

À quoi ça sert ?

Parce qu'il donne à JavaScript l'accès au système, Node ouvre trois grands usages que le navigateur interdit :

  • Serveurs web et API : répondre à des requêtes HTTP, servir des pages, exposer une API JSON. C'est l'usage historique de Node.
  • Outils en ligne de commande : la plupart des outils du front (bundlers, linters, npm lui-même) sont des programmes Node.
  • Scripts d'automatisation : renommer des fichiers en masse, appeler une API distante, générer un rapport — tout ce que tu ferais en Bash ou Python, mais en JavaScript.

Autrement dit, dès que tu veux faire tourner du JavaScript ailleurs que dans une page, Node est la réponse par défaut.

Cas réel

Tu utilises déjà Node sans le savoir. Quand tu lances npm install, npm run build, un serveur de développement Vite, ESLint ou Prettier : à chaque fois, c'est un programme Node qui s'exécute dans ton terminal. Tout l'outillage moderne du front — même pour des projets qui finiront dans un navigateur — est écrit en JavaScript et tourne sur Node. Apprendre Node, c'est donc aussi comprendre la machinerie qui fait fonctionner ton quotidien de développeur web.

Installer Node

La méthode la plus simple est de télécharger l'installeur depuis nodejs.org. Tu y trouveras deux lignes :

  • LTS (Long Term Support) : la version stable, recommandée pour la plupart des projets. Choisis celle-ci.
  • Current : la dernière version, avec les nouveautés les plus fraîches, mais moins éprouvée.

Pour un travail sérieux, tu auras vite besoin de jongler entre plusieurs versions de Node (un vieux projet sur l'une, un nouveau sur l'autre). C'est le rôle de nvm (Node Version Manager), à installer plutôt que l'installeur global.

node --version (ou node -v) est la première commande à lancer : si elle répond un numéro, Node est correctement installé.

Note

Les versions LTS portent un numéro pair (18, 20, 22…). Les versions Current ont un numéro impair. Pour suivre cette leçon, n'importe quelle LTS récente (Node ≥ 18) suffit : elle inclut fetch en global, le préfixe node: et le lanceur de tests node:test.

Le REPL : expérimenter en direct

Tape node seul, sans nom de fichier, et tu entres dans le REPL (Read–Eval–Print Loop) : une console interactive qui lit chaque ligne, l'évalue et affiche le résultat. C'est l'équivalent de la console du navigateur, mais côté serveur — parfait pour tester une idée vite fait.

Dans le REPL, le résultat de chaque expression s'affiche automatiquement ; une déclaration comme const renvoie undefined. Tape .exit ou Ctrl+D pour sortir.

Astuce — trois raccourcis qui font gagner du temps

Pour évaluer une expression sans ouvrir le REPL, utilise node -p "expr" (print : affiche le résultat) ou node -e "code" (execute : exécute sans afficher). Et pendant que tu développes un fichier, lance-le avec node --watch script.js : Node le relance automatiquement à chaque sauvegarde, comme un rechargement à chaud côté serveur.

Les différences avec le navigateur

Le langage est identique, mais l'environnement ne l'est pas. Le réflexe à perdre : dans Node, il n'y a ni document, ni window, ni DOM, ni alert. Ces objets appartiennent au navigateur, pas au langage. Les chercher dans Node lève une erreur.

En face du DOM, Node offre des globals comme process (le processus en cours), __dirname (le chemin du fichier) et Buffer (les données binaires brutes).

Pour interagir avec le système, Node expose des modules intégrés que tu importes par leur nom préfixé de node: — par exemple fs (système de fichiers) et http (serveur web). On les explorera en détail dès la leçon suivante.

Le préfixe node: désigne sans ambiguïté un module intégré. Ici, fs/promises donne la version promesse de l'API fichiers, qu'on utilise avec await.

Note

Node connaît deux systèmes de modules : CommonJS (l'historique, avec require() et module.exports) et ES Modules (le standard, avec import/export). On y revient à la leçon 2 ; retiens pour l'instant que __dirname existe d'office en CommonJS, et que l'import est la syntaxe moderne. La distinction sera précisée à chaque exemple.

Lire les arguments avec process.argv

Un script utile a souvent besoin de recevoir des données d'entrée depuis la ligne de commande. Node les range dans le tableau process.argv. Attention : les deux premiers éléments sont toujours le chemin de l'exécutable Node et le chemin du script ; tes véritables arguments commencent à l'indice 2.

process.argv.slice(2) est l'idiome standard pour récupérer uniquement les arguments fournis par l'utilisateur.

Pièges fréquents

Piège fréquent

Croire que le code du navigateur tourne dans Node. Toucher au DOM (document.querySelector), à window ou à localStorage lève une ReferenceError : ces objets n'existent pas côté serveur. Node parle au système (fichiers, réseau, processus), pas à une page.

Trois autres confusions classiques :

  • Node n'est pas un framework. C'est le runtime. Express, Next.js ou Fastify sont des frameworks qui tournent sur Node — ne confonds pas la fondation et ce qu'on bâtit dessus.
  • Une version trop ancienne. Beaucoup de tutoriels supposent fetch global, node:test ou le await de haut niveau ; tout cela exige Node ≥ 18. Vérifie toujours node --version avant de déboguer un « fetch is not defined ».
  • Oublier que le JavaScript de Node est mono-thread. Comme dans le navigateur, ton code s'exécute sur un seul fil. Un calcul lourd et synchrone bloque tout le programme : d'où l'importance de l'asynchrone, qu'on travaillera bientôt.

Pour aller plus loin

Pour aller plus loin

Glossaire

Runtime (environnement d'exécution)
Programme qui exécute ton code et lui donne accès à des API ; Node est le runtime de JavaScript hors du navigateur.
V8
Moteur JavaScript de Google (celui de Chrome) qui compile et exécute le code ; c'est le cœur de Node.
REPL
Read–Eval–Print Loop : la console interactive ouverte par node seul, qui lit, évalue et affiche chaque expression.
LTS
Long Term Support : version stable de Node (numéro pair) maintenue longtemps ; à préférer pour la plupart des projets.
nvm
Node Version Manager : outil pour installer plusieurs versions de Node et basculer de l'une à l'autre.
global
Variable disponible partout sans import ; côté Node, process, __dirname et Buffer remplacent window/document.
process.argv
Tableau des arguments de la ligne de commande ; ses deux premiers éléments sont l'exécutable et le script.
Module intégré
Module fourni d'office par Node (fs, http, path…), importé via le préfixe node:.

Récap et vérification

  • Node.js est un environnement d'exécution JavaScript bâti sur le moteur V8, pour le serveur et les outils — ni langage, ni framework.
  • On installe la version LTS (numéro pair) depuis nodejs.org ou via nvm ; on vérifie avec node --version.
  • node seul ouvre le REPL interactif ; node fichier.js exécute un script.
  • Pas de document/window/DOM : à la place, des modules node: (fs, http) et des globals (process, __dirname, Buffer).
  • process.argv.slice(2) récupère les arguments de la ligne de commande.
