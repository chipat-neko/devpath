Promesses et async/await

~32 min Intermédiaire Leçon 04 recommandée

À la fin de cette leçon, tu sauras

  • savoir utiliser les API Node en version promesse (node:fs/promises) avec async/await et try/catch ;
  • savoir lancer des tâches en parallèle avec Promise.all, allSettled et race, et corriger le piège de l'await dans une boucle ;
  • savoir appeler une API HTTP avec fetch global (Node ≥ 18) et traiter les codes d'erreur ;
  • savoir gérer les erreurs asynchrones et éviter les rejets non gérés (unhandledRejection).
Sommaire de la leçon

Tu connais déjà les Promise, async/await et les promesses côté navigateur. Bonne nouvelle : en Node moderne, c'est exactement le même langage. La différence, c'est l'écosystème : les modules intégrés exposent désormais une version promesse de leurs API (fini les callbacks à imbriquer), fetch est disponible globalement, et le runtime te prévient brutalement quand une promesse rejette dans le vide. Cette leçon te montre comment écrire de l'asynchrone Node lisible et efficace.

On part des Promesses appliquées à Node, on enchaîne sur async/await, on attaque le vrai sujet — le parallélisme et son piège n°1, l'await dans une boucle — puis fetch, la gestion d'erreurs, et le réflexe « API promesse plutôt que callback ».

Les Promesses, version Node

Une Promise représente une valeur future : elle finira résolue (succès) ou rejetée (échec). En Node, beaucoup de modules intégrés offrent un sous-module /promises. Le plus emblématique : node:fs/promises, où chaque fonction renvoie une promesse au lieu de prendre un callback en dernier argument.

Le .catch attrape l'erreur de n'importe quel maillon de la chaîne, y compris un JSON.parse qui échoue.

Note

En CommonJS, importe-le ainsi : const { readFile } = require("node:fs/promises");. Le préfixe node: est explicite et recommandé : il garantit que tu charges le module intégré, jamais un paquet npm du même nom installé par erreur.

async / await : du séquentiel lisible

Le chaînage then reste vite illisible. async/await aplatit tout : tu écris du code qui se lit de haut en bas, et tu attrapes les erreurs avec un try/catch classique. Une fonction async renvoie toujours une promesse ; await suspend jusqu'à sa résolution.

Trois étapes async lues comme du code synchrone, un seul try/catch pour les couvrir.

Note

L'await au niveau supérieur (top-level await) marche directement dans un module ES (fichier .mjs ou projet avec "type": "module"). En CommonJS, tu dois envelopper ton await dans une fonction async que tu appelles ensuite.

Le parallélisme : Promise.all

Voici le point qui sépare un code lent d'un code rapide. Trois lectures de fichiers indépendantes ne devraient pas s'attendre l'une l'autre. Promise.all lance tout en parallèle et attend que l'ensemble soit prêt — la durée totale devient celle de la tâche la plus longue, pas la somme.

Promise.all renvoie un tableau de résultats dans l'ordre des promesses — mais rejette dès la première erreur.

Si tu veux le résultat de chaque tâche même si certaines échouent, utilise Promise.allSettled : il ne rejette jamais, et te rend un tableau d'objets { status, value } ou { status, reason }.

allSettled = « dis-moi ce qui a marché ET ce qui a raté ». Promise.race, lui, se résout (ou rejette) avec la première promesse à terminer — pratique pour un timeout.

Le piège : await dans une boucle

C'est l'erreur de débutant Node la plus coûteuse. Écrire await à l'intérieur d'un for rend tes tâches indépendantes séquentielles : chaque itération attend la précédente, alors qu'elles pourraient courir ensemble.

Le map démarre toutes les promesses immédiatement ; Promise.all les rassemble. Garde la boucle séquentielle uniquement quand une étape dépend du résultat de la précédente.

fetch est global (Node ≥ 18)

Plus besoin d'installer node-fetch ni d'utiliser le vieux module http pour un simple appel : depuis Node 18, fetch est disponible globalement, avec la même API que dans le navigateur.

Le piège classique de fetch : la promesse ne rejette que sur un échec réseau. Un statut 4xx/5xx est une réponse « réussie » côté fetch — d'où le test reponse.ok.

Gérer les erreurs asynchrones

Avec async/await, la règle est simple : toute opération qui peut rejeter va dans un try/catch. Le danger, ce sont les promesses dont personne n'attend ni n'attrape le résultat : leur rejet devient un unhandledRejection, et Node finit le processus avec un code d'erreur non nul.

Toujours await une promesse ou lui attacher un .catch. Pour un filet de sécurité global, écoute l'événement processus.

Ce filet est un garde-fou de diagnostic, pas une excuse pour oublier tes try/catch.

Préférer l'API promesse à l'API callback

Les modules Node historiques utilisent le style error-first callback : fn(args, (err, resultat) => …). Il fonctionne, mais il imbrique, complique la gestion d'erreurs et empêche await. Dès qu'une version promesse existe (node:fs/promises, node:dns/promises, node:timers/promises…), choisis-la.

Pour une API callback sans variante promesse, enveloppe-la avec util.promisify plutôt que de mélanger les deux styles.

Cas réel : un tableau de bord six fois plus rapide

Cas réel

Un tableau de bord agrège six widgets, chacun alimenté par un appel HTTP indépendant. Première version : une boucle for … of avec await à l'intérieur. Chaque appel prenant ~250 ms, la page s'affiche en… 1,5 s (6 × 250). En remplaçant la boucle par await Promise.all(widgets.map(charger)), les six requêtes partent ensemble et le tableau se peint en ~250 ms — six fois plus vite, sans toucher à la logique métier. La leçon inverse existe aussi : lancer 500 requêtes d'un coup avec Promise.all peut noyer l'API distante ; on borne alors la concurrence (par lots, ou avec un limiteur type p-limit). Parallélise ce qui est indépendant, mais garde la main sur le nombre.

Pièges fréquents

Piège fréquent

await dans une boucle pour des tâches indépendantes : tu sérialises sans le vouloir et multiplies le temps total. Mappe vers des promesses et passe-les à Promise.all. Réserve la boucle séquentielle aux cas où chaque étape dépend de la précédente.

Piège fréquent

Oublier le try/catch (ou le .catch) provoque un unhandledRejection qui tue le processus. Oublier le mot await devant une promesse te donne un objet Promise au lieu de la valeur — et un rejet silencieux. Enfin, ne mélange pas callbacks et promesses sur la même opération.

Pour aller plus loin

Pour aller plus loin

Quand tu consommes un flux de données async, for await…of itère sur un itérable asynchrone (chaque tour attend la valeur suivante) — utile pour les Streams, qu'on verra en leçon 7. Si tu lances des centaines de tâches en parallèle, ne déclenche pas tout d'un coup : un limiteur de concurrence comme p-limit borne le nombre de promesses simultanées. Et pour annuler une opération en cours (fetch trop long), garde AbortController en tête.

Glossaire

Promise
Objet représentant une valeur future : elle finit résolue (succès) ou rejetée (échec).
async / await
async fait qu'une fonction renvoie toujours une promesse ; await suspend jusqu'à sa résolution, rendant l'asynchrone lisible de haut en bas.
Promise.all
Lance plusieurs promesses en parallèle et attend tout ; rejette dès le premier échec (et perd alors les autres résultats).
Promise.allSettled
Attend toutes les promesses sans jamais rejeter ; renvoie pour chacune son status et sa value ou sa reason.
Promise.race
Se résout (ou rejette) avec la première promesse à terminer ; pratique pour imposer un délai maximal (timeout).
fetch
API HTTP disponible globalement depuis Node 18 ; elle ne rejette que sur panne réseau — un statut 4xx/5xx se détecte via reponse.ok.
unhandledRejection
Rejet de promesse que personne n'attrape ; Node émet un avertissement et peut terminer le processus. On await ou on attache un .catch.

Récap et vérification

  • Les modules intégrés ont une version promesse (node:fs/promises) : préfère-la au style callback.
  • async/await + try/catch rendent l'asynchrone linéaire et lisible ; une fonction async renvoie toujours une promesse.
  • Promise.all lance tout en parallèle (rejette à la première erreur) ; allSettled rapporte succès et échecs ; race prend le premier arrivé.
  • L'await dans une boucle sérialise des tâches indépendantes : mappe vers Promise.all.
  • fetch est global (Node ≥ 18) mais ne rejette pas sur un statut 4xx/5xx : teste reponse.ok.
  • Toujours await ou .catch une promesse, sinon unhandledRejection termine le processus.
