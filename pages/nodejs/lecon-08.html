Le système de fichiers

~33 min Intermédiaire Module 2 recommandé

À la fin de cette leçon, tu sauras

  • savoir lire, écrire et ajouter du contenu à un fichier avec node:fs/promises en gérant l'encodage ;
  • savoir créer, lister, renommer et supprimer des dossiers, et inspecter les métadonnées d'un fichier ;
  • savoir construire des chemins portables avec node:path et viser le dossier du script via import.meta.url ;
  • savoir lire et écrire un fichier JSON de configuration.
Sommaire de la leçon

Jusqu'ici, tes scripts Node tournaient en vase clos. Pour qu'ils deviennent utiles, il leur faut un point de contact avec le monde extérieur : le système de fichiers. Lire un fichier de configuration, écrire un journal, parcourir un dossier d'images, sauvegarder un état entre deux exécutions — tout cela passe par le module intégré fs.

Dans cette leçon, tu vas apprendre à lire et écrire des fichiers, à manipuler des dossiers, à inspecter des métadonnées, et surtout à construire des chemins qui fonctionnent aussi bien sur Windows que sur macOS ou Linux. On travaille en async/await, avec la version moderne et promise du module.

Le module fs, en version promesse

Node expose le système de fichiers via le module intégré fs. Il en existe trois variantes : les callbacks (l'ancienne API), les versions synchrones bloquantes (suffixe Sync), et les versions qui renvoient des promesses. Tu connais déjà async/await : privilégie donc node:fs/promises, qui s'intègre naturellement à ton code asynchrone.

Toutes les fonctions de ce sous-module renvoient une promesse : tu les attends avec await.

Note

En ESM, on importe depuis 'node:fs/promises'. En CommonJS, tu peux aussi écrire const { readFile } = require('node:fs').promises;. Les deux pointent vers la même API. Les exemples qui suivent sont en ESM (avec await au niveau supérieur du module, autorisé en ESM) ; en CJS, place ton code dans une fonction async.

Lire, écrire, ajouter

Trois fonctions couvrent l'essentiel. readFile lit un fichier entier ; writeFile l'écrit (en écrasant le contenu existant) ; appendFile ajoute à la fin. Point crucial pour la lecture : précise l'encodage, sinon tu récupères un Buffer (des octets bruts) au lieu d'une chaîne de caractères.

Un Buffer est utile pour des fichiers binaires (image, archive). Pour du texte, demande toujours 'utf-8'.

Manipuler les dossiers

Côté répertoires : mkdir crée un dossier, readdir liste son contenu, rename renomme ou déplace, rm supprime. L'option recursive: true est ton amie : pour mkdir, elle crée toute l'arborescence manquante sans erreur si le dossier existe déjà ; pour rm, elle supprime un dossier et tout ce qu'il contient.

readdir accepte aussi { withFileTypes: true } pour obtenir des objets Dirent et tester directement entry.isDirectory().

Les métadonnées : stat et access

Pour connaître la taille d'un fichier, ses dates ou savoir si c'est un dossier, utilise stat. Il renvoie un objet riche : size (octets), mtime (dernière modification), et les méthodes isFile() / isDirectory().

Des chemins portables avec node:path

Ne concatène jamais des chemins à la main avec '/' : le séparateur diffère selon l'OS (\ sur Windows) et tu risques les doubles barres. Le module node:path fait ce travail correctement.

join assemble des bouts relatifs ; resolve ancre le tout en chemin absolu. basename, extname et dirname décomposent un chemin existant.

Cibler le dossier du script, pas le CWD

Quand tu écris fs.readFile('config.json'), Node cherche le fichier relativement au répertoire courant (le cwd : l'endroit d'où tu lances node), pas relativement à ton fichier .js. Lance le même script depuis un autre dossier, et le chemin casse. Pour viser un fichier situé à côté du script, ancre-toi sur l'emplacement du script.

En CommonJS, la variable __dirname donne le dossier du module. En ESM, elle n'existe pas : on la reconstruit depuis import.meta.url.

Astuce

Sur Node récent (≥ 21.2), tu peux écrire directement import.meta.dirname (et import.meta.filename) sans passer par fileURLToPath. Plus court, même résultat — on l'utilise dans la section suivante.

Cas réel — un outil en ligne de commande

Quand tu lances prettier ou eslint dans ton projet, l'outil jongle avec deux origines de chemins. Ses propres ressources (règles, gabarits) vivent à côté de son code, dans node_modules : il les vise avec l'équivalent de import.meta.dirname. Mais ta configuration (.prettierrc) et tes fichiers à formater vivent dans ton dossier de travail : il les cherche à partir du CWD (process.cwd()). Confondre les deux, et l'outil irait chercher ta config au milieu de son propre code — introuvable. Distinguer « relatif au script » et « relatif au projet » n'est pas une subtilité d'école : c'est ce qui fait qu'un outil installé une fois fonctionne dans n'importe quel dossier.

Lire et écrire un JSON de configuration

Cas très courant : charger une configuration depuis un fichier .json. fs ne connaît que le texte : c'est à toi de convertir avec JSON.parse (lecture) et JSON.stringify (écriture). Le troisième argument de stringify indente joliment le résultat.

On distingue « fichier absent » (on repart d'un objet vide) d'une vraie erreur de parsing, qu'on laisse remonter. Sur un Node antérieur à 21.2, remplace import.meta.dirname par path.dirname(fileURLToPath(import.meta.url)).

Pièges fréquents

Piège fréquent

Concaténer des chemins à la main : 'data' + '/' + nom passe encore sous Windows (vérifié : data//a.txt se lit sans erreur), mais donne des chemins bâtards qu'aucun outil ne normalise, et casse dès qu'un segment contient déjà un séparateur ou un ... Passe toujours par path.join(...), qui nettoie et choisit le bon séparateur.

Piège fréquent

Oublier l'encodage : await fs.readFile('x.txt') renvoie un Buffer, pas une chaîne. Tu obtiens <Buffer ...> au lieu de ton texte. Ajoute 'utf-8'.

Piège fréquent

Confondre chemin relatif au CWD et au script. 'config.json' dépend d'où tu lances node ; path.join(import.meta.dirname, 'config.json') vise toujours le bon fichier.

Piège fréquent

Utiliser les versions Sync (readFileSync…) par réflexe : elles bloquent tout l'événementiel pendant l'opération. Réserve-les aux scripts d'amorçage ; ailleurs, reste sur fs/promises et await.

Pour aller plus loin

Pour les gros fichiers, ne charge pas tout en mémoire : utilise les streams (revois la leçon 7). Explore aussi fs.watch pour réagir aux modifications, la gestion fine des permissions (chmod, modes de access), et le globbing pour filtrer des chemins par motif.

Glossaire

node:fs/promises
Variante du module système de fichiers dont les fonctions renvoient des promesses ; s'utilise avec await, contrairement aux versions à callbacks ou synchrones (Sync).
Buffer
Séquence d'octets bruts. Sans encodage précisé, readFile en renvoie un ; on obtient du texte en demandant 'utf-8' ou via .toString('utf-8').
Encodage
Convention qui relie octets et caractères (utf-8 le plus courant). En UTF-8, un é occupe deux octets : la taille en octets diffère de la longueur en caractères.
CWD (répertoire courant)
Dossier d'où l'on lance node (process.cwd()). Un chemin relatif nu comme 'config.json' s'y rattache ; il change donc selon l'endroit de lancement.
import.meta.dirname
Dossier du script en cours (ESM, Node ≥ 21.2) ; équivalent de __dirname en CommonJS. Sert à viser un fichier voisin du code, indépendamment du CWD.
ENOENT
Code d'erreur « Error NO ENTry » : le fichier ou dossier visé n'existe pas. On le teste via err.code === 'ENOENT' dans un catch.
stat (métadonnées)
Informations sur un fichier sans lire son contenu : taille (size), date de modification (mtime), type (isFile()/isDirectory()).
path.join vs path.resolve
join assemble des segments avec le bon séparateur ; resolve fait de même mais renvoie un chemin absolu, ancré sur le CWD.

Récap et vérification

  • Privilégie node:fs/promises avec async/await ; évite les versions Sync bloquantes.
  • readFile/writeFile/appendFile pour les fichiers ; précise 'utf-8' pour obtenir du texte.
  • mkdir (avec recursive), readdir, rename, rm pour les dossiers.
  • stat donne taille/dates/type ; access teste l'accessibilité.
  • node:path (join, resolve, basename, extname, dirname) pour des chemins portables.
  • import.meta.dirname (ou __dirname en CJS) pour cibler le dossier du script.
  • Pour le JSON : JSON.parse à la lecture, JSON.stringify(obj, null, 2) à l'écriture.

Vérifie ta compréhension

  2. Pourquoi path.join('a', 'b') est-il préférable à 'a' + '/' + 'b' ?
  3. Quelle différence entre lire 'config.json' et lire path.join(import.meta.dirname, 'config.json') ?
