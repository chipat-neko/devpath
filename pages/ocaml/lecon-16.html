Collections immuables : Map et Set

~55 min Avancé Prérequis : leçon 08

À la fin de cette leçon, tu sauras

  • créer un dictionnaire avec Map.Make et un ensemble avec Set.Make ;
  • comprendre l'immuabilité et la persistance de ces structures ;
  • employer find_opt, add, fold, union, inter ;
  • choisir entre Map et Hashtbl.
Sommaire de la leçon

Les listes sont parfaites pour parcourir, mais chercher un élément par sa clé y coûte cher (parcours linéaire). Pour associer des clés à des valeurs, ou manipuler des ensembles, OCaml offre deux structures élégantes : Map et Set. Leur particularité : elles sont immuables et persistantes, dans le plus pur esprit fonctionnel. Ajouter un élément ne modifie rien : cela fabrique une nouvelle collection.

Immuable et persistant

Voici le point qui déroute quand on vient de Python ou JavaScript : StringMap.add ne modifie pas l'annuaire — il en renvoie un nouveau. L'ancien reste intact et parfaitement utilisable. On dit que la structure est persistante : toutes ses versions coexistent.

Astuce — toujours find_opt, pas find

StringMap.find lève l'exception Not_found si la clé manque. Préfère find_opt, qui renvoie une option (Some v ou None) : le compilateur t'oblige alors à traiter le cas absent, dans le droit fil de la culture « pas de null » d'OCaml (leçon 06).

Les ensembles : Set

Set suit exactement le même patron par foncteur, pour des collections sans doublon et sans valeur associée. Sa force : les opérations ensemblistes mathématiques.

Cas réel — compter les mots d'un texte

L'exemple d'école de la Map : le comptage de fréquences. On parcourt les mots et, pour chacun, on incrémente son compteur dans la map — find_opt pour lire l'ancien total, add pour écrire le nouveau. En quelques lignes immuables, on obtient un histogramme fiable, sans état partagé ni surprise. Les Set, eux, brillent pour la déduplication et les relations : « quels utilisateurs sont dans le groupe A et le groupe B » ? Une simple inter. C'est ce genre de code, court et sûr, qui fait dire aux équipes OCaml (dont beaucoup à Jane Street) que les structures immuables simplifient le raisonnement plutôt que de le compliquer.

Attention — Map ou Hashtbl ?

OCaml a aussi Hashtbl, une table de hachage mutable (modifiée en place, accès moyen O(1)). Règle simple : Map quand tu veux l'immuabilité, la persistance (garder d'anciennes versions), un parcours ordonné par clé, ou partager sans risque entre threads ; Hashtbl quand tu as un cache local très sollicité, sans besoin de versions ni d'ordre. En cas de doute, commence par Map : le raisonnement est plus simple, et on n'optimise que si un profil le réclame.

Antisèche — Map et Set

Glossaire

Map
Dictionnaire immuable associant des clés à des valeurs, créé par Map.Make.
Set
Ensemble immuable d'éléments sans doublon, créé par Set.Make.
Foncteur
Module paramétré ; Map.Make(K) fabrique un dictionnaire pour le type de clé K.
Immuable
Qui ne se modifie pas : une opération d'ajout renvoie une nouvelle collection.
Persistant
Propriété d'une structure dont toutes les versions successives restent disponibles.
Partage de structure
Réutilisation des parties communes entre deux versions, pour un coût mémoire faible.
find_opt
Recherche renvoyant une option (pas d'exception si la clé manque).
Hashtbl
Table de hachage mutable : rapide, mais sans persistance ni ordre.

Récap et vérification

  • Map et Set se créent par foncteur (Map.Make, Set.Make), qui exige un compare sur les clés.
  • Ce sont des structures immuables et persistantes : add renvoie une nouvelle collection, l'ancienne survit.
  • On lit avec find_opt (une option), on agrège avec fold ; Set ajoute union/inter/diff.
  • Map pour l'immuabilité et l'ordre ; Hashtbl pour un cache mutable rapide.

Exercices

Exercice 1Échauffement

Crée un module StringMap, construis une map associant "un" → 1 et "deux" → 2, puis affiche la valeur de "deux" et celle de "trois" (absente) sans provoquer d'exception.

Voir une solution

find_opt renvoie une option : le pattern matching Some/None gère les deux cas sans jamais lever d'exception. "deux" affiche 2, "trois" affiche « absent ».

Exercice 2Application

Écris une fonction frequences : string list -> int StringMap.t qui compte les occurrences de chaque mot, puis affiche le résultat.

Voir une solution

On replie la liste des mots (List.fold_left) : pour chaque mot, on lit son compteur actuel avec find_opt (0 s'il est absent, via le cas None), et on écrit le nouveau total avec add. Comme la map est ordonnée par clé, l'itération finale sort les mots triés — un bonus gratuit par rapport à une Hashtbl.

Exercice 3Défi

Deux listes d'identifiants représentent les inscrits à deux ateliers. Avec des Set, calcule : (a) ceux inscrits aux deux, (b) ceux inscrits à au moins un, (c) ceux du premier seulement. Explique pourquoi les Set conviennent mieux qu'une liste.

Voir une solution

Pourquoi les Set : les trois questions sont exactement les opérations intersection, union et différence de la théorie des ensembles — une fonction chacune, lisible et correcte du premier coup. Avec des listes, il faudrait écrire à la main des boucles avec List.mem (coûteux : O(n) par test, O(n²) au total), gérer les doublons soi-même et perdre le tri. Le Set déduplique automatiquement, reste ordonné, et offre ces opérations en O(n log n). Quand le problème parle d'ensembles, on utilise des ensembles : le code épouse alors le vocabulaire du domaine.
