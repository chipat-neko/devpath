Module 2 · Le système de types — Leçon 06

Records, options et erreurs

~50 min Avancé Prérequis : leçon 5

À la fin de cette leçon, tu sauras

  • définir et utiliser des records ;
  • remplacer null par le type option (Some/None) ;
  • gérer les erreurs avec le type result ;
  • comprendre quand utiliser les exceptions.
Sommaire de la leçon

Pour des données aux champs nommés, OCaml a les records. Et pour la sûreté, deux types fondamentaux remplacent les sources d'erreurs classiques : option bannit le null, result gère les erreurs sans exception cachée. Ensemble, ils éliminent une grande part des plantages habituels.

Les records

Un record regroupe des champs nommés et typés. On le définit avec des accolades, et on accède aux champs avec un point.

Mise à jour fonctionnelle

Un record est immuable. Pour en obtenir une version modifiée, on utilise la syntaxe with : elle crée un nouveau record en copiant l'ancien et en changeant certains champs.

Déstructurer un record

On n'est pas obligé de lire les champs un par un avec le point : un motif déstructure un record d'un coup, dans un let ou un match. Et quand la variable porte le nom du champ, on abrège { nom = nom; age = age } en { nom; age } — c'est le « field punning ».

Astuce

Le punning marche aussi à la construction : si tu as déjà des variables nom et age, écris simplement { nom; age } pour bâtir le record, sans répéter nom = nom. Le code reste court et les noms restent alignés sur ceux du type.

Le type option : en finir avec null

Comment représenter « une valeur peut être absente » ? Pas avec null (source de plantages partout), mais avec le type option : soit Some valeur, soit None. Le type oblige à traiter le cas « absent ».

Manipuler une option

On déballe une option par filtrage, ou avec les fonctions du module Option.

Le type result : gérer les erreurs

Pour une opération qui peut échouer avec une raison, le type result : Ok valeur en cas de succès, Error raison en cas d'échec. L'erreur fait partie du type de retour : impossible de l'ignorer.

Les exceptions, avec parcimonie

OCaml a aussi des exceptions (raise, try ... with), mais l'usage idiomatique les réserve aux cas vraiment exceptionnels (erreurs de programmation). Pour les erreurs attendues, on préfère option ou result, visibles dans les types.

Pièges fréquents

Piège fréquent

Vouloir « sortir » la valeur d'une option sans traiter le None : c'est précisément ce qu'OCaml empêche. Tu dois gérer les deux cas (par match ou Option.value). Cette contrainte est une force : pas de plantage « valeur nulle » possible.

Piège fréquent

Les fonctions qui extraient « sans filet » — Option.get, List.hd, Hashtbl.find — lèvent une exception si l'option est None ou la liste vide : elles court-circuitent la garantie du type. Préfère un match, Option.value ~default, ou les variantes _opt (List.nth_opt, Hashtbl.find_opt) qui renvoient une option.

Pour aller plus loin

Pour aller plus loin

Pour enchaîner plusieurs opérations faillibles sans pyramide de match, on utilise les opérateurs de liaison (let*) ou Option.bind/Result.bind. C'est l'équivalent OCaml du ? de Rust : court-circuiter proprement à la première absence ou erreur.

Cas réel : le pari « zéro null » de Jane Street

Cas réel

Jane Street, société de trading, a bâti la quasi-totalité de son infrastructure sur OCaml. La raison ? En pleine séance de marché, un plantage « valeur nulle » coûte cher. En rendant l'absence visible dans le type (option), le compilateur refuse le code qui oublie le cas None : une classe entière de bugs disparaît. C'est le fameux « billion-dollar mistake » que Tony Hoare, inventeur du null, regrettait publiquement. La même idée a été reprise par Rust (Option), Swift (Optional) et Kotlin (types ?).

Glossaire

Record
Structure de données à champs nommés et typés, définie avec des accolades : { nom : string; age : int }. On lit un champ avec un point (ada.nom).
Immuabilité
Une valeur ne se modifie pas sur place : toute « modification » produit une nouvelle valeur, l'ancienne restant intacte.
Mise à jour fonctionnelle (with)
Syntaxe { r with champ = v } qui recopie un record en changeant certains champs, sans toucher à l'original.
option
Type Some v | None modélisant une valeur éventuellement absente, en remplacement de null. Le filtrage force à traiter l'absence.
result
Type Ok v | Error e rendant l'échec explicite dans le type de retour : l'appelant doit le gérer.
Exception
Mécanisme raise / try … with réservé aux cas vraiment exceptionnels ; pour les erreurs attendues, on préfère option ou result.
Type abstrait / null-safety
Absence de null garantie par le type : aucune valeur ne peut être « nulle » à l'insu du programme, éliminant les déréférencements nuls.
Déstructuration de record
Motif qui extrait les champs d'un record en une fois : let { nom; age } = p, ou { age; _ } dans un match pour ne lire que le champ utile.
Field punning
Raccourci où l'on écrit { nom; age } au lieu de { nom = nom; age = age } quand la variable porte déjà le nom du champ. Valable à la lecture comme à la construction.

Récap et vérification

  • Les records ont des champs nommés ; { r with champ = ... } crée une copie modifiée.
  • option (Some/None) remplace null : l'absence est dans le type.
  • result (Ok/Error) gère les erreurs attendues, visibles dans le type de retour.
  • Les exceptions existent mais sont réservées aux cas vraiment exceptionnels.
