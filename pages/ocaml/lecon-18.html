Module 5 · OCaml, encore plus loin — Leçon 18

Tester et outiller un projet OCaml

~55 min Avancé Prérequis : leçon 10

À la fin de cette leçon, tu sauras

  • écrire des tests par l'exemple (Alcotest, tests inline) ;
  • découvrir le test par propriété avec QCheck ;
  • situer la chaîne d'outils : opam, dune, ocamlformat, odoc, LSP, utop ;
  • enchaîner build, test et format dans un flux reproductible.
Sommaire de la leçon

Écrire du code juste, c'est bien ; garder ce code juste dans le temps, c'est le métier. Un projet OCaml mûr se teste automatiquement et s'appuie sur une chaîne d'outils soignée. Cette dernière leçon boucle le cours : on part de dune (leçon 10), on y greffe deux styles de tests complémentaires, et on fait le tour de l'outillage qui rend le développement OCaml fluide et reproductible.

Un projet sérieux se teste

Il existe deux grandes familles de tests, complémentaires. Le test par l'exemple : on fournit une entrée et l'on affirme la sortie attendue (« 2 + 2 vaut 4 »). Le test par propriété : on énonce une loi qui doit tenir pour toute entrée, et un outil la vérifie sur des centaines de cas générés. Les deux se conjuguent : les exemples documentent des cas précis, les propriétés ratissent large.

Tester par l'exemple : Alcotest et tests inline

Alcotest est un framework de tests léger et lisible : un test associe un nom à une fonction qui vérifie une égalité attendue avec check.

Astuce — les tests inline, au plus près du code

Avec l'extension ppx_inline_test, on écrit un test juste sous la fonction qu'il éprouve : let%test "double" = double 3 = 6. Idéal pour les petites vérifications locales qui vivent avec le code qu'elles gardent. Alcotest, lui, brille pour des suites structurées avec de beaux rapports.

Tester par la propriété : QCheck

Un test par l'exemple ne couvre que les cas que tu as imaginés. Le test par propriété renverse la charge : tu énonces une loi, et QCheck génère des centaines d'entrées aléatoires pour tenter de la mettre en défaut. S'il trouve un contre-exemple, il le réduit (shrinking) au plus petit cas fautif, facile à déboguer.

Cas réel — le bug qu'aucun exemple n'aurait trouvé

Le test par propriété a une réputation méritée : dénicher les cas limites que personne n'écrit à la main. Une liste vide, un entier négatif, une chaîne avec un accent, un débordement à la frontière d'un intervalle… QCheck les génère sans état d'âme. Dans l'écosystème OCaml, on l'emploie couramment pour éprouver des parsers (la propriété « afficher puis relire redonne la même valeur ») et des structures de données (une Map se comporte-t-elle comme une liste d'associations de référence ?). L'approche vient d'Haskell (QuickCheck) et s'est répandue partout : c'est l'un des filets de sécurité les plus rentables du génie logiciel moderne.

Pour aller plus loin — dune fmt et l'intégration continue

Le formatage n'est pas un caprice : ocamlformat (via dune fmt) impose un style à toute l'équipe, ce qui supprime les débats et les diffs cosmétiques. En intégration continue, un projet OCaml enchaîne typiquement dune build @all (tout compiler), dune runtest (tous les tests) et une vérification de format : si l'un échoue, la fusion est bloquée. Le code reste ainsi compilable, testé et uniforme en permanence.

Antisèche — tester et outiller

Glossaire

Test par l'exemple
Vérifier une sortie attendue pour une entrée donnée (ex. Alcotest).
Test par propriété
Énoncer une loi vérifiée sur de nombreuses entrées générées (ex. QCheck).
Shrinking
Réduction automatique d'un contre-exemple au plus petit cas fautif.
Test inline
Test écrit juste à côté du code testé (let%test …).
opam
Gestionnaire de paquets et de versions du compilateur OCaml.
dune
Système de construction qui pilote build, tests, format et doc.
ocamlformat
Formateur imposant un style uniforme via dune fmt.
odoc
Générateur de documentation HTML depuis les commentaires (** … *).

Récap et vérification

  • Deux styles complémentaires : par l'exemple (Alcotest, tests inline) et par propriété (QCheck).
  • QCheck génère des entrées et réduit les contre-exemples : il trouve les cas limites oubliés.
  • La chaîne opam + dune + ocamlformat + odoc + LSP + utop rend le développement reproductible.
  • En intégration continue, dune build @all et dune runtest gardent le code compilable et testé.

Vérifie ta compréhension

  2. Que fait QCheck quand il trouve un contre-exemple ?
  3. Quelle commande dune lance les tests d'un projet ?

Exercices

Exercice 1Échauffement

Écris un test Alcotest qui vérifie que List.length [1; 2; 3] vaut 3.

Voir une solution

Alcotest.(check int) compare deux entiers : la valeur attendue (3) et la valeur obtenue (List.length …). Le premier argument est un libellé qui apparaîtra dans le rapport en cas d'échec. Alcotest.run regroupe les cas et rend un rapport lisible.

Exercice 2Application

Énonce, en QCheck, la propriété « concaténer deux listes donne une longueur égale à la somme des longueurs ».

Voir une solution

Le générateur QCheck.(pair (list int) (list int)) fabrique des couples de listes d'entiers aléatoires. La fonction exprime la loi : pour tout couple (a, b), la longueur de la concaténation égale la somme des longueurs. QCheck tentera des dizaines de couples (dont la liste vide, les listes longues…) et ne signalera un échec que s'il déniche un contre-exemple.

Exercice 3Défi

Ton équipe se dispute : faut-il des tests par l'exemple ou par propriété ? Tranche, en montrant ce que chacun attrape que l'autre manque, et propose une règle d'emploi.

Voir une solution

La bonne réponse est « les deux », car ils échouent différemment. Le test par l'exemple excelle à documenter un comportement précis et à verrouiller un cas de régression connu : « le bug #42 sur l'entrée "" ne doit plus revenir ». Il est lisible, sert de spécification exécutable, mais ne teste que ce que tu as pensé à écrire — il rate les cas limites que tu n'as pas imaginés. Le test par propriété couvre justement cet angle mort : en générant des centaines d'entrées, il déniche la liste vide, l'entier négatif, la frontière d'intervalle, l'accent inattendu. En revanche, une propriété est parfois difficile à formuler (quelle loi universelle décrit vraiment ma fonction métier ?) et un échec aléatoire peut surprendre en intégration continue.

Règle d'emploi : écris une propriété quand ta fonction obéit à une loi claire (involution, idempotence, symétrie, « encoder puis décoder redonne l'original », cohérence avec une implémentation de référence). Ajoute des exemples pour les cas emblématiques, les régressions et la documentation. Concrètement : un parser mérite une propriété roundtrip plus quelques exemples réels ; une petite fonction utilitaire se contente souvent d'exemples. Les deux filets se superposent : l'un précis et parlant, l'autre large et impitoyable.

Mini-projet fil rouge — un inventaire

Pour clore ce cours, assemblons un petit inventaire. Il réunit un type enregistrement, des liaisons let, les opérateurs flottants (*., +.), une liste, List.iter/List.fold_left et Printf.printf — un condensé d'OCaml. Et, dans l'esprit de cette dernière leçon, on termine par une vérification automatique.

Ce que tu vas construire

Un type produit (nom, prix, quantité), une fonction valeur, l'affichage de chaque article, le total via List.fold_left, et une assertion qui contrôle le calcul.

Étapes

Le type produit

Déclare type produit = { nom : string; prix : float; quantite : int }.

La fonction valeur

Écris let valeur p = p.prix *. float_of_int p.quantite (noter *. et la conversion).

Le stock

Construis une liste d'enregistrements [ { ... }; ... ].

Afficher

Parcours avec List.iter (fun p -> Printf.printf ...).

Le total

Cumule avec List.fold_left (fun acc p -> acc +. valeur p) 0. stock.

Vérifier

Ajoute une assert qui contrôle valeur sur un produit connu : le premier réflexe de la leçon 18.

ProjetFil rouge

Assemble les six étapes en un programme complet. Essaie d'abord par toi-même, puis compare avec la solution de référence.

Voir une solution complète

L'assert échoue bruyamment si valeur se trompe : c'est un test par l'exemple minimal, sans dépendance. Dans un vrai projet, on le remplacerait par un cas Alcotest ou une propriété QCheck (« valeur d'un stock vide = 0 », « doubler la quantité double la valeur »).
