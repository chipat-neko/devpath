Module 1 · Les bases d'OCaml — Leçon 01

Découvrir OCaml

~45 min Avancé Prérequis : savoir programmer dans un autre langage

À la fin de cette leçon, tu sauras

  • comprendre la philosophie d'OCaml : fonctionnel, typé, pragmatique ;
  • utiliser le REPL (utop) et compiler un fichier ;
  • écrire un premier programme et afficher ;
  • situer OCaml et son influence (Rust, ReScript).
Sommaire de la leçon

OCaml est un langage fonctionnel né en France (à l'INRIA, années 1990), réputé pour marier trois qualités rares : un système de types extrêmement puissant, une inférence de types qui t'évite de tout annoter, et des performances proches du C. Sa devise pourrait être « le fonctionnel pragmatique » : pur quand c'est utile, impératif quand il le faut.

OCaml a profondément influencé la programmation moderne. Rust lui doit ses types algébriques, son pattern matching et son Option ; le compilateur Rust lui-même fut d'abord écrit en OCaml. ReScript et F# en descendent directement. Apprendre OCaml, c'est comprendre les idées qui façonnent les langages d'aujourd'hui.

Installer et lancer OCaml

On installe OCaml via opam (son gestionnaire de paquets). Pour expérimenter, le REPL utop est idéal : on tape une expression suivie de ;; et on voit immédiatement sa valeur et son type inféré.

Remarque : le REPL affiche toujours le type (int, string) en plus de la valeur.

Ton premier programme

Dans un fichier .ml, on lie des valeurs avec let et on affiche avec print_endline. Le point d'entrée est simplement le code au niveau supérieur.

Le mot-clé let

En OCaml, let nom = valeur lie un nom à une valeur. Par défaut, ces liaisons sont immuables : on ne réaffecte pas, on crée de nouvelles valeurs. Le typage est inféré automatiquement.

Les commentaires s'écrivent entre (* et *) et peuvent s'imbriquer.

int et float sont distincts

Particularité à connaître d'emblée : OCaml sépare strictement les entiers et les flottants. Les opérateurs flottants portent un point : +., -., *., /.. Pas de conversion implicite !

Les chaînes : concaténer avec ^

Même logique pour le texte : OCaml a un type string, mais on ne concatène pas avec +. L'opérateur dédié est l'accent circonflexe ^. On retrouve la règle « un type, ses opérateurs » : + pour les int, +. pour les float, ^ pour les string.

Dès qu'on assemble plusieurs valeurs, Printf.sprintf et ses marqueurs (%d pour un entier, %s pour une chaîne, %f pour un flottant) sont souvent plus clairs qu'une longue file de ^.

Piège fréquent

On ne mélange pas une chaîne et un nombre : "J'ai " ^ 36 ne compile pas, car ^ attend deux string. Il faut convertir : "J'ai " ^ string_of_int 36. Et "a" + "b" échoue tout autant, puisque + ne travaille que sur des entiers.

Tout est une expression

Voici l'idée qui dépayse le plus quand on vient de C, Java ou Python : en OCaml, il n'y a presque pas d'instructions, seulement des expressions qui produisent une valeur. Un if … then … else … ne se contente pas d'exécuter une branche : il renvoie une valeur, qu'on peut lier directement.

Corollaire : il n'existe pas de return. La valeur d'une fonction est celle de sa dernière expression. Et une fonction faite pour son effet (afficher, écrire un fichier) renvoie (), l'unique valeur du type unit — l'équivalent OCaml du « rien d'utile », le void d'ailleurs.

Astuce

Le ;; que tu tapes dans utop n'est pas nécessaire dans un fichier .ml : il sert seulement à dire au REPL « évalue maintenant ». Dans un vrai programme on l'omet et on enchaîne les définitions avec let. En voir traîner partout est la marque d'un code recopié depuis le REPL.

Pièges fréquents

Piège fréquent

Utiliser + sur des flottants : 1.5 + 2.5 est une erreur de type en OCaml. Les flottants exigent +.. C'est déroutant au début, mais c'est cohérent avec la rigueur du langage : aucune conversion ne se fait dans ton dos.

Pour aller plus loin

Pour aller plus loin

La grande force d'OCaml est que « si ça compile, c'est souvent correct ». Le compilateur attrape une énorme classe d'erreurs avant l'exécution. Beaucoup de programmeurs OCaml ne lancent leur code qu'après avoir satisfait le typeur — un gain de fiabilité considérable.

Cas réel : OCaml dans l'industrie

Cas réel

La société de trading Jane Street a bâti la quasi-totalité de son infrastructure — des millions de lignes — en OCaml, précisément parce que « si ça compile, ça marche » réduit les bugs coûteux dans un domaine où une erreur se chiffre en millions. Côté grand public, le pare-feu réseau de Docker for Mac/Windows (vpnkit) est écrit en OCaml, et le premier compilateur de Rust le fut aussi : OCaml est discret mais présent sous des outils que tu utilises tous les jours.

Glossaire

OCaml
Langage fonctionnel typé né à l'INRIA (France, années 1990), de la famille ML : allie typage puissant, inférence et performances proches du C.
Inférence de types
Capacité du compilateur à déduire le type de chaque expression sans annotation. On garde un typage statique strict tout en écrivant un code concis.
REPL / utop
« Read-Eval-Print Loop » : boucle interactive. utop est le REPL amélioré d'OCaml, qui affiche pour chaque expression sa valeur et son type.
opam
Le gestionnaire de paquets d'OCaml (installe le compilateur, les bibliothèques et les outils comme utop ou dune).
let
Mot-clé qui lie un nom à une valeur. Par défaut la liaison est immuable : on ne réaffecte pas, on crée de nouvelles valeurs.
int / float
Deux types numériques distincts. Les entiers utilisent + - * /, les flottants +. -. *. /. (suffixés d'un point). Aucune conversion implicite.
Langage fonctionnel
Style où l'on programme surtout par expressions et fonctions plutôt que par instructions modifiant un état. OCaml est fonctionnel « pragmatique » : il autorise aussi l'impératif.
^ (concaténation)
Opérateur qui colle deux chaînes : "a" ^ "b" donne "ab". Comme +. pour les flottants, il existe parce que + est réservé aux entiers.
unit / ()
Le type « rien d'utile », dont la seule valeur est (). C'est ce que renvoient les fonctions faites pour leur effet (comme print_endline) ; l'équivalent du void d'autres langages.

Récap et vérification

  • OCaml : fonctionnel pragmatique, typage puissant + inférence, performances élevées.
  • Il a influencé Rust, F#, ReScript ; le REPL utop affiche valeur et type.
  • let nom = valeur lie une valeur immuable ; types inférés.
  • int et float sont distincts : opérateurs flottants avec un point (+.).
  • Chaînes : on concatène avec ^ (jamais +) ; tout est une expression, pas de return.
