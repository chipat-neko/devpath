Module 3 · OCaml en pratique — Leçon 09

Mutabilité et impératif

~50 min Avancé Prérequis : leçon 8

À la fin de cette leçon, tu sauras

  • utiliser les références (ref, !, :=) quand c'est justifié ;
  • manier les tableaux mutables ;
  • écrire des boucles for/while ;
  • mêler proprement fonctionnel et impératif.
Sommaire de la leçon

OCaml est fonctionnel, mais pragmatique : quand l'état mutable ou les boucles simplifient vraiment, il les permet. Cette leçon montre les références, les tableaux mutables et les boucles — et surtout comment mêler proprement les styles fonctionnel et impératif.

Les références

Par défaut, une liaison let est immuable. Pour une vraie variable modifiable, on utilise une référence : ref la crée, ! lit son contenu, := le modifie.

!r n'est pas une négation ici : c'est « le contenu de la référence r ».

Les tableaux mutables

Contrairement aux listes (immuables), les tableaux (array) ont une taille fixe et des éléments modifiables, avec un accès indexé rapide.

Choisis le tableau pour l'accès indexé et la mutation ; la liste pour la construction fonctionnelle.

Les boucles

OCaml a des boucles for et while. Elles renvoient unit (rien d'utile) : on ne les utilise que pour des effets de bord (modifier un tableau, afficher).

Le type unit et le point-virgule

Une expression qui ne produit « rien » a le type unit (sa seule valeur est ()). On enchaîne des effets de bord avec le point-virgule ; : « fais ceci, puis cela ».

Mêler les deux styles proprement

La bonne pratique OCaml : garder le cœur fonctionnel (logique pure, sans état) et isoler l'impératif là où il est vraiment utile (performance d'un algorithme, entrées/sorties). On obtient le meilleur des deux mondes : clarté et efficacité.

À l'extérieur, somme_tableau est une fonction pure ; la mutation reste cachée à l'intérieur.

Cas réel — accumuler vite, exposer proprement

Pour sommer des millions de mesures dans un moteur de calcul, une boucle for sur un array avec une ref accumulatrice évite de reconstruire une liste à chaque étape : c'est nettement plus rapide et sans pression sur le ramasse-miettes. Chez Jane Street (finance), c'est exactement l'approche : la logique métier reste fonctionnelle et testable, tandis que les points chauds de performance passent en impératif local — mutation confinée, jamais visible de l'appelant.

Astuce — la ref n'est pas le premier réflexe

Avant d'atteindre une ref, demande-toi si un List.fold_left ne suffit pas : la plupart des accumulations s'écrivent sans mutation. Réserve ref, for et array aux cas où ils apportent un vrai gain (performance mesurée, entrées/sorties), pas par habitude venue d'un autre langage.

Pièges fréquents

Piège fréquent

Oublier le ! pour lire une référence : écrire compteur + 1 au lieu de !compteur + 1 est une erreur de type, car compteur est une référence (un int ref), pas un int. Pour obtenir la valeur, c'est toujours !compteur.

Pour aller plus loin

Pour aller plus loin

Un champ de record peut être déclaré mutable pour autoriser sa modification (champ <- valeur) : une autre façon, parfois plus claire qu'une ref, d'avoir un état modifiable encapsulé dans une structure.

Glossaire

Référence (ref)
Cellule mutable de type 'a ref : !r en lit le contenu, r := v le remplace. La liaison ne bouge pas ; son contenu, si.
Déréférencement (!)
Opérateur qui renvoie le contenu d'une référence. Rien à voir avec une négation : !r se lit « la valeur pointée par r ».
Affectation (:=)
Opérateur qui écrit une nouvelle valeur dans une référence. À ne pas confondre avec <-, réservé aux cases de tableau et aux champs mutable.
Tableau (array)
Séquence de taille fixe à cases mutables, notée [| … |], avec accès et écriture par index en temps constant (t.(i)).
unit
Type de l'« absence de valeur utile », dont l'unique valeur est (). C'est le type des expressions évaluées pour leurs effets (boucles, affichage).
Effet de bord
Action qui modifie l'état ou interagit avec le monde (muter une ref, écrire à l'écran) au lieu de simplement renvoyer une valeur.
Séquence (;)
Enchaîne deux expressions : « fais ceci, puis cela ». La partie gauche doit être de type unit ; la valeur retenue est celle de droite.
Champ mutable
Champ de record modifiable via champ <- valeur : une alternative à ref, souvent plus lisible pour un état encapsulé dans une structure.

Récap et vérification

  • Une référence (ref) est mutable : !r lit, r := v écrit ; incr/decr.
  • Les tableaux ([| ... |]) sont à taille fixe et modifiables (t.(i) <- v).
  • Les boucles for/while renvoient unit : pour les effets de bord ; on les enchaîne avec ;.
  • Bonne pratique : cœur fonctionnel, impératif isolé et caché.
