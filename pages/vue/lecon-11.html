Module 5 · Construire une application — Leçon 11

Les formulaires et leur validation

~36 min Avancé Leçons 01 à 05 conseillées

À la fin de cette leçon, tu sauras

  • lier tous les champs avec v-model (texte, case, radio, liste) ;
  • appliquer les modificateurs .trim, .number, .lazy ;
  • valider les saisies et afficher les messages d'erreur ;
  • soumettre proprement avec @submit.prevent.
Sommaire de la leçon

Les formulaires sont partout : connexion, inscription, recherche, paiement. C'est aussi là que Vue brille, grâce à la liaison bidirectionnelle : le champ et l'état restent synchronisés, dans les deux sens. Cette leçon reprend v-model (vu en leçon 03) sur tous les types de champs, puis construit une validation claire, jusqu'à la soumission.

v-model, la liaison bidirectionnelle

v-model relie un champ à une donnée réactive : taper dans le champ met à jour l'état, et changer l'état met à jour le champ. Deux directions, une seule directive.

v-model sur tous les champs

La même directive s'adapte au type de champ : elle lie une chaîne pour un texte, un booléen pour une case, la valeur choisie pour des radios ou une liste.

Les modificateurs

Trois suffixes rendent service au quotidien :

  • .trim retire les espaces en début et fin de saisie ;
  • .number convertit la valeur en nombre (sinon un champ texte renvoie toujours une chaîne ; Vue 3 l'applique d'office sur type="number") ;
  • .lazy ne met à jour l'état qu'au changement (perte de focus), pas à chaque frappe.

.number évite un bug fréquent

Un champ texte renvoie toujours une chaîne. Sans .number, age + 1 donne "30" + 1 = "301" au lieu de 31 ! Le modificateur convertit dès la liaison. Sur un type="number", Vue 3 l'applique d'office : l'écrire quand même rend l'intention visible.

Valider les saisies

Valider, c'est vérifier chaque règle et n'autoriser l'envoi que si tout est correct. Avec la Composition API, on exprime les règles en computed : elles se recalculent automatiquement à chaque frappe.

Côté gabarit, on affiche un message d'erreur seulement si le champ a été saisi et qu'il est invalide, et on désactive le bouton tant que le formulaire n'est pas valide :

Soumettre le formulaire

On écoute l'événement submit du <form> avec le modificateur .prevent, qui empêche le rechargement de la page (comportement HTML par défaut). La fonction n'est appelée que si le formulaire est valide.

La validation client ne suffit JAMAIS

Désactiver le bouton et afficher des erreurs améliore l'expérience, mais un utilisateur mal intentionné contourne le navigateur. Toute donnée doit être revalidée côté serveur avant d'être enregistrée. La validation front est un confort, pas une sécurité.

Cas réel — le formulaire d'inscription qui frustrait

Sur un site, l'inscription affichait toutes les erreurs dès l'ouverture, avant même que l'utilisateur ait tapé quoi que ce soit : un mur de rouge décourageant. En conditionnant chaque message à champ && !valide (afficher l'erreur seulement après une saisie), et en gardant le bouton désactivé tant que tout n'est pas correct, le parcours est devenu limpide : l'erreur n'apparaît qu'au bon moment, sur le bon champ, et s'efface dès la correction. Le taux d'inscriptions abandonnées a nettement baissé.

Pour aller plus loin — VeeValidate & Zod

Pour des formulaires complexes (nombreux champs, règles croisées, messages localisés), des bibliothèques évitent de tout écrire à la main : VeeValidate gère l'état de validation champ par champ, et Zod définit un schéma réutilisable, partageable avec le serveur.

Glossaire

v-model
Directive de liaison bidirectionnelle : synchronise un champ et une donnée réactive dans les deux sens.
Liaison bidirectionnelle
Le champ met à jour l'état, et l'état met à jour le champ, sans code de synchronisation manuel.
Modificateur
Suffixe ajouté à une directive : .trim, .number, .lazy pour v-model.
Validation
Vérification des règles sur les saisies avant d'autoriser l'envoi ; ici exprimée en computed.
computed
Valeur dérivée qui se recalcule automatiquement quand ses dépendances changent — idéale pour une règle.
@submit.prevent
Écoute l'envoi du formulaire en empêchant le rechargement HTML par défaut.
:disabled
Liaison d'attribut qui désactive un bouton tant qu'une condition (formulaire invalide) est vraie.
Validation serveur
Revérification des données côté serveur ; seule garantie de sécurité, la validation client n'étant qu'un confort.

Récap et vérification

  • v-model lie tous les champs : chaîne, booléen (case), valeur choisie (radio, liste).
  • Les modificateurs .trim, .number, .lazy nettoient, convertissent ou temporisent la liaison.
  • On valide avec des computed ; on affiche l'erreur si champ && !valide et on désactive le bouton via :disabled.
  • On soumet avec @submit.prevent ; la validation client est un confort — revalider côté serveur.

Exercices

Exercice 1Échauffement

Lie un champ texte à une donnée ville et affiche « Vous habitez à … » juste en dessous, qui se met à jour à chaque frappe.

Voir une solution

Avec const ville = ref('') dans le script, v-model synchronise le champ et la donnée : le paragraphe reflète la saisie en direct, sans le moindre écouteur écrit à la main.

Exercice 2Application

Un champ « âge » doit contenir un nombre entre 0 et 120. Écris la liaison et une règle ageValide qui n'accepte que cet intervalle.

Voir une solution

.number garantit que age est un vrai nombre (Vue 3 le fait déjà d'office sur type="number" ; l'écrire protège si l'on retire ce type), sinon les comparaisons >= et <= seraient faites sur une chaîne. La règle ageValide se recalcule à chaque frappe, et l'erreur ne s'affiche qu'après une saisie.

Exercice 3Défi

Construis un mini-formulaire de connexion : e-mail + mot de passe (8 caractères minimum), bouton désactivé tant que c'est invalide, et une fonction envoyer appelée sans recharger la page.

Voir une solution

Chaque règle est un computed qui se met à jour tout seul ; valide combine les deux et pilote :disabled. @submit.prevent évite le rechargement et n'appelle envoyer qu'au clic sur un bouton actif. On penserait ensuite à revalider côté serveur.

Exercice 4Au clavier

La validation d'un formulaire est une fonction pure, indépendante de tout composant. Écris valider(champs) qui rend un objet d'erreurs (clé = champ, valeur = message), puis affiche le JSON obtenu pour { nom: ' ', courriel: 'ada' }.
