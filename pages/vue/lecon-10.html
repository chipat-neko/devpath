Module 5 · Construire une application — Leçon 10

Vue Router : le routage d'une application

~38 min Avancé Leçons 01 à 06 conseillées

À la fin de cette leçon, tu sauras

  • définir des routes et les afficher avec <RouterView> ;
  • naviguer avec <RouterLink> et par programmation ;
  • lire les paramètres dynamiques d'une URL ;
  • protéger l'accès avec une garde de navigation.
Sommaire de la leçon

Une application d'une seule page (SPA) n'a qu'un fichier HTML, mais l'utilisateur, lui, s'attend à des « pages » : une adresse par écran, des liens, le bouton Précédent qui fonctionne. C'est le rôle du routeur. Vue Router est la bibliothèque officielle : elle associe chaque URL à un composant et échange l'affichage sans recharger la page. Tu l'as croisée dans la leçon 06 sur l'écosystème ; on la détaille ici.

Installer et déclarer les routes

Après npm install vue-router, on crée un routeur en associant des chemins (path) à des composants. createWebHistory active les URL propres (sans #), grâce à l'API History du navigateur.

On branche ensuite le routeur sur l'application, dans le point d'entrée :

Afficher et lier : RouterView et RouterLink

Deux composants suffisent à l'usage courant. <RouterView> est l'emplacement où s'affiche le composant de la route courante. <RouterLink> remplace la balise <a> : il change l'URL sans recharger la page.

Sans RouterView, rien ne s'affiche

L'erreur classique du débutant : déclarer les routes mais oublier de placer un <RouterView /> dans le gabarit. Les liens changent bien l'URL, mais aucun composant n'apparaît — car il n'y a pas d'emplacement pour l'accueillir.

Les routes dynamiques

Un segment préfixé de : devient un paramètre. Une seule route /produit/:id couvre tous les produits. Dans le composant, on lit le paramètre avec useRoute().

useRoute vs useRouter

Ne les confonds pas : useRoute() (au singulier) décrit la route actuelle — on la lit (params, query). useRouter() est l'instance du routeur — on l'utilise pour naviguer (push, back).

Charger les vues à la demande

Importer chaque vue au démarrage alourdit le premier chargement. En remplaçant l'import par une fonction qui importe, Vite découpe le code : la vue n'est téléchargée qu'à la première visite de sa route (lazy loading).

Protéger l'accès : les gardes

Une garde de navigation s'exécute avant chaque changement de route. router.beforeEach reçoit la destination ; renvoyer une autre adresse redirige, renvoyer false annule. On l'utilise typiquement pour l'authentification.

Le champ meta d'une route porte des informations libres, comme requiresAuth: true, que la garde consulte pour décider.

Cas réel — le tableau de bord protégé

Une application de gestion a un tableau de bord réservé aux membres connectés. Sans garde, un visiteur pouvait taper directement l'URL /tableau-de-bord et atteindre l'écran (vide, mais visible) avant que les données ne refusent de charger — une fuite d'interface gênante. En ajoutant meta: { requiresAuth: true } sur les routes sensibles et une seule beforeEach qui redirige les non-connectés vers /connexion, toute la zone privée est verrouillée d'un coup, à un seul endroit. Bonus : la garde mémorise l'URL demandée pour y revenir après connexion.

Pour aller plus loin — routes imbriquées & Nuxt

Une route peut contenir des children pour afficher des sous-vues dans un <RouterView> imbriqué (utile pour des onglets). À plus grande échelle, Nuxt génère le routeur automatiquement à partir de l'arborescence des fichiers du dossier pages/ — chaque fichier devient une route.

Antisèche — Vue Router

Glossaire

SPA (application d'une page)
Application chargée une seule fois ; le routeur échange les vues côté client sans recharger le HTML.
Route
Association d'un chemin d'URL (path) à un composant à afficher.
RouterView
Composant marquant l'emplacement où s'affiche la vue de la route courante.
RouterLink
Composant de lien qui change l'URL sans recharger la page (remplace <a>).
Paramètre dynamique
Segment d'URL variable, noté :id ; lu via useRoute().params.
Navigation programmatique
Changer de route depuis le code avec useRouter().push(...).
Lazy loading
Charger le composant d'une route à la première visite, via () => import(...).
Garde de navigation
Fonction (ex. beforeEach) exécutée avant un changement de route, qui peut l'autoriser, le rediriger ou l'annuler.

Récap et vérification

  • Le routeur associe chaque URL à un composant, affiché dans <RouterView> ; on navigue avec <RouterLink>.
  • Une route :param est dynamique ; on lit sa valeur avec useRoute().params.
  • On navigue depuis le code avec useRouter().push(...) ; on allège le chargement avec () => import(...).
  • Une garde (beforeEach) protège l'accès en redirigeant selon une condition.

Vérifie ta compréhension

  1. Quelle est la différence entre <RouterLink> et une balise <a> ordinaire ?
  2. Comment récupérer l'id depuis l'URL /produit/42 ?
  3. À quoi sert router.beforeEach ?

Exercices

Exercice 1Échauffement

Déclare deux routes : / vers un composant Accueil et /contact vers un composant Contact. Écris le tableau routes.

Voir une solution

Chaque entrée associe un path à un component. Il restera à passer ce tableau à createRouter et à placer un <RouterView /> dans le gabarit pour voir le résultat.

Exercice 2Application

Une route /article/:slug affiche un article. Dans le composant, comment récupérer le slug pour aller chercher le bon article ?

Voir une solution

useRoute() donne la route courante ; params.slug contient la valeur du segment dynamique :slug. On l'utilise ensuite pour requêter l'article. (Astuce : si l'on navigue de /article/a à /article/b, surveille route.params.slug avec un watch pour recharger.)

Exercice 3Défi

Protège la route /admin pour que seuls les utilisateurs connectés y accèdent ; les autres sont renvoyés vers /connexion. Décris la meta et la garde.

Voir une solution

On marque les routes sensibles avec meta.requiresAuth. La garde beforeEach s'exécute avant chaque navigation : si la destination exige l'authentification et que l'utilisateur n'est pas connecté, elle renvoie '/connexion', ce qui redirige. Une seule garde protège ainsi toute la zone privée, sans dupliquer la vérification dans chaque composant. On peut aussi passer { path: '/connexion', query: { retour: to.fullPath } } pour revenir à la page voulue après connexion.
