Module 5 · Construire une application — Leçon 12

Les transitions et les animations

~34 min Avancé Leçons 02 et 04 conseillées

À la fin de cette leçon, tu sauras

  • animer l'apparition et la disparition d'un élément avec <Transition> ;
  • comprendre les six classes du cycle enter / leave ;
  • nommer une transition pour composer plusieurs effets ;
  • animer une liste entière avec <TransitionGroup>.
Sommaire de la leçon

Une animation bien dosée n'est pas un ornement : elle explique un changement. Quand un élément apparaît, disparaît ou se déplace, une courte transition laisse à l'œil le temps de suivre, atténue l'effet de « saut » et renforce le sentiment de fluidité. Vue fournit deux composants intégrés — <Transition> et <TransitionGroup> — qui orchestrent ces effets sans code impératif : tu décris l'état, Vue anime le passage.

Le composant <Transition>

<Transition> anime l'entrée et la sortie d'un seul élément (ou composant) affiché conditionnellement par v-if, v-show ou :is. Il n'ajoute aucune balise au DOM : il se contente de poser et retirer des classes CSS au bon moment.

Les six classes du cycle

Pendant une transition, Vue applique six classes successives : trois à l'entrée, trois à la sortie. On met la déclaration transition: sur la classe -active (présente pendant toute la durée de l'effet), et les états visuels de départ et d'arrivée sur -from et -to.

Nommer une transition

Sans nom, le préfixe des classes est v-. En donnant un name, le préfixe devient nom- : on peut alors définir plusieurs transitions distinctes dans la même application.

Anime opacity et transform, pas la mise en page

Pour une animation fluide à 60 images par seconde, préfère animer opacity et transform (translate, scale) : le navigateur les traite sur le compositeur, sans recalculer la disposition. Animer width, height, top/left déclenche des reflows coûteux qui saccadent l'effet.

Animer une liste : <TransitionGroup>

Pour animer l'ajout, le retrait et le déplacement d'éléments dans un v-for, on utilise <TransitionGroup>. À la différence de <Transition>, il rend un vrai élément conteneur (précisé par tag), exige une :key stable sur chaque enfant, et ajoute une classe -move pour animer le repositionnement des voisins.

Respecte prefers-reduced-motion

Certaines personnes règlent leur système sur « animations réduites » (vertiges, troubles vestibulaires). Respecte ce choix en neutralisant ou en raccourcissant les transitions dans une media query : @media (prefers-reduced-motion: reduce) { * { transition: none !important } }. L'accessibilité prime toujours sur l'effet.

Cas réel — la liste qui « sautait »

Sur un tableau de bord, supprimer une ligne la faisait disparaître brutalement, et les lignes suivantes remontaient d'un coup : si vite qu'on perdait de vue ce qui venait d'être retiré. En enveloppant la liste dans <TransitionGroup name="ligne"> avec un fondu de sortie et une classe .ligne-move { transition: transform .25s }, la ligne s'efface en douceur pendant que les voisines glissent à leur nouvelle place. Les utilisateurs ont cessé de se demander « qu'est-ce qui vient de changer ? » : le mouvement racontait l'histoire à leur place.

Pour aller plus loin — au-delà du CSS

Pour des animations pilotées par la logique (ressorts, gestes, valeurs interpolées), des bibliothèques prennent le relais : @vueuse/motion (déclaratif), GSAP (timelines puissantes), ou AutoAnimate (une ligne pour animer les changements d'une liste). Les hooks JavaScript de <Transition> (@enter, @leave) permettent aussi de brancher n'importe quel moteur d'animation.

Glossaire

<Transition>
Composant intégré qui anime l'entrée et la sortie d'un seul élément conditionnel, en posant des classes CSS.
<TransitionGroup>
Variante qui anime l'ajout, le retrait et le déplacement des éléments d'une liste v-for.
Classe -active
Appliquée pendant toute la durée de l'effet ; porte la déclaration transition.
Classe -from / -to
États visuels initial et final de l'animation, à l'entrée comme à la sortie.
name (transition)
Attribut qui change le préfixe des classes : v- devient nom-.
Classe -move
Appliquée par <TransitionGroup> aux éléments qui se repositionnent, pour animer leur glissement.
prefers-reduced-motion
Préférence système signalant de limiter les animations ; à respecter par une media query.

Récap et vérification

  • <Transition> anime un élément (v-if/v-show) ; <TransitionGroup> anime une liste.
  • Six classes : -enter-from/active/to et -leave-from/active/to ; la durée va sur -active.
  • name="x" préfixe les classes en x- ; .x-move anime le déplacement des voisins.
  • Anime opacity/transform pour la fluidité, et respecte prefers-reduced-motion.

Vérifie ta compréhension

  1. Quelle est la différence entre <Transition> et <TransitionGroup> ?
  2. Sur quelle classe met-on la déclaration transition:, et pourquoi ?
  3. Pourquoi vaut-il mieux animer transform que top/left ?

Exercices

Exercice 1Échauffement

Fais apparaître et disparaître un message d'aide en fondu quand on bascule un booléen aide. Écris le gabarit et le CSS minimal.

Voir une solution

Sans nom, Vue utilise le préfixe v-. Deux règles suffisent : -active pour la durée, -from/-to pour l'opacité de départ et d'arrivée.

Exercice 2Application

Nomme une transition glisse qui fait entrer un panneau depuis la droite (décalage horizontal + fondu). Donne le CSS.

Voir une solution

Le name change le préfixe en glisse-. On anime transform et opacity — deux propriétés fluides — plutôt que right ou margin.

Exercice 3Défi

Anime une liste de tâches : chaque ajout apparaît en fondu depuis le bas, chaque suppression disparaît en fondu, et les voisines glissent doucement. Écris le gabarit et le CSS, sans oublier ce qui rend le déplacement possible.

Voir une solution

Trois points-clés : une :key stable (l'id, pas l'index) pour que Vue suive chaque élément ; tag="ul" pour rendre un vrai conteneur ; et surtout .tache-move, sans laquelle les voisines sauteraient au lieu de glisser. C'est exactement l'effet « liste qui respire » d'une bonne to-do list.
