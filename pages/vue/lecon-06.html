L'écosystème Vue

~30 min Intermédiaire Leçon 05 requise

À la fin de cette leçon, tu sauras

  • distinguer Composition API et Options API ;
  • situer le routage avec Vue Router ;
  • situer la gestion d'état avec Pinia ;
  • connaître l'outillage et la suite (Vite).
Sommaire de la leçon

Tu maîtrises le cœur de Vue : réactivité, template, composants, communication. Une vraie application a aussi besoin de naviguer entre des pages et de partager un état entre composants éloignés. Vue offre pour cela un écosystème officiel cohérent. Cette dernière leçon le survole — sans tout détailler — pour que tu saches quoi chercher quand ton projet grandit.

Composition API vs Options API

Ce cours utilise la Composition API (<script setup>, ref, computed…). Tu rencontreras aussi l'Options API, plus ancienne, où la logique est organisée en sections nommées (data, methods, computed…). Les deux font la même chose, différemment.

La Composition API est aujourd'hui recommandée pour les nouveaux projets : elle regroupe la logique par fonctionnalité (plus facile à organiser et à réutiliser sur de gros composants) et s'intègre mieux à TypeScript. L'Options API reste valide, plus structurée pour les débutants, et très présente dans le code existant. Savoir lire les deux est utile ; pour écrire du neuf, la Composition API est le choix par défaut.

Le routage : Vue Router

Une application web a plusieurs « pages » (accueil, profil, détail…). Mais une application Vue est une Single Page Application : une seule page HTML où le contenu change sans rechargement. C'est Vue Router, la bibliothèque officielle de routage, qui associe une URL à un composant à afficher.

Vue Router gère les liens (<router-link>, qui ne rechargent pas la page), les paramètres d'URL (:id, pour une page de détail), l'historique du navigateur (bouton retour), et plus. C'est l'outil standard dès qu'une application a plusieurs vues. Tu n'as pas besoin de le maîtriser maintenant : retiens qu'il existe et résout le problème de la navigation.

La gestion d'état : Pinia

Les props et les events suffisent entre un parent et son enfant. Mais quand un état doit être partagé entre des composants éloignés (l'utilisateur connecté, le panier, le thème), les faire transiter de parent en enfant devient pénible (le « prop drilling »). Pinia, la bibliothèque officielle de gestion d'état, offre un magasin central (store) accessible de n'importe où.

Pinia centralise l'état partagé en un endroit réactif et clair, avec des actions pour le modifier. Tout composant qui en a besoin y accède directement, sans faire descendre des props à travers dix niveaux. C'est l'équivalent Vue de ce que d'autres écosystèmes appellent un « store global ». Comme Vue Router, on l'adopte quand le besoin apparaît, pas avant.

Cas réel — l'utilisateur connecté, partout à la fois

Sur presque tout site, l'utilisateur connecté doit être visible à de nombreux endroits : son avatar dans l'en-tête, son nom sur la page profil, ses droits qui conditionnent certains boutons, son panier au paiement. Le faire descendre en props partout serait un cauchemar. La solution retenue dans la vraie vie : un store Pinia useAuth qui contient l'utilisateur et des actions (connexion, deconnexion). Chaque composant l'importe et réagit automatiquement : quand l'utilisateur se déconnecte, l'en-tête, le menu et les pages se mettent à jour d'un coup.

L'outillage et la suite

Pour finir, le paysage pratique :

  • Vite : l'outil de build officiel, ultra-rapide. npm create vue@latest crée un projet complet (avec options pour Router, Pinia, TypeScript, tests).
  • TypeScript : Vue 3 et la Composition API s'y intègrent très bien (cours TypeScript) — un atout pour les projets sérieux.
  • Nuxt : un méta-framework bâti sur Vue (rendu côté serveur, routage automatique, SEO) pour les sites et applications complets.
  • les outils de dev (Vue DevTools) pour inspecter composants et état dans le navigateur.

Tu as désormais une carte complète : le cœur de Vue (ce cours), la navigation (Vue Router), l'état partagé (Pinia), l'outillage (Vite). De quoi construire de vraies applications et savoir où aller pour chaque besoin.

Tout brancher en une commande

npm create vue@latest lance un assistant qui te propose d'ajouter, dès la création du projet, Vue Router, Pinia, TypeScript, ESLint et des tests — tout est pré-câblé et prêt à l'emploi. Plutôt que d'installer chaque pièce à la main, laisse l'assistant officiel monter la structure : tu gagnes du temps et tu obtiens l'agencement recommandé par l'équipe Vue.

Pour aller plus loin

La meilleure suite : construire un vrai projet. Lance npm create vue@latest, ajoute Vue Router et Pinia, et fais une petite application (liste de tâches, mini-catalogue). La documentation officielle de Vue est excellente et progressive : c'est ta référence. Explore ensuite les slots avancés, les composables (extraire et réutiliser de la logique réactive), la gestion des formulaires et les tests de composants (cours Tests). Tu as les fondations ; le reste s'apprend en pratiquant.

Glossaire

Composition API
Style d'écriture d'un composant (<script setup>) qui regroupe la logique par fonctionnalité.
Options API
Style plus ancien organisant la logique en sections nommées (data, methods, computed).
SPA (Single Page Application)
Application à page unique dont le contenu change sans rechargement complet.
Vue Router
Bibliothèque officielle de routage : associe une URL à un composant.
Pinia
Bibliothèque officielle de gestion d'état : un store central réactif.
Store
Espace central qui contient un état partagé et les actions pour le modifier.
Prop drilling
Faire transiter une donnée par de nombreux composants intermédiaires via des props.
Vite
Outil de build et de développement officiel, très rapide (npm create vue@latest).

Récap et vérification

  • Composition API (recommandée, ce cours) vs Options API (plus ancienne, à savoir lire) : deux styles pour la même logique.
  • Vue Router : associe les URL à des composants ; navigation sans rechargement (SPA).
  • Pinia : un store central pour l'état partagé entre composants éloignés (évite le prop drilling).
  • Outillage : Vite (build/création de projet), TypeScript, Nuxt (méta-framework), Vue DevTools.

Exercices

Exercice 1Échauffement

Quelle commande crée un nouveau projet Vue avec l'outillage officiel ?

Voir une solution

Cette commande (basée sur Vite) génère un projet Vue complet et propose d'ajouter Vue Router, Pinia, TypeScript, des tests, etc.

Exercice 2Application

Tu dois afficher une page différente selon l'URL (/ et /contact). Quel outil de l'écosystème utilises-tu, et quel est son rôle ?

Voir une solution

Vue Router. Son rôle : associer chaque URL à un composant à afficher (/ → un composant Accueil, /contact → un composant Contact) et changer le contenu sans recharger la page. On déclare les routes, on navigue avec <router-link to="/contact">, et Router gère l'affichage et l'historique du navigateur.

Exercice 3Défi

Dans une application, le panier doit être accessible depuis l'en-tête, la page produit et la page de paiement — des composants très éloignés. Pourquoi les props sont-elles inadaptées ici, et que proposes-tu ?

Voir une solution

Les props sont inadaptées car elles ne circulent que de parent à enfant, niveau par niveau. Pour partager le panier entre des composants éloignés dans l'arbre (en-tête, page produit, paiement), il faudrait faire descendre le panier et ses fonctions à travers de nombreux composants intermédiaires qui n'en ont pas besoin — c'est le « prop drilling », verbeux et fragile. Proposition : utiliser un store Pinia « panier » — un état central réactif (la liste des articles) avec des actions (ajouter, retirer). Chaque composant qui a besoin du panier l'importe directement (const panier = usePanier()), sans dépendre de la hiérarchie. L'état reste cohérent et accessible partout, et chaque composant réagit automatiquement à ses changements.
