Les composants et les props

~37 min Intermédiaire Leçon 03 requise

À la fin de cette leçon, tu sauras

  • créer et réutiliser un composant ;
  • passer des données par les props ;
  • comprendre le flux de données descendant ;
  • insérer du contenu avec un slot.
Sommaire de la leçon

Une interface entière dans un seul fichier deviendrait vite ingérable. La solution : découper en composants, des briques d'interface réutilisables et autonomes (un bouton, une carte, un en-tête, un formulaire). On les assemble comme des Lego. Cette leçon montre comment créer un composant, le réutiliser, et lui passer des données via les props.

Créer et utiliser un composant

Un composant est un fichier .vue (leçon 1). Pour l'utiliser dans un autre composant, on l'importe puis on l'emploie comme une balise.

On importe le composant, puis on l'utilise comme une balise (<CarteProduit />). On peut le réutiliser à volonté : c'est tout l'intérêt : écrire une fois, utiliser partout. Avec <script setup>, un composant importé est directement disponible dans le template, sans déclaration supplémentaire.

Passer des données : les props

Un composant réutilisable doit pouvoir s'adapter : une CarteProduit doit afficher un produit différent à chaque usage. Pour ça, le parent lui passe des données via les props (propriétés), qu'on déclare dans l'enfant avec defineProps.

Le parent passe les props comme des attributs : une chaîne littérale (nom="Clavier") ou une donnée liée avec : (:prix="49", où la valeur est une expression). L'enfant les déclare avec defineProps (en précisant leur type, ce qui documente et valide) et les utilise comme n'importe quelle donnée dans son template. Un même composant, des contenus différents.

Le flux de données descendant

Règle fondamentale : les données circulent du parent vers l'enfant (one-way data flow, vu aussi dans le cours React). Un enfant ne doit pas modifier une prop reçue : elle appartient au parent, qui en est la source de vérité.

Pourquoi cette règle ? Parce qu'elle rend le flux de données prévisible : pour comprendre d'où vient une valeur, on remonte au parent, sans se demander si un enfant l'a modifiée en douce. Si un enfant a besoin de provoquer un changement, il demande au parent en émettant un événement (la leçon suivante). Données vers le bas, événements vers le haut.

Ne modifie jamais une prop dans l'enfant

Écrire props.prix = 99 dans l'enfant est une erreur : Vue affiche un avertissement en console, et le parent réécrasera la valeur au prochain rendu (la prop lui appartient). Si l'enfant a besoin d'une valeur locale dérivée d'une prop, il crée sa propre ref ou computed ; s'il doit changer la source, il émet un événement (leçon 5).

Insérer du contenu : les slots

Parfois, on veut qu'un composant accueille du contenu fourni par le parent (un panneau dont l'intérieur varie). C'est le rôle du slot : un emplacement, dans le template de l'enfant, où Vue insère ce que le parent met entre les balises.

Le <slot></slot> est un trou que le parent remplit : tout ce qu'il place entre <Panneau> et </Panneau> s'insère à cet endroit. C'est complémentaire des props : les props passent des données (des valeurs), les slots passent du contenu (du balisage). Ensemble, ils rendent un composant à la fois configurable et flexible.

Cas réel — le bouton unique d'un design system

Dans une vraie application, on ne réécrit pas un bouton à chaque page. On crée un seul composant BoutonUI qui reçoit des props pour se décliner : variante (primaire, secondaire, danger), taille, desactive… et un slot pour son libellé. Résultat : des dizaines de boutons cohérents partout dans le site, pilotés depuis un seul fichier. C'est le principe des bibliothèques comme Vuetify ou des design systems maison : props pour configurer, slot pour le contenu.

Penser en composants

Le réflexe à acquérir : découper une interface en petits composants à responsabilité unique (un principe vu dans le cours Design patterns). Un bouton, une carte, une barre de navigation deviennent chacun un composant réutilisable. On compose ensuite l'application en les assemblant. Une bonne découpe rend le code plus clair, testable et réutilisable — l'inverse d'un composant géant qui fait tout.

Pour aller plus loin — plusieurs slots et props affinées

Un composant peut exposer plusieurs slots nommés (par exemple un #header, un slot par défaut, un #footer pour une carte) que le parent remplit séparément. Un <slot> peut aussi contenir un contenu par défaut, affiché si le parent ne fournit rien. Côté props, on peut aller au-delà du type : valeur par défaut, prop required, validateur personnalisé. Ces raffinements rendent les composants vraiment robustes.

Glossaire

Composant
Brique d'interface réutilisable et autonome, définie dans un fichier .vue.
Parent / enfant
Un composant qui en utilise un autre est son parent ; celui utilisé est l'enfant.
Prop
Donnée passée du parent à l'enfant, déclarée avec defineProps.
defineProps
Macro de <script setup> qui déclare les props qu'un composant accepte (et leur type).
Flux descendant (one-way)
Les données vont du parent vers l'enfant ; l'enfant ne modifie pas ses props.
Slot
Emplacement du template de l'enfant où s'insère le contenu (balisage) fourni par le parent.
Source de vérité
Le composant qui possède une donnée ; les autres la reçoivent en lecture.

Récap et vérification

  • Un composant (.vue) s'importe et s'utilise comme une balise ; réutilisable à volonté.
  • Les props (defineProps) passent des données du parent à l'enfant ; on les transmet par attribut (nom="…" ou :prix="…").
  • Flux descendant : l'enfant ne modifie pas ses props (le parent est la source de vérité) ; pour changer, il émet un événement.
  • Les slots (<slot>) insèrent du contenu fourni par le parent.

Exercice 3Défi

Tu veux un composant Alerte qui affiche une icône d'avertissement puis un message libre (du HTML fourni par le parent). Props ou slot ? Écris le composant et un exemple d'usage.

Voir une solution

Un slot : le message est du contenu (potentiellement du balisage riche), pas une simple valeur. Le parent doit pouvoir y mettre n'importe quoi, donc on utilise un emplacement de contenu, pas une prop chaîne.

L'icône fixe est dans le composant ; le <slot> reçoit le message du parent, qui peut contenir du HTML (ici un <strong>). Si le message était une simple chaîne sans mise en forme, une prop conviendrait aussi ; mais pour du contenu libre, le slot est le bon choix.
