Module 1 · Les bases de Vue — Leçon 01

Découvrir Vue

~33 min Intermédiaire JavaScript requis

À la fin de cette leçon, tu sauras

  • expliquer ce qu'est Vue et sa philosophie ;
  • comprendre la réactivité (le DOM suit les données) ;
  • reconnaître un composant monofichier (SFC) ;
  • lire un premier exemple complet.
Sommaire de la leçon

Après le JavaScript et le HTML, construire une interface « à la main » (manipuler le DOM, écouter chaque événement, synchroniser l'affichage) devient vite fastidieux. Les frameworks automatisent ce travail. Vue est l'un des plus appréciés : réputé pour sa douceur d'apprentissage et son approche progressive. Si tu connais le cours React, tu retrouveras des idées communes, exprimées autrement.

Un framework progressif

La signature de Vue est d'être progressif (incrementally adoptable) : tu peux l'utiliser pour un petit bout de page (en l'ajoutant via une simple balise script), comme pour une application complète et complexe. Tu adoptes autant de Vue que ton projet en a besoin, et tu montes en puissance progressivement.

Cette philosophie le rend accessible : pas besoin de tout réécrire pour commencer. Vue se concentre sur la couche « vue » (l'affichage), et son écosystème officiel (routage, gestion d'état) s'ajoute quand on en a besoin, sans imposer de tout adopter d'un coup. C'est un framework qui grandit avec toi.

La réactivité : le DOM suit les données

L'idée centrale de Vue (et des frameworks modernes) est la réactivité : tu décris l'interface en fonction de tes données, et quand les données changent, Vue met à jour l'affichage automatiquement. Fini de chercher l'élément du DOM et de le modifier à la main.

C'est un changement de mentalité : au lieu de dire comment mettre à jour le DOM étape par étape (impératif), on déclare à quoi l'interface doit ressembler selon l'état (déclaratif), et le framework fait le lien. Moins de code, moins de bugs de synchronisation. C'est la promesse commune à Vue, React et leurs pairs.

Le composant monofichier (SFC)

En Vue, on construit l'interface avec des composants (des briques réutilisables, leçon 4). La façon la plus courante de les écrire est le composant monofichier (Single-File Component, fichier .vue) : il regroupe en un seul fichier la structure, la logique et le style d'un composant.

Trois blocs : <script setup> contient la logique (les données, les fonctions), <template> décrit le HTML affiché (avec la réactivité), et <style scoped> le style (limité à ce composant). Tout ce qui concerne un composant vit au même endroit : c'est lisible et facile à maintenir. Le scoped garantit que le style ne « déborde » pas sur le reste de l'application.

Cas réel — qui utilise Vue ?

Vue a été créé en 2014 par Evan You, alors chez Google : il voulait isoler « la partie qui lui plaisait dans Angular » pour en faire un outil léger. Aujourd'hui, l'interface de GitLab — l'une des plus grandes applications web open source — est bâtie avec Vue, tout comme des pans des sites de Nintendo, BMW ou Louis Vuitton. Son caractère progressif explique ce succès : on peut l'introduire sur une seule page d'un site existant, puis l'étendre. C'est aussi le socle de Nuxt, le framework de rendu côté serveur pour Vue.

Composition API et Vite

Ce cours utilise Vue 3 et la Composition API avec <script setup> — le style recommandé aujourd'hui (concis et bien adapté à TypeScript). Il existe aussi l'Options API, plus ancienne (leçon 6). Pour démarrer un vrai projet, l'outil officiel Vite crée une application Vue prête à l'emploi en une commande : npm create vue@latest. Tu n'as pas besoin de tout installer pour comprendre les exemples de ce cours : lis-les comme du pseudo-code Vue.

Glossaire

Framework
Ensemble d'outils qui automatise la construction d'interfaces (mise à jour du DOM, gestion des événements…).
Progressif
Adoptable par étapes : d'une simple balise sur une page jusqu'à une application complète.
Réactivité
Mécanisme par lequel l'affichage se met à jour automatiquement quand une donnée change.
Déclaratif
On décrit à quoi l'interface doit ressembler selon l'état (par opposition à impératif, qui décrit chaque étape).
Composant monofichier (SFC)
Fichier .vue réunissant <script setup>, <template> et <style scoped>.
ref
Fonction qui crée une donnée réactive ; on lit et écrit sa valeur via .value en JavaScript.
Composition API
Style d'écriture des composants Vue 3 avec <script setup>, concis et adapté à TypeScript.
Vite
Outil officiel qui crée et sert un projet Vue (npm create vue@latest).

Récap et vérification

  • Vue est un framework progressif : on l'adopte par petites touches ou pour une app complète.
  • Réactivité : on décrit l'interface en fonction des données ; quand elles changent, le DOM se met à jour automatiquement (déclaratif).
  • Un composant monofichier (.vue) regroupe <script setup> (logique), <template> (HTML), <style scoped> (style).
  • Ce cours utilise Vue 3 + Composition API ; Vite crée un projet en une commande.

Exercices

Exercice 1Échauffement

Avec tes mots, explique la différence entre une approche impérative et déclarative pour mettre à jour un affichage.

Voir une solution

En impératif (sans framework), on décrit chaque étape de la mise à jour : « trouve l'élément, change son texte » à la main, à chaque changement. En déclaratif (avec Vue), on déclare à quoi l'interface doit ressembler selon l'état (par ex. afficher {{ compteur }}), et le framework se charge de mettre le DOM à jour quand l'état change. Le déclaratif réduit le code et les bugs de synchronisation.

Exercice 2Application

Dans l'exemple du compteur, qu'est-ce qui fait que le texte du bouton se met à jour quand on clique ?

Voir une solution

Trois choses combinées : 1) compteur est une donnée réactive (créée avec ref(0)) ; 2) le @click="incrementer" appelle la fonction qui fait compteur.value++ au clic ; 3) le template affiche {{ compteur }}, donc lié à cette donnée. Quand compteur change, Vue détecte le changement (réactivité) et met à jour automatiquement le texte affiché. On ne touche jamais le DOM directement.

Exercice 3Défi

Pourquoi le bloc <style scoped> d'un composant est-il utile dans une grande application ?

Voir une solution

L'attribut scoped limite le style au composant où il est défini : les règles CSS n'affectent que les éléments de ce composant, pas le reste de l'application. Dans une grande application avec des dizaines de composants, c'est précieux : on évite les collisions de styles (une règle p { color: teal } qui colorerait par accident tous les paragraphes du site). Chaque composant gère son apparence sans risque d'interférer avec les autres ; on peut réutiliser et déplacer un composant sans craindre que son style casse ailleurs. C'est l'équivalent, pour le CSS, de l'isolation qu'apportent les composants pour la logique.
