Module 1 · Les bases de Vue — Leçon 02

Le template et les directives

~37 min Intermédiaire Leçon 01 requise

À la fin de cette leçon, tu sauras

  • interpoler des données dans le template ({{ }}) ;
  • lier un attribut avec v-bind ;
  • afficher conditionnellement avec v-if/v-show ;
  • répéter avec v-for et ses clés.
Sommaire de la leçon

Le template est le HTML d'un composant, enrichi par Vue. Il ressemble à du HTML normal, mais avec deux superpouvoirs : l'interpolation (insérer des données) et les directives (des attributs spéciaux préfixés de v- qui ajoutent un comportement). Cette leçon couvre les directives que tu utiliseras le plus.

L'interpolation

Pour afficher une donnée dans le texte, on l'entoure de doubles accolades (la « moustache »). Vue remplace l'expression par sa valeur, et la maintient à jour automatiquement.

Entre les accolades, on met une expression JavaScript (pas une instruction) : une variable, un calcul, un appel de méthode. Vue l'évalue et affiche le résultat. Dès qu'une donnée utilisée change, l'affichage suit — c'est la réactivité de la leçon 1. La moustache ne s'utilise que dans le texte ; pour les attributs, on a v-bind.

Lier un attribut : v-bind

Pour rendre un attribut HTML dynamique (sa valeur vient d'une donnée), on utilise la directive v-bind, presque toujours écrite avec son raccourci : les deux-points (:).

Différence clé avec l'interpolation : {{ }} sert au contenu texte, :attribut sert aux attributs. Avec :src="cheminImage", la valeur de l'attribut src est l'expression cheminImage (une donnée), pas le texte littéral. Le :disabled="enChargement" montre la puissance : l'attribut s'active ou non selon un booléen réactif.

Piège fréquent

Réflexe fréquent quand on vient d'un autre outil : écrire <img src="{{ cheminImage }}">. Vue 3 refuse l'interpolation à l'intérieur d'un attribut, et le compilateur affiche une erreur qui te renvoie explicitement vers v-bind. Retiens la frontière : les moustaches ne remplissent que le texte d'un élément ; pour une valeur d'attribut, c'est :src="cheminImage".

Afficher sous condition : v-if et v-show

Pour afficher un élément seulement si une condition est vraie, deux directives : v-if (et ses compagnons v-else-if, v-else) et v-show.

La nuance : v-if ajoute ou retire réellement l'élément du DOM (idéal si la condition change rarement) ; v-show garde l'élément dans le DOM mais le masque en CSS (display:none), ce qui est plus efficace si on bascule souvent l'affichage. Règle pratique : v-if par défaut ; v-show pour ce qu'on montre/cache fréquemment (un menu, un panneau).

Répéter avec v-for

Pour afficher une liste à partir d'un tableau, on utilise v-for. On y associe une clé unique (:key), indispensable pour que Vue suive efficacement chaque élément.

La syntaxe élément in tableau répète le balisage pour chaque entrée. La :key doit être unique et stable (l'identifiant de chaque élément, pas l'index si la liste peut changer d'ordre) : elle permet à Vue de réutiliser intelligemment les éléments du DOM lors des mises à jour, au lieu de tout recréer. Oublier :key est l'erreur classique ; elle provoque des bugs subtils d'affichage.

Cas réel — la case à cocher qui change de ligne

Une liste de tâches affichée avec v-for utilise l'index comme clé (:key="i"). Chaque ligne a une case à cocher. Tout va bien… jusqu'à ce qu'on supprime la première tâche : soudain, la case cochée « saute » sur une autre ligne. La raison : après suppression, les index se décalent, et Vue — qui identifie les éléments par leur clé — croit que la ligne d'index 0 est la même qu'avant, alors que son contenu a changé. En passant à :key="tache.id" (un identifiant stable), le bug disparaît. C'est l'un des pièges les plus fréquents avec les listes, en Vue comme en React.

Les directives, en un coup d'œil

Une directive est un attribut spécial commençant par v- qui dit à Vue d'appliquer un comportement à l'élément. Tu en connais déjà les principales : v-bind (:) lie un attribut, v-if/v-show conditionnent l'affichage, v-for répète, et v-on (@, leçon 5) écoute les événements. Il en existe d'autres (v-model, v-html…), mais ces quatre-là couvrent l'essentiel des templates.

Glossaire

Template
Le HTML d'un composant, enrichi par l'interpolation et les directives de Vue.
Interpolation
Insertion d'une donnée dans le texte via les doubles accolades {{ }}.
Directive
Attribut spécial préfixé de v- qui applique un comportement à l'élément.
v-bind (:)
Lie la valeur d'un attribut HTML à une donnée réactive.
v-if / v-show
Affichage conditionnel : v-if ajoute/retire du DOM, v-show masque en CSS.
v-for
Répète un élément pour chaque entrée d'un tableau (x in liste).
:key
Identifiant unique et stable qui permet à Vue de suivre chaque élément d'une liste.
Expression
Bout de JavaScript évalué dans le template (variable, calcul, appel de méthode) ; pas une instruction.

Récap et vérification

  • Interpolation {{ expression }} : affiche une donnée (ou une expression JS) dans le texte.
  • v-bind (raccourci :) : lie un attribut à une donnée (:src, :disabled…).
  • v-if/v-else (ajoute/retire du DOM) vs v-show (masque en CSS) : condition d'affichage.
  • v-for répète sur un tableau ; toujours une :key unique et stable.

Vérifie ta compréhension

  1. Quand utilise-t-on {{ }} et quand utilise-t-on :attribut ?
  2. Quelle différence entre v-if et v-show ?
  3. Pourquoi faut-il une :key avec v-for ?

Exercices

Exercice 1Échauffement

Dans un template, affiche le texte « Prix : X € » où X est la donnée prix, et lie l'attribut title d'un élément à la donnée info.

Voir une solution

{{ prix }} pour le texte, :title="info" (v-bind) pour l'attribut.

Exercice 2Application

Affiche une liste <li> de tâches à partir d'un tableau taches (chaque tâche a un id et un titre), avec la clé appropriée.

Voir une solution

On itère avec v-for et on fournit :key="tache.id" (l'identifiant unique et stable de chaque tâche).

Exercice 3Défi

Un panneau de notification doit s'afficher/se masquer très souvent quand l'utilisateur clique. v-if ou v-show ? Justifie, et écris le template.

Voir une solution

v-show : comme on bascule l'affichage fréquemment, mieux vaut garder l'élément dans le DOM et le masquer/montrer en CSS (display:none), plutôt que de le détruire et le recréer à chaque fois (ce que ferait v-if, plus coûteux pour des bascules répétées).

Règle générale : v-show pour ce qu'on montre/cache souvent ; v-if pour des conditions qui changent rarement, ou pour ne carrément pas rendre l'élément quand il est inutile.

Exercice 4Au clavier

v-for combiné à un filtre se prépare dans le script, pas dans le template. Écris rendre(taches) qui rend les libellés des tâches non faites, séparés par une virgule et une espace, pour [{texte:'Pain', fait:false}, {texte:'Appeler', fait:true}, {texte:'Lait', fait:false}], et affiche le résultat.
