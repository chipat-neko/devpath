Module 2 · Programmer avec méthode — Leçon 06

Enregistrements et types

~51 min Intermédiaire Prérequis : leçon 5

À la fin de cette leçon, tu sauras

  • regrouper des champs dans un record ;
  • définir des types énumérés ;
  • créer des sous-domaines (intervalles) ;
  • donner des noms à ses types avec type.
Sommaire de la leçon

Les types de base (integer, string…) suffisent pour des données simples. Mais le monde réel a des structures plus riches : une fiche contient un nom et un âge et une ville ; une couleur ne prend que quelques valeurs précises. Pascal brille ici : il permet de définir ses propres types, parfaitement adaptés au problème. Cette capacité — créer le vocabulaire de son programme — est l'une des grandes leçons que Pascal enseigne. Au menu : les enregistrements, les types énumérés et les sous-domaines.

La section type

Avant de créer des structures, sachons nommer un type. La section type donne un nom à un type, qu'on réutilise ensuite. C'est plus lisible et évite les répétitions.

Par convention, on préfixe souvent les noms de types par T (héritage de Delphi). Ce n'est pas obligatoire, mais c'est une habitude répandue qui aide à repérer les types.

Nommer par le domaine

Baptise tes types d'après ce qu'ils représentent (TCouleur, TNote, TPersonne), pas d'après leur implémentation. Un nom parlant transforme la déclaration note : TNote en documentation vivante : on sait tout de suite ce que la variable peut contenir.

Les enregistrements : regrouper des champs

Un enregistrement (record) rassemble plusieurs champs, possiblement de types différents, sous un même nom. C'est l'outil pour modéliser une « chose » avec plusieurs attributs.

On accède à un champ avec un point : p.nom, p.age. Un record se manipule comme un tout : on peut affecter p2 := p pour copier tous les champs d'un coup, ou passer un record entier à une procédure.

L'instruction with

Quand on touche plusieurs champs d'un même record, with évite de répéter son nom.

Les types énumérés

Un type énuméré liste explicitement toutes ses valeurs possibles. Idéal quand une donnée ne peut prendre que quelques états nommés : un jour, une couleur, une direction.

L'avantage est immense pour la lisibilité et la sûreté : feu := Rouge est bien plus clair que feu := 0, et le compilateur interdit d'affecter une valeur hors de la liste. On ne peut pas se tromper de couleur. Les énumérés s'utilisent aussi dans un case ou une boucle for.

Les sous-domaines

Un sous-domaine restreint un type ordinal à une plage de valeurs valides. 0..20 n'accepte que les entiers de 0 à 20 : parfait pour une note, une heure, un pourcentage.

Comme en Ada, la contrainte est portée par le type lui-même : nul besoin de vérifier partout, le compilateur (et l'exécution) garantit que la valeur reste valide.

Composer les types

La vraie puissance vient de la composition : un tableau de records, un record contenant un tableau ou un énuméré… On bâtit ainsi des modèles de données complexes mais clairs.

Cas réel : la fiche d'un contact

Une application de carnet d'adresses modélise chaque contact par un record : nom, email, telephone, favori (boolean). Un array de ces records forme le carnet entier. Besoin d'ajouter un champ « anniversaire » ? Une seule ligne dans le type, et tout le programme en profite. Le record fait correspondre la structure du code à la structure du réel — la marque d'un bon modèle de données.

Pièges fréquents

Piège fréquent

Vouloir afficher directement une valeur énumérée avec writeln(feu) : en Pascal standard, cela ne fonctionne pas, car l'énuméré est représenté en interne par un numéro, pas par son nom. Pour afficher « Rouge », il faut un case qui traduit chaque valeur en texte. Les valeurs énumérées servent à raisonner clairement dans le code, pas à être imprimées telles quelles.

Pour aller plus loin

Pour aller plus loin

L'idée de définir ses propres types adaptés au problème — au lieu de tout coder avec des entiers et des chaînes — est une marque de maturité en programmation. Un type TCouleur rend impossible une couleur invalide ; un sous-domaine TNote empêche une note de 25. On parle de « rendre les états illégaux irreprésentables », un principe puissant que Pascal enseigne naturellement et que l'on retrouve dans les langages typés les plus modernes.

Glossaire

Section type
Zone où l'on nomme ses propres types, réutilisables ensuite dans var ou d'autres types.
Enregistrement (record)
Type composite qui regroupe plusieurs champs, possiblement de types différents, sous un même nom.
Champ
Élément nommé d'un record, atteint avec un point (p.age).
Instruction with
Raccourci qui ouvre un record pour accéder à ses champs sans répéter son nom.
Type énuméré
Type dont on liste explicitement toutes les valeurs nommées (Rouge, Vert…) ; sûr et lisible.
Ordinal (ord)
Numéro interne d'une valeur énumérée, attribué dans l'ordre de déclaration (Rouge=0).
Sous-domaine
Restriction d'un type ordinal à une plage (0..20) ; le compilateur garantit que la valeur y reste.
Composition
Assemblage de types (tableau de records, record contenant un tableau…) pour modéliser des données riches.

Récap et vérification

  • La section type nomme des types réutilisables (convention T…).
  • Record : regroupe des champs nommés (accès par p.champ) ; with évite la répétition.
  • Énuméré : liste de valeurs nommées, lisibles et sûres.
  • Sous-domaine (0..20) : restreint une plage valide ; les types se composent librement.

Vérifie ta compréhension

  1. Comment accède-t-on à un champ d'un record ?
  2. Quel intérêt à un type énuméré plutôt qu'à des entiers ?
  3. Que garantit un sous-domaine 0..20 ?
