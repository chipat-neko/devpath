Les ensembles & les énumérations

~48 min Intermédiaire Prérequis : leçons 02 & 03 conseillées

À la fin de cette leçon, tu sauras

  • définir un type énuméré et jouer avec son ordre (Ord, Succ, Pred) ;
  • restreindre une plage avec un sous-domaine (0..9) ;
  • construire des ensembles et les combiner (+, *, -) ;
  • tester l'appartenance avec in pour un code plus sûr.
Sommaire de la leçon

Pascal offre des types énumérés et des ensembles d'une élégance rare, hérités des idées de Niklaus Wirth. Plutôt que de manipuler des entiers « magiques » dont personne ne se rappelle la signification, tu nommes tes valeurs et tu laisses le compilateur veiller sur elles. Le résultat : un code plus lisible (on lit Lundi au lieu de 0) et plus sûr (le compilateur refuse une valeur hors du domaine). Cette leçon te fait découvrir ces types qui rapprochent le code du langage humain.

Les types énumérés

Un type énuméré liste, une fois pour toutes, l'ensemble des valeurs possibles d'une variable — chacune portant un nom. On les déclare entre parenthèses :

Ces valeurs ne sont pas seulement nommées : elles sont ordonnées. En interne, chaque nom reçoit un rang (un ordinal) qui commence à 0 : Lundi vaut 0, Mardi vaut 1, … Dimanche vaut 6. Mais tu n'écris jamais ces nombres : tu manipules les noms, et le compilateur s'occupe du reste.

L'ordre : Ord, Succ, Pred, Low, High

Puisque les valeurs sont ordonnées, Pascal fournit des fonctions d'ordinal pour naviguer :

Ord renvoie le rang ; Succ et Pred donnent la valeur suivante et précédente ; Low et High renvoient la première et la dernière valeur du type. Attention : Succ(Dimanche) déborde du domaine — comme Pred(Lundi).

Bannis les « nombres magiques »

Chaque fois que tu es tenté d'écrire if statut = 3 ou couleur := 2, demande-toi si un type énuméré ne serait pas plus clair (TStatut = (EnAttente, Validee, Expediee, Livree)). Le code se relit six mois plus tard sans commentaire, et une valeur invalide devient impossible à écrire.

Les sous-domaines (sous-intervalles)

Le sous-domaine hérite de l'ordre du type parent (entiers, caractères, ou un énuméré). Il documente l'intention (« un chiffre », pas « n'importe quel entier ») et permet un contrôle de bornes : dépasser la plage est signalé.

Les ensembles : set of

Un ensemble (set of) est une collection non ordonnée et sans doublon de valeurs prises dans un type de base ordinal. On le construit avec des crochets :

Les crochets [ ] énumèrent les membres ; [Lundi..Vendredi] utilise même un sous-intervalle. L'ensemble vide s'écrit []. En mémoire, un set of est représenté de façon très efficace, en bits : un bit par valeur possible du type de base (présent = 1, absent = 0), d'où des opérations quasi instantanées.

Combiner les ensembles : +, *, -

Trois opérateurs combinent les ensembles, exactement comme en mathématiques :

+ réunit, * garde les éléments communs, - retire de l'un ceux de l'autre. Le tout reste un ensemble : pas de doublon, pas d'ordre imposé.

Appartenance et inclusion : in, <=, >=

La star des ensembles est l'opérateur in, qui teste si une valeur appartient à un ensemble — de façon très lisible :

x in E renvoie True si x est membre de E. Les opérateurs <= et >= testent l'inclusion (sous-ensemble / sur-ensemble), et = l'égalité de deux ensembles. Le test c in ['0'..'9'] remplace avantageusement un long (c >= '0') and (c <= '9').

Cas réel : les jours d'ouverture d'un commerce et les permissions d'une appli

Imagine un logiciel de caisse qui doit savoir si le magasin est ouvert. Avec des booléens séparés (ouvertLundi, ouvertMardi, … ouvertDimanche), tu multiplies les variables et les if. Un simple ensemble JoursOuverture : set of TJour := [Lundi..Samedi] dit tout, et le test tient en une ligne : if AujourdHui in JoursOuverture then Ouvrir. Même logique pour les permissions d'une application : Droits : set of TPermission := [Lire, Ecrire] remplace élégamment cinq booléens, et vérifier un droit devient if Ecrire in Droits then …. Plus clair à lire, plus court à écrire, et impossible d'oublier un cas.

Pièges fréquents

Piège fréquent

Un type de base d'ensemble doit être ordinal et de faible étendue : set of char passe, mais set of integer est refusé (trop de valeurs possibles). Autre confusion classique : Ord attend une valeur ordinale, pas un ensemble — on n'écrit pas Ord([Lundi]). Et n'oublie pas les parenthèses avec not : écris not (x in E), car sans elles la priorité des opérateurs peut surprendre.

Pour aller plus loin

Pour aller plus loin

Les énumérations de Pascal ont essaimé partout : on retrouve les enum en C, C#, Java ou Rust, et l'idée d'un ensemble de drapeaux (flags) manipulé par bits est un grand classique. Là où Pascal brille, c'est en offrant le set of comme type de première classe, avec une syntaxe mathématique (+, *, -, in) et une implémentation en bits automatique : ce que d'autres langages font « à la main » avec des masques binaires, Pascal l'exprime lisiblement.

Glossaire

Type énuméré
Type dont on liste explicitement toutes les valeurs nommées et ordonnées : (Lundi, Mardi, …).
Ordinal
Valeur associée à un rang entier. Ord donne ce rang (le premier vaut 0).
Succ / Pred
Fonctions qui renvoient la valeur suivante et précédente d'un type ordinal.
Low / High
Fonctions donnant la première et la dernière valeur d'un type ou d'un tableau.
Sous-domaine
Type restreint à une plage contiguë d'un type ordinal, noté avec .. (ex. 0..9).
Ensemble (set of)
Collection non ordonnée, sans doublon, de valeurs d'un type de base ; représentée en bits.
Appartenance (in)
Opérateur testant si une valeur est membre d'un ensemble : x in E.
Union / intersection / différence
Combinaisons d'ensembles avec + (tout), * (commun) et - (retrait).

Récap et vérification

  • Un type énuméré nomme et ordonne ses valeurs ; Ord, Succ, Pred, Low, High les manipulent.
  • Un sous-domaine (0..9) borne une plage et fait contrôler les dépassements.
  • Un ensemble (set of) se combine avec + (union), * (intersection), - (différence).
  • in teste l'appartenance ; ces types rendent le code plus lisible et plus sûr que des entiers ou des booléens épars.

Exercice 3Défi

Voir une solution

L'union réunit tous les éléments ; l'intersection ne garde que 3 et 4 (présents des deux côtés) ; la différence A - B conserve 1 et 2, présents dans A mais pas dans B.
