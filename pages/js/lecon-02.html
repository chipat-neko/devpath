Variables, types et valeurs

~33 min Débutant Leçon 01 recommandée

À la fin de cette leçon, tu sauras

  • Savoir déclarer et réassigner une variable avec let, et choisir const pour ce qui ne change pas ;
  • Savoir nommer correctement ses variables en camelCase et reconnaître les types primitifs (string, number, boolean, undefined, null) ;
  • Savoir utiliser l'opérateur typeof pour inspecter le type d'une valeur, y compris ses pièges ;
  • Savoir modéliser une donnée simple (une tâche) à l'aide de variables bien choisies.
Sommaire de la leçon

Dans la leçon précédente, tu as écrit tes premières instructions et affiché des messages avec console.log. C'est utile, mais un programme qui ne fait qu'afficher des textes figés reste très limité. Pour qu'il devienne vraiment intéressant, il doit pouvoir retenir des informations : un âge, un prénom, un état « fait / pas fait »… et les réutiliser plus loin.

C'est exactement le rôle des variables. Dans cette leçon, tu vas apprendre à créer des variables, à les nommer proprement, à connaître les grandes familles de valeurs (les types) et à inspecter ces valeurs avec typeof. À la fin, tu sauras modéliser une donnée concrète : une tâche de notre futur gestionnaire.

Qu'est-ce qu'une variable ?

Imagine une boîte étiquetée dans laquelle tu ranges une valeur. La boîte porte un nom (l'étiquette) ; à l'intérieur, il y a un contenu (la valeur). Quand tu as besoin du contenu, tu prononces le nom de la boîte, et JavaScript va chercher ce qu'il y a dedans.

Pour créer une variable, on la déclare avec le mot-clé let, on lui donne un nom, puis on lui affecte une valeur avec le signe =.

Lis cette ligne ainsi : « crée une boîte nommée age et mets-y la valeur 25 ». Le signe = n'est pas le « égal » des mathématiques : c'est une affectation, c'est-à-dire l'action de ranger une valeur à droite dans la boîte à gauche.

L'intérêt d'une variable déclarée avec let, c'est qu'on peut changer son contenu plus tard. On parle alors de réassignation. Remarque : pour réassigner, on ne réécrit pas let (la boîte existe déjà).

Note

Chaque instruction se termine par un point-virgule ;. Ce n'est pas toujours obligatoire en JavaScript, mais c'est une excellente habitude : tes intentions restent claires et tu évites certains pièges subtils.

let vs const

À côté de let, il existe const. La différence tient en une phrase : une variable déclarée avec const ne peut pas être réassignée. Tu la fixes une fois, et c'est définitif. Conséquence : une const doit recevoir sa valeur au moment de sa déclaration.

Astuce

La règle d'or : const par défaut, et passe à let seulement quand tu sais que la valeur va changer. Tu rends ton intention lisible et tu réduis les bugs.

Tu croiseras parfois un troisième mot-clé, var, hérité de l'ancien JavaScript. On l'évite aujourd'hui : sa portée (la zone du code où la variable existe) réserve des surprises désagréables, car elle ignore les blocs { }. Retiens simplement « const et let oui, var non » ; on reverra la notion de portée en détail plus tard.

Bien nommer ses variables

Un bon nom de variable raconte ce qu'elle contient. x ne dit rien ; nomComplet se comprend en un coup d'œil. Quelques règles à connaître :

  • La convention en JavaScript est le camelCase : on colle les mots et on met une majuscule au début de chaque mot sauf le premier, comme nomComplet ou estMajeur.
  • Choisis des noms parlants : prix plutôt que p, nombreEssais plutôt que n.
  • JavaScript est sensible à la casse : age et Age sont deux variables différentes.
  • Interdit d'utiliser un mot réservé du langage comme nom (par exemple let, const, return).
  • Un nom ne peut pas commencer par un chiffre : 1prix est invalide, mais prix1 fonctionne.

Les types primitifs

Une valeur appartient toujours à un type, c'est-à-dire une famille. Les types de base, dits primitifs, sont peu nombreux et tu les utiliseras tous les jours.

  • string (chaîne de caractères) : du texte, entre guillemets doubles "texte" ou simples 'texte'.
  • number (nombre) : 42, 3.14, -7. Un seul type pour les entiers et les décimaux.
  • boolean (booléen) : seulement deux valeurs, true (vrai) ou false (faux).
  • undefined : une variable déclarée mais à laquelle on n'a pas encore donné de valeur.
  • null : un « vide volontaire », une absence de valeur que toi tu décides de mettre.

La nuance entre undefined et null est importante : undefined signifie « personne n'a encore rempli la boîte », tandis que null signifie « j'ai délibérément mis du vide ici ».

Note

Il existe deux autres types primitifs plus avancés : bigint (pour des nombres entiers gigantesques) et symbol (pour des identifiants uniques). Tu n'en auras pas besoin avant un moment ; je les mentionne juste pour que les noms ne te surprennent pas plus tard.

Inspecter une valeur avec typeof

Comment savoir de quel type est une valeur ? L'opérateur typeof répond à cette question : il renvoie le nom du type, sous forme de chaîne de caractères.

C'est un outil précieux pour déboguer : quand un calcul donne un résultat bizarre, vérifier le type avec typeof révèle souvent le problème (par exemple un nombre qui était en réalité du texte).

Cas réel

Sur un vrai formulaire web, la valeur saisie dans un champ « âge » arrive toujours sous forme de texte : tu obtiens "25" (une chaîne), pas 25 (un nombre). D'innombrables bugs viennent de là : 25 + 3 donne 28, mais "25" + 3 donne "253" (une concaténation) ! Le réflexe des développeurs face à un résultat incohérent : ajouter un console.log(typeof valeur) pour vérifier qu'on manipule bien le type attendu.

Piège fréquent

typeof null renvoie "object", et non "null". C'est un bug historique de JavaScript, conservé depuis les origines pour ne pas casser le web existant. Retiens simplement que null est une exception : ne te fie pas à typeof pour le détecter.

Confondre = (affectation, « range cette valeur ») et == (comparaison, « est-ce égal ? »). Dans let estMajeur = age >= 18;, le premier = range le résultat, il ne compare rien. On reverra les comparaisons en détail bientôt.

Pour aller plus loin

Les valeurs primitives ont une propriété essentielle : elles sont copiées quand on les affecte à une autre variable. Chaque boîte possède donc sa propre copie indépendante.

Pour aller plus loin

Ce comportement « par copie » est propre aux primitifs. Les objets et les tableaux, eux, fonctionnent « par référence » : plusieurs variables peuvent pointer vers la même boîte partagée, et modifier l'une affecte l'autre. C'est l'une des sources de bugs les plus classiques pour les débutants — on le verra en profondeur dans la leçon sur les objets.

Antisèche : variables et types

Le mémo à garder ouvert pendant tes premiers programmes.

Glossaire

Variable
Une « boîte » nommée qui retient une valeur réutilisable plus loin dans le programme.
Déclaration
La création d'une variable avec let ou const, qui réserve le nom.
Affectation
L'action de ranger une valeur dans une variable avec le signe = ; ce n'est pas l'égalité mathématique.
Réassignation
Remplacer le contenu d'une variable déjà déclarée (possible avec let, refusé avec const).
Type primitif
Une famille de valeurs de base : string, number, boolean, undefined, null (plus bigint et symbol).
typeof
Opérateur qui renvoie, sous forme de texte, le type d'une valeur — utile pour déboguer.
camelCase
Convention d'écriture des noms : mots collés, majuscule au début de chaque mot sauf le premier (nombreEssais).
Portée (scope)
La zone du code où une variable existe et est utilisable ; on l'étudiera en détail plus loin.

Récap et vérification

  • On déclare une variable avec let (réassignable) ou const (fixée une fois) ; règle d'or : const par défaut.
  • Le signe = est une affectation, pas une égalité mathématique.
  • On nomme en camelCase, avec des noms parlants ; JavaScript est sensible à la casse.
  • Les types primitifs courants : string, number, boolean, undefined, null.
  • typeof révèle le type d'une valeur, avec le piège célèbre typeof null //=> "object".
