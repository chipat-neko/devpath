Module 09 · Robustesse & outillage — Leçon 28

Map, Set et structures de données

~34 min Avancé Leçon 27 recommandée

À la fin de cette leçon, tu sauras

  • choisir entre tableau, objet, Map et Set selon le besoin (ordre, unicité, recherche par clé) ;
  • manipuler un Set pour garantir l'unicité et dédoublonner avec [...new Set(t)] ;
  • construire et parcourir une Map pour indexer des données et accéder à une valeur en O(1) ;
  • convertir entre Map, Set, objets et tableaux, et éviter les pièges de référence et de sérialisation.
Sommaire de la leçon

Jusqu'ici, tu as rangé tes données dans deux structures : le tableau, parfait pour une liste ordonnée que l'on parcourt, et l'objet littéral, pratique pour un enregistrement à clés connues. Tu connais aussi leurs méthodes (map, filter, find, la destructuration…). Ces deux outils couvrent beaucoup de cas, mais pas tous : comment garantir qu'une collection ne contient aucun doublon ? Comment associer une valeur à une clé qui n'est pas une chaîne ? Comment retrouver un élément par son identifiant sans relire tout le tableau ?

JavaScript propose deux structures faites pour ça : Set (collection de valeurs uniques) et Map (dictionnaire clé → valeur). Dans cette leçon, tu vas apprendre à les manipuler, à les convertir, et surtout à choisir la bonne structure selon le problème. À la fin, ton gestionnaire de tâches indexera ses tâches par identifiant et collectera l'ensemble de ses tags.

Set : une collection de valeurs uniques

Un Set est une collection qui n'accepte jamais deux fois la même valeur. On le construit à partir de n'importe quel itérable (souvent un tableau), et les doublons disparaissent automatiquement.

Les quatre opérations clés : add, has, delete, et la propriété size.

Un Set est itérable : tu peux le parcourir avec for...of, et il conserve l'ordre d'insertion.

L'usage le plus courant : dédoublonner un tableau. On enveloppe le tableau dans un Set (qui supprime les doublons), puis on le redéploie en tableau avec le spread [...] que tu connais déjà.

Astuce

Pour tester si un élément appartient à une grande liste de façon répétée, transforme-la une fois en Set puis utilise has. C'est bien plus rapide que d'appeler includes sur le tableau à chaque fois.

Cas réel

Pour compter les visiteurs uniques d'une page, un site glisse chaque identifiant de session dans un Set : peu importe combien de fois une même personne recharge, elle ne compte qu'une seule fois, et visiteurs.size donne le total distinct. C'est le même réflexe qui sert à dédoublonner une liste d'adresses e-mail avant un envoi groupé — pour ne jamais écrire deux fois à la même personne.

Map : des paires clé → valeur

Un Map associe des clés à des valeurs, comme un objet. La grande différence : une clé de Map peut être de n'importe quel type — un nombre, un booléen, voire un objet — alors que les clés d'un objet littéral sont toujours converties en chaînes.

Les méthodes miroir de l'objet : set, get, has, delete, et size.

On itère un Map avec for...of : chaque tour fournit une paire [cle, valeur] que l'on destructure directement. L'ordre d'insertion est garanti.

Note

Un Map se construit directement à partir d'un tableau de paires [[cle, valeur], …]. C'est exactement le format produit par Object.entries : on s'en servira pour convertir un objet en Map.

Map ou objet : lequel choisir ?

Visuellement, un Map et un objet se ressemblent. Mais le Map apporte quatre garanties que l'objet n'offre pas :

  • Ordre d'insertion fiable et explicitement spécifié, quel que soit le type des clés.
  • Clés de tout type (objets, nombres, booléens), pas seulement des chaînes.
  • Taille immédiate via size, sans devoir faire Object.keys(obj).length.
  • Aucune clé héritée : un Map vide est vraiment vide, alors qu'un objet porte des propriétés du prototype (comme toString), ce qui peut piéger un test d'appartenance.

Règle simple : si tes clés sont connues à l'avance et fixes (un enregistrement « utilisateur » avec nom, email…), garde un objet. Si les clés sont dynamiques et nombreuses (un dictionnaire qui grandit, une recherche par identifiant), prends un Map.

Convertir entre structures

Ces structures ne vivent pas en vase clos : tu passeras souvent de l'une à l'autre. Voici les conversions à connaître par cœur.

Object.entries/Object.fromEntries font le pont avec les objets ; le spread [...] fait le pont avec les tableaux.

Quand utiliser quoi

Le vrai savoir-faire de cette leçon, c'est de relier un besoin à une structure. Garde cette grille en tête :

  • Tableau : une liste ordonnée que l'on parcourt, filtre, transforme. Les doublons sont permis. C'est ta structure par défaut.
  • Objet : un enregistrement à clés connues et fixes, regroupant des champs hétérogènes ({ id, texte, faite }).
  • Map : un dictionnaire dynamique où l'on cherche une valeur par clé — typiquement un index « id → élément ».
  • Set : une question d'unicité ou d'appartenance — « cette valeur est-elle présente ? », « quelles sont les valeurs distinctes ? ».

Astuce

Pose-toi la question : « Ai-je besoin d'un ordre ? d'une unicité ? d'une recherche par clé ? » Les réponses te conduisent presque toujours directement à la bonne structure.

Pièges fréquents

Piège fréquent

Un Set compare les objets par référence, pas par valeur. new Set([{x:1}, {x:1}]) contient deux éléments, car ce sont deux objets distincts en mémoire. Pour dédoublonner par contenu, tu dois comparer une clé primitive (par exemple JSON.stringify de l'objet, ou un champ id).

Piège fréquent

Un Map n'est pas un objet : map.cle, Object.keys(map) ou JSON.stringify(map) ne font pas ce que tu crois. JSON.stringify(new Map([["a",1]])) renvoie "{}" ! Pour sérialiser un Map (avant un localStorage.setItem, par exemple), convertis-le d'abord : JSON.stringify([...map]) ou Object.fromEntries(map). Et get sur une clé absente renvoie undefined — pense à le gérer.

Pour aller plus loin

Pour aller plus loin

Il existe WeakMap et WeakSet : leurs clés (toujours des objets) sont faibles, c'est-à-dire que le ramasse-miettes peut les effacer si plus rien d'autre ne les référence. Pratique pour attacher des métadonnées à un objet sans empêcher sa libération mémoire. On ne peut ni les itérer ni connaître leur taille.

Côté performance : retrouver un élément par clé dans un Map coûte un temps constant O(1), alors que tableau.find(...) parcourt la liste jusqu'à trouver — un temps linéaire O(n). Sur quelques éléments, aucune différence ; sur des milliers de recherches répétées, l'index Map change tout.

Projet fil rouge — épisode 28

Ton gestionnaire stocke ses tâches dans un tableau taches d'objets { id, texte, faite }. Jusqu'ici, pour retrouver une tâche, tu écrivais taches.find((t) => t.id === id) — un parcours complet à chaque clic. On va indexer les tâches par identifiant dans un Map pour un accès direct.

taches.map((t) => [t.id, t]) produit le tableau de paires que le constructeur Map attend.

Ensuite, on enrichit les tâches de tags écrits dans le texte sous la forme #urgent. On extrait ces tags, puis on collecte l'ensemble des tags uniques du projet dans un Set.

flatMap aplatit les tableaux de tags de chaque tâche en une seule liste, que le Set dédoublonne.

Tu disposes maintenant d'un accès instantané à chaque tâche par son id et de la liste des tags distincts — la base idéale pour, plus tard, filtrer l'affichage par tag.

Glossaire

Set
Collection de valeurs uniques et itérable, sans doublon possible ; opérations add, has, delete, size.
Map
Dictionnaire clé → valeur dont les clés sont de n'importe quel type, avec ordre d'insertion garanti ; set, get, has, delete, size.
Unicité
Propriété d'une collection sans répétition ; garantie « gratuitement » par un Set.
Dédoublonner
Supprimer les valeurs répétées d'une liste ; idiome [...new Set(tableau)].
Index
Map construit pour retrouver un élément par une clé (souvent un id) sans reparcourir tout un tableau.
O(1) vs O(n)
Coût d'une recherche : constant (accès direct par clé dans un Map/Set) contre linéaire (parcours avec find/includes).
Égalité par référence
Pour un Set/Map, deux objets de même contenu restent distincts : ils n'occupent pas la même adresse mémoire.
Object.fromEntries
Convertit un Map (ou un tableau de paires) en objet littéral ; l'inverse de Object.entries.

Récap et vérification

  • Un Set stocke des valeurs uniques ; [...new Set(t)] dédoublonne un tableau.
  • add, has, delete, size pour le Set ; set, get, has, delete, size pour le Map.
  • Un Map accepte des clés de tout type, garde l'ordre d'insertion et s'itère en [cle, valeur].
  • Object.entries/Object.fromEntries convertissent objet ↔ Map ; le spread convertit vers un tableau.
  • Choisir : tableau (ordre), objet (clés fixes), Map (recherche dynamique), Set (unicité).

Vérifie ta compréhension

  2. Que renvoie JSON.stringify appliqué à un Map, et comment le sérialiser correctement ?
  3. Dans quel cas un index Map est-il nettement plus rapide qu'un tableau.find(...) ?
