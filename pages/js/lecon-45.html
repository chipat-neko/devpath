Module 14 · Le langage en profondeur — Leçon 45

Proxy et Reflect (métaprogrammation)

~38 min Avancé Leçon 02 recommandée

À la fin de cette leçon, tu sauras

  • savoir intercepter les opérations fondamentales d'un objet via new Proxy et ses trappes (get, set, has, apply, construct)
  • savoir déléguer le comportement standard à Reflect en préservant this grâce au recepteur
  • savoir bâtir des cas réels : valeurs par défaut, validation, objets réactifs et tableaux à index négatif
  • savoir éviter les pièges : invariants des proxys, perte de this, coût en performance et non-égalité proxy / cible.
Sommaire de la leçon

Tu sais déjà manipuler des objets : lire et écrire des propriétés, déléguer via la chaîne de prototypes, geler avec Object.freeze. Jusqu'ici, tu agissais sur les objets. Cette leçon t'apprend à agir sur le comportement même de ces opérations : que se passe-t-il, précisément, quand le moteur évalue obj.x, obj.y = 3 ou "z" in obj ? Avec Proxy, tu interposes ton propre code entre l'opération et son effet.

Tu débloques ainsi des patrons impossibles autrement : objets réactifs qui notifient leurs changements (le cœur de Vue 3), validation déclarative à l'écriture, propriétés calculées à la volée, API tolérantes aux clés absentes. Le tout en restant transparent pour le code appelant, qui croit manipuler un objet ordinaire.

Métaprogrammation : agir sur le langage

La métaprogrammation, c'est écrire du code qui observe ou modifie le comportement d'autre code à l'exécution. Tu en as déjà fait sans le nommer : les getters/setters, Object.defineProperty, ou Symbol.iterator sont des hooks dans la mécanique du langage. Proxy généralise ce principe : au lieu de personnaliser une seule propriété, tu interceptes n'importe quelle opération fondamentale (lecture, écriture, suppression, appel, new…) de façon uniforme.

Note

Chaque opération du langage correspond à une « méthode interne » de la spec ([[Get]], [[Set]], [[HasProperty]]…). Une trappe de Proxy n'est rien d'autre qu'un moyen de redéfinir l'une de ces méthodes internes.

new Proxy(cible, handler)

Un proxy enveloppe une cible (target). Le handler est un objet dont chaque méthode est une trappe (trap) interceptant une opération précise. Toute opération sans trappe correspondante est transmise telle quelle à la cible.

Sans trappe, un proxy se comporte exactement comme sa cible — mais reste un objet distinct.

La trappe get

La trappe get(cible, clef, recepteur) intercepte toute lecture. Le recepteur est l'objet sur lequel la lecture a démarré (le proxy lui-même, ou un objet qui en hérite). Premier cas d'usage : fournir une valeur par défaut pour une clé absente.

On délègue la lecture réelle à Reflect.get et on ne remplace que le cas « clé absente ».

Deuxième usage : la journalisation transparente des accès, utile en débogage ou pour tracer quelles propriétés un module consomme réellement.

La trappe set

set(cible, clef, valeur, recepteur) intercepte les affectations. Sa valeur de retour est sémantique : renvoyer une valeur fausse signale un échec, ce qui lève un TypeError en mode strict (le cas des modules ES, toujours stricts). On valide donc en refusant explicitement.

Reflect.set renvoie true/false selon le succès : on retourne directement son résultat.

Astuce

Retourne toujours Reflect.set(...) plutôt que true : si la cible est elle-même gelée ou possède un setter qui refuse, Reflect.set renvoie false et tu propages fidèlement l'échec au lieu de mentir.

Autres trappes utiles

Au-delà de get/set, le handler couvre toutes les opérations primitives. Les plus courantes :

has pilote in ; deleteProperty pilote delete.

Deux trappes ne s'appliquent qu'aux cibles appelables (fonctions) : apply(cible, ceci, args) intercepte l'appel f(...), et construct(cible, args, nouvelleCible) intercepte new F(...). Idéal pour mémoïser, tracer les appels ou injecter des contrôles avant instanciation.

Reflect.apply relaie l'appel avec son this et ses arguments d'origine.

Reflect : le comportement par défaut

Reflect est un objet (non constructible, sans new) qui expose une méthode par trappe : Reflect.get, set, has, deleteProperty, ownKeys, apply, construct… Chacune reproduit exactement l'opération standard correspondante. C'est le miroir du handler. À l'intérieur d'une trappe, tu l'utilises pour exécuter le comportement normal après ou avant ta logique.

Le bénéfice décisif tient au troisième argument de Reflect.get/set : le récepteur. Si la cible a un getter qui lit this, passer le récepteur garantit que this pointe vers le proxy (ou l'héritier appelant), pas vers la cible — la chaîne de délégation reste cohérente.

Sans transmettre recepteur, this.prenom vaudrait « Ada » : le getter perdrait l'objet appelant.

Note

La signature de chaque méthode Reflect est calquée sur sa trappe : les arguments arrivent dans le même ordre. Tu peux donc, dans la plupart des cas, écrire return Reflect.maTrappe(...arguments) pour un relais parfait.

Cas d'usage réels

Un objet réactif minimal : notifier un abonné à chaque écriture. C'est le principe exact de la réactivité moderne.

On ne notifie que si l'écriture a réussi et que la valeur change réellement.

Autre exemple parlant : des tableaux à index négatif, façon Python, où arr[-1] désigne le dernier élément.

Les méthodes natives (map, length…) continuent de fonctionner : elles passent par la branche Reflect.get standard.

Cas réel

La réactivité de Vue 3 est bâtie exactement sur ce patron. reactive(obj) renvoie un Proxy : la trappe get enregistre quel effet (rendu, computed) lit quelle propriété, et la trappe set redéclenche ces effets quand la valeur change. Écrire state.compteur++ dans un composant met à jour l'écran sans une seule ligne d'abonnement manuel — tout transite par les trappes. MobX (côté React) applique la même idée. C'est le cas d'usage industriel n° 1 de Proxy.

Pièges fréquents

Piège fréquent

Les invariants des proxys. Tu ne peux pas « mentir » sur une propriété non configurable et non writable de la cible : si get renvoie une valeur différente de celle réellement définie, le moteur lève un TypeError. De même, ownKeys doit lister toutes les clés non configurables. Les invariants garantissent qu'un proxy ne casse pas les hypothèses fondamentales du langage.

Piège fréquent

Perte de this et coût caché. Sans passer recepteur à Reflect, les getters et méthodes qui dépendent de this se brisent silencieusement. Attention aussi aux clés Symbol dans une trappe get : Number(clef) ou clef.startsWith(...) lèveront sur un Symbol — teste typeof clef === "string" avant. Par ailleurs, chaque opération traversant un proxy paie un surcoût : n'en mets pas sur du code chaud (boucles serrées, structures de données critiques). Enfin, p === cible vaut toujours false : un proxy n'est jamais identique à sa cible, ce qui peut piéger les comparaisons d'identité et les Map/WeakMap mixant les deux.

Pour aller plus loin

Pour aller plus loin

La réactivité de Vue 3 repose entièrement sur Proxy (paquet @vue/reactivity) : reactive() trace les lectures pour construire un graphe de dépendances, puis déclenche les effets aux écritures. Explore aussi Reflect.ownKeys (qui inclut les clés Symbol et non énumérables, contrairement à Object.keys) et les proxys révocables : Proxy.revocable(cible, handler) renvoie { proxy, revoke } ; après revoke(), toute opération sur le proxy lève un TypeError — pratique pour invalider un accès accordé temporairement (capacités, sécurité).

Antisèche : trappes et Reflect

Glossaire

Métaprogrammation
Écrire du code qui observe ou modifie le comportement d'autre code à l'exécution ; ici, intercepter les opérations fondamentales d'un objet.
Proxy
Objet qui enveloppe une cible et redirige les opérations vers les trappes d'un handler ; transparent pour le code appelant.
Cible (target)
Objet réel enveloppé par le proxy : il reçoit les opérations non interceptées et détient l'état.
Handler
Objet dont les méthodes sont les trappes ; toute trappe absente laisse l'opération passer telle quelle à la cible.
Trappe (trap)
Méthode du handler interceptant une opération précise (get, set, has, apply…).
Reflect
Objet exposant une méthode par trappe qui reproduit le comportement standard : le miroir du handler.
Récepteur (receiver)
Troisième argument de Reflect.get/set fixant le this des accesseurs ; préserve la chaîne d'héritage.
Invariant
Garantie du langage qu'un proxy ne peut pas violer (ex. renvoyer la vraie valeur d'une propriété non-configurable et non-inscriptible) ; sa violation lève un TypeError.

Récap et vérification

  • new Proxy(cible, handler) interpose des trappes entre une opération et son effet ; sans trappe, tout est délégué à la cible.
  • get, set, has, deleteProperty, apply, construct couvrent les opérations primitives ; set renvoie un booléen de succès.
  • Reflect est le miroir des trappes : appelle-le dans une trappe pour le comportement standard, en transmettant recepteur pour préserver this.
  • Attention aux invariants, à la perte de this, aux clés Symbol, au coût en perf, et au fait qu'un proxy n'est jamais === à sa cible.

Vérifie ta compréhension

  1. Pourquoi faut-il retourner Reflect.set(...) dans une trappe set plutôt que true en dur ?
  2. Quel rôle joue le troisième argument recepteur de Reflect.get, et que casse-t-on en l'omettant ?
  3. Cite un invariant qu'un Proxy ne peut pas violer, et explique pourquoi le langage l'impose.

Exercices

Exercice 1Échauffement

Écris zeroParDefaut(obj) qui renvoie un proxy : toute lecture d'une propriété numérique absente renvoie 0 au lieu de undefined ; les propriétés présentes se comportent normalement. Attention : une clé peut être un Symbol, ne le convertis pas en nombre.

Exercice 2Application
