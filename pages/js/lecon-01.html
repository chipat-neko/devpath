Module 01 · Fondations — Leçon 01

Prendre en main JavaScript

~30 min Débutant Aucun prérequis de code

À la fin de cette leçon, tu sauras

  • expliquer ce qu'est JavaScript et où il s'exécute ;
  • ouvrir la console du navigateur et y écrire du code ;
  • relier un fichier .js à une page HTML proprement ;
  • afficher des valeurs avec console.log() et commenter ton code.
Sommaire de la leçon

Pourquoi JavaScript ?

Une page web repose sur trois technologies complémentaires. Le HTML décrit le contenu (un titre, un paragraphe, un bouton). Le CSS décrit l'apparence (les couleurs, la mise en page). Le JavaScript, lui, décrit le comportement : ce qui se passe quand on clique, quand on tape du texte, quand des données arrivent.

Reprenons une image simple. Si une page web était une maison, le HTML serait les murs et les pièces, le CSS la peinture et la décoration, et le JavaScript l'électricité : les interrupteurs, qui rendent la maison vivante. Sans lui, une page reste un document figé ; avec lui, elle réagit.

JavaScript est le seul langage de programmation que tous les navigateurs comprennent nativement. C'est pour cela qu'il est incontournable, et un excellent premier langage : tu as déjà tout ce qu'il faut pour l'exécuter, dans l'onglet où tu lis cette page.

Note

« JavaScript » n'a rien à voir avec « Java », malgré le nom. Ce sont deux langages différents. Le nom a été choisi pour des raisons commerciales en 1995 ; le vrai nom standardisé du langage est ECMAScript.

Où s'exécute le code ?

Un langage a besoin d'un moteur pour exécuter ses instructions. Pour JavaScript, ce moteur est intégré au navigateur (par exemple V8 dans Chrome). Quand tu ouvres une page, le navigateur lit le HTML, applique le CSS, puis exécute le JavaScript.

Le même langage peut aussi tourner en dehors du navigateur, grâce à Node.js, qui embarque le moteur de Chrome pour exécuter du JS sur ton ordinateur ou un serveur. Mais pour ce cours, le navigateur suffit largement : tu n'as rien à installer.

Cas réel

La console n'est pas un jouet réservé à l'apprentissage : les développeuses et développeurs professionnels l'ouvrent tous les jours. Quand un bouton d'un vrai site ne réagit pas, le premier réflexe est d'ouvrir la console pour y lire les messages d'erreur en rouge et vérifier, avec un console.log, ce que contient telle ou telle valeur. C'est l'outil de diagnostic numéro un du métier.

Il existe donc deux endroits pratiques pour écrire ton premier code : la console du navigateur (pour tester vite), et un fichier .js relié à une page (pour conserver ton code). Voyons les deux.

Ta première ligne : la console

Chaque navigateur cache un bac à sable pour développeurs : les outils de développement. Leur onglet Console permet de taper du JavaScript et de voir le résultat immédiatement.

Pour l'ouvrir :

  1. fais un clic droit n'importe où sur une page, puis « Inspecter » ;
  2. clique sur l'onglet Console ;
  3. écris l'instruction ci-dessous, puis appuie sur Entrée.

La console affiche alors : Bonjour, le code !

Astuce

Raccourci pour ouvrir directement la console : F12 (ou Ctrl+Maj+J sur Windows, Cmd+Option+J sur Mac).

Relier un fichier .js à une page

La console est parfaite pour expérimenter, mais le code y disparaît dès qu'on recharge. Pour garder ton travail, on écrit le JavaScript dans un fichier séparé (par convention script.js) et on le relie à la page HTML avec la balise <script>.

Décortiquons l'attribut le plus important. src="script.js" indique où se trouve le fichier. L'attribut defer dit au navigateur : « télécharge le script pendant que tu lis la page, mais ne l'exécute qu'après avoir construit tout le HTML ». C'est ce qui évite la plupart des erreurs de débutant, où le code cherche un élément qui n'existe pas encore.

Piège fréquent

Ne mets pas de code à l'intérieur de la balise quand tu utilises src : <script src="script.js">...</script> ignore le contenu entre les balises. Une balise relie un fichier ou contient du code, pas les deux à la fois.

Afficher des valeurs avec console.log

console.log() est ton meilleur ami pour apprendre : il affiche dans la console tout ce qu'on lui passe entre les parenthèses. On s'en sert sans arrêt pour voir ce que fait le code.

Observe deux détails. Le texte est entouré de guillemets ("Salut !") : on parle de chaîne de caractères. Les nombres, eux, s'écrivent sans guillemets. Cette distinction reviendra dès la prochaine leçon, alors gardons-la en tête. Le symbole //=> dans nos exemples n'est pas du code : c'est une convention de ce cours pour montrer ce que la ligne produit.

Instructions, point-virgule et commentaires

Un programme est une suite d'instructions, exécutées de haut en bas, une par une. Chaque instruction se termine idéalement par un point-virgule ;. JavaScript pardonne souvent son oubli (il l'insère automatiquement), mais prendre l'habitude de le mettre évite des surprises plus tard.

Les commentaires sont des notes ignorées par le moteur. Ils servent à expliquer ton code (à toi-même, plus tard, ou à d'autres). Il en existe deux formes :

Note

JavaScript distingue les majuscules des minuscules : console.log fonctionne, mais Console.log ou console.Log déclenchent une erreur. La casse compte, toujours.

Pièges fréquents au démarrage

  • Oublier les guillemets autour du texte. console.log(Salut) provoque une erreur : sans guillemets, JavaScript croit que Salut est le nom d'une donnée, qu'il ne trouve pas. Écris console.log("Salut").
  • Confondre la console et la page. console.log n'écrit rien sur la page visible : le résultat apparaît uniquement dans la console des outils de développement.
  • Mauvais fichier ouvert. Pour voir l'effet d'un script.js, tu dois ouvrir la page HTML qui le relie, pas le fichier .js tout seul.
  • Guillemets « intelligents ». Un traitement de texte transforme " en “ ”. Le code exige des guillemets droits : utilise un éditeur de code, pas un logiciel de bureautique.

Pour aller plus loin

Pour aller plus loin

JavaScript évolue chaque année via la norme ECMAScript (ES2015, ES2016…). Quand tu liras « ES6 », il s'agit d'ECMAScript 2015, une version majeure qui a modernisé le langage. Nous utiliserons sa syntaxe tout au long du cours. Autre point : console propose d'autres méthodes utiles, comme console.warn() (avertissement) et console.error() (erreur), qui s'affichent avec une couleur différente.

Glossaire

JavaScript
Langage de programmation que tous les navigateurs comprennent nativement ; il décrit le comportement d'une page (interactions, calculs, mises à jour).
ECMAScript
Le nom officiel et standardisé du langage. Les versions (ES2015 alias ES6, ES2016…) ajoutent de nouvelles fonctionnalités chaque année.
Moteur JavaScript
Le composant qui lit et exécute le code (par exemple V8 dans Chrome). Il est intégré au navigateur et aussi embarqué par Node.js.
Console
Onglet des outils de développement du navigateur où l'on tape du JavaScript et où s'affichent les messages et les erreurs.
console.log()
Instruction qui affiche dans la console tout ce qu'on lui passe entre parenthèses ; l'outil de base pour voir ce que fait le code.
Attribut defer
Sur une balise <script>, il télécharge le fichier en parallèle et n'exécute le code qu'après l'analyse du HTML.
Instruction
Une action élémentaire du programme, exécutée de haut en bas et terminée idéalement par un point-virgule ;.
Commentaire
Note ignorée par le moteur (// ou /* … */), destinée à expliquer le code aux humains.

Récap et vérification

En résumé :

  • JavaScript décrit le comportement d'une page ; il s'exécute dans le navigateur (ou avec Node).
  • On teste vite dans la console, on conserve son code dans un fichier .js relié via <script src="…" defer>.
  • console.log() affiche des valeurs ; le texte va entre guillemets, pas les nombres.
  • Le code se lit de haut en bas ; les commentaires (// ou /* */) sont ignorés à l'exécution.

Vérifie ta compréhension

  1. Quelle est la différence de rôle entre HTML, CSS et JavaScript ?
  2. À quoi sert l'attribut defer sur une balise <script> ?
  3. Pourquoi console.log(Bonjour) échoue-t-il, alors que console.log("Bonjour") fonctionne ?
