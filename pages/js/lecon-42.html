Module 13 · Pour aller plus loin — Leçon 42

Stocker des données côté client

~36 min Avancé JSON et objets recommandés

À la fin de cette leçon, tu sauras

  • distinguer localStorage et sessionStorage (durée de vie, portée) ;
  • lire et écrire avec setItem, getItem, removeItem, clear ;
  • stocker des objets en les sérialisant avec JSON.stringify/parse ;
  • connaître les limites (quota, synchrone, même origine) et l'événement storage ;
  • savoir quand passer à IndexedDB et ce qu'il ne faut jamais y stocker.
Sommaire de la leçon

Recharge une page : par défaut, tout ce que ton JavaScript avait en mémoire disparaît. Comment un site retient-il alors ton thème sombre, le contenu de ton panier ou le brouillon d'un formulaire ? Grâce au stockage côté client — de petits coffres rangés dans le navigateur, propres à chaque site, qui survivent aux rechargements sans aucun serveur. Le plus simple s'appelle localStorage.

Deux coffres : localStorage et sessionStorage

Le navigateur offre deux boîtes à la même API, qui ne diffèrent que par leur durée de vie. localStorage persiste indéfiniment (jusqu'à effacement explicite) ; sessionStorage ne vit que le temps de l'onglet et disparaît à sa fermeture.

L'API : quatre méthodes, des paires clé → valeur

Le stockage fonctionne comme un dictionnaire : une clé (chaîne) pointe vers une valeur (chaîne). Quatre méthodes suffisent.

Attention

Tout est chaîne de caractères. setItem("age", 30) range en réalité "30", et getItem te rendra "30" (chaîne), pas 30. Une clé absente renvoie null — jamais undefined — pense à ce cas avant de l'utiliser.

Stocker autre chose qu'une chaîne : JSON

Comme le coffre n'accepte que des chaînes, on sérialise les objets et tableaux avec JSON.stringify avant d'écrire, et on les reconstruit avec JSON.parse après lecture. C'est l'aller-retour fondamental du stockage.

Bonne pratique

Passe toujours par un repli (?? "{}" ou ?? "[]") avant JSON.parse : si la clé n'existe pas encore, getItem renvoie null et JSON.parse(null) lèverait un piège. Mieux : enveloppe la lecture dans un try…catch au cas où la donnée stockée serait corrompue.

Cas réel : le thème de ce site

Cas réel

Le bouton clair/sombre en haut de cette page mémorise ton choix dans localStorage. À ta prochaine visite, un petit script lu avant l'affichage relit la clé et applique aussitôt le bon thème — d'où l'absence de « flash blanc ». Même principe pour un panier qui survit au rechargement, un brouillon d'article sauvegardé à chaque frappe, ou la bannière « cookies acceptés » qui ne revient plus. À chaque fois : une préférence légère, propre à l'appareil, sans base de données.

Réagir aux changements entre onglets

Quand une autre fenêtre du même site modifie le stockage, le navigateur émet un événement storage dans les autres onglets (pas dans celui qui a écrit). Pratique pour synchroniser l'affichage : change de thème dans un onglet, les autres suivent.

Les limites à connaître

Le stockage web est simple, mais volontairement modeste. Il faut en connaître les bornes pour ne pas s'y cogner.

  • Quota réduit : environ 5 Mo par origine. Au-delà, setItem lève QuotaExceededError.
  • Synchrone : chaque lecture/écriture bloque le fil principal. Parfait pour de petites valeurs, à éviter pour de gros volumes en boucle.
  • Même origine : un coffre est isolé par site (protocole + domaine + port). Un autre site n'y accède pas.
  • Que des chaînes : d'où le passage obligé par JSON pour tout le reste.

Quand passer à IndexedDB

Dès que tu dépasses « quelques préférences » — beaucoup de données, des objets structurés à rechercher, un besoin de fonctionner hors-ligne — localStorage ne suffit plus. Le navigateur offre alors IndexedDB : une vraie base de données locale, asynchrone, capable de stocker des centaines de mégaoctets d'objets et de les interroger par index.

Pour aller plus loin

L'API brute d'IndexedDB est verbeuse ; en pratique on utilise une surcouche comme idb ou Dexie.js. Pour une application vraiment hors-ligne (PWA), IndexedDB se combine avec un Service Worker (vu en HTML avancé) qui met en cache les fichiers. Il existe aussi la Cache API pour les réponses réseau, et l'API navigator.storage.estimate() pour connaître le quota disponible.

Sécurité : ce qu'on ne stocke jamais

Attention — règle de sécurité

Le contenu de localStorage est lisible en clair par n'importe quel JavaScript de la page. Une faille XSS (injection de script) donnerait un accès total à tout ce qui s'y trouve. On n'y met donc jamais de mot de passe, de jeton de session sensible, de numéro de carte ni de donnée personnelle critique. Ces secrets restent côté serveur, ou dans un cookie marqué HttpOnly (inaccessible au JavaScript).

Antisèche

Glossaire

localStorage
Coffre clé/valeur du navigateur, propre à un site, qui persiste jusqu'à effacement explicite.
sessionStorage
Même API que localStorage, mais effacé à la fermeture de l'onglet.
Web Storage
Nom de l'API qui regroupe localStorage et sessionStorage.
Sérialisation
Transformer une donnée en chaîne (JSON.stringify) pour la stocker ; l'opération inverse est JSON.parse.
Quota
Volume maximal de stockage autorisé par origine (environ 5 Mo pour Web Storage) ; le dépasser lève QuotaExceededError.
Origine (same-origin)
Combinaison protocole + domaine + port qui isole le stockage : un site ne voit pas le coffre d'un autre.
Événement storage
Signal émis dans les autres onglets du même site quand une clé change ; utile pour synchroniser l'affichage.
IndexedDB
Base de données locale du navigateur, asynchrone, pour de gros volumes d'objets structurés et interrogeables.

Récap et vérification

  • localStorage persiste ; sessionStorage vit le temps de l'onglet — même API.
  • Quatre méthodes : setItem, getItem (→ chaîne ou null), removeItem, clear.
  • On ne stocke que des chaînes : sérialise les objets avec JSON.stringify/parse.
  • Limites : ~5 Mo, synchrone, isolé par origine ; l'événement storage synchronise les onglets.
  • Gros/structuré/hors-ligne → IndexedDB ; et jamais de secret dans localStorage (risque XSS).

  3. Que renvoie getItem pour une clé qui n'existe pas ?
  4. Pourquoi ne jamais mettre de jeton de session sensible dans localStorage ?
