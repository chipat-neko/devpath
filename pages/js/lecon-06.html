Module 02 · Logique — Leçon 06

Factoriser (fonctions)

~36 min Débutant Leçon 05 recommandée

À la fin de cette leçon, tu sauras

  • Savoir déclarer et appeler une fonction, avec ou sans paramètres ;
  • Savoir distinguer afficher (console.log) et retourner (return) une valeur ;
  • Savoir écrire une fonction fléchée et utiliser des paramètres par défaut ;
  • Savoir raisonner sur la portée d'une variable locale et globale.
Sommaire de la leçon

Jusqu'ici, tu as appris à manipuler des variables, à tester des conditions avec if et à répéter des actions avec des boucles. Mais tu as peut-être remarqué un problème : dès qu'une même suite d'instructions doit servir à plusieurs endroits, tu la recopies. C'est fatigant, ça gonfle le code, et le jour où tu veux corriger un détail, tu dois le faire partout. Les fonctions sont la réponse à ce problème.

Dans cette leçon, tu vas apprendre à factoriser ta logique : la regrouper sous un nom, lui donner des entrées, récupérer une sortie. On part du connu (des instructions que tu sais déjà écrire) et on les emballe, petit à petit, dans des outils réutilisables. À la fin, tu enrichiras le gestionnaire de tâches avec deux fonctions concrètes.

Pourquoi des fonctions

Une fonction, c'est un bloc d'instructions auquel on donne un nom. Une fois nommé, ce bloc peut être déclenché autant de fois que tu veux, en écrivant simplement son nom. Trois bénéfices, à garder en tête :

  • Éviter la répétition. Tu écris la logique une seule fois. Si tu dois la modifier, tu le fais à un seul endroit.
  • Nommer une intention. calculerTotalPanier() dit ce que ça fait, bien mieux qu'une dizaine de lignes anonymes posées au milieu du programme.
  • Tester isolément. Une logique enfermée dans une fonction peut être appelée seule, avec différentes entrées, pour vérifier qu'elle se comporte bien.

Une bonne fonction fait une chose, et son nom décrit cette chose. C'est une habitude qui rend ton code lisible dès la première version.

Cas réel

Sur une boutique en ligne, une fonction formaterPrix(montant) transforme 1990 en "19,90 €". Elle est appelée à des dizaines d'endroits : fiche produit, panier, e-mail de confirmation, facture. Le jour où l'entreprise change de devise ou d'arrondi, on ne corrige qu'une fonction et tout le site suit. Sans factorisation, il faudrait retrouver et modifier chaque affichage de prix un par un — avec le risque d'en oublier.

Déclarer et appeler

Commençons par le cas le plus simple : une fonction sans entrée ni sortie, qui se contente d'afficher quelque chose. On la déclare avec le mot-clé function, suivi d'un nom, de parenthèses, puis d'un bloc entre accolades.

Note

Les parenthèses sont le signal de l'appel. direBonjour (sans parenthèses) désigne la fonction elle-même ; direBonjour() (avec parenthèses) l'exécute. Garde cette nuance en tête, on y revient dans les pièges.

Paramètres et arguments

Une fonction qui dit toujours exactement la même chose est limitée. On veut souvent lui passer une information pour qu'elle s'adapte. Cette information entre par un paramètre : un nom de variable déclaré entre les parenthèses de la définition.

Ici, nom est le paramètre : c'est une variable locale qui prend la valeur fournie à l'appel. "Sam" et "Léa" sont les arguments : les valeurs concrètes passées au moment de l'appel. Paramètre = l'étiquette dans la recette ; argument = l'ingrédient réel que tu mets dedans.

Une fonction peut avoir plusieurs paramètres, séparés par des virgules. L'ordre compte : le premier argument va dans le premier paramètre, et ainsi de suite.

Dans aire(4, 3), largeur vaut 4 et hauteur vaut 3. Ici la multiplication est commutative, donc aire(3, 4) donne le même résultat ; mais avec une soustraction ou une division, inverser les arguments changerait tout. Prends l'habitude de respecter l'ordre des paramètres.

Renvoyer une valeur avec return

Nos fonctions affichent un résultat, mais elles ne le donnent pas. Or, le plus souvent, on veut récupérer une valeur pour la réutiliser : la stocker, la comparer, la combiner. C'est le rôle de return.

Ici, carre(5) ne montre rien à l'écran tout seul : il renvoie la valeur 25, qu'on range dans r. L'appel carre(5) est littéralement remplacé par 25 dans l'expression qui l'entoure. Pour la deuxième ligne, carre(3) vaut 9 et carre(4) vaut 16 : 9 + 16 donne bien 25. C'est ce qui rend les fonctions composables : tu peux les additionner, les imbriquer, les passer ailleurs.

Piège fréquent

Afficher n'est pas retourner. console.log("texte") écrit dans la console mais ne renvoie rien d'exploitable. Une fonction qui se contente d'un console.log renvoie undefined. Si tu veux réutiliser le résultat, il te faut return.

Deux règles essentielles sur return :

  • Une fonction sans return renvoie undefined. Ce n'est pas une erreur, mais si tu fais const r = saluer("Sam"), alors r vaudra undefined, car saluer affiche mais ne retourne pas.
  • Le code après return ne s'exécute pas. Dès que return est atteint, la fonction s'arrête net et rend la main.

Paramètres par défaut

Parfois, un argument est optionnel : tu veux une valeur de repli si l'appelant n'en fournit pas. On déclare alors une valeur par défaut directement dans la liste des paramètres, avec =.

Quand on appelle saluer() sans argument, nom n'est pas fourni : il prend donc sa valeur par défaut "tout le monde". La valeur par défaut ne s'applique que si l'argument est absent (ou vaut explicitement undefined).

Fonctions fléchées

Il existe une écriture plus courte pour définir une fonction : la fonction fléchée (arrow function). On la range dans une variable avec const, et on remplace le mot function par une flèche => placée après les paramètres.

Deux formes à distinguer :

  • Sans accolades (forme courte), l'expression à droite de la flèche est automatiquement renvoyée. C'est le retour implicite. Tu n'écris pas return.
  • Avec accolades (forme longue), tu retrouves un vrai bloc : si tu veux renvoyer quelque chose, tu dois écrire return explicitement, comme avec function.

Les deux écritures sont équivalentes pour ce qu'on fait ici. Les fonctions fléchées sont surtout pratiques pour les petites fonctions passées en callback (donner une fonction à une autre fonction), ce que tu verras en détail à la leçon 08.

Astuce

Quand une fonction tient sur une seule ligne et ne fait que calculer puis renvoyer une valeur, la fonction fléchée à retour implicite est plus lisible. Pour une logique en plusieurs étapes, garde les accolades et un return explicite : c'est plus clair.

Portée des variables

Une variable déclarée à l'intérieur d'une fonction n'existe que dans cette fonction. C'est ce qu'on appelle la portée (scope). Elle naît à l'appel et disparaît à la fin. À l'extérieur, elle est tout simplement inconnue.

À l'inverse, une variable déclarée tout en haut, hors de toute fonction, est globale : elle est visible partout, y compris dans les fonctions. C'est pratique, mais à utiliser avec parcimonie : trop de variables globales rend le code difficile à suivre, car n'importe quelle fonction peut les modifier.

Plus finement, la portée ne concerne pas que les fonctions : tout bloc { } (celui d'un if, d'une boucle…) crée sa propre portée pour les variables let et const. Une variable déclarée dans un if n'existe pas en dehors de ce if.

Cette règle est une bonne nouvelle : chaque fonction travaille dans sa bulle, sans risquer d'écraser par accident une variable d'ailleurs. C'est exactement ce qui rend les fonctions sûres à réutiliser.

Pièges fréquents

  • Oublier return. La fonction calcule mais ne rend rien : tu récupères undefined. Vérifie qu'une fonction censée donner une valeur contient bien un return.
  • Confondre afficher et retourner. console.log sert à voir pendant le développement ; return sert à donner une valeur au reste du programme. Les deux ne se remplacent pas.
  • Appeler sans parenthèses. maFonction désigne la fonction (une référence), maFonction() l'exécute. Oublier les parenthèses est une erreur silencieuse : rien ne s'exécute.
  • Croire qu'une variable locale fuit dehors. Une variable déclarée dans une fonction (ou dans un bloc) n'existe pas à l'extérieur. Vouloir la lire dehors déclenche une ReferenceError.

Piège fréquent

Un appel comme console.log(saluer) (sans parenthèses) affiche le texte de la fonction, pas son résultat. Si tu vois quelque chose comme [Function: saluer] dans ta console, c'est que tu as oublié les parenthèses de l'appel.

Pour aller plus loin

Une fonction peut renvoyer un booléen (true ou false). C'est très courant pour poser une question dont la réponse est oui/non, et l'utiliser directement dans un if.

Remarque qu'on renvoie directement le résultat de la comparaison n % 2 === 0 : c'est déjà un booléen, inutile d'écrire un if autour.

Pour aller plus loin

Une fonction « se souvient » des variables de l'endroit où elle a été créée : c'est la notion de fermeture (closure). On reviendra dessus plus tard, mais retiens l'idée : même appelée ailleurs, une fonction garde un accès aux variables de son contexte d'origine.

Dernière subtilité utile : les fonctions déclarées avec function sont hissées (hoisting), c'est-à-dire utilisables même avant leur ligne de définition dans le fichier.

Ce n'est pas le cas des fonctions rangées dans une const (fléchées ou non) : tant que la ligne const n'a pas été exécutée, le nom existe mais n'est pas encore initialisé. L'appeler avant lève une erreur.

Retiens la règle simple : avec const, définis toujours la fonction avant de l'appeler.

Projet fil rouge — épisode 6

Notre gestionnaire de tâches manipule un tableau taches rempli d'objets { id, texte, faite }. Jusqu'ici, ajouter une tâche ou la mettre en forme se faisait à la main. Factorisons ces deux opérations dans des fonctions réutilisables.

Première fonction : ajouterTache. Elle reçoit la liste et le texte, ajoute le texte à la liste, puis renvoie la liste mise à jour.

Seconde fonction : formaterTache. Elle reçoit un texte et un booléen faite, et renvoie une chaîne lisible avec une case cochée ou non. On utilise l'opérateur ternaire vu plus tôt pour choisir le préfixe.

Vois comme chaque fonction fait une seule chose et porte un nom clair. Demain, si tu changes la façon d'afficher une tâche, tu ne touches qu'à formaterTache : tout le reste du programme suit automatiquement. C'est tout l'intérêt de factoriser.

Note

Ici ajouterTache reçoit une liste de textes simples pour rester lisible. Dans les épisodes suivants, on lui fera créer un vrai objet { id, texte, faite } à partir du texte fourni, une fois que tu manieras bien les objets.

Antisèche

Glossaire

Fonction
Bloc d'instructions nommé, défini une fois et réutilisable : on l'exécute en écrivant son nom suivi de parenthèses.
Déclaration / appel
Déclarer, c'est décrire la fonction sans la lancer ; appeler, c'est l'exécuter avec ().
Paramètre
Variable locale nommée entre les parenthèses de la définition ; elle reçoit la valeur fournie à l'appel.
Argument
Valeur concrète passée à la fonction au moment de l'appel ; elle vient remplir le paramètre correspondant.
return
Mot-clé qui renvoie une valeur et arrête la fonction : l'appel est alors remplacé par cette valeur. Sans lui, la fonction renvoie undefined.
Paramètre par défaut
Valeur de repli (a = 1) utilisée quand l'argument est absent ou vaut undefined.
Fonction fléchée
Écriture concise avec => ; sans accolades, elle renvoie automatiquement l'expression (retour implicite).
Portée (scope)
Zone où une variable existe. Une variable déclarée dans une fonction ou un bloc { } est invisible à l'extérieur.

Récap et vérification

  • Une fonction regroupe une logique sous un nom, pour la réutiliser et la nommer clairement.
  • On déclare avec function (ou via une const fléchée) et on appelle avec des parenthèses.
  • Les paramètres sont les entrées ; les arguments sont les valeurs passées à l'appel.
  • return renvoie une valeur ; sans lui, une fonction renvoie undefined. Afficher (console.log) n'est pas retourner.
  • Les paramètres par défaut fournissent une valeur de repli ; les fléchées offrent une écriture courte avec retour implicite.
  • Une variable locale n'existe que dans sa fonction (ou son bloc) : c'est la portée.

Vérifie ta compréhension

  1. Quelle est la différence entre définir une fonction et l'appeler ?
  2. Que renvoie une fonction qui se contente d'un console.log sans return ?
  3. Pourquoi console.log(interne) échoue-t-il si interne est déclarée dans une fonction ?
