Module 02 · Logique — Leçon 04

Prendre des décisions (conditions)

~35 min Débutant Module 1 recommandé

À la fin de cette leçon, tu sauras

  • savoir écrire des branchements avec if, else if et else en ordonnant correctement les conditions ;
  • savoir choisir entre switch et l'opérateur ternaire selon la situation, et éviter le fall-through ;
  • savoir utiliser le court-circuit && / || et l'opérateur ?? pour donner des valeurs par défaut ;
  • savoir reconnaître les valeurs falsy et les pièges classiques (= vs ===, break oublié).
Sommaire de la leçon

Jusqu'ici, ton code s'exécutait toujours de la même façon, ligne après ligne, sans jamais dévier. Tu sais déclarer des variables avec let et const, manipuler des nombres, des chaînes et des booléens, et tu connais les opérateurs de comparaison comme === ou >=. C'est exactement le moment d'apprendre à faire réagir ton programme : exécuter un bloc de code seulement si une condition est vraie.

Dans cette leçon, tu vas partir du if le plus simple et monter progressivement jusqu'aux outils plus fins — le switch, le ternaire, le court-circuit et l'opérateur nullish ??. À la fin, ton gestionnaire de tâches saura afficher l'état d'une tâche selon qu'elle est faite ou non. On y va une brique à la fois.

if et else

La structure de base s'écrit avec le mot-clé if, suivi d'une condition entre parenthèses, puis d'un bloc entre accolades. Le bloc ne s'exécute que si la condition vaut true.

Décortiquons. JavaScript évalue d'abord age >= 18. Comme age vaut 20, l'expression vaut true : on entre dans le premier bloc et on affiche "Majeur". Le bloc else est l'alternative : il s'exécute uniquement quand la condition est fausse. Avec age = 15, on aurait sauté le premier bloc pour exécuter le second et afficher "Mineur".

Le else est facultatif. Si tu veux juste agir « quand c'est vrai » et ne rien faire sinon, un if seul suffit.

Note

La condition doit produire un booléen (true ou false). Tout opérateur de comparaison — ===, !==, <, >, <=, >= — renvoie justement un booléen. C'est pour ça qu'on les utilise dans les if.

else if : enchaîner les cas

Souvent, deux possibilités ne suffisent pas. Imagine que tu veuilles classer une note sur 20 en trois catégories. Tu peux enchaîner des else if entre le if et le else final.

JavaScript teste les conditions de haut en bas et s'arrête à la première qui est vraie. Ici, 14 >= 16 est faux, donc on passe au cas suivant ; 14 >= 12 est vrai, on affiche "Bien" et on ignore tout le reste, y compris le else.

L'ordre des conditions est crucial. Si tu mettais note >= 12 en premier, alors une note de 18 déclencherait "Bien" avant même d'avoir testé note >= 16, et le cas « Très bien » deviendrait inatteignable. La règle : du cas le plus restrictif au plus large.

Imbriqué ou retour anticipé ?

On peut placer un if à l'intérieur d'un autre if : ce sont des conditions imbriquées. C'est parfois nécessaire, mais ça empile vite les accolades et rend le code difficile à lire.

Dans une fonction, une technique plus claire consiste à traiter d'abord les cas qui bloquent, puis à sortir immédiatement avec return : c'est le retour anticipé. On garde le « chemin principal » à plat, sans imbrication.

Le ! est l'opérateur « non » : il inverse un booléen. !utilisateur se lit « s'il n'y a pas d'utilisateur ». On reparlera de cette idée de simplification dans une leçon dédiée aux fonctions ; retiens pour l'instant qu'on préfère des conditions à plat plutôt que des poupées russes.

switch : comparer une valeur à des cas

Quand tu compares une même variable à plusieurs valeurs constantes, une cascade de else if devient répétitive. Le switch exprime cela plus clairement.

JavaScript compare jour à chaque case avec une égalité stricte (comme ===). Dès qu'un cas correspond, il exécute le code à partir de là. Le default est l'équivalent du else : il attrape tout ce qui n'a matché aucun cas.

Le mot-clé break est essentiel : il fait sortir du switch. Sans lui, l'exécution « déborde » sur les cas suivants — c'est le fameux fall-through. Ce comportement est parfois voulu (remarque comment "samedi" et "dimanche" partagent volontairement le même bloc, sans break entre eux), mais le plus souvent un break oublié est un bug.

Piège fréquent

Oublier un break dans un case fait exécuter aussi le bloc suivant, même si sa valeur ne correspond pas. Mets un break à la fin de chaque cas, sauf quand tu regroupes des cas exprès.

L'opérateur ternaire

Pour les choix très simples — « telle valeur si vrai, telle autre sinon » — il existe une écriture compacte : l'opérateur ternaire. Sa forme est condition ? valeurSiVrai : valeurSiFaux. Contrairement au if, c'est une expression : elle produit une valeur qu'on peut affecter.

On lit ça comme une question : « faite est-il vrai ? Si oui, prends "Terminée", sinon "À faire". » C'est l'équivalent exact d'un if/else qui assignerait etat, mais en une ligne. Réserve-le aux cas courts et lisibles : dès que la logique se complique, le if/else reste plus clair.

Court-circuit && et ||

Les opérateurs && (et) et || (ou) ne renvoient pas seulement true ou false : ils renvoient l'une des valeurs testées. C'est ce qu'on appelle l'évaluation en court-circuit, et c'est très pratique.

Avec ||, JavaScript renvoie la première valeur truthy (qui « vaut vrai ») ; si toutes sont falsy, il renvoie la dernière. C'est l'astuce classique pour une valeur par défaut.

Avec &&, c'est l'inverse : il renvoie la première valeur falsy ; si toutes sont truthy, il renvoie la dernière. On s'en sert pour « ne faire quelque chose que si la condition tient ».

Comme faite est truthy, && évalue la partie de droite, ce qui appelle action(). Si faite était false, JavaScript s'arrêterait à gauche (« court-circuit ») et action() ne serait jamais appelée.

Cas réel

Ce court-circuit est le pain quotidien des interfaces web. Dans des bibliothèques comme React, on écrit nonLus && afficherPastille(nonLus) pour n'afficher la pastille rouge de notifications que s'il y a des messages non lus : si nonLus vaut 0 (falsy), le côté droit est court-circuité et rien ne s'affiche. De même, utilisateur && utilisateur.nom évite une erreur quand utilisateur n'existe pas encore (données en cours de chargement).

L'opérateur ?? (nullish)

Le || a un défaut pour les valeurs par défaut : il réagit à toutes les valeurs falsy, donc aussi à 0 et à "". Or il arrive que 0 soit une valeur parfaitement légitime. L'opérateur ?? (« nullish coalescing ») résout ça : il ne se déclenche que pour null ou undefined.

Règle simple : utilise ?? quand 0, "" ou false sont des valeurs valides que tu veux garder, et || seulement quand n'importe quelle valeur falsy doit être remplacée.

Cas réel

Imagine un réglage de volume enregistré par l'utilisateur. S'il a choisi 0 (muet), c'est un choix volontaire à respecter. Avec volume || 50, ce 0 serait écrasé par 50 — le son se rallumerait tout seul ! Avec volume ?? 50, on ne met la valeur par défaut que si aucun réglage n'existe (null/undefined), et le 0 est préservé. C'est le réflexe pour tout compteur, prix ou paramètre où zéro est une vraie valeur.

Pièges fréquents

  • Écrire = au lieu de === dans un if. if (x = 5) affecte 5 à x puis teste cette valeur (toujours vraie ici), au lieu de comparer. Pour comparer, c'est ===.
  • Comparer avec ==. Le double égal convertit les types avant de comparer, ce qui donne des surprises comme 0 == "" qui vaut true. Préfère toujours === et !==.
  • Oublier break dans un switch : l'exécution déborde sur les cas suivants.
  • Imbriquer des ternaires (a ? b : c ? d : e) : c'est vite illisible. Pour plus de deux issues, repasse à if/else if.

Piège fréquent

if (x = 5) ne déclenche aucune erreur visible : c'est une affectation valide. C'est justement ce qui le rend dangereux. Relis tes conditions : à l'intérieur d'un if, tu veux presque toujours ===.

Pour aller plus loin

Une condition n'a pas forcément besoin d'un opérateur de comparaison : toute valeur placée dans un if est convertie en booléen. Les valeurs dites falsy sont peu nombreuses — false, 0, "", null, undefined et NaN — et tout le reste est truthy. Cela permet des raccourcis élégants.

Ici taches.length vaut 2, donc truthy ; si le tableau était vide, length vaudrait 0, donc falsy, et on tomberait dans le else. C'est plus court que taches.length > 0 tout en restant clair.

Pour aller plus loin

La vraie différence entre || et ?? tient à ce déclenchement : || remplace toute valeur falsy, alors que ?? ne remplace que null et undefined. Pour des compteurs, des prix ou des champs où 0 a un sens, ?? est le bon choix.

Projet fil rouge — épisode 4

Rappelle-toi notre gestionnaire de tâches : un tableau taches contenant des objets de forme { id, texte, faite }. Jusqu'ici on les stockait ; on va maintenant afficher l'état d'une tâche de façon lisible, avec une case cochée [x] ou vide [ ]. Le ternaire est parfait pour ce choix binaire.

La fonction lit tache.faite. Si c'est true, le ternaire produit "[x] " suivi du texte ; sinon "[ ] ". On voit ici tout l'intérêt d'une condition qui renvoie une valeur : on l'insère directement dans console.log. Dans un prochain épisode, on bouclera sur tout le tableau pour afficher la liste complète.

Astuce

Le préfixe "[x] " et "[ ] " est répété de chaque côté du ternaire. Tu peux factoriser : const prefixe = tache.faite ? "[x] " : "[ ] "; console.log(prefixe + tache.texte); — même résultat, encore plus lisible.

Antisèche : les décisions

Le mémo des structures de choix vues dans cette leçon.

Glossaire

Condition
Une expression booléenne (true/false) placée entre les parenthèses d'un if pour décider d'exécuter un bloc.
Branche
Un des chemins d'exécution possibles ; le if, chaque else if et le else définissent des branches.
switch
Structure qui compare une valeur à plusieurs case constants, par égalité stricte.
break
Instruction qui fait sortir d'un switch (ou d'une boucle) ; sans elle, le switch déborde.
Fall-through
Le débordement d'un case sur les suivants quand le break manque : parfois voulu, souvent un bug.
Ternaire
L'opérateur condition ? a : b, une décision compacte qui produit une valeur.
Court-circuit
L'arrêt anticipé de && / || dès que le résultat est connu ; ils renvoient l'une des valeurs testées.
Nullish (??)
Opérateur qui ne fournit une valeur par défaut que si l'opérande de gauche vaut null ou undefined.

Récap et vérification

  • if / else if / else testent des conditions de haut en bas et s'arrêtent à la première vraie : l'ordre compte.
  • switch compare une valeur à des case constants ; n'oublie ni break ni default.
  • Le ternaire condition ? a : b est une expression compacte, à réserver aux choix simples.
  • || renvoie la 1re valeur truthy, && la 1re falsy ; ?? ne remplace que null/undefined.
  • Compare avec === (jamais = ni == dans un if).

Vérifie ta compréhension

  1. Pourquoi le cas « Très bien » devient-il inatteignable si on teste note >= 12 avant note >= 16 ?
  2. Que se passe-t-il si tu oublies un break au milieu d'un switch ?
  3. Quelle est la différence de résultat entre 0 || 5 et 0 ?? 5, et pourquoi ?
