Module 04 · Navigateur — Leçon 10

Le DOM : sélectionner et modifier

~38 min Intermédiaire Module 3 recommandé

À la fin de cette leçon, tu sauras

  • Savoir sélectionner des éléments avec querySelector et querySelectorAll ;
  • Savoir lire et modifier le contenu d'un élément avec textContent et son apparence avec classList ;
  • Savoir lire et écrire des attributs, y compris les data-* via dataset ;
  • Savoir créer, insérer et supprimer des éléments pour générer une liste à partir d'un tableau.
Sommaire de la leçon

Jusqu'ici, tu écrivais du JavaScript qui calculait, bouclait et affichait dans la console avec console.log. C'est parfait pour apprendre, mais l'utilisateur final ne voit jamais la console : il voit une page web. Dans cette leçon, on franchit le pont entre ton code et ce qui s'affiche à l'écran. Tu vas apprendre à lire et à changer le contenu d'une page directement depuis JavaScript.

Prérequis : tu dois être à l'aise avec les variables (let/const), les tableaux et leurs boucles (for...of), et savoir comment un fichier .js est relié à une page HTML (leçon 1, avec l'attribut defer). On va beaucoup s'appuyer sur ces bases.

Qu'est-ce que le DOM

Quand le navigateur reçoit ton fichier HTML, il ne le garde pas sous forme de texte. Il le lit et le transforme en un arbre d'objets en mémoire : le DOM, pour Document Object Model. Chaque balise (<body>, <h1>, <li>…) devient un objet appelé nœud, avec un parent, des enfants, des propriétés et des méthodes.

La racine de cet arbre s'appelle document. C'est une variable globale toujours disponible dans le navigateur. À partir d'elle, tu peux descendre dans l'arbre pour trouver n'importe quel élément, puis le modifier. Quand tu changes un objet du DOM, le navigateur met à jour l'affichage automatiquement. C'est ça, la magie : tu manipules des objets, et l'écran suit.

Note

Le DOM n'est pas le HTML : c'est sa représentation vivante en mémoire. Tu peux modifier le DOM sans toucher au fichier .html sur le disque ; le fichier reste tel quel, seul l'affichage change.

Sélectionner

Avant de modifier un élément, il faut le retrouver dans l'arbre. La méthode la plus polyvalente est document.querySelector : tu lui passes un sélecteur CSS (le même que dans une feuille de style) et elle te renvoie le premier élément qui correspond.

Pour récupérer tous les éléments qui correspondent, utilise document.querySelectorAll. Elle renvoie une NodeList, une collection que l'on peut parcourir.

Il existe aussi document.getElementById("liste"), plus ancienne et très rapide, qui cherche uniquement par identifiant (sans le #). On la mentionne, mais querySelector couvre déjà ce besoin et bien plus.

Lire et écrire le texte

Une fois l'élément en main, la propriété textContent te donne accès à son texte. En lecture, elle renvoie le texte ; en écriture, elle le remplace.

Il existe une cousine, innerHTML, qui interprète son contenu comme du HTML : el.innerHTML = "<b>Salut</b>" affichera « Salut » en gras. Pratique, mais dangereux : si tu insères des données venant de l'utilisateur via innerHTML, un texte malveillant peut injecter du code dans ta page (faille XSS). Par défaut, préfère toujours textContent : il traite tout comme du texte brut, sans jamais exécuter de balises.

Piège fréquent

Ne mets jamais une saisie utilisateur dans innerHTML. Si l'utilisateur tape <img src=x onerror=...>, le navigateur l'exécutera. Avec textContent, ce texte s'affiche tel quel, inoffensif.

Classes et style

Pour changer l'apparence d'un élément, la bonne pratique n'est pas d'écrire du style en JavaScript, mais d'ajouter ou de retirer des classes CSS. Attributs et data-*

Les éléments portent des attributs (comme href, src, id). Tu les lis et les écris avec getAttribute et setAttribute.

Pour stocker tes propres données sur un élément, HTML propose les attributs data-*. Un <li data-id="3"> se lit en JavaScript via li.dataset.id (le préfixe data- disparaît, on accède au reste). C'est idéal pour relier un élément affiché à l'objet JavaScript qu'il représente.

Créer et insérer

Le plus puissant : tu peux fabriquer de nouveaux éléments et les ajouter à la page. On crée un nœud avec document.createElement, on le configure, puis on l'insère avec append (à la fin du parent) ou prepend (au début).

Le vrai intérêt apparaît avec un tableau : on parcourt les données et on génère un élément par entrée. C'est exactement comme ça qu'une application affiche une liste dynamique.

Cas réel

Un fil d'actualité (réseau social, boutique, résultats de recherche) fonctionne exactement ainsi : le serveur renvoie un tableau de publications en JSON, et le navigateur boucle dessus pour fabriquer une carte (createElement + textContent + append) par entrée. Quand tu fais défiler et que de nouveaux articles « apparaissent », c'est du JavaScript qui ajoute des nœuds au DOM en direct : la page HTML de départ, elle, ne contenait aucun de ces articles.

Supprimer

Retirer un élément de la page est très simple : appelle remove dessus. Il disparaît de l'arbre, et donc de l'affichage.

Astuce

Pour vider complètement une liste avant de la redessiner, le plus simple est liste.innerHTML = "" (ici la chaîne est vide, donc aucun risque d'injection). On s'en servira pour rafraîchir l'affichage du gestionnaire de tâches.

Pièges fréquents

  • Le script s'exécute trop tôt. Si ton JavaScript tourne avant que le navigateur ait construit le DOM, tes querySelector ne trouvent rien. Solution : ajoute l'attribut defer à ta balise <script> (vu en leçon 1), ou place le <script> juste avant </body>.
  • querySelector peut renvoyer null. Si aucun élément ne correspond, tu n'obtiens pas une erreur tout de suite : tu obtiens null. L'erreur arrive après, quand tu écris null.textContent. Vérifie l'existence si tu as un doute.
  • Une NodeList n'est pas un vrai tableau. Elle a bien forEach, mais pas map, filter ni les autres. Pour la convertir en tableau, écris [...nodeList] (spread).
  • Ne confonds pas textContent et innerHTML. Mettre du HTML dans textContent affiche les balises littéralement ; mettre du texte utilisateur dans innerHTML ouvre une faille.

Pour aller plus loin

querySelector et getElementById diffèrent surtout par leur entrée : la première accepte n'importe quel sélecteur CSS (classes, descendants, attributs…), la seconde uniquement un identifiant. getElementById est légèrement plus rapide, mais en pratique la souplesse de querySelector l'emporte presque toujours.

Côté performance, chaque insertion dans le DOM peut déclencher un recalcul de la page. Quand tu ajoutes beaucoup d'éléments, construis-les d'abord, puis insère-les en une fois : une seule boucle qui prépare tout, suivie d'un append final, est préférable à des dizaines d'insertions dispersées.

Enfin, tu croiseras parfois innerText. Il ressemble à textContent mais tient compte de la mise en page (il ignore le texte caché par CSS et déclenche un calcul de rendu). Pour lire ou écrire du texte de façon prévisible et performante, textContent reste le choix par défaut.

Pour aller plus loin

createElement n'est pas la seule façon de bâtir du DOM. Des bibliothèques comme React automatisent ces opérations. Mais comprendre ces primitives reste essentiel : c'est ce qui tourne sous le capot de tous les frameworks.

Projet fil rouge — épisode 10

Jusqu'à présent, notre gestionnaire de tâches vivait dans un tableau d'objets { id, texte, faite } affiché en console. Il est temps de le montrer à l'écran. On ajoute une <ul> vide dans la page, puis on génère un <li> par tâche.

Chaque <li> connaît désormais l'id de sa tâche (via dataset) et porte la classe fait si elle est terminée. C'est la base sur laquelle on branchera bientôt les clics.

Glossaire

DOM
Document Object Model : la représentation de la page sous forme d'arbre d'objets en mémoire, que JavaScript peut lire et modifier.
Nœud (node)
Un élément de l'arbre DOM (souvent une balise). Il possède un parent, d'éventuels enfants, des propriétés et des méthodes.
document
La racine de l'arbre, variable globale toujours disponible ; point d'entrée de toute sélection (document.querySelector…).
querySelector / querySelectorAll
Sélectionnent via un sélecteur CSS : le premier élément (ou null) pour l'un, une NodeList de tous pour l'autre.
NodeList
Collection d'éléments renvoyée par querySelectorAll. Parcourable avec forEach ; à convertir en tableau ([...liste]) pour map/filter.
textContent
Propriété qui lit et écrit le texte d'un élément en texte brut, sans interpréter de HTML : le choix sûr par défaut.
classList
Objet pour gérer les classes CSS d'un élément : add, remove, toggle, contains.
dataset
Accès aux attributs data-* : <li data-id="3"> se lit li.dataset.id (toujours une chaîne).

Récap et vérification

  • Le navigateur transforme le HTML en un arbre d'objets, le DOM, dont la racine est document.
  • On sélectionne avec querySelector (le premier) et querySelectorAll (tous, une NodeList).
  • On lit/écrit le texte avec textContent (sûr) ; innerHTML interprète le HTML et présente un risque d'injection.
  • On change l'apparence via classList (add, remove, toggle, contains), et on stocke des données avec dataset.
  • On crée avec createElement, on insère avec append/prepend, on retire avec remove.

Vérifie ta compréhension

  1. Quelle est la différence entre querySelector et querySelectorAll, et que renvoie chacune si rien ne correspond ?
  2. Pourquoi privilégier textContent plutôt que innerHTML pour afficher une saisie utilisateur ?
  3. Quelles méthodes utilises-tu pour créer un <li>, lui donner du texte et l'ajouter à la fin d'une <ul> ?
