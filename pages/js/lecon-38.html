Métaprogrammation : Proxy et Reflect

~34 min Avancé Leçon 19 recommandée

À la fin de cette leçon, tu sauras

  • expliquer ce qu'est la métaprogrammation ;
  • envelopper un objet dans un Proxy et intercepter ses accès avec des trappes (get, set) ;
  • valider et protéger des données à l'écriture ;
  • appliquer le comportement par défaut proprement avec Reflect ;
  • reconnaître un usage réel : la réactivité de Vue 3.
Sommaire de la leçon

Jusqu'ici, tu écrivais du code qui manipule des données : lire une propriété, en écrire une autre. La métaprogrammation, c'est le cran au-dessus : écrire du code qui agit sur le comportement du code lui-même. Avec un Proxy, tu peux dire : « chaque fois qu'on lit ou écrit une propriété de cet objet, passe d'abord par ma fonction ». C'est le mécanisme qui fait fonctionner la réactivité des frameworks modernes.

Qu'est-ce qu'un Proxy ?

Un Proxy (mandataire, intermédiaire) enveloppe un objet — la cible — et intercepte les opérations qu'on fait dessus. Tu fournis un objet de trappes (les handlers) : une fonction par type d'opération. Quand elle existe, elle est appelée à la place du comportement normal.

La syntaxe est toujours la même : new Proxy(cible, trappes). On utilise ensuite le proxy, jamais la cible directement — sinon on court-circuite l'interception.

Proxy transparent

Si tu ne fournis aucune trappe (new Proxy(cible, {})), le proxy se comporte exactement comme la cible : chaque opération est transmise telle quelle. Une trappe ne fait que s'ajouter au comportement par défaut ; tu ne redéfinis que ce que tu veux modifier.

La trappe set : valider à l'écriture

La trappe get intercepte les lectures ; la trappe set intercepte les écritures. C'est l'endroit rêvé pour valider une donnée avant de l'accepter : on garde l'objet toujours dans un état correct.

Erreur fréquente

La trappe set doit renvoyer true quand l'écriture réussit (et false pour la refuser en mode strict). Si tu oublies le return, JavaScript considère l'écriture comme un échec et lève un TypeError en mode strict (celui des modules ES). D'où l'intérêt de Reflect.set, qui renvoie ce booléen pour toi.

Reflect : le comportement par défaut, proprement

Écrire obj[prop] = valeur dans une trappe fonctionne, mais reste bancal : on doit penser à renvoyer true, gérer l'héritage, les getters… L'objet Reflect est le miroir des trappes : une méthode par opération (Reflect.get, Reflect.set, Reflect.has, Reflect.deleteProperty…), qui exécute exactement le comportement standard et renvoie la bonne valeur.

La règle de style est simple : dans une trappe get/set/has… appelle la méthode Reflect du même nom pour « laisser passer » l'opération une fois ta logique ajoutée. Les arguments correspondent trappe pour trappe.

Cas réel

Vue 2 utilisait Object.defineProperty pour cette réactivité, avec des angles morts célèbres : ajouter une nouvelle clé ou modifier un index de tableau n'était pas détecté (d'où le Vue.set d'antan). Vue 3 est passé à Proxy précisément parce qu'il intercepte tout, y compris l'ajout de propriétés et les tableaux — le code du framework s'en est trouvé plus simple et plus fiable.

Quand (ne pas) utiliser un Proxy

Un Proxy est puissant, mais il ajoute une indirection à chaque accès : chaque lecture ou écriture appelle ta fonction. Dans une boucle très chaude (des millions d'accès), ça coûte. À réserver donc aux frontières « intelligentes » : validation d'entrée, journalisation, réactivité, API simulée — pas comme brique de calcul bas niveau.

Bonne pratique

Pour un simple contrôle à la création d'un objet, Object.freeze() (gel superficiel) ou des getters/setters de classe suffisent souvent et coûtent moins cher. Sors le Proxy quand tu veux intercepter des accès dynamiques et imprévisibles (clés inconnues à l'avance, tout un objet à observer).

Pour aller plus loin

Il existe treize trappes au total : apply (intercepter un appel de fonction), construct (intercepter new), ownKeys, getPrototypeOf, defineProperty… Proxy.revocable() crée en prime un proxy que l'on peut désactiver d'un coup (utile pour couper l'accès à des données sensibles). De quoi construire des ORM, des objets fantômes ou des API dynamiques entières.

Glossaire

Métaprogrammation
Écrire du code qui agit sur le comportement d'autre code : intercepter, modifier ou générer des opérations à l'exécution.
Proxy
Objet qui enveloppe une cible et intercepte les opérations faites dessus via un ensemble de trappes.
Cible (target)
L'objet réel enveloppé par le proxy ; c'est lui qui stocke effectivement les données.
Trappe (trap / handler)
Fonction du proxy déclenchée pour un type d'opération précis (get, set, has, deleteProperty…).
Reflect
Objet global offrant une méthode par opération fondamentale, miroir des trappes ; exécute le comportement standard et renvoie sa valeur.
Réactivité
Mécanisme par lequel une modification de donnée déclenche automatiquement une réaction (souvent : redessiner l'interface).
Récepteur (receiver)
Dernier argument des trappes : le proxy (ou l'objet héritant) sur lequel l'opération a réellement été demandée ; à repasser à Reflect.

Récap et vérification

  • Un Proxy enveloppe une cible et intercepte ses opérations via des trappes.
  • get intercepte les lectures, set les écritures ; set doit renvoyer true en cas de succès.
  • Reflect applique le comportement par défaut proprement : appelle-le depuis la trappe du même nom.
  • Motifs classiques : validation, valeurs par défaut, lecture seule, réactivité (Vue 3).
  • Coût : une indirection par accès ; à réserver aux frontières intelligentes, pas aux boucles chaudes.
