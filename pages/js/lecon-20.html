Module 07 · Programmation orientée objet — Leçon 20

Les classes

~38 min Avancé Leçon 19 recommandée

À la fin de cette leçon, tu sauras

  • créer une classe avec un constructor, des champs et des méthodes, et l'instancier avec new ;
  • encapsuler des données avec des champs privés (#) et exposer des get/set ;
  • distinguer les membres d'instance des membres statiques (rattachés à la classe) ;
  • tester le type d'un objet avec instanceof et refactorer le gestionnaire de tâches en classe Tache.
Sommaire de la leçon

Jusqu'ici, tes tâches sont des objets littéraux { id, texte, faite } que tu fabriques à la main, et leurs comportements (basculer l'état, calculer un libellé) vivent dans des fonctions séparées. Ça marche, mais les données et les fonctions qui les manipulent sont dispersées. Tu vas apprendre à regrouper données et comportements dans un même moule grâce aux classes ES6.

L'objectif de cette leçon : maîtriser la syntaxe class, le constructeur, les méthodes partagées, les champs (publics, privés, statiques) et l'opérateur instanceof. À la fin, tu transformeras chaque tâche en une vraie instance d'une classe Tache.

Un moule à objets

Une classe est un patron qui décrit à quoi ressemblent les objets d'un même type et ce qu'ils savent faire. On la déclare avec le mot-clé class, puis on fabrique un objet — une instance — avec new.

Une classe vide ne sert à rien, mais elle montre déjà le geste de base : new NomDeClasse().

Note

La syntaxe class est du « sucre » posé par-dessus le système de prototypes de JavaScript. Tout ce que tu écris avec class pourrait s'écrire avec des fonctions et prototype, en bien plus verbeux. La classe rend juste l'intention plus lisible.

Le constructeur

Le constructor est une méthode spéciale appelée automatiquement à chaque new. Il reçoit les arguments passés à new et c'est là qu'on initialise les propriétés de l'instance, via le mot-clé this qui désigne l'objet en cours de création.

Chaque new crée un objet neuf avec ses propres texte et faite.

Piège fréquent

Oublier this. devant la propriété : écrire texte = texte dans le constructeur ne crée pas de propriété sur l'objet, ça réassigne juste le paramètre local. Sans this., l'information est perdue dès la fin du constructeur.

Des méthodes partagées

Une méthode est une fonction déclarée directement dans le corps de la classe (sans function, sans =). Elle agit sur l'instance via this. Détail important : les méthodes ne sont pas copiées dans chaque objet, elles vivent sur le prototype et sont partagées par toutes les instances.

Mille tâches partagent une seule fonction basculer : c'est économe en mémoire.

Champs de classe

Plutôt que d'initialiser this.faite = false dans le constructeur, tu peux déclarer un champ de classe directement dans le corps, avec une valeur par défaut. C'est plus lisible : on voit d'un coup d'œil quelles propriétés possède une instance.

Les champs sont initialisés juste avant l'exécution du corps du constructeur.

Astuce

Réserve les champs de classe aux valeurs par défaut indépendantes des arguments (comme faite = false). Tout ce qui dépend d'un paramètre de new reste dans le constructeur.

Champs privés avec #

Par défaut, toutes les propriétés sont publiques : n'importe qui peut écrire t.faite = "n'importe quoi". Pour protéger une donnée interne, préfixe son nom d'un # : c'est un champ privé, accessible uniquement à l'intérieur de la classe. C'est de la vraie encapsulation, garantie par le langage.

Le # fait partie du nom. Impossible d'y accéder, ni même de le lire, depuis l'extérieur.

Tu peux exposer un champ privé de façon contrôlée avec un getter (get) et un setter (set). On les utilise comme des propriétés, sans parenthèses, mais ce sont des fonctions qui s'exécutent.

Le setter valide la donnée ; le getter fahrenheit calcule sans stocker.

Piège fréquent

Accéder à un champ # hors de sa classe n'est pas undefined : c'est une erreur de syntaxe, détectée avant même l'exécution. Et un champ privé doit être déclaré dans le corps de la classe : tu ne peux pas l'inventer à la volée dans une méthode.

Membres statiques

Un membre statique (mot-clé static) appartient à la classe elle-même, pas aux instances. On y accède via le nom de la classe. C'est idéal pour des fonctions fabriques ou un compteur global d'instances.

creer et total sont sur Tache, pas sur t.

Piège fréquent

Une méthode statique n'est pas disponible sur l'instance. Appeler t.creer(...) déclenche t.creer is not a function. Inversement, une méthode d'instance n'est pas appelable sur la classe. Choisis le bon niveau.

Tester le type avec instanceof

L'opérateur instanceof renvoie true si un objet a été créé à partir d'une classe donnée (ou d'un de ses parents). Pratique pour vérifier qu'on manipule bien le bon genre d'objet.

instanceof répond à la question « cet objet vient-il de ce moule ? ».

Cas réel — tes propres balises HTML sont des classes

Les Web Components du navigateur reposent directement sur class. Pour créer une balise <compteur-clic>, tu écris class CompteurClic extends HTMLElement { … } puis customElements.define("compteur-clic", CompteurClic). Dès lors, chaque <compteur-clic> présent dans la page devient une instance de ta classe, avec son propre état interne (souvent rangé dans un champ privé #). Des bibliothèques comme Lit, et même les éléments natifs (<video>, <details>), fonctionnent exactement sur ce principe : une classe = un type d'élément.

Pièges fréquents

  • Oublier new : appeler Tache("Lire") sans new lève l'erreur Class constructor cannot be invoked without 'new'. Toujours new pour instancier.
  • Oublier this. dans le constructeur ou une méthode : la propriété n'est jamais posée sur l'objet.
  • Lire un champ # de l'extérieur : erreur de syntaxe, pas undefined.
  • Confondre statique et instance : t.creer() n'existe pas si creer est static.
  • Virgules entre méthodes : dans un objet littéral on sépare par des virgules ; dans une classe, aucune virgule entre les membres.

Pour aller plus loin

Pour aller plus loin

Contrairement aux fonctions classiques, les classes ne sont pas hoistées de façon utilisable : utiliser new Tache() avant la ligne class Tache {} lève une ReferenceError (zone morte temporelle). On peut aussi déclarer des méthodes privées (#valider()), invisibles de l'extérieur. Enfin, les méthodes publiques vivent sur Tache.prototype : Tache.prototype.basculer est la fonction partagée — c'est la mécanique réelle derrière le sucre class.

Projet fil rouge — épisode 20

On refactore les tâches : au lieu d'objets littéraux, chaque tâche devient une instance de Tache. L'id devient privé et n'est lisible qu'en lecture seule, et les comportements (basculer, libelle) deviennent des méthodes.

Les données et les comportements d'une tâche sont maintenant réunis dans un seul moule.

Note

Attention pour la persistance : JSON.stringify(taches) ne sérialise pas les champs privés ni les méthodes, seulement les propriétés publiques (texte, faite, creeLe). En rechargeant depuis localStorage, tu obtiendras des objets nus : il faudra les repasser dans new Tache(...) pour retrouver les méthodes. On verra ça en détail plus loin dans le cours.

Glossaire

Classe
Moule décrivant les données et les comportements des objets d'un même type ; déclarée avec class.
Instance
Objet concret fabriqué à partir d'une classe avec new ; il possède ses propres données.
Constructeur
Méthode constructor appelée automatiquement à chaque new pour initialiser l'instance via this.
Champ de classe
Propriété déclarée dans le corps de la classe avec une valeur par défaut, posée sur chaque instance.
Champ privé (#)
Propriété préfixée d'un #, accessible uniquement à l'intérieur de la classe : vraie encapsulation.
Membre statique (static)
Propriété ou méthode rattachée à la classe elle-même, pas aux instances ; on y accède via le nom de la classe.
Getter / setter
Couple get/set exposant une propriété qui se lit et s'écrit sans parenthèses, avec validation possible.
instanceof
Opérateur renvoyant true si un objet a été créé à partir d'une classe donnée (ou d'un de ses parents).

Récap et vérification

  • Une classe est un moule ; new en fabrique une instance.
  • Le constructor reçoit les arguments de new et initialise les propriétés via this..
  • Les méthodes sont partagées sur le prototype ; les champs de classe portent des valeurs par défaut.
  • Un champ #privé n'est lisible que dans la classe ; get/set exposent un accès contrôlé.
  • Les membres static appartiennent à la classe ; instanceof teste l'origine d'un objet.

Vérifie ta compréhension

  1. Quelle erreur obtiens-tu si tu appelles Tache("Lire") sans new, et pourquoi ?
  2. Pourquoi une méthode static n'est-elle pas accessible via une instance ?
  3. Quelle est la différence entre déclarer faite = false comme champ de classe et l'écrire this.faite = false dans le constructeur ?
