Les objets (données nommées)

~36 min Intermédiaire Leçon 08 recommandée

À la fin de cette leçon, tu sauras

  • Savoir créer un objet, lire, ajouter, modifier et supprimer ses propriétés avec la notation point et la notation crochets ;
  • Savoir utiliser les méthodes et this, ainsi que les raccourcis modernes : déstructuration, spread et propriétés abrégées ;
  • Savoir parcourir un objet avec Object.keys/values/entries et le convertir en texte avec JSON ;
  • Savoir modéliser proprement une tâche du gestionnaire grâce à une fonction qui renvoie un objet structuré.
Sommaire de la leçon

Jusqu'ici tu sais ranger plusieurs valeurs dans un tableau : une liste ordonnée où chaque élément se repère par sa position (taches[0], taches[1]…). C'est parfait quand l'ordre compte, mais ça devient vite illisible dès qu'on veut décrire une seule chose faite de plusieurs informations. Que voudrait dire tache[2] ? Le texte ? La date ? On ne sait plus.

Dans cette leçon, tu vas découvrir l'objet : la structure qui regroupe des données liées sous des noms plutôt que sous des positions. C'est l'outil central pour modéliser le monde réel en JavaScript, et il va transformer la tâche de notre gestionnaire en une donnée propre et explicite.

Pourquoi un objet

Un tableau ordonne par position ; un objet nomme. Compare ces deux façons de décrire un utilisateur :

Un objet s'écrit entre accolades { }. À l'intérieur, on liste des paires clé : valeur séparées par des virgules. La clé (à gauche) est le nom de la donnée ; la valeur (à droite) peut être n'importe quoi : une chaîne, un nombre, un booléen, un tableau, voire un autre objet.

Note

On dit propriété pour parler d'une paire clé/valeur de l'objet. « L'objet user a une propriété nom qui vaut "Sam" ».

Objets imbriqués

Une valeur peut elle-même être un objet. On parle alors d'objets imbriqués, et c'est ainsi qu'on représente des données structurées.

Lis tache.auteur.nom de gauche à droite : « dans tache, prends auteur ; dans ce résultat, prends nom ». Chaque point fait un pas de plus à l'intérieur.

Méthodes et this

Une propriété dont la valeur est une fonction s'appelle une méthode : c'est une action que l'objet sait faire. À l'intérieur, le mot-clé this désigne l'objet sur lequel on a appelé la méthode.

Quand tu écris compteur.incr(), JavaScript regarde ce qui précède le point : c'est compteur, donc this vaut compteur le temps de l'appel. C'est ce qui permet à une même méthode de fonctionner sur n'importe quel objet qui la possède.

Note

Reste simple pour l'instant : retiens juste que this, dans une méthode appelée avec objet.methode(), pointe vers l'objet à gauche du point. Les subtilités de this viendront plus tard.

Déstructuration

La déstructuration extrait plusieurs propriétés d'un objet vers des variables, en une ligne. Tu décris à gauche la forme de ce que tu veux récupérer.

Si une clé peut manquer, tu fournis une valeur par défaut avec =. Elle ne sert que si la propriété est absente (vaut undefined).

JSON

Un objet vit en mémoire ; pour le stocker ou le transmettre, il faut le transformer en texte. C'est le rôle de JSON (un format texte universel). JSON.stringify transforme un objet en chaîne, JSON.parse fait l'inverse.

C'est exactement ce mécanisme qui permettra de sauvegarder nos tâches dans le navigateur avec localStorage (leçon 12) ou de les envoyer à un serveur.

Cas réel

Quand ton code appelle une API (météo, réseau social, boutique), le serveur répond avec du texte JSON ; JSON.parse (ou response.json()) le retransforme en objet manipulable. Dans l'autre sens, pour retenir les préférences d'un visiteur, on écrit localStorage.setItem("prefs", JSON.stringify(prefs)), car localStorage ne sait stocker que des chaînes. C'est le même aller-retour objet ⇄ texte, des milliards de fois par jour sur le web.

Pièges fréquents

  • La référence partagée. Affecter un objet à une autre variable ne le copie pas : les deux noms pointent vers le même objet en mémoire.
  • Propriété inexistante. Lire une clé absente renvoie undefined, sans erreur : une faute de frappe dans le nom passe donc inaperçue.
  • JSON est partiel. JSON.stringify ignore les fonctions (méthodes) et les valeurs undefined : elles disparaissent du texte produit.

Piège fréquent

Copier un objet par simple affectation ne crée pas de copie : const b = a; b.x = 1; modifie aussi a.x, car a et b désignent le même objet. Pour une vraie copie, utilise le spread : const b = { ...a };.

Piège fréquent

Le this peut être « perdu » si tu détaches une méthode de son objet : const f = compteur.incr; f(); n'a plus d'objet à gauche du point, donc this ne pointe plus vers compteur. Appelle toujours la méthode via son objet : compteur.incr().

Pour aller plus loin

Un tableau d'objets est la combinaison la plus utile : une liste dont chaque élément est un objet structuré. C'est exactement la forme de notre liste de tâches, et elle se marie parfaitement avec map et filter vus dans les leçons précédentes.

Avec des objets imbriqués, méfie-toi : lire tache.auteur.nom plante si auteur est undefined. Tu peux d'abord vérifier la présence du parent avec &&, ou utiliser le chaînage optionnel ?. qui renvoie undefined au lieu de lever une erreur.

Pour aller plus loin

const rend la variable immuable, pas le contenu de l'objet : tu peux toujours modifier ses propriétés. Pour geler aussi le contenu (interdire ajout, modification, suppression), il existe Object.freeze(obj) — à découvrir plus tard.

Glossaire

Objet
Structure qui regroupe des données liées sous des noms plutôt que des positions : { clé: valeur, … }.
Propriété
Une paire clé/valeur d'un objet. La clé (à gauche) nomme la donnée, la valeur (à droite) peut être de tout type.
Méthode
Propriété dont la valeur est une fonction : une action que l'objet sait faire, appelée avec objet.action().
this
Dans une méthode appelée via objet.methode(), désigne l'objet situé à gauche du point.
Déstructuration
Extraire des propriétés vers des variables en une ligne : const { nom, age } = user;.
Spread (...)
Déverse les propriétés d'un objet dans un nouvel objet : { ...user } copie, { ...user, age: 27 } met à jour.
Immuabilité
Produire une nouvelle version de l'objet au lieu de modifier l'original ; le spread est l'outil clé de cette habitude.
JSON
Format texte universel pour stocker/transmettre des données : JSON.stringify (objet → texte) et JSON.parse (texte → objet).

Récap et vérification

  • Un objet { clé: valeur } regroupe des données liées sous des noms, contrairement au tableau qui les ordonne par position.
  • On lit avec le point (user.nom) ou les crochets (user["nom"], utile pour une clé dynamique) ; on ajoute, modifie et supprime avec = et delete.
  • Une méthode est une fonction propriété ; this y désigne l'objet appelant.
  • Déstructuration et spread raccourcissent le code ; le spread crée une copie indépendante (immuabilité).
  • Object.keys/values/entries parcourent l'objet ; JSON.stringify/parse le convertissent en texte et inversement.
