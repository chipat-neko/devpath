Codes de statut et en-têtes

~35 min Débutant Leçon 02 requise

À la fin de cette leçon, tu sauras

  • classer un code de statut par sa famille (2xx, 4xx…) ;
  • employer les codes courants (200, 201, 404, 500…) ;
  • lire et écrire les en-têtes clés ;
  • renvoyer le bon statut selon le résultat.
Sommaire de la leçon

Chaque réponse HTTP commence par un code de statut : un nombre à trois chiffres qui résume le résultat de la requête. C'est la première chose que lit un client : a-t-on réussi ? échoué ? par sa faute ou celle du serveur ? Bien choisir ses codes de statut est ce qui sépare une API claire d'une API qui ment. Cette leçon couvre aussi les en-têtes, ces métadonnées qui accompagnent chaque requête et réponse.

La distinction 4xx vs 5xx est cruciale : un 4xx dit « tu as fait une erreur » (mauvaise URL, données invalides, pas le droit) ; un 5xx dit « j'ai échoué » (bug serveur, base indisponible). Cette frontière oriente le débogage : à qui la faute ?

Quelques réflexes : une création réussie renvoie 201 (pas 200) ; une suppression sans corps renvoie 204 ; une ressource absente renvoie 404 ; des données invalides renvoient 400 ou 422. Le statut doit dire la vérité : renvoyer 200 avec un message d'erreur dans le corps est une faute classique qui trompe les clients et les outils.

Le statut doit dire la vérité

Renvoyer 200 OK avec un message d'erreur caché dans le corps est une faute classique. Les clients, caches et outils de supervision se fient au code : un 200 leur dit « tout va bien », ils n'affichent donc pas d'erreur et ne réessaient pas. Choisis le code qui correspond vraiment au résultat.

Cas réel

Une équipe a longtemps renvoyé 200 pour toutes ses réponses, le vrai code d'erreur « dans le JSON ». Résultat : la supervision affichait 100 % de succès pendant que les utilisateurs voyaient des erreurs, et le cache stockait des réponses fausses. En rétablissant de vrais 4xx/5xx, alertes et réessais automatiques se sont remis à fonctionner.

401 contre 403

Deux codes souvent confondus. 401 Unauthorized signifie « je ne sais pas qui tu es » — tu n'es pas authentifié (jeton manquant ou invalide). 403 Forbidden signifie « je sais qui tu es, mais tu n'as pas le droit » — tu es authentifié mais pas autorisé pour cette action.

La règle : 401 = authentification (prouve ton identité), 403 = autorisation (ton identité est connue, mais insuffisante). Les confondre brouille le message renvoyé au client.

Inspecter les en-têtes

Avec curl -i, tu vois la ligne de statut et les en-têtes de la réponse, en plus du corps ; curl -I ne demande que les en-têtes (requête HEAD). C'est le réflexe pour vérifier qu'une API renvoie le bon code et le bon Content-Type — souvent plus parlant que le corps lui-même.

Antisèche : les codes de statut

Glossaire

Code de statut
Nombre à trois chiffres en tête de chaque réponse HTTP, qui résume le résultat de la requête.
Famille (2xx, 4xx…)
Catégorie donnée par le premier chiffre : 2xx succès, 3xx redirection, 4xx erreur client, 5xx erreur serveur.
200 / 201 / 204
Succès : OK (lecture ou mise à jour), Created (création), No Content (succès sans corps).
404 Not Found
La ressource demandée n'existe pas à cette URL.
401 vs 403
401 = non authentifié (identité inconnue) ; 403 = authentifié mais non autorisé.
500 Internal Server Error
Erreur inattendue côté serveur (bug, dépendance en panne).
En-tête (header)
Paire clé-valeur de métadonnées accompagnant requête ou réponse (et non les données elles-mêmes).
Content-Type / Accept
Content-Type décrit le format du corps envoyé ; Accept indique le format souhaité en réponse.

Récap et vérification

  • Le 1er chiffre du statut donne la famille : 2xx succès, 3xx redirection, 4xx erreur client, 5xx erreur serveur.
  • Codes clés : 200, 201 (créé), 204 (vide), 400/422 (invalide), 404, 500.
  • 401 = pas authentifié ; 403 = authentifié mais pas autorisé.
  • En-têtes : Content-Type (format envoyé), Accept (format voulu), Authorization (jeton).

Exercices

Exercice 1Échauffement

À quelle famille appartiennent les codes 200, 404 et 503 ? Que veulent-ils dire ?

Voir une solution

200 → famille 2xx (succès) : la requête a réussi. 404 → famille 4xx (erreur client) : ressource introuvable. 503 → famille 5xx (erreur serveur) : service indisponible (surcharge, maintenance).

Exercice 3Défi

Un utilisateur connecté tente de supprimer le compte d'un autre utilisateur, ce qui lui est interdit. Quel statut renvoie l'API, et pourquoi pas 401 ?

Voir une solution

403 Forbidden. L'utilisateur est bien authentifié (l'API sait qui il est), donc ce n'est pas un 401 (qui veut dire « identifie-toi d'abord »). Le problème est l'autorisation : son identité est connue, mais il n'a pas le droit d'effectuer cette action. C'est exactement la situation que décrit 403.
