Les verbes HTTP et le CRUD

~35 min Débutant Leçon 01 requise

À la fin de cette leçon, tu sauras

  • associer chaque verbe HTTP à une action ;
  • relier les verbes au CRUD (créer, lire, modifier, supprimer) ;
  • distinguer PUT de PATCH ;
  • comprendre la sécurité et l'idempotence d'un verbe.
Sommaire de la leçon

En REST, l'URL dit sur quoi on agit (la ressource) ; le verbe HTTP dit ce qu'on fait. Cette séparation est l'idée la plus élégante de REST : une poignée de verbes standards, combinés aux URL, suffit à exprimer toutes les opérations. Quatre opérations de base reviennent partout — on les regroupe sous l'acronyme CRUD.

Les quatre opérations : CRUD

GET et POST

GET lit une ressource sans la modifier. Une requête GET ne porte pas de corps : tout passe dans l'URL. POST crée une nouvelle ressource ; les données du nouvel élément voyagent dans le corps de la requête, en JSON.

L'option -X POST choisit le verbe ; -H précise le type du corps (application/json) ; -d fournit les données. Le serveur crée la ressource et renvoie généralement la version créée, avec son nouvel identifiant attribué.

Tester sans coder

Pas besoin d'écrire une ligne de code pour essayer une API : curl en terminal, mais aussi des clients graphiques comme Hoppscotch, Insomnia ou Postman te laissent choisir le verbe, l'URL, les en-têtes et le corps, puis lire la réponse. Idéal pour explorer une API avant de l'intégrer dans ton code.

PUT contre PATCH

Les deux modifient une ressource existante, mais différemment. PUT remplace l'intégralité de la ressource : on envoie l'objet complet. PATCH applique une modification partielle : on n'envoie que les champs à changer.

Choisis selon l'intention : PATCH pour « change juste le statut », PUT pour « voici la version complète et définitive ». En pratique, PATCH est souvent plus pratique pour des mises à jour ciblées.

Sécurité et idempotence

Deux propriétés classent les verbes et guident leur usage :

  • un verbe est sûr (safe) s'il ne modifie pas la ressource. GET est sûr : le lire mille fois ne change rien.
  • un verbe est idempotent si l'appeler plusieurs fois a le même effet que l'appeler une fois. PUT et DELETE le sont ; POST ne l'est pas.

Ces propriétés ne sont pas théoriques : elles ont des conséquences réelles. POST n'étant pas idempotent, un client qui réessaie après un échec réseau risque de créer deux fois la même ressource ; il faut s'en prémunir. À l'inverse, on peut sans risque rejouer un PUT ou un DELETE qui semble avoir échoué.

Cas réel

Sur un site marchand, un client clique « Payer », la connexion coupe avant la réponse, il reclique : sans précaution, deux POST /paiements partent et il est débité deux fois. La parade standard : une clé d'idempotence — un identifiant unique envoyé par le client (souvent l'en-tête Idempotency-Key) que le serveur mémorise pour ignorer le second appel. Stripe et les grandes API de paiement fonctionnent exactement ainsi.

Pourquoi pas tout en GET ou POST ?

On pourrait techniquement tout faire avec GET et POST. Mais respecter les verbes apporte beaucoup : les caches, proxys et navigateurs savent qu'un GET est sûr (donc cachable) et qu'un DELETE est destructif. Utiliser le bon verbe, c'est parler le langage commun du web ; le détourner casse des optimisations et trompe les outils.

Antisèche : les verbes HTTP

Glossaire

Verbe HTTP (méthode)
Le mot en tête d'une requête (GET, POST…) qui dit l'action à effectuer sur la ressource désignée par l'URL.
CRUD
Les quatre opérations de base sur des données : Create, Read, Update, Delete — mappées sur POST, GET, PUT/PATCH, DELETE.
GET
Lit une ressource sans la modifier ; pas de corps, tout passe dans l'URL.
POST
Crée une nouvelle ressource ; les données voyagent dans le corps de la requête (JSON).
PUT
Remplace l'intégralité d'une ressource existante (on envoie l'objet complet).
PATCH
Modifie partiellement une ressource (on n'envoie que les champs à changer).
Sûr (safe)
Se dit d'un verbe qui ne modifie pas la ressource : le rejouer ne change rien (GET).
Idempotent
Se dit d'un verbe dont l'appel répété a le même effet qu'un seul appel (PUT, DELETE) ; POST ne l'est pas.

Récap et vérification

  • L'URL désigne la ressource ; le verbe HTTP dit l'action.
  • CRUD → verbes : POST (créer), GET (lire), PUT/PATCH (modifier), DELETE (supprimer).
  • PUT remplace tout ; PATCH modifie partiellement.
  • Sûr = ne modifie pas (GET) ; idempotent = rejouable sans effet supplémentaire (PUT, DELETE ; pas POST).

  1. Quel verbe pour créer une ressource ? Pour la supprimer ?
  2. Quelle différence entre PUT et PATCH ?
  3. Pourquoi POST n'est-il pas idempotent, et quel risque cela pose-t-il ?

Exercice 3Défi

Tu veux seulement passer l'article 42 en « publié », sans toucher au reste. Quel verbe choisis-tu, et pourquoi pas l'autre ?

Voir une solution

On choisit PATCH car on ne modifie qu'un champ. Avec PUT, il faudrait renvoyer l'objet entier (titre, contenu, etc.) ; tout champ omis serait remplacé ou réinitialisé, ce qui risquerait d'effacer des données par accident.
