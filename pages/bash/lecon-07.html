Module 02 · Scripter en Bash — Leçon 07

Conditions et boucles

~35 min Intermédiaire Leçon 6 recommandée

À la fin de cette leçon, tu sauras

  • savoir lire le code de retour d'une commande et écrire un if/elif/else/fi ;
  • savoir tester chaînes, nombres et fichiers avec [[ … ]] et enchaîner avec &&, || et ! ;
  • savoir écrire des boucles for, while, until et lire un fichier ligne par ligne ;
  • savoir aiguiller avec case … esac et maîtriser break et continue.
Sommaire de la leçon

Jusqu'ici, tes scripts déroulaient leurs commandes l'une après l'autre, sans jamais réfléchir. Pourtant, dès qu'on automatise une vraie tâche, on a besoin de décider (« si ce fichier existe, alors je le sauvegarde ») et de répéter (« pour chaque image du dossier, fais ceci »). C'est exactement ce que tu fais déjà à la main quand tu ranges un dossier : tu regardes, tu choisis, tu recommences. Bash sait faire pareil, en beaucoup plus rapide.

Dans cette leçon, tu vas donner de la logique à tes scripts : les conditions (if), les tests ([[ … ]]), les boucles (for, while) et l'aiguillage (case). Toutes les commandes s'exécutent dans un vrai terminal (Bash sous Linux ou macOS ; sous Windows, via WSL ou Git Bash) ; les sorties attendues sont montrées en commentaire (lignes commençant par #).

Le code de retour : le « vrai/faux » de Bash

Chaque commande, en se terminant, laisse un code de retour (un nombre de 0 à 255). La règle peut surprendre : 0 signifie « succès » (vrai), et tout nombre différent de 0 signifie « échec » (faux). Tu peux le lire dans la variable spéciale $? juste après la commande.

$? contient toujours le code de la dernière commande. C'est ce code que if va observer.

Note

Ce « 0 = vrai » est l'inverse des autres langages, où 0 vaut souvent « faux ». Pense plutôt « 0 problème » = tout va bien. C'est une convention POSIX, valable sur tous les systèmes Unix.

if / then / elif / else / fi

La structure if exécute des commandes seulement si une condition réussit (code 0). On la referme avec fi (« if » à l'envers). Le point-virgule avant then sépare deux instructions sur la même ligne ; tu peux aussi mettre then à la ligne suivante.

elif (« else if ») permet d'enchaîner plusieurs cas ; else couvre tout le reste.

Les tests avec [[ … ]]

Pour comparer des valeurs, Bash fournit la construction [[ … ]]. Elle renvoie un code 0 (vrai) ou non-0 (faux), parfaite pour un if. Attention aux espaces : il en faut un après [[ et un avant ]].

Comparer des chaînes : = (égal), != (différent), -z (chaîne vide), -n (chaîne non vide).

Comparer des nombres : on n'utilise PAS = ni >, mais des codes à deux lettres : -eq (égal), -ne (différent), -lt (<), -le (≤), -gt (>), -ge (≥).

Tester des fichiers : -e (existe), -f (fichier régulier), -d (dossier), -r/-w/-x (lisible/inscriptible/exécutable).

On peut combiner deux tests avec && (« et ») ou || (« ou ») à l'intérieur des doubles crochets.

Note : [[ ]] contre [ ]

Il existe une forme plus ancienne, [ … ] (la commande test, POSIX et portable partout). Mais [[ … ]], propre à Bash, est plus sûr : il gère mieux les variables vides ou contenant des espaces, et accepte && / || directement. En Bash, préfère toujours [[ ]]. Réserve [ ] aux scripts qui doivent tourner sous le shell sh minimal.

Les opérateurs &&, || et la négation !

En dehors des tests, && et || servent à enchaîner des commandes selon leur succès. A && B exécute B seulement si A a réussi ; A || B exécute B seulement si A a échoué.

Pratique pour une garde courte : « fais ça, sinon préviens ».

Les boucles for et while

La boucle for répète des actions pour chaque élément d'une liste. La liste peut être des mots, des fichiers (via un motif glob comme *.txt), ou une séquence {1..5}.

Le glob *.txt est développé par Bash en la liste réelle des fichiers : c'est sûr, même si un nom contient des espaces.

La boucle while répète tant que sa condition réussit. Sa cousine until fait l'inverse : elle répète jusqu'à ce que la condition réussisse.

while sert surtout à lire un fichier ligne par ligne. La forme recommandée est while read -r ligne : l'option -r empêche Bash de mal interpréter les antislashs.

Le < courses.txt branche le fichier sur l'entrée de la boucle : chaque ligne devient $ligne.

case … esac : l'aiguillage par motifs

Quand tu veux réagir à plusieurs valeurs possibles, une cascade de elif devient lourde. case compare une valeur à des motifs et exécute la branche correspondante. On le referme avec esac (« case » à l'envers), et chaque branche se termine par ;;.

La barre | liste plusieurs motifs pour une même branche ; * est le motif « attrape-tout » (le cas par défaut).

Cas réel

Pendant des décennies, chaque service Linux (Apache, MySQL, SSH…) était piloté par un script rangé dans /etc/init.d/ et bâti autour d'un unique case "$1" : case "$1" in start) … ;; stop) … ;; restart) stop; start ;; status) … ;; *) echo "Usage: $0 {start|stop|restart|status}" ;; esac. C'est ce motif qui te permettait de taper service apache2 restart : le premier argument aiguillait la bonne branche. Aujourd'hui systemd a largement pris le relais, mais des millions de serveurs tournent encore sur ce squelette — le même case que celui de cette leçon.

break et continue

Dans une boucle, break sort immédiatement de la boucle, et continue saute directement au tour suivant.

(( … )) est une parenthèse de calcul arithmétique : pratique pour % (reste), +, *…

Pièges fréquents

Piège fréquent

Oublier les espaces dans les crochets. [[-f "$f"]] échoue : il faut [[ -f "$f" ]], avec un espace après [[ et avant ]]. Bash lit ces crochets comme une commande, et une commande a besoin de séparateurs.

Piège fréquent

Confondre = et -eq. = compare des chaînes (caractère par caractère), -eq compare des nombres. Ainsi [[ "01" = "1" ]] est faux (chaînes différentes), mais [[ 01 -eq 1 ]] est vrai (même valeur numérique).

Piège fréquent

Boucler sur la sortie de ls (for f in $(ls)) casse dès qu'un nom contient une espace. Utilise toujours un glob : for f in *.txt. Et n'oublie jamais -r dans while read -r ligne, sinon les antislashs des lignes sont mal interprétés.

Astuce

Mets toujours tes variables entre guillemets dans un test : [[ -f "$f" ]]. Si $f est vide ou contient une espace, les guillemets évitent que Bash ne se trompe sur le nombre d'arguments.

Glossaire

Code de retour
Nombre laissé par une commande : 0 = succès (vrai), tout autre = échec (faux). Lu dans $?.
if … fi
Exécute un bloc then si la condition réussit, sinon elif/else. Se referme par fi.
[[ … ]]
Construction de test propre à Bash (espaces obligatoires à l'intérieur) ; plus sûre que [ … ] avec les variables vides.
Opérateur numérique
Code à deux lettres comparant des nombres : -eq, -ne, -lt, -le, -gt, -ge.
&& / ||
Enchaînent selon le succès : A && B lance B si A réussit ; A || B si A échoue.
Boucle for
Répète un bloc pour chaque élément d'une liste (mots, glob *.txt, séquence {1..5}).
Boucle while / until
while répète tant que la condition tient ; until jusqu'à ce qu'elle devienne vraie.
case … esac
Aiguille une valeur vers la branche dont le motif correspond ; * attrape tout le reste.

Récap et vérification

  • Code de retour : 0 = succès/vrai, tout autre nombre = échec/faux ; lu dans $?.
  • Condition : if … then … elif … else … fi, qui observe le code d'une commande.
  • Tests [[ … ]] : chaînes (=, !=, -z, -n), nombres (-eq, -lt, -ge…), fichiers (-e, -f, -d, -r/-w/-x).
  • Enchaînement : A && B (si A réussit), A || B (si A échoue), ! pour inverser.
  • Boucles : for x in liste, while, until, et while read -r ligne < fichier.
  • Aiguillage : case … esac par motifs ; break/continue pour contrôler la boucle.

Vérifie ta compréhension

  1. Quel code de retour correspond à un succès, et dans quelle variable le lit-on ?
  2. Pourquoi écrire [[ $age -ge 18 ]] et non [[ $age >= 18 ]] ?
  3. Quelle différence entre = et -eq dans un test ?
  4. Pourquoi préférer for f in *.txt à for f in $(ls *.txt) ?
