Développer une application mobile

Connaître Swift, Kotlin ou Dart, c'est connaître un langage : la moitié du chemin. L'autre moitié — celle qui fait la différence entre un exercice et une vraie application — n'a rien à voir avec la syntaxe. Une app mobile vit sur un appareil qu'on interrompt sans cesse (un appel, une notification, l'écran qui s'éteint), au réseau capricieux, à la batterie comptée, dans une poche. Ce cours est transverse : il enseigne ce qui vaut pour les trois écosystèmes — le cycle de vie, la navigation, l'état, les listes, le stockage local, le hors-ligne, les permissions, les notifications, l'adaptation aux écrans, les tests et la publication — illustré tour à tour avec SwiftUI, Kotlin/Compose et Flutter.

Bien s'équiper

De quoi coder pour mobile

Les vrais ateliers du mobile sont Xcode (pour iOS, sur Mac) et Android Studio (pour Android), qui embarquent les simulateurs et émulateurs. Mais on écrit beaucoup de code mobile dans VS Code — surtout en Flutter. Ouvre le panneau Extensions (Ctrl+Shift+X) et installe de quoi lire et écrire les trois écosystèmes :

À installer pour suivre le cours

  • Flutter et Dart (Google) — l'atelier multiplateforme le plus complet dans VS Code : complétion, hot reload, aperçu.
  • Swift (Swift Server Work Group) — coloration et complétion Swift hors de Xcode.
  • Kotlin — lire et éditer du code Android/Kotlin dans l'éditeur.
  • Error Lens — voir les erreurs à côté de la ligne fautive, précieux quand on découvre un framework.
  • Et surtout : Xcode (Mac) ou Android Studio pour l'émulateur et la publication — irremplaçables pour lancer une vraie app.

Pour qui ?

Ce cours vise les développeurs qui savent déjà (ou apprennent) un langage mobile — Swift, Kotlin ou Dart / Flutter — et veulent comprendre ce qui entoure le code pour livrer une application qui tient dans la vraie vie. Il est conceptuel et transverse : les principes (cycle de vie, hors-ligne, permissions, publication) valent quel que soit l'écosystème. Les exemples de code sont courts et donnés dans les trois langages pour montrer que l'idée compte plus que la syntaxe. Aucun matériel payant n'est requis pour lire le cours ; un Mac (iOS) ou un simple PC (Android/Flutter) suffit pour pratiquer.

Ce que tu vas apprendre

D'un langage connu à une application qui tient

À la fin du cours, tu sauras

  • penser mobile : ce qui change par rapport au web, choisir entre natif et multiplateforme, gérer le cycle de vie et l'architecture en écrans ;
  • construire l'interface : navigation entre écrans, état et remontée d'événements, listes performantes, adaptation à toutes les tailles d'écran ;
  • affronter le monde réel : stockage local, appels réseau, mode hors ligne et synchronisation, permissions et vie privée, notifications ;
  • livrer et tenir : tester sur un appareil réel et publier sur l'App Store et le Play Store, puis suivre les versions.

Pour qui, et pourquoi

Un débutant qui a appris Flutter ou SwiftUI sait afficher un écran. Puis viennent les vraies questions : que se passe-t-il quand un appel arrive au milieu ? Comment retrouver l'écran exact où l'utilisateur en était ? Pourquoi la liste rame à mille éléments ? Comment fonctionner dans le métro sans réseau ? Faut-il demander l'accès à la caméra maintenant ou plus tard ? Comment publier sans se faire refuser ? Aucune de ces questions n'est une question de langage — ce sont les questions de l'application, et ce sont elles qui séparent une démo d'un produit.

Chaque leçon est autonome, illustrée de schémas dessinés et d'exemples courts donnés dans les trois écosystèmes. Le fil rouge : Carnet, une petite application de balades où l'on note ce qu'on voit — une photo, un lieu sur la carte, quelques mots — même sans réseau, en pleine nature. Ce terrain rend naturels tous les sujets difficiles du mobile : le hors-ligne (pas de 4G dans la forêt), les permissions (photo, position), les notifications (« il fait beau, sors marcher »), le stockage local, la synchronisation. Un seul projet, décliné du premier écran jusqu'au dépôt sur les magasins.

Récapitulatif

À retenir & glossaire

Les points clés du cours, puis les termes essentiels à connaître.

À retenir

  • Une app mobile est interrompue en permanence : le cycle de vie (actif, arrière-plan, tué) est la première chose à maîtriser, car un état non sauvegardé est un état perdu.
  • La règle d'or de l'interface : une source de vérité unique. L'écran est le reflet de l'état ; on change l'état, l'écran suit — jamais l'inverse.
  • Une liste performante ne dessine que ce qui est visible (recyclage) : c'est le premier réflexe de fluidité sur mobile.
  • Le stockage local est la source de vérité ; le réseau n'est qu'un miroir qu'on rattrape. C'est le socle du hors-ligne d'abord.
  • Une permission se demande au bon moment (quand l'utilisateur comprend pourquoi), jamais au lancement, et l'app doit survivre à un refus.
  • Les notifications sont un budget de confiance : peu, pertinentes, jamais du bruit — sous peine d'être coupées ou l'app désinstallée.
  • Tester sur un vrai appareil révèle ce que l'émulateur cache : lenteur, réseau réel, batterie, permissions, taille de pouce.
  • Publier n'est pas la fin : c'est le début du cycle versions → retours → correctifs, encadré par la revue des magasins.
Cycle de vie
Les états successifs d'une application (au premier plan, inactive, en arrière-plan, tuée) et les transitions entre eux : le moment où l'on sauvegarde et restaure l'état.
Natif vs multiplateforme
Natif : un code par plateforme (SwiftUI pour iOS, Compose pour Android). Multiplateforme (Flutter, React Native) : un seul code pour les deux.
Source de vérité
L'endroit unique où vit une donnée ; l'interface s'en déduit. Éviter de dupliquer un état, c'est éviter les incohérences d'affichage.
Recyclage de liste
Technique qui ne rend que les éléments visibles d'une longue liste et réutilise les cellules qui défilent, pour garder le défilement fluide.
Hors-ligne d'abord
Concevoir l'app pour fonctionner sans réseau : le stockage local fait autorité, le réseau synchronise plus tard.
Synchronisation
Rapprocher l'état local et l'état distant : rejouer les changements en attente, récupérer les nouveautés, résoudre les conflits.
Permission
Autorisation explicite de l'utilisateur pour accéder à une ressource sensible (caméra, position, notifications, contacts).
Notification locale / push
Un rappel affiché par le système : locale (planifiée par l'app elle-même) ou push (envoyée depuis un serveur).
Deep link
Un lien qui ouvre l'application directement sur un écran précis, plutôt que sur son accueil.
Magasin d'applications
L'App Store (Apple) et le Play Store (Google) : le canal de distribution, avec sa revue, sa signature et ses règles.
