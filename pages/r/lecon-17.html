Module 6 · Projet — Leçon 17

Projet — une analyse de données de bout en bout

~55 min Intermédiaire Prérequis : l'ensemble du cours

À la fin de cette leçon, tu sauras

  • situer les six étapes du cycle d'une analyse : importer, nettoyer, transformer, visualiser, modéliser, communiquer ;
  • enchaîner ces étapes sur un vrai jeu de données, du fichier brut au résultat ;
  • reconnaître la boucle exploratoire (transformer ↔ visualiser ↔ modéliser) ;
  • assembler tes acquis (vecteurs, dplyr, ggplot2, stats, modèles) en un livrable reproductible.
Sommaire de la leçon

Te voilà au bout du chemin. Tu sais créer des vecteurs et des data frames, filtrer et regrouper avec dplyr, dessiner avec ggplot2, décrire, tester, modéliser, joindre des tables et itérer avec purrr. Ce sont des briques. Cette dernière leçon les assemble en une démarche — celle que suit tout analyste, du fichier reçu par mail jusqu'au graphique qui convainc.

Le cycle d'une analyse de données

Une analyse n'est pas une suite d'astuces, mais un cycle aux étapes bien identifiées, popularisé par Hadley Wickham (l'auteur du tidyverse). On importe, on nettoie, puis on entre dans une boucle exploratoire où l'on transforme, visualise et modélise en allers-retours, jusqu'à comprendre. Enfin, on communique.

Déroulons-le sur un vrai jeu de données livré avec R : airquality, des mesures quotidiennes de qualité de l'air à New York (ozone, température, mois…). Il a le mérite d'être imparfait — avec de vraies valeurs manquantes.

1. Importer & inspecter

Avant toute chose : regarder. On ne se jette pas sur un calcul sans connaître la forme, les types et les trous du jeu de données.

Le réflexe qui sauve

str(), summary() et head() (ou glimpse() côté dplyr) sont les trois premiers gestes de toute analyse. Ici, summary révèle 37 valeurs manquantes dans Ozone : les ignorer fausserait toutes les moyennes.

2. Nettoyer & remodeler

Les données réelles sont sales : valeurs manquantes, types mal devinés, format « large » à pivoter. On décide ici, consciemment, quoi faire des NA.

3. Transformer & explorer avec dplyr

On entre dans la boucle. Première question : l'ozone varie-t-il selon le mois ? On agrège.

4. Visualiser avec ggplot2

Un tableau se lit, un graphique se comprend. La deuxième question : l'ozone dépend-il de la température ?

5. Modéliser (si la question l'exige)

Le graphique suggère un lien ; le modèle le chiffre. On ajuste une régression et on lit l'essentiel.

Corrélation n'est pas causalité

Le modèle dit que l'ozone augmente avec la température, pas que la chaleur le cause à elle seule (le rayonnement solaire, le vent… jouent aussi). Un modèle résume une relation observée ; l'interpréter en mécanisme demande de la prudence et des connaissances du domaine.

6. Communiquer un résultat reproductible

Une analyse qui vit dans ta seule console ne sert personne. La dernière étape emballe tout — texte, code, figures — dans un document qui se régénère d'un clic (leçon 12). En Quarto, chaque bloc de code s'exécute et son résultat s'insère dans le rapport final.

Cas réel

Cas réel

Dans un institut de santé publique, une analyste reçoit un export de capteurs : relevés horaires de polluants sur un an, avec des pannes (donc des NA) et des colonnes mal typées. Sa mission : « les pics d'ozone sont-ils liés aux vagues de chaleur ? ». Elle déroule exactement ce cycle : read_csv pour importer, filter/mutate pour nettoyer les pannes, group_by par semaine, un ggplot pour voir, un lm pour chiffrer, et un rapport Quarto envoyé aux décideurs. Le même document, relancé le mois suivant avec les nouvelles données, se met à jour tout seul. Ce n'est pas un exercice d'école : c'est littéralement le métier — et R a été conçu pour ça.

Pour aller plus loin

Pour aller plus loin

Le cycle se prolonge : pour un tableau de bord interactif, emballe l'analyse dans une application Shiny ; pour des données trop lourdes pour la mémoire, bascule vers data.table ou interroge une base SQL via dbplyr ; pour partager ta méthode, transforme tes fonctions en un paquet R documenté. Mais la démarche, elle, ne change jamais : importer, nettoyer, explorer, modéliser, communiquer.

Antisèche

Glossaire

Cycle d'analyse
Suite d'étapes — importer, nettoyer, explorer, modéliser, communiquer — qui structure tout travail sur données.
Boucle exploratoire
Cœur du cycle où l'on alterne transformer, visualiser et modéliser jusqu'à comprendre.
Valeur manquante (NA)
Donnée absente ; à traiter explicitement (écarter, imputer) sous peine de fausser les calculs.
Données propres (tidy)
Table où chaque variable est une colonne et chaque observation une ligne.
Modèle
Résumé chiffré d'une relation entre variables (ex. : lm(Ozone ~ Temp)).
Reproductibilité
Propriété d'une analyse qui se rejoue à l'identique à partir de son code source.
Quarto
Format de document mêlant texte, code et résultats, régénérable d'un geste.

Récap et vérification

  • Une analyse suit un cycle : importer → nettoyer → (transformer ↔ visualiser ↔ modéliser) → communiquer.
  • On inspecte toujours (str, summary) avant de calculer, pour repérer types et NA.
  • Le nettoyage est une décision écrite dans le code, donc traçable.
  • Graphique et modèle se complètent : l'un montre, l'autre chiffre.
  • La reproductibilité (Quarto) transforme l'analyse en livrable partageable.

Vérifie ta compréhension

  1. Quelles sont les deux premières choses à faire dès qu'on ouvre un jeu de données inconnu ?
  2. Pourquoi parle-t-on d'une boucle entre transformer, visualiser et modéliser plutôt que d'étapes linéaires ?
  3. Qu'apporte l'étape « communiquer » avec Quarto par rapport à un copier-coller dans un document Word ?

Mini-projet fil rouge — une analyse de ventes

Pour clore ce cours, faisons une petite analyse de ventes. Elle réunit un data.frame, les vecteurs, sum, l'agrégation par groupe (aggregate) et l'indexation avec which.max — un condensé de R orienté données.

Ce que tu vas construire

Un tableau de ventes (produit, montant), son total général, le total par produit, et le produit le plus vendu.

Étapes

Le data.frame

Crée ventes avec deux colonnes : produit (texte) et montant (numérique), via c(...).

Le total général

Affiche sum(ventes$montant) avec cat.

Le total par produit

Utilise aggregate(montant ~ produit, data = ventes, FUN = sum).

Le produit le plus vendu

Repère la ligne maximale avec which.max et l'indexation [ligne, ].

Afficher

Affiche le tableau agrégé avec print et le top avec cat.

ProjetFil rouge

Assemble les cinq étapes en un script complet. Essaie d'abord par toi-même, puis compare avec la solution de référence.
