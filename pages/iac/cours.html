Infrastructure as Code (Terraform)

Configurer un serveur « à la main » dans une console, c'est lent, non reproductible et impossible à relire. L'Infrastructure as Code (IaC) décrit l'infrastructure dans des fichiers texte versionnés, qu'un outil applique pour atteindre l'état voulu. Ce cours t'apprend les principes de l'IaC avec Terraform : providers, ressources, state, plan/apply, modules et environnements.

Bien s'équiper

Les extensions VS Code pour Terraform

On écrit du HCL (le langage de Terraform). Ouvre le panneau Extensions de VS Code (Ctrl+Shift+X) :

À installer pour ce cours

  • HashiCorp Terraform — coloration, autocomplétion, validation et formatage du HCL.
  • YAML — utile pour les fichiers de configuration voisins.
  • GitLens — l'IaC se versionne : suivre l'historique de l'infra est précieux.
  • Indent Rainbow — visualiser les blocs imbriqués du HCL.

Prérequis

Avoir suivi le cours Cloud aide beaucoup (l'IaC décrit l'infrastructure cloud), ainsi que les bases de Git (on versionne le code d'infra) et de la ligne de commande. Le cours est conceptuel et lisible sans compte cloud.

Ce que tu vas apprendre

Objectifs du cours

À la fin du cours, tu sauras

  • expliquer ce qu'apporte l'IaC (reproductibilité, revue, versionnage) ;
  • déclarer des ressources via un provider ;
  • comprendre le state et le cycle plan / apply ;
  • paramétrer avec des variables et des outputs ;
  • factoriser avec des modules ;
  • gérer plusieurs environnements proprement.

Pour qui, et pourquoi

Ce cours est pour toi si tu déploies de l'infrastructure et veux le faire de façon fiable, reproductible et relisible, plutôt qu'en cliquant dans une console. L'IaC transforme l'infrastructure en code : on la revoit en équipe, on la versionne, on la recrée à l'identique.

Le fil conducteur est le principe déclaratif : tu décris l'état voulu, l'outil calcule les changements nécessaires et les applique. Tu ne donnes pas des ordres pas à pas — tu décris la cible.

Astuce

« Si je perdais tout mon cloud, pourrais-je le recréer en une commande ? » Avec l'IaC, la réponse est oui : l'infrastructure est décrite dans des fichiers que tu réappliques.

Récapitulatif

À retenir & glossaire

Les points clés du cours, puis les termes essentiels à connaître.

À retenir

  • L'IaC décrit l'infrastructure en code versionné : reproductible et relisible.
  • Terraform est déclaratif : on décrit l'état voulu, il calcule les changements.
  • Le state mémorise ce qui existe ; plan prévisualise, apply applique.
  • Les variables paramètrent, les modules factorisent.
  • Plusieurs environnements (test/prod) à partir du même code, paramétré.
Infrastructure as Code
Décrire et gérer l'infrastructure via des fichiers de code versionnés, plutôt qu'à la main.
Terraform
Un outil d'IaC déclaratif, indépendant du fournisseur, très répandu.
HCL
HashiCorp Configuration Language : le langage de configuration de Terraform.
Provider
Le plugin qui permet à Terraform de piloter une plateforme (un cloud, un service).
Ressource
Un élément d'infrastructure déclaré (machine, réseau, base, conteneur…).
State (état)
Le fichier où Terraform mémorise la correspondance entre le code et la réalité.
Plan
L'aperçu des changements que Terraform appliquerait (créer/modifier/détruire).
Apply
L'application effective des changements pour atteindre l'état voulu.
Module
Un ensemble de ressources réutilisable et paramétrable.
Variable
Une entrée paramétrant la configuration (région, taille, nom…).
Idempotence
Réappliquer la même configuration ne change rien si l'état est déjà conforme.
