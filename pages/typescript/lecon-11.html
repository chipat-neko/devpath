Module 04 · TypeScript en profondeur — Leçon 11

Types conditionnels, mappés et template literals

~36 min Avancé Cours TypeScript recommandé

À la fin de cette leçon, tu sauras

  • construire des types mappés avancés avec modificateurs +/-readonly, +/-? et remapping de clés via as ;
  • écrire des types conditionnels T extends U ? X : Y, maîtriser leur distributivité et extraire des sous-types avec infer ;
  • composer des template literal types et des types récursifs comme DeepReadonly ;
  • savoir quand la type gymnastics nuit à la lisibilité et choisir de s'arrêter.
Sommaire de la leçon

Jusqu'ici tu as consommé des types utilitaires comme Partial<T> ou Pick<T, K>. Dans cette leçon, tu passes de l'autre côté : tu vas écrire ces utilitaires et les généraliser. L'idée centrale est que le système de types de TypeScript est un petit langage à part entière — purement fonctionnel, évalué à la compilation par tsc, où les types jouent le rôle des valeurs.

On va combiner quatre briques : les types mappés (transformer chaque clé), les types conditionnels (brancher selon une relation de sous-typage), infer (capturer un type au passage) et les template literal types (manipuler des chaînes au niveau type). Rien ne s'« exécute » : tout se vérifie en lisant le type inféré que tsc calcule, indiqué en commentaire dans chaque exemple.

Types mappés : au-delà de la copie de clés

Tu connais la forme { [K in keyof T]: T[K] }. Ce qui change ici, ce sont les modificateurs que tu peux ajouter ou retirer explicitement avec + et - : readonly et ? (optionnalité). Retirer un modificateur est le mécanisme exact derrière Required<T> et un éventuel Mutable<T>.

La nouveauté la plus puissante est le remapping de clés via as : tu peux renommer, voire supprimer une clé en la mappant vers never (une clé de type never est éliminée du type produit). Combiné aux template literal types (section plus bas), c'est l'outil qui génère des getters, des noms d'événements, etc.

Types conditionnels et distributivité

Un type conditionnel a la forme T extends U ? X : Y : si T est assignable à U, le type vaut X, sinon Y. Le point subtil et indispensable à comprendre est la distributivité : quand T est un type paramètre nu et qu'on lui passe une union, la condition s'applique à chaque membre séparément, puis les résultats sont réunis.

Cette distributivité est souvent ce que tu veux (elle reproduit NonNullable de la lib standard). Mais parfois tu veux raisonner sur l'union entière ; on verra dans les pièges comment désactiver ce comportement avec un tuple enveloppant.

Extraire un type avec infer

Le mot-clé infer s'utilise dans la branche extends d'un type conditionnel : il déclare une variable de type que le compilateur va inférer par filtrage de motif. C'est le cœur de ReturnType, Parameters, Awaited, etc.

Note

Tu peux contraindre une variable inférée : infer E extends string. Le compilateur n'accepte le motif que si E respecte la contrainte, ce qui évite des branches never involontaires et améliore l'inférence dans les template literal types.

Template literal types

Un template literal type s'écrit comme un gabarit de chaîne, mais au niveau type : `on${Capitalize<K>}`. Combiné aux utilitaires intrinsèques Capitalize, Uncapitalize, Uppercase et Lowercase, il génère des littéraux de chaîne précis. Mappé sur les clés d'un objet, il produit des API typées comme un jeu de handlers d'événements.

On peut aussi décomposer une chaîne avec infer dans un motif littéral — par exemple extraire le segment avant un séparateur.

Cas réel

Ces mécaniques ne sont pas un jeu abstrait : elles font tourner les bibliothèques que tu utilises tous les jours. Une requête Prisma calcule le type de son résultat par des types conditionnels et mappés à partir de ton schéma — sélectionne trois colonnes, le type de retour n'en contient que trois. Quand un routeur typé t'autocomplète les paramètres de "/user/:id", c'est un template literal type qui a décomposé la chaîne pour en extraire id. Tu profites de la type gymnastics des auteurs de librairies sans jamais l'écrire toi-même — et c'est très bien ainsi.

Types récursifs

Un type peut se référencer lui-même. C'est ce qui permet de décrire des structures arbitrairement imbriquées comme du JSON, ou d'appliquer une transformation en profondeur. Voici un DeepReadonly qui descend dans les objets, et un type qui décrit une valeur JSON valide.

Astuce

Préfixe un type récursif par son cas de base et place le cas object après les cas plus spécifiques (tableau, fonction). En TypeScript, any[] et les fonctions satisfont aussi extends object : l'ordre des branches décide donc du résultat.

keyof, indexed access et leur combinaison

keyof T donne l'union des clés ; l'accès indexé T[K] donne le type de la valeur. Leur force apparaît quand on les combine : T[keyof T] est l'union de toutes les valeurs, et T[K] avec K extends keyof T permet d'écrire des accès génériques sûrs. Sur les tuples, T[number] donne le type d'élément.

Quand s'arrêter

Tout ceci est séduisant, mais un type illisible est une dette. Un bon repère : si l'auteur du type doit ajouter trois lignes de commentaire pour expliquer une seule ligne de type, c'est souvent qu'une fonction utilitaire à l'exécution, un type nommé intermédiaire, ou simplement un type plus large feraient mieux l'affaire. La type gymnastics se justifie dans une bibliothèque réutilisée par des dizaines de modules ; rarement dans le code applicatif courant.

Note

Découpe les types complexes en alias nommés intermédiaires, exactement comme tu extrairais des variables locales. type Keys = ... puis type Result = ...<Keys> se relit bien mieux qu'une expression de 80 colonnes, et les messages d'erreur de tsc deviennent plus lisibles.

Pièges fréquents

Piège fréquent

Distributivité non voulue. T extends any ? T[] : never sur string | number donne string[] | number[], pas (string | number)[]. Pour traiter l'union comme un bloc, enveloppe les deux côtés dans un tuple : [T] extends [any] ? .... Le tuple « casse » la distribution.

Piège fréquent

Récursion trop profonde. tsc coupe les types récursifs au-delà d'une certaine profondeur et lève Type instantiation is excessively deep and possibly infinite (ts(2589)). Si tu accumules dans un type-niveau (par ex. construire un grand tuple), repense l'algorithme ou ajoute un compteur de profondeur explicite pour borner la récursion.

Piège fréquent

Template literal types illisibles. Un motif comme `${A}-${B}_${C}` imbriqué sur trois niveaux devient vite indéchiffrable et explose le nombre de combinaisons quand A, B, C sont des unions. Nomme les étapes intermédiaires et, si le produit cartésien des littéraux dépasse quelques dizaines de cas, demande-toi si un type plus large (un simple string validé à l'exécution) ne suffit pas.

Pour aller plus loin

Pour aller plus loin

La bibliothèque type-fest rassemble des dizaines d'utilitaires de qualité production (Simplify, SetRequired, CamelCase…) : lis-en le code source, c'est la meilleure école de types avancés. Explore aussi l'opérateur satisfies (vérifier qu'une valeur respecte un type sans en élargir l'inférence), la variance des paramètres de fonction, et le profilage du compilateur avec tsc --generateTrace ./trace pour repérer les types coûteux à vérifier.

Antisèche

Glossaire

Type mappé
Type qui parcourt les clés d'un autre avec [K in keyof T] et applique une transformation à chacune.
Remapping de clés
Renommage ou filtrage d'une clé dans un type mappé via as ; mapper vers never supprime la clé.
Type conditionnel
Type « ternaire » T extends U ? X : Y qui choisit un type selon une relation de sous-typage.
Distributivité
Application d'un conditionnel à chaque membre d'une union (quand T est un paramètre nu) ; bloquée par [T] extends [U].
infer
Déclare une variable de type dans la branche extends pour capturer un sous-type par filtrage de motif.
Template literal type
Gabarit de chaîne au niveau type (`on${K}`) pour construire ou décomposer des littéraux de chaîne.
Type récursif
Type qui se référence lui-même pour décrire des structures imbriquées ; sa profondeur est bornée par le compilateur.
never
Type « aucune valeur » ; il s'absorbe dans une union (string | never = string) et sert à éliminer un cas.

Récap et vérification

  • Les types mappés acceptent les modificateurs +/-readonly et +/-?, plus le remapping de clés via as (vers never pour filtrer).
  • T extends U ? X : Y distribue sur les unions quand T est un paramètre nu ; on bloque la distribution avec [T] extends [U].
  • infer capture un type par filtrage de motif dans la branche extends, y compris dans un motif de chaîne.
  • Les template literal types construisent et décomposent des chaînes au niveau type, idéaux avec le remapping de clés.
  • Les types récursifs décrivent des structures imbriquées (JSON, DeepReadonly) mais sont bornés par le compilateur.
  • Privilégie la lisibilité : alias nommés, types plus larges, et utilitaires à l'exécution quand le type devient illisible.

Vérifie ta compréhension

  1. Pourquoi NonNull<string | null> donne-t-il string et non string | never visible ? Quel rôle joue la distributivité ?
  2. Écris de tête la signature d'un ElementType<T> qui fonctionne aussi sur les readonly arrays, en utilisant infer.
  3. Quand utiliserais-tu [T] extends [U] plutôt que T extends U ?
