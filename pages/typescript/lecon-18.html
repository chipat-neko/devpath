Gardes de type et fonctions d'assertion

~37 min Avancé Leçon 04 recommandée

À la fin de cette leçon, tu sauras

  • écrire une garde de type personnalisée (x is T) ;
  • écrire une fonction d'assertion (asserts) ;
  • exploiter les unions discriminées ;
  • garantir l'exhaustivité d'un switch avec never.
Sommaire de la leçon

Le compilateur sait rétrécir un type au fil des conditions : après un typeof x === "string", il traite x comme une chaîne. C'est le narrowing. Mais ses outils intégrés ne couvrent pas tout : pour les objets, les unions complexes ou les valeurs éventuellement absentes, on fabrique nos propres réducteurs de type. Cette leçon montre les trois outils du typage fin : les gardes de type, les fonctions d'assertion, et l'exhaustivité par never.

Unions discriminées et exhaustivité

Le patron le plus sûr pour manipuler « une chose parmi plusieurs » est l'union discriminée : chaque membre porte un champ littéral commun (le discriminant). Un switch dessus rétrécit chaque cas ; et une clause default qui affecte la valeur à never garantit qu'aucun cas n'est oublié :

Cas réel

Dans un reducer (façon Redux), l'état évolue selon des actions discriminées par un champ type : { type: "ajout" }, { type: "suppression" }… Le switch sur action.type traite chaque cas, et un default: const _: never = action ferme la marche. Le jour où un développeur ajoute une action "modification" sans écrire son case, le projet ne compile plus : le bug est attrapé à l'écriture, pas en production quand un utilisateur clique sur le bouton oublié. C'est le principal argument des unions discriminées : elles transforment un oubli en erreur de compilation.

Astuce

Pour qu'un discriminant soit bien un littéral ("cercle" et non string), fige-le avec as const quand tu construis l'objet à la volée : { kind: "cercle" as const, rayon: 3 }. Sinon TypeScript élargit kind en string et l'union ne se rétrécit plus.

Piège fréquent

Une garde ou une assertion est une promesse que TypeScript ne vérifie pas. Si le corps de estChat renvoie true à tort, le compilateur te croit : le narrowing devient faux et le code plantera à l'exécution. Le prédicat déplace la responsabilité sur toi : assure-toi que la logique interne teste réellement ce qu'elle annonce.

Pour aller plus loin

Ces outils rejoignent la validation aux frontières (leçon 15) : le safeParse de Zod renvoie justement une union discriminée { success: true; data } | { success: false; error } — un if (r.success) rétrécit vers la donnée validée. Écrire ses propres gardes est le pendant « fait main » de cette idée ; les bibliothèques de schémas ne font que la généraliser et la fiabiliser.

Glossaire

Narrowing
Rétrécissement d'un type au fil des conditions (ex. après typeof x === "string", x devient string).
Garde de type
Fonction à signature x is T ; si elle renvoie true, elle rétrécit la variable vers T.
Prédicat de type
Autre nom de la garde : l'annotation param is Type placée sur le retour.
Fonction d'assertion
Fonction annotée asserts … qui lève si la condition est fausse et affine le type pour la suite.
Union discriminée
Union dont chaque membre partage un champ littéral commun (le discriminant) permettant de les distinguer.
Discriminant
Le champ littéral (souvent kind ou type) sur lequel on branche pour rétrécir l'union.
Exhaustivité
Garantie que tous les cas d'une union sont traités ; vérifiée en affectant le reste à never.
never
Type « aucune valeur possible » ; sert de garde-fou : y affecter une valeur non vide échoue.

Récap et vérification

  • Une garde x is T rétrécit le type dans la branche if.
  • Une fonction d'assertion asserts lève sinon, et rétrécit pour toute la suite.
  • Les unions discriminées se manipulent par switch sur le discriminant.
  • const _: never = x garantit l'exhaustivité : un cas oublié ne compile plus.

Exercice 3Défi

Quand préférer une fonction d'assertion à une garde ?

Voir une solution

Quand la valeur doit avoir le bon type pour continuer et qu'une valeur invalide est une erreur (et non un cas à gérer). L'assertion lève alors immédiatement, et surtout elle affine le type pour tout le reste de la fonction sans imposer un bloc if : idéal pour « cette variable ne peut pas être null ici, sinon on arrête ». La garde, elle, convient quand les deux branches (true/false) sont deux cas légitimes à traiter différemment.
