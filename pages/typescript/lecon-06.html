Module 02 · Le système de types — Leçon 06

Les génériques

~38 min Avancé Leçon 5 recommandée

À la fin de cette leçon, tu sauras

  • savoir écrire une fonction générique avec un ou plusieurs paramètres de type (<T>, <K, V>)
  • savoir poser une contrainte avec extends (dont T extends keyof O) pour des accès sûrs
  • savoir créer des interfaces et classes génériques et utiliser une valeur par défaut de paramètre de type
  • savoir reconnaître les génériques de la bibliothèque standard (Array<T>, Promise<T>, Map<K, V>) et éviter la sur-généralisation.
Sommaire de la leçon

Jusqu'ici, tu as appris à donner un type précis à une valeur : string, number[], ou une interface bien définie. Mais comment typer une fonction qui doit marcher avec n'importe quel type, tout en gardant le lien entre ce qu'elle reçoit et ce qu'elle renvoie ? C'est exactement le rôle des génériques : du code réutilisable qui ne perd pas l'information de type au passage.

Dans cette leçon, on part d'un problème concret — une fonction qui doit retourner le même type qu'elle reçoit — puis on construit pas à pas les fonctions, interfaces et classes génériques, avec leurs contraintes. Tu verras qu'une fois le concept en main, tu reconnaîtras les génériques partout dans TypeScript.

Le problème : préserver le type d'entrée

Imagine une fonction identite qui reçoit une valeur et la renvoie telle quelle. En JavaScript, c'est trivial. En TypeScript, comment la typer ? La tentation est d'utiliser any :

Avec any, le compilateur ne voit plus que n est un nombre : il accepte n'importe quel appel dessus. On a désactivé le typage au lieu de l'exploiter. Ce qu'on veut, c'est dire : « le type de sortie est le même que le type d'entrée, quel qu'il soit ». C'est précisément ce qu'un paramètre de type exprime.

Les fonctions génériques

On introduit une variable de type, par convention nommée T, entre chevrons juste après le nom de la fonction. T n'est pas une valeur : c'est un type déduit au moment de l'appel.

Le lien entrée → sortie est rétabli : passer un number donne un number en retour, passer un string donne un string. Tu n'as rien écrit de plus à l'appel : TypeScript infère T tout seul. Un exemple plus utile, une fonction qui renvoie le premier élément d'un tableau :

Pourquoi les génériques sont partout

Tu as déjà utilisé des génériques sans le savoir : la bibliothèque standard de TypeScript en est tissée. Les types des structures que tu manipules tous les jours sont génériques :

Array<T> est « un tableau de T », Promise<T> est « une promesse qui résoudra un T », Map<K, V> est « une table de clés K vers des valeurs V ». Comprendre les génériques, c'est donc aussi comprendre la signature de presque toutes les API typées que tu croiseras.

Cas réel

Le client d'API typé est le cas d'école du générique. On écrit une seule fonction : async function get<T>(url: string): Promise<T> { const r = await fetch(url); return r.json(); }. Puis const u = await get<Utilisateur>("/api/moi") donne un u typé Utilisateur sans rien redéclarer : u.emial (faute de frappe) est aussitôt refusé. Sans le générique, r.json() renvoie any et toute la chaîne perd son typage. C'est exactement le même mécanisme que useState<T> en React ou Map<K, V> : un conteneur réutilisable qui n'oublie jamais ce qu'il transporte.

Bonnes pratiques

Un générique n'est utile que s'il relie plusieurs positions (entrée et sortie, deux paramètres entre eux). Un paramètre de type utilisé une seule fois n'apporte rien : il peut souvent être remplacé par le type direct attendu.

Attention toutefois : unknown n'est pas un remplaçant universel d'un générique. Il convient ici parce qu'on se contente de journaliser x ; dès qu'il faut réutiliser la valeur en gardant son type, c'est bien un générique qu'il faut. Côté nommage, suis les conventions : T (type générique), K/V (clé/valeur), E (élément). Pour des génériques riches, un nom parlant comme <TItem> reste lisible.

Pièges fréquents

Piège fréquent

Remplacer un générique par any « pour que ça passe » : tu perds le lien entre l'entrée et la sortie, et donc toute l'aide du compilateur. Un générique conserve l'information de type, any la jette.

Piège fréquent

Accéder à une propriété sans contrainte : function f<T>(x: T) { return x.length; } échoue, car rien ne garantit que T a un length. Ajoute <T extends { length: number }>.

Note

Ne confonds pas un paramètre de type (entre <>, vit à la compilation) et un paramètre de valeur (entre (), existe à l'exécution). T disparaît une fois le code compilé en JavaScript ; il ne sert qu'au vérificateur de types.

Pour aller plus loin

Pour aller plus loin

Les génériques sont la base des types conditionnels et des types mappés (leçon 7), qui transforment un type en un autre, parfois avec le mot-clé infer. Tu rencontreras aussi la notion de variance (quand un Boite<Chat> est-il un Boite<Animal> ?) et, côté React, des composants et props génériques comme useState<T> ou Array<Props>.

Antisèche

Glossaire

Générique
Code (fonction, interface, classe) paramétré par un ou plusieurs types, réutilisable sans perdre l'information de type.
Paramètre de type
Variable de type entre chevrons (<T>), déduite à l'appel ; vit à la compilation et disparaît du JavaScript produit.
Inférence de type
Déduction automatique de T par le compilateur à partir des arguments, sans l'écrire explicitement.
Contrainte (extends)
Borne qui restreint T aux types satisfaisant une forme, autorisant en retour des accès sûrs.
keyof
Opérateur de type produisant l'union des clés d'un type ; K extends keyof O garantit une clé valide.
Accès indexé (O[K])
Récupère le type de la valeur associée à une clé, pour un retour exact plutôt qu'élargi.
Valeur de type par défaut
Type utilisé quand le paramètre générique n'est pas précisé (<T = string>).
Sur-généralisation
Défaut consistant à introduire un T utilisé une seule fois : il ne relie rien et complique inutilement.

Récap et vérification

  • Un générique introduit une variable de type <T> déduite à l'appel, qui préserve le lien entrée → sortie là où any le détruit.
  • On peut avoir plusieurs paramètres de type (<K, V>), chacun déduit indépendamment.
  • Une contrainte extends restreint T et autorise des accès sûrs ; K extends keyof O sécurise l'accès aux propriétés.
  • Interfaces et classes se paramètrent (Boite<T>, Pile<T>) ; un paramètre de type peut avoir une valeur par défaut (<T = string>).
  • Array<T>, Promise<T> et Map<K, V> montrent que les génériques sont partout dans TypeScript.

  3. Quelle différence y a-t-il entre un paramètre de type et un paramètre de valeur, et lequel disparaît après compilation ?
