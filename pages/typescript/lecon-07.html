Module 02 · Le système de types — Leçon 07

Types utilitaires et transformation de types

~37 min Avancé Leçon 6 recommandée

À la fin de cette leçon, tu sauras

  • savoir dériver un type d'un autre avec keyof, typeof et l'accès indexé T["clé"] ;
  • savoir utiliser les utility types intégrés (Partial, Required, Pick, Omit, Record, ReturnType…) ;
  • savoir écrire un type mappé { [K in keyof T]: … } pour transformer chaque propriété ;
  • savoir lire un type conditionnel T extends U ? X : Y et reconnaître infer.
Sommaire de la leçon

En JavaScript, quand deux objets partagent une forme, tu finis souvent par recopier la même structure à plusieurs endroits. En TypeScript, tu peux faire mieux : tu définis un seul type « source de vérité » et tu en dérives toutes les variantes dont tu as besoin. Plus de copier-coller de structures qui se désynchronisent dès qu'une propriété change.

Dans cette leçon, tu pars d'une interface Utilisateur et tu apprends à en extraire des morceaux, à transformer ses propriétés et à fabriquer de nouveaux types sans jamais réécrire la liste de ses champs. Tout se passe au moment de la compilation : ces outils décrivent des types, ils ne produisent aucune ligne de code à l'exécution.

Un type comme source de vérité

Tout part d'un type de référence. Si tu le définis une seule fois et que tu en dérives le reste, une modification se propage automatiquement partout. C'est l'objectif de toute cette leçon.

keyof et typeof

keyof T récupère les clés d'un type sous forme d'union de littéraux. C'est l'équivalent, au niveau des types, de la liste des noms de propriétés. À ne pas confondre avec Object.keys, qui s'exécute à l'exécution et renvoie un tableau de string.

typeof, lui, prend une valeur existante et te donne son type. Pratique quand la valeur (souvent un objet de configuration) est la vraie source de vérité.

Note

Le typeof de TypeScript s'écrit comme l'opérateur JavaScript, mais il vit dans le monde des types : on l'utilise après type … = ou dans une annotation, jamais dans une expression exécutée.

L'accès indexé

Tu peux lire le type d'une propriété précise, comme on lit une valeur dans un objet, mais avec des crochets sur le type. Ça évite de réécrire à la main le type d'un champ qui pourrait évoluer.

Les utility types intégrés

TypeScript fournit des types génériques prêts à l'emploi qui transforment un type existant. Ce sont tes outils du quotidien. Voici les plus utiles, avec leur résultat en commentaire.

Record<K, V> construit un type « objet » dont les clés et les valeurs ont un type donné. Parfait pour un index ou un dictionnaire.

Enfin, certains utility types travaillent sur des fonctions. ReturnType<F> extrait le type de retour, Parameters<F> le tuple des paramètres, et NonNullable<T> retire null et undefined.

Cas réel

Une même entité Utilisateur nourrit toute une API sans jamais recopier ses champs. À la création, le serveur génère l'id : l'entrée est Omit<Utilisateur, "id">. Pour une mise à jour partielle (PATCH), on accepte n'importe quel sous-ensemble : Partial<Omit<Utilisateur, "id">>. Et la réponse renvoyée au client masque les champs sensibles (mot de passe, jeton…) : Omit<Utilisateur, "motDePasse">. Ajoute un champ à Utilisateur, et ces trois vues se mettent à jour seules — impossible d'en oublier une. C'est le cœur des back-ends typés (NestJS, tRPC, Prisma) : un modèle unique, des vues dérivées cohérentes.

Les types mappés

Les utility types ne sortent pas de nulle part : tu peux les réécrire toi-même avec un type mappé, qui parcourt chaque clé d'un type avec [K in keyof T] et applique une transformation. C'est la mécanique derrière Partial, Readonly et compagnie.

On peut aussi ajouter ou retirer les modificateurs ? (optionnel) et readonly avec les préfixes + et -. Par exemple, -? rend une propriété obligatoire : c'est exactement comme ça que Required<T> est défini.

Les types conditionnels en survol

Tu croiseras aussi des types conditionnels, qui choisissent un type selon une condition : T extends U ? X : Y. Lis-le comme un ternaire, mais sur les types. Le mot-clé infer permet de capturer un type au passage ; c'est, par exemple, ainsi qu'est écrit ReturnType.

Tu n'as pas besoin d'en écrire dès maintenant : l'essentiel est de les reconnaître quand tu survoles un type dans ton éditeur.

Quand s'arrêter

Ces outils sont puissants, mais la lisibilité prime sur la virtuosité. Un type que personne ne relit sans effort est un coût, pas un atout. Si une dérivation devient illisible, écris plutôt un type explicite et commente-le. Le but reste de supprimer la duplication, pas de gagner un concours.

Pièges fréquents

Piège fréquent

Recopier à la main la forme d'un type au lieu de le dériver. Le jour où la source change, ta copie ne suit pas et les deux se désynchronisent en silence. Préfère Pick, Omit ou un accès indexé.

Piège fréquent

Confondre keyof (monde des types, à la compilation) et Object.keys (valeur réelle, à l'exécution). Object.keys renvoie un string[] « élargi », pas l'union littérale des clés. Et abuser des types conditionnels imbriqués : au-delà de deux niveaux, plus personne ne les lit.

Piège fréquent

Omit<T, K> ne vérifie pas que les clés retirées existent vraiment dans T : Omit<Utilisateur, "telephon"> (faute de frappe) ne déclenche aucune erreur. Si tu renommes un champ sans corriger l'Omit, la dérivation ne suit pas. Pick, lui, refuse une clé inconnue.

Glossaire

keyof
Opérateur de type produisant l'union littérale des clés d'un type (keyof T), connue à la compilation.
typeof (de type)
Prend une valeur existante et donne son type ; utile quand un objet de config est la source de vérité.
Accès indexé
Écriture T["cle"] qui lit le type d'une propriété précise, sans le réécrire à la main.
Utility type
Type générique intégré qui transforme un type existant (Partial, Pick, Omit, Record…).
Type mappé
Type qui parcourt les clés d'un autre avec [K in keyof T] et applique une transformation à chacune.
Type conditionnel
Type « ternaire » T extends U ? X : Y qui choisit un type selon une condition.
infer
Dans un type conditionnel, capture un type au passage (ex. le type de retour dans ReturnType).
Source de vérité
Type défini une seule fois duquel on dérive toutes les variantes, pour éviter la duplication et la désynchronisation.

Récap et vérification

  • Source de vérité : un type défini une fois, des variantes dérivées partout.
  • keyof T = union des clés (type) ; typeof valeur = type d'une valeur ; T["cle"] = accès indexé.
  • Utility types : Partial, Required, Readonly, Pick, Omit, Record, ReturnType, Parameters, NonNullable.
  • Type mappé { [K in keyof T]: … } pour transformer chaque propriété ; +/- et ?/readonly pour les modificateurs.
  • Type conditionnel T extends U ? X : Y avec infer pour capturer : à reconnaître plus qu'à écrire.
  • Lisibilité d'abord : dérive pour supprimer la duplication, pas pour la performance.

Vérifie ta compréhension

  3. Avec quel utility type construis-tu un compteur « mot → nombre » ?
