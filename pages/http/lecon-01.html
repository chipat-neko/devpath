Module 1 · Le web, comment ça marche — Leçon 01

Le web : client, serveur et Internet

~24 min Débutant Aucun prérequis

À la fin de cette leçon, tu sauras

  • expliquer le modèle client-serveur ;
  • distinguer le web d'Internet ;
  • dire à quoi sert une adresse IP ;
  • raconter le voyage d'une page web.
Sommaire de la leçon

Quand tu tapes une adresse et qu'une page s'affiche, un dialogue invisible vient de se jouer entre ta machine et un ordinateur à l'autre bout du monde. Comprendre ce dialogue — c'est le but de ce cours — change la façon dont on construit et débogue un site. On commence par la fondation : qui parle à qui, et par quels tuyaux. Pas besoin de savoir programmer pour cette leçon.

Le modèle client-serveur

Le web repose sur une idée simple : deux rôles qui se répondent.

  • le client : le programme qui demande. Le plus souvent ton navigateur (Firefox, Chrome…), mais aussi une application mobile ou un outil en ligne de commande.
  • le serveur : l'ordinateur, toujours allumé, qui répond en renvoyant la page, l'image ou les données demandées.

Le client envoie une requête, le serveur renvoie une réponse. C'est tout le principe : un échange en deux temps, à l'initiative du client. Le serveur, lui, attend les demandes et y répond une à une. Ce langage commun qu'ils parlent pour le web s'appelle HTTP (on l'étudiera en détail dès la leçon 03).

Web et Internet : ne pas confondre

On emploie les deux mots comme synonymes, à tort.

  • Internet est le réseau : l'infrastructure mondiale de câbles, routeurs et machines reliés entre eux. C'est la route.
  • le web est un service qui circule sur cette route : l'ensemble des pages et applications accessibles via HTTP. C'est un véhicule parmi d'autres (l'e-mail, par exemple, en est un autre).

Autrement dit : le web a besoin d'Internet pour exister, mais Internet ne se réduit pas au web. Ce cours parle du web et de son protocole, HTTP.

Vois-le toi-même

Ouvre les outils de développement de ton navigateur (touche F12), onglet Réseau (Network), puis recharge une page. Tu verras la liste réelle de toutes les requêtes : la page, puis chaque image, script et style, avec leur statut et leur durée. C'est le cours qui prend vie sous tes yeux ; reviens-y à chaque leçon.

Cas réel

Le 4 octobre 2021, Facebook, Instagram et WhatsApp sont devenus injoignables pendant près de six heures. Leurs serveurs, pourtant, fonctionnaient : ce qui avait disparu, c'était la route. Une mauvaise manœuvre avait retiré du réseau les annonces qui indiquaient aux routeurs du monde comment atteindre les adresses IP de Facebook. Sans chemin vers l'IP, aucune requête ne pouvait aboutir : une panne du réseau, pas du service. Détail parlant : leurs propres badges d'accès aux bâtiments, branchés au même réseau, ont cessé de fonctionner. La distinction réseau/service n'est pas qu'un mot de vocabulaire.

Pour aller plus loin

Sous HTTP, deux protocoles font le vrai travail de livraison : IP achemine les paquets d'une adresse à l'autre, et TCP garantit qu'ils arrivent tous, dans l'ordre. C'est la fameuse pile TCP/IP. HTTP se pose au sommet ; HTTPS y ajoute le chiffrement (leçon 06). Chaque service a en plus un numéro de port : 80 pour HTTP, 443 pour HTTPS — comme un numéro d'appartement à l'adresse IP de l'immeuble.

Antisèche

Glossaire

Client
Programme qui demande une ressource : le plus souvent le navigateur, mais aussi une appli mobile ou un outil en ligne de commande.
Serveur
Ordinateur toujours allumé qui répond aux requêtes en renvoyant pages, images ou données.
Requête / Réponse
Les deux temps d'un échange web : le client émet une requête, le serveur renvoie une réponse. L'initiative vient toujours du client.
HTTP
HyperText Transfer Protocol : le langage commun que client et serveur parlent pour échanger sur le web.
Internet
Le réseau mondial d'infrastructures (câbles, routeurs, machines) reliées entre elles : la « route ».
Web
Un service qui circule sur Internet : l'ensemble des pages et applications accessibles via HTTP.
Adresse IP
Identifiant numérique unique d'une machine sur le réseau (ex. 93.184.216.34), comparable à une adresse postale.
Nom de domaine / DNS
Le nom de domaine (exemple.com) est un alias lisible d'une adresse IP ; le DNS assure la traduction du nom vers l'IP.

Récap et vérification

  • Le web suit le modèle client-serveur : le client (navigateur) envoie une requête, le serveur renvoie une réponse.
  • Internet est le réseau (la route) ; le web est un service qui y circule (un véhicule), via le protocole HTTP.
  • Chaque machine a une adresse IP ; on utilise un nom de domaine plus lisible, traduit en IP par le DNS.
  • Afficher une page déclenche plusieurs requêtes (HTML, puis CSS, images, scripts), toutes sur le même schéma requête/réponse.

Vérifie ta compréhension

  1. Qui envoie la requête et qui envoie la réponse ?
  2. Quelle est la différence entre le web et Internet ?
  3. Pourquoi une seule page web génère-t-elle souvent plusieurs requêtes ?

Exercices

Exercice 1Échauffement

Avec une analogie au restaurant, décris les rôles du client et du serveur sur le web.

Voir une solution

Le client (navigateur) est le client du restaurant : il commande (envoie une requête). Le serveur web est le serveur de salle : il prend la commande, va chercher le plat en cuisine et le rapporte (la réponse). Le client ne va jamais en cuisine ; il demande, on lui apporte. Et il peut passer plusieurs commandes (plusieurs requêtes) au cours du repas.

Exercice 2Application

Ouvre l'onglet Réseau des outils de développement (F12) et recharge une page d'actualités. Que t'attends-tu à voir, et qu'est-ce que cela illustre ?

Voir une solution

On voit une longue liste de requêtes : d'abord le document HTML, puis quantité de ressources (feuilles de style, scripts, images, polices, parfois publicités et trackers). Chaque ligne montre une URL, un code de statut (souvent 200), un type et une durée. Cela illustre que l'affichage d'une page est en réalité la somme de nombreux échanges requête/réponse indépendants, et explique pourquoi une page lourde met du temps à charger.

Exercice 3Défi

On dit que « le web fonctionne, même si une partie d'Internet tombe en panne ». En t'appuyant sur la distinction réseau/service et sur les adresses IP, propose une explication.

Voir une solution

Internet est un réseau maillé : les machines sont reliées par de multiples chemins, pas un seul. Quand un message part vers une adresse IP, il est découpé en paquets que des routeurs acheminent de proche en proche ; si un câble ou un routeur tombe, les paquets empruntent un autre chemin pour atteindre la même IP. Le web, lui, n'est qu'un service posé au-dessus de ce réseau : tant qu'il existe au moins une route entre ton client et le serveur visé, l'échange requête/réponse aboutit. C'est précisément la robustesse pour laquelle Internet a été conçu : décentralisé, sans point unique de défaillance. (Si le serveur lui-même tombe, en revanche, sa page devient inaccessible : la panne d'un service n'est pas la panne du réseau.)
