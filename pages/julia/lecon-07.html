Le multiple dispatch

~55 min Avancé Prérequis : leçon 6

À la fin de cette leçon, tu sauras

  • comprendre le multiple dispatch et ses différences avec la POO classique ;
  • définir plusieurs méthodes d'une même fonction selon les types ;
  • exploiter les types abstraits pour des méthodes génériques ;
  • voir pourquoi ce paradigme rend le code extensible et rapide.
Sommaire de la leçon

Voici le concept qui fait l'identité de Julia : le multiple dispatch. C'est l'idée que le comportement d'une fonction est choisi selon les types de tous ses arguments. Cela paraît subtil, mais c'est le secret de l'élégance et de l'extensibilité de Julia. Une fois compris, on ne voit plus la programmation pareil.

Une fonction, plusieurs méthodes

En Julia, une function peut avoir plusieurs méthodes : des définitions différentes selon les types des arguments. Julia choisit automatiquement la bonne à l'appel.

Ce ne sont pas des fonctions différentes : ce sont des méthodes de la même fonction aire.

Dispatcher sur le type

L'annotation ::Type sur un argument indique pour quel type la méthode s'applique. Avec des types abstraits, on couvre des familles entières.

Julia choisit toujours la méthode la plus spécifique qui correspond : Int avant Number.

Dispatcher sur ses propres types

Le multiple dispatch brille avec des types abstraits et des structs. On définit une hiérarchie, puis des méthodes par type concret.

Pourquoi c'est puissant

En POO classique, une méthode « appartient » à une classe (cercle.aire()). En Julia, les fonctions sont libres et dispatchent sur tous leurs arguments. Conséquence majeure : tu peux ajouter une méthode à une fonction existante (même de la stdlib !) pour tes types, sans modifier le code original. C'est l'extensibilité ultime.

Dispatcher sur plusieurs arguments

Le « multiple » de multiple dispatch : la méthode est choisie selon la combinaison des types de plusieurs arguments — impossible en POO simple.

Pièges fréquents

Piège fréquent

Trop spécialiser les types des arguments : une méthode f(x::Float64) ne s'appliquera pas à un Int ! Pour rester générique, annote avec un type abstrait (::Real, ::Number) ou n'annote pas du tout — Julia spécialisera quand même à la compilation.

Pour aller plus loin

Pour aller plus loin

methods(aire) liste toutes les méthodes d'une fonction ; @which aire(3.0) dit laquelle sera appelée. Ces outils sont précieux pour comprendre un gros écosystème Julia, où des centaines de packages s'enrichissent mutuellement par dispatch.

Un cas réel

Cas réel — des packages qui coopèrent sans se connaître

C'est le multiple dispatch qui donne à l'écosystème Julia sa réputation de « composabilité ». Le package Measurements.jl définit un type Measurement (une valeur ± son incertitude) et enseigne à +, *, sqrt… comment le manipuler. Le package DifferentialEquations.jl, écrit indépendamment et sans rien connaître de Measurements, résout des équations sur n'importe quel type de nombre. Résultat : on peut résoudre une équation différentielle en propageant automatiquement les barres d'erreur, alors que les deux auteurs ne se sont jamais concertés. En POO classique, il aurait fallu modifier l'une des deux bibliothèques ; ici, le dispatch les fait coopérer gratuitement. C'est la réponse de Julia au fameux « problème de l'expression ».

Glossaire

Fonction générique
Nom de fonction regroupant plusieurs méthodes ; à l'appel, Julia choisit la méthode adaptée aux types des arguments.
Méthode
Implémentation concrète d'une fonction pour une signature de types donnée (aire(c::Cercle)).
Multiple dispatch (répartition multiple)
Choix de la méthode selon les types de tous les arguments, pas seulement du premier.
Signature
La combinaison de types des paramètres d'une méthode ((::Cercle, ::Carre)), qui sert à la sélectionner.
Spécificité
Quand plusieurs méthodes conviennent, Julia retient la plus précise (::Int avant ::Number).
Type abstrait
Type sans champ (abstract type Forme end) servant de racine à une famille pour écrire des méthodes génériques.
Extensibilité
Capacité d'ajouter une méthode à une fonction existante (même de Base) pour ses propres types, sans toucher au code d'origine.
Ambiguïté
Situation où deux méthodes conviennent sans que l'une soit plus spécifique : Julia lève une erreur d'ambiguïté à résoudre en précisant une méthode.

Récap et vérification

  • Une fonction peut avoir plusieurs méthodes selon les types de ses arguments.
  • Julia choisit la méthode la plus spécifique qui correspond.
  • On dispatche sur ses propres types (hiérarchie abstract type + structs).
  • On peut étendre des fonctions existantes pour ses types : extensibilité maximale.

Vérifie ta compréhension

  1. Qu'est-ce qu'une « méthode » au sens de Julia ?
  2. En quoi le multiple dispatch diffère-t-il de la POO classique ?
  3. Si f(x::Int) et f(x::Number) existent, laquelle appelle f(5) ?
