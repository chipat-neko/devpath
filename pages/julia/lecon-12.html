Métaprogrammation : expressions et macros

~52 min Avancé Prérequis : leçon 04

À la fin de cette leçon, tu sauras

  • comprendre que le code est une donnée (Expr, Symbol) ;
  • citer du code avec :( )/quote et l'interpoler avec $ ;
  • écrire une macro qui transforme le code avant exécution ;
  • inspecter avec @macroexpand et savoir quand ne pas en écrire.
Sommaire de la leçon

Julia possède un super-pouvoir hérité de la famille Lisp : il peut se regarder lui-même. Un morceau de code n'est pas qu'un texte à exécuter : c'est une donnée qu'on peut inspecter, construire et transformer avant qu'elle ne tourne. C'est la métaprogrammation — et c'est ce qui se cache derrière @time, @assert et les fameux DSL scientifiques comme JuMP.

Le code est une donnée

Quand Julia lit a + b * 2, il en construit une expression (type Expr) : un petit arbre. Chaque nœud a une tête (head, ici :call) et des arguments (args). Les noms de variables y sont des symboles (type Symbol, écrits :a).

Citer du code : :( ) et quote

Citer (quoting), c'est fabriquer une expression sans l'exécuter. Deux formes : :( ... ) pour une ligne, quote ... end pour un bloc.

eval est un dernier recours

eval s'exécute au niveau du module global, pas dans la portée locale, et il empêche le compilateur d'optimiser. On l'utilise pour générer du code au chargement (ex. définir des fonctions en boucle), presque jamais dans une fonction courante. Si tu te surprends à appeler eval dans une boucle chaude, c'est le signe qu'une autre approche (dispatch, fonction d'ordre supérieur) convient mieux.

Les macros : transformer le code avant l'exécution

Pourquoi une macro et pas une fonction ?

Parce qu'une macro voit le code source, pas seulement les valeurs. @assert x > 0 peut afficher le texte "x > 0" dans son message d'erreur ; @time expr peut entourer l'expression de mesures sans l'évaluer d'abord. Une fonction, qui ne reçoit que le résultat déjà calculé, en serait incapable.

Cas réel — les DSL qui se lisent comme des maths

La force scientifique de Julia tient beaucoup aux macros. Avec JuMP (optimisation), on écrit @variable(m, x >= 0), @constraint(m, 2x + y <= 10), @objective(m, Max, 5x + 4y) : le modèle se lit comme sa notation mathématique. Ces macros transforment ces lignes en un code efficace pour le solveur. Même principe pour Turing.jl (@model pour l'inférence bayésienne) ou DifferentialEquations.jl. Sans métaprogrammation, il faudrait construire ces modèles à la main, ligne par ligne : illisible. La macro offre une langue dédiée au domaine, tout en restant du Julia compilé.

Pour aller plus loin

Les macros sérieuses doivent être hygiéniques : Julia renomme automatiquement les variables qu'elles introduisent pour éviter qu'elles n'entrent en collision avec celles de l'utilisateur (on utilise esc() pour désigner explicitement ce qui appartient à l'appelant). Au-delà, les fonctions générées (@generated) produisent un code spécialisé selon les types des arguments : le sommet de la performance, mais un outil de spécialiste.

Quand ne PAS écrire de macro

Les macros impressionnent, mais elles compliquent la lecture et le débogage. La règle : si une fonction suffit, écris une fonction. Réserve les macros aux cas où tu as besoin du code lui-même — mesurer une expression, bâtir un DSL, générer des définitions. Pour tout le reste, le multiple dispatch (leçon 07) et les fonctions d'ordre supérieur sont plus simples et tout aussi puissants.

Glossaire

Métaprogrammation
Écrire du code qui manipule du code : en Julia, inspecter et transformer des expressions avant leur exécution.
Expr
Type représentant une expression Julia sous forme d'arbre, avec une head et des args.
Symbol
Nom (identifiant) utilisé comme donnée, écrit avec deux-points : :x, :+.
Quoting (citation)
Fabriquer une expression sans l'exécuter, avec :( ) ou quote ... end.
Interpolation $
Insérer la valeur (ou l'expression) d'une variable dans du code cité.
eval
Exécuter une expression ; s'évalue dans la portée du module global.
Macro
Construction appelée avec @ qui reçoit du code et renvoie un nouveau code, inséré avant la compilation.
@macroexpand
Macro qui affiche le code réellement produit par une autre macro ; sert à comprendre et déboguer.

Récap et vérification

  • En Julia, le code est une donnée : une Expr (arbre avec head/args) dont les noms sont des Symbol.
  • On cite avec :( )/quote, on interpole avec $, on exécute avec eval.
  • Une macro transforme le code avant l'exécution ; une fonction agit sur les valeurs à l'exécution.
  • @macroexpand montre le code généré ; si une fonction suffit, préfère la fonction.

Exercices

Exercice 1Échauffement

Cite l'expression 3 * (4 + 1) sans la calculer, puis exécute-la avec eval.

Voir une solution

Tant qu'on ne fait qu'écrire :(...), on manipule du code-donnée. C'est eval qui déclenche le calcul.

Exercice 2Application

Écris une macro @deux_fois qui exécute deux fois l'expression qu'on lui passe.

Voir une solution

La macro reçoit l'expression ex (du code, pas un résultat) et renvoie un bloc qui la répète. esc(ex) garantit que l'expression s'exécute dans la portée de l'appelant (hygiène). Une fonction ne pourrait pas faire cela : elle recevrait le résultat déjà calculé une seule fois.

Exercice 3Défi

Utilise @macroexpand pour observer ce que produit @assert x > 0. Explique pourquoi @assert ne peut pas être une simple fonction.

Voir une solution

Le message d'erreur contient le texte de la condition, "x > 0". Une fonction assert(cond) ne recevrait que la valeur false : elle aurait perdu le code source, donc serait incapable d'afficher quelle condition a échoué. La macro, elle, voit l'Expr et peut à la fois l'évaluer et en réutiliser le texte. C'est exactement le genre de tâche qui justifie une macro plutôt qu'une fonction.
