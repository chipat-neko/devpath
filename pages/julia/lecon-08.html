Types et performance

~55 min Avancé Prérequis : leçon 7

À la fin de cette leçon, tu sauras

  • comprendre la stabilité de type et son impact sur la vitesse ;
  • éviter les variables globales non typées (le piège n°1) ;
  • mesurer avec @time et @benchmark ;
  • inspecter le code avec @code_warntype.
Sommaire de la leçon

Julia promet la vitesse du C — mais à une condition : écrire du code que le compilateur peut optimiser. La clé tient en deux mots : stabilité de type. Cette leçon t'apprend les quelques règles qui séparent un code Julia lent d'un code Julia fulgurant, et les outils pour les vérifier.

La règle d'or : tout dans des fonctions

La première règle de performance : ne fais pas de calcul lourd au niveau global d'un script. Mets-le dans une fonction. Julia compile et optimise les fonctions ; le code global, lui, reste interprété et lent.

La stabilité de type

Une fonction est type-stable si le type de chaque variable ne change pas en cours de route. Le compilateur peut alors générer du code machine spécialisé. Une variable qui change de type le force à des vérifications coûteuses.

Un détail aussi minime que 0 vs 0.0 peut multiplier le temps d'exécution.

Éviter les variables globales

Le piège n°1 de performance : utiliser une variable globale non typée dans une fonction. Le compilateur ne peut rien supposer sur son type. Passe-la en argument, ou déclare-la const si elle ne change pas.

Mesurer : @time et @benchmark

On ne devine pas la performance, on la mesure. La macro @time donne une première idée (rappelle-toi d'ignorer le premier appel, qui compile). Le package BenchmarkTools et sa macro @benchmark donnent une mesure fiable.

Diagnostiquer : @code_warntype

Pour traquer l'instabilité de type, @code_warntype affiche le code analysé : les types incertains apparaissent en rouge (souvent sous la forme Any ou Union). C'est l'outil du chasseur de lenteurs.

Pièges fréquents

Piège fréquent

N'optimise pas à l'aveugle ! Annoter tous les types « pour aller plus vite » n'aide généralement pas : Julia spécialise déjà. Les vrais leviers sont : code dans des fonctions, stabilité de type, pas de globales. Mesure d'abord, optimise ensuite.

Pour aller plus loin

Pour aller plus loin

Les allocations mémoire sont l'autre grand frein. @time les compte : vise zéro allocation dans les boucles chaudes (en réutilisant des tableaux, avec @view et les opérations en place !). C'est souvent là que se gagnent les facteurs 10.

Un cas réel

Cas réel — du petit script au pétaflop

Un analyste s'étonne qu'un calcul Julia soit plus lent que son équivalent Python. En sortant sa boucle du niveau global pour l'enfermer dans une fonction et en remplaçant 0 par 0.0, le temps chute d'un facteur ~50 — sans toucher à l'algorithme. Ce n'est pas une anecdote isolée : c'est cette même discipline de type qui a permis au projet astronomique Celeste.jl d'atteindre 1,5 pétaflop/s (plus de mille milliards d'opérations par seconde) sur le supercalculateur Cori en 2017, plaçant du code Julia lisible au niveau du C et du Fortran. La performance en Julia vient de la stabilité de type, pas d'annotations partout.

Glossaire

Stabilité de type
Propriété d'une fonction dont le type de retour se déduit des seuls types des arguments ; condition d'un code rapide.
Instabilité de type
Cas où une variable ou une valeur de retour change de type : l'inférence retombe sur Any et le code ralentit.
Inférence de type
Analyse par laquelle le compilateur déduit le type de chaque expression avant de générer le code machine.
Type concret
Type instanciable et précis (Float64, Int64) sur lequel Julia peut spécialiser ; s'oppose à Any.
Compilation JIT
Compilation « juste à temps » : la première exécution d'une fonction compile un code natif, réutilisé ensuite (d'où l'appel de « chauffe »).
Allocation mémoire
Réservation de mémoire sur le tas (nouveaux tableaux, objets) ; nombreuse en boucle chaude, elle sollicite le ramasse-miettes et freine.
@code_warntype
Macro affichant le code typé par l'inférence, signalant les types non concrets (Any, Union).
const
Déclare une globale dont le type ne changera plus, rendant son usage aussi rapide qu'une constante.

Récap et vérification

  • Mets tout calcul lourd dans des fonctions (pas au niveau global).
  • Vise la stabilité de type (attention à 0 vs 0.0).
  • Évite les globales non typées ; passe en argument ou utilise const.
  • Mesure avec @time/@benchmark, diagnostique avec @code_warntype.
