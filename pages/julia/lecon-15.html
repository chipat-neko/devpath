Module 4 · Aller plus loin — Leçon 15

Interfacer et déployer

~54 min Avancé Prérequis : leçon 09

À la fin de cette leçon, tu sauras

  • fixer un environnement reproductible avec Project.toml et Manifest.toml ;
  • appeler une fonction C avec ccall et une bibliothèque Python avec PyCall ;
  • comprendre la latence de compilation (le « time to first plot ») ;
  • produire un exécutable autonome avec PackageCompiler.
Sommaire de la leçon

Julia a résolu le « problème des deux langages » : on prototype et on optimise dans le même code. Mais un projet réel ne vit pas en vase clos : il faut figer ses dépendances, réutiliser des bibliothèques C ou Python existantes, et parfois livrer un programme qui démarre vite. C'est le sujet de cette leçon.

Des environnements reproductibles

Chaque projet Julia sérieux possède deux fichiers. Project.toml liste ce que tu demandes (les paquets directs) ; Manifest.toml fige les versions exactes de tout l'arbre de dépendances. À deux, ils garantissent qu'un collègue — ou toi, dans six mois — obtiendra le même environnement.

Appeler du C : ccall

Julia parle le C nativement, sans écrire de code de liaison. ccall appelle directement une fonction d'une bibliothèque partagée, avec un coût quasi nul : c'est ce qui lui permet de réutiliser des décennies de bibliothèques numériques éprouvées.

Réutiliser Python : PyCall

Besoin d'une bibliothèque qui n'existe qu'en Python ? PyCall (ou son cousin PythonCall) fait le pont : on importe un module et on appelle ses fonctions comme si elles étaient en Julia.

Cas réel — Julia comme chef d'orchestre

De nombreux paquets Julia sont en réalité des façades élégantes autour de bibliothèques C ou Fortran de référence. SpecialFunctions.jl s'appuie sur du code C éprouvé ; les solveurs d'équations différentielles historiques (SUNDIALS, écrit en C) sont pilotés depuis Julia via ccall ; et une équipe peut migrer progressivement un code Python vers Julia en gardant, le temps de la transition, les parties Python appelées par PyCall. On garde le meilleur des deux mondes : la vitesse et l'expressivité de Julia, sans jeter des années de bibliothèques déjà validées.

La latence de compilation

Le revers du JIT : le premier appel d'une fonction la compile, ce qui prend du temps. Historiquement, afficher un premier graphe pouvait demander plusieurs secondes — le fameux « time to first plot ». Une fois compilée, la fonction est ensuite quasi instantanée.

Latence de démarrage, pas d'exécution

Ce coût est payé une seule fois par session, à la première utilisation. Il pénalise les petits scripts en ligne de commande relancés sans cesse, jamais un service qui tourne en continu ni un long calcul. Les versions récentes de Julia (1.9+) l'ont beaucoup réduit grâce à la précompilation du code natif des paquets, mise en cache sur le disque.

Créer un exécutable : PackageCompiler

Pour livrer un programme qui démarre vite, PackageCompiler.jl compile ton code (et ses dépendances) en avance. Deux produits : une sysimage (image système préchauffée à charger dans le REPL) ou une application autonome distribuable, qui ne requiert pas d'installation de Julia chez l'utilisateur.

Pour aller plus loin

Pour réduire encore la latence, PrecompileTools.jl permet d'inscrire, dans ton package, des appels à précompiler à l'installation. Côté interopérabilité, Cxx.jl vise le C++, et RCall.jl le langage R. Enfin, pour exposer ton code Julia à d'autres langages, la macro Base.@ccallable et l'outil jlrs (côté Rust) ouvrent la porte inverse.

Glossaire

Project.toml
Fichier listant les dépendances directes d'un projet (ce que l'on demande).
Manifest.toml
Fichier figeant les versions exactes de toutes les dépendances, pour la reproductibilité.
Environnement
Ensemble des paquets activés pour un projet ; isolé du reste du système.
ccall
Appel direct d'une fonction d'une bibliothèque C partagée, sans code de liaison.
PyCall
Paquet qui permet d'importer et d'appeler des modules Python depuis Julia.
Time to first plot
Latence du premier appel, due à la compilation JIT ; payée une fois par session.
Sysimage
Image système contenant du code déjà compilé, chargée au démarrage pour l'accélérer.
PackageCompiler
Outil produisant des sysimages ou des exécutables autonomes.

Récap et vérification

  • Project.toml (paquets demandés) + Manifest.toml (versions figées) = environnement reproductible.
  • ccall appelle du C sans surcoût ; pyimport (PyCall) réutilise du Python.
  • La latence de compilation (time to first plot) se paie une fois par session, pas à chaque appel.
  • PackageCompiler produit une sysimage ou un exécutable autonome pour livrer.

Vérifie ta compréhension

  1. Que produit create_app, et quel problème cela résout-il ?
  2. Que fait ccall, et qu'exige-t-il de précis ?
  3. Pourquoi la latence de démarrage ne pénalise-t-elle pas un long calcul ?

Exercices

Exercice 1Échauffement

Dans le REPL, quelles commandes du mode Pkg (]) faut-il pour créer un environnement local et y ajouter le paquet Plots ?

Voir une solution

Après ces commandes, un Project.toml et un Manifest.toml apparaissent dans le dossier. Les partager suffit à recréer l'environnement ailleurs avec ] instantiate.

Exercice 2Application

Appelle la fonction C sqrt de la libm pour calculer la racine de 144.0, via ccall.

Voir une solution

On indique le symbole :sqrt et la bibliothèque "libm", puis le type de retour Float64, le tuple des types d'arguments (Float64,) (la virgule est indispensable pour un tuple à un élément), et enfin la valeur 144.0. Les types doivent correspondre exactement à la signature C.

Exercice 3Défi

Explique en une phrase pourquoi transformer un petit script relancé 500 fois par jour en une application PackageCompiler peut valoir la peine.

Voir une solution

Chaque lancement d'un script Julia « normal » repaie la latence de compilation (time to first plot). Multipliée par 500 démarrages quotidiens, cette seconde perdue devient un vrai coût. Une application compilée avec create_app embarque le code déjà compilé : elle démarre presque instantanément, et se distribue sans exiger d'installer Julia sur la machine cible.
