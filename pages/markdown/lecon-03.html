Module 1 · Les bases — Leçon 03

Liens, images et citations

~32 min Débutant Leçon 02 requise

À la fin de cette leçon, tu sauras

  • créer des liens (inline et par référence) ;
  • insérer des images ;
  • écrire des citations (blockquote) ;
  • tracer une règle horizontale.
Sommaire de la leçon

Un document n'est pas qu'un bloc de texte : il renvoie ailleurs, montre des images, cite des sources. Cette leçon complète tes bases avec les éléments qui relient et enrichissent un document Markdown : liens, images, citations et séparateurs.

Les liens

Un lien s'écrit en deux temps : le texte cliquable entre crochets, puis l'URL entre parenthèses, collés l'un à l'autre.

La forme est [texte](url) : le texte entre [ ] est ce qu'on voit, l'URL entre ( ) est la destination. On peut ajouter un titre (affiché au survol) entre guillemets après l'URL. C'est l'équivalent de la balise <a href> du HTML, en bien plus court.

Les liens par référence

Quand une même URL revient souvent, ou pour garder le texte propre, on utilise un lien par référence : on met une étiquette dans le texte, et on définit l'URL ailleurs (souvent en bas du document).

Avantage : le corps du texte reste lisible (pas de longues URL au milieu des phrases), et on gère toutes les adresses au même endroit. C'est très pratique pour un document riche en liens. Le rendu est identique à un lien inline.

Les images

Une image s'écrit comme un lien, précédé d'un point d'exclamation. Le texte entre crochets devient le texte alternatif (affiché si l'image ne charge pas, et lu par les lecteurs d'écran).

La syntaxe ![texte alternatif](chemin) ne diffère du lien que par le ! initial. Le texte alternatif n'est pas décoratif : décris vraiment l'image (accessibilité, cours HTML). Le chemin peut être relatif (un fichier du projet) ou une URL. C'est l'équivalent de la balise <img>.

Erreur fréquente

Une image liée par un chemin relatif (images/logo.png) s'affiche bien tant que le fichier .md et l'image gardent la même position l'un par rapport à l'autre. Déplace le .md ailleurs, ou colle son contenu dans un autre document, et l'image disparaît (icône cassée). Pour un contenu destiné à voyager, pointe vers une URL absolue ; pour un dépôt, garde le chemin relatif mais respecte l'arborescence.

Cas réel

Sur une pull request GitHub, on colle très souvent une capture d'écran pour montrer un bug ou un avant/après. GitHub génère alors automatiquement un Markdown d'image ![Capture…](https://…) avec une URL hébergée. Si tu remplaces le texte entre crochets par une vraie description (« le bouton d'envoi masqué sur mobile »), la personne qui relit sans charger les images (connexion lente, lecteur d'écran) comprend quand même de quoi il s'agit. Le texte alternatif n'est pas une formalité : c'est ce qui reste quand l'image manque.

Les citations

Une citation (blockquote) met un passage en retrait, comme pour rapporter les propos de quelqu'un. On préfixe chaque ligne d'un chevron >.

Le chevron > en début de ligne crée le retrait visuel (équivalent du <blockquote> HTML). On peut citer sur plusieurs lignes et même imbriquer (un > de plus). Les citations servent à mettre en valeur une remarque, un avertissement, ou un extrait rapporté.

La règle horizontale

Pour séparer visuellement deux sections, on trace une règle horizontale (une ligne) avec trois tirets (ou astérisques) seuls sur une ligne.

Trois tirets --- sur une ligne vide produisent un trait horizontal (le <hr> du HTML). Attention : trois tirets juste sous un texte (sans ligne vide avant) seraient interprétés comme un soulignement de titre par certains outils ; laisse une ligne vide avant et après pour obtenir bien une règle.

Les liens automatiques

Beaucoup d'outils transforment une URL écrite directement en lien cliquable (un autolien). En CommonMark, on peut aussi entourer une URL de chevrons pour la rendre explicitement cliquable : <https://exemple.com>. Pratique pour partager une adresse sans texte de remplacement. Mais pour un lien lisible, préfère la forme [texte](url) : un lien dont le texte décrit la destination est plus clair qu'une longue URL brute.

Glossaire

Lien inline
Lien dont l'URL est écrite directement dans la phrase : [texte](url). La forme la plus courante.
Lien par référence
Lien dont l'URL est définie ailleurs (souvent en bas) via une étiquette : [texte][id] puis [id]: url. Garde le texte lisible.
Étiquette (label)
Identifiant entre crochets qui relie un lien par référence à sa définition. Réutilisable plusieurs fois pour une même adresse.
Texte alternatif
Description d'une image, entre [ ] dans ![alt](chemin) : affichée si l'image manque, lue par les lecteurs d'écran.
Blockquote
Citation en retrait, obtenue en préfixant les lignes de > ; imbricable avec > >.
Règle horizontale
Trait de séparation entre sections : --- (ou ***) seul sur une ligne, entouré de lignes vides. Rend un <hr>.
Autolien
URL rendue cliquable telle quelle, soit automatiquement, soit encadrée de chevrons <…>.

Récap et vérification

  • Lien : [texte](url) ; par référence : [texte][étiquette] + [étiquette]: url ailleurs.
  • Image : ![texte alternatif](chemin) — comme un lien, avec un ! devant ; décris l'image.
  • Citation : > en début de ligne (imbricable avec > >).
  • Règle horizontale : --- seul sur une ligne, entouré de lignes vides.

Exercices

Exercice 1Échauffement

Écris un lien dont le texte est « mon portfolio » pointant vers https://exemple.com.

Voir une solution
Exercice 2Application

Insère une image locale captures/accueil.png avec un texte alternatif décrivant « la page d'accueil de l'application ».

Voir une solution

Le ! indique une image ; le texte entre crochets est le texte alternatif (utile si l'image ne charge pas et pour l'accessibilité).

Exercice 3Défi

Rédige un court extrait de README : un titre de niveau 2 « Ressources », une citation rappelant de lire la doc, et deux liens (vers la doc et le dépôt) écrits par référence.

Voir une solution

Le titre structure la section ; la citation (>) met en valeur le rappel ; les deux liens par référence gardent la phrase lisible, leurs URL étant définies en bas.
