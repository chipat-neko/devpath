Front matter et sites de documentation

~34 min Intermédiaire Leçon 08 requise

À la fin de cette leçon, tu sauras

  • ajouter un front matter (métadonnées YAML) à un fichier ;
  • expliquer ce qu'est un générateur de site statique ;
  • situer Jekyll, Hugo, MkDocs, Docusaurus ;
  • reconnaître les admonitions et fonctions de doc.
Sommaire de la leçon

Un fichier .md ne reste pas forcément isolé : c'est souvent une page parmi d'autres dans un site entier — un blog, une documentation, un cours comme celui-ci. Deux ingrédients rendent cela possible : le front matter, qui attache des informations à chaque fichier, et le générateur de site statique, qui transforme un dossier de .md en site web complet. C'est la façon dont la plupart des documentations de projet sont fabriquées.

Le front matter

Le front matter est un petit bloc de métadonnées placé tout en haut du fichier, encadré par deux lignes de trois tirets ---. On y écrit, au format YAML (des paires clé: valeur), des informations sur le document : titre, date, auteur, étiquettes, gabarit…

Ces informations ne s'affichent pas dans le texte : le générateur les lit pour, par exemple, remplir la balise <title>, dater l'article, l'ajouter à la liste des étiquettes, ou l'exclure du site tant que draft: true. Le corps Markdown, lui, suit après le second ---.

Les générateurs de sites statiques

Un générateur de site statique (SSG, static site generator) prend un dossier de fichiers .md (+ des gabarits) et produit un site de pages HTML prêtes à héberger — sans base de données, sans serveur applicatif. C'est rapide, sûr et bon marché : le résultat n'est que des fichiers.

Les plus répandus :

  • Jekyll : intégré à GitHub Pages (hébergement gratuit d'un site depuis un dépôt) — le plus simple pour publier.
  • Hugo : très rapide, populaire pour les blogs et gros sites.
  • MkDocs (thème Material) : pensé pour la documentation technique, recherche intégrée.
  • Docusaurus : basé sur React (MDX), utilisé par de nombreux projets open source.

Cas réel

Une immense partie de la documentation que tu consultes est faite ainsi. La doc de React, Jest ou Docusaurus lui-même (Meta) tourne sous Docusaurus ; d'innombrables projets Python utilisent MkDocs Material ; des millions de sites personnels sont publiés gratuitement via GitHub Pages + Jekyll. Dans tous ces cas, les auteurs écrivent en Markdown : le générateur s'occupe du reste.

Admonitions et fonctions de doc

Pour la documentation, les générateurs ajoutent des éléments bien commodes. Les admonitions (encadrés note / avertissement / astuce) en sont l'exemple phare. Dans MkDocs Material, on les écrit avec !!! :

Le générateur transforme ce bloc en encadré coloré (comme les alertes GitHub de la leçon précédente, mais côté site). D'autres fonctions courantes : la table des matières automatique (à partir des titres), des permaliens stables sur chaque titre, une navigation latérale générée depuis l'arborescence, et souvent une recherche intégrée.

Astuce

Commence petit : pour publier une doc rapidement, un dépôt GitHub + Pages suffit (Jekyll est déjà là). Tu écris tes .md, tu actives Pages dans les réglages, et le site se construit à chaque push. Tu passeras à MkDocs ou Docusaurus le jour où tu voudras une recherche, un thème riche ou une navigation élaborée.

Choisir, et rester portable

Un point de vigilance : le front matter et les admonitions sont propres à chaque outil. Un fichier écrit pour MkDocs (!!! note) ne rendra pas ses encadrés sur GitHub ; les clés de front matter attendues diffèrent d'un générateur à l'autre. Le corps Markdown reste portable ; l'emballage (métadonnées, admonitions) est lié au générateur choisi.

Le bon réflexe : choisir l'outil selon le besoin — blog personnel (Jekyll/Hugo), doc technique (MkDocs/Docusaurus) — puis se conformer à sa convention. Et garder à l'esprit que le même fichier, lu ailleurs, montrera son front matter en clair : c'est normal.

Attention

Le front matter est du YAML : il est sensible à l'indentation et à la syntaxe. Un deux-points de trop, une valeur avec caractères spéciaux non entre guillemets, et le générateur échoue ou ignore la page. En cas de doute, mets les chaînes à risque entre guillemets (title: "Prix : 10 €") et vérifie l'alignement des listes.

Pour aller plus loin

Le front matter n'est pas réservé aux sites : Obsidian l'utilise pour les propriétés d'une note, et de nombreux outils de notes ou de gestion de connaissances s'en servent pour trier et relier des fichiers. La logique est toujours la même : du texte lisible dans le corps, des métadonnées structurées en tête. À l'échelle d'un site, on parle d'architecture de contenu : des centaines de .md qu'un générateur assemble en un tout cohérent.

Glossaire

Front matter
Bloc de métadonnées en tête de fichier, encadré par --- ; décrit le document (titre, date, tags…) sans s'afficher dans le corps.
YAML
Format de configuration en paires clé: valeur, sensible à l'indentation ; langage habituel du front matter.
Générateur de site statique (SSG)
Outil transformant un dossier de .md et de gabarits en un site de pages HTML, sans base de données ni serveur applicatif.
Jekyll
Générateur intégré à GitHub Pages ; la voie la plus directe pour publier gratuitement un site depuis un dépôt.
MkDocs / Docusaurus
Générateurs orientés documentation technique : navigation, recherche, admonitions ; Docusaurus repose sur React et MDX.
Admonition
Encadré coloré (note, avertissement, astuce) fourni par un générateur, souvent écrit !!! note avec un contenu indenté.
GitHub Pages
Service d'hébergement gratuit de sites statiques directement depuis un dépôt GitHub, propulsé par Jekyll.

Récap et vérification

  • Le front matter (YAML entre ---) attache des métadonnées à un fichier ; le générateur les lit sans les afficher.
  • Un générateur de site statique transforme un dossier de .md en site HTML : Jekyll, Hugo, MkDocs, Docusaurus.
  • Les admonitions et fonctions de doc (TOC, permaliens, recherche) enrichissent le rendu, mais dépendent de l'outil.
  • Le corps Markdown reste portable ; l'emballage (métadonnées, admonitions) suit la convention du générateur choisi.

Vérifie ta compréhension

  1. Où place-t-on le front matter, et à quoi sert-il ?
  2. Que fait un générateur de site statique ?
  3. Pourquoi une admonition !!! note peut-elle ne pas s'afficher sur GitHub ?

Exercices

Exercice 1Échauffement

Dans le front matter d'un article, écris la ligne YAML qui déclare les étiquettes markdown et astuces (clé tags).

Voir une solution

Une métadonnée YAML s'écrit clé: valeur ; ici la valeur est une liste, notée entre crochets. Placée entre les deux --- du front matter, cette ligne permet au générateur de ranger la page par étiquette. Le bloc complet ajouterait par exemple title: et date:.

Exercice 2Application

Tu veux publier gratuitement une petite doc depuis un dépôt, sans configurer grand-chose. Quel générateur est déjà disponible, et comment ?

Voir une solution

Jekyll, via GitHub Pages. Tu déposes tes fichiers .md dans le dépôt, tu actives Pages dans les réglages, et GitHub reconstruit le site à chaque push. Aucune installation locale n'est requise pour démarrer : c'est la voie la plus rapide pour mettre une documentation en ligne.

Exercice 3Synthèse

Explique, à un collègue, pourquoi le corps d'un fichier reste portable alors que son front matter et ses admonitions ne le sont pas.

Voir une solution

Le corps utilise la syntaxe Markdown de base (titres, listes, liens, code), commune à tous les moteurs : il s'affiche correctement partout. Le front matter et les admonitions, eux, sont des conventions propres à chaque générateur : les clés YAML attendues et la syntaxe !!! note ne sont interprétées que par l'outil pour lequel elles sont prévues. Ailleurs, elles s'affichent en clair. On garde donc l'essentiel de l'information dans le corps portable, et on réserve l'emballage à l'outil choisi.
