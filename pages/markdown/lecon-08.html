Maths et diagrammes en texte

~35 min Avancé Leçon 07 requise

À la fin de cette leçon, tu sauras

  • écrire des formules mathématiques en LaTeX (inline et bloc) ;
  • dessiner un diagramme avec Mermaid depuis du texte ;
  • mettre en valeur avec les alertes GitHub ([!NOTE], [!WARNING]) ;
  • comprendre que ces rendus dépendent de la plateforme.
Sommaire de la leçon

Markdown ne sert pas qu'à mettre en forme du texte : sur les plateformes modernes, on y écrit aussi des formules mathématiques et on y dessine des diagrammes — tout cela en texte brut, versionnable comme le reste. Le secret ? Un bloc de code au bon langage (math, mermaid) que la plateforme interprète au lieu de l'afficher. C'est un tournant : la documentation technique devient illustrée sans image binaire à maintenir.

Les mathématiques (LaTeX)

La notation mathématique de référence s'appelle LaTeX. En Markdown, on l'encadre par des dollars : un seul $…$ pour une formule dans le texte, deux $$…$$ (ou un bloc math) pour une formule centrée sur sa propre ligne.

Le moteur de rendu (souvent KaTeX ou MathJax) transforme c^2 en exposant, \frac{a}{b} en fraction empilée, \sum en grand sigma, etc. Tu n'as pas besoin de connaître tout LaTeX : quelques commandes (^, _, \frac, \sqrt, \sum) couvrent déjà l'essentiel.

Cas réel

GitHub rend les maths LaTeX nativement depuis 2022 dans les fichiers .md, les issues et les discussions ; GitLab, Jupyter, Obsidian et Notion font de même. C'est devenu le standard de fait pour la documentation scientifique et les README de bibliothèques de calcul : la formule vit dans le texte, se versionne dans Git, et reste lisible même sans rendu.

Les diagrammes avec Mermaid

Mermaid décrit un schéma en texte, et le moteur le dessine. On ouvre un bloc de code au langage mermaid, puis on déclare des nœuds et des flèches :

graph TD signifie « graphe de haut en bas » (top-down) ; les crochets […] dessinent une boîte, les accolades {…} un losange de décision, et --> une flèche. Mermaid gère bien d'autres types : sequenceDiagram (échanges entre acteurs), gantt (planning), pie (camembert), erDiagram (base de données).

Astuce

Un diagramme en texte a un avantage décisif sur une image : il se versionne et se relit dans un diff Git. Quand l'architecture change, tu modifies deux lignes de Mermaid plutôt que de rouvrir un logiciel de dessin, exporter un PNG et remplacer le fichier. Le schéma reste toujours synchrone avec le texte qui l'entoure.

Les alertes GitHub

GitHub a introduit des alertes : des citations spéciales qui se rendent en encadrés colorés avec icône. On part d'une citation >, et on ajoute un marqueur en tête :

Cinq marqueurs existent : [!NOTE], [!TIP], [!IMPORTANT], [!WARNING] et [!CAUTION]. Chacun a sa couleur et son icône. C'est l'équivalent, en Markdown pur, des encadrés colorés que tu vois dans cette leçon.

Un rendu qui dépend de la plateforme

Point commun de ces trois nouveautés : elles sont calculées à l'affichage par la plateforme (des bibliothèques JavaScript comme KaTeX ou Mermaid tournent dans la page). Rien n'est « dans » le fichier : le .md ne contient que du texte. Conséquence directe : le même fichier s'affiche différemment selon l'endroit.

  • Sur GitHub : maths, Mermaid et alertes sont rendus.
  • Dans un éditeur brut ou un moteur minimal : tu vois le $…$ et le bloc mermaid tels quels.
  • Ailleurs (Obsidian, GitLab, MkDocs…) : le support varie, parfois via un greffon.

On retrouve exactement les trois cercles de portabilité de la leçon précédente : ces éléments sont répandus mais pas universels. Utile, spectaculaire, mais à réserver aux contextes qui les gèrent.

Attention

Ne fais jamais reposer une information essentielle uniquement sur un rendu Mermaid ou LaTeX. Si le document est lu là où ce rendu n'existe pas, le lecteur ne verra que du code. Accompagne un diagramme important d'une phrase qui le résume, et une formule d'une explication en toutes lettres : le fond doit survivre à l'absence de rendu.

Pour aller plus loin

La même idée — « un bloc de code que la plateforme interprète » — s'étend à d'autres langages de schéma : PlantUML (diagrammes UML), Graphviz/DOT (graphes), Vega-Lite (graphiques de données). Mermaid domine parce qu'il est intégré par défaut sur GitHub et GitLab, sans installation. Pour des maths lourdes ou des figures publiables, on passe souvent par Pandoc et un vrai moteur LaTeX (prochaine leçon).

Glossaire

LaTeX
Notation de référence pour les formules mathématiques ; en Markdown, on l'encadre par $…$ (en ligne) ou $$…$$ (bloc).
KaTeX / MathJax
Bibliothèques JavaScript qui lisent le LaTeX dans la page et dessinent la formule au chargement. KaTeX est rapide, MathJax très complet.
Mermaid
Langage textuel de diagrammes (organigrammes, séquences, gantt…) ; un bloc de code mermaid est dessiné par la plateforme.
graph TD
En-tête Mermaid déclarant un graphe top-down (de haut en bas) ; LR le disposerait de gauche à droite.
Alerte GitHub
Citation marquée > [!NOTE], [!WARNING]… rendue en encadré coloré avec icône ; cinq types disponibles.
Rendu côté client
Transformation faite à l'affichage par du JavaScript, pas stockée dans le fichier ; d'où un rendu qui dépend de la plateforme.

Récap et vérification

  • Les maths s'écrivent en LaTeX entre $…$ (en ligne) ou $$…$$ (bloc), rendues par KaTeX ou MathJax.
  • Mermaid dessine un diagramme depuis un bloc de code : graph TD, boîtes […], décisions {…}, flèches -->.
  • Les alertes GitHub (> [!NOTE]…) rendent des encadrés colorés à partir d'une citation.
  • Ces rendus sont calculés par la plateforme : répandus mais pas universels — prévois un repli en texte.

Vérifie ta compréhension

  1. Quelle est la différence entre $…$ et $$…$$ ?
  2. Comment déclare-t-on un diagramme Mermaid, et pourquoi préférer un diagramme en texte à une image ?
  3. Pourquoi un même fichier peut-il afficher une formule ici et du code brut ailleurs ?

Exercices

Exercice 1Échauffement

Écris la racine carrée de deux, en ligne dans une phrase, en LaTeX.

Voir une solution

La commande \sqrt{…} dessine le radical ; encadrée d'un seul $, la formule reste dans le fil du texte. Sur une plateforme sans rendu maths, le lecteur verrait $\sqrt{2}$ tel quel — d'où l'utilité de préciser « racine carrée de deux » à côté.

Exercice 2Application

Dessine avec Mermaid un mini-processus à deux étapes : Rédiger → Publier.

Voir une solution

graph LR dispose le schéma de gauche à droite (left-right) ; chaque […] est une boîte, la flèche --> relie les deux étapes. Mermaid calcule tout seul le placement.

Exercice 3Synthèse

Ajoute dans un README un avertissement bien visible avec une alerte GitHub, et explique pourquoi tu ne te reposes pas uniquement sur cet encadré.

Voir une solution

L'alerte [!WARNING] ressort en encadré coloré sur GitHub. Mais ce rendu dépend de la plateforme : ailleurs, le lecteur voit une simple citation. Le message (« sauvegarde avant de mettre à jour ») doit donc rester clair même sans la couleur — le fond survit à l'absence de rendu.
