Code et blocs de code

~32 min Débutant Leçon 03 requise

À la fin de cette leçon, tu sauras

  • afficher du code en ligne ;
  • écrire des blocs de code délimités ;
  • activer la coloration syntaxique par langage ;
  • gérer les caractères spéciaux dans le code.
Sommaire de la leçon

Markdown a été pensé par et pour des gens qui écrivent sur du code : c'est l'une des raisons de son succès. Afficher du code proprement — sans qu'il soit déformé par la mise en forme — est l'une de ses fonctions clés. Cette leçon couvre les deux façons de montrer du code (en ligne et en bloc) et la coloration syntaxique.

Le code en ligne

Pour insérer un fragment de code au milieu d'une phrase (un nom de fonction, une commande, une variable), on l'entoure d'accents graves (backticks, le caractère `).

Le texte entre backticks s'affiche en police à chasse fixe (monospace), distincte du texte normal, comme ceci. C'est l'équivalent de la balise <code> du HTML. Le code en ligne n'est pas interprété par Markdown : `**gras**` affiche littéralement les astérisques au lieu de mettre en gras. Pratique pour montrer de la syntaxe sans qu'elle s'active.

Les blocs de code délimités

Pour plusieurs lignes de code, on utilise un bloc délimité (fenced code block) : trois backticks sur une ligne, le code, puis trois backticks pour fermer.

Tout ce qui est entre les deux lignes de backticks est affiché tel quel : indentation préservée, rien d'interprété, sur fond distinct. C'est la façon standard de partager un extrait de code, une configuration, ou une sortie de terminal. (Une variante plus ancienne : indenter chaque ligne de quatre espaces ; mais les blocs à backticks sont plus clairs et plus répandus.)

La coloration syntaxique

Le vrai plus : indiquer le langage juste après les backticks d'ouverture — ce mot s'appelle l'info-string. Les outils colorent alors le code selon la syntaxe de ce langage (syntax highlighting), ce qui le rend bien plus lisible.

On précise python, bash, js, json, html… selon le contenu. La plateforme (GitHub, ton éditeur…) applique alors les couleurs adaptées. C'est exactement ce que tu vois dans les blocs de code de ce cours ! Toujours préciser le langage : c'est un petit effort pour un grand gain de lisibilité.

Les caractères spéciaux et l'échappement

Parfois, on veut écrire littéralement un caractère que Markdown interprète (un astérisque, un croisillon, un backtick). On le fait précéder d'une barre oblique inverse (\) pour l'échapper.

L'échappement (\*, \#…) dit à Markdown « traite ce caractère comme du texte, pas comme une instruction » — une idée que tu connais déjà des regex et des chaînes (cours Regex). Pour afficher un backtick à l'intérieur de code en ligne, l'astuce élégante est d'entourer de doubles backticks. Ces cas sont rares, mais bons à connaître pour ne pas être bloqué.

Piège : le bloc de code par accident

Un vestige de la vieille syntaxe te guette : quatre espaces (ou une tabulation) en début de ligne transforment cette ligne en bloc de code, même sans aucun backtick. On tombe dessus en collant du texte indenté, ou après une liste dont on a gardé le retrait : un paragraphe se retrouve soudain en monospace sur fond gris. Le réflexe : si un texte passe en « code » sans raison, vérifie les espaces en tête de ligne.

Astuce : plus d'accents graves autour, pas d'échappement

Pour montrer un ou plusieurs accents graves dans du code en ligne, inutile de sortir la barre oblique inverse : allonge simplement le délimiteur. Deux accents graves autour affichent un accent grave isolé (`` ` ``) ; trois autour en affichent deux. La règle : le délimiteur doit compter plus d'accents graves que la plus longue suite présente dans le contenu.

Cas réel

Sur Stack Overflow ou dans une issue GitHub, la première chose qu'on demande à quelqu'un qui colle du code « cassé », c'est de l'encadrer d'un bloc délimité. Sans les trois backticks, l'indentation Python saute, les * d'un pointeur C passent en italique, et le message devient illisible — voire trompeur. Un développeur qui maîtrise les blocs de code obtient des réponses plus vite : son problème est reproductible parce que son code est intact. C'est une compétence de communication autant que de syntaxe.

Pour aller plus loin

Deux finesses des blocs délimités. 1) On peut ouvrir avec quatre backticks (ou plus) quand le code contient lui-même une ligne de trois backticks — la clôture doit alors compter autant de backticks. 2) Certains outils acceptent le tilde ~~~ à la place des backticks. Ces variantes servent surtout à écrire… de la documentation sur Markdown, comme cette leçon !

Code en ligne vs bloc

Règle simple : un petit fragment dans une phrase (un nom, une commande courte) → code en ligne (backticks simples). Plusieurs lignes ou un extrait qu'on veut détacher → bloc délimité (triple backticks + langage). Mettre un long bloc en code « en ligne » casserait la mise en page ; mettre un seul mot dans un bloc serait disproportionné. Le bon choix rend la lecture fluide.

Glossaire

Backtick (accent grave)
Caractère ` qui délimite le code : un seul pour du code en ligne, trois pour un bloc. Sur clavier français : AltGr + 7.
Code en ligne
Fragment de code inséré dans une phrase, entouré de backticks simples ; rendu en police à chasse fixe, non interprété. Équivaut à <code>.
Bloc de code délimité
Fenced code block : plusieurs lignes encadrées par ```. Le contenu est affiché tel quel, indentation comprise.
Coloration syntaxique
Syntax highlighting : mise en couleur du code selon le langage indiqué après les backticks d'ouverture (```js…).
Chasse fixe (monospace)
Police où chaque caractère occupe la même largeur ; standard pour le code, car elle aligne les colonnes.
Échappement
Barre oblique inverse \ placée devant un caractère spécial pour l'afficher littéralement au lieu de l'interpréter.
Info-string (langage)
Le mot collé aux backticks d'ouverture d'un bloc (```python, ```bash) : il nomme le langage et déclenche la coloration syntaxique.
Doubles accents graves
Délimiteur allongé (``…``) utilisé pour afficher un accent grave dans du code en ligne, sans échappement ; le délimiteur doit être plus long que le contenu.
Bloc de code par accident
Bloc créé sans le vouloir par quatre espaces (ou une tabulation) en début de ligne ; vestige de la syntaxe indentée, source de texte passé en monospace par surprise.

Récap et vérification

  • Code en ligne : entre backticks simples `code` ; affiché en monospace, non interprété.
  • Bloc de code : trois backticks pour ouvrir et fermer ; contenu affiché tel quel.
  • Coloration : préciser le langage après les backticks d'ouverture (```python).
  • Échappement : \ devant un caractère spécial pour l'afficher littéralement ; doubles backticks pour un backtick dans du code en ligne.

Exercice 3Défi

Tu veux montrer, dans ton README, l'exemple de syntaxe Markdown **gras** sans qu'il s'affiche réellement en gras. Comment faire ?

Voir une solution

Deux façons. 1) Le mettre en code en ligne avec des backticks : `**gras**` — le contenu d'un code en ligne n'est pas interprété, donc les astérisques s'affichent littéralement (et en monospace, ce qui convient bien pour montrer de la syntaxe). 2) Échapper les astérisques : \*\*gras\*\* affiche **gras** en texte normal. La première (backticks) est généralement préférée pour montrer de la syntaxe Markdown, car elle distingue visuellement l'exemple et évite d'échapper chaque caractère.
