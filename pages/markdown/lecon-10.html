Convertir et outiller Markdown

~35 min Intermédiaire Leçon 09 requise

À la fin de cette leçon, tu sauras

  • convertir un .md en PDF, HTML ou Word avec Pandoc ;
  • générer une table des matières automatiquement ;
  • vérifier et formater avec markdownlint et Prettier ;
  • choisir le bon moteur (CommonMark ou GFM).
Sommaire de la leçon

Un fichier Markdown n'est que du texte brut. Cet apparent dénuement est une force : on peut le transformer en presque n'importe quel format de livraison (PDF, Word, diapositives) et l'outiller comme du code — le vérifier, le mettre en forme automatiquement. Cette leçon présente les deux familles d'outils qui gravitent autour de Markdown : les convertisseurs et les outils de qualité (linters, formateurs).

Pandoc : convertir vers presque tout

Pandoc est le convertisseur universel de documents. Une seule commande transforme ton .md en PDF, page HTML autonome, document Word (.docx), diapositives, LaTeX ou EPUB. Tu écris une fois en Markdown ; Pandoc produit le format que ton destinataire attend.

L'option de sortie -o décide du format d'après l'extension du fichier voulu : .pdf, .docx, .html… Le drapeau -s (standalone) produit un document complet (avec en-tête HTML), et non un simple fragment.

La table des matières automatique

Plutôt que d'écrire et maintenir une table des matières à la main, laisse l'outil la construire à partir des titres. Avec Pandoc, l'option --toc insère une table cliquable ; --number-sections numérote les titres.

La table reste toujours à jour : ajoute une section, régénère, elle apparaît. C'est le même principe que la navigation générée par les sites de documentation (leçon 09) : les titres sont la structure, tout le reste en découle.

Cas réel

Dans le monde académique, beaucoup rédigent thèses et articles en Markdown puis génèrent avec Pandoc à la fois le PDF soigné (composé via LaTeX) et le .docx réclamé par la revue — depuis une source unique, versionnée dans Git. Fini le copier-coller entre Word et l'outil de mise en page : on corrige le .md, on relance la commande, les deux formats se régénèrent identiques.

Pandoc convertit aussi vers Markdown

La conversion n'est pas à sens unique. pandoc vieux-rapport.docx -o rapport.md récupère un document Word en Markdown éditable ; on peut de même partir d'un .html, d'un .tex ou d'un .epub. C'est souvent le moyen le plus simple de faire entrer un contenu hérité dans une chaîne outillée : une fois en .md, il se versionne, se relit dans un diff et se reconvertit comme le reste.

Vérifier et formater : linters et formateurs

Comme pour le code, on peut imposer un style cohérent à ses fichiers Markdown, surtout quand plusieurs personnes y écrivent. Deux outils complémentaires :

  • markdownlint — un linter : il signale les entorses aux conventions (niveau de titre sauté, absence de ligne vide autour d'un bloc, espaces en fin de ligne, listes mal indentées). Il ne change rien ; il pointe les problèmes.
  • Prettier — un formateur : il réécrit le fichier dans un style canonique (puces uniformes, espacements réguliers, largeur de ligne). Tu ne discutes plus du style : l'outil tranche.

Astuce

Linter et formateur sont complémentaires, pas concurrents. Prettier normalise la mise en forme (espaces, puces, retours à la ligne) ; markdownlint vérifie des règles que Prettier ne couvre pas (un seul titre de niveau 1, pas de niveau sauté, texte alternatif présent). Beaucoup de projets utilisent les deux : on formate d'abord, on vérifie ensuite.

CommonMark ou GFM ? La question de la portabilité

Rappelle-toi (leçon 06) que Markdown est une famille de moteurs. Un même fichier peut rendre différemment selon celui qui le lit. Les deux à connaître : CommonMark (la base stricte et non ambiguë) et GFM (GitHub Flavored Markdown = CommonMark + tableaux, listes de tâches, barré, autoliens). Un tableau rendu joliment sur GitHub restera du texte brut sous un moteur CommonMark strict, qui ne connaît pas les tableaux.

Le bon réflexe : savoir où ton document sera lu, et convertir avec le bon moteur. Pandoc te laisse préciser le dialecte d'entrée : -f gfm lit du GitHub Flavored, -f commonmark la base stricte.

Attention

La sortie PDF de Pandoc passe par un moteur LaTeX (TeX Live, MiKTeX) : s'il n'est pas installé, la commande échoue avec « pdflatex not found ». Les sorties HTML et DOCX, elles, ne demandent rien de plus. Commence par .html ou .docx pour tester ta chaîne, puis installe LaTeX quand tu veux vraiment du PDF.

Pour aller plus loin

Pandoc va bien au-delà : il génère des diapositives (reveal.js, Beamer), des EPUB, et accepte des gabarits et des filtres pour personnaliser la sortie. Côté qualité, markdownlint et Prettier s'intègrent dans un hook Git ou dans la CI (cours CI/CD) : la documentation est alors vérifiée automatiquement à chaque contribution, exactement comme le code.

Glossaire

Pandoc
Convertisseur universel de documents : transforme un .md en PDF, HTML, Word, diapositives, EPUB… depuis une source unique.
Conversion
Passage d'un format à un autre ; en Markdown, on écrit une fois et l'on génère les formats de livraison à la demande.
Table des matières (TOC)
Liste des titres générée automatiquement (--toc) ; toujours à jour puisqu'elle découle des titres.
Linter
Outil qui signale les entorses aux conventions sans rien modifier ; pour Markdown : markdownlint.
Formateur
Outil qui réécrit le fichier dans un style canonique ; pour Markdown : Prettier.
CommonMark
Spécification stricte et non ambiguë de Markdown : la base lisible sur tout moteur compatible.
GFM
GitHub Flavored Markdown : CommonMark + tableaux, tâches, barré et autoliens ; le dialecte le plus répandu.
Standalone (-s)
Drapeau Pandoc produisant un document complet et autonome (avec en-tête, structure) plutôt qu'un simple fragment à insérer dans une autre page.

Récap et vérification

  • Pandoc convertit un .md en PDF, HTML, Word, diapositives… depuis une source unique (-o choisit le format).
  • Une table des matières se génère à partir des titres (--toc) : pas de maintenance à la main.
  • markdownlint signale, Prettier reformate : deux outils complémentaires pour une doc homogène.
  • Choisir le moteur (CommonMark ou GFM) selon l'endroit où le document sera lu : la base rend partout, les extensions non.

Vérifie ta compréhension

  1. Avec quel outil convertit-on un .md en PDF ou en Word ?
  2. Quelle différence entre markdownlint et Prettier ?
  3. Pourquoi un tableau peut-il rester en texte brut sur certains moteurs ?

Exercices

Exercice 1Échauffement

Écris la commande Pandoc qui convertit memo.md en memo.pdf (pour l'impression).

Voir une solution

C'est l'extension du fichier de sortie donné à -o qui détermine le format : -o memo.pdf produit un PDF, -o memo.docx un document Word. Une seule source Markdown, autant de livrables qu'on veut. (Le PDF suppose un moteur LaTeX installé ; le .docx ne demande rien de plus.)

Exercice 2Application

Ton équipe se dispute sur le style des fichiers Markdown (puces * ou -, espaces, largeur). Quel type d'outil règle le débat, et lequel choisir ?

Voir une solution

Un formateur : il réécrit tous les fichiers dans un même style canonique, ce qui clôt le débat. Pour Markdown, Prettier fait très bien l'affaire (prettier --write "**/*.md"). On peut y ajouter markdownlint pour vérifier des règles supplémentaires (un seul titre de niveau 1, pas de niveau sauté).

Exercice 3Synthèse

Un collègue t'envoie un .md plein de tableaux qui s'affichent en texte brut dans ton éditeur. Tu le convertis en HTML avec Pandoc en lui faisant lire du GitHub Flavored Markdown. Quelle option ajoutes-tu à la commande ?

Voir une solution

Les tableaux sont une extension GFM, pas de la base CommonMark : l'aperçu de l'éditeur utilise sans doute un moteur strict qui ne les interprète pas, d'où le texte brut. L'option -f gfm (from) dit à Pandoc de lire l'entrée comme du GitHub Flavored : les tableaux sont alors reconnus et rendus. Connaître le moteur qui lira le document conditionne les extensions qu'on peut utiliser.
