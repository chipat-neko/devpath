Module 2 · Structurer un document — Leçon 05

Tableaux, listes de tâches et GFM

~35 min Intermédiaire Leçon 04 requise

À la fin de cette leçon, tu sauras

  • créer des tableaux ;
  • faire des listes de tâches (cases à cocher) ;
  • utiliser le texte barré et autres extensions GFM ;
  • éviter les coquilles fréquentes.
Sommaire de la leçon

Le Markdown « de base » (CommonMark) ne couvre pas tout. Le dialecte le plus utilisé, le GitHub Flavored Markdown (GFM), ajoute des fonctionnalités très pratiques : tableaux, listes de tâches, texte barré. Comme GFM est le standard de fait sur GitHub, GitLab et bien d'autres outils, tu t'en serviras tout le temps. Cette leçon couvre ses ajouts les plus utiles.

Les tableaux

Un tableau se dessine avec des barres verticales (|) pour les colonnes, et une ligne de tirets pour séparer l'en-tête du corps.

La première ligne est l'en-tête ; la deuxième (des tirets) la sépare du contenu ; les suivantes sont les données. Les barres verticales délimitent les cellules. Bonne nouvelle : l'alignement des barres dans la source n'a pas besoin d'être parfait — l'outil aligne le rendu. Mais aligner proprement la source la rend plus lisible (la plupart des éditeurs le font pour toi).

Aligner les colonnes

On peut contrôler l'alignement d'une colonne en plaçant des deux-points (:) dans la ligne de séparation.

Les deux-points indiquent où « colle » le contenu : :--- à gauche, :---: centré, ---: à droite. C'est utile pour les colonnes de nombres (alignées à droite) ou les étiquettes (centrées). Les tableaux Markdown restent simples (pas de fusion de cellules) ; pour des tableaux complexes, on bascule en HTML.

Ne les aligne pas à la main

Aligner les barres d'un tableau à la main est fastidieux : la plupart des éditeurs le font pour toi. Dans VS Code, l'extension Markdown All in One reformate le tableau proprement à la sauvegarde ; de nombreux sites proposent aussi un « générateur de tableau Markdown » où l'on remplit une grille. Écris le contenu sans te soucier des espaces : seul compte que chaque ligne ait le bon nombre de barres | et que la ligne de tirets soit présente.

Les listes de tâches

Très appréciée : la liste de tâches (task list), une liste à puces où chaque élément est une case à cocher. On écrit - [ ] pour une tâche à faire, - [x] pour une tâche faite.

Le rendu affiche de vraies cases à cocher (cochées pour [x], vides pour [ ]). Sur des plateformes comme GitHub, on peut même cliquer les cases directement dans l'interface pour mettre à jour l'avancement. C'est idéal pour des listes de choses à faire dans une issue, une pull request, ou un README de suivi.

Cas réel

Dans une pull request GitHub, une liste de tâches sert de checklist de relecture vivante : « tests ajoutés », « doc mise à jour », « changelog complété ». Chaque relecteur coche les cases directement dans l'interface (sans toucher au fichier), et GitHub affiche l'avancement « 3/5 » en tête de la PR. Beaucoup d'équipes bloquent la fusion tant que toutes les cases ne sont pas cochées. Ce petit - [ ] devient ainsi un vrai outil de coordination d'équipe, pas seulement une jolie liste.

Texte barré et autres extensions

GFM ajoute encore quelques touches :

Le texte barré (~~ ~~) sert à marquer ce qui est obsolète ou annulé. Les autoliens transforment une URL écrite directement en lien cliquable. Et beaucoup d'outils interprètent des raccourcis d'émojis (:rocket: → 🚀). Ces extensions ne font pas partie du Markdown « pur » mais sont quasi universelles dans les outils de développement.

Les coquilles fréquentes

Quelques erreurs reviennent souvent et cassent le rendu :

Les pièges classiques : oublier l'espace après # ou un marqueur de liste ; oublier les lignes vides autour des blocs (listes, tableaux, titres) ; oublier la ligne de séparation d'un tableau ; mettre des espaces entre l'emphase et le texte. La parade universelle : prévisualiser (leçon 2). Un coup d'œil au rendu repère instantanément ce qui ne s'est pas formé comme prévu.

Tout n'est pas portable

Attention : les extensions GFM (tableaux, cases à cocher, barré, émojis) ne sont pas garanties partout. Un outil qui ne suit que CommonMark affichera la source brute d'un tableau au lieu de le rendre. Avant d'utiliser une extension, vérifie qu'elle est supportée par l'endroit où ton document sera lu. Pour une portabilité maximale, tiens-toi aux éléments de base (titres, listes, liens, code) ; pour GitHub et la plupart des outils de dev, GFM est sûr.

Glossaire

GFM (GitHub Flavored Markdown)
Dialecte de Markdown, standard de fait chez les développeurs, qui ajoute à CommonMark les tableaux, listes de tâches, texte barré et autoliens.
Tableau
Structure en colonnes délimitées par des barres | ; nécessite une ligne de séparation en tirets entre l'en-tête et le corps.
Ligne de séparation
Deuxième ligne d'un tableau, faite de tirets (---) ; obligatoire pour que le tableau soit reconnu. Des deux-points (:) y règlent l'alignement.
Liste de tâches (task list)
Liste à puces où chaque élément est une case à cocher : - [ ] (à faire) ou - [x] (faite).
Texte barré
Texte entouré de doubles tildes ~~ ~~, rendu rayé ; sert à marquer ce qui est obsolète ou annulé.
Autolien
URL écrite directement dans le texte, transformée automatiquement en lien cliquable par les outils compatibles GFM.
Portabilité
Capacité d'un document à s'afficher correctement partout ; les extensions GFM ne sont pas garanties sur un outil qui ne suit que CommonMark.

Récap et vérification

  • Tableaux : barres | + une ligne de tirets séparant l'en-tête ; deux-points (:) pour l'alignement.
  • Listes de tâches : - [ ] (à faire) et - [x] (fait) → cases à cocher.
  • Extensions GFM : barré ~~ ~~, autoliens, émojis :nom:.
  • Coquilles : espaces après # et marqueurs, lignes vides autour des blocs, ligne de tirets du tableau ; prévisualiser. Toutes les extensions ne sont pas portables.

Vérifie ta compréhension

  1. Quelle ligne est indispensable pour qu'un tableau soit reconnu ?
  2. Comment écrit-on une tâche cochée et une tâche à faire ?
  3. Pourquoi une extension GFM peut-elle ne pas s'afficher partout ?

Exercice 3Défi

Un collègue écrit un tableau qui s'affiche comme une suite de lignes avec des barres, pas comme un vrai tableau. Quelle est la cause la plus probable, et comment vérifier ?

Voir une solution

La cause la plus probable : il manque la ligne de séparation en tirets entre l'en-tête et le corps (par ex. | --- | --- |). Sans elle, l'outil ne reconnaît pas la structure comme un tableau et affiche simplement les lignes avec leurs barres verticales en texte. Autres causes possibles : l'outil ne supporte pas les tableaux (CommonMark pur, pas GFM) ; ou il manque une ligne vide avant le tableau, qui se retrouve collé au paragraphe précédent. Comment vérifier : 1) prévisualiser le rendu ; 2) s'assurer que la 2e ligne est bien une ligne de tirets, et qu'une ligne vide précède le tableau ; 3) confirmer que la plateforme cible gère bien GFM. Le plus souvent, ajouter la ligne de tirets règle le problème.
