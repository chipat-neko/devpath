Module 1 · Les bases — Leçon 01

Pourquoi Markdown

~24 min Débutant Aucun prérequis

À la fin de cette leçon, tu sauras

  • définir ce qu'est Markdown ;
  • expliquer pourquoi il est lisible tel quel ;
  • citer ses avantages (portable, durable) ;
  • savoir où il est utilisé.
Sommaire de la leçon

Tu as forcément déjà croisé du Markdown, peut-être sans le savoir : le fichier README d'un projet, un message sur un forum technique, une issue sur un dépôt de code, une note dans une application. Markdown est un langage de balisage léger qui permet de mettre en forme du texte (titres, gras, listes, liens…) avec une syntaxe si simple qu'elle reste lisible même sans être transformée. Ce cours, court et pratique, te le fait maîtriser de bout en bout.

Un balisage léger

Pour mettre du texte en forme sur le web, il y a le HTML (cours HTML) : puissant, mais verbeux. Markdown est une alternative légère : au lieu de balises, on utilise quelques signes de ponctuation discrets. Un outil transforme ensuite ce Markdown en HTML pour l'affichage.

Le Markdown est bien plus court, et surtout : même sans connaître la syntaxe, on devine le sens. # Mon titre ressemble à un titre ; **gras** attire l'œil sur le mot. C'est tout l'art de Markdown : une mise en forme discrète qui n'abîme pas la lecture du texte source.

Lisible tel quel

C'est la grande idée de Markdown, énoncée par son créateur : un document Markdown doit être aussi lisible brut que mis en forme. La syntaxe imite des conventions que les gens utilisaient déjà naturellement dans les e-mails ou les notes (un astérisque pour une liste, des soulignements pour insister).

Lis ce bloc : tu comprends tout, même sans qu'il soit « rendu » en page formatée. C'est ce qui distingue Markdown des formats où le source est illisible (un document Word ouvert dans un éditeur de texte est incompréhensible). Avec Markdown, le source est le document.

Astuce

Presque tous les éditeurs de texte et de code affichent un aperçu côte à côte : source à gauche, rendu à droite. Cherche un bouton « Preview » ou le raccourci de ton éditeur ; c'est le meilleur moyen d'apprendre la syntaxe en voyant l'effet de chaque signe en temps réel.

Portable et durable

Markdown n'est que du texte brut (cours Formats de données). Cela lui donne des qualités précieuses :

  • portable : un fichier .md s'ouvre partout, dans n'importe quel éditeur, sur n'importe quel système. Aucun logiciel propriétaire requis.
  • durable : du texte brut sera toujours lisible dans 20 ans, contrairement à des formats binaires qui dépendent d'un logiciel précis.
  • versionnable : comme c'est du texte, Git (cours Git) le suit parfaitement : on voit les différences ligne par ligne, on fusionne, on collabore. Impossible avec un document binaire.
  • léger : on l'écrit vite, au clavier, sans quitter les doigts du texte pour aller cliquer dans des menus.

Ces qualités expliquent son adoption massive par les développeurs : il s'intègre naturellement à leurs outils (éditeurs de code, Git, terminaux) et à leur façon de travailler.

Cas réel

Ouvre n'importe quel projet populaire sur GitHub — React, VS Code, le noyau Linux… La grande page de présentation que tu vois en dessous de la liste des fichiers n'est pas codée à la main : c'est un simple fichier README.md écrit en Markdown, que GitHub convertit en HTML et affiche automatiquement. Le même fichier, cloné sur ta machine, reste parfaitement lisible dans le terminal. Un seul texte source sert à la fois d'affichage web soigné et de note brute : c'est exactement la promesse de Markdown.

Pour aller plus loin

Deux références font autorité : la spécification CommonMark (avec un bac à sable interactif « Try CommonMark » pour tester la syntaxe en direct) et le guide du GitHub Flavored Markdown. Garde-les sous la main : dès que tu doutes du rendu d'un signe, un aller-retour dans un aperçu tranche la question.

Plusieurs « dialectes »

Markdown a été créé en 2004 par John Gruber. Sa simplicité a engendré des variantes (dialectes) qui ajoutent des fonctionnalités : tableaux, listes de tâches, coloration de code… La plus répandue est le GitHub Flavored Markdown (GFM). Un effort de standardisation, CommonMark, fixe une base commune. On verra ces extensions au fil du cours ; retiens pour l'instant que la base est partout la même.

Glossaire

Markdown
Langage de balisage léger créé en 2004 par John Gruber : on met en forme du texte avec quelques signes discrets, converti ensuite en HTML.
Balisage léger
Famille de syntaxes de mise en forme (Markdown, reStructuredText, AsciiDoc…) où les marques restent minimales et lisibles, par opposition aux balises verbeuses du HTML.
Texte brut
Contenu fait de simples caractères, sans mise en forme binaire cachée : ouvrable partout, versionnable, durable. Le fichier .md en est.
Rendu
Résultat visuel obtenu après conversion du Markdown en HTML par un outil : titres en gros, mots en gras, listes à puces…
CommonMark
Effort de standardisation qui fixe une base commune et sans ambiguïté du Markdown, adoptée par de nombreux outils.
GFM
« GitHub Flavored Markdown » : le dialecte le plus répandu, qui ajoute à CommonMark les tableaux, listes de tâches, coloration de code…
README
Fichier de présentation d'un projet (souvent README.md), affiché automatiquement et formaté sur la page d'accueil d'un dépôt.

Récap et vérification

  • Markdown est un langage de balisage léger : une mise en forme discrète par quelques signes, transformée en HTML pour l'affichage.
  • Son idée maîtresse : être lisible tel quel, même non rendu — le source est le document.
  • C'est du texte brut : portable, durable, versionnable (Git), léger à écrire.
  • Omniprésent : README, docs, issues, forums, notes, sites ; le GFM est le dialecte le plus courant.

  2. Que signifie « lisible tel quel » ?
  3. Pourquoi Markdown se versionne-t-il bien avec Git ?

Exercices

Exercice 1Échauffement

Cite trois endroits où l'on utilise couramment Markdown.

Voir une solution

Par exemple : les README et la documentation de projets ; les issues et pull requests sur les plateformes de code (GitHub, GitLab) ; les messageries et forums techniques (Discord, Reddit…). On peut ajouter : la prise de notes (Obsidian, Notion) et les générateurs de sites statiques.

Exercice 2Application

Sans connaître encore la syntaxe précise, devine ce que produit ce Markdown : # Notes puis une ligne - point un puis - point deux.

Voir une solution

Un titre « Notes » (le # en début de ligne), suivi d'une liste à puces de deux éléments : « point un » et « point deux » (chaque - en début de ligne crée une puce). C'est justement la force de Markdown : on devine le rendu rien qu'en lisant la source.

Exercice 3Défi

Un collègue propose de rédiger la documentation d'un projet dans un document Word partagé. Quels arguments avances-tu en faveur du Markdown ?

Voir une solution

Plusieurs arguments objectifs. 1) Versionnement : en Markdown (texte brut), la doc vit dans le dépôt Git avec le code ; on suit chaque modification ligne par ligne, on fusionne les contributions, on revient en arrière — impossible avec un document Word binaire. 2) Proximité avec le code : la doc évolue en même temps que le code, dans les mêmes pull requests ; elle reste à jour. 3) Portabilité et durabilité : un .md s'ouvre partout, sans logiciel propriétaire, et restera lisible dans des années. 4) Rendu automatique : les plateformes (GitHub…) affichent le Markdown joliment formaté. Word a sa place pour des documents bureautiques riches, mais pour de la documentation technique vivante, Markdown s'intègre bien mieux au flux de travail des développeurs.
