Analyser du texte : les grammaires DCG

~52 min Avancé Prérequis : leçon 11

À la fin de cette leçon, tu sauras

  • écrire une grammaire avec la notation --> et la lancer avec phrase/2 ;
  • comprendre la traduction d'une DCG en listes de différences ;
  • ajouter des arguments pour construire un résultat pendant l'analyse ;
  • insérer du code avec { }, et exploiter la réversibilité (analyser et générer).
Sommaire de la leçon

Analyser une séquence — une phrase, une ligne de configuration, une expression — est un besoin récurrent. Prolog possède pour cela une notation dédiée, élégante et puissante : les grammaires à clauses définies (DCG). On décrit la structure attendue avec des règles, et Prolog en déduit un analyseur — qui, cerise sur le gâteau, sait aussi générer les séquences valides. C'est l'un des joyaux historiques du langage, à l'origine de son usage en traitement du langage naturel.

Une première grammaire

La flèche --> définit une règle de grammaire. À gauche, un non-terminal (un nom de constituant) ; à droite, la séquence de constituants ou de mots qui le composent. Les mots concrets (les terminaux) s'écrivent comme des éléments de liste, entre crochets.

Cette grammaire se lit : « une phrase simple est un groupe nominal, suivi d'un verbe, suivi d'un groupe nominal ; un groupe nominal est un article suivi d'un nom ».

phrase/2 : lancer l'analyse

On ne lance pas une DCG directement : on passe par phrase(NonTerminal, Liste), qui réussit si Liste peut être entièrement décrite par le non-terminal.

Comment ça marche : les listes de différences

La magie n'en est pas une : Prolog traduit chaque règle --> en une clause ordinaire à deux arguments cachés, qui représentent la liste avant et après consommation. C'est la technique des listes de différences. Ainsi :

Un non-terminal composé enchaîne simplement ces différences : la sortie de l'un devient l'entrée du suivant. phrase(But, L) n'est alors qu'un raccourci pour But(L, []) — « analyse L et exige qu'il ne reste rien ».

Astuce

Tu peux voir la traduction réelle avec listing(article). après avoir chargé la grammaire, ou l'obtenir avec dcg_translate_rule/2. Comprendre les deux arguments cachés démystifie complètement les DCG : ce ne sont que des clauses Prolog déguisées.

{ But } : appeler du Prolog dans la grammaire

Les accolades { But } insèrent du code Prolog ordinaire au milieu d'une règle : il s'exécute sans rien consommer de la liste. Ci-dessus, { N is N0 + 1 } fait le calcul. On s'en sert pour poser une condition, appeler un prédicat, ou bâtir un terme résultat (par exemple un arbre de syntaxe).

Cas réel

Les DCG sont nées avec Prolog dans les années 1970 pour le traitement du langage naturel, et elles restent bien vivantes. SWI-Prolog fournit library(dcg/basics) pour analyser des nombres, des espaces ou des chaînes, et sa bibliothèque HTTP s'en sert pour découper les en-têtes HTTP et les URL. Plus largement, écrire un analyseur (parser) de format — un mini-langage de configuration, une expression arithmétique, un protocole — en DCG est souvent plus court et plus lisible qu'à la main dans un langage impératif, précisément parce que la grammaire est le programme.

Antisèche — les DCG

Glossaire

DCG
Grammaire à clauses définies : notation Prolog (-->) pour décrire et analyser des séquences.
Non-terminal
Nom de constituant défini par des règles (par ex. groupe_nominal) ; il se décompose en d'autres constituants.
Terminal
Élément concret de la séquence, écrit entre crochets ([le]) ; il est consommé tel quel.
Liste de différences
Technique des deux arguments cachés (entrée / reste) par laquelle Prolog traduit une DCG en clauses ordinaires.
phrase/2
Prédicat qui lance une DCG sur une liste et exige qu'elle soit entièrement consommée.
{ But }
Insertion de code Prolog dans une règle DCG ; s'exécute sans consommer de terminal.
Réversibilité
Propriété d'une DCG d'analyser une liste et d'en générer, selon les arguments fournis.

Récap et vérification

  • Une DCG se définit avec --> ; les terminaux sont entre crochets.
  • On la lance avec phrase(NonTerminal, Liste).
  • Prolog la traduit en clauses à deux arguments cachés : les listes de différences.
  • Des arguments construisent un résultat ; { } insère du code ; une DCG analyse et génère.
