Module 3 · Comportement — Leçon 05

Patterns comportementaux

~38 min Intermédiaire Leçon 04 requise

À la fin de cette leçon, tu sauras

  • interchanger des algorithmes avec Strategy ;
  • notifier des changements avec Observer ;
  • parcourir une collection avec Iterator ;
  • encapsuler une action avec Command.
Sommaire de la leçon

Les patterns comportementaux répondent à : « comment les objets se répartissent-ils les responsabilités et communiquent-ils ? » Ils organisent les interactions et les algorithmes. Ce sont souvent les plus utiles au quotidien, car ils résolvent des problèmes que tu rencontres dès qu'une application grandit. On en voit quatre incontournables.

Strategy

Le pattern Strategy (stratégie) permet d'interchanger des algorithmes à l'exécution. On encapsule chaque variante derrière une interface commune, et on choisit laquelle utiliser sans modifier le code qui s'en sert.

Strategy remplace avantageusement les gros if/else ou switch qui choisissent un comportement : chaque branche devient une stratégie isolée, testable, et on en ajoute sans rouvrir le code existant (ouvert/fermé). Tu reconnais l'esprit du Decorator : composer plutôt que ramifier.

Observer

Le pattern Observer (observateur) établit une relation « un-à-plusieurs » : quand un objet (le sujet) change, tous ses observateurs sont notifiés automatiquement. C'est le cœur de la réactivité : interfaces qui se mettent à jour, événements, abonnements.

Le sujet ne connaît pas les détails de ses observateurs : il leur envoie juste une notification. On peut en ajouter ou en retirer sans le modifier. C'est le pattern derrière les systèmes d'événements, les boutons d'interface, et la réactivité de frameworks comme React ou Vue.

Iterator

Le pattern Iterator (itérateur) fournit une façon uniforme de parcourir les éléments d'une collection, sans exposer sa structure interne (tableau, liste chaînée, arbre…). Le code de parcours ne change pas, quelle que soit la collection.

Ce pattern est si fondamental qu'il est intégré à la plupart des langages modernes : la boucle for…of (JS), for…in (Python), les Iterator de Java… reposent tous dessus. Le comprendre éclaire ce qui se passe sous le capot de chaque boucle d'itération.

Command

Le pattern Command (commande) encapsule une action dans un objet : la requête « fais ceci » devient un objet qu'on peut stocker, passer, mettre en file, ou annuler. Cela découple celui qui demande une action de celui qui l'exécute.

En transformant une action en objet, Command rend possibles des fonctionnalités puissantes : annuler/refaire (undo/redo), files d'attente de tâches, journalisation des actions, ou macros (enchaîner plusieurs commandes). C'est un pattern clé des éditeurs et des outils interactifs.

Tu les utilises peut-être déjà

Les patterns comportementaux sont souvent cachés dans les outils que tu utilises : Observer derrière chaque addEventListener et la réactivité de React/Vue ; Iterator derrière chaque for…of ; Strategy dès qu'une fonction reçoit une autre fonction en paramètre (un comparateur de tri, par exemple). Les nommer t'aide à reconnaître ces structures et à les employer consciemment.

Cas réel : l'annuler d'un éditeur et le « live » d'une page

Ouvre un éditeur de texte et tape Ctrl+Z : chaque frappe a été enregistrée comme une Command dans une pile, et l'annulation dépile la dernière. Sur la même page, quand un compteur de likes s'incrémente tout seul sans recharger, c'est un Observer : ton affichage s'est abonné à une source de données et se met à jour à chaque notification. Et le bouton « trier par » d'une boutique en ligne ? Un Strategy : on échange l'algorithme de tri sans réécrire la liste. Ces trois patterns cohabitent dans quasiment toute application interactive.

Lequel choisir ? Pars du verbe

Le bon réflexe est de nommer le besoin : « j'ai plusieurs façons de faire la même chose » → Strategy ; « plusieurs objets doivent réagir à un changement » → Observer ; « je veux parcourir sans exposer la structure » → Iterator ; « je veux stocker, rejouer ou annuler une action » → Command. Le pattern découle du verbe, pas l'inverse.

Observer : pense à te désabonner

Un observateur qu'on oublie de retirer continue d'être notifié : c'est une source classique de fuites mémoire et de bugs « fantômes » (un composant démonté qui réagit encore). Chaque abonner() appelle un desabonner() ; c'est exactement pourquoi React renvoie une fonction de nettoyage dans useEffect.

Glossaire

Pattern comportemental
Famille de patrons qui organise la répartition des responsabilités et la communication entre objets (algorithmes, notifications, parcours, actions).
Strategy (stratégie)
Encapsule chaque variante d'un algorithme derrière une interface commune, interchangeable à l'exécution ; remplace les gros switch.
Observer (observateur)
Relation un-à-plusieurs : un sujet notifie automatiquement tous ses observateurs abonnés lorsqu'il change.
Iterator (itérateur)
Fournit un parcours uniforme d'une collection sans révéler sa structure interne ; intégré à for…of, for…in…
Command (commande)
Transforme une action en objet doté d'executer() (et souvent annuler()), stockable, rejouable, empilable.
Sujet
Dans Observer, l'objet observé qui tient la liste des abonnés et déclenche les notifications.
Undo / redo
Annuler / refaire : fonctionnalité rendue simple par Command, en empilant les actions dans un historique.

Récap et vérification

  • Strategy : algorithmes interchangeables derrière une interface commune (remplace les gros switch).
  • Observer : un sujet notifie automatiquement ses observateurs (événements, réactivité).
  • Iterator : parcours uniforme sans exposer la structure interne (intégré aux for…of).
  • Command : une action devient un objet (undo/redo, files, journalisation, macros).

  2. Quelle relation établit le pattern Observer ?
  3. Quelle fonctionnalité le pattern Command rend-il facile ?

Exercices

Exercice 1Échauffement

Quel pattern comportemental se cache derrière un monBouton.addEventListener("click", ...) ?

Voir une solution

Le pattern Observer : le bouton est le sujet, et la fonction passée est un observateur qu'on abonne à l'événement « click ». Quand le clic survient, le bouton notifie tous ses abonnés.

Exercice 2Application

Implémente le pattern Strategy pour calculer une remise : deux stratégies, remiseFixe (-5 €) et remisePourcent (-10 %), interchangeables.

Voir une solution
Exercice 3Défi

Avec le pattern Command, esquisse un système d'« annuler » pour deux actions sur un compteur : Incrementer et Decrementer.

Voir une solution

Chaque action est un objet qui sait s'exécuter et s'annuler ; on les empile dans un historique pour offrir l'undo.

Exercice 4Au clavier

Un observateur ne vaut que s'il sait aussi se DÉSABONNER — sans quoi il fuit. Écris Sujet avec abonner(fn) qui rend une fonction de désabonnement, et publier(valeur). Abonne deux témoins qui empilent leurs réceptions dans recus, publie 1, désabonne le premier, publie 2, puis affiche le JSON de recus.
