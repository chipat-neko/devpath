Module 01 · Les bases de Rust — Leçon 02

Variables, types et fonctions

~33 min Avancé Leçon 1 recommandée

À la fin de cette leçon, tu sauras

  • Comprendre l'immutabilité par défaut et l'usage de let mut ;
  • Distinguer le shadowing de la mutation, et annoter ou laisser inférer les types ;
  • Manipuler tuples et arrays, et écrire des fonctions dont la dernière expression est la valeur de retour ;
  • Identifier les pièges classiques : point-virgule de trop, débordement, type de retour oublié.
Sommaire de la leçon

En Rust, les fondamentaux que tu connais déjà ailleurs — déclarer une variable, choisir un type, écrire une fonction — sont marqués par une décision de conception qui change tout : une variable est immuable par défaut. Ce n'est pas une contrainte gratuite. C'est le premier levier que le compilateur utilise pour t'éviter des bugs, et la base sur laquelle reposeront plus tard la possession et le borrow checker.

Dans cette leçon, on pose les briques : let et let mut, le shadowing, les types numériques, les constantes, les tuples et arrays, puis les fonctions et le fait que Rust est un langage orienté expressions. Chaque section montre du code et sa sortie (ou l'erreur du compilateur, souvent plus instructive que le succès). Le code se compile avec cargo et s'exécute en natif : lis les blocs et les sorties commentées, puis rejoue-les dans ton propre projet.

1. let : immuable par défaut, mut sur demande

Avec let, tu lies un nom à une valeur. Par défaut, tu ne peux pas réassigner ce nom. Pour autoriser la mutation, tu écris explicitement let mut.

Ce n'est pas du formalisme : déclarer ton intention rend ton code plus sûr et plus lisible. Quand tu vois let sans mut, tu sais que la valeur ne bougera pas — une garantie vérifiée à la compilation.

Note

Immuable n'est pas la même chose que constant. Une variable immuable est calculée à l'exécution mais ne change plus une fois liée. Une const (section 4) est figée à la compilation.

2. Le shadowing : redéclarer avec let

Tu peux réutiliser le même nom en le redéclarant avec let. Ce n'est pas une mutation : tu crées une nouvelle variable qui masque (shadow) la précédente. Avantage majeur : le type peut changer.

Avec let mut, tu ne pourrais pas passer de &str à usize sous le même nom : la mutation conserve le type. Le shadowing, lui, te laisse transformer la valeur tout en gardant l'immutabilité de chaque étape.

3. Les types : entiers, flottants, bool, char

Rust est fortement typé, mais l'inférence te dispense souvent d'écrire le type. Tu peux toujours l'annoter quand c'est utile (ou requis).

Quelques repères : i32 et u32 sont signé/non signé sur 32 bits ; u64 pour les grands entiers ; usize est la taille naturelle de la plateforme, utilisée pour indexer. f64 est le flottant par défaut. Un char tient un scalaire Unicode (4 octets), d'où le support de 'é' ou '♥'.

Astuce

Quand le compilateur n'arrive pas à inférer (par exemple let n = "42".parse().unwrap();), il te le dira et te demandera une annotation. Écris alors let n: i32 = ... ou utilise la syntaxe turbofish parse::<i32>().

4. Les constantes : const

Une const est une valeur figée à la compilation. Son type est obligatoire, elle peut être déclarée dans n'importe quelle portée (y compris globale), et par convention son nom est en MAJUSCULES_AVEC_UNDERSCORES.

Contrairement à let, une const ne peut jamais être mut. Son expression d'initialisation doit être évaluable à la compilation (pas d'appel à une fonction d'exécution). C'est le bon choix pour des valeurs vraiment fixes de ton programme.

5. Tuples et arrays

Le tuple regroupe des valeurs de types éventuellement différents, taille fixe. On y accède par déstructuration ou par index .0, .1…

L'array regroupe des éléments du même type, avec une taille connue à la compilation : [i32; 3] signifie « trois i32 ». L'accès se fait par index, et tout dépassement provoque une panique contrôlée (pas de lecture mémoire sauvage comme en C).

Note

Un array a une taille fixe connue à la compilation. Pour une collection qui grandit, tu utiliseras plus tard Vec<T>, allouée sur le tas.

6. Les fonctions : la dernière expression est la valeur de retour

Une fonction se déclare avec fn. Les paramètres ont un type obligatoire, et le type de retour s'écrit après ->. Point clé : la dernière expression sans point-virgule est la valeur renvoyée. Pas besoin de return (réservé aux retours anticipés).

Piège fréquent

Si tu écris a + b; (avec point-virgule), tu transformes l'expression en instruction qui renvoie () (le type unité). La fonction ne renvoie alors plus un i32 et le compilateur refuse : mismatched types: expected `i32`, found `()`.

7. Les blocs et if sont des expressions

Rust est orienté expressions : un bloc { ... } produit une valeur (sa dernière expression), et if aussi. Tu peux donc affecter directement le résultat d'un if à une variable — pas d'opérateur ternaire, le if suffit.

Les deux branches d'un if-expression doivent renvoyer le même type. C'est encore une vérification à la compilation qui t'évite des incohérences silencieuses.

Pièges fréquents

Piège fréquent

Réassigner une variable non mut est une erreur. Le message est limpide et te propose même la correction.

Autres écueils à garder en tête :

  • Le point-virgule de trop sur l'expression de retour : transforme la valeur en () et casse le type (voir section 6).
  • Confondre shadowing et mutation : let x = ...; let x = ...; crée deux variables ; let mut x = ...; x = ...; en réutilise une seule, et le type ne peut pas changer.
  • Oublier le -> du type de retour : sans lui, Rust suppose que la fonction renvoie (), et toute dernière expression typée sera signalée.

Piège fréquent

Le débordement d'entier. En mode debug (cargo run), 255u8 + 1 provoque une panique attempt to add with overflow. En mode release (--release), l'opération « boucle » silencieusement (wrap-around) à 0. Pour un comportement explicite et portable, utilise les méthodes wrapping_add, checked_add (qui renvoie un Option) ou saturating_add.

Pour aller plus loin

Pour aller plus loin

Rust ne fait aucune conversion numérique implicite. Pour passer d'un type à l'autre, tu écris une conversion explicite avec as (let f = n as f64;) — rapide mais qui peut tronquer. Pour des conversions sûres qui signalent les pertes, regarde TryFrom/TryInto (qui renvoient un Result). Côté littéraux, tu peux suffixer un nombre pour fixer son type (3u8, 2.0f32) et compter sur l'inférence avancée le reste du temps. Et souviens-toi : presque tout est une expression en Rust, y compris match et loop, que tu rencontreras bientôt.

Un cas réel : Ariane 5, 37 secondes de vol

Cas réel

Le 4 juin 1996, le vol inaugural de la fusée Ariane 5 s'est soldé par son autodestruction 37 secondes après le décollage. La cause tient en une ligne : une valeur de vitesse horizontale stockée dans un flottant 64 bits a été convertie vers un entier signé 16 bits… qui ne pouvait pas la contenir. Le débordement, non géré, a déclenché une exception, l'arrêt du calculateur de vol, puis la perte du lanceur (~370 millions de dollars). C'est précisément ce que Rust rend visible : une conversion réductrice s'écrit explicitement (as, ou mieux TryFrom/TryInto qui renvoient un Result signalant le dépassement), et en mode debug une addition qui déborde panique au lieu de « boucler » en silence. Le langage ne t'interdit pas de tout casser : il refuse simplement de cacher la troncature.

Antisèche

Glossaire

Immutabilité
Propriété par défaut d'une variable let : une fois liée, sa valeur ne peut plus être réassignée (sauf let mut).
Shadowing
Redéclarer un nom avec let : on crée une nouvelle variable qui masque l'ancienne ; le type peut changer.
Inférence de type
Capacité du compilateur à deviner le type d'une variable d'après sa valeur, ce qui évite d'annoter partout.
const
Valeur figée à la compilation, au type obligatoire et nommée en MAJUSCULES ; jamais mutable.
Tuple
Regroupement ordonné de valeurs de types éventuellement différents, de taille fixe ; accès par .0, .1… ou par déstructuration.
Array
Tableau d'éléments de même type et de taille connue à la compilation, noté [T; N] ; l'accès hors borne panique.
Expression / instruction
Une expression produit une valeur ; ajouter un ; la transforme en instruction qui vaut () (le type unité).
Débordement (overflow)
Dépassement de la capacité d'un type entier : panique en mode debug, enroulement (wrap) en release ; à gérer avec checked_add, wrapping_add…

Récap et vérification

  • Les variables sont immuables par défaut ; let mut autorise la mutation (sans changer le type).
  • Le shadowing (let x = ... à nouveau) crée une nouvelle variable et peut changer le type.
  • Types de base : i32/u32/u64/usize, f64, bool, char (Unicode) ; inférence ou annotation let x: T.
  • const pour les valeurs figées à la compilation (type obligatoire, MAJUSCULES).
  • Tuples (types mixtes, déstructuration) et arrays [T; N] (taille fixe, même type).
  • Fonctions : fn nom(p: T) -> R ; la dernière expression sans ; est la valeur de retour.
  • Blocs et if sont des expressions qui produisent une valeur.

Vérifie ta compréhension

  1. Quelle est la différence concrète entre let mut x = 1; puis x = "a"; et let x = 1; puis let x = "a"; ? Lequel compile ?
  2. Pourquoi fn carre(n: i32) -> i32 { n * n; } ne compile-t-il pas ? Comment le corriger ?
  3. Que se passe-t-il avec let x: u8 = 255; let y = x + 1; en mode debug, puis en mode release ?
