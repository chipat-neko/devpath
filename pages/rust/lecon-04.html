Module 01 · Les bases de Rust — Leçon 04

Structures, enums et pattern matching

~35 min Avancé Leçon 3 recommandée

À la fin de cette leçon, tu sauras

  • Savoir définir des struct (classique, tuple, unit), les instancier et leur attacher méthodes et fonctions associées via impl
  • Savoir créer des enum dont les variantes portent des données et les analyser par match exhaustif
  • Savoir utiliser Option<T> à la place du null et le traiter sans risque de plantage
  • Savoir choisir entre match, if let et let ... else selon le cas, et afficher un type avec #[derive(Debug)].
Sommaire de la leçon

Tu sais maintenant manipuler les types de base de Rust. Mais un vrai programme manipule des données structurées : un point a deux coordonnées, une forme géométrique peut être un cercle ou un rectangle, une recherche renvoie une valeur ou rien du tout. C'est là que Rust déploie l'un de ses plus beaux atouts : un système de types expressif où le compilateur t'oblige à traiter tous les cas possibles. Plus de null qui plante à 3 h du matin, plus de cas oublié.

Dans cette leçon, tu vas modéliser des données avec struct et enum, leur attacher des méthodes via impl, découvrir Option<T> (la réponse de Rust au null), et surtout maîtriser match, le pattern matching exhaustif. C'est le cœur de la pensée « à la Rust ».

La syntaxe de mise à jour ..

Pour créer une instance qui reprend la plupart des champs d'une autre, Rust offre une syntaxe concise : ..autre remplit les champs non précisés depuis une instance existante.

Note

La syntaxe ..base déplace (move) les champs non-Copy de base. Si Config contenait une String, base deviendrait partiellement inutilisable ensuite. Ici tous les champs sont Copy, donc base reste utilisable.

Les méthodes avec impl

On attache des comportements à un type dans un bloc impl. Une méthode prend &self (emprunt en lecture de l'instance) ; une fonction associée n'a pas de self et s'appelle avec :: — c'est le rôle classique d'un constructeur new.

Astuce

Choisis ta réception selon le besoin : &self pour lire, &mut self pour modifier, self (rare) pour consommer l'instance. Commence toujours par &self — c'est le moins contraignant pour l'appelant.

Les enums : des variantes qui portent des données

En C, un enum n'est qu'une liste de constantes entières. En Rust, c'est beaucoup plus puissant : chaque variante peut transporter ses propres données. C'est un « type somme » : une valeur est exactement l'une des variantes.

Un seul type Forme représente trois structures de données différentes, et le compilateur sait laquelle est laquelle. C'est cette combinaison enum + match qui rend Rust si agréable pour modéliser un domaine.

Option<T> : Rust n'a pas de null

Le « null » a coûté des milliards de bugs. Rust le supprime à la racine : une valeur qui peut être absente a le type Option<T>, un enum de la bibliothèque standard avec deux variantes : Some(valeur) ou None. Tu ne peux pas oublier le cas absent : le compilateur t'y force.

Note

Beaucoup de méthodes de la bibliothèque standard renvoient un Option<T> : vec.first(), vec.get(i), texte.chars().next()… À chaque fois, le type t'informe « ça peut être vide ».

Le pattern matching avec match

match compare une valeur à des motifs, extrait les données au passage, et — point crucial — est exhaustif : tu dois couvrir tous les cas, sinon ça ne compile pas. Tu peux ajouter une garde (if) et le motif attrape-tout _.

Cette erreur est un cadeau : Rust vient de t'éviter un bug en production.

if let et let ... else pour les cas simples

Quand un seul cas t'intéresse, un match complet est verbeux. if let ne traite qu'un motif. let ... else (moderne, édition 2021) extrait la valeur ou sort du bloc si le motif échoue.

Astuce

let ... else garde le « chemin heureux » non indenté : après le let Some(n) = x else {...}, la variable n est disponible dans tout le reste de la fonction. C'est idéal pour valider des entrées en début de fonction.

Afficher avec #[derive(Debug)]

Par défaut, tes types ne savent pas s'afficher. L'attribut #[derive(Debug)] génère automatiquement une représentation pour le débogage, utilisable avec {:?} (compact) ou {:#?} (joliment indenté).

Pièges fréquents

Piège fréquent

Oublier None dans un match sur un Option. Le compilateur te le refuse : non-exhaustive patterns: `None` not covered. Ce n'est pas une corvée, c'est la garantie que ton code ne plantera jamais sur un cas absent oublié.

Piège fréquent

Dégainer .unwrap() sur un Option par flemme. x.unwrap() renvoie la valeur si Some, mais panique (crash) si None. Pratique en prototype, dangereux en production. Préfère match, if let, ou des combinateurs comme x.unwrap_or(0).

Piège fréquent

Oublier &self dans une méthode. Une fn aire() -> f64 dans un impl devient une fonction associée (appelée par Rectangle::aire()), pas une méthode : r.aire() ne compilera pas. Écris bien fn aire(&self) -> f64.

Piège fréquent

Confondre l'enum à données et l'enum « à la C ». enum Forme { Cercle(f64) } porte une valeur : tu n'y accèdes que par match ou if let, jamais par forme.0. Un enum sans données (Couleur::Rouge) se compare directement.

Pour aller plus loin

Pour aller plus loin

Un enum peut être récursif (un arbre, une liste chaînée), mais comme sa taille serait infinie, on encapsule la récursion dans une Box<T> (pointeur sur le tas) : enum Arbre { Feuille(i32), Noeud(Box<Arbre>, Box<Arbre>) }. Côté motifs, explore le pattern matching avancé : alternatives A | B, intervalles 1..=9, et liaison @ pour capturer tout en testant. Enfin, le cousin de Option pour gérer les erreurs, Result<T, E>, arrive en leçon 9. Tes struct et enum peuvent aussi devenir génériques (struct Paire<T> { a: T, b: T }).

Un cas réel : « l'erreur à un milliard de dollars »

Cas réel

En 2009, Tony Hoare — l'informaticien qui a inventé la référence null en 1965 pour le langage ALGOL W — a livré une confession restée célèbre : il a qualifié le null de « erreur à un milliard de dollars » (billion-dollar mistake). Son constat : le null était si facile à ajouter qu'il n'a pas résisté ; mais depuis, d'innombrables plantages, failles de sécurité et NullPointerException ont découlé de valeurs « absentes » déréférencées par mégarde, pour un coût cumulé qu'il chiffre en milliards. Rust tire la leçon jusqu'au bout : il n'y a pas de null. Une valeur qui peut manquer est une Option<T>, et le compilateur refuse de la traiter comme présente tant que tu n'as pas géré le cas None. Le bug le plus courant de l'histoire du logiciel devient, ici, impossible à compiler.

Glossaire

struct
Type « produit » qui regroupe des champs nommés (ou positionnels) ; une instance contient tous ses champs.
impl
Bloc où l'on attache à un type ses méthodes (&self, &mut self) et ses fonctions associées (sans self, appelées via Type::…).
enum (type somme)
Type dont une valeur est exactement une variante parmi plusieurs ; chaque variante peut porter ses propres données.
Variante
L'un des cas possibles d'un enum (ex. Cercle(f64), None). On y accède par match ou if let, pas par index.
Option<T>
Enum standard Some(T) / None qui remplace le null : l'absence possible est inscrite dans le type.
match
Filtrage par motifs exhaustif : extrait les données et force à couvrir tous les cas (garde if, attrape-tout _).
if let / let … else
Formes courtes pour un seul motif : if let ne traite qu'un cas ; let … else extrait la valeur ou quitte le bloc.
#[derive(Debug)]
Attribut qui génère automatiquement l'affichage de débogage d'un type, utilisable avec {:?} (compact) ou {:#?} (indenté).

Récap et vérification

  • struct regroupe des données nommées ; trois formes : classique, tuple, unit. La syntaxe ..autre recopie les champs restants.
  • impl attache méthodes (&self, &mut self) et fonctions associées (Self::new).
  • enum définit un type somme : chaque variante peut porter ses propres données.
  • Option<T> (Some/None) remplace le null : l'absence est dans le type.
  • match est exhaustif, extrait les données, accepte gardes if et motif _ ; if let et let ... else gèrent les cas simples.
  • #[derive(Debug)] rend un type affichable avec {:?}.

Vérifie ta compréhension

  1. Quelle est la différence entre une méthode (fn aire(&self)) et une fonction associée (fn new()), et comment appelle-t-on chacune ?
  2. Pourquoi le compilateur refuse-t-il un match qui ne couvre pas le cas None d'un Option ? En quoi est-ce un avantage ?
  3. Écris la signature d'un enum Forme dont la variante Rectangle porte une largeur et une hauteur. Comment extrais-tu ces deux valeurs ?
