Module 07 · Rust au quotidien — Leçon 19

Fichiers, entrées/sorties et système

~35 min Intermédiaire Gestion d'erreurs (leçon 9) utile

À la fin de cette leçon, tu sauras

  • lire et écrire un fichier entier avec std::fs ;
  • propager les erreurs d'E/S avec Result et ?, jusque dans main ;
  • lire un gros fichier ligne par ligne avec un BufReader, à mémoire constante ;
  • manipuler les chemins (Path) et lire les arguments et variables d'environnement.
Sommaire de la leçon

Un programme utile finit toujours par toucher le monde extérieur : lire un fichier de configuration, écrire un rapport, parcourir un journal. En Rust, ces opérations passent par std::fs (le système de fichiers) et std::io (les entrées/sorties). Toutes partagent un trait : elles renvoient un Result, parce qu'un disque plein, un fichier absent ou une permission refusée sont des échecs normaux, pas des exceptions surprises.

Lire et écrire un fichier entier

Les deux raccourcis les plus fréquents : fs::write (crée ou écrase) et fs::read_to_string (charge tout dans une String). Remarque que main peut lui-même renvoyer un Result : cela autorise l'opérateur ? dès le point d'entrée.

Le ? après chaque appel dit : « si c'est un Err, arrête la fonction et renvoie cette erreur ». Comme main renvoie io::Result<()>, une erreur remonte jusqu'à l'exécutable, qui l'affiche et se termine avec un code de sortie non nul. Le Ok(()) final signale que tout s'est bien passé.

Pourquoi un Result partout

Rust n'a pas d'exceptions : une E/S qui peut échouer renvoie un Result<T, io::Error>, et le compilateur t'oblige à traiter le cas d'échec. Parfois on ne veut pas propager mais réagir — par exemple retomber sur une valeur par défaut :

Ici, un fichier manquant n'est pas fatal : on l'intercepte avec match, on prévient sur stderr, et on continue. Séparer stdout (le résultat normal) de stderr (les messages) permet de rediriger l'un sans polluer l'autre — un réflexe d'outil en ligne de commande.

Lire ligne par ligne, sans tout charger

Pour un fichier de plusieurs gigaoctets, read_to_string saturerait la RAM. On ouvre alors le fichier avec File::open, on l'enveloppe dans un BufReader (qui ajoute un tampon mémoire pour éviter un appel système par ligne), et on itère avec .lines().

File::open ouvre en lecture seule ; BufReader::new l'entoure d'un tampon ; .lines() produit un itérateur où chaque ligne est un Result (une lecture peut échouer en cours de route, d'où le ligne?). Quelle que soit la taille du fichier, une seule ligne occupe la mémoire à la fois.

Ajouter à un fichier

Pour compléter un fichier sans l'écraser (un journal, par exemple), on ouvre avec OpenOptions en mode append. Les macros write! / writeln! écrivent alors dedans comme dans println!.

write! et writeln! fonctionnent sur tout ce qui implémente Write : un fichier, la sortie standard (io::stdout()), voire un Vec<u8> en mémoire. La même macro, cibles différentes — c'est la force des traits (leçon 8).

Les chemins, proprement

Ne colle jamais des chaînes avec / à la main : Windows sépare avec \. Path et PathBuf construisent des chemins portables.

Arguments et variables d'environnement

Le module std::env donne accès au contexte du programme : les arguments passés en ligne de commande, et les variables d'environnement.

On utilise args.get(1) plutôt que args[1] pour éviter une panique si l'argument manque : get renvoie une Option, qu'on traite avec if let. La leçon 21 bâtira une vraie interface en ligne de commande sur ces bases.

Cas réel — 2 Go de logs, quelques kilo-octets de RAM

Une équipe d'astreinte cherchait pourquoi un service ralentissait la nuit. Ouvrir le journal de 2 Go dans un éditeur figeait la machine. Un collègue a écrit quinze lignes de Rust : un BufReader parcourait le fichier en flux, comptait les lignes ERROR par heure, et crachait un résumé en une seconde. Avec read_to_string, l'outil aurait réclamé 2 Go de RAM et se serait peut-être fait tuer par le système ; le BufReader, lui, n'en consommait que quelques kilo-octets. Choisir le bon mode de lecture, c'est parfois la différence entre « ça marche » et « ça plante ».

Astuce — fn main() -> Result

Faire renvoyer un Result à main débloque l'opérateur ? dès le point d'entrée : fini les unwrap() partout. En cas d'Err, Rust affiche le message de debug de l'erreur et sort avec un code non nul — exactement ce qu'attend un script ou une CI.

Erreur fréquente

Écrire dans un fichier sans tampon, une ligne à la fois avec File directement, déclenche un appel système par écriture : très lent sur des milliers de lignes. Enveloppe dans un BufWriter pour regrouper les écritures. Et n'oublie pas : fs::write écrase le fichier — utilise OpenOptions::append quand tu veux compléter.

Pour aller plus loin

Pour des données binaires, fs::read renvoie un Vec<u8> plutôt qu'une String. Pour lire l'entrée clavier, io::stdin().read_line(&mut ligne). Pour parcourir une arborescence entière, la crate walkdir ; pour un tampon d'écriture, BufWriter ; pour des chemins et erreurs plus riches, les crates camino et anyhow. Enfin, std::process::Command lance d'autres programmes.

Glossaire

std::fs
Module de la bibliothèque standard pour le système de fichiers : lire, écrire, créer, supprimer.
std::io
Module des entrées/sorties : traits Read/Write, tampons, flux standard, type io::Error.
Result<T, E>
Type de retour des E/S : Ok(valeur) en cas de succès, Err(erreur) sinon.
Opérateur ?
Propage l'erreur : sur un Err, il quitte la fonction en renvoyant cette erreur.
BufReader
Lecteur à tampon : il lit par gros blocs pour éviter un appel système par ligne ; .lines() itère les lignes.
Tampon (buffer)
Zone mémoire intermédiaire qui regroupe les lectures ou écritures pour limiter les coûteux appels système.
Path / PathBuf
Chemin de fichier emprunté / possédé, portable entre systèmes (gère / et \).
stdout / stderr
Sortie standard (le résultat, via println!) et sortie d'erreur (les messages, via eprintln!).

Récap et vérification

  • Les E/S renvoient un Result : on le traite avec ? (propager) ou match (réagir).
  • Petit fichier : fs::read_to_string / fs::write. Gros fichier : BufReader ligne par ligne.
  • fn main() -> io::Result<()> permet d'utiliser ? dès le point d'entrée.
  • Compléter un fichier : OpenOptions::append(true) ; écrire : writeln!.
  • Chemins portables avec Path ; arguments et env via std::env ; erreurs sur eprintln!.
