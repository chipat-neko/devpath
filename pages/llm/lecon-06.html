Les agents (boucle d'outils)

~35 min Intermédiaire Leçon 05

À la fin de cette leçon, tu sauras

  • définir ce qu'est un agent LLM ;
  • décrire la boucle observer → penser → agir ;
  • nommer ses composants (modèle, outils, mémoire, arrêt) ;
  • poser les garde-fous indispensables.
Sommaire de la leçon

Jusqu'ici, un appel = une réponse. Un agent va plus loin : c'est un LLM placé dans une boucle, capable d'utiliser des outils à plusieurs reprises pour atteindre un but, en s'adaptant aux résultats. C'est la combinaison naturelle de tout ce qu'on a vu.

Qu'est-ce qu'un agent ?

Un agent est un système où le LLM décide des actions à entreprendre, les exécute via des outils, observe les résultats, et recommence jusqu'à avoir résolu la tâche. Au lieu de tout faire en un coup, il raisonne par étapes et corrige sa trajectoire.

La différence clé

Un appel simple : « réponds à cette question ». Un agent : « atteins ce but ; tu peux chercher, calculer, appeler des outils autant de fois que nécessaire ». Le modèle pilote sa propre suite d'actions.

La boucle d'un agent

Cas réel

Un assistant de programmation (Claude Code, Cursor, Copilot) est un agent. Pour corriger un bug, il lit les fichiers (outil), lance les tests (outil), observe l'erreur, modifie le code, relance — et boucle jusqu'à ce que les tests passent. Il n'écrit pas la solution d'un coup : il avance par essais, en s'appuyant sur ce que chaque outil lui répond. C'est exactement la boucle penser → agir → observer.

Les composants

  • Le modèle : il raisonne et choisit les actions.
  • Les outils : recherche, base de données, calcul, API… déclarés via le tool use (leçon 4).
  • La mémoire : l'historique des étapes, renvoyé à chaque appel (le modèle est sans mémoire).
  • La condition d'arrêt : tâche résolue, ou limite d'étapes atteinte.

Commence simple

Beaucoup de tâches ne nécessitent pas d'agent : un seul appel, ou un appel + un outil, suffit souvent. N'ajoute la boucle que si la tâche demande vraiment plusieurs étapes décidées dynamiquement. La simplicité est une fonctionnalité.

Les garde-fous

Un agent agit : il faut l'encadrer. Trois risques principaux et leurs parades :

  • Boucle sans fin → limite le nombre d'étapes (et le budget de tokens).
  • Action dangereuse (supprimer, payer, envoyer) → exige une confirmation humaine ou restreins les outils.
  • Coût qui dérape → fixe un budget et journalise chaque appel.

Le principe du moindre privilège

Ne donne à l'agent que les outils strictement nécessaires, avec les droits minimaux. Un agent qui peut seulement lire est bien moins risqué qu'un agent qui peut supprimer ou dépenser.

Pièges fréquents

  • Sortir l'agent trop tôt. Pour une tâche simple, un appel suffit ; l'agent ajoute coût et imprévisibilité.
  • Pas de limite d'étapes. Risque de boucle infinie et de facture salée.
  • Outils trop puissants. Applique le moindre privilège ; valide les actions sensibles.
  • Oublier l'observation. Le résultat de chaque outil doit revenir dans l'historique, sinon l'agent « oublie ».

Pour aller plus loin

Des frameworks (LangChain, LlamaIndex, et les SDK d'agents des fournisseurs) fournissent la boucle, la gestion des outils et la mémoire. Mais comprendre la boucle « observer-penser-agir » à la main est le meilleur moyen de déboguer et de ne pas la subir comme une boîte noire.

Pour aller plus loin

Au-delà d'un agent, on compose parfois plusieurs agents spécialisés qui coopèrent (un planifie, un autre exécute, un autre vérifie). Puissant, mais à n'envisager qu'une fois le cas à un seul agent bien maîtrisé.

Glossaire

Agent
Un LLM placé dans une boucle où il choisit des actions, les exécute via des outils, observe les résultats et recommence jusqu'au but.
Boucle ReAct
Reason + Act : penser → agir (outil) → observer → répéter → répondre. Le patron de base d'un agent.
Outil (tool)
Une fonction que l'agent peut appeler pour agir : recherche, base de données, API, calcul. Déclaré via le tool use.
Mémoire (historique)
La suite des étapes, renvoyée au modèle à chaque appel puisqu'une API de LLM est sans mémoire.
Condition d'arrêt
Ce qui ferme la boucle : tâche jugée résolue, ou limite d'étapes (ou de budget) atteinte.
Moindre privilège
Ne donner à l'agent que les outils strictement nécessaires, avec les droits minimaux, pour limiter les dégâts possibles.
Budget (de tokens)
Plafond de coût/appels fixé à l'agent pour éviter qu'une boucle ne fasse déraper la facture.
Multi-agents
Plusieurs agents spécialisés qui coopèrent (planifier, exécuter, vérifier). Puissant, mais à réserver aux cas déjà maîtrisés à un seul agent.

Récap et vérification

  • Un agent = un LLM dans une boucle qui utilise des outils pour atteindre un but.
  • Boucle ReAct : penser → agir (outil) → observer → répéter → répondre.
  • Composants : modèle, outils, mémoire (historique), condition d'arrêt.
  • Garde-fous : limite d'étapes, budget, moindre privilège, validation des actions sensibles.

Vérifie ta compréhension

  1. Qu'est-ce qui distingue un agent d'un simple appel ?
  2. Cite les étapes de la boucle ReAct.
  3. Quels garde-fous mettre en place ?

Exercices

Exercice 1Échauffement

Décris en une phrase ce que fait la boucle d'un agent à chaque tour.

Voir une solution

À chaque tour, l'agent réfléchit à la prochaine action, appelle un outil (avec des arguments), observe le résultat renvoyé par ton code, puis recommence — jusqu'à juger la tâche terminée et formuler la réponse finale.

Exercice 2Application

Ajoute deux garde-fous au pseudo-code d'un agent : une limite d'étapes et une validation avant toute action « destructrice ».

Voir une solution
Exercice 3Défi

On te demande un assistant qui « répond à une question simple de l'utilisateur ». Faut-il un agent ? Justifie, et dis quand l'agent deviendrait justifié.

Voir une solution

Non pour une simple question : un appel unique (éventuellement avec un outil) suffit ; un agent ajouterait du coût, de la latence et de l'imprévisibilité sans bénéfice. L'agent devient justifié quand la tâche exige plusieurs étapes décidées dynamiquement — par exemple : chercher des informations, les croiser, effectuer un calcul, puis agir — sans qu'on puisse fixer la séquence à l'avance. La règle : la complexité de l'outil doit suivre la complexité réelle de la tâche.
