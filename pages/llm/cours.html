Développer avec l'IA & les LLM

Les grands modèles de langage (LLM) sont devenus une brique logicielle comme une autre : on les appelle par API pour résumer, classer, extraire, dialoguer ou raisonner. Ce cours t'apprend à construire avec eux — comprendre comment ils fonctionnent, les piloter par le prompt, structurer leurs sorties, les augmenter avec tes données (RAG) et les transformer en agents.

Bien s'équiper

À installer pour ce cours

  • Continue (ou un assistant équivalent) — discuter avec un LLM dans l'éditeur.
  • REST Client — tester les appels d'API de LLM sans quitter VS Code.
  • Python / Pylance — si tu codes les exemples en Python.
  • DotENV — colorer le fichier .env où vit ta clé d'API.

Prérequis

Savoir lire un peu de Python ou de JavaScript et connaître les bases d'une API REST suffit. Une clé d'API d'un fournisseur de LLM permet de pratiquer, mais le cours reste compréhensible sans, grâce aux exemples commentés.

Ce que tu vas apprendre

Objectifs du cours

À la fin du cours, tu sauras

  • expliquer ce qu'est un LLM : tokens, contexte, température ;
  • rédiger des prompts efficaces et fiables ;
  • appeler une API de LLM et lire sa réponse ;
  • obtenir des sorties structurées (JSON) et utiliser le tool use ;
  • brancher tes données avec le RAG ;
  • concevoir un agent et une petite application IA ;
  • évaluer, sécuriser, maîtriser le coût et adapter un modèle en production.

Pour qui, et pourquoi

Ce cours est pour toi si tu veux intégrer un LLM dans un logiciel, pas seulement discuter avec un assistant. On démystifie la « magie » : un LLM est un outil probabiliste qu'on apprend à diriger, encadrer et brancher à des données réelles.

Le fil conducteur est pratique : à chaque étape, une brique utilisable — un prompt robuste, un appel d'API, une sortie JSON validée, une recherche documentaire, une boucle d'agent — jusqu'à une petite application complète.

Astuce

Un LLM ne « sait » pas : il prédit le texte le plus probable. Garder cette idée en tête explique ses forces (fluidité, généralisation) comme ses faiblesses (hallucinations) — et comment l'encadrer.

Récapitulatif

À retenir & glossaire

Les points clés du cours, puis les termes essentiels à connaître.

À retenir

  • Un LLM prédit le token suivant ; il ne consulte pas une base de faits.
  • Le prompt (et le message système) dirige le modèle : sois clair, donne des exemples.
  • On l'intègre via une API ; on peut exiger une sortie JSON ou des outils.
  • Le RAG branche tes documents pour des réponses fondées et à jour.
  • Un agent = un LLM dans une boucle qui appelle des outils pour agir.
LLM
Grand modèle de langage : un modèle entraîné à prédire le mot (token) suivant.
Token
Un morceau de texte (souvent un bout de mot) ; l'unité que le modèle manipule.
Contexte
La quantité de texte (en tokens) que le modèle peut prendre en compte d'un coup.
Température
Un réglage de l'aléatoire : basse = sûr et répétable, haute = varié et créatif.
Prompt
Le texte d'instruction envoyé au modèle pour obtenir une réponse.
Message système
Une consigne de cadrage qui fixe le rôle et les règles du modèle.
Hallucination
Une réponse fausse mais plausible, inventée par le modèle.
Tool use
La capacité du modèle à demander l'appel d'une fonction/outil défini par toi.
RAG
Génération augmentée par récupération : fournir au modèle des extraits pertinents.
Embedding
Une représentation numérique d'un texte, pour mesurer sa similarité.
Agent
Un LLM placé dans une boucle où il appelle des outils pour atteindre un but.
Injection de prompt
Faire exécuter au modèle des instructions non prévues, cachées dans une entrée non fiable ; menace n°1 de l'OWASP Top 10 LLM.
Streaming
Afficher la réponse token par token, au fil de l'eau, pour réduire la latence perçue (viser le premier token).
Fine-tuning
Poursuivre l'entraînement d'un modèle sur tes exemples pour ancrer un comportement ; n'ajoute pas de faits fiables (c'est le rôle du RAG).
