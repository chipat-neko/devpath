Extensions et personnalisation

~29 min Débutant Leçon 03 conseillée

À la fin de cette leçon, tu sauras

  • installer et gérer des extensions ;
  • régler VS Code via l'interface et settings.json ;
  • changer de thème et de raccourcis ;
  • créer tes propres snippets.
Sommaire de la leçon

VS Code démarre volontairement léger : c'est toi qui l'adaptes à ton travail, par des extensions (ajouter des langages et des outils) et par des réglages (changer le comportement et l'apparence). Cette leçon montre comment, et pourquoi le tout est portable d'une machine à l'autre. C'est aussi le pont vers la seconde partie de ce cours : chaque langage a ses extensions de prédilection.

Installer une extension

Clique l'icône Extensions dans la barre d'activité (les carrés), ou Ctrl+Shift+X. La barre latérale devient une place de marché : tape un nom (langage, outil), lis la fiche, clique Install. Une extension peut apporter :

  • la coloration et l'IntelliSense d'un langage (Python, Rust, PHP…) ;
  • un formateur (Prettier) ou un analyseur (ESLint) qui repère et corrige le style ;
  • des outils : clients HTTP, support Docker, thèmes d'icônes, etc.

Une fois installées, tes extensions sont listées ; on peut les désactiver (globalement ou pour un seul projet) sans les désinstaller. Trop d'extensions ralentissent le démarrage : n'installe que ce qui te sert.

Vérifie ce que tu installes

Les extensions sont du code tiers qui s'exécute dans ton éditeur. Privilégie les extensions vérifiées, au nombre de téléchargements élevé et à l'éditeur connu ; lis les permissions. Comme pour toute dépendance (cf. cours Sécurité), une extension malveillante est un risque réel.

Les réglages : interface et fichier JSON

Ouvre les réglages avec Ctrl+, (virgule). Tu as deux faces de la même chose :

  • l'interface graphique : une recherche et des cases à cocher, parfaite pour découvrir une option ;
  • le fichier settings.json (icône « {} » en haut à droite, ou la commande « Preferences: Open User Settings (JSON) ») : les mêmes réglages en texte (cours Formats de données), faciles à copier et à versionner.

Deux réglages valent leur pesant d'or dès le début : "editor.formatOnSave": true formate le code à chaque enregistrement (avec un formateur installé), et "files.autoSave" enregistre automatiquement. À chaque réglage de l'interface correspond une clé dans ce JSON : les deux sont synchronisés.

Réglages utilisateur ou réglages du projet

Il existe deux niveaux de réglages, et c'est une distinction importante :

  • les réglages utilisateur s'appliquent à tous tes projets (ton profil personnel) ;
  • les réglages d'espace de travail vivent dans un fichier .vscode/settings.json à la racine du projet ; ils ne valent que pour ce projet et, étant versionnés, sont partagés avec l'équipe.

On met dans les réglages du projet ce qui doit être commun à tous (taille d'indentation, formateur), et dans les réglages utilisateur ses préférences personnelles (thème, police).

Cas réel — un projet qui se configure tout seul

Une équipe en a assez des « chez moi le formatage est différent ». Elle ajoute au dépôt un .vscode/settings.json (Format On Save + Prettier + indentation) et un .vscode/extensions.json listant les extensions recommandées du projet. Résultat : quand un nouveau venu clone le dépôt et ouvre le dossier, VS Code lui propose d'installer les bonnes extensions, et le formatage est déjà réglé. L'environnement de travail est versionné avec le code : plus de demi-journée perdue à configurer sa machine, et le même rendu pour toute l'équipe.

Activer une extension par projet

Une extension lourde (le support d'un langage que tu n'utilises que sur un seul projet) peut être désactivée globalement puis réactivée pour l'espace de travail concerné, via son menu. Ton démarrage reste rapide partout ailleurs. Pour aller plus loin, les profils (leçon 06) regroupent d'un coup tout un jeu d'extensions et de réglages.

Thèmes et raccourcis

Le thème de couleurs se change via Ctrl+Shift+P → « Couleur du thème », ou la clé workbench.colorTheme. Des extensions ajoutent des thèmes (sombres, clairs) et des thèmes d'icônes de fichiers.

Synchroniser ses réglages

La fonction Settings Sync (intégrée) sauvegarde tes réglages, extensions, thèmes et snippets dans ton compte (GitHub ou Microsoft). Sur une nouvelle machine, tu te connectes et tu retrouves exactement ton environnement. Comme tout est du texte (JSON), on peut aussi versionner ces fichiers dans un dépôt.

Glossaire

Extension
Module tiers qui ajoute à VS Code un langage, un formateur, un analyseur, un thème ou un outil.
Place de marché (Marketplace)
Catalogue d'extensions accessible via Ctrl+Shift+X, où l'on cherche et installe.
settings.json
Fichier texte (JSON) des réglages ; chaque option de l'interface y correspond à une clé.
Réglages utilisateur
Ton profil personnel de réglages, appliqué à tous tes projets.
Réglages d'espace de travail
Réglages propres à un projet, dans .vscode/settings.json, versionnés et partagés avec l'équipe.
Snippet
Modèle de code inséré par un préfixe suivi de Tab, avec des emplacements de curseur ($1, $2, $0).
Thème
Jeu de couleurs de l'interface et du code (workbench.colorTheme) ; des extensions en ajoutent.
Settings Sync
Fonction qui sauvegarde réglages, extensions et snippets dans un compte pour les retrouver sur une autre machine.

Récap et vérification

  • Les extensions (Ctrl+Shift+X) ajoutent langages, formateurs et outils ; n'installe que l'utile, et fais attention à la provenance.
  • Les réglages (Ctrl+,) ont deux faces : l'interface et le fichier settings.json (texte, versionnable).
  • Deux niveaux : réglages utilisateur (tous projets) et d'espace de travail (.vscode/settings.json, partagés avec l'équipe).
  • On personnalise thèmes, raccourcis (keybindings.json) et snippets ; Settings Sync rend tout cela portable.

Exercices

Exercice 1Échauffement

Tu veux que VS Code formate automatiquement ton code à chaque enregistrement. Comment l'activer, et de quoi as-tu besoin en plus ?

Voir une solution

Active le réglage "editor.formatOnSave": true (via l'interface Ctrl+, en cherchant « format on save », ou directement dans settings.json). Il te faut aussi un formateur pour ton langage : par exemple l'extension Prettier pour JavaScript/CSS/HTML, que tu définis comme formateur par défaut. À chaque Ctrl+S, le fichier est mis en forme.

Exercice 2Application

Toute ton équipe doit utiliser une indentation de 2 espaces sur un projet, quels que soient les réglages personnels de chacun. Où places-tu ce réglage ?

Voir une solution

Dans les réglages d'espace de travail : crée (ou complète) le fichier .vscode/settings.json à la racine du projet avec { "editor.tabSize": 2, "editor.insertSpaces": true }. Comme ce fichier est versionné avec le code (Git), il s'applique à tous ceux qui ouvrent le projet, par-dessus leurs préférences personnelles — sans imposer ce choix à leurs autres projets. C'est la bonne place pour les conventions d'équipe.
