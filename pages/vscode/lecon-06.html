Module 3 · Aller plus loin — Leçon 06

Le débogage et fonctionnalités avancées

~31 min Intermédiaire Leçons 01 à 05 conseillées

À la fin de cette leçon, tu sauras

  • poser un point d'arrêt et lancer le débogueur ;
  • avancer pas à pas et inspecter l'état ;
  • configurer le débogage avec launch.json ;
  • utiliser le renommage et les actions de code.
Sommaire de la leçon

On termine ce cours par ce qui distingue vraiment un éditeur de code d'un simple bloc-notes : le débogueur intégré, qui permet d'arrêter un programme en plein vol pour examiner ce qu'il fait, et les outils de refactorisation, qui transforment le code en sécurité. Tu as maintenant tous les repères des leçons précédentes pour comprendre où ces fonctions se logent dans l'interface.

Poser un point d'arrêt

Un point d'arrêt (breakpoint) dit au programme : « arrête-toi ici, que je regarde ». Clique dans la gouttière, à gauche d'un numéro de ligne : un point rouge apparaît. Quand l'exécution atteindra cette ligne, elle se mettra en pause avant de l'exécuter.

C'est bien plus puissant que parsemer le code de console.log : tu inspectes tout l'état au moment de la pause, sans modifier le code.

Piège fréquent

La pause a lieu avant l'exécution de la ligne, jamais après. Pose ton point d'arrêt sur const somme = notes.reduce(…) et, à l'arrêt, somme n'a pas encore sa valeur : le panneau Variables ne montre rien d'utile et tu conclus à tort que le calcul est faux. Avance d'un pas (F10) pour exécuter la ligne, puis relis la valeur.

Lancer et piloter le débogueur

Appuie sur F5 pour démarrer le débogage (VS Code te demande le type d'environnement la première fois, ex. Node.js). Le programme s'exécute et s'arrête à ton point d'arrêt. Une barre de contrôle apparaît ; ses boutons :

Pendant la pause, la vue Exécuter et déboguer (barre d'activité) montre :

  • Variables : la valeur de chaque variable locale et globale, en direct ;
  • Espions (Watch) : des expressions que tu choisis de suivre ;
  • Pile d'appels (Call Stack) : la suite des fonctions qui ont mené ici ;
  • tu peux aussi survoler une variable dans le code pour voir sa valeur.

Points d'arrêt conditionnels

Clic droit sur un point d'arrêt → Modifier le point d'arrêt : tu peux poser une condition (ex. i === 42) pour ne t'arrêter que dans ce cas, ou un point de journalisation (logpoint) qui affiche un message sans interrompre l'exécution. Idéal pour traquer un bug qui n'arrive qu'à une itération précise.

Configurer avec launch.json

Pour un projet réel, on enregistre la configuration de débogage dans .vscode/launch.json. La vue Exécuter propose « créer un fichier launch.json » et le pré-remplit selon l'environnement détecté :

Chaque entrée de configurations devient un choix dans le menu déroulant de la vue Exécuter. On peut en avoir plusieurs (lancer le serveur, lancer les tests, attacher à un processus…). Les variables comme ${workspaceFolder} évitent de coder en dur les chemins.

Cas réel — le bug qui n'arrivait qu'une fois sur mille

Un développeur traque un plantage qui ne survient qu'occasionnellement dans une longue boucle de traitement. Après une heure à semer des console.log qui noient la console sous des milliers de lignes, il pose un point d'arrêt conditionnel montant < 0 sur la ligne suspecte. Le débogueur ne s'arrête qu'au moment fautif : la pile d'appels révèle aussitôt qu'une remise négative avait été appliquée deux fois. Bug compris en cinq minutes, sans une seule ligne de log ajoutée. C'est le quotidien : un débogueur bien utilisé remplace des dizaines d'console.log.

Renommer proprement (refactorisation)

En leçon 02, Ctrl+D renommait visuellement dans un fichier. Pour un renommage sûr et global, place le curseur sur un symbole et appuie sur F2 (Renommer le symbole) : VS Code comprend le code et renomme toutes les références, y compris dans d'autres fichiers, sans toucher à un texte qui porterait le même nom par hasard. C'est une vraie refactorisation, pas un chercher-remplacer.

Les actions de code (Quick Fix)

Quand une ampoule 💡 apparaît à gauche d'une ligne (ou avec Ctrl+.), VS Code propose des actions de code : corriger une erreur, importer un symbole manquant, extraire une portion dans une fonction ou une variable, etc. C'est un assistant de transformation contextuel, alimenté par l'extension de langage. Avec un analyseur comme ESLint (cours Tests & qualité), beaucoup de problèmes se corrigent d'un clic.

Encore deux fonctions à connaître

  • les profils : tu peux créer plusieurs configurations complètes (extensions + réglages) et basculer de l'une à l'autre — par exemple un profil « web » et un profil « Python », pour ne pas tout charger en même temps ;
  • le développement à distance : des extensions permettent d'éditer du code qui vit ailleurs (sur un serveur via SSH, dans un conteneur Docker, dans WSL sous Windows, ou dans un codespace) tout en gardant l'interface locale. L'éditeur est local, le code et son exécution sont distants.

Glossaire

Point d'arrêt (breakpoint)
Marque posée sur une ligne (clic dans la gouttière) qui met l'exécution en pause avant de l'exécuter.
Point d'arrêt conditionnel
Point d'arrêt qui ne suspend l'exécution que si une condition est vraie (ex. i === 499).
Logpoint (point de journalisation)
Variante qui affiche un message dans la console sans interrompre l'exécution.
Pas à pas (step over / into)
F10 exécute la ligne sans entrer dans les fonctions ; F11 y entre.
Pile d'appels (call stack)
Suite des fonctions qui ont mené au point courant, lisible pendant la pause.
launch.json
Fichier .vscode/ décrivant une ou plusieurs configurations de débogage du projet.
Renommer le symbole (F2)
Refactorisation qui met à jour toutes les références réelles d'un symbole, sans toucher les homonymes.
Action de code (Quick Fix)
Correction ou transformation contextuelle proposée par l'ampoule ou Ctrl+. (importer, extraire…).

Récap et vérification

  • Un point d'arrêt (clic dans la gouttière) met le programme en pause pour inspecter son état — mieux que les console.log.
  • F5 lance/continue ; F10/F11 avancent pas à pas ; on lit Variables, Espions et Pile d'appels.
  • launch.json enregistre une ou plusieurs configurations de débogage pour le projet.
  • F2 renomme un symbole partout ; l'ampoule (Ctrl+.) propose des actions de code (corriger, importer, extraire).

Vérifie ta compréhension

  1. Pourquoi un point d'arrêt vaut-il mieux que des console.log pour comprendre un bug ?
  2. Quelle est la différence entre F10 et F11 pendant le débogage ?
  3. En quoi F2 diffère-t-il d'un simple chercher-remplacer ?

Exercices

Exercice 1Échauffement

Une fonction renvoie un résultat faux. Décris les étapes pour l'examiner avec le débogueur plutôt qu'avec des console.log.

Voir une solution

1) Pose un point d'arrêt en cliquant dans la gouttière, sur la première ligne intéressante de la fonction. 2) Lance le débogage avec F5 : l'exécution s'arrête à cette ligne. 3) Lis le panneau Variables (ou survole les variables dans le code) pour vérifier les valeurs d'entrée. 4) Avance avec F10 ligne par ligne, en observant comment les valeurs évoluent ; entre dans une sous-fonction suspecte avec F11. 5) Repère la ligne où une valeur devient incorrecte : tu as trouvé l'origine du bug, sans avoir modifié le code.

Exercice 2Application

Un bug ne se produit qu'à la 500ᵉ itération d'une boucle. Comment éviter d'appuyer 500 fois sur « Continuer » ?

Voir une solution

Utilise un point d'arrêt conditionnel. Pose un point d'arrêt dans la boucle, puis clic droit dessus → Modifier le point d'arrêt, et saisis une condition sur le compteur, par exemple i === 499 (ou la condition qui caractérise le cas fautif). Le débogueur ne s'arrêtera qu'à ce moment précis. Variante : un logpoint affichera la valeur de i et d'autres variables à chaque tour sans interrompre, pour observer la progression dans la console de débogage.

Exercice 3Défi

Tu dois renommer une fonction calc en calculerTotal dans un projet de plusieurs fichiers, où le mot « calc » apparaît aussi dans des commentaires et des chaînes. Quelle méthode choisis-tu, et pourquoi pas un chercher-remplacer ?

Voir une solution

Place le curseur sur le nom de la fonction calc et appuie sur F2 (Renommer le symbole), tape calculerTotal, valide. VS Code, qui comprend le code, met à jour la déclaration et toutes les références réelles de cette fonction, dans tous les fichiers — sans toucher au mot « calc » présent dans un commentaire, une chaîne de caractères ou une autre variable homonyme. Un chercher-remplacer textuel (Ctrl+Shift+H), lui, remplacerait aveuglément toutes les occurrences du texte, y compris celles qui n'ont rien à voir, et casserait potentiellement le code ou la documentation. F2 est donc à la fois plus sûr et plus complet : c'est l'outil de refactorisation adapté.
