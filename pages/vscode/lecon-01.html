Module 1 · Prendre en main — Leçon 01

Découvrir VS Code et son interface

~25 min Débutant Aucun prérequis

À la fin de cette leçon, tu sauras

  • dire ce qu'est VS Code et à quoi il sert ;
  • nommer les cinq grandes zones de l'interface ;
  • expliquer qui fait quoi dans chacune ;
  • te repérer pour la suite du cours.
Sommaire de la leçon

Visual Studio Code (abrégé VS Code) est un éditeur de code gratuit, multiplateforme (Windows, macOS, Linux) et extensible, développé par Microsoft. Ce n'est pas un simple bloc-notes : il comprend le code que tu écris, le colore, signale les erreurs, t'aide à compléter, lance un terminal, gère les versions avec Git… C'est aujourd'hui l'outil de travail le plus répandu chez les développeurs. Avant d'apprendre à s'en servir, il faut savoir qui fait quoi à l'écran : c'est tout l'objet de cette première leçon.

Éditeur, pas « IDE »

On parle souvent de VS Code comme d'un éditeur de code plutôt que d'un environnement de développement intégré (IDE) complet : il démarre léger et rapide, puis on l'enrichit avec des extensions selon le langage. C'est ce qui le rend à la fois simple pour débuter et puissant pour les pros.

Cas réel — l'éditeur le plus utilisé au monde

Lancé par Microsoft en 2015, VS Code s'est imposé en quelques années : dans l'enquête annuelle de Stack Overflow auprès de dizaines de milliers de développeurs, il est cité comme l'environnement le plus utilisé par près de trois développeurs sur quatre, tous langages confondus. La raison de ce succès ? Exactement ce qu'on découvre ici : une interface claire et légère, la même sur Windows, macOS et Linux, que l'on enrichit ensuite d'extensions selon ses besoins.

Une fenêtre, cinq zones

Quand tu ouvres VS Code, l'écran se découpe toujours de la même façon. Mémorise ce schéma : tout le reste du cours s'y réfère.

Cinq zones, cinq rôles : A la barre d'activité, B la barre latérale, C l'éditeur, D le panneau, E la barre d'état. Voyons-les une par une.

A — La barre d'activité (Activity Bar)

C'est la fine colonne d'icônes tout à gauche. Chaque icône ouvre une vue différente dans la barre latérale. Tu y cliques pour changer de mode de travail :

  • Explorateur (deux feuilles) : les fichiers et dossiers de ton projet.
  • Rechercher (loupe) : chercher (et remplacer) du texte dans tout le projet.
  • Contrôle de source (branche) : les modifications Git, les commits (voir leçon 04).
  • Exécuter et déboguer (triangle + insecte) : lancer et déboguer un programme (leçon 06).
  • Extensions (carrés) : installer des modules pour ajouter des langages et des outils (leçon 05).

Tout en bas de cette barre se trouve la roue dentée des réglages (Manage), qui ouvre les paramètres, les raccourcis et les thèmes.

B — La barre latérale (Side Bar)

Juste à droite de la barre d'activité, c'est la zone large qui affiche le contenu de la vue choisie. Si tu as cliqué sur l'Explorateur, elle montre l'arborescence de ton dossier ; sur Recherche, elle montre le champ de recherche et les résultats ; etc. Autrement dit : la barre d'activité (A) choisit, la barre latérale (B) affiche.

On peut la masquer pour gagner de la place avec Ctrl+B (un raccourci à retenir tôt), puis la rouvrir avec le même raccourci.

Astuce

Sur Windows et Linux, le raccourci de menu s'écrit avec Ctrl. Sur macOS, remplace-le par Cmd (la touche ⌘). Ainsi Ctrl+B devient Cmd+B. Le cours note les raccourcis Windows/Linux ; pense à cette équivalence si tu es sur Mac.

C — L'éditeur (Editor)

C'est la grande zone centrale, là où tu écris ton code. Chaque fichier ouvert apparaît dans un onglet en haut. Quelques points clés :

  • tu peux ouvrir plusieurs onglets et passer de l'un à l'autre ;
  • tu peux fractionner l'éditeur (le couper en deux ou trois colonnes) pour voir deux fichiers côte à côte : Ctrl+\ ;
  • un onglet dont le nom est en italique est en mode « aperçu » : il sera remplacé au prochain fichier ouvert tant que tu n'y as pas écrit (double-clique son onglet pour le « fixer ») ;
  • un point à la place de la croix de fermeture signale un fichier non enregistré.

D — Le panneau (Panel)

En bas de l'éditeur, le panneau regroupe des outils qui travaillent avec ton code. On l'ouvre/ferme avec Ctrl+J. Ses onglets principaux :

  • Terminal : une vraie ligne de commande intégrée, dans le dossier du projet (leçon 04).
  • Problèmes : la liste des erreurs et avertissements détectés dans tes fichiers.
  • Sortie (Output) : les messages des outils et extensions.
  • Console de débogage : pour inspecter un programme en cours de débogage (leçon 06).

E — La barre d'état (Status Bar)

C'est la fine bande colorée tout en bas de la fenêtre. Elle résume l'état du fichier et du projet, et beaucoup de ses éléments sont cliquables :

  • à gauche : la branche Git active et le nombre de modifications, le compte d'erreurs (✗) et d'avertissements (⚠).
  • à droite : la position du curseur (ligne/colonne), l'indentation (espaces/tabulations), l'encodage (UTF-8…), la fin de ligne (LF/CRLF) et le langage du fichier (JavaScript, Python…).

Cliquer sur le langage, par exemple, permet d'en changer ; cliquer sur la branche permet de basculer de branche. La barre d'état n'est donc pas qu'un affichage : c'est aussi un jeu de raccourcis.

La palette de commandes

Il existe une sixième « zone » qui apparaît à la demande : la palette de commandes, ouverte par Ctrl+Shift+P. C'est une barre de recherche universelle pour toutes les actions de VS Code. On lui consacre la leçon 03 ; retiens dès maintenant ce raccourci, c'est le plus important de tous.

Glossaire

Éditeur de code
Logiciel spécialisé dans l'écriture de code : coloration, complétion, détection d'erreurs. Plus léger qu'un IDE complet.
Extension
Module que l'on installe pour ajouter un langage ou un outil à VS Code (leçon 05). C'est ce qui rend l'éditeur extensible.
Barre d'activité
Colonne d'icônes tout à gauche ; chaque icône sélectionne une vue affichée dans la barre latérale.
Barre latérale
Zone à droite de la barre d'activité qui affiche le contenu de la vue active (arborescence, recherche, Git…).
Panneau
Zone sous l'éditeur regroupant le terminal, la liste des problèmes, la sortie et la console de débogage.
Barre d'état
Bande tout en bas résumant l'état du projet (branche Git, erreurs, langage, position du curseur) ; ses éléments sont cliquables.
Palette de commandes
Barre de recherche universelle (Ctrl+Shift+P) donnant accès à toutes les actions de VS Code et de ses extensions.
Vue
Mode de travail ouvert par une icône de la barre d'activité (Explorateur, Recherche, Contrôle de source…).

Récap et vérification

  • VS Code est un éditeur de code gratuit, multiplateforme et extensible.
  • L'interface a cinq zones : barre d'activité (choisir une vue), barre latérale (l'afficher), éditeur (écrire), panneau (terminal, problèmes…), barre d'état (état + raccourcis).
  • La barre d'activité choisit la vue, la barre latérale affiche son contenu.
  • Ctrl+Shift+P ouvre la palette de commandes, l'accès universel aux actions.

Vérifie ta compréhension

  1. Quelle est la différence de rôle entre la barre d'activité et la barre latérale ?
  2. Où regardes-tu pour savoir sur quelle branche Git tu es ?
  3. À quoi sert le panneau, et comment l'ouvrir ?

Exercices

Exercice 1Échauffement

Cite les cinq grandes zones de l'interface de VS Code et, en une phrase, le rôle de chacune.

Voir une solution

1) Barre d'activité : les icônes à gauche, pour choisir une vue (fichiers, recherche, Git, débogage, extensions). 2) Barre latérale : affiche le contenu de la vue choisie. 3) Éditeur : la zone centrale où l'on écrit le code, en onglets. 4) Panneau : en bas, le terminal, les problèmes, la sortie, la console de débogage. 5) Barre d'état : tout en bas, l'état du fichier et du projet (branche Git, erreurs, langage, position du curseur…).

Exercice 2Application

Tu ouvres un fichier : son onglet est en italique, et un petit point remplace la croix de fermeture. Que t'apprennent ces deux signes ?

Voir une solution

L'italique indique que l'onglet est en mode aperçu : il sera remplacé par le prochain fichier que tu ouvres, tant que tu n'y as pas tapé de texte. Pour le conserver, double-clique l'onglet (ou modifie le fichier). Le point à la place de la croix signale que le fichier contient des modifications non enregistrées : enregistre avec Ctrl+S.

Exercice 3Défi

Un ami débute et trouve l'écran « chargé ». Il veut écrire son code sur toute la largeur, sans la liste des fichiers. Quels éléments peut-il masquer, et comment ? Comment les retrouver ?

Voir une solution

Il peut masquer la barre latérale avec Ctrl+B (l'éditeur s'élargit aussitôt) ; le même raccourci la fait revenir. Il peut aussi fermer le panneau du bas avec Ctrl+J. Pour aller plus loin, le mode Zen (via la palette de commandes Ctrl+Shift+P → « Zen ») masque presque toute l'interface pour ne garder que le texte ; Échap Échap en sort. Aucun de ces éléments n'est supprimé : ils sont seulement cachés, et reviennent d'un raccourci.
