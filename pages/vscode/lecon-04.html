Module 2 · Outils intégrés — Leçon 04

Le terminal intégré et Git

~29 min Débutant Notions de Git utiles

À la fin de cette leçon, tu sauras

  • ouvrir et utiliser le terminal intégré ;
  • gérer plusieurs terminaux et les fractionner ;
  • faire un commit depuis la vue Contrôle de source ;
  • lire les différences et changer de branche.
Sommaire de la leçon

Deux outils intégrés à VS Code changent radicalement le confort de travail : le terminal, qui évite d'aller-retour vers une fenêtre séparée, et la vue Contrôle de source, qui rend Git visuel sans pour autant le remplacer. Cette leçon montre qui fait quoi entre ces deux-là, et comment les utiliser ensemble.

Ouvrir le terminal intégré

Le terminal s'ouvre dans le panneau du bas (leçon 01) avec Ctrl+ù sur un clavier français (le raccourci officiel est Ctrl+`, l'accent grave). Il démarre dans le dossier du projet ouvert : tu peux taper tes commandes tout de suite, sans cd.

C'est un vrai terminal : il utilise le shell de ton système (PowerShell ou cmd sur Windows, bash/zsh sur macOS et Linux). Tu peux en choisir un autre via la petite flèche à côté du +.

Plusieurs terminaux à la fois

On a souvent besoin de deux terminaux : un pour lancer le serveur, un autre pour taper des commandes Git. VS Code le permet :

  • le + crée un nouveau terminal ; la liste à droite permet de basculer entre eux ;
  • l'icône « fractionner » (Split) affiche deux terminaux côte à côte ;
  • la corbeille ferme le terminal actif.

Astuce : tu peux nommer un terminal (clic droit → Renommer) pour t'y retrouver, par exemple « serveur » et « git ».

Cliquer un chemin ou une erreur

Dans le terminal, VS Code rend les chemins de fichiers cliquables (Ctrl+clic ouvre le fichier), et beaucoup d'erreurs de compilation renvoient directement à la ligne fautive. Le terminal n'est donc pas isolé : il est relié à ton éditeur.

Attention : « commande introuvable » après une installation

Le terminal hérite du PATH au moment où il s'ouvre. Si tu installes un outil (Node, Python, la CLI de Git…) alors que VS Code est déjà lancé, le terminal ouvert ne le connaît pas encore : tu obtiens « command not found ». La solution : ferme ce terminal et ouvre-en un nouveau (ou recharge la fenêtre), pour qu'il reprenne le PATH à jour.

La vue Contrôle de source (Git)

Clique l'icône Contrôle de source dans la barre d'activité (la branche), ou Ctrl+Shift+G. Si ton projet est un dépôt Git (cours Git), tu y vois la liste des fichiers modifiés. Chaque fichier porte une lettre : M (modifié), U (non suivi/nouveau), D (supprimé).

Faire un commit y est visuel :

  • survole un fichier et clique le + pour l'indexer (l'ajouter au prochain commit) ; le + en tête de section indexe tout ;
  • écris un message de commit dans le champ en haut ;
  • clique Valider (Commit). Le bouton « Synchroniser » pousse ensuite vers le dépôt distant.

Les deux approches coexistent : tu peux faire la même chose dans le terminal intégré. L'interface visuelle est pratique pour voir l'état ; la ligne de commande reste reine pour les opérations fines.

Piège fréquent

Cliquer Valider n'envoie rien sur le dépôt distant. Un commit est local : il enregistre dans le dépôt de ta machine, et c'est Synchroniser (git push) qui publie. Beaucoup croient leur travail sauvegardé après un commit et perdent tout avec leur poste. La barre d'état affiche justement le nombre de commits en attente d'envoi : prends le réflexe de la regarder.

Lire une différence (diff)

Clique un fichier modifié dans la vue Contrôle de source : VS Code ouvre une vue côte à côte (l'ancien à gauche, le nouveau à droite) qui surligne précisément ce qui a changé, ligne par ligne. C'est le meilleur moyen de se relire avant de valider un commit.

Sans même ouvrir cette vue, l'éditeur signale les changements dans la gouttière (à gauche des numéros de ligne) : une barre verte pour une ligne ajoutée, bleue pour une ligne modifiée, un chevron rouge pour une suppression. Clique cette marque pour voir, annuler ou indexer le changement directement.

Cas réel — le diff qui évite une bêtise

Avant de valider, un développeur clique chacun de ses fichiers modifiés pour relire le diff côte à côte. Bien lui en prend : sur la droite, surligné, il retrouve un console.log("DEBUG ici") laissé pendant ses essais, et une clé d'API collée en dur « juste pour tester ». Il les retire avant de committer. Cette relecture de deux minutes, offerte par la vue Contrôle de source, évite chaque jour à des équipes entières d'envoyer du code de débogage — ou pire, un secret — dans l'historique du projet.

Indexer seulement quelques lignes

Le + indexe un fichier entier, mais on veut parfois ne committer qu'une partie de ses changements. Ouvre le diff, sélectionne les lignes voulues, puis, dans le menu du survol ou via la palette, choisis « Indexer la sélection » (Stage Selected Ranges). C'est l'équivalent visuel de git add -p : un commit propre, qui ne mélange pas deux sujets.

Changer de branche

Le nom de la branche active est affiché en bas à gauche, dans la barre d'état (leçon 01). Clique-le : une liste s'ouvre pour basculer vers une autre branche ou en créer une nouvelle — l'équivalent visuel de git switch. La même barre d'état affiche une flèche de synchronisation avec le nombre de commits à envoyer/recevoir.

Pour aller plus loin : GitLens

La vue intégrée couvre le quotidien. Pour aller plus loin, l'extension GitLens (leçon 08) superpose au code l'auteur et la date de chaque ligne (blame en ligne), un historique de fichier navigable et des comparaisons de branches visuelles. Utile quand la question n'est plus « qu'ai-je changé ? » mais « qui a écrit cette ligne, et pourquoi ? ».

Glossaire

Terminal intégré
Ligne de commande incluse dans VS Code (Ctrl+`), ouverte dans le dossier du projet.
Shell
Programme qui interprète les commandes du terminal (PowerShell, cmd, bash, zsh selon le système).
Contrôle de source
Vue (Ctrl+Shift+G) qui rend Git visuel : fichiers modifiés, indexation, commits, branches.
Indexer (stage)
Ajouter un fichier au prochain commit ; le + de la vue équivaut à git add.
Commit
Enregistrement d'un ensemble de modifications dans l'historique, accompagné d'un message.
Diff
Vue côte à côte comparant l'ancienne et la nouvelle version d'un fichier, changements surlignés.
Gouttière
Bande à gauche des numéros de ligne où l'éditeur signale les lignes ajoutées, modifiées ou supprimées.
Branche
Ligne de développement indépendante ; la branche active s'affiche dans la barre d'état et s'y change d'un clic.

Récap et vérification

  • Le terminal intégré (Ctrl+`) s'ouvre dans le dossier du projet ; on peut en avoir plusieurs et les fractionner.
  • La vue Contrôle de source (Ctrl+Shift+G) rend Git visuel : indexer, écrire un message, valider, synchroniser.
  • Cliquer un fichier modifié ouvre un diff côte à côte ; la gouttière signale les changements ligne par ligne.
  • La branche active, dans la barre d'état, sert à basculer ou à créer une branche.

Vérifie ta compréhension

  1. Dans quel dossier s'ouvre le terminal intégré, et pourquoi est-ce pratique ?
  2. Quelles sont les trois étapes pour faire un commit depuis la vue Contrôle de source ?
  3. Comment relire précisément ce qu'on a changé dans un fichier avant de valider ?

Exercices

Exercice 1Échauffement

Tu veux lancer un serveur de développement et garder une ligne de commande libre pour Git, sans fermer l'un pour l'autre. Comment organiser tes terminaux ?

Voir une solution

Ouvre un premier terminal (Ctrl+`) et lance le serveur (ex. npm run dev). Crée un second terminal avec le + (ou fractionne avec l'icône Split pour les voir côte à côte) et utilises-y Git. Tu peux renommer le premier « serveur » et le second « git » (clic droit → Renommer) pour t'y retrouver. Les deux tournent en parallèle, chacun dans le dossier du projet.

Exercice 2Application

Tu as modifié trois fichiers mais tu ne veux committer que deux d'entre eux. Comment procéder dans la vue Contrôle de source ?

Voir une solution

Ouvre la vue Contrôle de source (Ctrl+Shift+G). Survole les deux fichiers à inclure et clique leur + pour les indexer : ils passent dans la section « Modifications indexées ». Le troisième reste dans « Modifications », non indexé. Écris le message de commit, puis clique Valider : seuls les deux fichiers indexés entrent dans le commit. C'est l'équivalent visuel de git add sélectif suivi de git commit.

Exercice 3Défi

Tu te demandes si la vue Contrôle de source « remplace » Git, ou si tu dois encore connaître les commandes. Argumente.

Voir une solution

La vue Contrôle de source est une interface par-dessus Git, pas un remplacement : chaque action (indexer, valider, basculer de branche) correspond à une commande (git add, git commit, git switch). Elle excelle pour voir l'état et relire un diff avant de committer, ce qui prévient des erreurs. Mais les opérations plus fines (rebase interactif, résolution avancée de conflits, manipulation de l'historique, options précises) passent par la ligne de commande. La bonne posture : profiter de l'interface pour le quotidien et la lecture, tout en comprenant les commandes sous-jacentes pour ne jamais être bloqué. Le terminal intégré rend justement cette combinaison naturelle.
