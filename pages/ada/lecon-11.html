La POO : les types étiquetés

~40 min Avancé Prérequis : leçon 5

À la fin de cette leçon, tu sauras

  • déclarer un type étiqueté (tagged) ;
  • hériter en étendant un type et en redéfinissant ses primitives ;
  • utiliser le polymorphisme via 'Class et le dispatching ;
  • reconnaître les types abstraits et les interfaces.
Sommaire de la leçon

Un enregistrement (record) regroupe des données. La programmation orientée objet ajoute deux idées : l'héritage (bâtir un type à partir d'un autre) et le polymorphisme (traiter une famille de types de manière uniforme, chacun réagissant à sa façon). En Ada, tout cela repose sur les types étiquetés — une approche typiquement rigoureuse : les données restent séparées des opérations, et le choix entre appel figé et appel dynamique est explicite.

Le type étiqueté : un record qui connaît son type

Un type tagged est un enregistrement qui porte, à l'exécution, une étiquette (tag) identifiant son type réel. C'est cette étiquette qui rendra le polymorphisme possible plus loin.

La fonction Cri est une primitive d'Animal : elle est déclarée dans le même paquet et prend un Animal en premier paramètre. En Ada, les « méthodes » ne sont pas dans le record — ce sont des sous-programmes liés au type par le paquet.

L'héritage : étendre un type

On crée un nouveau type à partir d'un type étiqueté avec is new … with record : le descendant hérite des champs et des primitives de l'ancêtre, et peut en ajouter.

Le mot overriding n'est pas obligatoire, mais fortement recommandé : il demande au compilateur de vérifier qu'on redéfinit bien une primitive existante. Une faute de frappe dans le nom serait alors signalée, au lieu de créer silencieusement une nouvelle opération sans effet.

Le polymorphisme : 'Class et le dispatching

Voici le cœur de la POO. L'attribut Animal'Class désigne « n'importe quel type de la famille Animal » : un Chien, un Chat, ou tout futur descendant. Quand on appelle une primitive sur une valeur de type 'Class, Ada choisit la bonne version à l'exécution, d'après l'étiquette : c'est le dispatching dynamique.

La même ligne Cri (Bete) produit « Ouaf » ou « Miaou » selon ce qu'on lui passe. On peut ainsi ranger des Chien et des Chat dans un même tableau de Animal'Class et tous les faire crier d'une seule boucle.

Statique ou dynamique : un choix explicite

Point subtil mais essentiel : le dispatching n'a lieu que sur un type 'Class. Si le paramètre est déclaré du type précis Animal (sans 'Class), l'appel est lié à la compilation et appellera toujours Cri (Animal), même si la valeur venait d'un Chien. Ada te fait donc choisir : appel figé (rapide, prévisible) ou dispatché (polymorphe).

Types abstraits et interfaces

Un type abstract tagged ne peut pas être instancié directement : il sert de socle. Ses primitives peuvent être déclarées abstract, ce qui oblige chaque descendant à les définir.

Ada 2005 a ajouté les interfaces (type T is interface;) : des contrats purs, sans données, qu'un type peut implémenter — y compris plusieurs à la fois, ce qui donne une forme d'héritage multiple sûr.

Bonne pratique

Depuis Ada 2005, tu peux écrire Mon_Chien.Cri au lieu de Cri (Mon_Chien) : c'est la notation pointée, familière à qui vient de Java ou C++. Les deux formes sont équivalentes. Mets systématiquement le mot overriding (ou not overriding) devant tes primitives redéfinies : c'est un filet de sécurité gratuit contre les fautes de frappe.

Piège fréquent

Oublier le 'Class. Si tu écris procedure Traiter (A : Animal) au lieu de Animal'Class, l'appel ne dispatchera pas : tous les animaux seront traités comme de simples Animal, et pire, affecter un Chien à un Animal le tronque à sa partie ancêtre (perte des champs ajoutés). Règle : pour du polymorphisme, manipule toujours des 'Class (souvent via un pointeur access Animal'Class).

Cas réel — une famille d'équipements ferroviaires

Dans un poste d'aiguillage moderne, on modélise chaque équipement de la voie — signal, aiguille, circuit de voie, passage à niveau — comme un descendant d'un type étiqueté commun Equipement, doté de primitives Etat, Commander, Auto_Test. Le superviseur range tous les équipements dans une collection de Equipement'Class et lance leur auto-test d'une seule boucle, dispatchée : chaque type réagit selon sa nature. Ajouter demain un nouveau type d'équipement n'oblige à rien réécrire dans le superviseur — il suffit de fournir ses primitives. Cette extensibilité maîtrisée, avec vérification stricte à la compilation, est exactement ce qu'attend un système où une régression peut coûter des vies.

Pour aller plus loin

Le type Ada.Finalization.Controlled permet, par héritage, de définir des opérations Initialize, Adjust et Finalize appelées automatiquement à la construction, la copie et la destruction d'un objet : c'est le pendant Ada des constructeurs/destructeurs, utile pour libérer une ressource à coup sûr. Combiné aux interfaces et aux génériques (leçon 10), il permet de bâtir des composants réutilisables et sûrs.

Glossaire

Type étiqueté (tagged)
Enregistrement portant à l'exécution une étiquette de type ; base de l'héritage et du polymorphisme en Ada.
Étiquette (tag)
Marque interne identifiant le type réel d'une valeur ; c'est elle qui guide le dispatching.
Héritage
Création d'un type par extension d'un type étiqueté (is new … with record) : champs et primitives sont hérités.
Primitive
Sous-programme déclaré dans le paquet d'un type et prenant ce type en paramètre ; l'équivalent Ada d'une « méthode ».
overriding
Mot-clé optionnel qui demande au compilateur de vérifier qu'une primitive en redéfinit bien une héritée.
'Class
Attribut désignant la famille formée par un type étiqueté et tous ses descendants ; support du polymorphisme.
Dispatching dynamique
Choix, à l'exécution et d'après l'étiquette, de la primitive à appeler sur une valeur de type 'Class.
Type abstrait
Type abstract tagged non instanciable, servant de socle ; ses primitives abstract doivent être définies par les descendants.

Récap et vérification

  • Un type tagged porte une étiquette qui rend le polymorphisme possible.
  • On hérite avec is new … with record ; on redéfinit avec overriding.
  • Les primitives sont des sous-programmes du paquet, pas des membres du record.
  • T'Class déclenche le dispatching ; sans 'Class, l'appel est figé.
  • Types abstract et interface imposent des contrats aux descendants.
