Module 1 · Les bases d'Ada — Leçon 02

Types et fortes contraintes

~50 min Avancé Prérequis : leçon 1

À la fin de cette leçon, tu sauras

  • déclarer variables et constantes ;
  • utiliser les types scalaires et les plages ;
  • créer des sous-types et types contraints ;
  • comprendre pourquoi le typage fort prévient les bugs.
Sommaire de la leçon

Si un seul trait devait résumer Ada, ce serait son typage extrêmement fort. Là où d'autres langages laissent passer des mélanges douteux, Ada exige que chaque valeur ait un type précis, avec des contraintes que le programme s'engage à respecter. Cette rigueur, qui peut sembler tatillonne, est précisément ce qui attrape des bugs avant qu'ils ne deviennent des catastrophes. Cette leçon explore les types Ada et l'art de les contraindre.

Déclarer variables et constantes

En Ada, on déclare le nom, puis le type après deux-points, et éventuellement une valeur initiale avec :=. Une constante porte le mot constant.

Le type vient toujours après le nom, ce qui se lit naturellement : « Compteur, de type Integer ». Une constante ne peut plus changer : toute tentative de la modifier est rejetée à la compilation.

Les types scalaires de base

Ada fournit les types attendus : Integer (entiers), Float (réels), Boolean (vrai/faux), Character (caractère). Mais leur force vient de ce qu'on peut en dériver des versions sur mesure.

Les plages : contraindre les valeurs possibles

Voici une idée centrale d'Ada : un type peut imposer une plage de valeurs valides via range. Toute valeur hors de cette plage déclenche une erreur — à la compilation si elle est détectable, sinon à l'exécution.

En définissant Pourcentage comme « un entier de 0 à 100 », on rend impossible de lui assigner 150. Le type lui-même porte la règle métier : pas besoin de vérifications éparpillées dans le code, la contrainte est garantie partout.

Astuce — interroger un type

Un type Ada connaît ses propres bornes. Les attributs Pourcentage'First et Pourcentage'Last valent ici 0 et 100 ; for P in Pourcentage'Range loop parcourt toutes les valeurs valides. Écrire les boucles à partir du type plutôt qu'avec des 0 et 100 « en dur » rend le code robuste : si la borne change un jour, tout suit automatiquement.

Les sous-types

Un sous-type restreint un type existant sans en créer un nouveau, incompatible. Les valeurs d'un sous-type restent compatibles avec le type parent : pratique pour ajouter une contrainte tout en gardant l'interopérabilité.

Distinction subtile mais utile : un type distinct (type Compteur is range …) crée une famille séparée, qu'on ne peut pas mélanger par accident avec un autre ; un subtype ajoute juste une contrainte à un type existant.

Le typage fort en action

La grande force : Ada refuse de mélanger des types incompatibles sans conversion explicite. On ne peut pas additionner par mégarde des mètres et des secondes, ni un compteur de pommes et un compteur de poires.

Cette intransigeance a une histoire célèbre : nombre de bugs coûteux (y compris dans l'aérospatiale) venaient de la confusion entre unités. Le typage fort d'Ada rend ces erreurs structurellement impossibles. On notera aussi le _ dans 100_000 : un séparateur de milliers, purement visuel, pour la lisibilité.

Cas réel — la sonde perdue pour une histoire d'unités

En 1999, la sonde Mars Climate Orbiter de la NASA fut détruite en arrivant sur Mars. La cause : un logiciel fournissait une poussée en livres-force·seconde quand l'autre l'attendait en newtons·seconde. Aucune conversion : la trajectoire était fausse d'un facteur ~4,45, la sonde est passée trop bas et a brûlé. Coût : environ 125 millions de dollars. Avec le typage fort d'Ada, ces deux unités seraient des types distincts : les additionner sans conversion explicite aurait été refusé à la compilation, des mois avant le lancement.

Pièges fréquents

Piège fréquent

S'attendre à des conversions automatiques entre Integer et Float, ou entre deux types distincts. Ada exige une conversion explicite : Float (Mon_Entier) ou Integer (Mon_Reel). C'est délibéré : chaque conversion devient un choix visible dans le code, jamais un effet de bord silencieux qui fausserait un calcul.

Pour aller plus loin

Pour aller plus loin

Ada permet de définir des types numériques avec une précision garantie : type Tension is delta 0.01 range 0.0 .. 240.0; déclare un réel à pas fixe de 0,01 — crucial en embarqué où l'on maîtrise exactement la représentation. Cette finesse, rare dans les langages courants, explique l'adoption d'Ada là où chaque bit compte.

Antisèche

Glossaire

Typage fort
Chaque valeur a un type strict ; aucun mélange ni conversion implicite : le compilateur bloque les incompatibilités avant l'exécution.
type / subtype
type crée une famille séparée (incompatible avec les autres) ; subtype ajoute une contrainte à un type existant tout en restant compatible avec lui.
range (plage)
Contrainte qui borne les valeurs valides d'un type (ex. 0 .. 100) ; une valeur hors bornes est refusée.
constant
Qualificatif d'une déclaration dont la valeur ne peut plus changer après son initialisation.
Constraint_Error
Exception prédéfinie levée à l'exécution quand une valeur viole la contrainte de son (sous-)type.
Conversion explicite
Passage volontaire d'un type à un autre, écrit dans le code (Float (N)) ; Ada ne convertit jamais en douce.
Attribut ('First, 'Last, 'Range)
Information demandée à un type, comme sa borne inférieure, sa borne supérieure ou l'ensemble de ses valeurs.
Type à virgule fixe (delta)
Type réel à pas constant garanti, utile en embarqué pour maîtriser exactement la représentation des nombres.

Récap et vérification

  • Déclaration : Nom : Type := Valeur; ; constant pour l'immuable.
  • Les plages (range) contraignent les valeurs valides : la règle est dans le type.
  • Sous-type = contrainte compatible ; type distinct = famille séparée.
  • Typage fort : pas de mélange ni de conversion implicite ; conversions explicites obligatoires.
