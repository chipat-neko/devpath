Les paquets et la modularité

~55 min Avancé Prérequis : leçon 5

À la fin de cette leçon, tu sauras

  • séparer spécification et corps d'un paquet ;
  • exposer une interface claire ;
  • encapsuler avec les types privés ;
  • réutiliser via with et use.
Sommaire de la leçon

Un logiciel critique compte souvent des centaines de milliers de lignes. Pour rester maîtrisable, il faut le découper en modules indépendants, aux frontières nettes. En Ada, ce module s'appelle le paquet (package), et c'est l'unité d'organisation reine du langage. Sa grande idée : séparer ce qu'un module offre (sa spécification) de la façon dont il le réalise (son corps). Cette leçon t'apprend à structurer un vrai projet.

Spécification et corps : deux faces, un module

Un paquet Ada se compose de deux parties, souvent dans deux fichiers :

  • la spécification (fichier .ads) : l'interface publique — ce que les autres peuvent utiliser ;
  • le corps (fichier .adb) : l'implémentation — le code interne, caché.

Qui utilise Maths ne voit que la spécification : les signatures, pas le code. On peut réécrire entièrement le corps sans gêner personne, tant que l'interface tient. C'est l'encapsulation au niveau du module.

Utiliser un paquet : with et use

Pour employer un paquet, on le rend visible avec with. On peut ajouter use pour éviter de préfixer chaque nom.

Bonne pratique courante en logiciel critique : utiliser with seul et garder le préfixe (Maths.Carre), car cela montre d'où vient chaque nom. Le use allège, mais peut masquer l'origine ; on le réserve aux paquets très courants.

Encapsuler avec les types privés

La spécification peut déclarer un type privé : les utilisateurs savent qu'il existe et peuvent s'en servir via les opérations offertes, mais ne voient pas sa structure interne. C'est le secret d'une véritable abstraction.

Hors du paquet, on ne peut pas écrire C.Solde_Interne : on est obligé de passer par Deposer et Solde. Impossible donc de corrompre l'état en touchant directement aux entrailles. Le type est une boîte noire dont seules les opérations autorisées ouvrent l'accès.

Pourquoi cette séparation est précieuse

Cette discipline apporte trois bénéfices décisifs pour les grands systèmes :

  • compilation séparée : modifier un corps ne force pas à recompiler tout ce qui en dépend ;
  • contrats clairs : la spécification est le contrat entre l'auteur et les utilisateurs ;
  • sûreté : ce qui est privé ne peut pas être mal employé de l'extérieur.

Cas réel — changer l'intérieur sans casser l'extérieur

Une équipe stocke un identifiant client comme un simple Integer, exposé via un type privé Id_Client et ses opérations (Creer, Formater, Egal). Des années plus tard, il faut passer à un identifiant plus riche (préfixe régional + numéro de série). Parce que le type était private et que tout le code passait par les opérations, changer la représentation interne n'a demandé de retoucher qu'un seul fichier : le corps du paquet. Aucun des dizaines de modules clients n'a bougé. C'est le retour sur investissement concret de l'encapsulation : le coût d'un changement reste local au lieu de se propager dans tout le projet.

Pièges fréquents

Piège fréquent

Oublier qu'une signature déclarée dans la spécification doit correspondre exactement à celle du corps : même nom, mêmes types, mêmes modes de paramètres. La moindre divergence est rejetée à la compilation. C'est contraignant, mais c'est ce qui garantit que l'interface promise est bien celle qui est livrée — aucune dérive silencieuse possible entre ce qu'on annonce et ce qu'on fait.

Pour aller plus loin

Pour aller plus loin

Les paquets peuvent être génériques : paramétrés par un type, ils se réutilisent pour n'importe quel élément, comme un paquet « pile » qui marche aussi bien pour des entiers que pour des records. C'est l'équivalent Ada des templates ou generics, et le fondement des bibliothèques de conteneurs standard (Ada.Containers). On retrouve la généricité, mais avec la sûreté de type d'Ada.

Glossaire

Paquet (package)
Unité de modularité d'Ada : regroupe types, variables et sous-programmes derrière une interface.
Spécification (.ads)
Partie publique d'un paquet : ce qu'il offre (types, en-têtes de sous-programmes), sans le code.
Corps (.adb)
Partie cachée d'un paquet : l'implémentation réelle des sous-programmes déclarés dans la spécification.
with
Clause qui déclare une dépendance vers un paquet et rend ses éléments publics utilisables.
use
Clause qui rend les noms d'un paquet accessibles sans préfixe ; à réserver aux paquets très courants.
Type privé (private)
Type dont le nom est public mais dont la structure interne est invisible de l'extérieur.
Encapsulation
Principe consistant à cacher les détails internes derrière une interface stable, protégeant les invariants.
Compilation séparée
Possibilité de recompiler un corps sans recompiler tout ce qui dépend seulement de sa spécification.

Récap et vérification

  • Le paquet sépare spécification (.ads, l'interface) et corps (.adb, l'implémentation).
  • with rend un paquet visible ; use évite le préfixe (à employer avec parcimonie).
  • Un type privé cache sa structure : accès uniquement via les opérations offertes.
  • Bénéfices : compilation séparée, contrats clairs, sûreté par encapsulation.

Vérifie ta compréhension

  1. Que contient la spécification d'un paquet, par opposition au corps ?
  2. Qu'apporte un type private ?
  3. À quoi sert le mot-clé with ?

Exercice 3Défi

Explique pourquoi, avec un type Compte privé, du code externe ne peut pas écrire C.Solde_Interne := -1000;.

Voir une solution

Parce que la structure du type Compte est déclarée dans la partie private du paquet : elle est invisible hors de ce paquet. Le code externe ne connaît que le nom du type et les opérations publiques (Ouvrir, Deposer, Solde). Tenter d'accéder à Solde_Interne de l'extérieur est rejeté à la compilation, ce qui empêche de placer le compte dans un état incohérent (comme un solde négatif imposé directement).
