Module 4 · Ada : aller plus loin — Leçon 10

La généricité : un code, tous les types

~38 min Avancé Prérequis : leçon 6

À la fin de cette leçon, tu sauras

  • écrire une unité générique (procédure ou paquet) ;
  • déclarer des paramètres formels de type, d'objet et de sous-programme ;
  • instancier un générique pour un type concret ;
  • reconnaître les génériques dans la bibliothèque standard.
Sommaire de la leçon

Tu as besoin d'une pile d'entiers. Puis d'une pile de flottants. Puis d'une pile de chaînes. Vas-tu copier-coller le même code trois fois ? En Ada, non : on écrit le composant une seule fois, en laissant le type « en blanc », et on le réutilise pour chaque type voulu — sans jamais renoncer au typage fort. C'est la généricité, et Ada l'a proposée dès 1983, bien avant les templates du C++ ou les génériques de Java.

Le problème : dupliquer, c'est trahir

Sans généricité, un composant « pile » pour les entiers et un autre pour les flottants seraient deux fichiers presque identiques. Chaque correction de bug devrait être reportée dans les deux — et tôt ou tard, on en oublie un. La règle d'or du logiciel fiable est DRY (Don't Repeat Yourself) : une idée, un seul endroit.

Un générique est un moule : un patron paramétré à partir duquel le compilateur fabrique, à la demande, une version pour un type précis. Le moule lui-même ne s'exécute pas ; ce sont ses instances qui vivent dans le programme.

Écrire une unité générique

Une unité générique se compose de deux parties : une partie formelle introduite par le mot generic (la liste des paramètres), suivie de l'unité elle-même (procédure, fonction ou paquet). Voici le plus simple des génériques : échanger deux valeurs de n'importe quel type.

Le mot private ici signifie : « je ne suppose rien de ce type, sauf qu'on peut l'affecter (:=) et le comparer par égalité ». C'est le contrat minimal. La procédure Echanger n'a pas besoin d'en savoir plus.

Les trois familles de paramètres formels

Un générique peut recevoir trois sortes de paramètres, tous explicites : c'est la marque de fabrique d'Ada. Rien n'est deviné, tout est déclaré.

  • Un type — avec un degré de contrainte au choix : type T is private; (quelconque), type T is (<>) (type discret : entier ou énumération), type T is range <>; (entier signé), type T is digits <>; (flottant).
  • Un objet — une valeur, par exemple une capacité : Capacite : Positive;.
  • Un sous-programme — une opération que l'unité pourra appeler : with function "<" (A, B : Element) return Boolean;.

Ce troisième cas est décisif : si ton générique doit trier, il lui faut une relation d'ordre. Plutôt que de la supposer, Ada demande qu'on la fournisse à l'instanciation. Le contrat est complet et lisible.

Un paquet générique complet : la pile bornée

Assemblons tout dans un paquet réutilisable : une pile de taille bornée, paramétrée par le type de ses éléments et par sa capacité.

Le corps (package body Piles) implémente les opérations sur ce Sommet. Peu importe ici : l'essentiel est que ce code n'est écrit qu'une fois et fonctionnera pour tous les types.

Instancier : du moule à l'objet utilisable

Un générique ne s'utilise pas directement : on l'instancie avec le mot new, en fournissant les paramètres réels. On obtient alors une unité ordinaire, comme si on l'avait écrite à la main.

À partir de là, Pile_Entiers est une pile d'entiers pleinement typée : lui empiler un Float serait refusé à la compilation. La généricité ne sacrifie rien à la sûreté ; c'est même l'inverse du « tout est objet » dynamique d'autres langages.

Bonne pratique

Choisis le paramètre de type le plus précis possible. Si ton générique fait des additions, écris type T is range <>; (entier) plutôt que is private : le contrat devient plus clair, et le compilateur t'offre gratuitement les opérations arithmétiques du type. Un formel trop large oblige à tout passer « à la main ».

Piège fréquent

Avec type Element is private, tu ne peux ni comparer avec <, ni afficher, ni additionner tes éléments : le type est « opaque ». Si l'unité en a besoin, il faut passer ces opérations comme sous-programmes formels (with function …). Oublier ce paramètre est l'erreur classique du débutant en génériques : le compilateur refuse alors le corps, faute de savoir comparer.

Cas réel — la bibliothèque standard est faite de génériques

Quand tu veux une liste dynamique en Ada, tu écris package Entiers is new Ada.Containers.Vectors (Positive, Integer);. Toute la bibliothèque de conteneurs standard (Vectors, Doubly_Linked_Lists, Hashed_Maps, Ordered_Sets…) est un ensemble de paquets génériques que tu instancies pour tes propres types. Même Ada.Text_IO repose sur des génériques : Ada.Sequential_IO et Ada.Direct_IO, que tu instancies avec le type des données à lire ou écrire. Dans l'avionique, on instancie une fois pour toutes des tampons circulaires bornés génériques, réutilisés dans des dizaines de sous-systèmes — un seul code audité, zéro duplication.

Pour aller plus loin

Contrairement aux templates du C++, un générique Ada se compile indépendamment de ses instanciations : le contrat formel est vérifié une fois, sur le moule, ce qui donne des messages d'erreur nets au lieu des « pavés » d'erreurs de templates. On peut aussi grouper des paramètres formels récurrents dans un paquet-signature réutilisable, et imbriquer les génériques (instancier un générique à l'intérieur d'un autre).

Glossaire

Généricité
Capacité d'écrire un composant paramétré par des types (ou des valeurs, ou des opérations), réutilisable sans duplication ni perte de typage.
Unité générique
Procédure, fonction ou paquet précédé d'une partie generic ; c'est un « moule » qui ne s'exécute pas tel quel.
Paramètre formel
Élément déclaré dans la partie generic (type, objet ou sous-programme) que l'unité a le droit d'utiliser.
Type formel
Paramètre de type d'un générique ; sa forme (is private, range <>…) fixe ce qu'on peut en faire.
Sous-programme formel
Opération (fonction ou procédure) exigée par le générique et fournie lors de l'instanciation, via with function/procedure.
Instanciation
Création, avec new, d'une unité concrète à partir d'un générique en fournissant les paramètres réels.
Contrat
Ensemble des exigences explicites d'un générique (types, valeurs, opérations) ; en Ada, rien n'est implicite.
Ada.Containers
Bibliothèque standard de conteneurs (vecteurs, listes, dictionnaires…) fournis sous forme de paquets génériques à instancier.

Récap et vérification

  • Un générique est un moule : on écrit le code une fois, on l'instancie pour chaque type.
  • Trois familles de paramètres formels : type, objet, sous-programme — tous explicites.
  • Un type formel is private n'offre que l'affectation et l'égalité ; les autres opérations se passent en paramètre.
  • On instancie avec new, et le résultat est une unité pleinement et fortement typée.
  • Toute la bibliothèque standard (conteneurs, E/S typées) repose sur des génériques.

Exercices

Exercice 1Échauffement

Écris la partie generic d'une fonction Maximum qui compare deux valeurs d'un type Element. De quel paramètre formel a-t-elle besoin en plus du type ?

Voir une solution

Comme Element est private, il faut fournir la comparaison > en sous-programme formel : sans elle, la fonction ne saurait pas départager X et Y.

Exercice 3Défi

Explique pourquoi ce type formel est un meilleur choix que is private pour un générique de calcul de somme : type Nombre is range <>;

Voir une solution

Avec type Nombre is range <>;, le paramètre est forcément un type entier : le générique reçoit gratuitement +, 0 et l'ordre, sans qu'on ait à les passer en sous-programmes formels. Le contrat est plus précis (on ne pourra pas l'instancier avec un type non numérique) et le code plus court. is private obligerait à fournir l'addition et la valeur nulle à la main.
