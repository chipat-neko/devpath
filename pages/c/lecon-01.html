Module 01 · Les bases du C — Leçon 01

Découvrir le C et la compilation

~31 min Avancé Des bases en programmation aident

À la fin de cette leçon, tu sauras

  • comprendre ce qu'est le C et pourquoi c'est un langage compilé proche de la machine ;
  • maîtriser la chaîne de compilation et compiler avec gcc et ses options (-Wall -Wextra -std=c17 -g) ;
  • écrire un premier programme avec main, printf et les bons spécificateurs de format ;
  • lire les warnings du compilateur comme un garde-fou et corriger ton code en conséquence.
Sommaire de la leçon

Bienvenue dans le monde du C. C'est un langage ancien (1972) mais toujours incontournable : il est compilé, bas niveau et très proche de la machine. Quand tu écris du C, tu manipules directement la mémoire et tu obtiens un fichier exécutable autonome, sans machine virtuelle ni interpréteur entre ton code et le processeur.

Dans cette première leçon, tu vas découvrir ce qu'est réellement le C, comprendre comment ton fichier source devient un programme exécutable, et écrire ton tout premier programme. Tout le code de ce cours se compile et s'exécute en natif : il n'y a rien à « tester » dans un navigateur. Tu utiliseras un terminal et le compilateur gcc.

Le C en bref

Le C est le socle d'une grande partie de l'informatique moderne. Les systèmes d'exploitation Unix, Linux et une bonne partie de Windows sont écrits en C. On le retrouve dans l'embarqué (microcontrôleurs, capteurs), dans les pilotes matériels, et au cœur de nombreux autres langages : l'interpréteur de référence de Python (CPython) est écrit en C, tout comme une grande partie de la machine virtuelle Java.

Sa force est sa proximité avec la machine : tu contrôles précisément ce qui se passe en mémoire, ce qui rend le code rapide et léger. Sa contrepartie est la rigueur exigée : le langage te fait confiance et ne te protège pas de tes erreurs. C'est pourquoi nous insisterons beaucoup, tout au long du cours, sur la mémoire et sur le comportement indéfini (en anglais undefined behavior), c'est-à-dire les situations où le standard ne garantit plus rien sur ce que fait ton programme.

Note

Contrairement à un langage interprété (Python, JavaScript), un programme C n'a pas besoin que le langage soit installé sur la machine cible : l'exécutable produit contient directement les instructions machine. C'est ce qui le rend portable au niveau du code source, mais pas au niveau du binaire (un exécutable Linux ne tourne pas tel quel sous Windows).

La chaîne de compilation

Passer de ton fichier main.c à un exécutable n'est pas une seule étape, mais une chaîne de quatre étapes. Comprendre ces étapes t'aidera plus tard à décrypter les messages d'erreur.

  • Préprocesseur : traite les lignes commençant par # (comme #include). Il copie-colle le contenu des fichiers d'en-tête et remplace les macros. Le résultat est toujours du C, mais « déplié ».
  • Compilation : traduit ce C en code assembleur propre à ton processeur.
  • Assemblage : convertit l'assembleur en code machine, dans un fichier objet (.o).
  • Édition de liens (en anglais linking) : assemble les fichiers objets et les bibliothèques (comme celle qui contient le code de printf) en un exécutable final.

En pratique, gcc enchaîne ces quatre étapes pour toi en une seule commande.

On compile main.c vers un exécutable nommé prog, puis on le lance.

Sans l'option -o, gcc produit par défaut un fichier nommé a.out. Quelques options sont à connaître dès maintenant :

-Wall et -Wextra activent les avertissements ; -std=c17 fixe la version du langage ; -g ajoute les infos de débogage.

Note

Le \n à la fin de la chaîne n'est pas affiché : c'est un caractère spécial, le retour à la ligne. Sans lui, le texte suivant (et l'invite du terminal) collerait directement à ton message.

printf et les formats

printf ne sert pas qu'à afficher du texte fixe : il sait insérer des valeurs grâce à des spécificateurs de format, repérés par %. Chaque spécificateur dans la chaîne est remplacé par l'argument correspondant, dans l'ordre.

Retiens les spécificateurs de base :

  • %d pour un entier (int) ;
  • %f pour un flottant (double) ;
  • %c pour un caractère (char) ;
  • %s pour une chaîne de caractères.

Astuce

Tu peux limiter le nombre de décimales avec %.2f : printf("%.2f\n", prix) affiche 19.99 au lieu de 19.990000.

Les commentaires

Les commentaires sont du texte ignoré par le compilateur, destiné à toi et aux autres humains. Il y a deux formes en C moderne.

Sers-t'en pour expliquer le pourquoi d'un choix, pas pour paraphraser le code. Un bon commentaire éclaire une intention ; un mauvais commentaire répète ce que le code dit déjà.

La compilation comme garde-fou

Le compilateur n'est pas seulement un traducteur : c'est ton premier relecteur. Avec -Wall, il signale des constructions douteuses qui compilent quand même mais cachent souvent un bug. Considère chaque warning comme une erreur potentielle à corriger.

Lire une variable non initialisée est un comportement indéfini : le programme peut afficher n'importe quoi, planter, ou sembler fonctionner par chance. Le warning t'a évité un bug sournois ; ignore-le, et tu le paieras plus tard.

Cas réel

Sur un vrai projet, un printf("%d", prix) où prix est un double affichait le bon montant sur la machine du développeur… puis des valeurs absurdes une fois recompilé ailleurs (autre compilateur, autres options, autre architecture). Le comportement indéfini n'est pas « toujours faux » : il est imprévisible, donc il peut marcher par chance en test et casser en production. Le -Wall avait pourtant signalé le mauvais format dès la première compilation. Moralité : un warning ignoré est une bombe à retardement.

Le rôle de stdio.h

Pourquoi cette ligne #include <stdio.h> en haut de chaque programme ? Le fichier stdio.h (pour standard input/output) contient les déclarations des fonctions d'entrée/sortie, dont printf. Une déclaration dit au compilateur quel est le nom de la fonction, quels arguments elle attend et ce qu'elle renvoie.

Pièges fréquents

Piège fréquent

Un mauvais spécificateur de format est un comportement indéfini, pas une simple coquille. Écrire printf("%d\n", 3.14) (un %d pour un double) peut afficher une valeur aberrante. Avec -Wall, gcc te prévient : warning: format '%d' expects argument of type 'int', but argument 2 has type 'double'. Utilise %f pour les flottants.

Quelques autres erreurs classiques de débutant :

  • Oublier #include <stdio.h> : avertissement (ou erreur) d'implicit declaration, à corriger systématiquement.
  • Ignorer les warnings : un programme qui compile « avec des warnings » n'est pas un programme correct.
  • Oublier le \n : l'affichage devient illisible, tout collé sur une ligne.
  • Oublier de recompiler : si tu modifies main.c sans relancer gcc, tu exécutes encore l'ancien prog. Le code source n'est pas exécuté directement ; seul le binaire compilé l'est.

Pour aller plus loin

Pour aller plus loin

clang est un compilateur alternatif à gcc, aux messages d'erreur souvent très clairs : clang -Wall main.c -o prog. Le standard C a évolué (C89, C99, C11, C17, et le récent C23) : chaque version ajoute des fonctionnalités, d'où l'intérêt de fixer -std=c17. Pour automatiser la compilation de projets, on utilise make. Enfin, les sanitizers (-fsanitize=address) instrumentent ton programme pour détecter à l'exécution les erreurs mémoire : un outil que tu apprendras à apprécier.

Glossaire

Langage compilé
Langage dont le code source est traduit une fois en instructions machine par un compilateur, produisant un exécutable autonome (par opposition à interprété).
Chaîne de compilation
Suite d'étapes — préprocesseur, compilation, assemblage, édition de liens — qui transforme un fichier .c en exécutable.
Préprocesseur
Première étape qui traite les directives # (#include, macros) en produisant du C « déplié », avant la compilation proprement dite.
Édition de liens (linking)
Étape finale qui assemble les fichiers objets et les bibliothèques (comme celle contenant printf) en un seul exécutable.
gcc
Compilateur C répandu ; enchaîne les quatre étapes en une commande. Options clés : -Wall -Wextra, -std=c17, -g, -o.
Spécificateur de format
Marqueur %… dans une chaîne printf (%d, %f, %c, %s) remplacé par l'argument correspondant ; son type doit concorder.
Warning
Avertissement du compilateur sur une construction douteuse qui compile quand même ; à traiter comme une erreur, car il cache souvent un bug.
Comportement indéfini
Undefined behavior : situation où le standard ne garantit plus rien (variable non initialisée, mauvais format) ; le programme peut planter, afficher n'importe quoi, ou sembler marcher par chance.

Récap et vérification

  • Le C est un langage compilé, bas niveau, à la base des systèmes et de l'embarqué.
  • La chaîne de compilation enchaîne préprocesseur, compilation, assemblage et édition de liens pour produire un exécutable.
  • On compile avec gcc -Wall -Wextra -std=c17 -g main.c -o prog, puis on lance ./prog.
  • Un programme minimal repose sur #include <stdio.h>, int main(void), printf et return 0;.
  • printf utilise des formats : %d, %f, %c, %s, et \n pour le retour à la ligne.
  • Les warnings sont précieux : traite-les comme des erreurs.
