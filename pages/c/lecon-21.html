Projet : un outil en ligne de commande

~40 min Avancé Projet de synthèse — mobilise tout le cours

À la fin de cette leçon, tu sauras

  • lire les arguments de la ligne de commande (argc/argv) et distinguer options et fichiers ;
  • ouvrir un fichier ou lire l'entrée standard, et le parcourir caractère par caractère ;
  • gérer les erreurs à la manière d'un outil Unix : message sur stderr et code de sortie non nul ;
  • assembler un outil complet compter (à la manière de wc) qui compte lignes, mots et octets.
Sommaire de la leçon

Tu as vu, tout au long de ce cours, les briques du C : types, pointeurs, allocation, fichiers, chaînes robustes, bibliothèque standard. Il est temps de les assembler en un vrai programme utile. Notre objectif : un outil en ligne de commande baptisé compter, qui reproduit l'essentiel de wc (le vénérable word count d'Unix) : il compte les lignes, les mots et les octets d'un fichier ou de l'entrée standard. Un projet modeste en taille, mais qui réunit tout ce qui fait un logiciel système propre.

Anatomie d'un outil en ligne de commande

Un programme reçoit ses paramètres par int main(int argc, char *argv[]) : argc est le nombre d'arguments, argv le tableau des chaînes. argv[0] est le nom du programme lui-même. Un outil bien élevé écrit son résultat sur la sortie standard (stdout), ses erreurs sur la sortie d'erreur (stderr), et renvoie un code de sortie (0 = succès).

Lire les arguments

On parcourt argv de 1 à argc-1. Ce qui commence par - est une option ; le reste est un nom de fichier. Pour un argument numérique, on convertit proprement avec strtol (vu au module précédent), jamais avec atoi qui avale les erreurs.

Astuce

Quand aucun fichier n'est fourni, un bon outil lit l'entrée standard : cela permet de l'enchaîner avec un tube (cat notes.txt | ./compter). C'est la convention Unix qui rend les outils combinables entre eux.

Le cœur : compter lignes, mots et octets

On lit le flux caractère par caractère avec fgetc jusqu'à EOF. Chaque octet compte ; chaque '\n' est une ligne ; un mot commence à chaque passage d'un espace vers un non-espace. On tient un petit état booléen « suis-je dans un mot ? » — une machine à états minimale.

Gérer les erreurs proprement

Un fichier peut être introuvable, illisible, protégé. Un outil robuste ne plante pas : il écrit un message clair sur stderr et renvoie un code de sortie non nul. La fonction perror ajoute le message système exact (No such file or directory…).

Ne jamais utiliser un FILE* sans l'avoir vérifié

fopen renvoie NULL en cas d'échec. Utiliser ce pointeur sans le tester (fgetc(NULL)) est un comportement indéfini : plantage assuré, un jour ou l'autre. Le réflexe : if (!f) { perror(chemin); return 1; } immédiatement après l'ouverture.

Assembler l'outil complet

On réunit les trois morceaux : analyse des arguments, ouverture robuste (fichier ou stdin), comptage, affichage. Voici l'outil compter entier, en une soixantaine de lignes.

Cas réel : la philosophie Unix

Cas réel

Notre compter reproduit wc, l'un des premiers outils d'Unix (1971), toujours écrit en C aujourd'hui. Sa force n'est pas sa complexité — il fait une chose — mais sa composabilité : parce qu'il lit stdin et écrit stdout, on l'enchaîne avec d'autres : grep erreur journal.log | wc -l compte les lignes contenant « erreur ». C'est la philosophie Unix : des petits programmes qui font bien une seule tâche et se combinent par des tubes. En respectant ce contrat (trois flux, un code de sortie), ton outil de 60 lignes devient une brique réutilisable dans des chaînes que tu n'avais pas prévues. Des outils modernes comme ripgrep ou fd perpétuent exactement cet héritage.

Pour aller plus loin

Pour industrialiser l'outil : gérer plusieurs fichiers d'un coup (avec une ligne de total), analyser les options avec getopt (options groupées, --help), lire par gros blocs avec fread plutôt que caractère par caractère (plus rapide), et compter de vrais caractères UTF-8 plutôt que des octets. Chaque amélioration réutilise une brique du cours.

Antisèche

Glossaire

argc / argv
Nombre d'arguments de la ligne de commande et tableau des chaînes correspondantes ; argv[0] est le nom du programme.
Option / drapeau
Argument qui modifie le comportement (par convention préfixé d'un -, comme -l), par opposition à un argument « positionnel » comme un fichier.
stdin / stdout / stderr
Les trois flux standard : entrée, sortie normale (le résultat) et sortie d'erreur (les diagnostics).
Code de sortie
Entier renvoyé par main (0 = succès, ≠ 0 = échec) ; consulté par le shell via $? et par les scripts.
fopen / fclose
Ouvrent et ferment un fichier ; fopen renvoie un FILE * ou NULL en cas d'échec, à tester systématiquement.
fgetc
Lit un caractère d'un flux et renvoie un int (pour distinguer EOF d'un octet valide).
perror
Écrit sur stderr un message décrivant la dernière erreur système (errno), précédé d'un préfixe fourni.
Tube (pipe)
Mécanisme du shell (|) reliant la sortie d'un programme à l'entrée du suivant ; fondement de la composition des outils Unix.

Récap et vérification

  • Un outil reçoit ses paramètres par argc/argv ; argv[0] est son nom, le reste des options ou des fichiers.
  • Il écrit son résultat sur stdout, ses erreurs sur stderr, et renvoie un code de sortie.
  • On lit un flux avec fgetc jusqu'à EOF ; compter les mots = une petite machine à états.
  • Toujours tester le retour de fopen ; en cas d'échec, perror + return 1.
  • Lire stdin par défaut rend l'outil composable avec des tubes : c'est la philosophie Unix.

Vérifie ta compréhension

  1. Que contient argv[0], et où commencent les vrais arguments ?
  2. Pourquoi compter lit-il stdin lorsqu'aucun fichier n'est passé en argument ?
  3. Comment compte-t-on un mot sans compter deux fois s'il y a plusieurs espaces ?

Mini-projet fil rouge — un carnet de notes

Pour clore ce cours, écrivons un petit carnet de notes. Il réunit un type structuré, les tableaux (de caractères et de flottants), une fonction recevant un pointeur constant, une boucle et printf avec ses formats — l'essentiel du C réuni.

Ce que tu vas construire

Un type Etudiant (nom + trois notes), une fonction moyenne qui reçoit le tableau de notes via un pointeur, et une boucle qui affiche la moyenne de chaque étudiant.

Étapes

Le type Etudiant

Définis une struct (via typedef) avec un char nom[32] et un float notes[3].

La fonction moyenne

Écris moyenne(const float *notes, int n) : elle somme les notes et divise par n.

Le tableau d'étudiants

Déclare un tableau de Etudiant et initialise-le avec quelques noms et notes.

La boucle d'affichage

Parcours le tableau avec un for et affiche chaque moyenne avec printf("%.2f", ...).

Passage par pointeur

Remarque que moyenne reçoit l'adresse du tableau (const float *) : aucune copie, et le const protège les données.
