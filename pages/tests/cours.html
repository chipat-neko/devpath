Tests & qualité : tester son code et le garder sain

Du code qui marche aujourd'hui doit encore marcher demain, après cent modifications. Ce cours transversal et indépendant du langage t'apprend à écrire de bons tests automatisés et à bâtir une vraie posture qualité : pyramide des tests, TDD, doublures, couverture et intégration continue, jusqu'aux tests de propriétés, de performance, de contrat et de sécurité.

Bien s'équiper

Les extensions VS Code pour les tests

Avant de te lancer, ouvre le panneau Extensions de VS Code (Ctrl+Shift+X) et installe ces incontournables : ils rendent les tests visibles et la couverture lisible dans l'éditeur.

À installer pour les tests

  • Error Lens (Alexander) — voir les échecs directement en ligne.
  • Coverage Gutters (ryanluker) — affiche la couverture de test dans la marge.
  • Jest (Orta) — lancer et suivre les tests Jest.
  • Playwright Test (Microsoft) — tests end-to-end du navigateur.

Pour qui ?

Pour qui sait programmer dans un langage. Ce cours donne les principes ; les cours de langage (Java, Rust, Kotlin…) montrent comment les appliquer avec leur framework de test (JUnit, cargo test, kotlin.test…).

Ce que tu vas apprendre

Tester, et au-delà

À la fin du cours, tu sauras

  • expliquer la valeur des tests et écrire un bon test (Arrange-Act-Assert, indépendance) ;
  • doser les niveaux avec la pyramide des tests (unitaires, intégration, E2E) ;
  • pratiquer le TDD (rouge-vert-refactor) et utiliser des doublures (mocks, stubs, fakes) ;
  • lire une couverture, mettre en place une intégration continue et des garde-fous qualité ;
  • écrire des tests paramétrés, tester l'asynchrone, énoncer des propriétés et mesurer tes tests par mutation ;
  • tester la performance, les contrats entre services et la sécurité, puis reprendre un code legacy sous filet de tests.

Pour qui, et pourquoi

Savoir tester est l'une des compétences qui distinguent un développeur débutant d'un développeur fiable. Les tests font gagner du temps, donnent le courage de faire évoluer le code, et documentent le comportement attendu. C'est un savoir attendu dans presque toutes les équipes.

Les principes de ce cours valent pour tous les langages ; les exemples, eux, sont écrits en JavaScript : avec des assertions en français (affirmer, affirmerEgal) dans les leçons 1 à 6, puis dans le style de Jest (test, expect) à partir de la leçon 7. Tu pourras ensuite appliquer ces principes avec l'outillage de ton langage préféré.

Récapitulatif

À retenir & glossaire

Les points clés du cours, puis les termes essentiels à connaître.

À retenir

  • Structure d'un test : Arrange-Act-Assert.
  • Test unitaire (isolé) vs intégration vs end-to-end.
  • beforeEach pour un état frais ; doublures (stubs, mocks) pour les dépendances.
  • TDD : rouge, vert, refactor.
  • Pyramide des tests : beaucoup d'unitaires, peu d'E2E.
  • Une propriété éprouve une règle sur des cas générés ; le score de mutation mesure la force des tests.
  • La performance se lit en centiles (p95, p99), avec un seuil qui fait échouer le build.
  • Un test de contrat vérifie que deux services se comprennent ; un code legacy se reprend sous un filet de tests.
Test unitaire
Vérifie une unité de code isolée.
AAA
Arrange (préparer), Act (agir), Assert (vérifier).
Doublure (stub, mock)
Substitut d'une dépendance réelle : le stub fournit des réponses, le mock vérifie les appels.
TDD
Écrire le test AVANT le code (rouge, vert, refactor).
Régression
Comportement qui marchait et qui casse après un changement ; un test doit l'attraper.
Flaky
Test au résultat instable : rouge ou vert sans changement de code.
Mutant
Copie du code avec une petite altération ; un bon test le « tue ».
p95
Temps sous lequel tombent 95 % des requêtes.
