Module 1 · Les bases de Scala — Leçon 02

Types, expressions et chaînes

~50 min Avancé Prérequis : leçon 1

À la fin de cette leçon, tu sauras

  • savoir utiliser les types de base de Scala et comprendre la hiérarchie Any / AnyVal / AnyRef / Nothing ;
  • savoir construire des chaînes avec l'interpolation s, f et raw ;
  • savoir traiter if/else et un bloc comme des expressions qui produisent une valeur ;
  • savoir manipuler tuples, Range et comprendre que les opérateurs sont des méthodes.
Sommaire de la leçon

Dans la leçon précédente, tu as lancé ton premier programme Scala. Place maintenant aux briques élémentaires : les types que manipule le langage, et surtout une idée qui irrigue tout Scala — presque tout est une expression, c'est-à-dire un morceau de code qui produit une valeur. Là où d'autres langages séparent les instructions (qui agissent) des expressions (qui calculent), Scala efface cette frontière le plus possible. C'est l'un des premiers endroits où ses deux âmes, objet et fonctionnel, se réconcilient.

On va parcourir les types numériques et leurs cousins, la façon idiomatique d'assembler des chaînes, puis le grand basculement mental : if, les blocs, les opérateurs… tout devient valeur ou message envoyé à un objet. Garde en tête le fil du cours : ces fondations sont exactement les mêmes du petit script jusqu'aux pipelines Spark sur des téraoctets.

Les types de base

Scala possède les types numériques classiques de la JVM, plus quelques compagnons. Tu n'as presque jamais besoin de les écrire : le compilateur les infère (les devine) à partir de la valeur. Mais les connaître t'aide à lire les messages d'erreur.

Unit est le type des expressions qui n'ont rien d'intéressant à renvoyer (comme println) : c'est le void de Java, sauf que c'est un vrai type avec une unique valeur écrite (). Tu le croiseras dès qu'une fonction agit « pour son effet » plutôt que pour son résultat.

La hiérarchie des types

En Scala, tout est un objet, y compris les nombres. Tous les types descendent d'une racine commune, Any. Sous elle, deux branches : AnyVal (les valeurs « primitives » : Int, Double, Boolean, Char, Unit…) et AnyRef (les objets référence : String, tes classes, tout ce qui vient de Java via java.lang.Object).

Tout en bas vit Nothing : un type qui n'a aucune valeur et qui est sous-type de tous les autres. Il sert au compilateur pour typer du code qui ne renvoie jamais (une exception levée, une boucle infinie). Tu n'écris quasiment jamais Nothing toi-même, mais le voir dans une erreur signifie souvent « cette branche ne produit aucune valeur ».

Note

Le frère de Nothing est Null (sous-type de tous les AnyRef), dont l'unique valeur est null. En Scala moderne on évite null au profit de Option ; tu le verras dans un prochain module.

Conversions entre types

Scala ne convertit pas en silence un Double vers un Int (perte de précision possible) : tu demandes explicitement la conversion avec une méthode toXxx. En revanche, élargir vers un type plus grand (un Int vers un Long ou un Double) est automatique.

Retiens la dissymétrie : élargir est gratuit, rétrécir se demande. C'est une sécurité : le compilateur refuse de te faire perdre de l'information sans ton accord.

Les chaînes et l'interpolation

Pour insérer des valeurs dans une chaîne, oublie la concaténation à coups de +. Scala offre l'interpolation : une lettre devant les guillemets active un mode spécial où $ introduit une variable, et ${...} une expression complète.

Trois outils, trois usages : s pour le cas courant, f quand tu veux contrôler le format (décimales, padding), raw quand tu veux que les \n et autres restent tels quels (très pratique pour des chemins Windows ou des expressions régulières).

Astuce

Pour une chaîne sur plusieurs lignes, encadre-la par trois guillemets : """...lignes...""". Combinée à s (soit s"""..."""), elle gère proprement gros textes, SQL ou JSON sans échappements pénibles.

if/else est une expression

Voici le basculement promis. En Scala, if/else renvoie une valeur. Tu peux donc l'affecter directement à un val. La syntaxe moderne de Scala 3 ajoute le mot-clé then et autorise de se passer de parenthèses.

C'est pour cela que Scala n'a pas d'opérateur ternaire : il serait redondant. Un if sans else, lui, a pour type Unit et vaut () quand la condition est fausse — signe que tu l'utilises pour un effet et non pour une valeur.

Les blocs sont aussi des expressions

Un bloc entre accolades (ou délimité par l'indentation en Scala 3) est une expression dont la valeur est celle de sa dernière ligne. Pas de mot-clé return à écrire : la dernière expression évaluée est le résultat.

Cette règle est fondamentale : le corps d'une fonction n'est qu'un bloc, donc une fonction « renvoie » sa dernière expression. Tu retrouveras ce principe partout, y compris dans les fonctions Spark.

Opérateurs, tuples et ranges

Puisque tout est objet, les opérateurs ne sont pas magiques : ce sont des méthodes. 1 + 2 est exactement 1.+(2) — on envoie le message + à l'objet 1 avec l'argument 2. Scala autorise simplement d'écrire l'appel sans point ni parenthèses (notation « infixe »).

Ici aussi, to, until et by sont des méthodes appelées en notation infixe. Les tuples, eux, sont parfaits pour renvoyer plusieurs valeurs sans créer une classe : tu les destructures à la réception comme ci-dessus.

while, récursion et lazy val

Scala possède bien une boucle while, mais elle est rare en code idiomatique : elle ne renvoie rien (Unit) et suppose souvent une variable mutable. On lui préfère les expressions, les méthodes de collections et la récursion. Mentionnons aussi lazy val, qui retarde un calcul jusqu'au premier accès.

Et un avant-goût du pattern matching, que tu approfondiras bientôt : match est, lui aussi, une expression qui renvoie une valeur, en bien plus puissant qu'une cascade de if.

Pièges fréquents

Piège fréquent

Oublier le else d'un if utilisé comme expression. val x = if cond then 1 donne à x le type Unit : si la condition est fausse, x vaut (), pas ce que tu crois ; et même quand elle est vraie, le 1 est « noyé » dans Unit. Dès que tu affectes le résultat, fournis toujours un else.

Piège fréquent

Confondre apostrophes et guillemets : 'A' est un Char (un seul caractère), "A" est une String. "A" + "B" donne "AB", mais 'A' + 'B' additionne leurs codes numériques et donne 131 !

Pour aller plus loin

Pour aller plus loin

Les interpolateurs s, f et raw ne sont pas câblés dans le langage : ce sont des méthodes sur une classe StringContext, et tu peux définir tes propres interpolateurs (par exemple un sql"..." qui protège contre les injections). C'est un bel exemple de la philosophie Scala : peu de magie dans le compilateur, beaucoup de pouvoir dans la bibliothèque.

Cas réel

Cas réel

Dans une appli de facturation, tu génères des milliers de lignes « Total : 12,50 € ». L'interpolateur f impose deux décimales quel que soit le nombre (f"$montant%.2f"), là où une simple concaténation afficherait 12.5 ou 12.499999. Pour les requêtes SQL, on va plus loin : un interpolateur maison sql"..." (comme ceux des bibliothèques Doobie ou Quill) échappe automatiquement les valeurs et bloque les injections. L'interpolation n'est donc pas qu'un confort d'écriture, c'est aussi un outil de correction et de sécurité.

Glossaire

Type
Catégorie d'une valeur (Int, String…) qui décrit ce qu'on peut en faire.
Any / AnyVal / AnyRef
Racine de la hiérarchie ; AnyVal regroupe les valeurs primitives, AnyRef les objets référence.
Nothing
Type sans aucune valeur, sous-type de tous les autres ; type du code qui ne renvoie jamais.
Unit
Type des expressions sans résultat utile ; son unique valeur s'écrit ().
Interpolation
Insertion de valeurs dans une chaîne via un préfixe (s, f, raw) et $.
Tuple
Regroupement ordonné de valeurs de types éventuellement différents, ex. (3, 4).
Range
Intervalle d'entiers engendré par to (inclusif) ou until (exclusif), au pas réglable par by.
lazy val
Valeur dont le calcul est différé jusqu'au premier accès, puis mémorisé.

Récap et vérification

  • Les types de base : Int, Long, Double, Boolean, Char, String, Unit (le void) ; le compilateur les infère.
  • Tout descend de Any ; deux branches AnyVal et AnyRef ; Nothing est sous-type de tout.
  • Conversions : élargir est automatique, rétrécir demande toInt/toDouble…
  • Interpolation : s"$x", f"$x%.2f", raw"...".
  • if/else, blocs et match sont des expressions qui renvoient une valeur ; pas d'opérateur ternaire.
  • Les opérateurs sont des méthodes (1 + 2 = 1.+(2)) ; tuples, ranges (1 to 10, 1 until 10) et lazy val.

Vérifie ta compréhension

  1. Quelle est la différence de comportement entre 1 to 10 et 1 until 10 ?
  2. Pourquoi Scala n'a-t-il pas besoin d'un opérateur ternaire cond ? a : b ?
  3. Quel type et quelle valeur a l'expression if 2 > 3 then 7 (sans else) lorsque la condition est fausse ?
