Module 1 · Les bases de Scala — Leçon 01

Découvrir Scala

~45 min Avancé Prérequis : connaître un langage à objets

À la fin de cette leçon, tu sauras

  • expliquer ce qui rend Scala singulier : objet + fonctionnel, typage inféré, sur la JVM ;
  • installer la chaîne d'outils (Coursier, sbt) et lancer la REPL ;
  • écrire un premier programme avec @main et afficher du texte ;
  • distinguer val et var, et comprendre que tout est une expression.
Sommaire de la leçon

Bienvenue dans ce cours sur Scala. Si tu connais déjà un langage à objets — Java, C#, Python — tu vas retrouver des repères familiers : des classes, des méthodes, des objets. Mais Scala apporte autre chose : il réconcilie deux grandes façons de programmer, l'objet et le fonctionnel, dans un seul langage cohérent, au typage solide et qui tourne sur la machine virtuelle Java (JVM).

Dans cette première leçon, on ne va pas encore plonger dans les classes ou les fonctions d'ordre supérieur. On pose les fondations : comprendre pourquoi Scala existe, installer de quoi le faire tourner, et écrire ton tout premier programme. À la fin, tu sauras lancer du code Scala et tu comprendras la distinction centrale entre val et var.

Pourquoi Scala ?

Scala a été créé par Martin Odersky en 2004. Le nom vient de scalable language : un langage qui « passe à l'échelle », du petit script jusqu'aux systèmes massifs. Son pari est de marier deux paradigmes que beaucoup de langages séparent.

  • Objet : tout est un objet, même un nombre. On a des classes, de l'héritage, des traits.
  • Fonctionnel : les fonctions sont des valeurs, on privilégie l'immutabilité et les expressions plutôt que les instructions.

Scala est aussi fortement typé, mais le compilateur infère la plupart des types pour toi : tu écris peu d'annotations tout en gardant la sécurité d'un typage strict. Et comme il vise la JVM, toutes les bibliothèques Java existantes sont disponibles directement.

Là où Scala brille particulièrement : le big data (Apache Spark, l'outil de référence du traitement distribué, est écrit en Scala), les back-ends robustes, et tous les domaines où un système de types riche évite des bugs coûteux.

Note

Ce cours utilise Scala 3, la version moderne du langage. Elle simplifie beaucoup la syntaxe et autorise une indentation significative (comme Python), tout en restant compatible avec les accolades classiques. On en reparle plus bas.

Installer la chaîne d'outils

Le moyen le plus simple pour démarrer est Coursier, l'installateur officiel de l'écosystème Scala. Il installe Java, le compilateur, la REPL et l'outil de build sbt. Une fois Coursier en place, une seule commande prépare le terrain.

Après cs setup, redémarre ton terminal pour que les commandes soient reconnues.

Deux outils vont nous accompagner. La commande scala (qui, depuis Scala 3.5, embarque Scala CLI) est parfaite pour exécuter un fichier ou expérimenter rapidement. sbt (Scala Build Tool) gère les vrais projets : dépendances, compilation, tests. Pour cette leçon, la commande scala suffit largement.

La REPL : un bac à sable

La REPL (Read-Eval-Print Loop) est une console interactive : tu tapes une expression, elle l'évalue et affiche le résultat immédiatement. C'est l'endroit idéal pour tester une idée sans créer de fichier.

Tape :quit pour sortir de la REPL.

Remarque que la REPL nomme chaque résultat (res0, res1…) et indique son type (Int, String). C'est l'inférence de type à l'œuvre : tu n'as rien annoté, mais Scala sait exactement à quoi il a affaire.

Ton premier programme

Pour un programme exécutable, on écrit un fichier .scala avec un point d'entrée. En Scala 3, cela se fait avec l'annotation @main placée devant une fonction.

On exécute ce fichier directement avec la commande scala, sans étape de compilation séparée.

Décortiquons cette ligne. @main désigne la fonction comme point de démarrage. def introduit une fonction (on dira méthode plus tard). hello() est son nom, sans paramètres ici. Après le = vient le corps, qui appelle println pour afficher du texte. Pas de point-virgule en fin de ligne : Scala s'en passe.

val et var : l'immutabilité d'abord

Pour donner un nom à une valeur, Scala offre deux mots-clés. val crée une liaison immuable : une fois affectée, elle ne change plus. var crée une variable mutable, qu'on peut réaffecter.

La règle idiomatique en Scala est simple : utilise val par défaut, et ne passe à var que si tu as une vraie raison de muter. Le code immuable est plus facile à suivre, plus sûr en concurrence, et c'est l'esprit fonctionnel du langage. Tu peux toujours annoter le type explicitement si tu veux être clair : val age: Int = 30.

Astuce

Quand tu hésites entre val et var, commence toujours par val. Si le compilateur se plaint d'une réaffectation, tu verras précisément où la mutation est nécessaire — et souvent, tu trouveras une façon de l'éviter.

Tout est une expression

Voici une idée centrale qui distingue Scala de Java. En Scala, presque tout produit une valeur. Même un if est une expression : il renvoie un résultat qu'on peut affecter à un val.

En Java, on aurait écrit une variable mutable puis affecté dans chaque branche du if. Ici, le if tout entier est la valeur, qu'on range directement dans un val. C'est plus court, plus sûr, et c'est la manière idiomatique de penser en Scala : on combine des expressions plutôt que d'enchaîner des instructions.

Syntaxe, commentaires et conventions

Scala 3 autorise deux styles. Le style à indentation significative (sans accolades, comme dans les exemples précédents) et le style à accolades, plus proche de Java. Les deux sont valides ; choisis celui qui rend le code le plus lisible.

Côté nommage, Scala suit des conventions strictes que tout le monde respecte : camelCase pour les valeurs, variables et méthodes (scoreTotal, calculerAire) ; PascalCase pour les types, classes et objets (String, CompteBancaire). S'y tenir rend ton code immédiatement familier aux autres développeurs.

Aperçu du cours

Tu viens de poser la première pierre. Le voyage qui t'attend suit un fil clair : du script au big data. On commencera par maîtriser les bases (types, fonctions, collections), puis le versant objet (classes, traits, objets), puis le versant fonctionnel (fonctions d'ordre supérieur, pattern matching, immutabilité poussée). On verra comment Scala dialogue avec Java, et on terminera par un aperçu de Spark, où Scala déploie toute sa puissance sur des données massives. Garde en tête le fil rouge : Scala, ce sont deux paradigmes réconciliés.

Pièges fréquents

Piège fréquent

Croire que val rend l'objet immuable. Non : val empêche seulement de réaffecter le nom. Si la valeur pointe vers une structure mutable, son contenu peut changer. Pour de vraies données immuables, utilise aussi des types immuables (on les verra avec les collections).

Piège fréquent

Mélanger indentation et accolades n'importe comment. Si tu ouvres un bloc avec une accolade, ferme-le avec une accolade. Si tu choisis l'indentation, reste régulier : une indentation incohérente peut changer le sens du code ou déclencher une erreur.

Cas réel

Cas réel

Apache Spark, le moteur de traitement de données massives utilisé par Netflix, Airbnb ou la NASA, est écrit en Scala. Quand un analyste écrit donnees.filter(_.montant > 100).map(_.client), il enchaîne des expressions immuables — exactement l'esprit val + « tout est expression » de cette leçon — et Spark distribue ce calcul sur des centaines de machines. Les réflexes que tu prends ici passent donc, sans rupture, du petit script au pipeline de plusieurs téraoctets.

Antisèche

Glossaire

JVM (Java Virtual Machine)
Machine virtuelle qui exécute le bytecode ; Scala compile vers elle et accède à tout l'écosystème Java.
REPL
Read-Eval-Print Loop : console interactive qui évalue une expression et affiche aussitôt son résultat et son type.
Coursier (cs)
Installateur officiel de l'écosystème Scala (JDK, compilateur, sbt), lancé via cs setup.
val / var
val lie une valeur de façon immuable ; var crée une variable réassignable.
Inférence de type
Capacité du compilateur à déduire le type d'une valeur sans annotation explicite.
Expression
Morceau de code qui produit une valeur ; en Scala, même un if ou un bloc en est une.
Immutabilité
Propriété d'une donnée qui ne change pas après sa création ; socle du style fonctionnel.

Récap et vérification

  • Scala marie objet et fonctionnel, avec un typage fort et inféré, sur la JVM.
  • On installe la chaîne d'outils avec Coursier (cs setup) ; la commande scala exécute du code, sbt gère les projets.
  • La REPL évalue des expressions interactivement et affiche leur type.
  • Un programme démarre via @main def … ; println affiche du texte.
  • val (immuable, à privilégier) vs var (mutable) ; le type est généralement inféré.
  • Tout est expression, même if : on combine des valeurs au lieu d'enchaîner des instructions.

Vérifie ta compréhension

  2. Pourquoi préférer val à var par défaut, et que se passe-t-il si tu réaffectes un val ?
  3. En quoi le fait que if soit une expression change-t-il ta façon d'écrire le code par rapport à Java ?
