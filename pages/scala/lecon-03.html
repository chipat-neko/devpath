Module 1 · Les bases de Scala — Leçon 03

Fonctions et ordre supérieur

~50 min Avancé Prérequis : leçon 2

À la fin de cette leçon, tu sauras

  • savoir définir une fonction avec def, paramètres nommés, par défaut et varargs ;
  • savoir traiter une fonction comme une valeur de type Int => Int et écrire des lambdas abrégées ;
  • savoir écrire des fonctions d'ordre supérieur, du currying et de l'application partielle ;
  • savoir composer des fonctions avec andThen / compose et distinguer méthode et fonction.
Sommaire de la leçon

En Scala, une fonction n'est pas un simple bloc de code : c'est une valeur comme une autre. Tu peux la stocker dans un val, la passer en argument, la renvoyer depuis une autre fonction. C'est exactement ce qui réconcilie les deux âmes du langage : l'objet (tout est un objet, même une fonction) et le fonctionnel (les fonctions circulent librement). Cette leçon pose ce socle ; les méthodes de collections comme map et filter, que tu croiseras bientôt, ne sont que des fonctions d'ordre supérieur appliquées aux listes.

On part de la déclaration la plus simple, puis on monte en puissance jusqu'à un petit pipeline de transformations composées. Le code ne s'exécute pas sur le site : les résultats sont donnés en commentaire //.

Déclarer une fonction avec def

La forme de base associe un nom, des paramètres typés et un type de retour. Comme tout est expression en Scala, le corps après le = est la valeur renvoyée : pas besoin de return.

Le type de retour peut souvent être inféré, mais l'écrire explicitement documente l'intention et accélère la compilation. Garde-le pour les fonctions publiques.

Note

Scala 3 autorise la syntaxe à indentation : le corps multiligne se délimite par l'indentation, sans accolades. Tu peux toujours écrire { ... } quand cela clarifie un bloc imbriqué.

Une fonction comme valeur : le type Int => Int

Tu peux écrire une fonction sans la nommer via une lambda et la ranger dans un val. Son type s'écrit avec une flèche : Int => Int se lit « prend un Int, rend un Int ».

Sous le capot, cette valeur est un objet de type Function1 (ou Function2…) doté d'une méthode apply. Écrire doubler(10) appelle en réalité doubler.apply(10) : voilà le pont concret entre objet et fonctionnel.

Fonctions d'ordre supérieur

Une fonction d'ordre supérieur prend une fonction en paramètre ou en renvoie une. C'est le moteur de tout le style fonctionnel.

Remarque comme multiplicateurPar capture la valeur n : la fonction renvoyée « se souvient » de n. C'est une fermeture (closure), brique essentielle pour fabriquer des comportements sur mesure.

Lambdas abrégées : le _ placeholder

Quand le contexte fixe déjà les types, Scala propose une syntaxe ultra-courte avec le souligné _, où chaque _ représente un argument successif.

Astuce

Le _ est parfait pour les lambdas qui utilisent chaque argument une seule fois, dans l'ordre. Dès qu'un argument sert deux fois (ex. x * x), reviens à la forme nommée x => x * x : _ * _ signifierait deux arguments distincts.

Paramètres nommés, par défaut et varargs

Scala laisse donner une valeur par défaut à un paramètre, et appeler en nommant les arguments pour gagner en lisibilité. Les varargs (x: Int*) acceptent un nombre variable d'arguments.

Currying et application partielle

Le currying consiste à découper les paramètres en plusieurs listes (x: Int)(y: Int). On peut alors fournir une liste à la fois : appliquer la première produit une nouvelle fonction en attente de la seconde. C'est l'application partielle.

Le currying brille quand une liste de paramètres est souvent fixe : tu spécialises une fonction générale en une variante prête à l'emploi, sans réécrire de code.

Note

Avec une méthode def, l'application partielle est directe : ajouter(100) suffit. Avec une fonction-valeur « classique » (un seul groupe de paramètres), passe d'abord par .curried pour pouvoir fournir les arguments un à un.

Paramètres by-name (=> T) : évaluation différée

Par défaut, un argument est évalué avant l'appel (by-value). Un paramètre by-name, noté => T, n'est évalué qu'au moment où la fonction l'utilise — et autant de fois qu'elle l'utilise. Idéal pour différer un calcul ou éviter une exception.

Composer des fonctions : andThen et compose

Deux fonctions du bon type s'enchaînent en une seule. f.andThen(g) applique f puis g ; f.compose(g) applique g d'abord. C'est le cœur d'un pipeline de transformations.

Méthode ou fonction ? L'eta-expansion

Une méthode déclarée avec def appartient à un objet et n'est pas, en soi, une valeur. Une fonction (lambda, val f = ...) est une valeur de type FunctionN. Quand tu passes une méthode là où une fonction est attendue, Scala la convertit automatiquement en valeur : c'est l'eta-expansion.

En pratique tu n'as presque jamais besoin de forcer la conversion en Scala 3 : elle se fait dès qu'un type fonction est attendu (la forme estPair _ est d'ailleurs dépréciée). Retiens surtout la distinction conceptuelle : def = méthode liée à un objet, lambda = valeur transportable.

Pièges fréquents

Piège fréquent

Confondre andThen et compose. f.andThen(g)(x) vaut g(f(x)) (sens de lecture naturel, gauche à droite). f.compose(g)(x) vaut f(g(x)) (notation mathématique). En cas de doute pour un pipeline, préfère andThen : l'ordre du code suit l'ordre d'exécution.

Piège fréquent

Croire que _ * _ signifie « le carré ». Chaque _ est un argument différent : _ * _ est (a, b) => a * b, une fonction à deux paramètres. Pour le carré d'un seul argument, écris x => x * x.

Pour aller plus loin

Pour aller plus loin

Les paramètres by-name sont la base des structures paresseuses : LazyList ne calcule ses éléments qu'à la demande, ce qui permet des suites infinies. Tu retrouveras aussi l'ordre supérieur partout dans les collections (map, filter, fold) et, à grande échelle, dans Spark, où les transformations distribuées sont des fonctions passées au moteur.

Cas réel

Cas réel

Quand un blog transforme le titre « Mon Premier Article » en adresse mon-premier-article pour l'URL, il enchaîne exactement ce genre de petites fonctions : retirer les espaces de bord, passer en minuscules, remplacer les espaces par des tirets. Composées avec andThen, elles forment un pipeline testable morceau par morceau. À l'échelle de Spark, c'est le même principe : chaque transformation d'un jeu de données est une fonction d'ordre supérieur passée au moteur, qui l'applique en parallèle sur des millions de lignes.

Glossaire

Fonction d'ordre supérieur
Fonction qui prend une fonction en paramètre ou en renvoie une.
Lambda
Fonction anonyme écrite sur place, ex. (x: Int) => x * 2.
Fermeture (closure)
Fonction qui capture et « se souvient » d'une valeur de son environnement.
Currying
Découpage des paramètres en plusieurs listes (x)(y), permettant l'application partielle.
Application partielle
Fixer une partie des arguments pour obtenir une nouvelle fonction en attente du reste.
Paramètre by-name
Argument noté => T, évalué seulement à l'usage (et à chaque usage).
Eta-expansion
Conversion automatique d'une méthode def en fonction-valeur là où un type fonction est attendu.
andThen / compose
Enchaîner deux fonctions : andThen applique de gauche à droite, compose l'inverse.

Récap et vérification

  • def nom(x: Int): Int = ... déclare une fonction ; le corps après = est la valeur renvoyée.
  • Une fonction est une valeur : val f: Int => Int = x => x * 2, abrégeable en _ * 2.
  • Une fonction d'ordre supérieur prend ou renvoie une fonction.
  • Currying def f(x)(y) + application partielle f(x) = spécialisation sans réécriture.
  • Paramètres nommés, par défaut, varargs x: Int* et by-name => T assouplissent les signatures.
  • andThen / compose enchaînent les fonctions ; def = méthode, lambda = valeur (eta-expansion).

Vérifie ta compréhension

  1. Quel est le type de val f = (a: Int, b: Int) => a + b, et que vaut f.curried comme type ?
  2. Pourquoi verifier(1 > 2) { coûteux() } n'exécute-t-il pas coûteux() si le paramètre est by-name et que la condition rend l'appel inutile ?
  3. Réécris nettoyer.andThen(minuscules) avec compose pour obtenir le même résultat.
