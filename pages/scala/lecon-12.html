Module 3 · Scala en pratique — Leçon 12

Vers le big data et au-delà

~45 min Avancé Prérequis : leçon 11

À la fin de cette leçon, tu sauras

  • comprendre comment Apache Spark réutilise map, filter et reduce à l'échelle distribuée ;
  • situer les grandes briques de l'écosystème Scala (web, effets typés, acteurs, Scala.js) ;
  • lire un pipeline Spark conceptuel de bout en bout (lire, transformer, agréger) ;
  • tracer un plan d'apprentissage et connaître les débouchés du langage.
Sommaire de la leçon

Tu as parcouru un long chemin depuis la première leçon : les val et l'immutabilité, les fonctions et les expressions, les collections avec map/filter/reduce, les classes et les case class, le pattern matching, les traits, les types et la gestion d'erreurs avec Option et Try. Cette dernière leçon ne t'apprend pas une nouvelle syntaxe : elle te montre où tout cela mène, et pourquoi des entreprises entières construisent leur infrastructure sur Scala.

Le fil conducteur du cours était que Scala réconcilie deux paradigmes : objet et fonctionnel. C'est précisément cette double nature qui en fait un langage de choix pour le big data, le back-end exigeant et la programmation fonctionnelle pure. Faisons le tour de l'horizon.

Apache Spark : tes collections, mais distribuées

Apache Spark est le cas d'usage phare de Scala. C'est un moteur qui traite d'énormes volumes de données — des téraoctets — en répartissant le travail sur des dizaines ou des centaines de machines. Et voici la bonne nouvelle : tu sais déjà t'en servir. Spark expose une API qui ressemble trait pour trait aux méthodes de collections de la leçon 4.

Une collection distribuée s'appelle un RDD (Resilient Distributed Dataset) ou, plus moderne, un DataFrame. Tu la manipules avec map, filter, reduce, groupBy — exactement comme une List. La différence : au lieu de boucler sur ta machine, Spark découpe la donnée et l'envoie travailler sur le cluster.

Tu retrouves filter(_ > 2), map(_ * 10) et un reduce(_ + _) identiques à ce que tu écrivais sur une List. La syntaxe fonctionnelle de Scala est ce qui permet à Spark d'être à la fois expressif (tu décris le quoi) et parallélisable (le moteur décide du comment).

Note

Spark est écrit en Scala. C'est pour ça que l'API Scala y est la plus complète et la plus naturelle : les transformations distribuées épousent exactement les méthodes de collections que tu connais déjà.

Un pipeline Spark de bout en bout

Un traitement big data suit presque toujours trois temps : lire la donnée brute, la transformer, puis l'agréger pour en extraire un résultat. Voici un exemple conceptuel : calculer le chiffre d'affaires par pays à partir d'un gros fichier de commandes.

Lis, transforme, agrège : ce sont les trois mouvements. Le code tient en quelques lignes et pourtant il peut traiter des milliards de lignes réparties sur un cluster. filter, groupBy, agg(sum(...)) — chaque verbe que tu connais s'applique, simplement à une autre échelle.

Note

Spark est paresseux (lazy) : filter et groupBy ne calculent rien tout de suite, ils construisent un plan. Le travail ne démarre vraiment qu'à une action comme show() ou write. C'est l'LazyList de la leçon 4, à l'échelle d'un cluster.

Cas réel

Netflix traite chaque nuit des pétaoctets de journaux de visionnage avec des jobs Spark en Scala pour alimenter ses recommandations ; les banques rejouent des portefeuilles entiers pour le calcul de risque réglementaire. Le pipeline « lire / transformer / agréger » que tu viens de lire est exactement la forme de ces traitements — seule change la taille : quelques lignes de CSV en cours, des milliards de lignes sur des centaines de machines en production. Le code, lui, reste ces mêmes filter, groupBy et agg.

Le web : Play et http4s

Scala n'est pas réservé au calcul de masse. Pour construire des serveurs web et des API REST, deux familles dominent. Play Framework est un framework complet et productif, à la Rails ou Spring. http4s adopte une approche purement fonctionnelle : une requête HTTP y est une simple fonction Request => Response.

Tu reconnais le pattern matching de la leçon 7 : ici on filtre sur la méthode HTTP et le chemin de l'URL. La même mécanique de langage sert à des usages très différents.

Effets typés : Cats Effect et ZIO

C'est la direction la plus moderne de Scala. Cats Effect et ZIO sont des bibliothèques de programmation fonctionnelle pure : l'idée est de représenter les effets de bord (lire un fichier, appeler une base, échouer) comme des valeurs typées que l'on compose, plutôt que de les exécuter immédiatement.

Le type ZIO[Any, Throwable, Unit] encode trois informations dans la signature : ce dont le programme a besoin, comment il peut échouer, ce qu'il produit. C'est la philosophie « rendre les choses explicites par les types » de la leçon 9, poussée à son maximum. La concurrence, la gestion des erreurs et l'annulation y deviennent sûres et composables.

Acteurs : Akka et Pekko

Pour les systèmes hautement concurrents et distribués (messagerie, IoT, jeux temps réel), le modèle d'acteurs propose une autre approche : des entités isolées qui communiquent uniquement par messages, sans mémoire partagée. Akka a longtemps régné ; Pekko en est le fork open source de la fondation Apache, désormais privilégié pour les nouveaux projets.

Note

Akka a changé de licence en 2022, ce qui a poussé la communauté à créer Pekko. Pour un nouveau projet sans budget de licence, on choisit aujourd'hui Pekko : l'API est quasi identique.

Scala.js : le même langage côté navigateur

Scala.js compile ton code Scala non pas vers du bytecode JVM, mais vers du JavaScript. Tu peux ainsi écrire le front-end d'une application web dans le même langage, avec les mêmes types, partagés avec le back-end.

Partager les case class d'un modèle de données entre le serveur et le client, sans les redéfinir en TypeScript : c'est l'un des grands attraits de cette approche full-stack.

Où Scala s'emploie : panorama emploi

Scala occupe des niches précises et bien rémunérées :

  • Data engineering : pipelines Spark, traitement de flux (Kafka, Flink). C'est le débouché numéro un.
  • Fintech et banques : systèmes transactionnels où la sûreté des types et l'immutabilité réduisent les bugs coûteux.
  • Back-end à forte charge : services exigeants en débit et en concurrence (Twitter/X, Netflix, Disney+ ont des briques Scala).
  • Plateformes fonctionnelles : équipes adeptes de ZIO/Cats qui visent un code très fiable et composable.

Le marché est plus étroit que celui de Java ou Python, mais les postes sont qualifiés et l'expertise est valorisée. Scala est un excellent second langage qui te démarque.

Pièges fréquents

Piège fréquent

Croire qu'apprendre Spark, c'est repartir de zéro. C'est faux : map, filter, reduce et groupBy sont exactement ceux des collections de la leçon 4. La courbe d'apprentissage de Spark porte sur le distribué (partitions, évaluation paresseuse, shuffle), pas sur l'API de base.

Piège fréquent

Vouloir tout apprendre d'un coup : Spark et ZIO et Akka et Play. Ces écosystèmes ne se rencontrent quasiment jamais dans le même projet. Choisis ta voie (data ou back-end fonctionnel) et approfondis-la d'abord.

Pour aller plus loin

Pour aller plus loin

Pour la data, installe Spark en local et rejoue le pipeline « lire / transformer / agréger » sur un petit CSV. Pour le back-end fonctionnel, le livre Functional Programming in Scala (dit « le livre rouge ») reste la référence. Et la documentation officielle de ZIO propose un excellent parcours guidé pour découvrir les effets typés.

Glossaire

Apache Spark
Moteur de traitement de données distribué écrit en Scala ; expose une API de collections (map, filter, reduce, groupBy) sur des jeux de données répartis.
RDD / DataFrame
Collection distribuée de Spark : le Resilient Distributed Dataset (bas niveau) et le DataFrame/Dataset (typé, optimisé) qu'on manipule comme une List.
Évaluation paresseuse (Spark)
Les transformations construisent un plan sans rien calculer ; le travail ne démarre qu'à une action (show(), write).
Effet typé
Effet de bord représenté comme une valeur composée puis exécutée à la fin (Cats Effect IO, ZIO[R,E,A]) plutôt qu'exécuté immédiatement.
Modèle d'acteurs
Concurrence par entités isolées qui communiquent uniquement par messages, sans mémoire partagée (Akka, Pekko).
Scala.js
Compilateur de Scala vers JavaScript : permet d'écrire le front-end web en Scala et de partager le modèle avec le back-end.
Data engineering
Construction de pipelines de traitement de données (Spark, Kafka, Flink) ; premier débouché professionnel de Scala.

Récap et vérification

Tu refermes ce cours avec une vue d'ensemble du langage et de son terrain de jeu :

  • Spark réutilise tes méthodes de collections (map, filter, reduce, groupBy) à l'échelle distribuée.
  • Un pipeline big data se résume à trois mouvements : lire, transformer, agréger.
  • L'écosystème couvre le web (Play, http4s), les effets typés (Cats Effect, ZIO), les acteurs (Akka, Pekko) et le navigateur (Scala.js).
  • Les débouchés se concentrent en data engineering, fintech et back-end exigeant.
  • Tout repose sur les fondations du cours : val, immutabilité, expressions, pattern matching et types explicites.
