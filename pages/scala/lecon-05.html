Module 2 · Objet et fonctionnel — Leçon 05

Classes, objects et case classes

~50 min Avancé Prérequis : leçon 4

À la fin de cette leçon, tu sauras

  • déclarer une class avec paramètres de constructeur, champs val/var et méthodes ;
  • utiliser un object singleton et un companion object pour fournir des fabriques apply et des constantes ;
  • modéliser des données immuables avec une case class (equals, toString, copy, déstructuration gratuits) ;
  • représenter un ensemble fini de cas avec un enum Scala 3.
Sommaire de la leçon

Scala réconcilie deux mondes : l'objet, hérité de Java, et le fonctionnel, où les données sont immuables et où l'on raisonne par expressions. Dans cette leçon, tu vas voir comment Scala outille les deux à travers trois constructions complémentaires : la class classique (souvent mutable, façon objet), l'object (le singleton qui remplace le static de Java), et la case class (le joyau pour modéliser des données immuables, taillé pour le pattern matching).

Le fil rouge : on modélise un petit domaine bancaire — un Compte, une Transaction, un statut. Tu verras qu'en Scala, une structure de données solide tient en une ligne, là où Java en demande trente.

Une classe avec constructeur dans l'en-tête

En Scala, les paramètres du constructeur se déclarent directement dans l'en-tête de la classe, entre parenthèses. Préfixer un paramètre par val en fait un champ public en lecture seule ; var en fait un champ modifiable. Sans préfixe, le paramètre reste un simple argument, invisible de l'extérieur.

Tout le corps de la classe (en dehors des méthodes) constitue le constructeur primaire : il s'exécute à chaque instanciation. En Scala 3, le mot-clé new est facultatif pour la plupart des classes.

Note

L'interpolation s"...$nom..." insère la valeur de la variable dans la chaîne. Pour une expression, on utilise des accolades : s"dans 5 ans : ${age + 5}".

object : le singleton de Scala

Scala n'a pas de mot-clé static. À la place, tu déclares un object : c'est une instance unique, créée paresseusement à la première utilisation. Tout ce que tu y mets (méthodes, constantes) est accessible directement par le nom de l'objet, comme des membres statiques.

Un object est aussi le point d'entrée d'un programme : une fonction annotée @main y vit naturellement, puisqu'il n'y a qu'une seule instance.

Companion object : fabriques et constantes

Quand un object porte le même nom qu'une classe et vit dans le même fichier, on parle de companion object. Les deux se voient mutuellement, y compris leurs membres privés. C'est l'endroit idéal pour ranger des constantes partagées et des méthodes de fabrique.

La méthode de fabrique la plus idiomatique s'appelle apply : Scala l'appelle automatiquement quand tu écris Compte(...) sans new. C'est exactement ce mécanisme qui te permet d'écrire Personne("Ada", 36) plus haut.

L'interpolateur f permet un formatage à la printf : %.2f affiche deux décimales.

case class : le joyau pour modéliser des données

Une case class est une classe pensée pour représenter des données immuables. Le compilateur t'offre gratuitement : des champs val (pas besoin d'écrire val devant chaque paramètre), un equals/hashCode par valeur, un toString lisible, une méthode copy, un apply de fabrique, et la déstructuration pour le pattern matching.

Compare avec l'équivalent Java : pour obtenir le même comportement (champs finaux, equals, hashCode, toString, constructeur), il faut des dizaines de lignes ou un record récent. En Scala, une ligne suffit.

Astuce

Pour « modifier » une donnée immuable, on ne mute jamais : on crée une copie avec le changement voulu via copy(champ = nouvelleValeur). L'ancienne valeur reste intacte — c'est la clé du raisonnement fonctionnel.

apply et unapply : ce qui rend le pattern matching possible

Sous le capot, le companion object d'une case class reçoit deux méthodes : apply (construire) et unapply (déconstruire). C'est unapply qui autorise la déstructuration dans un match ou une affectation.

Le if s < 0 après le motif s'appelle une garde : le cas ne s'applique que si la condition est vraie. On reviendra en détail sur le pattern matching dans une leçon dédiée — retiens ici que la case class le rend possible sans aucun effort.

enum : un ensemble fini de cas (Scala 3)

Quand un type ne peut prendre qu'un nombre fini de valeurs (un statut, une couleur, un mode), Scala 3 offre enum. Chaque cas est une valeur unique, et l'on peut associer des données à certains cas.

Un enum avec cas paramétrés est en réalité un raccourci pour une hiérarchie de case class scellée : combiné au pattern matching, le compilateur peut même t'avertir si tu oublies un cas.

Données immuables vs classe mutable

Récapitulons le choix de conception. Une class avec un var modélise un objet qui change d'état dans le temps (un compteur, un cache). Une case class modélise une valeur qui ne change jamais : pour refléter une évolution, on produit une nouvelle valeur.

Le style immuable demande à peine plus de code mais élimine toute une classe de bugs : personne ne peut modifier ta donnée derrière ton dos. C'est le défaut recommandé en Scala, et le socle des traitements distribués comme Spark, où les données circulent entre machines.

Cas réel

Chez les utilisateurs d'Apache Spark (moteur de traitement de données massives écrit en Scala), on décrit le schéma d'un jeu de données par une case class : case class Vente(produit: String, montant: Double, pays: String). Spark s'en sert pour typer chaque ligne d'un Dataset[Vente], valider les colonnes à la compilation et sérialiser les enregistrements qui transitent entre les machines du cluster. L'immutabilité est ici indispensable : une donnée qui voyage sur le réseau ne doit jamais être modifiée en route. Même principe dans Akka, où les messages échangés entre acteurs sont des case class immuables.

Pièges fréquents

Piège fréquent

copy ne modifie jamais l'objet d'origine : il en renvoie un nouveau. Si tu écris t1.copy(libelle = "Thé") sans réaffecter le résultat à une val, le changement est perdu. La donnée immuable l'est pour de bon.

Piège fréquent

Le companion object doit porter exactement le même nom que la classe et vivre dans le même fichier. Sinon ce n'est qu'un objet indépendant, sans accès aux membres privés de la classe, et ton apply ne sera pas reconnu comme fabrique.

Piège fréquent

Mettre un var dans une case class est techniquement possible mais casse tout l'intérêt : l'égalité par valeur et le hashCode deviennent instables si le champ change après insertion dans une Map ou un Set. Laisse les champs en val (le défaut).

Pour aller plus loin

Pour aller plus loin

Les case class combinées aux enum forment ce qu'on appelle des types de données algébriques (ADT) : la brique de base pour modéliser un domaine de façon sûre. Le pattern matching exhaustif, les sealed trait et l'optionnel Option s'appuient tous dessus — autant de sujets des prochaines leçons.

Glossaire

Constructeur primaire
Le corps de la classe (hors méthodes) ; ses paramètres se déclarent dans l'en-tête, entre parenthèses.
val / var (paramètre)
Préfixe qui transforme un paramètre en champ : val lecture seule, var modifiable.
object (singleton)
Instance unique créée paresseusement ; sert de porte-membres « statiques » et de point d'entrée @main.
Companion object
Objet de même nom qu'une classe, dans le même fichier ; accès mutuel aux membres privés.
apply
Méthode-fabrique appelée implicitement par C(...), ce qui rend new facultatif.
case class
Classe pour données immuables : champs val, égalité par valeur, toString, copy, déstructuration offerts.
copy
Produit une nouvelle instance en changeant un ou plusieurs champs, sans muter l'original.
unapply
Méthode de déconstruction qui autorise la déstructuration et le pattern matching.
enum (Scala 3)
Type à un nombre fini de cas ; sucre pour une hiérarchie scellée de case class (ADT).

Récap et vérification

  • Une class déclare son constructeur dans l'en-tête ; val crée un champ en lecture seule, var un champ modifiable.
  • Un object est un singleton : il remplace le static de Java pour les constantes et utilitaires.
  • Un companion object (même nom, même fichier) héberge les fabriques apply et les constantes partagées.
  • Une case class offre gratuitement equals par valeur, toString, copy, l'apply/unapply et la déstructuration.
  • copy(champ = valeur) produit une nouvelle valeur sans toucher à l'originale.
  • enum (Scala 3) modélise un ensemble fini de cas, éventuellement porteurs de données.

Vérifie ta compréhension

  1. Quelle différence de comportement y a-t-il entre val et var devant un paramètre de constructeur ?
  2. Pourquoi Compte("Ada", 0.0) fonctionne-t-il sans new, et quel membre du companion object est appelé ?
  3. Si t1 est une case class, que vaut t1 après t1.copy(libelle = "Thé") exécuté sans réaffectation ?
