Métaprogrammation : quote, unquote et macros

~52 min Avancé Leçon 14 requise

À la fin de cette leçon, tu sauras

  • comprendre que le code Elixir est une donnée (l'AST) ;
  • capturer une expression avec quote et y injecter avec unquote ;
  • écrire une macro simple avec defmacro ;
  • savoir quand ne pas écrire de macro.
Sommaire de la leçon

Depuis le début du cours, tu utilises if, unless, def, defmodule comme des mots-clés. Surprise : ce sont des macros. En Elixir, une grande partie du langage est écrite… en Elixir, grâce à la métaprogrammation — la capacité d'un programme à manipuler du code comme une donnée ordinaire. Cette leçon lève le capot : comment le code devient une structure de données, comment on la fabrique (quote), comment on y insère des morceaux (unquote), et comment on écrit une macro. Pouvoir redoutable : on finira par la règle qui évite de s'y brûler.

Le code est une donnée : l'AST

Avant d'être exécutée, chaque expression Elixir est représentée par un arbre de syntaxe abstraite (AST). On l'obtient avec quote, qui capture une expression au lieu de l'évaluer :

Toute expression composée devient un tuple à trois éléments : {opération, métadonnées, arguments}. Ici 1 + 2 est « l'opération :+ appliquée aux arguments 1 et 2 ». Comme c'est une simple structure de données, un programme peut la lire, la transformer et la reconstruire. C'est toute l'idée.

unquote : injecter dans le code capturé

À l'intérieur d'un quote, le code est « gelé ». Pour y insérer une valeur ou un fragment calculé, on utilise unquote : c'est une fenêtre qui s'évalue et se colle dans l'arbre. La paire quote/unquote fonctionne comme l'interpolation de chaîne ("#{x}"), mais pour du code :

quote décide de la structure du code produit ; unquote y branche les parties variables. Ce sont les deux seules primitives dont on a besoin pour fabriquer du code à la volée.

Écrire une macro avec defmacro

Une macro est une fonction spéciale qui reçoit l'AST de ses arguments, renvoie un AST (généralement construit avec quote), et dont le résultat est inséré à la place de l'appel — le tout à la compilation. Réécrivons unless pour comprendre :

La macro reçoit condition et bloc non évalués (sous forme d'AST) et fabrique le code équivalent d'un if inversé. Une fonction ne pourrait pas faire ça : elle recevrait déjà la valeur de la condition, en ayant perdu son texte et sans contrôle sur l'exécution du bloc. require charge la macro avant de l'appeler (les macros doivent être connues à la compilation).

Cas réel : l'assert des tests

Dans ExUnit (leçon 11), quand assert 1 + 1 == 3 échoue, le rapport n'affiche pas juste « faux » : il montre left: 2 et right: 3. Impossible avec une fonction — elle recevrait false, l'expression déjà réduite. assert est une macro : elle reçoit l'AST {:==, _, [{:+, _, [1, 1]}, 3]}, repère la comparaison, et génère du code qui évalue chaque côté séparément pour construire un message de diagnostic précis. C'est la métaprogrammation qui rend les tests Elixir aussi lisibles.

La règle d'or : n'écris une macro qu'en dernier recours

José Valim, le créateur d'Elixir, le résume ainsi : « N'écris pas de macro quand une fonction suffit. » Une macro est plus dure à lire, à déboguer et à composer ; elle s'exécute à la compilation, loin des outils habituels. Réserve-la à ce qu'une fonction ne peut pas faire : retarder l'évaluation d'un argument, inspecter le texte d'une expression, ou générer du code répétitif. Dans 95 % des cas, une fonction bien nommée est le bon choix.

L'hygiène des macros

Les macros Elixir sont hygiéniques : les variables introduites dans un quote vivent dans leur propre espace et n'écrasent pas celles de l'appelant, même en cas de même nom. Une macro qui utilise en interne une variable temp ne cassera pas un temp du code appelant. C'est une protection majeure contre les bugs sournois des macros d'autres langages ; pour délibérément partager une variable, il faut la marquer explicitement avec var!.

Visualiser le code généré

Pour comprendre ce qu'une macro produit, transforme son AST en texte : quote do: … |> Macro.to_string() |> IO.puts(). Tu vois alors le code réellement injecté. Autre confort : bind_quoted: [x: valeur] sur un quote injecte proprement plusieurs valeurs et évite d'évaluer plusieurs fois un même unquote — une source classique d'effets de bord en double.

Pour aller plus loin

Le couple use MonModule / defmacro __using__(opts) est le mécanisme d'injection derrière Phoenix, Ecto et ExUnit : use ExUnit.Case injecte tout le nécessaire de test dans ton module. C'est ainsi qu'on construit un DSL (langage dédié) : le routeur Phoenix (get "/", …), les schémas Ecto (schema "users" do … end) sont des macros qui lisent un bloc et génèrent des fonctions. Macro.expand/2 permet d'inspecter, étape par étape, comment une macro se déploie.

Antisèche

Glossaire

Métaprogrammation
Écrire du code qui manipule du code (le lit, le transforme, le génère).
AST
Arbre de syntaxe abstraite : la représentation du code sous forme de donnée ; en Elixir, des tuples {op, meta, args}.
quote
Capture une expression sous forme d'AST au lieu de l'évaluer.
unquote
À l'intérieur d'un quote, évalue un fragment et l'injecte dans l'arbre (l'« interpolation » du code).
Macro
Fonction (defmacro) qui reçoit et renvoie de l'AST, exécutée à la compilation ; son résultat remplace l'appel.
Hygiène
Propriété des macros Elixir : leurs variables internes n'entrent pas en collision avec celles de l'appelant.
require
Charge un module pour rendre ses macros disponibles à la compilation avant de les appeler.
use / __using__
Mécanisme d'injection de code dans un module ; fondation des DSL (Phoenix, Ecto, ExUnit).

Récap et vérification

  • Le code Elixir est une donnée (l'AST, des tuples {op, meta, args}) qu'on obtient avec quote.
  • unquote injecte des fragments dans un bloc quote, comme l'interpolation pour les chaînes.
  • Une macro (defmacro) reçoit l'AST, en renvoie, et s'exécute à la compilation ; c'est ce qui rend assert si expressif.
  • Règle d'or : une macro seulement si une fonction ne suffit pas.

  2. Quelle est la différence essentielle entre ce que reçoit une fonction et une macro ?
  3. Pourquoi assert doit-il être une macro ?

Exercices

Exercice 1Échauffement

Dans iex, quelle forme donne quote do: a - b ? Écris le tuple attendu (métadonnées abrégées en _).

Voir une solution

L'opération est :- ; les arguments a et b sont eux-mêmes des variables, représentées par des tuples {:a, _, Elixir}. Tout est donnée.

Exercice 2Application

Écris une macro double(x) qui, à la compilation, remplace l'appel par x * 2.

Voir une solution

unquote(x) injecte l'AST reçu ; le quote l'entoure de * 2. À la compilation, Math.double(1 + 2) devient littéralement (1 + 2) * 2.

Exercice 3Défi

On veut une macro debug(expr) qui affiche le texte de l'expression et sa valeur, par exemple a + b = 7. Pourquoi une fonction ne peut-elle pas le faire, et comment la macro s'y prend ?

Voir une solution

Une fonction recevrait déjà la valeur (7), sans le texte « a + b ». La macro reçoit l'AST : Macro.to_string en tire le texte, puis unquote(expr) réinjecte l'expression pour l'évaluer. Voir le texte et la valeur exige de tenir l'AST — donc une macro.
