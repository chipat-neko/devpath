Module 4 · Elixir : aller plus loin — Leçon 13

Structs et protocoles

~48 min Avancé Leçon 12 requise

À la fin de cette leçon, tu sauras

  • définir une struct (defstruct, @enforce_keys) ;
  • filtrer et mettre à jour une struct par pattern matching ;
  • écrire un protocole et ses implémentations ;
  • personnaliser to_string et l'affichage d'une struct.
Sommaire de la leçon

Jusqu'ici, une donnée composite était une map aux clés libres. Pratique, mais rien ne garantit sa forme : une faute de frappe (:naem au lieu de :name) passe inaperçue. Elixir offre deux outils pour aller plus loin : les structs, des maps à forme fixe et nommée, et les protocoles, un polymorphisme ouvert qui ajoute un comportement à des types sans les modifier. Ensemble, ils structurent tes données et rendent ton code extensible.

Les structs : des maps à forme fixe

Une struct se déclare avec defstruct à l'intérieur d'un module. Elle fixe la liste des champs (avec des valeurs par défaut) et porte le nom du module :

Sous le capot, une struct est une map : elle porte juste une clé spéciale __struct__ qui vaut le nom du module. Différence essentielle avec une map libre : on ne peut pas y ajouter une clé qui n'existe pas. %Utilisateur{roles: []} lève une erreur à la compilation — c'est exactement la protection recherchée.

Pour rendre certains champs obligatoires, on ajoute @enforce_keys : créer la struct sans eux devient une erreur.

Le polymorphisme : le problème

Imaginons vouloir une fonction decrire/1 qui rende un texte pour un Utilisateur, mais aussi pour un Produit, un entier, une liste… Écrire un gros case qui teste chaque type est fermé : chaque nouveau type oblige à rouvrir la fonction. Il faudrait pouvoir brancher un comportement par type, y compris pour des types définis ailleurs. C'est exactement le rôle des protocoles.

Les protocoles : un polymorphisme ouvert

Un protocole déclare un ensemble de fonctions ; chaque type fournit ensuite sa propre implémentation. Au moment de l'appel, Elixir choisit l'implémentation selon le type du premier argument (le dispatch).

L'intérêt : pour couvrir un nouveau type, on écrit un nouveau defimpl — sans toucher ni au protocole, ni aux implémentations existantes. Le code est ouvert à l'extension, fermé à la modification.

Les protocoles intégrés : String.Chars et Inspect

Elixir s'appuie lui-même sur des protocoles. Deux reviennent souvent :

  • String.Chars — ce que to_string/1 et l'interpolation "#{valeur}" appellent. Par défaut, une struct n'est pas interpolable ; en implémentant ce protocole, tu décides de son rendu texte.
  • Inspect — ce que IO.inspect et la console affichent. Le personnaliser sert notamment à masquer un champ sensible.

Cas réel : masquer un mot de passe dans les journaux

Une struct Compte contient un champ mot_de_passe. Le jour où un développeur écrit Logger.info("échec pour #{inspect(compte)}"), le mot de passe part en clair dans les logs — une fuite classique. La parade idiomatique : implémenter Inspect pour la struct afin de redacter le champ sensible. En pratique, on utilise même le raccourci @derive {Inspect, except: [:mot_de_passe]} : inspect affiche alors #Compte<mot_de_passe: ...>. Le secret ne peut plus fuiter par mégarde, quel que soit l'endroit où la struct est journalisée.

Une struct n'est pas un objet

En Elixir, une struct ne contient aucune méthode : c'est de la donnée pure. Les fonctions qui agissent dessus vivent dans des modules (souvent le module qui définit la struct, comme Utilisateur.majeur?/1). Cette séparation données/comportement est au cœur du fonctionnel : on transforme des données avec des fonctions, on n'appelle pas de méthodes sur des objets.

Ne pas confondre protocole et behaviour

Un protocole apporte le polymorphisme par type de donnée (dispatch sur le premier argument). Un behaviour (comme GenServer, leçon 9) est un contrat de callbacks qu'un module s'engage à implémenter (@behaviour + @impl). Les deux organisent le code, mais l'un dispatche sur des valeurs, l'autre décrit ce qu'un module doit fournir.

Pour aller plus loin

@derive génère automatiquement une implémentation pour une struct (utile avec Jason.Encoder pour sérialiser en JSON, ou Inspect). Le protocole Enumerable rend une structure parcourable par Enum et Stream (leçon 5) ; Collectable est son pendant pour Enum.into/2. Enfin, le comportement Access autorise la syntaxe donnee[cle] et get_in/put_in sur tes structures.

Antisèche

Glossaire

Struct
Map à forme fixe et nommée, définie par defstruct ; refuse toute clé non déclarée.
defstruct
Macro qui déclare, dans un module, les champs d'une struct et leurs valeurs par défaut.
@enforce_keys
Liste des champs obligatoires ; créer la struct sans eux lève une erreur.
__struct__
Clé cachée d'une struct valant le nom de son module ; c'est ce qui distingue une struct d'une map ordinaire.
Protocole
Contrat de fonctions (defprotocol) offrant un polymorphisme ouvert : chaque type fournit son implémentation.
defimpl
Fournit l'implémentation d'un protocole pour un type donné (for: Type).
Dispatch
Choix de l'implémentation à l'exécution selon le type du premier argument.
String.Chars / Inspect
Protocoles intégrés : rendu de to_string/interpolation pour l'un, affichage console pour l'autre.

Récap et vérification

  • Une struct (defstruct) est une map à forme fixe ; @enforce_keys rend des champs obligatoires.
  • On la filtre par pattern matching (%User{} = u) et on la met à jour avec %{u | …}.
  • Un protocole (defprotocol + defimpl) apporte un polymorphisme ouvert : ajouter un type ne modifie rien d'existant.
  • String.Chars et Inspect personnalisent le rendu texte et l'affichage (utile pour masquer un secret).

Exercices

Exercice 1Échauffement

Définis une struct Livre avec les champs titre (obligatoire), pages (défaut 0) et lu (défaut false).

Voir une solution

@enforce_keys [:titre] impose le titre ; pages et lu ont des valeurs par défaut. %Livre{} sans titre lèverait une erreur.

Exercice 2Application

Écris une fonction Livre.marquer_lu/1 qui prend un %Livre{} et renvoie la même struct avec lu: true.

Voir une solution

La clause %Livre{} = livre garantit qu'on reçoit bien un livre ; %{livre | lu: true} renvoie une nouvelle struct (l'originale reste inchangée).

Exercice 3Défi

Déclare un protocole Resume avec une fonction court/1, puis implémente-le pour Livre afin de renvoyer "titre (pages p.)".

Voir une solution

Pour étendre Resume à un autre type (par exemple Article), il suffira d'ajouter un defimpl Resume, for: Article — sans rien changer ici.
