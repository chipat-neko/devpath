Module 1 · Découvrir Elixir — Leçon 03

Fonctions, modules et clauses

~50 min Avancé Prérequis : leçon 2

À la fin de cette leçon, tu sauras

  • définir un module avec des fonctions publiques def et privées defp ;
  • écrire des fonctions anonymes avec fn et le raccourci & ;
  • remplacer les if/switch par des fonctions multi-clauses et des gardes when ;
  • documenter et composer de petites fonctions pures avec @moduledoc et @doc.
Sommaire de la leçon

Tu as déjà rencontré le pattern matching et le pipe |>. Il est temps de ranger ton code dans des modules et de découvrir la vraie signature d'Elixir : les fonctions multi-clauses. Là où d'autres langages t'obligent à empiler des if et des switch, Elixir te laisse écrire plusieurs définitions d'une même fonction, chacune répondant à une forme d'argument différente. Le moteur de pattern matching choisit la bonne pour toi.

Dans cette leçon, on construit pas à pas un petit module de géométrie. Tu vas y voir comment nommer des fonctions, en cacher certaines, ajouter des gardes, des valeurs par défaut, de la documentation, puis composer le tout en fonctions pures minuscules. Le fil rouge : Elixir est le fonctionnel pragmatique, et ce pragmatisme commence par la façon dont on découpe le code.

Un module pour regrouper des fonctions

Un module est un sac à fonctions nommées. On le déclare avec defmodule, on y met des fonctions publiques avec def, et on appelle Module.fonction(args). La dernière expression d'une fonction est sa valeur de retour : pas de mot-clé return.

Le retour est implicite : x * 2 est la dernière (et seule) expression, donc c'est le résultat.

Note

La forme def f(x), do: expr et la forme def f(x) do ... end sont strictement équivalentes. La première est pratique pour les fonctions tenant sur une ligne, la seconde dès qu'il y a plusieurs lignes.

Fonctions privées avec defp

Toutes les fonctions d'un module n'ont pas vocation à être appelées de l'extérieur. Les détails internes se déclarent avec defp (le p de private). Une fonction privée n'est visible que dans son propre module : l'appeler depuis ailleurs lève une erreur.

On expose ttc/1 et on garde tva/1 pour soi. La notation tva/1 = nom + nombre d'arguments (l'arité) : deux fonctions de même nom mais d'arité différente sont deux fonctions distinctes.

Fonctions anonymes et le raccourci &

À côté des fonctions nommées, Elixir a des fonctions anonymes : des valeurs qu'on stocke dans une variable et qu'on passe en argument. On les écrit avec fn ... -> ... end, et on les appelle avec un point : f.(arg). Ce point distingue clairement l'appel d'une fonction anonyme de celui d'une fonction nommée.

&(&1 * 2) est la version condensée de fn x -> x * 2 end. &1 désigne le premier argument, &2 le deuxième, etc.

Astuce

On peut aussi capturer une fonction nommée existante : &Math.double/1 donne une fonction anonyme équivalente à fn x -> Math.double(x) end. Pratique pour la passer à Enum.map sans réécrire de fn.

Multi-clauses : le pattern matching à la définition

Voici le cœur de la leçon. Tu peux définir plusieurs fois la même fonction (même nom, même arité) : Elixir essaie les clauses dans l'ordre et exécute la première dont le motif d'argument correspond. C'est le remplaçant idiomatique du switch.

Trois définitions, un seul nom aire/1. Le tuple {:cercle, r} sert à la fois d'étiquette (:cercle) et de motif qui lie r.

Aucun if, aucun case. Chaque cas est une phrase autonome qu'on lit comme une équation mathématique. Ajouter une forme ? On ajoute une clause, sans toucher aux autres. Si aucune clause ne correspond, Elixir lève une FunctionClauseError — un signal clair que tu as oublié un cas, fidèle à la philosophie « let it crash ».

Les gardes avec when

Le pattern matching dit « cet argument a cette forme ». Les gardes ajoutent une condition sur la valeur : on les introduit par when. Elles n'acceptent qu'un jeu restreint de fonctions (comparaisons, is_integer, is_atom, opérateurs booléens and/or…), justement pour rester rapides et sûres.

when is_integer(n) and n > 0 ne s'applique que si n est un entier strictement positif. Combinée aux motifs, la garde couvre des conditions impossibles à exprimer par la seule forme ; un argument hors de tous les cas plante franchement, comme prévu par « let it crash ».

Note

Dans une garde, on écrit and / or (pas && / ||). Les versions mot-clé sont strictes et faites pour les gardes, alors que && et || acceptent n'importe quelle valeur « truthy » et ne sont pas autorisées ici.

Valeurs par défaut

Un argument peut recevoir une valeur par défaut avec \\. Elixir génère alors les clauses correspondantes pour toi. Pratique pour rendre un paramètre optionnel sans dupliquer la fonction.

message \\ "Bonjour" rend le deuxième argument facultatif. On appelle saluer/1 ou saluer/2 sans rien réécrire.

Documentation et composition de fonctions pures

Elixir intègre la documentation au langage. @moduledoc décrit le module, @doc décrit la fonction qui suit. Ces textes sont consultables dans IEx avec h. Assemblons une version documentée et pipée de notre module, en composant des fonctions pures (mêmes entrées → mêmes sorties, aucun effet de bord).

Deux petites fonctions pures, reliées par |>. Dans IEx, h Geo.aire afficherait la doc. :math.pi() appelle une fonction de la lib Erlang sous-jacente.

Astuce

Vise des fonctions courtes qui font une seule chose. Des fonctions pures et petites se testent isolément, se relisent d'un coup d'œil et se branchent entre elles au pipe : c'est la brique de base de tout système Elixir résilient.

Pièges fréquents

Piège fréquent

L'ordre des clauses compte. Une clause « attrape-tout » comme def aire(_), do: 0 placée en premier capturera tous les appels et masquera les clauses suivantes. Mets toujours les motifs les plus spécifiques d'abord, le cas général en dernier. Le compilateur t'avertit d'ailleurs avec « this clause cannot match ».

Piège fréquent

Appeler une fonction nommée avec le point — Math.double.(3) — est une erreur : le point ne sert qu'aux fonctions anonymes. Pour une fonction nommée, écris simplement Math.double(3).

Pour aller plus loin

Pour aller plus loin

Quand la logique de choix vit à l'intérieur d'une fonction plutôt qu'à sa définition, on utilise case et cond — mêmes idées de pattern matching et de gardes, mais en local. Tu les croiseras dans la prochaine leçon, juste à côté des modules Enum et Stream qui regorgent de fonctions d'ordre supérieur où ton raccourci & brillera.

Cas réel : le switch qui ne grossit jamais

Imagine un module bancaire qui traite des opérations. En objet classique, on écrit un gros switch (type) avec un cas :depot, un cas :retrait, un cas :virement… et chaque nouvelle opération oblige à rouvrir cette fonction fourre-tout, à risque de casser les cas voisins. En Elixir, on écrit def traiter({:depot, montant}, solde), def traiter({:retrait, montant}, solde), etc. Ajouter le prélèvement automatique ? Une nouvelle clause def traiter({:prelevement, ...}, solde), sans toucher aux autres. C'est exactement ainsi que les bibliothèques Elixir dispatchent sur la forme des messages reçus (tuples étiquetés) : le code grandit par ajout, pas par modification. Un cas oublié ne passe pas inaperçu : la FunctionClauseError pointe la forme non gérée.

Antisèche

Glossaire

Module
Regroupement nommé de fonctions, déclaré avec defmodule Nom do … end ; l'unité d'organisation du code Elixir.
def / defp
def définit une fonction publique (dans l'API du module), defp une fonction privée (visible seulement dans le module).
Arité
Nombre d'arguments d'une fonction ; on la note nom/N. f/1 et f/2 sont deux fonctions distinctes.
Fonction anonyme
Fonction sans nom, valeur rangée dans une variable : fn x -> … end, appelée avec un point f.(x).
Capture (&)
Raccourci d'écriture : &(&1 * 2) abrège fn x -> x * 2 end ; &Mod.f/1 capture une fonction nommée.
Multi-clauses
Plusieurs définitions d'une même fonction (même nom/arité) ; Elixir exécute la première clause dont le motif d'argument correspond.
Garde (when)
Condition sur la valeur d'un argument, ajoutée à une clause : when is_integer(n) and n > 0. Jeu de fonctions restreint.
Fonction pure
Fonction dont la sortie ne dépend que des entrées, sans effet de bord : se teste, se relit et se compose (au pipe) facilement.

Récap et vérification

  • defmodule regroupe des fonctions ; def les rend publiques, defp les garde privées.
  • Le retour est implicite : c'est la dernière expression évaluée.
  • Fonctions anonymes : fn x -> ... end appelée avec f.(x), ou le raccourci &(&1 ...).
  • Les fonctions multi-clauses remplacent les if/switch par du pattern matching à la définition.
  • Les gardes when ajoutent des conditions de valeur ; valeurs par défaut avec \\.
  • @moduledoc et @doc documentent ; on compose de petites fonctions pures au pipe |>.

Vérifie ta compréhension

  1. Quelle est la différence entre def et defp, et que se passe-t-il si tu appelles une fonction privée de l'extérieur ?
  2. Pourquoi écrit-on double.(3) avec un point pour une fonction anonyme, mais Math.double(3) sans point ?
  3. Dans un module multi-clauses, dans quel ordre Elixir essaie-t-il les clauses, et où doit aller le cas « attrape-tout » ?
