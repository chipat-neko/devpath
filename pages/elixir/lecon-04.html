Module 1 · Découvrir Elixir — Leçon 04

Collections : listes, tuples et maps

~50 min Avancé Prérequis : leçon 3

À la fin de cette leçon, tu sauras

  • Choisir entre liste, tuple et map selon l'usage ;
  • Lire, créer et « mettre à jour » une map de façon immuable ;
  • Extraire des champs par pattern matching sur les maps ;
  • Définir une struct avec defstruct pour modéliser des données.
Sommaire de la leçon

Jusqu'ici tu as manipulé des valeurs simples : des nombres, des chaînes, des atomes. Mais un programme réel jongle avec des collections : une liste d'utilisateurs, un résultat tagué {:ok, valeur}, une fiche client avec ses champs. Elixir te propose trois structures de base — la liste, le tuple et la map — auxquelles s'ajoutent les keyword lists et les structs. Chacune a sa forme, son coût et son usage idéal.

Le point commun à toutes : elles sont immuables. On ne modifie jamais une collection en place. « Modifier » signifie toujours produire une nouvelle structure. Cela peut sembler coûteux ; tu verras que sur la BEAM (la machine virtuelle d'Elixir, héritée d'Erlang), c'est au contraire une force, grâce au partage structurel. Et c'est précisément cette immutabilité qui rendra, plus tard, la concurrence par processus possible sans le moindre verrou. Voyons tout ça dans IEx, le shell interactif.

Les listes : chaînées, head et tail

Une liste s'écrit entre crochets. En Elixir, c'est une liste chaînée : chaque élément pointe vers le reste. Conséquence directe — prépendre (ajouter en tête) est instantané, alors qu'ajouter à la fin doit parcourir toute la liste pour la reconstruire.

Le motif [tete | reste] est du pattern matching : il décompose la liste en sa tête (premier élément) et sa queue (le reste). C'est l'outil de base pour parcourir une liste de façon récursive. Note que nombres n'a pas changé : [0 | nombres] a créé une nouvelle liste.

Note

Utilise les listes pour des collections de taille variable que tu parcours du début à la fin : suites de résultats, files d'attente, flux d'éléments. Évite l'accès par index (Enum.at(liste, 1000)), qui est lent : la BEAM doit suivre les maillons un par un.

Les tuples : taille fixe, accès rapide

Un tuple s'écrit entre accolades. Contrairement à la liste, il est stocké de façon contiguë : sa taille est fixe et l'accès à un élément par position est immédiat. On l'utilise pour regrouper un petit nombre de valeurs connues d'avance.

La convention {:ok, resultat} / {:error, raison} est partout en Elixir. Une fonction qui peut échouer renvoie l'un ou l'autre, et l'appelant les distingue par pattern matching. Tu retrouveras ce duo dans la quasi-totalité de la bibliothèque standard.

Les maps : associer des clés à des valeurs

La map est la collection clé-valeur d'Elixir, l'équivalent du dictionnaire ou du hash d'autres langages. La forme générale utilise => entre la clé et la valeur ; n'importe quelle valeur peut servir de clé.

Deux écritures, deux accès. map[:cle] renvoie nil si la clé est absente, ce qui est tolérant ; map.cle lève une erreur si la clé manque, ce qui est plus strict — utile quand tu veux être certain que le champ existe.

Astuce

Préfère les clés atomes (%{port: 4000}) pour les données dont tu contrôles la structure : c'est plus court et la notation point devient possible. Réserve les clés chaînes aux données venues de l'extérieur (JSON, formulaire), où les noms ne sont pas connus d'avance.

Mettre à jour une map sans la modifier

Une map est immuable : on ne change pas une valeur en place, on crée une nouvelle map. La syntaxe %{map | cle: nouvelle} produit une copie avec la clé mise à jour. Attention : cette barre verticale exige que la clé existe déjà.

Pour ajouter une clé qui n'existe pas encore, on passe par le module Map, qu'on voit juste après. La règle est saine : la barre | protège des fautes de frappe sur les clés, puisqu'elle échoue si tu vises une clé inexistante.

Note

« Créer une copie » paraît coûteux, mais la BEAM pratique le partage structurel : la nouvelle map réutilise en mémoire les parties inchangées de l'ancienne. Seul ce qui diffère est neuf. L'immutabilité est donc à la fois sûre et efficace — et c'est elle qui rend la concurrence sans verrou possible.

Le module Map : put, get, update, delete

Le module Map regroupe les fonctions pour travailler avec les maps de façon explicite. Toutes renvoient une nouvelle map sans toucher l'originale.

Retiens Map.put/3 pour ajouter sans risque, Map.get/3 pour lire avec un défaut, Map.update/4 pour transformer une valeur en fonction de l'ancienne, et Map.merge/2 pour fusionner. Ce sont les quatre verbes du quotidien — et ils s'enchaînent merveilleusement avec le pipe |> que tu découvriras bientôt.

Pattern matching sur les maps

Le pattern matching ne sert pas qu'aux listes et tuples : il extrait des champs d'une map en une ligne. Le motif peut être partiel — il réussit du moment que les clés citées sont présentes, en ignorant les autres.

Cette capacité à déstructurer directement dans les arguments d'une fonction est l'un des plus grands plaisirs d'Elixir : tes fonctions annoncent dans leur signature exactement les champs qu'elles attendent.

Keyword lists et structs

Deux structures dérivées complètent le tableau. Une keyword list est une liste de tuples {:cle, valeur}, avec un raccourci d'écriture. On la voit surtout comme dernier argument d'une fonction, pour passer des options : les clés peuvent se répéter et l'ordre est conservé.

Une struct, elle, est une map « typée » portant un nom. On la déclare avec defstruct dans un module. Une struct connaît ses champs autorisés et garantit qu'on ne fabrique pas de données mal formées.

Une struct se manipule comme une map (point, barre |, pattern matching) mais protège ta structure de données : impossible d'y glisser un champ qui n'existe pas. C'est l'outil idéal pour modéliser les entités de ton domaine.

Pièges fréquents

Piège fréquent

Oublier que tout est immuable : Map.put(config, :x, 1) ne change pas config, il renvoie une nouvelle map. Si tu ne réaffectes pas le résultat (config = Map.put(...)), ta modification est perdue.

Piège fréquent

Confondre map.cle et map[:cle]. Le premier lève une erreur si la clé manque ; le second renvoie nil. De même, %{map | debug: true} échoue sur une clé absente : pour ajouter une clé, il faut Map.put/3, pas la barre |.

Pour aller plus loin

Pour aller plus loin

Explore Access et les fonctions get_in/2, put_in/3, update_in/3 pour lire et modifier des structures imbriquées (une map dans une map) en un seul appel. Côté listes, le module Enum (que tu verras bientôt) et le pipe |> transformeront ta façon d'enchaîner les traitements.

Cas réel : le bug d'aliasing qui n'arrive jamais

Dans les langages à structures mutables, passer une liste ou un dictionnaire à une fonction qui le modifie change aussi la donnée de l'appelant : deux variables pointent le même objet (aliasing), et une modification « à distance » corrompt discrètement des données qu'on croyait intactes. C'est une source classique de bugs difficiles à traquer. En Elixir, ce scénario est structurellement impossible : aucune fonction ne peut modifier la collection que tu lui passes, elle ne peut qu'en renvoyer une nouvelle version. Cette même propriété est ce qui permet à la BEAM de faire tourner des millions de processus isolés sans un seul verrou — le socle sur lequel WhatsApp a encaissé des centaines de millions d'utilisateurs avec une toute petite équipe. L'immutabilité n'est pas une contrainte académique : c'est ce qui rend le code prévisible et la concurrence sereine.

Antisèche

Glossaire

Immutabilité
Une donnée ne change jamais en place ; « modifier » produit toujours une nouvelle valeur. L'ancienne reste intacte.
Partage structurel
Optimisation de la BEAM : une « copie » modifiée réutilise en mémoire les parties inchangées de l'originale. Sûr et économe.
Liste chaînée
Suite de maillons où chacun pointe vers le reste ; prépendre est en O(1), l'accès par index est lent.
Cons ([t | r])
Opérateur qui sépare (ou construit) une liste par sa tête t et sa queue r ; base du parcours récursif.
Tuple
Regroupement de taille fixe, stocké de façon contiguë : idéal pour un petit groupe de valeurs et les résultats tagués {:ok, _}.
Map
Collection clé-valeur (dictionnaire) ; clés atomes (%{k: v}) ou quelconques (%{"k" => v}).
Keyword list
Liste de tuples {:cle, valeur} avec raccourci [cle: valeur] ; sert à passer des options, clés ordonnées et répétables.
Struct (defstruct)
Map « typée » et nommée aux champs fixes ; refuse tout champ inconnu, idéale pour modéliser une entité.

Récap et vérification

  • Liste [1, 2, 3] : taille variable, chaînée, prépendre avec [x | reste] est rapide.
  • Tuple {:ok, val} : taille fixe, accès rapide, idéal pour les résultats tagués.
  • Map %{cle => val} ou %{cle: val} : clé-valeur ; accès map[:k] (tolérant) ou map.k (strict).
  • Tout est immuable : « modifier » crée une nouvelle structure, optimisée par le partage structurel.
  • Module Map : put, get, update, delete, merge ; pattern matching pour extraire des champs.
  • Keyword list pour les options ; struct (defstruct) pour une map typée et nommée.

Vérifie ta compréhension

  1. Pourquoi prépendre à une liste est-il rapide alors qu'ajouter à la fin est lent ?
  2. Quelle est la différence de comportement entre map[:absente] et map.absente ?
  3. Pourquoi %{config | debug: true} échoue-t-il, et que faut-il utiliser à la place pour ajouter cette clé ?
