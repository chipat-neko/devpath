Module 4 · Perl en pratique — Leçon 14

Interroger une base de données avec DBI

~45 min Avancé Prérequis : leçons 8 et 9

À la fin de cette leçon, tu sauras

  • comprendre le rôle de DBI et des pilotes DBD ;
  • te connecter et exécuter des requêtes préparées ;
  • te protéger de l'injection SQL avec les placeholders ;
  • lire des résultats et grouper des écritures en transaction.
Sommaire de la leçon

Le texte et les fichiers ont leurs limites : pour des données qui changent, se cherchent et se croisent, on utilise une base de données. Perl s'y connecte via DBI, une interface unique qui parle à SQLite, MySQL, PostgreSQL, Oracle… en changeant seulement le pilote. Le cours SQL t'a appris les requêtes ; voyons comment Perl les lance.

DBI et les pilotes DBD

DBI (Database Interface) est la couche standard : ton programme lui parle toujours de la même façon. Derrière, un pilote DBD::… (Database Driver) traduit vers un moteur précis. Changer de base = changer une chaîne de connexion, pas ton code.

Se connecter

Tout commence par connect, qui renvoie une poignée de base ($dbh, database handle). On active RaiseError pour que la moindre erreur SQL fasse mourir le script avec un message clair.

Astuce

RaiseError => 1 t'évite de tester la valeur de retour après chaque appel : une erreur lève une exception. Combine-le avec eval { … } (leçon suivante) pour rattraper proprement.

Le cycle d'une requête

Une interrogation suit toujours le même enchaînement. On prépare une fois le texte SQL (le moteur en calcule le plan), puis on exécute — éventuellement plusieurs fois avec des valeurs différentes — et on lit les lignes une à une.

Requêtes préparées et placeholders

La règle d'or : ne jamais insérer une variable directement dans le SQL. On écrit un ? à sa place (un placeholder), et on fournit la valeur à execute. Le pilote se charge de l'échapper — c'est plus sûr et plus rapide (le plan de requête est réutilisé).

Attention : l'injection SQL

Interpoler une saisie utilisateur dans une requête ("... = '$saisie'") est la faille la plus classique du web. Une entrée malveillante comme '; DROP TABLE produits; -- peut détruire tes données. Les placeholders ? l'empêchent par construction. Ne fais jamais d'exception.

Lire les résultats

Plusieurs méthodes selon le besoin :

Modifier et grouper en transaction

Pour une écriture unique sans résultat, do suffit. Pour plusieurs écritures qui doivent réussir ensemble (ou pas du tout), on ouvre une transaction.

Pourquoi begin_work, puisque AutoCommit est à 1 ?

Avec AutoCommit => 1, chaque écriture est validée immédiatement, comme si elle formait sa propre transaction : pratique, mais impossible d'annuler un lot à moitié fait. begin_work suspend ce mode le temps de la transaction ; commit ou rollback le réactive ensuite. C'est le bon réflexe dès que deux écritures doivent être solidaires.

Cas réel : un script de reporting nocturne

Beaucoup d'entreprises font tourner, chaque nuit, un script Perl qui interroge la base de production (SELECT agrégés), calcule des indicateurs et écrit un rapport CSV ou HTML envoyé par courriel. DBI + Text::CSV (leçon 13) suffisent : pas de framework, un fichier .pl lancé par cron. Cette robustesse discrète explique pourquoi tant de Perl tourne encore, invisible, dans les salles serveurs.

Pour aller plus loin

Au-delà de DBI, l'écosystème propose des ORM comme DBIx::Class (qui mappe les tables en objets Perl) et le constructeur de requêtes SQL::Abstract. Pour débuter, DBI brut reste la meilleure école : tu vois exactement le SQL qui part.

Glossaire

DBI
Database Interface : module standard qui offre une API unique vers toutes les bases.
DBD
Database Driver : pilote spécifique à un moteur (DBD::SQLite, DBD::Pg…), utilisé par DBI.
DSN
Data Source Name : chaîne décrivant la cible, ex. dbi:SQLite:dbname=x.db.
RaiseError
Option de connect : à 1, la moindre erreur SQL lève une exception au lieu de renvoyer une valeur fausse à tester.
AutoCommit
Option de connect : à 1, chaque écriture est validée aussitôt ; on la suspend avec begin_work pour grouper une transaction.
Poignée ($dbh / $sth)
Objet renvoyé par DBI : database handle pour la connexion, statement handle pour une requête préparée.
Placeholder
Le ? qui réserve la place d'une valeur ; remplie par execute, elle est échappée automatiquement.
Injection SQL
Faille où une saisie est interprétée comme du code SQL ; évitée par les placeholders.
Transaction
Groupe d'écritures validées ensemble (commit) ou annulées ensemble (rollback).

Récap et vérification

  • DBI offre une interface unique ; le pilote DBD vise un moteur précis.
  • prepare + ? + execute : la seule façon sûre d'insérer une valeur.
  • Les placeholders ferment la porte à l'injection SQL.
  • Une transaction garantit « tout ou rien » (commit / rollback).
