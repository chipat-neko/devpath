Module 4 · Perl en pratique — Leçon 15

Gérer les erreurs : die, eval, Try::Tiny et Carp

~48 min Avancé Prérequis : leçons 7 et 9

À la fin de cette leçon, tu sauras

  • lever une exception avec die et avertir avec warn ;
  • rattraper une erreur avec eval et lire $@ sans te faire piéger ;
  • écrire un try/catch lisible avec Try::Tiny ;
  • blâmer le bon coupable avec Carp (croak, carp).
Sommaire de la leçon

Un programme qui ne gère pas ses erreurs finit toujours par surprendre : un fichier manquant, une base injoignable, une ligne de données corrompue. En Perl, une erreur grave se signale par une exception — on lève l'erreur avec die, et on la rattrape pour décider quoi faire. Cette leçon te donne les quatre outils indispensables : die/warn, eval, Try::Tiny et Carp.

die et warn : signaler un problème

die lève une exception : le programme s'arrête immédiatement (sauf s'il est rattrapé) et le message part sur STDERR. warn écrit le même genre de message mais sans interrompre l'exécution. Si le message ne finit pas par un retour à la ligne, Perl ajoute « at script.pl line N. », très utile pour localiser la panne.

Astuce : $!, l'erreur système

Après un open, close ou appel système raté, la variable spéciale $! contient le message du système d'exploitation (« No such file or directory »…). Toujours l'inclure dans le die d'un open : c'est ce qui transforme « ça marche pas » en diagnostic.

Rattraper avec eval et $@

Pour qu'une erreur n'arrête pas tout le programme, on entoure le code risqué d'un bloc eval { … }. Si un die survient à l'intérieur, eval l'attrape : le programme continue, et la variable spéciale $@ contient le message d'erreur (chaîne vide si tout s'est bien passé).

Attention : $@ est fragile

$@ est une variable globale qu'un autre eval exécuté entre-temps (dans une fonction que tu appelles, ou dans un destructeur d'objet) remet à vide avant que tu ne la lises. L'idiome robuste teste la valeur de retour de eval, pas seulement $@ : on termine le bloc par 1 et on enchaîne avec or do { … }.

Try::Tiny : une syntaxe claire

Le module Try::Tiny (sur CPAN, sans dépendances) enveloppe tout cela dans une syntaxe familière try/catch/finally. Dans le bloc catch, l'erreur arrive dans $_ (et non $@), ce qui évite les pièges vus plus haut.

Note : pas de point-virgule oublié

try, catch et finally sont des fonctions, pas des mots-clés du langage. La chaîne complète forme une seule instruction : n'oublie pas le ; final après le dernier bloc, sinon Perl signale une erreur de syntaxe déroutante.

Carp : blâmer le bon coupable

Quand une bibliothèque détecte un mauvais argument, la faute est presque toujours chez l'appelant, pas dans la bibliothèque. Or die pointe la ligne où il s'exécute — à l'intérieur du module. Le module standard Carp corrige cela : croak se comporte comme die mais attribue l'erreur à l'appelant ; carp fait de même pour warn.

Cas réel : un import qui refuse d'abandonner

Un script d'import lit chaque nuit un fichier de 200 000 lignes venu d'un partenaire. Une seule ligne malformée ne doit pas faire échouer les 199 999 autres. La parade : entourer le traitement de chaque ligne d'un eval (ou d'un try), journaliser la ligne fautive avec son numéro, puis passer à la suivante. À la fin, le script rapporte « 3 lignes rejetées sur 200 000 » au lieu de planter à la ligne 5 812. C'est la différence entre un traitement robuste et un traitement fragile.

Pour aller plus loin

On peut faire mieux qu'un message texte : die accepte une référence ou un objet. Des modules comme Throwable ou Exception::Class permettent de lever des exceptions typées (ErreurReseau, ErreurValidation…) qu'on distingue dans le catch par ref $_ ou $_->isa(...). Utile dès qu'un programme doit réagir différemment selon la nature de l'erreur.

Glossaire

Exception
Signal d'erreur qui interrompt le flot normal ; en Perl, levée par die et rattrapée par eval/try.
die
Lève une exception : arrête le programme (sauf s'il est rattrapé) et écrit le message sur STDERR.
warn
Écrit un avertissement sur STDERR sans interrompre l'exécution.
eval { }
Exécute un bloc en rattrapant tout die ; le programme survit et l'erreur atterrit dans $@.
$@
Variable spéciale contenant le message de la dernière exception rattrapée (vide si aucune).
$!
Message d'erreur du système d'exploitation après un appel raté (open, close…).
Try::Tiny
Module CPAN offrant try/catch/finally ; l'erreur arrive dans $_.
croak / carp
Variantes de die/warn (module Carp) qui attribuent l'erreur à l'appelant.

Récap et vérification

  • die lève une exception ; warn avertit sans arrêter.
  • eval { … } rattrape le die ; l'erreur est dans $@.
  • Idiome sûr : eval { …; 1 } or do { … } — teste le retour, pas seulement $@.
  • Try::Tiny donne un try/catch clair ; Carp (croak) blâme l'appelant.

Vérifie ta compréhension

  1. Quelle est la différence entre die et warn ?
  2. Pourquoi tester le retour de eval plutôt que $@ seul ?
  3. Quand préférer croak à die ?
