Sous-programmes et portée

~50 min Intermédiaire Prérequis : leçon 6

À la fin de cette leçon, tu sauras

  • définir des sous-programmes (sub) et récupérer les arguments (@_) ;
  • renvoyer scalaires et listes selon le contexte ;
  • maîtriser la portée lexicale avec my ;
  • écrire des fonctions claires (déballage des arguments).
Sommaire de la leçon

Dès qu'un script dépasse quelques dizaines de lignes, on le découpe en sous-programmes (les fonctions de Perl). Ils nomment une logique, la rendent réutilisable, et structurent le code. Voyons comment les définir, leur passer des arguments et maîtriser la portée des variables.

Définir un sous-programme

Le mot-clé sub, un nom, un bloc. On l'appelle ensuite par son nom. La dernière expression évaluée est renvoyée automatiquement, mais return rend l'intention claire.

Les arguments arrivent dans @_

Perl ne déclare pas les paramètres dans la signature : tous les arguments arrivent dans le tableau spécial @_. L'idiome moderne consiste à les déballer aussitôt dans des variables nommées avec my.

Le déballage en première ligne rend la signature lisible, malgré l'absence de paramètres formels.

Recevoir une liste d'arguments

Comme @_ est un tableau, on peut récupérer un nombre variable d'arguments : on déballe les premiers, et le reste va dans un tableau.

Astuce

Dans un sous-programme, shift sans argument opère sur @_. L'idiome my $premier = shift; retire et récupère le premier argument — pratique pour isoler l'objet (my $self = shift; en POO) avant de déballer le reste.

Renvoyer selon le contexte

Un sous-programme peut renvoyer une liste ou un scalaire. Comme on l'a vu, le contexte d'appel décide. wantarray permet même d'adapter le retour.

La portée lexicale avec my

my crée une variable locale au bloc où elle est déclarée. Hors de ce bloc, elle n'existe pas. C'est ce qui rend les sous-programmes étanches et le code prévisible — la raison d'être de use strict.

Les fermetures (closures)

Un sous-programme anonyme peut capturer une variable de son environnement : c'est une fermeture. Utile pour fabriquer des générateurs ou des compteurs privés.

Cas réel : factoriser une règle métier

Un script de facturation calculait la TVA à quinze endroits, chaque fois recopiée — et le jour où le taux a changé, deux copies ont été oubliées. Extraire sub ttc { my ($ht, $taux) = @_; $taux //= 0.20; return $ht * (1 + $taux); } a réglé le problème pour de bon : une seule définition, un seul endroit à modifier. C'est la première vertu d'un sous-programme — nommer une logique pour ne l'écrire qu'une fois.

Pièges fréquents

Piège fréquent

Passer un tableau ET un scalaire à une fonction : ma_fonction(@liste, $x) aplatit tout dans @_, et tu ne sais plus où finit la liste ! Passe plutôt une référence (leçon suivante) : ma_fonction(\@liste, $x).

Pour aller plus loin

Pour aller plus loin

Perl moderne (5.36+) propose enfin des signatures natives : use feature 'signatures'; sub addition($a, $b) { $a + $b }. Plus besoin de déballer @_ à la main — une syntaxe bienvenue pour le nouveau code.

Glossaire

Sous-programme (sub)
Bloc de code nommé et réutilisable : la « fonction » de Perl.
@_
Tableau spécial où arrivent tous les arguments d'un sous-programme, dans l'ordre.
Déballage (unpacking)
Copie immédiate de @_ dans des variables nommées (my ($a,$b) = @_;) pour la lisibilité.
Portée lexicale
Zone de visibilité d'une variable my : le bloc où elle est déclarée, et lui seul.
my
Déclare une variable à portée lexicale ; exigée par use strict.
Contexte (d'appel)
Liste ou scalaire : il décide de la valeur renvoyée par un sous-programme ou une expression.
Fermeture (closure)
Sous-programme anonyme qui capture et conserve une variable de son environnement (état privé persistant).

Récap et vérification

  • sub nom { … } définit un sous-programme ; return renvoie une valeur.
  • Les arguments arrivent dans @_ ; on les déballe avec my ($a, $b) = @_;.
  • my crée une variable à portée lexicale (locale au bloc).
  • Un sub anonyme peut former une fermeture qui capture son état.

Vérifie ta compréhension

  1. Où arrivent les arguments d'un sous-programme ?
  2. Que fait my à une variable ?
  3. Pourquoi éviter de passer plusieurs tableaux directement à une fonction ?
