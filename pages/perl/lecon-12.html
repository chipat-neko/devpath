Les expressions régulières avancées

~42 min Avancé Prérequis : leçons 4 et 5

À la fin de cette leçon, tu sauras

  • nommer tes captures avec (?<nom>…) et les lire dans %+ ;
  • regarder sans consommer grâce aux assertions (look-around) ;
  • aérer et documenter un motif avec le modificateur /x ;
  • distinguer tr/// de s/// et maîtriser la gourmandise.
Sommaire de la leçon

En leçon 4, tu as découvert les motifs de base : classes de caractères, quantificateurs, ancres. Perl va bien plus loin : c'est le langage dont les expressions régulières servent de référence à tous les autres. Cette leçon te donne les outils qui font la différence entre « ça marche à peu près » et un motif précis, lisible et robuste.

Nommer ses captures

Numéroter les captures ($1, $2…) devient vite illisible dès qu'un motif en compte plusieurs. Perl permet de leur donner un nom avec la syntaxe (?<nom>…). Les résultats atterrissent alors dans le hachage spécial %+.

Le code se relit tout seul : $+{annee} dit ce qu'il contient, là où $1 obligeait à recompter les parenthèses. On peut même réutiliser une capture dans le motif avec \g{nom}.

Les assertions : regarder sans consommer

Une expression régulière avance normalement en « consommant » les caractères qu'elle reconnaît. Les assertions (ou look-around) permettent de vérifier ce qui entoure une position sans l'inclure dans la correspondance. Quatre formes :

Astuce

Un look-behind doit avoir une longueur bornée (255 caractères au plus) : (?<=prix: ) et (?<=\d{1,3} ) fonctionnent, mais (?<=\d+ ) échoue. Pour du variable, capture plutôt le contexte dans un groupe nommé et ignore-le à la lecture.

Aérer un motif : le modificateur /x

Un motif complexe devient vite un mur de symboles. Le modificateur /x ordonne à Perl d'ignorer les espaces et les retours à la ligne dans le motif, ce qui autorise l'indentation et les commentaires. Le même motif, mais lisible :

Les autres modificateurs utiles

Ils se cumulent (/gims) et changent le comportement du motif :

tr/// : la translittération

Attention à ne pas confondre s/// (substitution par motif) et tr/// (translittération, caractère par caractère). tr/// ne connaît pas les regex : il remplace chaque caractère d'un ensemble par le caractère de même rang dans l'autre. Il est très rapide et sait aussi compter.

Captures multiples et gourmandise

Avec /g en contexte de liste, un motif renvoie toutes les correspondances d'un coup :

Astuce : liste vs scalaire avec /g

Le même /(\d+)/g se comporte différemment selon le contexte : affecté à un tableau (my @tous = ...) il renvoie toutes les captures d'un coup ; utilisé dans un while (... =~ /.../g) il les rend une par une, position après position, ce qui est idéal pour traiter un gros texte au fil de l'eau sans tout charger.

Reste le piège classique : par défaut, les quantificateurs sont gourmands (greedy) — ils prennent le plus possible. Ajoute ? pour les rendre paresseux.

Attention : gourmand vs paresseux

Sur <b>gras</b>, le motif /<(.*)>/ capture b>gras</b (tout, jusqu'au dernier >) ! Le motif paresseux /<(.*?)>/ s'arrête au premier > et capture b. Le ? change tout.

Cas réel : extraire les champs d'un log Apache

Une ligne de journal web ressemble à 192.168.1.10 - - [26/Jul/2026:14:03:22 +0200] "GET /index.html HTTP/1.1" 200 1024. Un seul motif à groupes nommés en découpe tous les champs : /(?<ip>\S+).+?"(?<methode>\w+) (?<url>\S+).+?" (?<code>\d{3})/. On lit ensuite $+{ip}, $+{methode}, $+{code}… C'est exactement ce que font les outils d'analyse de logs, et la base du mini-projet à venir. Les .+? paresseux évitent de « déborder » sur les guillemets suivants.

Antisèche

Glossaire

Capture
Portion de la chaîne mémorisée par un groupe entre parenthèses ; relue par $1, $2… (position) ou $+{nom} (nom).
Groupe nommé
Capture identifiée par un nom avec (?<nom>…) ; sa valeur se lit dans le hachage %+ via $+{nom}.
Rétro-référence (backreference)
Renvoi, à l'intérieur du motif, vers une capture déjà faite : \1 ou \g{nom} exige la même sous-chaîne (utile pour détecter un mot répété).
Assertion (look-around)
Condition qui vérifie le contexte (avant ou après) sans l'inclure dans la correspondance : (?=), (?!), (?<=), (?<!).
Look-ahead / look-behind
Assertion regardant respectivement après ou avant la position courante.
Modificateur
Lettre après le motif qui change son comportement : /i, /g, /m, /s, /x, /r.
qr//
Opérateur qui précompile un motif dans une variable réutilisable.
tr///
Translittération : remplace, supprime ou compte des caractères un à un (sans regex).
Gourmand / paresseux
Un quantificateur gourmand (*, +) prend le plus possible ; suivi de ? il devient paresseux et prend le moins possible.

Récap et vérification

  • Nomme tes captures avec (?<nom>…) et lis-les dans %+ pour un code clair.
  • Les assertions vérifient le contexte sans le consommer.
  • /x aère un motif et autorise les commentaires ; qr// le précompile.
  • tr/// n'est pas une regex : il translittère (et sait compter).
  • Ajoute ? pour rendre un quantificateur paresseux.

Vérifie ta compréhension

  1. Comment lit-on une capture nommée (?<an>…) ?
  2. Que fait (?=…) par rapport à un groupe normal ?
  3. En quoi tr/// diffère-t-il de s/// ?
