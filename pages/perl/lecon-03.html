Module 1 · Les bases de Perl — Leçon 03

Conditions, boucles et contexte

~50 min Intermédiaire Prérequis : leçon 2

À la fin de cette leçon, tu sauras

  • écrire conditions et boucles (if, unless, while, for, foreach) ;
  • utiliser les modificateurs d'instruction (print $x if $cond) ;
  • comprendre le contexte scalaire vs liste ;
  • exploiter la variable spéciale $_.
Sommaire de la leçon

Tu sais stocker des données ; il te faut maintenant décider et répéter. Perl offre les structures de contrôle habituelles, mais avec deux spécificités très « perliennes » : les modificateurs d'instruction et, surtout, le contexte — une idée centrale qui change la valeur d'une expression selon l'endroit où on l'utilise.

Conditions : if, elsif, unless

La condition se place entre parenthèses, le bloc entre accolades (toujours obligatoires en Perl). unless est un if négatif, parfois plus lisible.

Comparaisons : nombres vs chaînes

Point crucial : Perl a deux jeux d'opérateurs. Pour les nombres : ==, !=, <, >, <=, >=. Pour les chaînes : eq, ne, lt, gt, le, ge. Se tromper donne des résultats surprenants.

Utilise == pour les nombres, eq pour les chaînes : une erreur classique et silencieuse.

Boucles

while répète tant qu'une condition tient ; for/foreach parcourt une liste (les deux mots sont interchangeables en Perl).

La variable spéciale $_

Perl a une variable « par défaut », $_, utilisée implicitement par de nombreuses fonctions. Dans un foreach sans variable nommée, c'est $_ qui prend chaque valeur.

Les modificateurs d'instruction

Très idiomatique : on peut placer la condition ou la boucle après l'instruction, sans accolades, pour les cas simples. C'est concis et lisible quand le corps tient en une ligne.

Cas réel : un filtre en une ligne

Le modificateur if postfixé brille quand on trie des lignes. Pour n'afficher que les lignes contenant « ERROR » d'un journal : while (<STDIN>) { print if /ERROR/; }. La condition tient à droite, $_ reçoit chaque ligne : c'est le genre de micro-outil qu'un·e ops écrit en quelques secondes, sans quitter le terminal.

Bonne pratique : next et last en postfixe

La forme postfixée sert surtout à écrire des gardes en tête de boucle : next if $ligne =~ /^#/; saute les commentaires, last unless $ok; arrête net dès qu'une condition tombe. On lit l'intention (« passer »/« s'arrêter ») avant sa condition, sans indenter tout le corps dans un if : le code reste plat et se parcourt d'un coup d'œil.

Le contexte : scalaire vs liste

Voici LE concept qui distingue Perl. Une même expression peut valoir des choses différentes selon le contexte dans lequel on l'utilise. Un tableau en contexte scalaire donne son nombre d'éléments ; en contexte liste, ses éléments.

Beaucoup de fonctions se comportent différemment selon le contexte. C'est puissant, mais source de surprises : garde l'idée en tête.

Pièges fréquents

Ce qui est « faux » en Perl : une courte liste

Perl n'a pas de type booléen dédié. Dans un test, seules cinq valeurs sont fausses : 0, la chaîne "0", la chaîne vide "", undef, et la liste vide. Tout le reste est vrai — y compris des valeurs qui surprennent : "0.0" est vrai (c'est "0" exactement qui est faux), "00" est vrai, et " " (une espace) est vrai. D'où l'astuce fréquente if (defined $x) quand on veut distinguer « absent » de « égal à zéro ».

Piège fréquent

Comparer des chaînes avec == : "chat" == "chien" renvoie vrai ! Car les deux chaînes valent 0 en contexte numérique. Pour comparer des chaînes, c'est toujours eq. use warnings t'avertira de ce genre d'erreur.

Pour aller plus loin

Pour aller plus loin

L'opérateur ternaire cond ? a : b existe aussi, et le given/when (équivalent du switch) a existé mais est aujourd'hui déconseillé : préfère une cascade de if/elsif ou une table de dispatch (un hachage de sous-programmes).

Glossaire

unless
Condition inversée : unless (C) équivaut à if (not C) ; plus lisible pour un cas négatif simple.
Comparaison numérique vs textuelle
Deux jeux d'opérateurs distincts : ==, <… pour les nombres ; eq, lt… pour les chaînes.
Opérateur de plage ..
Génère une liste d'entiers consécutifs : 1 .. 5 donne 1, 2, 3, 4, 5.
Modificateur d'instruction
Condition ou boucle placée après l'instruction, sans accolades : print if $ok;.
$_
Variable « par défaut » utilisée implicitement par de nombreuses fonctions et par foreach/map/grep sans variable nommée.
Contexte
Cadre d'évaluation d'une expression : en contexte scalaire un tableau rend sa taille, en contexte liste ses éléments.
Contexte scalaire
Évaluation attendant une valeur unique (affectation à un $, scalar, comparaison numérique) : un tableau y rend son nombre d'éléments.
Contexte de liste
Évaluation attendant une suite de valeurs (affectation à un @, arguments d'appel) : un tableau y rend tous ses éléments.
Valeur fausse
En Perl, seules 0, "0", "", undef et la liste vide sont fausses dans un test ; toute autre valeur est vraie.
Table de dispatch
Hachage associant des clés à des sous-programmes, alternative propre à une longue cascade de if/elsif.

Récap et vérification

  • if/elsif/else/unless décident ; les accolades sont obligatoires.
  • Comparaisons numériques (==, <) vs chaînes (eq, lt) : ne pas confondre.
  • $_ est la variable par défaut ; les modificateurs (… if cond) condensent les cas simples.
  • Le contexte (scalaire vs liste) change la valeur d'une expression.

Vérifie ta compréhension

  1. Quel opérateur pour comparer deux chaînes ? Et deux nombres ?
  2. Que vaut my $n = @tableau; et pourquoi ?
  3. À quoi sert $_ ?
