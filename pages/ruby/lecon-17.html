Module 5 · Le web avec Rails — Leçon 17

ActiveRecord et les vues

~44 min Intermédiaire Leçon 16 requise

À la fin de cette leçon, tu sauras

  • interroger la base avec ActiveRecord (find, where, order) ;
  • ajouter des validations à un modèle ;
  • relier deux modèles par une association ;
  • afficher des données dans une vue ERB.
Sommaire de la leçon

Dans la leçon précédente, le scaffolding a généré une application qui marche. Mais le vrai pouvoir de Rails se trouve dans deux pièces : ActiveRecord, qui traduit tes objets Ruby en lignes de base de données, et les vues ERB, qui mêlent HTML et Ruby pour afficher les données. Cette leçon entre dans ces deux pièces : tu n'écriras presque pas de SQL, et tes pages s'adapteront aux données.

ActiveRecord : le modèle parle à la base

Un modèle Rails hérite de ApplicationRecord (lui-même un ActiveRecord). Par la seule convention — une classe Article correspond à la table articles — il sait lire et écrire en base sans une ligne de SQL.

Ces méthodes (find, where, order, create, save) sont le quotidien d'ActiveRecord. Elles renvoient des objets Ruby, et les requêtes sont chaînables : Article.where(...).order(...).limit(5) compose une seule requête SQL efficace.

Cas réel

Une page listant 50 articles et, pour chacun, le nom de son auteur, se met à ramer. Dans les logs : 51 requêtes SQL — une pour la liste, puis une par article pour aller chercher l'auteur. C'est le fameux problème N+1, la cause la plus courante de lenteur d'une application Rails. Le remède tient en un mot : Article.includes(:auteur), qui charge tous les auteurs en une requête supplémentaire (eager loading). La liste passe de 51 requêtes à 2. Surveiller le nombre de requêtes dans les logs est un réflexe de tout développeur Rails.

Les vues ERB

Une vue Rails est un fichier ERB (Embedded Ruby) : du HTML dans lequel on insère du Ruby avec deux balises. <%= ... %> affiche une valeur ; <% ... %> exécute du code sans rien afficher (boucles, conditions).

La variable @articles, préparée par l'action index du contrôleur (leçon 16), est ici parcourue. <%= %> insère chaque titre et contenu ; <% %> porte la boucle each. Les helpers comme link_to génèrent les liens HTML à partir des routes — encore la convention qui t'épargne du code.

Échappement automatique

Rails échappe automatiquement le HTML dans <%= %> : si un titre contient <script>, il s'affiche en texte, pas exécuté. C'est une protection contre les failles XSS offerte par défaut. Tu n'as rien à faire pour en bénéficier ; il faut au contraire un effort explicite (raw, html_safe) pour la désactiver — à n'utiliser qu'en connaissance de cause.

Astuce

rails console est ton meilleur ami pour apprendre ActiveRecord : tu y tapes des requêtes et tu vois le SQL généré et les objets renvoyés, en direct, sans toucher au navigateur. Lance-la avec rails c.

Glossaire

ActiveRecord
L'ORM de Rails : chaque table devient une classe, chaque ligne un objet ; des méthodes chaînées sont traduites en SQL au dernier moment.
Relation
Objet requête renvoyé par where, order, limit… ; on l'enchaîne sans toucher la base tant qu'on ne l'énumère pas.
Évaluation paresseuse
Stratégie où le SQL n'est envoyé qu'au moment où l'on a réellement besoin des données (itération, to_a, affichage), pas à chaque appel chaîné.
Validation
Règle déclarée dans le modèle (validates …) vérifiée avant chaque sauvegarde ; en cas d'échec, save renvoie false et errors détaille pourquoi.
Association
Lien entre modèles déclaré par has_many et belongs_to ; ActiveRecord fournit alors la navigation entre objets reliés.
Clé étrangère
Colonne (par convention article_id) qui, dans la table des commentaires, référence l'identifiant de l'article parent.
ERB
Embedded Ruby : gabarit HTML où <%= %> affiche une valeur et <% %> exécute du code sans rien afficher.
Problème N+1
Explosion du nombre de requêtes (une par élément d'une liste) ; se corrige avec includes (eager loading), qui précharge les données liées.

Récap et vérification

  • ActiveRecord : find, where, order, create, save — du Ruby, pas du SQL.
  • Validations dans le modèle : validates :titre, presence: true protège la base.
  • Associations : has_many / belongs_to relient les modèles sans jointure manuelle.
  • Vues ERB : <%= %> affiche, <% %> exécute ; le HTML est échappé par défaut.
