Module 4 · Ruby en pratique — Leçon 12

Fichiers, erreurs et robustesse

~44 min Intermédiaire Prérequis : leçon 11

À la fin de cette leçon, tu sauras

  • savoir lire et écrire des fichiers avec File.read, File.write, File.foreach et le mode bloc de File.open ;
  • savoir intercepter une erreur avec begin/rescue/ensure en ciblant la bonne classe d'exception ;
  • savoir lever une exception avec raise et créer sa propre classe d'erreur ;
  • savoir sauvegarder et recharger des données avec le module JSON.
Sommaire de la leçon

Jusqu'ici, tes programmes vivaient dans leur bulle : tout disparaissait à la fin de l'exécution, et rien ne pouvait vraiment mal tourner. Dans la vraie vie, un programme lit des fichiers qui n'existent pas toujours, reçoit des données mal formées et doit survivre à l'imprévu. C'est exactement le sujet de cette leçon : parler au disque dur, encaisser les erreurs avec élégance, et sauvegarder tes données pour les retrouver au prochain lancement.

Fidèle à sa philosophie, Ruby rend tout cela étonnamment lisible : une ligne pour lire un fichier, un bloc pour garantir sa fermeture, et une gestion d'erreurs qui se lit presque comme une phrase.

Lire et écrire un fichier en une ligne

La classe File propose deux méthodes de classe qui couvrent la majorité des besoins : File.read renvoie tout le contenu sous forme de String, et File.write écrit une chaîne dans un fichier (en le créant ou en l'écrasant).

Lecture et écriture complètes : simple, direct, idiomatique.

Note

File.write sans option mode: écrase le fichier existant. C'est voulu : si tu veux compléter, dis-le explicitement avec mode: "a".

begin / rescue / ensure / else

Pour intercepter une exception, on entoure le code risqué d'un bloc begin…end et on attrape avec rescue. Deux clauses optionnelles complètent le tableau : else s'exécute si aucune erreur n'a eu lieu, et ensure s'exécute dans tous les cas — parfait pour le nettoyage.

Cas réel

Une petite application de prise de notes sauvegardait ses données à chaque frappe par un simple File.write("notes.json", JSON.pretty_generate(notes)). Un jour, l'ordinateur d'un utilisateur s'est éteint (batterie vide) pile pendant l'écriture : le fichier s'est retrouvé coupé au milieu d'un objet. Au redémarrage, JSON.parse levait une JSON::ParserError et l'appli refusait de s'ouvrir — toutes les notes semblaient perdues. La parade tient en deux lignes : écrire d'abord dans un fichier temporaire, puis le renommer sur le fichier final avec File.rename. Ce renommage est atomique pour le système : à tout instant, notes.json est soit l'ancienne version complète, soit la nouvelle complète, jamais un entre-deux corrompu. C'est le patron « write-then-rename », utilisé par les vrais éditeurs et bases de données.

Pièges fréquents

Piège fréquent

N'écris jamais rescue Exception. Tu attraperais aussi Interrupt (le Ctrl+C de l'utilisateur !) et SignalException : ton programme deviendrait impossible à arrêter proprement. rescue => e (qui cible StandardError) suffit toujours.

Piège fréquent

Un rescue vide qui ne fait rien (rescue; end) avale les erreurs en silence : le bug devient invisible et resurgira ailleurs, bien plus difficile à diagnostiquer. Gère l'erreur, journalise-la, ou laisse-la remonter — mais ne l'étouffe pas.

  • File.write sans mode: "a" écrase le fichier existant — vérifie ton intention avant chaque appel.
  • retry sans compteur de tentatives = boucle infinie garantie si l'erreur persiste.
  • JSON.parse sans symbolize_names: true renvoie des clés String : taches.first[:titre] donnerait nil alors que taches.first["titre"] fonctionne. Choisis un style et garde-le partout.
  • Hérite de StandardError pour tes exceptions, jamais de Exception directement — sinon le rescue => e standard ne les attrapera pas.

Pour aller plus loin

Pour aller plus loin

La bibliothèque standard regorge d'outils complémentaires : Pathname offre une approche objet des chemins (Pathname.new(__dir__) / "data" / "x.json"), FileUtils copie et déplace des dossiers entiers, et YAML est une alternative à JSON très lisible pour les fichiers de configuration. Côté exceptions, explore e.cause : quand tu relances une nouvelle exception depuis un rescue, Ruby y range automatiquement l'exception d'origine — indispensable pour déboguer des erreurs en cascade dans de vraies applications.

Antisèche

Glossaire

Exception
Objet qui décrit une erreur et interrompt le programme s'il n'est pas intercepté. En Ruby, les erreurs sont des objets comme les autres, organisés en hiérarchie de classes.
StandardError
Classe mère des erreurs « normales » que ton code doit gérer, et cible par défaut d'un rescue sans classe. Tes exceptions maison en héritent.
begin / rescue
Bloc qui isole du code risqué (begin) et intercepte l'exception d'une classe donnée (rescue Classe => e), laissant remonter les autres.
ensure
Clause exécutée dans tous les cas, qu'une erreur soit survenue ou non : l'endroit idéal pour libérer une ressource.
raise
Lève une exception. raise seul, dans un rescue, relance l'exception courante telle quelle.
Mode bloc (File.open)
Forme File.open(…) { |f| … } qui ferme le fichier automatiquement à la sortie du bloc, même en cas d'exception.
retry
Dans un rescue, relance le begin depuis le début ; à borner par un compteur de tentatives sous peine de boucle infinie.
Sérialisation
Transformation d'objets en texte (ici JSON) pour les stocker ou les transmettre ; JSON.parse fait l'opération inverse (désérialisation).

Récap et vérification

  • File.read / File.write pour tout lire ou écrire, File.foreach pour traiter ligne à ligne sans saturer la mémoire.
  • La forme bloc File.open("f", "w") { |f| … } garantit la fermeture du fichier, erreur ou pas.
  • File.join(__dir__, …) construit des chemins fiables ; Dir.glob liste les fichiers par motif.
  • On intercepte avec begin/rescue Classe => e/else/ensure, en ciblant toujours StandardError ou plus précis — jamais Exception.
  • raise Classe, "message" lève une erreur ; une classe maison hérite de StandardError ; retry réessaie (avec compteur !).
  • JSON.pretty_generate + File.write pour sauvegarder, JSON.parse(…, symbolize_names: true) pour recharger.
