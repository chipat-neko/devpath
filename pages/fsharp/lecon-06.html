Gestion d'erreurs : option et Result

~50 min Avancé Prérequis : leçon 5

À la fin de cette leçon, tu sauras

  • remplacer null par option (Some/None) ;
  • gérer les erreurs avec Result ;
  • enchaîner avec Option.bind/map ;
  • découvrir les computation expressions.
Sommaire de la leçon

Comme OCaml, F# bannit le null dangereux au profit de types explicites : option pour l'absence, Result pour l'échec. Et pour enchaîner proprement plusieurs opérations faillibles, F# offre les computation expressions, une syntaxe élégante. Le résultat : des erreurs visibles dans les types, impossibles à ignorer.

Le type option

Une valeur qui peut être absente a le type 'T option : soit Some valeur, soit None. Le type force à traiter le cas « absent ».

Beaucoup de fonctions de la stdlib renvoient une option : List.tryFind, Map.tryFind, Int32.TryParse…

Manipuler une option

On déballe par match, ou avec le module Option : Option.map (transformer si présent), Option.defaultValue (valeur de repli).

Le type Result

Pour une opération qui peut échouer avec une raison, le type Result<'Succes, 'Erreur> : Ok valeur ou Error raison. L'erreur fait partie du type de retour.

Enchaîner avec bind

Le problème classique : enchaîner plusieurs opérations qui renvoient chacune une option ou un Result, en court-circuitant à la première absence/erreur. Option.bind et Result.bind le font élégamment.

Les computation expressions

F# pousse plus loin avec les computation expressions : une syntaxe en bloc (let!) qui enchaîne des calculs « dans un contexte » (option, result, async…) sans imbrication. Avec une bibliothèque comme FsToolkit :

C'est l'équivalent F# du ? de Rust ou du do de Haskell : enchaîner sans pyramide de match.

Astuce

Ne « sors » de l'option/Result qu'au tout dernier moment : garde le type le plus longtemps possible et applique Option.defaultValue (ou un match) juste au bord, à l'affichage. Le module offre aussi Option.iter (agir seulement si présent), Result.map (transformer le succès) et Result.mapError (reformuler l'erreur) — souvent plus lisibles qu'un match complet.

Cas réel

Tony Hoare, inventeur de la référence null en 1965, l'a lui-même appelée son « erreur à un milliard de dollars » tant elle a causé de plantages. La famille ML — dont F# — l'évite par l'option. Côté industrie, Jet.com (e-commerce racheté par Walmart ~3,3 milliards $ en 2016) fut bâti en grande partie en F# : le style option/Result y rend « les états illégaux non représentables ». La validation d'un formulaire d'inscription en est l'exemple type : chaque règle renvoie un Result, bind les enchaîne, et la première qui échoue court-circuite et remonte son message — le railway-oriented programming de Scott Wlaschin.

Pièges fréquents

Piège fréquent

Utiliser Option.get pour « sortir » la valeur sans gérer None : si l'option est None, Option.get lève une exception — tu réintroduis le plantage que option évitait ! Préfère match, Option.map ou Option.defaultValue.

Pour aller plus loin

Pour aller plus loin

Attention en interop : les bibliothèques .NET écrites en C# peuvent renvoyer null. F# 9 ajoute des types de référence nullables pour gérer ce cas à la frontière ; côté F# pur, on convertit en option dès que possible (Option.ofObj).

Glossaire

option
Type d'une valeur éventuellement absente : Some x (présente) ou None (absente). Remplace le null.
Some / None
Les deux constructeurs du type option : la valeur entourée, ou le vide explicite.
Result
Type d'une opération faillible : Ok x (succès portant la valeur) ou Error e (échec portant une raison).
Ok / Error
Les deux constructeurs de Result ; contrairement à None, Error transporte un détail d'échec.
bind
Enchaîne une fonction qui renvoie elle-même une option/Result, en court-circuitant au premier None/Error.
Option.defaultValue
Fournit une valeur de repli quand l'option est None ; sortie sûre de l'option.
Computation expression
Bloc (result { let! … }, async { … }) qui enchaîne des calculs « dans un contexte » sans imbrication.
Railway-oriented programming
Métaphore (Scott Wlaschin) où Ok et Error sont deux rails : le premier échec fait basculer sur la voie d'erreur jusqu'à la sortie.

Récap et vérification

  • option (Some/None) remplace null ; Result (Ok/Error) gère les erreurs.
  • Option.map, Option.defaultValue, Option.bind manipulent ces types proprement.
  • Les computation expressions (result { let! ... }) enchaînent sans pyramide.
  • Évite Option.get ; traite toujours le cas None/Error.
