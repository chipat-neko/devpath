Module 3 · F# en pratique — Leçon 07

Asynchrone et interop .NET

~55 min Avancé Prérequis : leçon 6

À la fin de cette leçon, tu sauras

  • écrire du code asynchrone (async, task) ;
  • appeler des bibliothèques .NET et du C# ;
  • utiliser classes et interfaces quand c'est utile ;
  • comprendre l'interopérabilité bidirectionnelle.
Sommaire de la leçon

La grande force de F#, c'est de vivre sur .NET : tu écris du fonctionnel élégant et tu accèdes à tout l'écosystème C# — bibliothèques, asynchrone moderne, web, cloud. Cette leçon couvre l'asynchrone et l'interopérabilité, là où F# révèle son avantage décisif sur les langages fonctionnels isolés.

L'asynchrone : async

Pour des opérations longues (réseau, fichiers) sans bloquer, F# a le bloc async. On y écrit du code séquentiel ; let! attend un résultat asynchrone.

let! attend une valeur asynchrone ; do! attend une action ; return produit le résultat.

Paralléliser

On lance plusieurs calculs asynchrones en parallèle avec Async.Parallel : ils s'exécutent ensemble, on récupère tous les résultats.

task pour l'interop

F# propose aussi le bloc task, qui produit un Task .NET — le type asynchrone natif de C#. À privilégier quand on interagit avec des bibliothèques .NET asynchrones (ASP.NET, bases de données…).

Appeler des bibliothèques .NET

Tout ce que C# peut faire, F# le peut. On utilise les classes .NET directement : System.Math, System.DateTime, les collections, les fichiers…

Le point (.Méthode()) et les majuscules trahissent du code « à la C# » : c'est l'interop, parfaitement fluide.

Les objets quand il le faut

F# n'est pas dogmatique : il sait définir des classes et implémenter des interfaces .NET, indispensable pour s'intégrer à des frameworks orientés objet. On le réserve aux frontières avec le monde C#.

Interop bidirectionnelle

L'interop va dans les deux sens : du code C# peut utiliser une bibliothèque F#, et inversement. On peut donc écrire le cœur métier en F# (sûr, concis) et l'exposer à une application C# existante — ou l'inverse. Beaucoup d'équipes adoptent F# ainsi, par petites touches.

Astuce

Choisis le bon bloc : task { } dès que tu appelles des API .NET qui renvoient un Task (ASP.NET, EF Core, HttpClient) — interop et perf optimales ; async { } pour le F# pur et la composition (Async.Parallel, annulation). Et n'appelle Async.RunSynchronously qu'au point d'entrée du programme : l'utiliser au milieu du code rebloque un thread et gâche tout l'intérêt de l'asynchrone.

Cas réel

Les async workflows de F# (2007) ont directement inspiré le async/await de C# 5 (2012), conçu par la même équipe autour de Don Syme — un modèle depuis repris par JavaScript, Python, Rust… F# a donc « essuyé les plâtres » de l'asynchrone moderne. Sur le terrain, l'interop bidirectionnelle est la porte d'entrée de F# en entreprise : une équipe .NET garde son application C#, mais réécrit le moteur de règles ou le calcul financier en F# — plus court, typé plus finement — et l'appelle comme une simple bibliothèque.

Pièges fréquents

Piège fréquent

Oublier qu'une bibliothèque .NET peut renvoyer null ou lever une exception (conventions C#), là où le F# pur utilise option et Result. À la frontière avec .NET, convertis dès que possible (Option.ofObj) et encadre les appels qui peuvent lever.

Glossaire

async (workflow)
Bloc F# décrivant un calcul asynchrone ; différé, il ne s'exécute qu'une fois lancé (Async.RunSynchronously, Async.Start).
let! / do!
Dans un bloc de calcul, attendent une opération asynchrone : let! lie son résultat, do! attend une action sans valeur.
Async.Parallel
Combine une liste d'asyncs en un seul qui les exécute ensemble et rassemble tous les résultats.
Async.RunSynchronously
Déclenche un async et bloque jusqu'à son résultat ; à réserver au point d'entrée du programme.
task
Bloc produisant un Task .NET ; à préférer pour interopérer avec les API asynchrones C# (ASP.NET, EF Core).
Interopérabilité (interop)
Capacité de F# à utiliser tout code .NET (et réciproquement), les deux langages tournant sur le même runtime.
.NET / CLR
La plateforme et son runtime (Common Language Runtime) qui exécutent le code intermédiaire commun à F# et C#.
member
Mot-clé déclarant une méthode ou une propriété d'une classe F#, utile aux frontières orientées objet avec .NET.

Récap et vérification

  • async { ... } (avec let!/do!) pour l'asynchrone ; Async.Parallel pour paralléliser ; task pour l'interop.
  • F# accède à toutes les bibliothèques .NET (System.Math, fichiers, web…).
  • Il sait définir classes et interfaces quand l'objet est nécessaire (frontières C#).
  • Interop bidirectionnelle : F# et C# se consomment mutuellement.
