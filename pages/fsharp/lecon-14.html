Module 4 · Aller plus loin en F# — Leçon 14

Projet de synthèse : une petite bibliothèque

~55 min Avancé Prérequis : leçon 13

À la fin de cette leçon, tu sauras

  • modéliser un domaine avec des records et des unions discriminées ;
  • valider des données en renvoyant un Result ;
  • traiter une collection par pattern matching et pipelines ;
  • assembler le tout en un programme complet et lisible.
Sommaire de la leçon

Cette dernière leçon rassemble tout le cours dans un seul projet : un gestionnaire de bibliothèque. On y retrouve les records (leçon 4), les unions discriminées (leçon 4), Result (leçon 6), le pattern matching (leçon 5), l'opérateur pipe et List (leçon 3), et la composition >> (leçon 10). L'objectif : voir comment ces briques s'emboîtent dans un vrai programme, du domaine jusqu'au rapport affiché.

Le cahier des charges

On gère un petit fonds de livres. Chaque livre a un statut — disponible, emprunté par quelqu'un, ou perdu. Le programme doit : modéliser ces données, valider une année de publication, décrire chaque livre, et produire un petit rapport (combien de livres disponibles ?). Chaque besoin va tomber sur une brique précise du langage.

Étape 1 — modéliser le domaine

Un livre est un record. Son statut n'a que trois formes possibles : c'est le cas d'école d'une union discriminée, qui rend « les états illégaux non représentables ». Impossible d'oublier un cas : le compilateur les connaît tous.

Étape 2 — valider avec Result

Une année de publication doit être plausible. Plutôt que de lever une exception, on renvoie un Result (leçon 6) : Ok si tout va bien, Error avec un message sinon. L'appelant est forcé de traiter les deux cas.

Étape 3 — décrire et compter

Pour transformer un statut en phrase, on filtre par motif : le match déconstruit l'union et récupère au passage le nom de l'emprunteur. Pour le rapport, on enchaîne List.filter puis List.length dans un pipeline.

Astuce

Le pipeline se lit comme une phrase : « prends les livres, garde les disponibles, compte-les ». Chaque étape a une entrée et une sortie clairement typées ; on peut en insérer une nouvelle (par ex. List.map) au milieu sans démonter le reste. C'est la force du |> : on décrit un flux de données, pas une suite d'instructions.

Étape 4 — assembler et présenter

On réunit tout. La ligne d'affichage utilise la composition >> (leçon 10) : decrire >> printfn "%s" fabrique une seule fonction « décris puis affiche », qu'on passe à List.iter.

Cas réel

Cette progression — modéliser le domaine, puis rendre les états illégaux impossibles, puis calculer — porte un nom : le Domain-Driven Design. Scott Wlaschin en a fait un livre de référence, Domain Modeling Made Functional, très lu dans les équipes F#. L'idée qui a séduit l'industrie : en F#, le type devient la documentation et le garde-fou. Un statut de commande modélisé en union (Panier | Payée | Expédiée) interdit dès la compilation d'expédier une commande non payée — une règle métier gravée dans le code, pas seulement dans un commentaire.

Pièges fréquents

Piège fréquent

Ne pas confondre >> (composition : relie deux fonctions) et |> (pipe : passe une valeur à une fonction). decrire >> printfn "%s" fabrique une fonction ; livre |> decrire calcule une valeur. Autre piège : dans le .fsproj, Domaine.fs doit précéder Program.fs (leçon 13), sinon le programme référence des types pas encore compilés.

Pour aller plus loin

Pour aller plus loin

Pour muscler ce projet : ajoute une fonction emprunter qui renvoie un Result<Livre, string> (échec si le livre n'est pas disponible) ; regroupe le tout dans un module Bibliotheque (leçon 13) ; puis écris un test de propriété FsCheck vérifiant qu'emprunter puis rendre un livre le laisse disponible. Tu aurais alors un mini-projet .NET complet, testé, prêt à grandir.

Glossaire

Capstone
Projet de synthèse qui assemble, dans une application concrète, les notions vues au fil d'un cours.
Record
Type produit à champs nommés ({ Titre: string; Annee: int }), immuable et comparable par valeur.
Union discriminée
Type somme énumérant des cas exclusifs, dont certains portent une donnée ; rend « les états illégaux non représentables ».
Result
Type à deux cas, Ok (succès) ou Error (échec avec message), qui modélise une opération faillible sans exception.
Pattern matching
match … with : filtre une valeur par sa forme et déconstruit ses données ; l'exhaustivité est vérifiée à la compilation.
Pipe (|>)
Passe une valeur comme dernier argument d'une fonction ; enchaîné, il décrit un flux de données lisible de gauche à droite.
Composition (>>)
Combine deux fonctions en une seule : (f >> g) x vaut g (f x).
Domaine
La couche de types qui décrit les concepts métier (ici : Livre, Statut), socle sur lequel s'appuie le reste du programme.

Récap et vérification

  • On modélise d'abord le domaine : record pour les champs, union pour les cas.
  • On valide avec Result (Ok/Error), sans exception.
  • On traite par match et par pipelines List.
  • On présente via la composition >> et printfn.

Vérifie ta compréhension

  1. Pourquoi modéliser Statut par une union plutôt que par une chaîne ?
  2. Dans decrire, que capture le motif Emprunte qui ?
  3. Qu'apporte le Result renvoyé par validerAnnee ?

Mini-projet fil rouge — un inventaire

Pour clore ce cours, écrivons un petit inventaire. Il réunit un type enregistrement, des liaisons let, une liste, l'opérateur pipe |>, List (iter, map, sum) et printfn — un condensé de F#.

Ce que tu vas construire

Un type Produit (nom, prix, quantité), une fonction valeur, l'affichage de chaque article, et le total via un pipeline map → sum.

Étapes

Le type Produit

Déclare type Produit = { Nom: string; Prix: float; Quantite: int }.

La fonction valeur

Écris let valeur p = p.Prix * float p.Quantite (conversion explicite en float).

La liste

Construis let stock = [ ... ].

Afficher

Avec stock |> List.iter (fun p -> printfn "...").

Le total par pipeline

Enchaîne stock |> List.map valeur |> List.sum.

Assemble les cinq étapes en un programme complet. Essaie d'abord par toi-même, puis compare avec la solution de référence.
