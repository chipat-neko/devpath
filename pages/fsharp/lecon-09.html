Module 3 · F# en pratique — Leçon 09

Outils, écosystème et au-delà

~45 min Avancé Prérequis : leçon 8

À la fin de cette leçon, tu sauras

  • créer et structurer un projet avec dotnet ;
  • tester son code ;
  • situer F# dans le monde réel (finance, data, web) ;
  • savoir comment continuer.
Sommaire de la leçon

Tu maîtrises le langage ; voyons comment travailler en F# au quotidien. L'outillage est celui de .NET — mûr, multiplateforme, productif : le CLI dotnet pour tout gérer, des frameworks de test éprouvés, et un écosystème riche. Cette leçon te donne les clés pour démarrer un vrai projet et savoir où aller ; les leçons suivantes (module 4) approfondissent la composition, les computation expressions et la structuration d'un projet.

Le CLI dotnet

Tout passe par la commande dotnet : créer un projet, compiler, exécuter, gérer les dépendances. Pas besoin d'IDE lourd pour commencer.

NuGet est le dépôt de paquets .NET : des centaines de milliers de bibliothèques disponibles.

Structure d'un projet

Un projet F# se décrit par un fichier .fsproj (XML), qui liste les fichiers source dans l'ordre. Cet ordre compte : en F#, un fichier ne peut utiliser que ce qui est défini avant lui — une contrainte qui favorise un code sans dépendances circulaires.

Tester son code

On utilise les frameworks .NET standards : xUnit, NUnit, ou des outils plus fonctionnels comme Expecto et le property-testing avec FsCheck (générer des centaines de cas automatiquement, à la QuickCheck).

Astuce F# : les noms de fonctions entre double accents graves peuvent contenir des espaces — pratique pour des noms de tests descriptifs.

L'outillage de développement

Pour coder confortablement : VS Code avec l'extension Ionide (autocomplétion, types à la volée, REPL intégré), ou Visual Studio / Rider. Le formateur Fantomas met le code en forme automatiquement.

Où F# s'emploie

F# brille dans plusieurs domaines : la finance (modélisation de produits, calcul de risque — sa sûreté et ses unités de mesure y excellent), l'analyse de données et le scripting, le back-end web (Giraffe/Saturn), et partout où une équipe .NET veut plus de sûreté et de concision que C#. C'est un langage de niche, mais une niche productive et bien établie en entreprise.

Astuce

Pour explorer sans créer de projet, lance le REPL F# Interactive (dotnet fsi) ou écris un script .fsx exécuté par dotnet fsi script.fsx : idéal pour tester une idée ou traiter un fichier vite fait. Pendant le développement d'un projet, dotnet watch run recompile et relance à chaque sauvegarde — la boucle de retour la plus courte.

Cas réel

Né chez Microsoft Research sous la direction de Don Syme (inspiré d'OCaml), F# s'est imposé en finance pour une raison précise : ses unités de mesure. On type une valeur float<USD> ou float<m/s>, et le compilateur refuse d'additionner des dollars et des euros, ou des mètres et des pieds. C'est exactement la classe de bug qui a coûté la sonde Mars Climate Orbiter en 1999 (une confusion d'unités entre deux équipes) : là où d'autres langages laissent passer, F# la transforme en erreur de compilation.

Pièges fréquents

Piège fréquent

Oublier l'ordre des fichiers dans le .fsproj : si Program.fs utilise un type défini dans Domain.fs, Domain.fs doit être listé avant. Cette contrainte d'ordre déroute au début mais garantit un graphe de dépendances clair, sans cycles.

Pour aller plus loin

Pour aller plus loin

Pour continuer : le site officiel F# for Fun and Profit (une mine pédagogique), la documentation Microsoft Learn, et un petit projet réel. Si tu connais déjà C#, F# te donnera un autre regard ; si tu viens d'OCaml, tu seras en terrain familier avec un écosystème en prime.

Glossaire

dotnet (CLI)
L'outil en ligne de commande de .NET : crée, compile, exécute, teste un projet et gère ses dépendances.
NuGet
Le dépôt de paquets de l'écosystème .NET ; dotnet add package y récupère des bibliothèques.
.fsproj
Fichier projet (XML) qui liste les fichiers source dans l'ordre de compilation et les dépendances.
F# Interactive (fsi)
Le REPL de F# : évalue du code au fil de l'eau, y compris des scripts .fsx, sans créer de projet.
xUnit
Framework de test .NET courant ; en F#, un test s'écrit [<Fact>] let … = Assert.Equal(…).
FsCheck
Outil de property-testing : génère automatiquement des centaines de cas pour éprouver une propriété (à la QuickCheck).
Ionide
L'extension F# de VS Code : autocomplétion, types à la volée, REPL intégré.
Fantomas
Le formateur de code F# standard ; met la mise en forme en pilote automatique.

Récap et vérification

  • Le CLI dotnet gère tout : new, run, add package (NuGet), test.
  • Un projet se décrit par un .fsproj ; l'ordre des fichiers compte.
  • Tests avec xUnit/Expecto ; property-testing avec FsCheck ; outillage Ionide/Fantomas.
  • Usages : finance, données, web, équipes .NET en quête de sûreté.
