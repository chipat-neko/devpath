Module 02 · Branches & corrections — Leçon 04

Travailler avec des branches

~32 min Débutant Module 1 recommandé

À la fin de cette leçon, tu sauras

  • comprendre qu'une branche est un pointeur léger vers un commit et que HEAD suit la branche courante ;
  • lister, créer et basculer avec git branch, git switch <nom> et git switch -c <nom> ;
  • committer sur une branche en sachant que main ne bouge pas ;
  • renommer et supprimer une branche avec git branch -m et git branch -d.
Sommaire de la leçon

Jusqu'ici, tu as travaillé en ligne droite : un commit après l'autre, tous sur main. Ça marche tant que tu fais une seule chose à la fois. Mais dès que tu veux tester une idée ou corriger un bug sans risquer de casser la version qui fonctionne, tu as besoin d'un espace à part. C'est exactement le rôle des branches.

Une branche, c'est une ligne de développement indépendante. Tu peux y bricoler librement : si l'idée est bonne, tu la rapatries plus tard ; si elle est mauvaise, tu jettes la branche et main n'a jamais été touchée. Cette leçon t'apprend à créer, lister, parcourir et nettoyer tes branches.

Pourquoi une branche

Imagine que ton projet marche bien sur main et que tu veux ajouter une page de contact. Si tu modifies main directement et que tu te trompes à mi-chemin, ta version stable est cassée : impossible de la montrer ou de la déployer tant que tu n'as pas fini.

Avec une branche, tu ouvres un chantier parallèle. Tu y développes la fonctionnalité tranquillement pendant que main reste intacte et présentable. On crée typiquement une branche par :

  • une fonctionnalité (par exemple feature/page-contact) ;
  • un correctif (par exemple fix/bug-connexion) ;
  • une expérimentation que tu n'es pas sûr de garder.

L'idée centrale : ton travail principal n'est jamais en danger, parce que tes essais vivent ailleurs.

Cas réel — le correctif urgent

Tu développes depuis deux jours une grosse refonte sur feature/refonte-panier quand un bug critique tombe en production : le bouton « Payer » ne répond plus. Pas besoin de finir ta refonte ni de mélanger les deux chantiers : tu commites ton travail en cours, git switch main, puis git switch -c fix/bouton-payer. Tu corriges, tu livres, et ta refonte t'attend intacte sur sa branche. Les branches transforment une interruption stressante en simple changement de contexte.

Une branche est un pointeur léger

Voici le modèle mental qui rend tout limpide. Dans Git, l'historique est une suite de commits, chacun reliant au précédent. Une branche n'est rien d'autre qu'une étiquette qui pointe vers un commit — un simple marque-page, pas une copie de tes fichiers. C'est pour ça que créer une branche est instantané et ne coûte presque rien.

Il existe aussi un pointeur spécial nommé HEAD qui indique « où tu te trouves ». La plupart du temps, HEAD pointe vers la branche courante, qui elle-même pointe vers un commit.

« main » pointe vers le dernier commit ; « HEAD » indique que tu es sur « main ».

Lister et créer des branches

La commande git branch sans argument liste tes branches. Une étoile * marque celle où tu te trouves.

Après git branch page-contact, la nouvelle branche existe, mais l'étoile reste sur main : tu n'as pas encore bougé.

Retiens ce point important : git branch <nom> pose une nouvelle étiquette sur ton commit actuel, mais HEAD reste là où il était. Pour aller travailler dessus, il faut basculer.

Changer de branche

Pour te déplacer vers une branche, la commande moderne est git switch. Tu verras aussi git checkout dans d'anciens tutoriels : il fait la même chose ici, mais switch est plus clair car il ne sert qu'à ça.

Note

Changer de branche modifie les fichiers de ton dossier pour refléter l'état de cette branche. Si page-contact contient des commits que main n'a pas, tu verras réapparaître ou disparaître des fichiers en basculant : c'est normal, Git restaure l'instantané de la branche.

Committer sur une branche

Une fois sur ta branche, tu travailles comme d'habitude : tu modifies des fichiers, tu prépares, tu commites. La différence ? Seule la branche courante avance. main reste figée sur son dernier commit.

Pièges fréquents

  • Travailler directement sur main. Le réflexe de débutant est de tout faire sur main. Prends l'habitude d'ouvrir une branche dès que tu commences une fonctionnalité ou un correctif : ta version stable restera toujours propre.
  • Oublier sur quelle branche tu es. Tu peux committer au mauvais endroit sans t'en rendre compte. Vérifie souvent avec git status (qui affiche « On branch … ») ou git branch (l'étoile).
  • Perdre des modifications en changeant de branche. Si tu as des changements non committés, basculer peut être refusé (Git t'avertit pour ne rien écraser) ou les emporter avec toi de façon surprenante. Commite (ou mets de côté) avant de changer de branche.
  • Supprimer une branche non fusionnée. git branch -d refuse de supprimer une branche dont le travail n'a pas été rapatrié, pour te protéger. git branch -D (majuscule) force la suppression : ne l'utilise que si tu es certain de vouloir jeter ces commits.

Piège fréquent

Si git branch -d affiche « not fully merged », ce n'est pas un bug : Git te prévient que tu vas perdre du travail non fusionné. Avant de forcer avec -D, vérifie avec git log que ces commits ne te servent vraiment plus.

Pour aller plus loin

  • La fusion. Créer une branche, c'est la moitié du travail ; il faut ensuite rapatrier son contenu dans main. C'est le rôle de git merge, le sujet de la leçon suivante.
  • Conventions de nommage. Des préfixes clairs aident toute l'équipe : feature/ pour une nouveauté, fix/ pour un correctif, chore/ pour de la maintenance. Reste cohérent.
  • Allers-retours rapides. git switch - bascule vers la dernière branche utilisée ; combiné à git branch, il rend la navigation entre chantiers très fluide.

Pour aller plus loin

Tu sais maintenant diverger proprement : ouvrir des lignes de travail parallèles sans toucher à main. La prochaine étape logique est de les réunir : la leçon sur la fusion t'apprendra à rapatrier une branche terminée dans main.

Antisèche : les branches

Le mémo des commandes de cette leçon.

Glossaire

Branche
Ligne de développement indépendante ; techniquement, un simple pointeur (une étiquette) vers un commit.
HEAD
Pointeur qui indique où tu te trouves : la plupart du temps, il désigne la branche courante.
Branche courante
Celle sur laquelle tu es positionné (marquée d'un * par git branch) ; c'est la seule qui avance quand tu commites.
main
Branche principale par défaut ; on la garde stable et présentable en travaillant sur d'autres branches.
git switch
Commande moderne pour changer de branche ; -c en crée une et y bascule, - revient à la précédente.
git branch
Commande pour lister, créer, renommer (-m) ou supprimer (-d/-D) les branches.
-d vs -D
-d supprime prudemment (refuse si du travail n'est pas fusionné) ; -D force la suppression.
Diverger
Créer une histoire parallèle : deux branches partent d'un commit commun puis avancent chacune de leur côté.

Récap et vérification

  • Une branche est une ligne de développement indépendante : tu expérimentes sans toucher à main.
  • Techniquement, une branche est un pointeur léger vers un commit ; HEAD indique la branche courante.
  • git branch liste, git branch <nom> crée (sans basculer), git switch <nom> bascule, git switch -c <nom> fait les deux.
  • Quand tu commites, seule la branche courante avance ; main reste en place.
  • git branch -m renomme ; git branch -d supprime (et refuse si non fusionné, -D force).

Vérifie ta compréhension

  1. Quelle est la différence entre git branch page-contact et git switch -c page-contact ?
  2. Tu commites sur la branche page-contact : que devient le pointeur main ?
  3. Pourquoi git branch -d peut-il refuser de supprimer une branche, et que fait -D à la place ?
