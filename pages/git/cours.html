Git & GitHub : versionner son code

Tu écris du code, mais tu copies tes fichiers en projet-final-v2-vraiment-final et tu trembles avant chaque modification ? Git et GitHub te donnent un historique fiable, un filet de sécurité permanent et une vraie façon de travailler à plusieurs sans tout casser.

Bien s'équiper

Les extensions VS Code pour Git

Avant de te lancer, ouvre le panneau Extensions de VS Code (Ctrl+Shift+X) et installe ces incontournables : ils enrichissent le contrôle de source déjà intégré à l'éditeur.

À installer pour Git

  • GitLens (GitKraken) — qui a écrit quoi, quand et pourquoi, ligne par ligne.
  • Git Graph (mhutchie) — visualise branches et commits en graphe.
  • Git History (Don Jayamanne) — explore l'historique d'un fichier.
  • GitHub Pull Requests (GitHub) — gérer PR et issues depuis l'éditeur.
  • Conventional Commits (vivaxy) — messages de commit normalisés.

Cours complet

Les 24 leçons sont rédigées, des premiers commits jusqu'au rebase, aux workflows d'équipe et au fonctionnement interne de Git (objets, submodules, worktrees, hooks). Chaque notion est illustrée par des commandes que tu peux reproduire dans ton terminal.

Ce que tu vas apprendre

Objectifs du cours

À la fin du cours, tu sauras

  • créer un dépôt, indexer et enregistrer ton travail avec des commit clairs, et lire l'historique ;
  • travailler par branches, les fusionner, résoudre les conflits et annuler proprement ;
  • collaborer sur GitHub : dépôts distants (push/pull), pull requests, revue et forks ;
  • maîtriser les outils avancés : rebase, stash, tags, et adopter de bons workflows d'équipe.

Pour qui, et pourquoi

Ce cours s'adresse à toute personne qui code et qui n'a jamais vraiment apprivoisé Git : étudiant, développeur débutant, ou autodidacte qui a déjà tapé deux ou trois commandes sans bien comprendre ce qui se passait. On part du tout début, sans rien supposer de tes connaissances en versionnement.

Côté prérequis, il te faut seulement savoir ouvrir un terminal et y taper des commandes de base (te déplacer dans des dossiers, lister des fichiers). Aucun langage particulier n'est requis : Git fonctionne avec n'importe quel projet, qu'il s'agisse de Python, de JavaScript ou même d'un simple texte.

La philosophie est simple : un concept à la fois, du connu vers l'inconnu. On commence par le problème concret que Git résout, puis on construit chaque notion par-dessus la précédente, avec des exemples que tu peux reproduire chez toi. Tu n'apprends pas des commandes par cœur : tu comprends le modèle mental qui les rend logiques.

Astuce

Garde un petit projet sous la main pendant le cours. Apprendre Git en versionnant un vrai dossier à toi le rend bien plus parlant que de suivre les exemples en spectateur.

Récapitulatif

À retenir & glossaire

Les points clés du cours, puis les termes essentiels à connaître.

À retenir

  • commit enregistre un instantané ; add prépare (staging).
  • branch / switch pour les branches ; merge pour fusionner.
  • pull récupère, push publie.
  • revert annule proprement un commit déjà publié.
  • .gitignore liste ce qu'il faut ignorer.
Dépôt (repo)
Projet versionné par Git.
Commit
Instantané enregistré de l'état du projet.
Branche
Ligne de développement parallèle.
Fusion (merge)
Intégrer une branche dans une autre.
Staging (index)
Zone de préparation du prochain commit.
Remote
Dépôt distant (ex. origin sur GitHub).
