Module 07 · C++ en pratique — Leçon 21

Le système de fichiers

~34 min Intermédiaire Leçon 19 recommandée

À la fin de cette leçon, tu sauras

  • manipuler des chemins portables avec std::filesystem::path et l'opérateur / ;
  • interroger le disque (existence, type, taille, date) sans code spécifique à l'OS ;
  • parcourir un dossier, à plat ou récursivement ;
  • créer, copier, renommer, supprimer, et choisir entre exceptions et error_code.
Sommaire de la leçon

Avant C++17, lister un dossier ou tester l'existence d'un fichier imposait du code spécifique à chaque système : opendir sous Linux, FindFirstFile sous Windows, séparateurs / ou \… L'en-tête <filesystem> unifie tout cela derrière une API portable. Le même programme range des fichiers sur ton Mac, ton PC Windows et un serveur Linux.

On travaille avec trois idées : un objet chemin qui gère les séparateurs à ta place, des fonctions d'interrogation qui lisent l'état du disque, et des fonctions d'opération qui le modifient. On introduit presque toujours l'alias namespace fs = std::filesystem; pour raccourcir.

L'objet path : un chemin portable

Un fs::path représente un chemin sans forcément qu'il existe sur le disque. On le compose avec l'opérateur /, qui insère le bon séparateur selon l'OS, et on le décortique avec parent_path, filename, stem (nom sans extension) et extension.

Interroger : existence, type, taille, date

Les fonctions d'interrogation lisent l'état du disque sans le modifier. Les plus courantes : exists, is_directory, is_regular_file, file_size, last_write_time.

Piège fréquent — tester puis ouvrir (TOCTOU)

Entre un fs::exists(p) qui répond « oui » et l'ouverture qui suit, un autre programme peut supprimer le fichier. Cette course (time-of-check to time-of-use) rend le test trompeur. Le plus sûr reste souvent d'essayer l'opération et de gérer l'échec, plutôt que de vérifier d'abord.

Parcourir un dossier

Deux itérateurs listent un répertoire : directory_iterator ne descend pas dans les sous-dossiers (un seul niveau), tandis que recursive_directory_iterator traverse toute l'arborescence. Chaque élément est une directory_entry qui connaît son chemin et son type.

Créer, copier, renommer, supprimer

Les opérations modifient le disque : create_directories (crée aussi les parents manquants), copy, rename, remove (un élément) et remove_all (un dossier et tout son contenu).

Cas réel — un script qui range le dossier des téléchargements

Un dossier Téléchargements encombré de centaines de fichiers en vrac : un petit programme <filesystem> parcourt le dossier avec directory_iterator, lit l'extension() de chaque fichier, crée au besoin un sous-dossier par type (Images/, PDF/, Archives/) avec create_directories, puis déplace chaque fichier avec rename. Vingt lignes portables remplacent un rangement manuel hebdomadaire — et le même binaire tourne sur Windows comme sur Linux. C'est l'exemple type : interroger (extension), décider, opérer (créer + déplacer).

Deux styles de gestion d'erreurs

Chaque opération existe en deux versions. La version simple lève une fs::filesystem_error en cas d'échec (à attraper avec try/catch). La version qui prend un std::error_code& en dernier argument ne lève rien : elle renseigne le code, à toi de le tester. Utile dans une boucle où un échec ne doit pas tout arrêter.

Bon réflexe — compiler avec le bon standard

<filesystem> exige C++17 : compile avec -std=c++17 (ou plus récent). Sur d'anciens GCC (< 9), il fallait aussi lier -lstdc++fs ; ce n'est plus nécessaire aujourd'hui.

Pièges fréquents

Piège fréquent — remove_all est irréversible

fs::remove_all("sortie") efface le dossier et tout son contenu, sans corbeille. Une variable de chemin mal remplie (vide, ou "/") peut faire des dégâts. Valide toujours le chemin avant, et préfère un chemin absolu explicite dans les scripts destructeurs.

Pour aller plus loin

Découvre fs::space (place libre du disque), fs::canonical/fs::relative (normaliser un chemin), fs::permissions (droits), fs::create_symlink, et l'interaction avec <fstream> — un ifstream accepte directement un fs::path. Pour le format des dates de last_write_time, vois std::format et <chrono>.

Glossaire

<filesystem>
En-tête C++17 offrant une API portable pour chemins, interrogation et opérations sur fichiers/dossiers ; alias habituel namespace fs = std::filesystem;.
path
Objet représentant un chemin (pas forcément existant) ; se compose avec / et se décompose en parent_path, filename, stem, extension.
directory_iterator
Itérateur listant le contenu direct d'un dossier (un seul niveau) ; chaque élément est une directory_entry.
recursive_directory_iterator
Variante qui descend dans tous les sous-dossiers ; idéale pour sommer une taille ou chercher en profondeur.
create_directories
Crée un dossier et tous ses parents manquants d'un coup ; ne se plaint pas si le dossier existe déjà.
remove / remove_all
remove efface un seul élément ; remove_all efface un dossier et tout son contenu, de façon irréversible.
error_code
Objet renseigné par la version non lançante d'une opération ; se teste par if (ec), avec ec.message() pour le détail.
TOCTOU
Time-of-check to time-of-use : course entre un test (exists) et l'usage ; l'état du disque peut changer entre les deux, d'où l'idée d'essayer plutôt que de vérifier.

Récap et vérification

  • <filesystem> (C++17) rend le code fichiers portable ; alias namespace fs = std::filesystem;.
  • Un path se compose avec / et se décompose (filename, stem, extension) sans manipuler la chaîne.
  • Interroge avec exists, is_directory, file_size ; parcours à plat (directory_iterator) ou récursif.
  • Opère avec create_directories, copy, rename, remove ; méfie-toi de remove_all.
  • Choisis exceptions (filesystem_error) ou error_code selon que l'échec est exceptionnel ou attendu.
