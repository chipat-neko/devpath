Module 01 · Du C au C++ — Leçon 04

Classes et objets

~34 min Avancé Leçon 3 recommandée

À la fin de cette leçon, tu sauras

  • distinguer class et struct et choisir la bonne visibilité (public / private / protected) ;
  • écrire un constructeur qui initialise via la liste d'initialisation et savoir pourquoi la préférer ;
  • concevoir une classe encapsulée avec accesseurs, méthodes const et invariants protégés ;
  • utiliser this, les membres static et séparer déclaration (.h) et définition (.cpp).
Sommaire de la leçon

Une classe est le moule à partir duquel tu fabriques des objets : elle regroupe des données (l'état) et des méthodes (le comportement) sous un même toit, en contrôlant qui a le droit d'y toucher. C'est la brique centrale de la programmation orientée objet en C++, et tout le reste du cours (héritage, polymorphisme, RAII) s'appuie dessus.

Dans cette leçon, tu construis pas à pas une classe complète, un Compte bancaire, en intégrant à chaque étape un mécanisme clé du C++ moderne. L'objectif n'est pas seulement de faire compiler, mais d'écrire des classes robustes : qui garantissent leurs invariants et ne laissent pas le code appelant les casser.

class vs struct : une seule différence

En C++, class et struct sont quasi identiques. La seule différence sémantique est la visibilité par défaut des membres : private pour class, public pour struct (idem pour l'héritage).

Convention courante : struct pour un simple agrégat de données public, class dès qu'il y a des invariants à protéger.

Membres et niveaux d'accès

Une classe contient des données membres (l'état de chaque objet) et des méthodes (fonctions membres). Trois niveaux d'accès contrôlent leur visibilité : public (accessible partout), private (seulement dans la classe), protected (la classe et ses dérivées, utile avec l'héritage).

Les sections peuvent se répéter et s'enchaîner dans n'importe quel ordre. Le suffixe _ sur les données membres est une convention répandue pour les distinguer des paramètres.

Le constructeur : initialiser un objet

Un constructeur est une méthode spéciale, du même nom que la classe et sans type de retour, appelée automatiquement à la création d'un objet. Il garantit qu'aucun objet n'existe dans un état non initialisé.

La partie après le : est la liste d'initialisation : chaque membre est construit directement avec sa valeur. Le std::move évite une copie inutile de la chaîne en la déplaçant dans titulaire_ (il faut inclure <utility>).

Liste d'initialisation : pourquoi la préférer

On pourrait être tenté d'affecter les membres dans le corps du constructeur. C'est un anti-patron : les membres sont alors d'abord construits par défaut, puis réaffectés, soit deux opérations au lieu d'une.

La liste d'initialisation est de plus obligatoire dans trois cas : membres const, références (T&), et membres sans constructeur par défaut. C'est donc la forme à adopter systématiquement.

Piège fréquent

Les membres sont initialisés dans l'ordre de leur déclaration dans la classe, jamais dans l'ordre où tu les écris dans la liste. Si b_ est déclaré après a_ mais initialisé à partir de a_, range-les dans le bon ordre, sinon a_ n'est pas encore prêt. Compile avec -Wall : le compilateur t'avertit (-Wreorder).

this : le pointeur vers l'objet courant

Dans une méthode non statique, this est un pointeur vers l'objet sur lequel la méthode est appelée. On accède à un membre via this->membre, mais c'est implicite la plupart du temps. this sert surtout à lever une ambiguïté de nom ou à renvoyer l'objet courant.

Renvoyer *this sous forme de référence permet le method chaining : chaque appel rend l'objet pour enchaîner le suivant.

Méthodes const : promettre de ne rien modifier

Une méthode marquée const (le mot-clé se place après la liste de paramètres) s'engage à ne pas modifier l'état de l'objet. C'est indispensable : sur un objet const ou passé par référence constante, seules les méthodes const sont appelables.

Règle simple : toute méthode de lecture (un getter, un afficher, un calcul) doit être const. Le mot-clé explicit sur le constructeur à un argument empêche les conversions implicites surprenantes (par exemple resume(50.0) qui fabriquerait un Compte à la volée).

Encapsulation et invariants

L'encapsulation consiste à rendre les données private et à n'exposer qu'une interface public maîtrisée. L'intérêt : garantir des invariants, des règles qui doivent toujours rester vraies (ici, « le solde ne peut pas devenir négatif »). Si les données étaient publiques, n'importe qui pourrait les violer.

Le solde n'est jamais touché directement : chaque méthode valide l'opération avant de l'appliquer. En validant le dépôt via verifier dans la liste d'initialisation, l'invariant « solde >= 0 » est garanti dès la construction, sans jamais stocker une valeur invalide.

Cas réel

Le std::vector que tu utilises encapsule exactement de cette façon trois données : un pointeur vers le tampon, la taille et la capacité. Si ces champs étaient public, tu pourrais fixer la taille à 100 sans avoir alloué la mémoire correspondante — et le premier accès planterait. En les gardant private et en n'exposant que push_back, size ou at, la classe garantit qu'ils restent toujours cohérents. C'est le même principe que ta classe Compte, appliqué à l'échelle de la bibliothèque standard : l'encapsulation n'est pas un formalisme scolaire, c'est ce qui rend un type impossible à mettre dans un état invalide.

Membres static : partagés par la classe

Un membre static n'appartient pas à un objet mais à la classe : il existe en un seul exemplaire, partagé par toutes les instances. Pratique pour un compteur global, une constante de classe ou une fabrique.

Une méthode static n'a pas de this et s'appelle via la classe (Compte::nombre()). Le static inline (C++17) permet d'initialiser le membre directement dans la définition de la classe ; avant C++17, il fallait une définition séparée dans un .cpp.

Séparer déclaration (.h) et définition (.cpp)

Pour un vrai projet, on sépare l'interface (le .h, ce que voient les autres fichiers) de l'implémentation (le .cpp). Cela accélère la compilation et clarifie l'API.

L'opérateur de résolution de portée Compte:: indique à quelle classe appartient chaque définition.

Pièges fréquents

Piège fréquent

Affecter au lieu d'initialiser. Écrire solde_ = depot; dans le corps du constructeur construit puis réaffecte. Préfère la liste d'initialisation : solde_(depot), indispensable pour les membres const, références et types sans constructeur par défaut.

Piège fréquent

Données en public. Exposer solde_ en public casse l'encapsulation : n'importe qui peut le rendre négatif. Garde l'état private et passe par des méthodes qui valident.

Piège fréquent

Oublier const sur une lecture. Un getter non const ne peut pas être appelé sur un const Compte&, ce qui contamine tout le code appelant. Marque const dès qu'une méthode ne modifie rien.

Piège fréquent

Confondre class et struct. Si tu déclares tes membres juste après class sans écrire public:, ils sont private par défaut et inaccessibles de l'extérieur. Pense à ouvrir une section public: pour l'interface.

Glossaire

Classe / objet
Une classe est le moule (état + comportement) ; un objet (ou instance) en est un exemplaire avec ses propres valeurs.
Encapsulation
Rendre les données private et n'exposer qu'une interface public maîtrisée, afin de protéger les invariants.
Invariant
Règle toujours vraie pour un objet valide (ex. « solde ≥ 0 ») ; garanti par la construction et les méthodes.
Constructeur
Méthode de même nom que la classe, sans retour, appelée à la création pour initialiser l'objet.
Liste d'initialisation
Partie après : qui construit chaque membre directement ; obligatoire pour const, références et types sans constructeur par défaut.
Méthode const
Méthode s'engageant à ne pas modifier l'objet ; seule catégorie appelable sur un objet const.
this
Pointeur, dans une méthode non statique, vers l'objet courant ; *this permet le chaînage des appels.
Membre static
Membre appartenant à la classe (un seul exemplaire partagé), pas à un objet ; sans this.

Récap et vérification

  • class et struct ne diffèrent que par la visibilité par défaut (private vs public).
  • Le constructeur garantit un objet toujours initialisé ; utilise la liste d'initialisation, plus efficace et parfois obligatoire.
  • Les membres sont initialisés dans l'ordre de leur déclaration, pas celui de la liste.
  • Marque const toute méthode de lecture ; garde l'état private pour protéger les invariants.
  • Un membre static est partagé par la classe ; this pointe vers l'objet courant.
  • Sépare l'interface (.h) de l'implémentation (.cpp) pour les vrais projets.
