Module 01 · Du C au C++ — Leçon 01

Découvrir le C++

~30 min Avancé Des bases en C ou en programmation aident

À la fin de cette leçon, tu sauras

  • comprendre ce que le C++ ajoute au C (objets, généricité, STL, RAII) et où il sert ;
  • compiler et exécuter un programme avec g++ main.cpp -o prog -std=c++20 -Wall ;
  • écrire un premier programme avec std::cout, lire une entrée avec std::cin et déclarer une variable avec auto ;
  • identifier les différences clés avec le C et le piège de using namespace std.
Sommaire de la leçon

Tu connais peut-être déjà le C, ou un autre langage. Le C++ va te paraître familier — la syntaxe de base, les boucles, les fonctions, les types entiers s'y retrouvent presque à l'identique. Mais ne t'y trompe pas : le C++ est un langage bien plus vaste, qui empile sur le socle du C des objets, de la généricité, une bibliothèque standard riche et un style de gestion des ressources radicalement plus sûr.

Dans cette première leçon, on pose les fondations : ce qu'est le C++ et ce qu'il apporte, comment le compiler, comment écrire et lire dans la console, et les quelques idées modernes (auto, les espaces de noms) que tu utiliseras dès aujourd'hui. On reste volontairement dans le C++ moderne (C++11 à C++20) : pas de pointeurs nus, pas de new/delete à la main.

Le C++ : un C « avec des objets », et bien plus

Le C++ est né comme une extension du C : à l'origine « C with Classes ». Aujourd'hui c'est un langage à part entière, qui garde la compatibilité avec une grande partie du C mais ajoute quatre piliers majeurs :

  • Les objets (classes, héritage, polymorphisme) pour structurer le code autour de types métier.
  • La généricité (templates) : écrire du code qui marche pour n'importe quel type, sans le réécrire.
  • La STL (Standard Template Library) : conteneurs (std::vector, std::map), algorithmes, chaînes (std::string), prêts à l'emploi.
  • Le RAII (Resource Acquisition Is Initialization) : la libération des ressources est automatique, liée à la durée de vie des objets. C'est ce qui rend le C++ moderne sûr sans ramasse-miettes.

On le retrouve là où il faut à la fois de la performance et du contrôle : moteurs de jeux vidéo, calcul scientifique haute performance, systèmes embarqués et logiciels système, finance (trading à faible latence), navigateurs et bases de données. Partout où chaque microseconde et chaque octet comptent.

Cas réel

Le navigateur avec lequel tu lis cette page est en grande partie écrit en C++. Le moteur JavaScript V8 (Chrome, Node.js, Edge) et le moteur de rendu Blink le sont, tout comme une large part de Firefox. Même chose pour les moteurs de jeu Unreal Engine et le cœur natif d'Unity, les bases de données MySQL et MongoDB, ou le logiciel embarqué d'une voiture. Le point commun : manipuler des millions d'opérations par seconde tout en gardant la main sur la mémoire — précisément le créneau du C++.

Compiler : du fichier source au programme

Le C++ n'est pas interprété : il se compile en un exécutable natif. On utilise typiquement g++ (GNU) ou clang++ (LLVM). La commande de base prend ton fichier source et produit un programme :

On compile main.cpp vers l'exécutable prog, puis on le lance.

Décortiquons les options :

  • -o prog : nomme l'exécutable produit (sinon ce serait a.out).
  • -std=c++20 : choisit la version du langage. Indispensable pour utiliser les fonctionnalités modernes.
  • -Wall : active la plupart des avertissements (all warnings). À garder toujours actif : le compilateur signale des erreurs probables avant qu'elles ne deviennent des bugs.

Note

Sur Windows, l'exécutable s'appelle prog.exe et se lance avec .\prog.exe dans PowerShell. Sur Linux et macOS, c'est ./prog. Le C++ se compile et s'exécute en natif : il n'y a pas de bouton « Tester » dans le navigateur, on passe par le terminal.

Ligne par ligne :

  • #include <iostream> donne accès aux flux d'entrée/sortie standard (input/output stream), dont std::cout.
  • int main() est le point d'entrée. Le programme commence ici.
  • std::cout est le flux de sortie standard (la console). L'opérateur << y « pousse » des données : on l'appelle l'opérateur d'insertion. On peut en chaîner plusieurs : std::cout << a << b.
  • std::endl insère un retour à la ligne et vide le tampon de sortie.
  • return 0; signale au système que tout s'est bien passé (code de retour 0 = succès). Détail moderne : dans main, ce return 0; est même implicite si tu l'omets.

Le std:: devant cout et endl indique que ces noms vivent dans l'espace de noms std, celui de la bibliothèque standard. C'est l'objet de la section suivante.

Les espaces de noms (namespace)

Un espace de noms regroupe des noms (fonctions, types, objets) sous un préfixe commun pour éviter les collisions. Toute la bibliothèque standard vit dans l'espace std. C'est pourquoi on écrit std::cout, std::string, std::vector : le :: est l'opérateur de résolution de portée.

Un using ciblé : lisible et sans risque de collision.

Piège fréquent

Évite using namespace std; en haut de tes fichiers. Il importe tout l'espace std d'un coup et provoque des collisions sournoises : un std::count qui entre en conflit avec ta variable count, par exemple. Garde le préfixe std:: explicite, ou des using ciblés.

Lire une entrée avec std::cin

Symétrique de std::cout, le flux std::cin lit ce que l'utilisateur tape. L'opérateur d'extraction >> récupère la valeur et la range dans une variable :

>> convertit automatiquement le texte saisi en int.

Note la direction des chevrons : << pousse vers la sortie, >> tire depuis l'entrée. Une astuce mnémotechnique : les chevrons pointent dans le sens du flux de données.

auto : l'inférence de type

Depuis C++11, le mot-clé auto demande au compilateur de déduire le type d'une variable à partir de sa valeur initiale. Ce n'est pas du typage dynamique : le type reste fixé à la compilation, simplement tu n'as pas à l'écrire.

auto évite la répétition des types longs, surtout avec la STL.

L'intérêt explose avec des types verbeux. Plutôt qu'écrire std::vector<std::string>::iterator it = ..., un simple auto it = ... suffit. Utilise auto quand le type est évident d'après la valeur, et écris le type explicitement quand il clarifie l'intention.

Note

Un bool s'affiche par défaut comme 1 (vrai) ou 0 (faux) : c'est pourquoi la sortie montre actif=1. Pour obtenir true/false, on insère le manipulateur std::boolalpha dans le flux.

Différences clés avec le C

Si tu viens du C, voici ce qui change dès le premier programme :

  • Les flux plutôt que printf : <iostream> et std::cout remplacent <cstdio> et printf. Les flux sont typés : pas de %d/%s à accorder à la main.
  • Les références (int& r = x;) : un alias sûr vers une variable, alternative aux pointeurs pour passer des arguments modifiables.
  • La surcharge de fonctions : plusieurs fonctions peuvent porter le même nom si leurs paramètres diffèrent.
  • Le type bool natif avec true/false (en C il fallait <stdbool.h>).
  • Les commentaires // en plus des /* ... */ (le C les a finalement adoptés aussi).
  • La STL : std::string et std::vector remplacent les tableaux C et les chaînes char*, avec gestion mémoire automatique.

Références et surcharge : deux ajouts du C++ absents du C.

Pièges fréquents

Piège fréquent

Oublier #include <iostream> : tu obtiens une erreur du type 'cout' is not a member of 'std'. Chaque outil de la STL exige son en-tête (<string> pour std::string, <vector> pour std::vector).

  • std::endl vs '\n' : std::endl insère un retour à la ligne et vide le tampon, ce qui coûte cher dans une boucle. Préfère '\n' pour un simple saut de ligne ; réserve std::endl aux cas où tu veux forcer l'écriture immédiate.
  • Mélanger printf et std::cout sans raison : c'est légal, mais ça brouille le style et les deux tampons peuvent se désynchroniser. Choisis un style et tiens-t'y.
  • Oublier -std=c++20 : g++ compile alors dans un mode plus ancien et rejette les fonctionnalités modernes avec des erreurs déroutantes. Mets toujours le drapeau.
  • Abuser de using namespace std; : commode dans un mini-exemple, dangereux dans un vrai projet (collisions de noms).

Pour aller plus loin

Pour aller plus loin

Le langage évolue par standards : C++11 (le grand tournant moderne : auto, lambdas, move), C++14, C++17 (structured bindings, std::optional), C++20 (concepts, ranges, std::format), C++23. Côté compilateurs : g++, clang++ et MSVC. Pour des projets à plusieurs fichiers, on n'appelle plus g++ à la main : on utilise un outil de build comme CMake. Et pour formater proprement une sortie, std::format (C++20) remplace avantageusement les chaînes de <<.

Astuce

Avec C++20, std::format (en-tête <format>) rend l'affichage lisible : std::cout << std::format("{} a {} ans\n", nom, age);. Les accolades {} sont remplacées dans l'ordre, sans se soucier des types. Selon ton compilateur, il faut une version récente (g++ 13+) pour en disposer.

Antisèche

Glossaire

Compilation
Traduction du code source (.cpp) en exécutable natif par un compilateur (g++, clang++) ; étape obligatoire avant l'exécution.
STL
Standard Template Library : la bibliothèque standard du C++ (conteneurs std::vector/std::map, std::string, algorithmes).
RAII
Resource Acquisition Is Initialization : la libération d'une ressource est liée à la durée de vie d'un objet, ce qui automatise le nettoyage sans ramasse-miettes.
std::cout / std::cin
Flux de sortie (console) et d'entrée (clavier) standard, utilisés avec les opérateurs << (insertion) et >> (extraction).
Espace de noms
Préfixe (std::) qui regroupe des noms pour éviter les collisions ; :: est l'opérateur de résolution de portée.
auto
Mot-clé demandant au compilateur de déduire le type d'une variable à partir de son initialisateur, à la compilation (pas de typage dynamique).
Référence (T&)
Alias sûr vers une variable existante ; alternative aux pointeurs pour passer un argument modifiable.
Surcharge
Plusieurs fonctions de même nom distinguées par leurs paramètres ; le compilateur choisit la bonne selon les arguments fournis.

Récap et vérification

  • Le C++ étend le C avec les objets, la généricité, la STL et le RAII ; il sert là où performance et contrôle comptent.
  • On compile avec g++ main.cpp -o prog -std=c++20 -Wall, puis on lance ./prog.
  • std::cout << ... écrit, std::cin >> ... lit ; les noms standard vivent dans l'espace std.
  • auto infère le type à la compilation ; on évite using namespace std; pour prévenir les collisions.
  • Côté C : préfère '\n' à std::endl sauf si tu veux vider le tampon, et n'oublie jamais l'en-tête <iostream>.
