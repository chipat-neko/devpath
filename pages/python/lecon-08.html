Dictionnaires et ensembles

~35 min Débutant Leçon 07 recommandée

À la fin de cette leçon, tu sauras

  • créer et manipuler un dictionnaire : accès d[cle], get(), ajout, del et test cle in d ;
  • parcourir un dictionnaire avec keys(), values() et for cle, valeur in d.items() ;
  • utiliser un ensemble (set) pour des éléments uniques et combiner avec |, & et - ;
  • choisir la bonne structure entre liste, dictionnaire et ensemble selon le besoin.
Sommaire de la leçon

Tu sais déjà ranger des valeurs dans une liste, où chaque élément est repéré par sa position (un indice : 0, 1, 2…). Mais parfois la position n'a aucun sens : ce qu'on veut, c'est associer un nom à une valeur, comme dans un répertoire téléphonique où chaque contact mène à un numéro. C'est exactement le rôle du dictionnaire.

Dans cette leçon, tu découvres deux nouvelles structures. Le dictionnaire (dict) associe des clés à des valeurs. L'ensemble (set) stocke des éléments uniques, sans doublon ni ordre. Garde un interpréteur ouvert et recopie chaque exemple : ces deux outils reviennent dans presque tous les programmes Python.

Le dictionnaire : associer une clé à une valeur

Un dictionnaire stocke des paires clé → valeur. On l'écrit entre accolades, chaque paire séparée par une virgule, la clé et la valeur séparées par deux-points.

Contrairement à une liste, on ne cherche pas l'élément numéro 0 mais l'élément de clé "nom". La clé sert d'étiquette explicite, ce qui rend le code beaucoup plus lisible que contact[0].

Pour ajouter ou modifier une valeur, on assigne directement à une clé. Si la clé existe, on remplace ; sinon, on crée. Pour supprimer une paire, on utilise del.

Accès sûr avec get() et test d'appartenance

Accéder à une clé qui n'existe pas avec les crochets provoque une erreur (KeyError) qui interrompt le programme. La méthode get() est plus douce : elle renvoie None (ou une valeur par défaut de ton choix) au lieu de planter.

Pour savoir si une clé est présente avant d'y accéder, on utilise l'opérateur in. Attention : in porte sur les clés d'un dictionnaire, pas sur les valeurs.

Parcourir un dictionnaire

Trois méthodes donnent accès au contenu : keys() (les clés), values() (les valeurs) et items() (les paires clé-valeur). La plus utile est items(), qu'on parcourt en récupérant la clé et la valeur d'un coup.

Si tu n'as besoin que des valeurs, values() les fournit directement — pratique pour, par exemple, additionner un stock total avec sum(stock.values()).

Les clés doivent être immuables

N'importe quelle valeur peut servir de valeur dans un dictionnaire, mais les clés obéissent à une règle : elles doivent être immuables (non modifiables). En pratique, on utilise des str, des int ou des tuple. Une liste ne peut pas être une clé, car elle est modifiable.

Note

Le mot technique est « hachable » (hashable). Retiens simplement : si on peut le modifier (liste, autre dict, set), ça ne peut pas être une clé. Un tuple de valeurs immuables, lui, fait une excellente clé composée.

L'ensemble : des éléments uniques

Un ensemble (set) est une collection d'éléments uniques et non ordonnés. On le crée avec des accolades contenant des valeurs (pas des paires), ou avec set(). Les doublons disparaissent automatiquement.

Comme un set n'a pas d'ordre, tu ne peux pas écrire couleurs[0] : il n'y a pas d'indice. L'ordre d'affichage n'est d'ailleurs pas garanti, d'où le « par ex. » dans le commentaire ci-dessus. Son point fort, c'est de répondre instantanément à « cet élément est-il présent ? » et d'éliminer les doublons.

Un usage très courant : dédupliquer une liste en la convertissant en set.

Combiner des ensembles : union, intersection, différence

Les sets brillent pour comparer des collections. Trois opérateurs résument les opérations classiques : | (union, tout ce qui est dans l'un ou l'autre), & (intersection, ce qui est dans les deux) et - (différence, ce qui est dans le premier mais pas dans le second).

Exemple concret : tu as la liste des élèves inscrits au club d'échecs et au club de théâtre. L'intersection donne ceux qui font les deux, la différence ceux qui ne font que les échecs.

Choisir la bonne structure

Liste, dictionnaire, ensemble : comment décider ? Pose-toi trois questions.

  • L'ordre et les doublons comptent ? Tu veux une suite ordonnée, qui peut contenir des répétitions → liste (ex. l'historique des achats).
  • Tu associes une étiquette à une valeur ? Tu veux retrouver une info par son nom → dictionnaire (ex. un profil utilisateur, un stock par produit).
  • Tu veux des éléments uniques et tester l'appartenance ? L'ordre est sans importance, pas de doublon → ensemble (ex. les tags d'un article, les visiteurs distincts).

Astuce

Pour vérifier « est-ce que cet élément est dans la collection ? » sur beaucoup de données, un set ou un dict est bien plus rapide qu'une liste. Si tu fais souvent des tests in, c'est un signe qu'un set est le bon choix.

Dictionnaires imbriqués : une mini base de données

Une valeur d'un dictionnaire peut être… un autre dictionnaire. On obtient une structure imbriquée, idéale pour modéliser plusieurs « fiches » repérées par une clé.

Remarque l'usage de guillemets simples 'age' à l'intérieur de la f-string (qui utilise des guillemets doubles) pour éviter le conflit de guillemets. C'est un réflexe pratique quand tu accèdes à un dict dans une f-string.

Cas réel

Quand une application reçoit des données d'une API sur Internet, elles arrivent presque toujours sous forme de dictionnaires imbriqués — c'est le format JSON. Un profil utilisateur ressemble trait pour trait à utilisateurs["lou"]["ville"] ci-dessus. Côté coulisses, un set sert à dédupliquer en un éclair : compter les visiteurs uniques d'une page revient à verser tous les identifiants dans un set et à lire sa taille avec len(). Dict pour retrouver par clé, set pour garder l'unique : deux réflexes qu'on emploie chaque jour.

Pièges fréquents

  • Accéder à une clé absente avec les crochets. d["inconnu"] lève une KeyError et stoppe le programme. Préfère d.get("inconnu") quand tu n'es pas sûr que la clé existe.
  • Croire que {} crée un ensemble vide. Les accolades vides créent un dictionnaire vide. Pour un set vide, il faut écrire set().
  • Supposer un ordre dans un set. Un ensemble n'a pas d'ordre garanti ni d'indices : mon_set[0] est une erreur.
  • Utiliser une liste comme clé. {[1, 2]: "x"} lève une TypeError (non hachable). Utilise un tuple si tu as besoin d'une clé composée de plusieurs valeurs.

Piège fréquent

Le plus déroutant pour les débutants : type({}) renvoie <class 'dict'>, pas un set. Retiens la règle : accolades avec deux-points = dict ; accolades avec juste des valeurs = set ; accolades vides = dict. Un set vide, c'est toujours set().

Pour aller plus loin

Tu construiras vite des dictionnaires à partir d'autres données. Il existe une syntaxe condensée, les compréhensions de dict et de set (par exemple {x: x * x for x in range(5)}), qu'on verra en détail à la leçon 10.

Le module collections de la bibliothèque standard offre des outils pratiques : defaultdict (un dict qui crée automatiquement une valeur par défaut pour une clé absente) et Counter (qui compte les occurrences en une ligne, parfait pour l'exercice 1 ci-dessous).

Pour aller plus loin

Depuis Python 3.7, un dictionnaire conserve l'ordre d'insertion des clés : quand tu le parcours, tu retrouves les paires dans l'ordre où tu les as ajoutées. Un set, lui, n'offre toujours aucune garantie d'ordre.

Antisèche : dictionnaires et ensembles

L'essentiel de la leçon, en un coup d'œil.

Glossaire

Dictionnaire (dict)
Collection de paires clé → valeur, notée entre accolades ; on accède à une valeur par sa clé, pas par une position.
Clé
Étiquette immuable (str, int, tuple) qui identifie une valeur dans un dictionnaire ; unique dans un même dict.
Ensemble (set)
Collection d'éléments uniques et non ordonnés ; idéale pour tester l'appartenance et supprimer les doublons.
get()
Accès sûr à une clé : renvoie None (ou une valeur par défaut) au lieu de lever KeyError si la clé est absente.
items()
Renvoie les paires clé-valeur d'un dictionnaire, pour les parcourir d'un coup : for cle, valeur in d.items().
Hachable
Se dit d'un objet immuable utilisable comme clé de dict ou élément de set ; une liste, modifiable, ne l'est pas.
Union / intersection / différence
Opérations entre ensembles : | (dans l'un ou l'autre), & (dans les deux), - (dans le premier seulement).
Déduplication
Suppression des doublons ; en pratique, convertir une liste en set : set(liste).

Récap et vérification

  • Un dict associe des clés à des valeurs : accès d[cle], accès sûr d.get(cle, defaut), ajout/modif d[cle] = ..., suppression del d[cle].
  • cle in d teste la présence d'une clé ; on parcourt avec for cle, valeur in d.items().
  • Les clés doivent être immuables (str, int, tuple) — jamais une liste.
  • Un set contient des éléments uniques et non ordonnés ; opérations | (union), & (intersection), - (différence) ; set(liste) déduplique.
  • Attention : {} est un dict vide ; un set vide s'écrit set().

Vérifie ta compréhension

  1. Quelle est la différence de comportement entre contact["tel"] et contact.get("tel") si la clé n'existe pas ?
  2. Pourquoi {} ne crée-t-il pas un ensemble vide, et comment en crée-t-on un ?
  3. Que renvoie {1, 2, 2, 3} & {2, 3, 4}, et pourquoi ?
