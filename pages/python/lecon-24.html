Consommer une API web : HTTP et JSON

~36 min Avancé Leçons 8 et 12 recommandées

À la fin de cette leçon, tu sauras

  • expliquer ce qu'est une API web et le cycle requête / réponse HTTP ;
  • récupérer des données avec urllib (standard) et requests (populaire) ;
  • convertir du JSON en dictionnaire et inversement avec le module json ;
  • envoyer des paramètres et une requête POST ;
  • lire les codes de statut et gérer proprement les erreurs.
Sommaire de la leçon

La plupart des données utiles vivent ailleurs : la météo, un taux de change, les dépôts d'un compte GitHub, le catalogue d'une boutique. On y accède par une API web — un service qui répond à des requêtes HTTP et renvoie, presque toujours, du JSON. Savoir interroger une API, c'est ouvrir Python sur tout le web. Cette leçon te donne les deux outils (urllib et requests) et la grammaire commune : HTTP + JSON.

Le cycle requête / réponse

Une API fonctionne comme un guichet : ton programme (le client) envoie une requête à une URL (le endpoint), le serveur traite et renvoie une réponse composée d'un code de statut (200 = OK) et d'un corps (le JSON).

Sans rien installer : urllib

La bibliothèque standard suffit pour une requête simple. urllib.request.urlopen ouvre l'URL ; on lit la réponse et on la passe au module json.

À retenir

json.load (sans « s ») lit depuis un flux (un fichier, une réponse réseau) ; json.loads (avec « s » comme string) lit depuis une chaîne. Même logique pour dump/dumps à l'écriture.

Le confort : requests

En pratique, tout le monde utilise requests (à installer avec pip install requests) : plus lisible, il parse le JSON, gère les paramètres et les erreurs sans effort. C'est le standard de fait.

Le pont JSON ⇄ dictionnaire

Le JSON est un format texte universel, très proche des dictionnaires et listes Python. Le module json fait l'aller-retour : loads transforme du texte JSON en objets Python, dumps fait l'inverse.

Bonne pratique

Ajoute ensure_ascii=False à json.dumps pour garder les accents lisibles (sinon « é » devient é), et indent=2 pour un affichage aéré, pratique au débogage.

Paramètres et envoi de données

On affine une requête avec des paramètres d'URL (après le ?). Avec requests, on passe un simple dictionnaire à params — l'encodage est automatique. Pour créer une ressource, on utilise POST avec json=.

Les codes de statut

Le premier chiffre du code résume le sort de la requête. Les connaître évite bien des heures de débogage : un 404 n'est pas un bug de ton code, c'est une ressource introuvable ; un 401 réclame une authentification.

Cas réel : un tableau de bord météo

Cas réel

Un petit script qui affiche chaque matin la météo du jour interroge une API publique (comme Open-Meteo), reçoit un JSON {"temperature": 18, "vent": 12, …} et le met en forme dans le terminal. Le même schéma — requests.get → .json() → lire les champs — alimente un convertisseur de devises, un suivi de colis, un bot qui poste sur Slack, ou l'agrégation de plusieurs sources dans un tableau de bord. Une fois HTTP + JSON maîtrisés, ces projets se ressemblent tous.

Bien se comporter face à une API

Attention

Trois réflexes indispensables : (1) toujours un timeout= — sans lui, un serveur muet fige ton programme indéfiniment ; (2) une clé d'API ne se met jamais en dur dans le code (utilise une variable d'environnement, os.environ) ; (3) respecte les quotas et les délais (rate limits) pour ne pas te faire bloquer.

Pour aller plus loin

Pour envoyer de nombreuses requêtes, une requests.Session() réutilise la connexion (plus rapide). Les API protégées demandent un en-tête d'authentification (headers={"Authorization": "Bearer …"}). Et pour des milliers d'appels sans bloquer, on passe à l'asynchrone avec httpx ou aiohttp — la concurrence fait justement l'objet d'une prochaine leçon.

Antisèche

Glossaire

API web
Service accessible par HTTP qui expose des données ou des actions, généralement au format JSON.
REST
Style d'API le plus répandu : des URL (ressources) manipulées par les méthodes HTTP (GET, POST, PUT, DELETE).
Endpoint (point d'accès)
URL précise d'une API correspondant à une ressource ou une action, par exemple /repos/python/cpython.
Méthode HTTP
Verbe de la requête : GET lit, POST crée, PUT/PATCH modifient, DELETE supprime.
Code de statut
Nombre à trois chiffres résumant le résultat : 2xx succès, 3xx redirection, 4xx erreur client, 5xx erreur serveur.
JSON
Format texte d'échange de données, calqué sur les objets et tableaux ; se convertit en dict/list Python.
requests
Bibliothèque tierce de référence pour les requêtes HTTP en Python (pip install requests).
timeout
Délai maximal d'attente d'une réponse ; au-delà, une exception est levée plutôt que de bloquer indéfiniment.

Récap et vérification

  • Une API web répond à des requêtes HTTP par un code de statut + un corps JSON.
  • urllib (standard) dépanne ; requests est le confort du quotidien (.get, .json(), raise_for_status).
  • Le module json fait le pont : loads/load pour lire, dumps/dump pour écrire.
  • params={…} ajoute des paramètres d'URL ; POST avec json= envoie des données.
  • Réflexes : timeout systématique, clé d'API hors du code, familles de codes (4xx vs 5xx).

Vérifie ta compréhension

  1. Que renvoie généralement une API web, et via quel protocole ?
  2. Quelle est la différence entre json.loads et json.load ?
  3. À quoi sert r.raise_for_status() ?
  4. Que signifie un code 404 ? Et un 500 ?
