Module 02 · Logique & flux — Leçon 06

Les fonctions

~35 min Débutant Leçon 05 recommandée

À la fin de cette leçon, tu sauras

  • définir une fonction avec def, un corps indenté et return, et savoir qu'une fonction sans return renvoie None ;
  • passer des arguments positionnels, par défaut et nommés, et capter un nombre variable d'arguments avec *args et **kwargs ;
  • comprendre la portée locale/globale (règle LEGB) et documenter tes fonctions avec une docstring et des annotations de type ;
  • éviter les pièges classiques : oubli de return, confusion print/return et argument par défaut mutable.
Sommaire de la leçon

Jusqu'ici, tu écrivais des instructions les unes après les autres. Mais dès qu'un même calcul revient à plusieurs endroits, le copier-coller devient une corvée — et une source de bugs : corriger une faute t'oblige à la corriger partout. Les fonctions règlent ce problème : tu emballes un morceau de logique sous un nom, et tu le réutilises autant que tu veux, en une ligne.

Dans cette leçon, tu apprends à définir tes propres fonctions, à leur passer des informations (les paramètres), à récupérer un résultat avec return, et à éviter les pièges classiques du débutant. On part du connu — tu utilises déjà print() et int(), qui sont des fonctions — pour aller vers l'inconnu : créer les tiennes.

Définir une fonction

On définit une fonction avec le mot-clé def, suivi d'un nom, de parenthèses (qui peuvent contenir des paramètres) et de deux-points. Le corps de la fonction est le bloc indenté en dessous. Le mot-clé return indique la valeur que la fonction renvoie à celui qui l'appelle.

Définir une fonction ne l'exécute pas : le corps ne tourne que lorsque tu l'appelles, avec carre(5). La valeur passée (ici 5) est l'argument ; à l'intérieur, elle arrive dans le paramètre nombre.

Sans return, une fonction se contente d'exécuter son corps puis renvoie automatiquement None (l'absence de valeur). C'est tout à fait valable quand la fonction se contente d'agir (afficher, écrire dans un fichier...).

Les paramètres

Les paramètres les plus simples sont positionnels : à l'appel, les arguments sont associés dans l'ordre. Tu peux aussi donner une valeur par défaut à un paramètre : il devient alors facultatif.

À l'appel, tu peux aussi nommer explicitement les arguments : ce sont les arguments nommés (keyword arguments). C'est plus lisible et ça libère de l'ordre.

Note

Les paramètres avec valeur par défaut doivent venir après ceux qui n'en ont pas. def f(a, b=2) est correct ; def f(a=1, b) provoque une SyntaxError.

*args et **kwargs

Parfois, tu ne sais pas combien d'arguments seront passés. Le paramètre *args capture tous les arguments positionnels restants sous forme de tuple, et **kwargs capture tous les arguments nommés restants sous forme de dictionnaire.

Les noms args et kwargs sont une simple convention : ce sont les étoiles * et ** qui font le travail. Tu rencontreras souvent def f(*args, **kwargs) dans le code des autres.

La portée (scope) des variables

Une variable créée dans une fonction est locale : elle n'existe que le temps de l'appel et reste invisible à l'extérieur. Les variables définies au niveau du fichier sont globales : une fonction peut les lire, mais pas les réassigner sans précaution.

Pour trouver une variable, Python suit la règle LEGB : il cherche d'abord en Local, puis dans les fonctions Englobantes, puis au niveau Global (le module), enfin dans les Built-in (les noms intégrés comme print). Le premier trouvé gagne.

Piège fréquent

Le mot-clé global est à éviter : il rend le code difficile à suivre, car n'importe quel appel peut modifier l'état du programme à distance. Préfère une fonction qui reçoit la valeur et la renvoie mise à jour, puis réassigne toi-même : compteur = incrementer(compteur) avec def incrementer(n): return n + 1.

Docstrings et annotations de type

Une docstring est une chaîne placée en première ligne du corps : elle documente ce que fait la fonction. Les annotations de type précisent le type attendu des paramètres et du retour. Elles n'imposent rien à l'exécution, mais documentent le code et aident ton éditeur.

Lis rayon: float comme « le paramètre rayon est attendu comme un float » et -> float comme « la fonction renvoie un float ». C'est un contrat lisible, très utile dès que le code grandit.

Cas réel

Dans une vraie application, une même règle sert souvent à plusieurs endroits. Une fonction valider_mot_de_passe(mdp) est appelée à l'inscription, au changement et à la réinitialisation du mot de passe. Le jour où la sécurité impose une contrainte de plus (un caractère spécial obligatoire), on la modifie à un seul endroit et les trois parcours en profitent aussitôt. Sans fonction, la règle serait copiée-collée trois fois — et on finirait par en oublier une. Factoriser, c'est garder une seule source de vérité.

Les fonctions sont des objets

En Python, une fonction est une valeur comme une autre : tu peux la stocker dans une variable, la passer en argument à une autre fonction, ou la renvoyer. On parle de fonctions de première classe.

Cette idée ouvre la porte aux fonctions d'ordre supérieur (qui prennent ou renvoient des fonctions), que tu approfondiras en leçon 14.

Les fonctions lambda

Pour une fonction très courte et jetable, Python propose la syntaxe lambda : une fonction anonyme tenant sur une ligne. Après lambda, tu listes les paramètres, puis deux-points, puis une seule expression dont le résultat est renvoyé automatiquement.

On réserve lambda aux cas vraiment brefs (souvent en argument d'une autre fonction, comme ici avec sort). Pour le reste, un def nommé est plus lisible. On y reviendra en détail en leçon 14.

Pièges fréquents

  • Oublier return. Une fonction sans return renvoie None. Si resultat = ma_fonction() vaut None de façon inattendue, vérifie que tu as bien écrit return (et pas seulement print) dans le corps.
  • Confondre print et return. print() affiche à l'écran ; return renvoie une valeur réutilisable. Une fonction qui fait print(x) mais pas return x ne te permet pas de récupérer le résultat pour un calcul suivant.
  • Modifier une globale par mégarde. Sans global, réassigner une variable du même nom dans une fonction crée en réalité une variable locale distincte. La globale n'est pas touchée — ce qui surprend quand on s'attendait au contraire.

Piège fréquent

L'argument par défaut mutable est le piège le plus vicieux. Dans def ajouter(x, liste=[]), la liste par défaut est créée une seule fois, à la définition, puis partagée entre tous les appels : elle se remplit d'un appel à l'autre. La parade : utiliser None comme défaut, puis créer la liste dans le corps.

Pour aller plus loin

Les fonctions sont la brique de presque tout ce que tu écriras ensuite. Quelques pistes à explorer plus tard :

  • Les fonctions d'ordre supérieur et lambda en pratique (avec map, filter, sorted) — leçon 14.
  • Les décorateurs, des fonctions qui enveloppent d'autres fonctions pour ajouter un comportement (journalisation, mise en cache...).
  • Le typage avancé du module typing : Optional (une valeur ou None), Callable (une fonction), les listes typées.

Pour aller plus loin

Une bonne fonction fait une seule chose, porte un nom qui dit ce qu'elle fait, et renvoie son résultat plutôt que de l'afficher. Ce réflexe rend ton code testable et réutilisable bien au-delà de ce cours.

Glossaire

Fonction
Bloc de code nommé et réutilisable, défini avec def et déclenché par son nom suivi de parenthèses.
Paramètre
Nom déclaré entre les parenthèses de la définition ; il reçoit une valeur à l'appel.
Argument
Valeur réelle passée à la fonction lors de l'appel, rangée dans le paramètre correspondant.
return
Renvoie une valeur à l'appelant et termine la fonction ; son absence renvoie None.
LEGB
Ordre de recherche d'un nom : Local, Englobant, Global, Built-in ; le premier trouvé gagne.
*args / **kwargs
Captent un nombre variable d'arguments : positionnels (tuple) et nommés (dictionnaire).
Docstring
Chaîne placée en première ligne du corps qui documente ce que fait la fonction (fn.__doc__).
lambda
Fonction anonyme d'une seule expression, pratique pour un usage court et jetable.

Récap et vérification

  • On définit une fonction avec def nom(parametres): et un corps indenté ; return renvoie une valeur, son absence renvoie None.
  • Paramètres : positionnels, par défaut (message="Bonjour"), nommés à l'appel ; *args et **kwargs captent un nombre variable d'arguments.
  • Les variables d'une fonction sont locales ; la résolution suit la règle LEGB ; global existe mais est à éviter.
  • Une docstring documente la fonction ; les annotations (r: float, -> float) précisent les types sans les imposer.
  • Les fonctions sont des objets de première classe ; lambda écrit une mini-fonction anonyme.

Vérifie ta compréhension

  1. Quelle est la différence entre print(x) et return x dans une fonction ?
  2. Que renvoie une fonction qui ne contient aucun return ?
  3. Pourquoi def f(x, acc=[]) est-il dangereux, et comment le corriger ?
