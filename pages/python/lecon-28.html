Module 09 · Pour aller plus loin — Leçon 28

Projet : automatiser une tâche (capstone)

~40 min Intermédiaire Capstone — l'ensemble du cours recommandé

À la fin de cette leçon, tu sauras

  • parcourir et filtrer des fichiers avec pathlib et glob ;
  • piloter un programme externe avec subprocess ;
  • rendre un script paramétrable avec argparse ;
  • planifier une exécution automatique (cron, Planificateur de tâches) ;
  • assembler tout le cours dans un projet autonome.
Sommaire de la leçon

Python est le couteau suisse de l'automatisation : on l'appelle un « langage colle » parce qu'il relie facilement des fichiers, des programmes et des services. Renommer trois cents photos, télécharger un rapport chaque matin, nettoyer un tableau exporté : ces corvées répétitives mangent du temps et provoquent des erreurs. Un petit script les fait à ta place, à l'identique, en une commande. Cette leçon rassemble les briques du module « Pour aller plus loin » et clôt le cours par un projet complet.

D'une corvée répétée à un script

Automatiser, ce n'est pas magique : c'est décrire une tâche une seule fois, puis laisser la machine la répéter. Le gain n'est pas que la vitesse — c'est surtout la fiabilité : un script ne se lasse pas, ne saute pas de ligne et fait exactement la même chose la centième fois que la première.

Parcourir des fichiers avec pathlib

Le module pathlib représente un chemin par un objet Path, identique sous Windows, macOS et Linux (plus de \\ contre / à gérer). Il décompose un chemin en morceaux utiles et sait parcourir un dossier.

Bonne pratique

Assemble les chemins avec l'opérateur / plutôt qu'en collant des chaînes : Path("photos") / "2024" / "vacances.jpg" reste correct sur tous les systèmes. Et dossier.mkdir(parents=True, exist_ok=True) crée toute l'arborescence sans planter si elle existe déjà.

Piloter d'autres programmes avec subprocess

Automatiser, c'est souvent orchestrer des outils existants (git, ffmpeg, un convertisseur…). Le module subprocess lance une commande externe et récupère sa sortie, son erreur et son code de retour (0 = succès).

Attention — injection de commande

Passe toujours une liste d'arguments (["git", "status"]), jamais une chaîne avec shell=True construite à partir d'une saisie utilisateur : f"rm {nom}" devient catastrophique si nom vaut "a.txt; rm -rf ~". La liste isole chaque argument et supprime ce risque.

Un outil en ligne de commande : argparse

Un script codé en dur ne sert qu'une fois. Avec argparse, il devient un outil réutilisable : il accepte des arguments, des options, et génère même une aide (--help) automatiquement.

À retenir

Un nom sans tiret (dossier) est un argument obligatoire et positionnel ; un nom avec deux tirets (--ext) est une option facultative. argparse refuse les arguments manquants et affiche l'aide tout seul avec -h.

Planifier l'exécution automatiquement

Un script vraiment utile tourne sans qu'on y pense. Trois voies : cron (Linux/macOS), le Planificateur de tâches (Windows), ou la bibliothèque schedule pour un programme qui reste allumé.

Pour aller plus loin

cron et le Planificateur lancent le script même si l'ordinateur a redémarré : c'est le choix des tâches périodiques (sauvegarde de nuit, rapport hebdomadaire). schedule convient quand un programme tourne déjà en continu (un bot, un serveur). Pour des flux plus complexes, on passe ensuite à des orchestrateurs comme Airflow ou cron côté serveur.

Cas réel : le rapport du lundi matin

Cas réel

Dans des milliers d'équipes, un même rituel se répétait chaque lundi : télécharger un export, le nettoyer dans un tableur, coller un graphique dans un e-mail. Un script Python fait tout : il appelle l'API (leçon 24), range les chiffres dans SQLite (leçon 25), traite les données en parallèle si besoin (leçon 26), utilise Counter pour le top des ventes (leçon 27), génère un graphique et l'envoie par courriel. Planifié avec cron, il livre le rapport avant l'arrivée au bureau : une heure gagnée chaque semaine, sans erreur de copier-coller.

Idempotence

Un bon script d'automatisation est idempotent : le relancer deux fois ne double pas les données et ne casse rien. Vérifie avant d'agir (if not archive.exists()), écris dans un fichier temporaire puis renomme, et journalise ce qui a été fait avec le module logging.

Glossaire

Automatisation
Décrire une tâche une seule fois dans un script pour que la machine la répète à l'identique, sans effort ni erreur.
pathlib
Module standard qui représente les chemins par des objets Path, portables et faciles à décomposer (.name, .stem, .suffix).
glob
Filtrage de fichiers par motif : * remplace n'importe quelle suite de caractères, ** descend dans les sous-dossiers.
subprocess
Module pour lancer un programme externe et récupérer sa sortie, son erreur et son code de retour.
argparse
Module qui transforme un script en outil en ligne de commande : arguments, options et aide automatique.
Code de retour
Entier renvoyé par un programme en fin d'exécution : 0 signifie succès, toute autre valeur un problème.
cron
Planificateur d'Unix qui lance une commande à intervalle régulier ; l'équivalent Windows est le Planificateur de tâches.
Idempotent
Se dit d'un script qu'on peut relancer sans effet indésirable : le second passage ne duplique ni ne casse rien.

Récap et vérification

  • pathlib : chemins portables, glob pour filtrer, .name/.stem/.suffix pour décomposer.
  • subprocess : piloter d'autres programmes, récupérer sortie et code de retour (liste d'arguments, pas de shell=True risqué).
  • argparse : rendre un script réutilisable (arguments, options, --help).
  • Planifier : cron, Planificateur de tâches, ou schedule — et viser des scripts idempotents.
  • Le réflexe : une tâche répétée = un script + une planification.

Mini-projet fil rouge — un journal de dépenses

Pour clore ce cours, réunissons l'essentiel dans un seul programme : un petit journal de dépenses en ligne de commande. Il mobilise les fonctions, les listes et dictionnaires, les fichiers, les exceptions et le module datetime — tout ce que tu as appris, mis bout à bout.

Ce que tu vas construire

Un script qui enregistre des dépenses (montant, catégorie, date du jour), les sauvegarde dans un fichier, puis les recharge au lancement suivant et affiche le total ainsi que le total par catégorie.

Étapes

Modéliser une dépense

Représente chaque dépense par un dictionnaire à trois clés : date, montant et categorie. Conserve l'ensemble dans une liste.

Ajouter et totaliser

Écris une fonction ajouter(...) qui empile une dépense, et une fonction total(...) qui renvoie la somme des montants (pense à sum et à une compréhension).

Regrouper par catégorie

Parcours la liste pour construire un dictionnaire {categorie: montant cumulé} à l'aide de dict.get(cle, 0).

Sauvegarder et recharger

Écris chaque dépense sur une ligne d'un fichier, puis relis-le au démarrage. Gère le premier lancement (fichier absent) avec un try / except FileNotFoundError.

Dater automatiquement

Horodate chaque dépense avec date.today().isoformat() du module datetime, et soigne l'affichage avec des f-strings formatées (:.2f).
