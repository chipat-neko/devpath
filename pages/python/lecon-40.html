Métaprogrammation, packaging & synthèse

~37 min Avancé Leçon 11 recommandée

À la fin de cette leçon, tu sauras

  • savoir inspecter objets et fonctions avec inspect, getattr/setattr et __dict__ ;
  • savoir créer des classes dynamiquement et utiliser les hooks __init_subclass__ et __set_name__ ;
  • savoir quand recourir à une métaclasse et quand préférer un décorateur de classe ;
  • savoir structurer et distribuer un paquet avec pyproject.toml et venv.
Sommaire de la leçon

Tu sais déjà écrire du Python robuste et performant. Cette dernière leçon ferme la boucle : tu vas apprendre à agir sur le code lui-même — l'inspecter, fabriquer des classes à la volée, intercepter leur création — puis à distribuer ton travail sous forme de paquet installable. La métaprogrammation est puissante mais traîtresse : la règle d'or est de n'y recourir que lorsqu'un outil plus simple ne suffit pas.

On termine par une synthèse et des pistes pour la suite : tu auras alors fait le tour du langage.

L'introspection : interroger les objets

L'introspection consiste à examiner un objet à l'exécution : son type, ses attributs, sa signature. Les briques de base sont des fonctions intégrées, complétées par le module inspect pour les cas fins.

vars(obj) renvoie le __dict__ de l'instance ; dir(obj), lui, liste aussi les attributs hérités et les méthodes.

Le module inspect va plus loin : il lit la signature d'un appelable, ce qui est précieux pour générer de la documentation ou valider des arguments.

inspect.signature respecte les annotations et les paramètres keyword-only ; param.default vaut inspect.Parameter.empty quand il n'y en a pas.

Astuce

Pour récupérer les annotations résolues (et non leur forme texte sous from __future__ import annotations), préfère inspect.get_annotations(obj, eval_str=True) à un accès direct à __annotations__.

Créer des classes dynamiquement

Une classe est elle-même un objet, instance de type. L'écriture class n'est qu'un sucre syntaxique : tu peux fabriquer une classe à la main via type(nom, bases, namespace).

Utile pour générer des classes à partir de données (schémas, lignes de configuration). Dans 95 % des cas, une dataclass ou une fabrique de fonctions reste plus lisible.

__init_subclass__ et __set_name__

Avant de sortir l'artillerie des métaclasses, connais ces deux hooks introduits pour couvrir leurs usages courants — bien plus simples à lire.

__init_subclass__ est une méthode de classe (implicitement) appelée automatiquement chaque fois qu'une sous-classe est définie. Idéal pour enregistrer des plugins ou valider une configuration.

Les arguments passés dans la liste des bases (nom="json") arrivent en keyword dans __init_subclass__. Pas besoin de @classmethod : Python l'enveloppe tout seul.

__set_name__ est appelé sur un objet stocké comme attribut de classe, au moment où la classe se crée : il reçoit la classe propriétaire et le nom de l'attribut. C'est le cœur des descripteurs modernes (champs typés, ORM).

Sans __set_name__, il faudrait répéter le nom du champ (titre = Champ("titre")) : le hook l'injecte tout seul.

Les métaclasses : puissance et parcimonie

Une métaclasse est la « classe d'une classe ». Par défaut c'est type ; en héritant de type, tu peux intercepter la création de toute classe qui l'utilise. C'est le mécanisme qui alimente des frameworks et des ORM (Django, SQLAlchemy historique).

On surcharge __call__ de la métaclasse pour contrôler l'instanciation. __new__/__init__ de la métaclasse, eux, agissent sur la construction de la classe elle-même.

Piège fréquent

Les métaclasses se combinent mal : deux bases avec des métaclasses incompatibles lèvent TypeError: metaclass conflict. Pour un singleton comme ci-dessus, un simple décorateur ou functools.cache sur une fabrique évite ce risque. Réserve les métaclasses aux cas où tu dois agir sur chaque classe d'une hiérarchie sans coopération explicite.

Cas réel

Quand tu écris, dans Django, class Article(models.Model): titre = models.CharField(max_length=200), aucune de ces lignes ne crée « à la main » une table. C'est la métaclasse de models.Model (nommée ModelBase) qui, au moment où ta classe est définie, parcourt les attributs Field, en déduit les colonnes SQL, prépare les migrations et câble l'accès à la base. SQLAlchemy fait de même avec DeclarativeMeta. C'est le cas d'école où la métaclasse se justifie : le framework doit agir sur chaque modèle que tu définiras, sans que tu aies rien à appeler. Depuis Python 3.6, une bonne partie de ces usages a d'ailleurs migré vers le hook plus léger __init_subclass__ (PEP 487) — preuve que même les auteurs de frameworks fuient les métaclasses dès qu'ils le peuvent.

Le packaging moderne

Distribuer du code, c'est le rendre installable par pip. Le standard actuel repose sur un seul fichier déclaratif, pyproject.toml, et une disposition src-layout.

Le [build-system] indique l'outil de build (ici hatchling). [project.scripts] crée une commande exécutable qui appelle main().

Note

Les outils modernes comme uv ou hatch orchestrent venv, build et publication en quelques commandes, à partir du même pyproject.toml standard. Apprends d'abord le format ; l'outillage n'est qu'une couche au-dessus.

Et après

Tu maîtrises désormais le Python avancé : typage, robustesse, performance, asynchrone, métaprogrammation, packaging. Le langage n'a plus de zone d'ombre pour toi — reste à choisir ton terrain de jeu.

  • Data & calcul : NumPy et pandas pour manipuler de gros volumes, puis Polars pour la performance.
  • Web : FastAPI (async, typé, moderne) pour des API, Django pour des applications complètes.
  • Automatisation : scripts, scraping, ops — Python excelle pour relier des systèmes.
  • Performance native : Cython, ou des extensions en Rust via PyO3/maturin quand le CPU est le goulot.
  • Open source : lis le code de projets que tu utilises, ouvre une issue, propose une pull request. C'est le meilleur accélérateur.

Le plus dur est fait. Choisis un projet réel qui te motive et construis-le : c'est là que tout ce cours prendra son sens.

Checklist : métaprogrammation, oui ou non ?

Avant d'ajouter de la « magie », demande-toi si un outil plus simple ferait l'affaire. Voici quand y recourir — et quand t'en abstenir.

  • Recours justifié : enregistrer automatiquement des sous-classes (plugins) → __init_subclass__.
  • Recours justifié : champs descripteurs qui ont besoin de leur propre nom → __set_name__.
  • Recours justifié : framework/ORM imposant un comportement à toute une hiérarchie de classes → métaclasse.
  • Recours justifié : générer des classes à partir d'un schéma externe (données, IDL) → type(...).
  • À éviter : ajouter/modifier une méthode sur une classe → un décorateur de classe suffit, et se lit mieux.
  • À éviter : valider des attributs simples → @dataclass + __post_init__, ou pydantic.
  • À éviter : mémoriser un singleton ou un cache → functools.cache sur une fabrique.
  • Règle générale : si un junior de l'équipe ne peut pas comprendre le mécanisme en une minute, choisis l'option plus explicite.

Antisèche : métaprogrammation & packaging

Glossaire

Introspection
Examiner un objet à l'exécution : son type, ses attributs, sa signature (type, getattr, vars, inspect).
Métaprogrammation
Du code qui manipule du code : lire, modifier ou fabriquer des classes et des fonctions pendant l'exécution.
Métaclasse
La « classe d'une classe » (type par défaut). En hériter permet d'intercepter la création de chaque classe qui l'utilise.
__init_subclass__
Hook appelé automatiquement à la définition de chaque sous-classe ; remplace la plupart des métaclasses (enregistrement de plugins).
__set_name__
Méthode d'un descripteur, appelée à la création de la classe ; elle reçoit le nom de l'attribut (cœur des champs d'ORM).
pyproject.toml
Fichier déclaratif unique d'un paquet Python moderne : nom, version, dépendances, backend de build, commandes.
Wheel (.whl)
Format de distribution binaire installable directement par pip, produit par python -m build.
Installation éditable (-e)
pip install -e . installe un lien vers tes sources : tes modifications sont prises en compte sans réinstaller.

Récap et vérification

  • Introspection : type, isinstance, getattr/setattr/hasattr, vars/__dict__ et inspect.signature pour examiner objets et appelables.
  • Classes dynamiques : type(nom, bases, namespace) fabrique une classe à l'exécution.
  • Hooks : __init_subclass__ (à chaque sous-classe) et __set_name__ (nom d'un attribut de classe) remplacent souvent une métaclasse.
  • Métaclasses : réservées aux frameworks ; préfère un décorateur de classe ou __init_subclass__ dès que possible.
  • Packaging : pyproject.toml + src-layout, venv pour isoler, build/twine pour distribuer sur PyPI.
