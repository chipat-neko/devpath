Les compréhensions

~32 min Intermédiaire Leçon 09 recommandée

À la fin de cette leçon, tu sauras

  • écrire une compréhension de liste pour remplacer une boucle for avec append() ;
  • ajouter un filtre (if) et une transformation à l'intérieur d'une compréhension ;
  • construire des compréhensions de dict et de set, et reconnaître une expression génératrice ;
  • choisir entre une compréhension et une boucle classique selon la lisibilité.
Sommaire de la leçon

Tu sais déjà construire une liste avec une boucle : tu pars d'une liste vide, tu parcours un itérable, et tu ajoutes des éléments avec append(). C'est correct, mais Python propose une écriture plus courte et souvent plus lisible pour ce schéma très fréquent : la compréhension.

Dans cette leçon, on part de la compréhension de liste, puis on lui ajoute un filtre et une transformation. On découvre ensuite les compréhensions de dictionnaire et d'ensemble, les versions imbriquées (avec prudence), et les expressions génératrices. On finit par le plus important : savoir quand ne pas en abuser.

La compréhension de liste

Imaginons que tu veuilles la liste des carrés de 0 à 4. Avec une boucle classique, tu écris trois lignes : créer la liste vide, boucler, ajouter.

La compréhension de liste exprime exactement la même idée sur une seule ligne. Sa forme générale est [expression for element in iterable] : l'expression est ce que tu veux mettre dans chaque case, et for element in iterable indique sur quoi tu boucles.

Lis-la de gauche à droite, presque comme une phrase : « n * n pour chaque n dans range(5) ». Le résultat est une vraie liste, identique à celle de la boucle, mais l'intention saute aux yeux.

Note

Les crochets [ ] produisent une liste. À l'intérieur, on ne met pas de : ni de append() : la compréhension construit la liste pour toi, élément par élément.

Ajouter un filtre avec if

Souvent, tu ne veux garder qu'une partie des éléments. Il suffit d'ajouter une condition à la fin : [x for x in iterable if condition]. Seuls les éléments pour lesquels la condition est vraie entrent dans la liste.

Ici, x % 2 == 0 teste si x est pair. Les nombres impairs sont simplement ignorés : ils ne déclenchent aucun ajout. C'est l'équivalent direct d'un if placé à l'intérieur d'une boucle for.

Transformer chaque élément

L'expression de gauche n'est pas obligée de reprendre l'élément tel quel : tu peux le transformer. C'est tout l'intérêt : produire une nouvelle liste à partir d'une ancienne.

Tu peux bien sûr combiner les deux : transformer et filtrer dans la même compréhension. La transformation est à gauche, le filtre à droite.

Compréhensions de dict et de set

Le même principe s'applique aux dictionnaires et aux ensembles : on change juste les délimiteurs. Pour un dict, on utilise des accolades avec un couple cle: valeur séparé par deux-points : {cle: valeur for ...}.

Pour un set (ensemble : collection sans doublon), on garde les accolades mais sans le : : {x for ...}. Les doublons sont éliminés automatiquement.

Piège fréquent

Les accolades { } servent à la fois aux dicts et aux sets. La différence est la présence d'un : : {mot: len(mot) for ...} donne un dict, {mot for ...} donne un set. Attention : {} tout seul est un dict vide, pas un set vide (pour un set vide, il faut écrire set()).

Cas réel

Les compréhensions sont l'outil quotidien du traitement de données. Pour préparer un jeu de données, on filtre et on convertit en une ligne : [float(p) for p in prix if p] transforme des prix texte en nombres tout en ignorant les cases vides ; {u["id"]: u["nom"] for u in utilisateurs} construit un index id → nom à partir d'une liste d'enregistrements (typiquement du JSON reçu d'une API) ; [ligne.strip() for ligne in fichier] lit un fichier ligne par ligne en nettoyant chacune. C'est le pain quotidien de l'analyse de données et du back-end web.

Compréhensions imbriquées

On peut enchaîner deux for dans une même compréhension, par exemple pour parcourir une grille ou aplatir une liste de listes. L'ordre des for est le même que si tu les empilais dans une boucle.

Lis-la dans l'ordre d'écriture : « pour chaque ligne dans grille, pour chaque valeur dans ligne ». C'est puissant, mais ça devient vite illisible. Au-delà de deux niveaux, une boucle classique est presque toujours plus claire — on y revient dans les pièges.

Les expressions génératrices

Si tu remplaces les crochets par des parenthèses, tu obtiens une expression génératrice : (x for x in ...). Elle ne construit pas la liste d'un coup en mémoire : elle produit les valeurs à la demande, une par une, au fur et à mesure qu'on les consomme. On dit qu'elle est paresseuse.

Pour un calcul comme sum() qui consomme les valeurs au vol, l'expression génératrice évite de stocker mille nombres inutilement : elle est plus économe en mémoire. Quand une fonction n'a besoin de parcourir les valeurs qu'une fois, c'est le bon réflexe (on peut même omettre les parenthèses internes, comme ci-dessus).

Note

Une expression génératrice ne se parcourt qu'une seule fois. Si tu as besoin de réutiliser le résultat plusieurs fois, garde une vraie liste. On approfondira les générateurs et le mot-clé yield dans une leçon dédiée.

Quand ne pas en abuser

Une compréhension brille pour construire une collection à partir d'une autre. En revanche, deux cas appellent plutôt une boucle classique.

Premier cas : tu veux seulement un effet de bord (afficher, écrire dans un fichier…) sans construire de liste. Détourner une compréhension pour ça crée une liste de None inutile : c'est trompeur.

Second cas : la logique est complexe (plusieurs conditions, calculs intermédiaires). Une compréhension qu'on ne peut pas lire d'un coup d'œil a perdu son seul avantage. Si tu hésites, écris la boucle.

Astuce

Le bon critère est la lisibilité, pas la concision à tout prix. Une compréhension bien faite est à la fois plus courte, plus rapide qu'une boucle équivalente, et plus facile à lire. Si elle ne tient plus sur une ligne lisible, reviens à la boucle.

Pièges fréquents

  • Compréhension illisible. Trop de for et de if imbriqués rendent le code incompréhensible. Au-delà de deux niveaux, préfère une boucle.
  • Effet de bord détourné. [print(x) for x in liste] crée une liste de None dont personne ne se sert. Utilise une boucle for pour les effets de bord.
  • Confondre dict et set. {x for x in ...} est un set, {k: v for ...} est un dict. Et {} seul est un dict vide.
  • Croire qu'une compréhension est « juste un raccourci d'écriture ». Elle est aussi souvent plus rapide qu'une boucle append() équivalente : ce n'est pas qu'une question de style.

Piège fréquent

L'ordre compte : le filtre if se place après le for quand il ne fait que garder ou rejeter ([x for x in l if x > 0]). Un if … else qui choisit la valeur, lui, se place avant le for, dans l'expression ([x if x > 0 else 0 for x in l]).

Pour aller plus loin

Les expressions génératrices ne sont que la partie visible d'un sujet plus large : les générateurs et le mot-clé yield, qui permettent de produire des valeurs paresseusement dans tes propres fonctions. Tu croiseras aussi map() et filter(), deux fonctions qui font un travail proche des compréhensions, souvent considérées comme moins lisibles en Python moderne.

Enfin, la convention de style officielle (PEP 8) recommande de garder les compréhensions simples et sur une ligne lisible. Dès qu'une compréhension devient dense, c'est le signal de revenir à une boucle explicite.

Pour aller plus loin

La leçon sur les générateurs et yield reprendra les expressions génératrices en détail, et comparera map()/filter() aux compréhensions. Garde simplement en tête la forme (x for x in ...) : tu sauras la relire le moment venu.

Antisèche : les compréhensions

Toutes les formes en un coup d'œil.

Glossaire

Compréhension
Écriture concise qui construit une liste, un dict ou un set à partir d'un itérable, en une seule expression.
Itérable
Objet qu'on peut parcourir élément par élément : liste, chaîne, range, dictionnaire…
Expression
La partie de gauche d'une compréhension : elle calcule la valeur de chaque élément produit.
Filtre (if)
Condition placée après le for : elle décide si un élément entre ou non dans le résultat.
Compréhension de dict
Forme {cle: valeur for ...} qui construit un dictionnaire ; les deux-points la distinguent d'un set.
Expression génératrice
Forme entre parenthèses (expr for ...) qui produit les valeurs à la demande sans les stocker.
Paresseux (lazy)
Se dit d'un calcul qui ne produit une valeur qu'au moment précis où on en a besoin.
Effet de bord
Action qui agit sur l'extérieur (afficher, écrire) au lieu de renvoyer une valeur ; à éviter dans une compréhension.

Récap et vérification

  • Compréhension de liste : [expression for element in iterable] remplace une boucle avec append().
  • Filtre : [x for x in iterable if condition] ne garde que certains éléments.
  • Transformation : l'expression de gauche peut modifier chaque élément (x * 2, mot.upper()).
  • Dict : {cle: val for ...} ; set : {x for ...} ; {} est un dict vide.
  • Parenthèses → expression génératrice (x for x in ...) : paresseuse et économe en mémoire.
  • Pour un simple effet de bord ou une logique complexe, garde une boucle classique.

Vérifie ta compréhension

  1. Que produit [n + 1 for n in range(3)], et avec quelle boucle équivalente l'écrirais-tu ?
  2. Quelle est la différence entre {x for x in mots} et {x: len(x) for x in mots} ?
  3. Pourquoi sum(n for n in range(100)) est-il préférable à sum([n for n in range(100)]) ?
