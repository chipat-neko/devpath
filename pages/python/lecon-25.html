Stocker des données avec SQLite

~36 min Intermédiaire Leçons 8 et 12 recommandées

À la fin de cette leçon, tu sauras

  • expliquer ce qu'est SQLite et pourquoi il est idéal pour débuter ;
  • ouvrir une connexion, créer un curseur et une table ;
  • insérer et lire des données avec du SQL depuis Python ;
  • utiliser des requêtes paramétrées (?) pour éviter l'injection SQL ;
  • valider une transaction (commit) et fermer proprement avec un with.
Sommaire de la leçon

Jusqu'ici, tes données disparaissaient à la fin du programme. Pour les conserver, on peut écrire un fichier texte ou du JSON… mais dès qu'il s'agit de chercher, trier ou relier des milliers d'enregistrements, il faut une vraie base de données. La bonne nouvelle : Python en embarque une, SQLite, via le module sqlite3 de la bibliothèque standard. Aucune installation, aucun serveur : toute la base tient dans un seul fichier.

Une base de données dans un fichier

La plupart des bases (PostgreSQL, MySQL) sont des serveurs : un logiciel séparé qu'il faut installer, lancer et auquel on se connecte par le réseau. SQLite, lui, vit à l'intérieur de ton programme et range tout dans un fichier .db. C'est parfait pour apprendre, prototyper, ou pour une application locale.

Se connecter et créer une table

Tout part d'une connexion (connect) vers un fichier — créé s'il n'existe pas. On demande ensuite un curseur (cursor), l'objet qui exécute le SQL et récupère les résultats.

À retenir

Sans commit(), tes écritures (INSERT, UPDATE, DELETE) restent en attente et sont perdues à la fermeture. La lecture (SELECT), elle, ne nécessite pas de commit. Une base spéciale, sqlite3.connect(":memory:"), vit uniquement en mémoire : idéale pour les tests.

Insérer des données : toujours avec des paramètres

Pour insérer, on écrit la requête avec des points d'interrogation ? en guise de trous, et on fournit les valeurs à part, dans un tuple. Ne construis jamais une requête en collant les valeurs avec une f-string : c'est la porte ouverte à l'injection SQL.

Erreur fréquente

Écrire cur.execute(f"INSERT … VALUES ('{titre}')") semble marcher… jusqu'à ce qu'un titre contienne une apostrophe ou une commande malveillante. Toujours le ? et le tuple de valeurs. Détail : un tuple d'une seule valeur s'écrit (x,) avec la virgule.

Lire les données

Après un SELECT, on récupère les lignes : fetchone() pour la première, fetchall() pour toutes, ou une simple boucle for sur le curseur (la plus économe en mémoire). Chaque ligne est un tuple.

Bonne pratique

Par défaut, une ligne est un tuple : on y accède par position (ligne[0]). En posant conn.row_factory = sqlite3.Row, on accède aux colonnes par leur nom (ligne["titre"]), bien plus lisible quand les tables grossissent.

Le gestionnaire de contexte : fermer sans y penser

Comme pour les fichiers, un bloc with gère la connexion : il fait un commit automatique si tout se passe bien, et un rollback (annulation) si une exception survient. On n'oublie plus jamais de valider.

Cas réel : SQLite est partout

Cas réel

SQLite est probablement la base la plus déployée au monde : Firefox et Chrome y rangent ton historique, tes cookies et tes marque-pages ; Android et iOS l'utilisent pour les données des applications ; WhatsApp y stocke tes messages. La raison : un fichier unique, robuste, sans serveur à maintenir. Ton petit script de gestion de bibliothèque repose exactement sur la même technologie qu'un téléphone que des milliards de gens ont en poche.

Pour aller plus loin

Écrire du SQL à la main devient vite répétitif. Un ORM (Object-Relational Mapping) comme SQLAlchemy ou le module peewee traduit tes objets Python en lignes de table automatiquement. Et quand une application doit servir de nombreux utilisateurs en même temps, on migre vers un serveur comme PostgreSQL — mais le SQL appris ici reste presque identique.

Antisèche

Glossaire

SQLite
Moteur de base de données SQL léger et sans serveur, stockant toute la base dans un unique fichier ; inclus dans Python via sqlite3.
SQL
Langage standard d'interrogation des bases relationnelles (SELECT, INSERT, UPDATE, DELETE).
Connexion
Objet ouvrant l'accès à la base (connect) ; c'est lui qui valide (commit) ou annule (rollback) les changements.
Curseur
Objet qui exécute les requêtes (execute) et parcourt les résultats (fetchone, fetchall).
Requête paramétrée
Requête où les valeurs sont remplacées par des ? et fournies à part ; le moteur les traite comme des données, jamais comme du code.
Injection SQL
Faille où une valeur mal maîtrisée modifie la requête ; évitée par les requêtes paramétrées.
Transaction
Ensemble d'écritures validées d'un bloc par commit, ou toutes annulées par rollback.
Clé primaire
Colonne identifiant de façon unique chaque ligne d'une table (souvent id INTEGER PRIMARY KEY).

Récap et vérification

  • SQLite (sqlite3) offre une base SQL complète dans un simple fichier, sans serveur.
  • Le trio de base : connect → cursor → execute, puis commit pour les écritures.
  • On insère et on filtre toujours avec des paramètres ?, jamais avec une f-string (injection SQL).
  • On lit avec fetchone, fetchall ou une boucle ; sqlite3.Row donne l'accès par nom.
  • Un bloc with valide et ferme proprement, même en cas d'erreur.

Vérifie ta compréhension

  1. Qu'est-ce qui distingue SQLite d'une base comme PostgreSQL ?
  2. Que se passe-t-il si tu oublies conn.commit() après un INSERT ?
  3. Pourquoi utiliser ? plutôt qu'une f-string dans une requête ?
  4. Quelle est la différence entre fetchone() et fetchall() ?
