Le système d'import et les plugins

~40 min Avancé Leçon 12 recommandée

À la fin de cette leçon, tu sauras

  • décrire les étapes qu'un import déclenche réellement ;
  • expliquer le rôle du cache sys.modules et du chemin sys.path ;
  • distinguer imports absolus et relatifs et dénouer un import circulaire ;
  • importer dynamiquement un module avec importlib.import_module ;
  • construire un système de plugins par registre ou par entry points.
Sommaire de la leçon

Une ligne aussi banale que import json déclenche une machinerie que la plupart des développeurs n'ouvrent jamais. La comprendre change tout : on cesse de subir les imports circulaires, on sait pourquoi un module coûteux ralentit le démarrage, et surtout on peut bâtir des applications extensibles où des greffons se branchent sans toucher au cœur. C'est le mécanisme qui fait de pytest, Flask ou Django des plateformes et pas seulement des bibliothèques.

Ce que fait vraiment import

Importer n'est pas « coller un fichier » : c'est exécuter un module une fois, puis lier son objet à un nom local. La séquence tient en quatre temps : Python regarde d'abord si le module est déjà dans le cache sys.modules ; sinon, un finder le localise le long de sys.path ; un loader exécute son code de haut en bas ; le module obtenu est mis en cache et le nom est lié dans ton espace de noms.

Note

Parce qu'un module n'est exécuté qu'une fois puis mis en cache, une variable définie à son niveau supérieur se comporte comme un singleton partagé par tout le programme. C'est le mécanisme derrière les « modules de configuration » ou les connexions uniques : tout le monde qui fait from config import settings voit le même objet.

Packages, imports absolus et relatifs

Un package est un dossier de modules. Historiquement il contient un __init__.py (exécuté quand on importe le package) ; depuis Python 3.3, un dossier sans __init__.py forme un namespace package. Pour désigner un module voisin, deux styles : l'import absolu part de la racine du projet (from monapp.core import moteur) ; l'import relatif part du module courant (from .core import moteur, le point = « ici »).

Erreur fréquente : l'import circulaire

Si a.py fait import b en tête, et b.py fait import a en tête, le premier des deux à se charger tombe sur un module à moitié exécuté : ImportError: cannot import name… ou AttributeError. Trois issues : (1) déplacer l'import dans la fonction qui en a besoin (import différé) ; (2) extraire la partie commune dans un troisième module que les deux importent ; (3) importer le module (import b) plutôt que le nom (from b import X), et n'accéder à b.X qu'à l'exécution.

Import dynamique et paresseux

Le nom d'un module n'a pas besoin d'être écrit en dur. importlib.import_module("paquet.module") importe à partir d'une chaîne calculée à l'exécution — la base de tout chargement piloté par la configuration. Et un import placé dans une fonction n'est exécuté qu'au premier appel : on diffère ainsi le coût d'une dépendance lourde (et on brise au passage les cycles).

Astuce : le coût d'un import est du code exécuté

Tout ce qui est écrit au niveau supérieur d'un module tourne à l'import : ouvrir un fichier, compiler une regex géante ou charger un modèle de 200 Mo ralentit le démarrage de quiconque importe le module. Garde le niveau module léger (définitions), et fais le travail coûteux dans des fonctions appelées à la demande.

Construire un système de plugins

Un système de plugins, c'est un cœur qui expose un point d'extension et découvre des greffons sans les connaître à l'avance. Deux techniques dominent. La plus simple : un registre rempli par un décorateur, idéal à l'intérieur d'une même application. La plus puissante : les entry points, déclarés dans le pyproject.toml de chaque paquet et lus via importlib.metadata — c'est ainsi qu'un paquet tiers, installé séparément, s'ajoute tout seul.

Cas réel

Comment pytest découvre ses greffons. Installe pytest-cov ou pytest-django et, sans une ligne de configuration, la commande pytest gagne de nouvelles options. Le secret : chaque paquet publie un entry point dans le groupe pytest11 ; au démarrage, pytest lit importlib.metadata.entry_points(group="pytest11") et charge tout ce qu'il trouve. Flask (extensions), Django (applications), Sphinx (extensions) reposent sur le même principe : un cœur stable, une périphérie ouverte. Comprendre ce mécanisme, c'est pouvoir transformer ta propre bibliothèque en plateforme.

Glossaire

Module et package
Un module est un fichier .py ; un package est un dossier contenant un __init__.py qui regroupe plusieurs modules.
sys.modules
Cache des modules déjà importés : un second import y puise directement, sans réexécuter le code du module.
sys.path
Liste ordonnée des dossiers où Python cherche un module à importer ; l'ordre détermine la priorité en cas d'homonymes.
Finder et loader
Le finder localise le module sur sys.path, le loader exécute son code une seule fois pour construire l'objet module.
Import absolu / relatif
L'absolu part de la racine du package (from pkg.mod import X) ; le relatif part du module courant (. = ici, .. = parent).
Import circulaire
Deux modules qui s'importent mutuellement ; se résout en différant l'import dans une fonction ou en extrayant un module commun.
importlib.import_module
Importe un module dont le nom n'est connu qu'à l'exécution (une chaîne) : base du chargement dynamique.
Entry point
Déclaration publiée par un paquet et lue via importlib.metadata ; elle permet à un programme hôte de découvrir des plugins sans les connaître à l'avance.

Récap et vérification

  • Un import en 4 temps : cache sys.modules → finder sur sys.path → loader qui exécute le code une fois → nom lié et mis en cache.
  • Exécution unique : réimporter renvoie l'objet en cache ; les variables de niveau module sont des singletons partagés.
  • Absolu vs relatif : from pkg.mod import X (par défaut) ou from .mod import X (. ici, .. parent).
  • Import circulaire : différer l'import dans la fonction, extraire un module commun, ou importer le module et non le nom.
  • Dynamique & plugins : importlib.import_module pour charger par chaîne ; registre par décorateur ou entry points pour un cœur extensible.
