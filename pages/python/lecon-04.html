Module 02 · Logique & flux — Leçon 04

Les conditions

~33 min Débutant Module 1 recommandé

À la fin de cette leçon, tu sauras

  • écrire des branchements avec if, elif et else en respectant le deux-points et l'indentation ;
  • combiner des conditions avec and, or, not et comprendre le truthy/falsy ;
  • condenser un choix avec l'expression ternaire et comparer une valeur à des motifs avec match / case ;
  • structurer ton code avec des clauses de garde pour éviter l'imbrication profonde.
Sommaire de la leçon

Jusqu'ici, tes programmes exécutaient toutes leurs lignes, dans l'ordre, sans jamais en sauter aucune. Mais un programme utile doit souvent choisir : afficher un message différent selon l'âge, accepter ou refuser une saisie, traiter un cas particulier. C'est le rôle des conditions : exécuter un bloc de code seulement si quelque chose est vrai.

Dans cette leçon, on part du if le plus simple, puis on ajoute les variantes (elif, else), l'expression ternaire, le match / case et quelques bonnes habitudes. Garde un interpréteur ouvert : recopie chaque exemple et modifie les valeurs pour voir le branchement changer.

if / elif / else et l'indentation

Un if teste une condition (une expression qui vaut True ou False). Si elle est vraie, le bloc qui suit s'exécute. La ligne d'en-tête se termine obligatoirement par un deux-points :, et le bloc qui en dépend est indenté — par convention de 4 espaces.

En Python, ce ne sont pas des accolades qui délimitent le bloc, mais l'indentation elle-même. Tout ce qui est décalé sous le if appartient au bloc ; dès qu'on revient à gauche, on en sort. C'est la règle entrevue dans la leçon 1 : ici, elle devient ton principal outil de structure.

Pour gérer le cas contraire, ajoute un else. Pour intercaler d'autres tests, place un ou plusieurs elif (contraction d'« else if ») entre le if et le else.

Python teste les conditions de haut en bas et s'arrête à la première qui est vraie ; les suivantes sont ignorées. C'est pour cela qu'on ordonne du plus exigeant au moins exigeant : avec note = 13, note >= 16 est faux, note >= 14 aussi, puis note >= 12 est vrai — on s'arrête là.

Comparer des valeurs

Une condition repose le plus souvent sur une comparaison. Voici les opérateurs courants : == (égal à), != (différent de), <, <=, >, >=. Attention : l'égalité se teste avec deux signes égal ==, car un seul = sert à affecter une variable.

Note

Python autorise les comparaisons chaînées, comme en mathématiques : 0 <= age < 18 signifie « age est compris entre 0 inclus et 18 exclu ». C'est plus lisible que age >= 0 and age < 18.

Conditions imbriquées vs cascade elif

Tu peux mettre un if à l'intérieur d'un autre : on parle de conditions imbriquées. Chaque niveau ajoute 4 espaces d'indentation. C'est utile quand un test n'a de sens que si un premier est déjà vrai.

Combiner des conditions : and, or, not

Pour exprimer une condition composée, relie plusieurs tests avec les opérateurs logiques and (et), or (ou) et not (négation). and exige que tout soit vrai ; or se contente d'un seul vrai ; not inverse.

Une condition n'a même pas besoin d'être une comparaison. En Python, toute valeur a une « vérité » : c'est la notion de truthy / falsy. Sont considérés comme faux (falsy) : 0, la chaîne vide "", la liste vide [], et None. Presque tout le reste est vrai (truthy).

Écrire if nom: est plus pythonique que if nom != "": : on s'appuie directement sur la véracité de la valeur.

L'expression ternaire

Quand un if / else sert juste à choisir une valeur entre deux, tu peux le condenser en une seule ligne avec l'expression ternaire. Sa forme est : valeur_si_vrai if condition else valeur_si_faux.

Lis-la comme une phrase : « statut vaut "majeur" si age >= 18, sinon "mineur" ». Pratique aussi à l'intérieur d'un print() ou d'une f-string.

Astuce

Garde le ternaire pour les cas courts et lisibles. Dès qu'il y a trois branches ou plus, ou une logique un peu touffue, repasse à un if / elif / else classique : la clarté prime sur la concision.

match / case

Depuis Python 3.10, match / case compare une valeur à plusieurs motifs. C'est souvent plus lisible qu'une longue cascade de elif quand on teste une même variable contre plusieurs valeurs précises. Le motif _ (souligné) joue le rôle de « tout le reste », comme un else.

Chaque case ouvre son propre bloc indenté. Contrairement à d'autres langages, il n'y a pas besoin d'un break : Python n'exécute qu'un seul case et sort tout seul. La barre | permet de regrouper plusieurs valeurs dans un même cas.

Bonnes pratiques : clauses de garde

Quand plusieurs conditions doivent être vérifiées avant le « vrai » travail, l'instinct du débutant est d'imbriquer des if, ce qui décale le code de plus en plus vers la droite. La technique de la clause de garde (sortie anticipée) inverse la logique : on traite et on quitte dès qu'un cas invalide se présente, pour garder le chemin principal à plat.

Compare mentalement avec la version « tout imbriqué » : la garde évite trois niveaux d'indentation et rend chaque cas évident. (On reverra def et return dans la leçon sur les fonctions ; retiens ici l'idée de sortir tôt.)

Cas réel

Les clauses de garde sont omniprésentes dans le code de production. Une fonction qui traite un formulaire d'inscription commence par écarter les cas fautifs — champ vide, e-mail sans @, mot de passe trop court — en renvoyant un message d'erreur pour chacun. La création réelle du compte reste tout en bas, à plat. C'est le style early return qu'on retrouve dans la plupart des bases de code professionnelles.

Pièges fréquents

  • Le deux-points oublié. Toute ligne d'en-tête (if, elif, else, match, case) se termine par :. L'oublier déclenche une SyntaxError.
  • Espaces et tabulations mélangés. N'indente qu'avec des espaces (4 par convention). Mélanger espaces et tabulations provoque une IndentationError ou une TabError. Configure ton éditeur pour insérer des espaces.
  • = au lieu de ==. Dans une condition, if x = 5: est une erreur : il faut if x == 5:. Un seul = affecte, deux == comparent.
  • Comparer à True / False explicitement. Écris if actif: plutôt que if actif == True:, et if not actif: plutôt que if actif == False: : c'est plus court et plus pythonique.

Piège fréquent

L'erreur la plus classique est de confondre = (affectation) et == (comparaison). Heureusement, Python refuse if x = 5: avec une SyntaxError : il t'attrape tout de suite au lieu de produire un résultat faux en silence.

Pour aller plus loin

Le match / case va bien plus loin que la simple égalité : il sait déstructurer des données (par exemple un couple case (x, y): qui extrait deux valeurs) et filtrer avec une garde (case n if n < 0: ne s'applique que si la condition supplémentaire est vraie). C'est un outil puissant que tu apprivoiseras avec les structures de données.

Autre nouveauté à connaître : l'opérateur morse :=, qui permet d'affecter une variable dans la condition elle-même. Par exemple, if (n := len(nom)) > 10: stocke la longueur dans n tout en la testant, ce qui évite de répéter le calcul. À utiliser avec parcimonie, uniquement quand ça améliore vraiment la lisibilité.

Pour aller plus loin

Une condition claire vaut mieux qu'une condition courte. Nomme les sous-conditions complexes dans des variables (est_majeur = age >= 18) : ton if est_majeur and a_paye: se lira alors comme une phrase.

Glossaire

Condition
Expression qui vaut True ou False et décide si un bloc s'exécute.
Bloc
Ensemble de lignes indentées sous une même en-tête (if, elif, else…).
Indentation
Décalage de 4 espaces qui délimite un bloc en Python, à la place des accolades.
elif
Contraction d'« else if » : un cas supplémentaire, testé seulement si les précédents sont faux.
Expression ternaire
valeur_si_vrai if condition else valeur_si_faux : choisit une valeur en une ligne.
match / case
Compare une valeur à plusieurs motifs (depuis Python 3.10) ; _ capture « tout le reste ».
Clause de garde
Sortie anticipée (return, continue) sur les cas invalides pour éviter l'imbrication profonde.
Truthy / falsy
Véracité d'une valeur : 0, "", [], None sont faux ; presque tout le reste est vrai.

Récap et vérification

  • Un if exécute un bloc si sa condition est vraie ; l'en-tête finit par : et le bloc est indenté de 4 espaces.
  • elif ajoute des cas, else couvre le reste ; Python s'arrête à la première condition vraie.
  • On compare avec ==, !=, <, <=, >, >= ; on combine avec and, or, not et on s'appuie sur le truthy/falsy.
  • L'expression ternaire a if condition else b choisit une valeur sur une ligne ; match / case compare une valeur à des motifs.
  • Les clauses de garde (sortie anticipée) évitent l'imbrication profonde et gardent le code lisible.
