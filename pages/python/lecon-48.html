Sérialisation : pickle, JSON et binaire

~36 min Intermédiaire Leçon 5 recommandée

À la fin de cette leçon, tu sauras

  • sérialiser et désérialiser des objets Python avec pickle et connaître ses limites ;
  • comprendre pourquoi pickle.loads d'une source non fiable est dangereux ;
  • échanger des données interopérables en JSON avec default et object_hook ;
  • convertir une dataclass en JSON et inversement ;
  • empaqueter des données binaires compactes avec struct et l'endianness.
Sommaire de la leçon

Sérialiser, c'est transformer un objet vivant en mémoire en une suite d'octets qu'on peut écrire sur disque ou envoyer sur le réseau ; désérialiser, c'est reconstruire l'objet à partir de ces octets. Trois outils standard couvrent trois besoins : pickle (tout objet Python, mais Python seulement), json (interopérable avec le reste du monde), struct (binaire compact, format imposé). Bien choisir évite autant les fuites de sécurité que les fichiers illisibles.

pickle : sérialiser (presque) n'importe quel objet Python

pickle convertit des objets Python arbitraires — dictionnaires imbriqués, instances de classes, dataclasses — en un flux binaire, et les reconstruit à l'identique. C'est le format de la persistance interne (cache local, mémoïsation sur disque, communication entre processus multiprocessing).

Note

Tout n'est pas « picklable » : une connexion réseau ouverte, un fichier, un lambda ou une fonction locale ne le sont pas. Une classe peut personnaliser sa sérialisation via __getstate__ / __setstate__ (par exemple pour exclure un attribut non sérialisable et le recréer au chargement).

Le danger de pickle : ne jamais désérialiser une source non fiable

Point capital de sécurité : pickle.loads peut exécuter du code arbitraire. Le format autorise un objet à décrire, via __reduce__, « comment me reconstruire » — et cette instruction peut être un appel de fonction quelconque. Charger un pickle reçu d'une source non maîtrisée (upload utilisateur, message réseau, fichier téléchargé) revient à exécuter ce qu'elle veut sur ta machine.

Règle de sécurité

Ne pickle.loads que des données que tu as produites et protégées toi-même. Pour tout échange avec l'extérieur (API, upload, message d'un tiers), utilise JSON ou un autre format de données qui n'exécute rien. Si tu dois absolument transporter du pickle sur un canal, signe-le (HMAC) et vérifie la signature avant de le charger.

JSON : l'échange interopérable

json est le format universel du web : lisible, supporté par tous les langages, et surtout inerte (il ne décrit que des données). En contrepartie, il ne connaît qu'un jeu de types restreint : objets, tableaux, chaînes, nombres, booléens, null. Pour un type Python absent (datetime, Decimal, une classe), on fournit un convertisseur default à l'écriture et un object_hook à la lecture.

Pour un objet complexe (validation, types imbriqués, datetime gérés d'office), pydantic fait le travail de default/object_hook à ta place, avec vérification des types. C'est le choix de référence pour les API — mais comprendre les hooks bruts reste utile pour les cas sur mesure.

Le binaire compact : struct

Quand chaque octet compte — protocole réseau, format de fichier, en-tête binaire — struct empaquette des valeurs dans une disposition fixe décrite par une chaîne de format : type de chaque champ et boutisme (endianness, l'ordre des octets d'un nombre). C'est le contraire de JSON : illisible pour un humain, mais dense et exactement conforme à une spécification.

Pour manipuler de gros tampons binaires sans les copier, memoryview offre une vue directe sur les octets d'un objet : on peut découper (slicing) une trame réseau ou un fichier mappé sans dupliquer la mémoire.

Cas réel

Le cache « pratique » devenu porte d'entrée. Une application met en cache des objets de session avec pickle dans un magasin partagé (Redis) — rapide et sans effort de conversion. Mais un attaquant capable d'écrire dans ce magasin y dépose un pickle piégé : au prochain pickle.loads, son __reduce__ s'exécute sur le serveur (exécution de code à distance). Deux corrections : (1) sérialiser les sessions en JSON (données inertes, aucun code) quitte à écrire des convertisseurs ; (2) pour les échanges internes qui exigent pickle, signer chaque charge (HMAC) et refuser toute charge dont la signature ne correspond pas. La leçon : le format de sérialisation est une décision de sécurité, pas un détail d'implémentation.

Choisir le bon format

Trois questions tranchent : qui va relire (Python seul → pickle possible ; un autre langage → JSON) ? La source est-elle fiable (sinon jamais pickle) ? A-t-on besoin de compacité/conformité binaire (alors struct ou un format dédié comme Protocol Buffers) ?

Antisèche : les trois formats

Glossaire

Sérialisation
Transformation d'un objet en mémoire en une suite d'octets stockable ou transmissible ; la désérialisation fait l'inverse.
pickle
Format binaire propre à Python capable de sérialiser presque tout objet ; puissant mais dangereux à charger depuis une source non fiable.
__reduce__
Méthode qui indique à pickle comment reconstruire un objet ; c'est ce mécanisme qui rend possible l'exécution de code à la désérialisation.
JSON
Format texte interopérable et inerte (données uniquement) au jeu de types restreint : objets, tableaux, chaînes, nombres, booléens, null.
default / object_hook
Points d'extension de json : default convertit un type inconnu à l'écriture, object_hook reconstruit un type à la lecture.
struct
Module qui empaquette/déballe des données binaires selon une chaîne de format (types + endianness) : compact et conforme à une spécification.
Endianness (boutisme)
Ordre des octets d'un nombre multi-octets : big-endian (poids fort d'abord) ou little-endian ; à fixer explicitement dans un format binaire.

Récap et vérification

  • pickle : sérialise tout objet Python (dumps/loads), mais Python seulement — et jamais depuis une source non fiable.
  • Danger : pickle.loads peut exécuter du code via __reduce__ ; pour l'extérieur, JSON ou une charge signée.
  • JSON : interopérable et inerte ; default et object_hook gèrent les types absents ; asdict/**d pour les dataclasses.
  • struct : binaire compact et conforme à une spec ; pack/unpack + endianness ; memoryview pour découper sans copie.
  • Choisir : qui relit ? source fiable ? besoin de compacité binaire ?

Vérifie ta compréhension

  1. Pourquoi ne faut-il jamais pickle.loads un fichier reçu d'une source inconnue, alors que json.loads est sûr ?
  2. Comment sérialiser en JSON un objet d'un type que json ne connaît pas ?
