Fichiers et exceptions

~34 min Intermédiaire Leçon 11 recommandée

À la fin de cette leçon, tu sauras

  • ouvrir, lire et écrire des fichiers proprement avec with open(...) et les modes r, w, a ;
  • manipuler des chemins avec pathlib et persister des structures Python en JSON ;
  • gérer les erreurs avec try/except/else/finally, attraper un type précis et raise tes propres exceptions ;
  • comprendre la philosophie EAFP propre à Python.
Sommaire de la leçon

Jusqu'ici, tes programmes oubliaient tout en s'arrêtant : les valeurs vivaient en mémoire le temps de l'exécution, puis disparaissaient. Pour garder une trace — un score, une liste de tâches, une configuration — il faut écrire dans un fichier. Et dès qu'on touche au monde extérieur (un fichier absent, un disque plein, une saisie farfelue), des erreurs surviennent. Cette leçon couvre les deux faces de la même pièce : lire/écrire des fichiers, et gérer proprement ce qui peut mal tourner.

On part du plus simple — écrire une ligne de texte — puis on ajoute une notion à la fois : la lecture, les chemins, le format JSON, et enfin les exceptions. Garde un interpréteur ouvert et recopie chaque exemple : c'est en manipulant de vrais fichiers que ces réflexes s'installent.

Ouvrir un fichier avec with

La fonction open() ouvre un fichier. Tu lui donnes un chemin, un mode, et de préférence l'encodage. Les trois modes de base sont : "r" (lecture, read), "w" (écriture, write, qui écrase tout le contenu existant) et "a" (ajout, append, qui écrit à la fin sans rien effacer).

Un fichier ouvert doit être fermé pour que les données soient bien écrites sur le disque et que le système libère la ressource. Plutôt que d'appeler f.close() à la main (facile à oublier), on utilise le bloc with : il ferme le fichier automatiquement à la sortie du bloc, même si une erreur survient. C'est la façon idiomatique en Python.

Précise toujours encoding="utf-8" : c'est l'encodage universel pour le texte (accents, emojis, alphabets non latins). Sans lui, Python utilise un encodage par défaut qui varie selon le système d'exploitation, source de bugs difficiles à reproduire.

Note

Contrairement à print(), la méthode write() n'ajoute pas de retour à la ligne. Si tu veux que chaque appel écrive sa propre ligne, ajoute toi-même \n à la fin du texte.

Lire un fichier

En mode "r", plusieurs approches existent. read() renvoie tout le contenu en une seule chaîne. readlines() renvoie une liste de lignes. Mais le plus pythonique, surtout pour un gros fichier, est d'itérer directement sur le fichier : on lit ligne par ligne sans tout charger en mémoire.

Le mode "r" est celui par défaut : open("notes.txt", encoding="utf-8") ouvre aussi en lecture. Note l'usage de strip() pour retirer le \n que print() rajouterait sinon, te donnant des lignes vides en trop.

Écrire à la fin avec le mode a

Le mode "w" repart de zéro à chaque ouverture. Pour ajouter du contenu en conservant l'existant — un journal, un historique — utilise le mode "a".

Les chemins avec pathlib

Écrire un chemin « à la main » sous forme de texte ("dossier/sous-dossier/fichier.txt") pose problème : le séparateur diffère entre Windows (\) et Linux/macOS (/). La bibliothèque standard pathlib règle ça avec un objet Path portable, qui propose aussi des méthodes pratiques.

Avec Path, l'opérateur / ne fait pas une division : il assemble les segments d'un chemin. Les méthodes write_text() et read_text() ouvrent, écrivent ou lisent, et ferment le fichier en une seule ligne — pratique pour un petit contenu.

Persister des données en JSON

Un fichier texte stocke des chaînes. Mais comment sauvegarder un dict ou une list et les récupérer intacts ? Le format JSON est la réponse standard : un texte structuré que tout langage sait lire. Le module json de Python fait le pont : json.dump() écrit une structure dans un fichier, json.load() la relit.

Retiens le couple dump/load (avec un fichier) et son cousin dumps/loads (avec une simple chaîne, le s final pour string). Les types JSON correspondent aux types Python : objet ↔ dict, tableau ↔ list, true/false ↔ True/False, null ↔ None.

Cas réel

Quand une application garde tes réglages entre deux lancements — thème, langue, dernier fichier ouvert — elle les écrit très souvent dans un petit fichier JSON de configuration, du genre {"theme": "sombre", "langue": "fr"}. Au démarrage : json.load pour retrouver l'état ; à chaque changement : json.dump pour le sauvegarder. C'est le même principe que le bouton clair/sombre de ce site (côté navigateur, via un stockage cousin) : une préférence persistée qu'on relit plus tard.

Gérer les erreurs avec try / except

Ouvrir un fichier absent, convertir "abc" en nombre : ces actions lèvent une exception qui, non gérée, arrête le programme. Le bloc try / except permet d'intercepter l'erreur et de réagir au lieu de planter. La règle d'or : attrape un type précis, jamais « toutes les erreurs ».

Le bloc else regroupe le code qui ne doit s'exécuter que si tout s'est bien passé ; finally s'exécute dans tous les cas, idéal pour libérer une ressource. Le as e te donne accès à l'objet exception, dont le message est souvent instructif.

Lever et définir ses exceptions

Tu peux aussi déclencher une erreur toi-même avec raise, quand une situation est anormale pour ton programme. Et tu peux créer ta propre famille d'exceptions en héritant de Exception — utile pour distinguer tes erreurs métier des erreurs techniques.

Une classe d'exception qui se contente de pass suffit largement : son nom porte déjà tout le sens. En l'attrapant spécifiquement, l'appelant traite ce cas sans masquer d'autres bugs.

La philosophie EAFP

Beaucoup de langages encouragent à vérifier d'abord (« le fichier existe-t-il ? alors je l'ouvre »). Python préfère la philosophie EAFP — Easier to Ask Forgiveness than Permission, « il est plus facile de demander pardon que la permission ». On tente l'action, et on gère l'exception si elle échoue.

L'EAFP est souvent plus sûr (pas de décalage entre la vérification et l'action) et plus lisible. Tu retrouveras ce style partout dans le code Python idiomatique.

Pièges fréquents

  • Oublier de fermer le fichier. Sans with, des données peuvent ne pas être écrites et la ressource reste bloquée. Utilise toujours with open(...) as f:.
  • L'except: nu. except: ou except Exception: attrape tout, y compris des bugs que tu ne voulais pas cacher (faute de frappe, interruption clavier). Attrape un type précis : except ValueError.
  • Mauvais encodage. Lire un fichier UTF-8 sans préciser encoding="utf-8" peut transformer les accents en charabia ou lever une UnicodeDecodeError.
  • Écraser au lieu d'ajouter. Le mode "w" efface tout le contenu existant à l'ouverture. Pour conserver et compléter, c'est le mode "a".

Piège fréquent

Ouvrir un fichier important en mode "w" « pour voir » l'efface immédiatement, avant même que tu écrives quoi que ce soit. Dans le doute sur un fichier précieux, ouvre-le d'abord en "r", ou travaille sur une copie.

Pour aller plus loin

Le format texte et le JSON couvrent l'essentiel, mais d'autres outils de la bibliothèque standard méritent un coup d'œil quand tes besoins grandissent.

Le module csv lit et écrit les fichiers tableurs (colonnes séparées par des virgules), parfaits pour des données en lignes. Le module logging remplace avantageusement les print() de débogage par de vrais journaux configurables. Tu peux aussi écrire tes propres gestionnaires de contexte (l'objet derrière with) pour automatiser un nettoyage.

Pour aller plus loin

Le module pickle sait sérialiser presque n'importe quel objet Python, mais n'ouvre jamais un fichier pickle dont tu ne connais pas la source : sa lecture peut exécuter du code arbitraire. Pour échanger des données entre programmes, préfère le JSON, lisible et sûr.

Glossaire

Mode d'ouverture
Lettre passée à open() qui fixe l'usage : "r" lire, "w" écraser, "a" ajouter.
Gestionnaire de contexte
Objet utilisé avec with qui garantit une action de fin (ici, fermer le fichier) même en cas d'erreur.
Encodage
Façon de traduire le texte en octets. utf-8 gère accents et alphabets du monde entier ; à préciser toujours.
JSON
Format texte structuré et universel pour échanger et sauvegarder des données (objets, listes, nombres, booléens).
Sérialisation
Transformer une structure en mémoire (dict, list) en texte stockable ; l'inverse est la désérialisation.
Exception
Signal d'erreur levé pendant l'exécution ; non gérée, elle arrête le programme.
try / except
Bloc qui tente une action risquée et intercepte un type d'erreur précis pour y réagir sans planter.
EAFP
Easier to Ask Forgiveness than Permission : tenter l'action puis rattraper l'erreur, plutôt que tout vérifier avant.

Récap et vérification

  • with open(chemin, mode, encoding="utf-8") as f: ouvre et ferme automatiquement ; modes r (lire), w (écraser), a (ajouter).
  • On lit avec read(), readlines() ou en itérant ligne par ligne ; on écrit avec write() (qui n'ajoute pas de \n).
  • pathlib.Path assemble des chemins portables avec / et offre exists(), read_text(), write_text().
  • json.dump() / json.load() persistent et rechargent des dict et list.
  • try/except/else/finally gèrent les erreurs ; attrape un type précis, raise pour lever, et Python privilégie l'EAFP.

  2. Quelle est la différence entre les modes "w" et "a" ?
  3. Pourquoi un except ValueError est-il préférable à un except: nu ?
