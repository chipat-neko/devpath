Modules et bibliothèque standard

~32 min Intermédiaire Module 3 recommandé

À la fin de cette leçon, tu sauras

  • importer du code avec import module, from module import nom et import module as alias ;
  • créer ton propre module et protéger son code de lancement avec if __name__ == "__main__": ;
  • utiliser des modules de la bibliothèque standard (math, random, datetime, json, pathlib) ;
  • distinguer la bibliothèque standard des paquets tiers installés avec pip.
Sommaire de la leçon

Jusqu'ici, tu écrivais tout ton code dans un seul fichier. Mais un bon programme réutilise du code déjà écrit : le sien, celui des autres, et surtout celui que Python fournit en standard. Un module est simplement un fichier de code que l'on peut réutiliser ailleurs, et Python est livré avec des centaines de modules prêts à l'emploi. On résume ça par la formule « batteries included » : les piles sont fournies.

Dans cette leçon, tu vas apprendre à importer du code, à fabriquer ton propre module, puis à explorer quelques trésors de la bibliothèque standard. Garde un interpréteur ouvert : chaque exemple se recopie en quelques secondes.

Importer un module

Pour utiliser un module, on l'importe en haut du fichier avec le mot-clé import. Ensuite, on accède à ce qu'il contient avec la notation module.nom. Prenons math, le module des fonctions mathématiques.

Le préfixe math. indique clairement d'où vient chaque nom : c'est lisible et il n'y a aucun risque de collision avec tes propres variables. C'est la forme à privilégier par défaut.

from … import … et les alias

Si tu n'as besoin que d'un ou deux noms précis, tu peux les importer directement avec from module import nom. Tu les utilises alors sans préfixe.

Enfin, quand un nom de module est long, on lui donne un alias plus court avec as. C'est une convention très répandue dans l'écosystème scientifique (par exemple import numpy as np).

Piège fréquent

Évite from module import * (l'étoile). Cette forme importe tous les noms d'un coup et « pollue » ton espace de noms : tu ne sais plus d'où vient chaque fonction, et un nom du module peut écraser silencieusement une de tes variables. Importe ce dont tu as besoin, nommément.

Créer ton propre module

Un module, c'est juste un fichier .py. Si tu écris des fonctions dans un fichier, tu peux les importer depuis un autre fichier du même dossier. Créons un fichier outils.py.

Depuis un autre fichier placé dans le même dossier, on l'importe par son nom (sans le .py).

La garde if __name__ == "__main__"

Quand Python importe un fichier, il exécute tout son contenu de haut en bas. Problème : si outils.py contient des lignes de test ou d'affichage à la racine, elles s'exécuteraient aussi à l'import — ce qu'on ne veut pas. La solution est la garde principale.

Python remplit une variable spéciale __name__ : elle vaut "__main__" si le fichier est lancé directement, et le nom du module s'il est importé. On s'en sert pour ne lancer le code de démonstration que dans le premier cas.

Concrètement : python outils.py affiche le test ; import outils depuis un autre fichier ne l'affiche pas. C'est le réflexe standard pour rendre un fichier à la fois importable et exécutable.

La bibliothèque standard

La bibliothèque standard est l'ensemble des modules livrés avec Python : rien à installer, juste à importer. En voici un tour d'horizon utile.

Le module random gère le hasard : tirer un entier, choisir un élément, mélanger une liste.

Le module datetime manipule dates et heures, avec un formatage soigné via strftime.

Le module json convertit des données Python en texte (sérialisation) et inversement — indispensable pour les fichiers de configuration et les API web.

Pour les fichiers et les chemins, pathlib est l'approche moderne (objets Path), tandis que os et sys donnent accès au système et à l'interpréteur (arguments de ligne de commande, version…).

Note

L'opérateur / entre objets Path ne fait pas une division : il assemble un chemin. pathlib choisit automatiquement le bon séparateur selon ton système (/ sur macOS/Linux, \ sur Windows).

Cas réel

Quand une application web t'envoie des données — la liste de tes commandes, une fiche produit — elles voyagent presque toujours en JSON. Côté serveur, Python fait json.dumps(donnees) pour transformer un dictionnaire en texte ; à l'autre bout, un programme fait json.loads(texte) pour retrouver un objet exploitable. Le même module json, livré en standard, sert ainsi de langue commune entre des machines et des langages différents. C'est exactement le format que renvoient la plupart des API que tu appelleras plus tard.

Paquets tiers et pip

Tout n'est pas dans la bibliothèque standard. Pour le reste — requêtes web (requests), tableaux de données (pandas), etc. — on installe des paquets tiers depuis le dépôt public PyPI, à l'aide de l'outil pip. Ces commandes se tapent dans un terminal, pas dans le code Python.

Une fois installé, un paquet tiers s'importe exactement comme un module standard : import requests. La différence est uniquement à l'installation — d'où l'importance de ne pas les confondre.

Astuce

Pour isoler les paquets d'un projet, on crée un environnement virtuel avec python -m venv .venv. Chaque projet a ainsi ses propres dépendances, sans polluer le Python du système. On détaille tout ça dans la leçon 15.

Trouver la documentation

Personne ne connaît tous les modules par cœur. La documentation officielle, docs.python.org, est la référence : elle décrit chaque module et chaque fonction avec des exemples. Dans le REPL, deux outils dépannent vite : help(math) affiche l'aide d'un objet, et dir(math) liste tout ce qu'il contient.

Pièges fréquents

  • Nommer son fichier comme un module standard. Si tu appelles ton fichier random.py, ton fichier masque le vrai module : import random importera le tien, et random.randint plantera. Choisis un autre nom (et supprime le random.pyc éventuel).
  • Oublier la garde __main__. Sans elle, tout le code de test d'un module s'exécute aussi à l'import, avec des affichages parasites et parfois des erreurs.
  • Confondre standard et tiers. math et json sont déjà là ; requests doit être installé avec pip. Tenter import requests sans l'avoir installé lève un ModuleNotFoundError.
  • Abuser de import *. Pratique en apparence, il rend le code illisible et provoque des collisions de noms silencieuses.

Piège fréquent

Un ModuleNotFoundError: No module named 'requests' ne veut pas dire que ton code est faux : il signifie souvent que le paquet n'est pas installé (ou pas dans le bon environnement virtuel). Vérifie avec pip list.

Pour aller plus loin

La bibliothèque standard regorge de modules qui font gagner un temps fou : collections (structures de données pratiques comme Counter et defaultdict), itertools (combinaisons, produits, itérateurs paresseux) et functools (mise en cache avec lru_cache, fonctions partielles). Côté fichiers, pathlib mérite une exploration approfondie : lecture, écriture, parcours de dossiers.

Pour aller plus loin

Quand un projet grossit, on regroupe plusieurs modules dans un paquet (un dossier de fichiers .py) que l'on peut ensuite distribuer sur PyPI pour que d'autres l'installent avec pip. C'est le sujet du packaging, à découvrir plus tard.

Antisèche : imports et modules

Les formes d'import et quelques modules standard à garder sous la main.

Glossaire

Module
Un simple fichier .py contenant du code (fonctions, variables) réutilisable ailleurs grâce à un import.
Bibliothèque standard
L'ensemble des modules livrés avec Python (math, json, random…) : rien à installer, juste à importer.
Paquet tiers
Module qui ne vient pas avec Python : on le télécharge depuis PyPI avec pip avant de pouvoir l'importer.
pip
L'outil en ligne de commande qui installe les paquets tiers depuis le dépôt public PyPI.
Alias
Nom raccourci donné à un module avec as (ex. import numpy as np) pour l'écrire plus court.
__name__
Variable spéciale valant "__main__" si le fichier est lancé directement, sinon le nom du module.
Garde principale
Le bloc if __name__ == "__main__": qui n'exécute son contenu qu'au lancement direct, pas à l'import.
Environnement virtuel
Dossier isolé (python -m venv .venv) où un projet installe ses propres paquets sans toucher au Python du système.

Récap et vérification

  • import module donne accès via module.nom ; from module import nom importe un nom précis ; import module as alias raccourcit le nom.
  • Un module est un simple fichier .py importable ; la garde if __name__ == "__main__": n'exécute son contenu que si le fichier est lancé directement.
  • La bibliothèque standard (math, random, datetime, json, pathlib, os, sys) est livrée avec Python : rien à installer.
  • Les paquets tiers s'installent avec pip (idéalement dans un venv) puis s'importent comme un module standard.
  • La référence est docs.python.org ; help() et dir() dépannent dans le REPL.

Vérifie ta compréhension

  1. Quelle est la différence entre import math et from math import sqrt au moment d'appeler la fonction ?
  2. Pourquoi appeler un fichier random.py peut-il casser import random ?
  3. Que vaut __name__ quand un fichier est importé, et quand il est lancé directement ?
