Le modèle de données : méthodes spéciales & descripteurs

~36 min Avancé Leçon 01 recommandée

À la fin de cette leçon, tu sauras

  • Savoir implémenter __repr__, __eq__/__hash__ et un ordre cohérent avec @total_ordering
  • Savoir rendre un objet appelable, conteneur et surcharger les opérateurs (y compris les versions réfléchies)
  • Savoir maîtriser __getattr__, __setattr__ et __slots__ sans déclencher de récursion ;
  • Savoir écrire un descripteur réutilisable via __get__/__set__/__set_name__.
Sommaire de la leçon

En Python, ce qui rend un objet « pythonique » n'est pas une question de style : c'est l'implémentation des bons crochets du modèle de données (les méthodes dunder, pour double underscore). Quand tu écris len(obj), obj[k], a + b ou x in coll, l'interpréteur appelle en réalité obj.__len__(), obj.__getitem__(k), etc. Le langage délègue : à toi de fournir le comportement.

Cette leçon parcourt les familles de méthodes spéciales les plus utiles, puis descend d'un cran sous le capot avec les descripteurs, le mécanisme qui alimente @property et les méthodes elles-mêmes.

1. Identité et affichage : __repr__, __str__, __eq__, __hash__

Deux représentations textuelles cohabitent. __repr__ vise l'absence d'ambiguïté pour le développeur (idéalement une expression évaluable), __str__ vise la lisibilité pour l'utilisateur. Si tu n'en définis qu'une, choisis __repr__ : str() retombe dessus par défaut.

Renvoie NotImplemented (pas False) quand le type ne te concerne pas : Python tente alors l'opération réfléchie sur l'autre objet.

Règle de cohérence : deux objets égaux doivent avoir le même __hash__. @functools.total_ordering dérive <=, >, >= à partir de __eq__ + __lt__, ce qui t'évite trois méthodes.

2. Objets appelables et conteneurs

Implémenter __call__ rend une instance utilisable comme une fonction : parfait pour une fonction qui porte un état (un compteur, une configuration, une factory).

Pour un conteneur, le quatuor __len__, __getitem__, __setitem__, __contains__ suffit à offrir une API d'accès indexé ; __iter__ rend l'objet parcourable par for.

Note

Si tu définis __getitem__ indexable par des entiers à partir de 0 mais pas __iter__, Python sait quand même itérer (protocole d'itération « ancienne école »). Mais fournir __iter__ explicitement est plus clair et plus rapide.

3. Surcharge d'opérateurs et versions réfléchies

a + b appelle a.__add__(b). Si ça renvoie NotImplemented (ou si a n'a pas la méthode), Python tente b.__radd__(a) : la version réfléchie. C'est elle qui permet 2 * vecteur alors que int ne sait rien de ta classe.

La multiplication scalaire étant commutative, on alias simplement __rmul__ sur __mul__.

4. Gestion d'attributs : __getattr__, __setattr__, __slots__

__getattribute__ est appelé pour chaque accès d'attribut ; __getattr__ n'est appelé qu'en dernier recours, quand l'attribut est introuvable. Préfère __getattr__ pour les attributs « calculés à la volée » : il est plus sûr et bien moins coûteux.

__slots__ remplace le __dict__ par instance par un stockage fixe : mémoire réduite (utile à grande échelle) et jeu d'attributs figé. Toute tentative d'ajouter un attribut hors liste lève une AttributeError.

Astuce

Sur une @dataclass, passe @dataclass(slots=True) (Python 3.10+) pour générer __slots__ automatiquement : gain mémoire sans écrire le tuple à la main.

5. Les descripteurs : ce qui se cache derrière @property

Un descripteur est un objet dont la classe définit __get__ et/ou __set__. Placé en attribut de classe, il intercepte les accès depuis les instances. C'est exactement le mécanisme de @property, et celui qui transforme une fonction en méthode liée. __set_name__ reçoit automatiquement le nom sous lequel le descripteur est déclaré : indispensable pour stocker chaque valeur sans collision.

Le même objet PositiveInt valide quantity et pages sans dupliquer la logique : c'est l'avantage décisif des descripteurs sur @property, qui se réécrit à chaque attribut.

Cas réel

Les ORM reposent entièrement sur les descripteurs : dans un modèle Django (name = models.CharField(max_length=80)) ou SQLAlchemy (name = Column(String)), chaque champ est un descripteur qui valide, convertit et suit les modifications de l'attribut. De leur côté, NumPy et pandas exploitent la surcharge d'opérateurs (__add__, __mul__, __getitem__) pour que df["prix"] * 1.2 agisse sur une colonne entière. Sans le modèle de données, aucune de ces API expressives ne serait possible.

6. Aperçu : __enter__ / __exit__ (gestionnaires de contexte)

Le protocole de contexte est aussi un jeu de méthodes spéciales : __enter__ (à l'entrée du with) et __exit__ (à la sortie, même en cas d'exception). On l'explore en détail à la leçon 6, mais le squelette tient en quelques lignes.

Pièges fréquents

Piège fréquent

Définir __eq__ sans __hash__. Dès que tu redéfinis __eq__, Python met __hash__ à None : l'objet devient non hachable et ne peut plus servir de clé de dict ni entrer dans un set. Redéfinis explicitement __hash__ (ou utilise une dataclass avec frozen=True).

Piège fréquent

Récursion infinie dans __getattribute__. Si tu surcharges __getattribute__ et y écris self.x, tu rappelles __getattribute__… à l'infini. Passe toujours par super().__getattribute__(name). Même prudence avec __setattr__ : utilise object.__setattr__(self, name, value).

Piège fréquent

Un __repr__ ambigu ou absent. Le défaut (<Obj at 0x...>) ne dit rien lors d'un débogage. Et oublier __set_name__ dans un descripteur partagé entre plusieurs attributs fait écraser leurs valeurs entre elles : chaque champ doit avoir son propre slot de stockage.

Pour aller plus loin

Pour aller plus loin

Hériter de collections.abc.Sequence ou Mapping te donne gratuitement __contains__, index, count, keys… à partir de quelques méthodes seulement. Le module numbers formalise la hiérarchie numérique, functools.total_ordering complète l'ordre, et typing.Protocol (leçon 4) décrit ces protocoles de manière structurelle pour le typage statique.

Glossaire

Méthode spéciale (dunder)
Méthode à double underscore (__len__, __add__…) que l'interpréteur appelle pour une syntaxe donnée.
Modèle de données
L'ensemble des crochets dunder par lesquels Python délègue les opérations usuelles (affichage, comparaison, indexation…) à tes objets.
Protocole
Jeu de méthodes qui, une fois implémentées, rendent un objet compatible avec un comportement (itérable, conteneur, contexte…).
Opération réfléchie
Variante en r (__radd__, __rmul__) essayée sur l'opérande de droite quand celui de gauche renvoie NotImplemented.
Descripteur
Objet, placé en attribut de classe, dont __get__/__set__ interceptent l'accès depuis les instances ; moteur de @property et des méthodes.
__set_name__
Crochet reçu par un descripteur avec le nom sous lequel il est déclaré, pour attribuer à chaque champ son propre slot de stockage.
__slots__
Déclaration remplaçant le __dict__ par instance ; réduit la mémoire et fige la liste des attributs autorisés.
Hachable
Objet doté d'un __hash__ stable et cohérent avec __eq__, condition pour servir de clé de dict ou d'élément de set.

Récap et vérification

  • __repr__ non ambigu > __str__ lisible ; __eq__ et __hash__ doivent rester cohérents.
  • __call__, __len__/__getitem__/__iter__ rendent un objet appelable ou conteneur.
  • Les opérateurs ont une forme réfléchie (__radd__, __rmul__) déclenchée quand l'autre opérande ne sait pas faire.
  • __getattr__ est un dernier recours ; __slots__ réduit la mémoire et fige les attributs.
  • Un descripteur (__get__/__set__/__set_name__) factorise une logique d'accès réutilisable : c'est le moteur de @property.

Vérifie ta compréhension

  1. Pourquoi renvoyer NotImplemented plutôt que False dans __eq__ quand le type ne correspond pas ?
  2. Quel risque concret prends-tu en redéfinissant __eq__ sans toucher à __hash__ ?
  3. À quoi sert __set_name__ dans un descripteur partagé entre deux attributs de la même classe ?
