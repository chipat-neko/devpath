Module 01 · Comprendre Wasm — Leçon 02

Du C/Rust au .wasm

~30 min Intermédiaire Leçon 01 conseillée

À la fin de cette leçon, tu sauras

  • ce qu'est une chaîne d'outils (toolchain) de compilation ;
  • compiler du C/C++ avec Emscripten ;
  • compiler du Rust avec wasm-pack ;
  • identifier ce que produit la compilation (le .wasm et sa « colle »).
Sommaire de la leçon

On ne tape pas du WebAssembly à la main. On écrit dans un langage compilé — le plus souvent C, C++ ou Rust — puis une chaîne d'outils traduit ce code source en un fichier .wasm prêt à charger dans le navigateur. Cette leçon décrit ce passage du code source au binaire.

La chaîne d'outils (toolchain)

Une chaîne d'outils (en anglais toolchain) est l'ensemble des programmes qui transforment ton code source en module Wasm : compilateur, éditeur de liens, optimiseur. Tu n'appelles en général qu'une seule commande ; elle orchestre le reste.

Le langage source doit s'y prêter

Tous les langages ne ciblent pas (encore) Wasm aussi bien. C, C++ et Rust ont un support mûr et sont les choix les plus courants. D'autres (Go, AssemblyScript, etc.) le visent aussi, avec des compromis variables.

Compiler du Rust avec wasm-pack

Côté Rust, l'outil wasm-pack (avec la bibliothèque wasm-bindgen) rend l'expérience très fluide : il compile, génère la colle JavaScript et même un petit paquet prêt à l'emploi.

wasm-bindgen fait le pont

L'annotation #[wasm_bindgen] indique « cette fonction doit être appelable depuis JavaScript ». L'outil s'occupe de traduire les types entre les deux mondes — un confort que le C brut n'offre pas d'office.

Ce que produit la compilation

Quel que soit le langage, on obtient au moins :

  • un fichier .wasm — le binaire, le cœur du calcul ;
  • souvent une colle JavaScript — du code qui charge le module et expose ses fonctions proprement ;
  • parfois des déclarations de types (pour l'autocomplétion) et un fichier de description.

Le .wasm existe en deux représentations équivalentes : le binaire (ce qui s'exécute) et un format texte lisible appelé WAT (WebAssembly Text), utile pour inspecter ou apprendre.

Optimiser la taille

Un module envoyé sur le réseau doit rester léger. Les chaînes d'outils proposent des options d'optimisation (par exemple -O2/-O3 avec Emscripten, le profil --release avec Rust), et des outils comme wasm-opt réduisent encore la taille du binaire. On optimise après avoir vérifié que tout fonctionne.

N'oublie pas le coût de chargement

Un module Wasm doit être téléchargé avant de tourner. Pour un calcul minime, ce coût peut annuler le gain. Mesure la taille et le temps de chargement, surtout sur mobile.

Cas réel — FFmpeg compilé en Wasm

FFmpeg, la boîte à outils audio/vidéo écrite en C, a été compilée en WebAssembly (projet ffmpeg.wasm). Des sites peuvent ainsi convertir ou découper une vidéo directement dans le navigateur, sans téléverser le fichier sur un serveur — un vrai gain pour la confidentialité et les coûts d'hébergement. Le module pèse plusieurs mégaoctets : on le charge une fois, puis il traite des fichiers entiers, ce qui amortit largement le téléchargement initial. C'est l'exemple type où le calcul lourd justifie Wasm.

Le rôle de la « colle » JavaScript

La colle générée n'est pas du superflu : elle gère le chargement du binaire, l'initialisation de la mémoire, et expose les fonctions Wasm sous une forme agréable à appeler en JavaScript. On peut charger un .wasm « à la main » sans elle (on le fera en leçon 3 pour comprendre), mais en pratique la colle simplifie beaucoup les cas réels.

Glossaire

Chaîne d'outils (toolchain)
Ensemble des programmes (compilateur, éditeur de liens, optimiseur) qui transforment le code source en module Wasm.
Emscripten (emcc)
Chaîne d'outils de référence pour compiler du C/C++ vers le web ; s'appuie sur LLVM.
wasm-pack
Outil qui compile du Rust vers Wasm et génère la colle JavaScript et un paquet prêt à l'emploi.
wasm-bindgen
Bibliothèque Rust qui fait le « pont » entre Rust et JavaScript en traduisant les types entre les deux mondes.
Colle JavaScript
Code JS généré qui charge le .wasm, initialise la mémoire et expose ses fonctions proprement.
WAT (WebAssembly Text)
Représentation texte, lisible par un humain, équivalente au binaire .wasm.
wasm-opt
Outil qui réduit la taille et améliore les performances d'un binaire .wasm après compilation.

Récap et vérification

  • On écrit en C/C++/Rust, une chaîne d'outils produit le .wasm.
  • Emscripten (emcc) pour C/C++ ; wasm-pack + wasm-bindgen pour Rust.
  • La compilation donne le binaire .wasm et souvent une colle JS.
  • WAT est la forme texte lisible ; on optimise la taille à la fin.

Exercices

Exercice 1Échauffement

Associe chaque langage source à son outil de compilation vers Wasm le plus courant : (a) C/C++ ; (b) Rust.

Voir une solution

(a) C/C++ → Emscripten (commande emcc). (b) Rust → wasm-pack (avec wasm-bindgen pour le pont vers JavaScript). Les deux produisent un .wasm et, le plus souvent, une colle JavaScript.

Exercice 2Application

Pourquoi la compilation génère-t-elle souvent un fichier JavaScript « de colle » en plus du .wasm ? À quoi sert-il ?

Voir une solution

Le .wasm ne se charge pas tout seul : il faut le télécharger, l'instancier, initialiser sa mémoire et exposer ses fonctions sous une forme pratique. La colle JavaScript automatise tout cela : elle offre une fonction d'initialisation et des fonctions prêtes à appeler, en gérant aussi la traduction des types (chaînes, tableaux) entre JS et Wasm. On peut s'en passer pour un cas minimal et tout faire « à la main » (utile pour comprendre), mais pour un vrai projet elle évite beaucoup de code répétitif et d'erreurs.

Exercice 3Défi

Un module .wasm de calcul fait 800 Ko une fois compilé, pour accélérer une opération qui prend 5 ms en JavaScript. Quels éléments examinerais-tu avant de l'adopter ?

Voir une solution

Le calcul est déjà rapide (5 ms) — le gain potentiel est faible. En face, on paie un téléchargement de 800 Ko (lent sur mobile/réseau faible), un temps d'instanciation, et le coût d'échange JS ⇄ Wasm à chaque appel. À examiner : la taille après optimisation (-O3/--release + wasm-opt), la fréquence des appels (un module chargé une fois pour des milliers d'appels s'amortit ; un appel unique non), et surtout une mesure réelle bout en bout (chargement compris). Conclusion probable : pour 5 ms, Wasm n'en vaut pas la peine ici ; on le réserve aux calculs vraiment lourds et répétés.
