WebAssembly

JavaScript est formidable, mais pas taillé pour le calcul intensif (traitement d'image, jeux, cryptographie). WebAssembly (Wasm) comble ce vide : un format binaire portable et rapide, vers lequel on compile du C, du Rust ou d'autres langages, et qui s'exécute dans le navigateur à une vitesse proche du natif. Ce cours t'explique ce qu'est Wasm, comment on l'obtient, et comment le faire collaborer avec JavaScript.

Prérequis

Connaître JavaScript (Wasm s'utilise depuis lui) et avoir vu un langage compilé comme C/C++ ou Rust aide beaucoup. Le cours est conceptuel ; pour pratiquer, il faut servir les fichiers via un petit serveur local (pas en file://).

Ce que tu vas apprendre

Objectifs du cours

À la fin du cours, tu sauras

  • expliquer ce qu'est WebAssembly et ce qu'il apporte ;
  • compiler du C ou du Rust vers .wasm ;
  • charger et exécuter un module dans le navigateur ;
  • faire dialoguer JS et Wasm (fonctions, mémoire) ;
  • reconnaître les bons cas d'usage et les limites ;
  • assembler un petit module Wasm appelé depuis JS.

Pour qui, et pourquoi

Ce cours est pour toi si tu rencontres les limites de performance de JavaScript pour des tâches lourdes, ou si tu veux réutiliser du code C/C++/Rust existant dans le navigateur. Wasm n'est pas un remplaçant de JavaScript : c'est un complément, pour les portions de calcul intensif.

Le fil conducteur est l'idée de complémentarité : JavaScript orchestre et touche au DOM ; WebAssembly fait le gros calcul. Les deux communiquent, chacun à ce qu'il fait de mieux.

Astuce

N'adopte pas Wasm « pour aller plus vite » par réflexe : pour la plupart des sites, JavaScript suffit largement. Wasm vaut le coup quand le calcul est le vrai goulot d'étranglement, mesuré.

Récapitulatif

À retenir & glossaire

Les points clés du cours, puis les termes essentiels à connaître.

À retenir

  • WebAssembly est un format binaire portable, rapide, exécuté par le navigateur.
  • On l'obtient en compilant du C, du Rust, etc. vers .wasm.
  • Il complète JavaScript : le calcul lourd à Wasm, le DOM et l'orchestration à JS.
  • JS et Wasm communiquent par des fonctions et une mémoire partagée.
  • Il tourne dans un bac à sable sûr ; il vaut pour le calcul, pas pour tout.
WebAssembly (Wasm)
Un format d'instructions binaire, portable et rapide, exécutable dans le navigateur (et ailleurs).
Module
Une unité de code Wasm compilée (un fichier .wasm) qu'on charge et instancie.
Bytecode
Le format binaire compact des instructions Wasm (pas du code machine spécifique à un processeur).
Compilation
Transformer un code source (C, Rust…) en module .wasm via une chaîne d'outils.
Mémoire linéaire
Un grand tableau d'octets que le module Wasm utilise, partageable avec JavaScript.
Interopérabilité
La capacité de JS et Wasm à s'appeler mutuellement et à échanger des données.
Bac à sable (sandbox)
L'isolation qui empêche un module Wasm d'accéder au système sans permission.
Near-native
« Presque natif » : une vitesse d'exécution proche de celle d'un programme compilé classique.
Toolchain
La chaîne d'outils qui compile vers Wasm (par ex. Emscripten pour C/C++, wasm-pack pour Rust).
WASI
Une interface standard pour exécuter du Wasm hors du navigateur (système).
