Module 3 · Aller plus loin — Leçon 07

Conditions, boucles et bonnes pratiques

~30 min Intermédiaire Leçons 02 à 06 conseillées

À la fin de cette leçon, tu sauras

  • écrire des conditions (@if/@else) ;
  • générer du CSS avec @for, @each, @while ;
  • partager du style avec les placeholders et @extend ;
  • structurer un projet selon de bonnes pratiques.
Sommaire de la leçon

Dernière étape : faire écrire du CSS par Sass. Les directives de contrôle (conditions et boucles) génèrent des règles de façon programmatique — par exemple toute une échelle d'espacements ou une famille de classes de couleur à partir d'une seule map. On termine avec @extend, puis un tour des bonnes pratiques pour garder un projet Sass sain.

Conditions : @if / @else

Comme dans un langage de programmation, @if exécute un bloc selon une condition ; @else if et @else couvrent les autres cas. C'est surtout utile dans les mixins et les fonctions :

@if décide à la compilation, @media à l'exécution

Ne confonds pas @if avec la logique du CSS. @if est évalué une fois, à la compilation : selon la valeur d'une variable Sass, un bloc est écrit dans le .css ou non — après quoi il a disparu. Une règle comme @media (min-width: 600px), elle, reste dans le CSS et se réévalue en continu dans le navigateur, au fil des redimensionnements. @if choisit ce qu'on génère ; @media choisit ce qui s'applique chez le visiteur.

La boucle @each

@each parcourt une liste ou une map. C'est la boucle la plus utile : elle génère une famille de classes à partir d'un thème centralisé.

Ajouter une couleur au thème, c'est ajouter une ligne à la map : toutes les classes correspondantes apparaissent toutes seules. C'est le cœur des bibliothèques d'utilitaires.

Une boucle peut faire exploser la taille du CSS

Chaque tour de boucle écrit de vraies règles dans le fichier final : le compte se multiplie vite. Une boucle imbriquée qui croise 50 couleurs avec 3 propriétés (color, background, border-color) produit déjà 150 règles ; ajoute les états (:hover, :focus) et tu dépasses le millier — dont l'immense majorité ne servira jamais. Ne génère que les combinaisons réellement utilisées, et surveille le poids du .css produit : le confort à l'écriture ne doit pas se payer en kilo-octets chez le visiteur.

Placeholders et @extend

Un placeholder est un sélecteur qui commence par %. Il n'apparaît jamais seul dans le CSS : il n'existe que pour être étendu par @extend. Plusieurs sélecteurs qui l'étendent sont alors regroupés, sans duplication :

Contrairement à un mixin (qui recopie les déclarations dans chaque appelant), @extend fusionne les sélecteurs : le CSS produit est plus compact. Mais @extend n'accepte pas de paramètres et peut produire des regroupements de sélecteurs surprenants : réserve-le à un socle commun figé ; pour tout ce qui varie, préfère un mixin.

Cas réel — la grille et les utilitaires de Bootstrap

Les frameworks CSS comme Bootstrap reposent massivement sur ces directives. Leur grille de 12 colonnes (.col-1 … .col-12) et leurs classes d'espacement (.m-0 … .m-5) ne sont pas écrites à la main : une boucle @for les génère depuis une seule variable de configuration. Changer le nombre de colonnes ou l'échelle d'espacement, c'est éditer une variable ; toutes les classes se régénèrent. C'est exactement le mécanisme map/@each/@for de cette leçon, à l'échelle d'une bibliothèque utilisée par des millions de sites.

Bonnes pratiques

Pour finir, quelques principes qui font la différence sur la durée :

  • Découpe en partials et assemble avec @use/@forward (jamais @import). Une organisation type « 7-1 » sépare fondations (variables, mixins, fonctions) et composants.
  • Centralise le thème dans des variables et des maps : couleurs, espacements, points de rupture. La map + @each évite la répétition.
  • Mixin pour ce qui varie, placeholder pour le socle figé, fonction pour calculer une valeur.
  • N'imbrique pas trop (2-3 niveaux), pour ne pas gonfler la spécificité (leçon 03).
  • Combine avec les variables CSS quand une valeur doit changer à l'exécution (thème clair/sombre piloté côté navigateur) : Sass au build, propriétés personnalisées au runtime.

Garde la sortie en tête

Tout le pouvoir de Sass s'évapore à la compilation : le navigateur ne reçoit que du CSS. Prends l'habitude de regarder le .css produit (surtout avec @each et @extend) : c'est le meilleur moyen de vérifier qu'une boucle ou une extension génère bien ce que tu crois, et de ne pas alourdir la feuille de style sans le voir.

Glossaire

Directive de contrôle
Instruction Sass qui pilote la génération du CSS : conditions (@if) et boucles (@each, @for, @while).
@if / @else
Condition évaluée à la compilation : Sass écrit le premier bloc dont le test est vrai (@else if pour les cas suivants, @else par défaut) et ignore les autres.
Map
Structure Sass associant des clés à des valeurs, ex. ("primaire": #2563c8, …) ; source privilégiée d'un @each pour générer une famille de classes.
@each
Boucle qui parcourt une liste ou les paires clé/valeur d'une map ; l'outil idéal pour générer une famille de classes depuis un thème centralisé.
@for
Boucle sur un intervalle de nombres ; through inclut la borne finale, to l'exclut.
Placeholder
Sélecteur commençant par % qui n'apparaît jamais seul dans le CSS : il n'existe que pour être repris par @extend.
@extend
Fait hériter un sélecteur des styles d'un autre en fusionnant les sélecteurs (CSS compact, mais sans paramètre).
Interpolation
#{ } insère la valeur d'une expression dans un nom de classe, un sélecteur ou une valeur.
Pattern 7-1
Organisation des partials en dossiers thématiques (abstracts, base, components…) reliés par un fichier principal.

Récap et vérification

  • @if/@else if/@else conditionnent du CSS, surtout dans les mixins et fonctions.
  • @each (liste/map), @for (intervalle, through/to) et @while génèrent des règles ; map + @each = familles de classes.
  • Un placeholder %x + @extend fusionne des sélecteurs partageant un socle, sans duplication (mais sans paramètre).
  • Bonnes pratiques : partials + @use, thème centralisé, mixin/placeholder/fonction selon le besoin, imbrication modérée, et complément des variables CSS.

Exercices

Exercice 1Échauffement

Avec une boucle @for, génère les classes .p-1 à .p-5 où chaque niveau ajoute 0.25rem de padding (.p-1 = 0.25rem, .p-5 = 1.25rem).

Voir une solution

through inclut la borne 5. L'interpolation construit le nom .p-#{$i} et la valeur #{$i * 0.25}rem. On obtient une échelle d'espacements cohérente sans l'écrire à la main.

Exercice 2Application

Tu as un socle commun de boutons (padding, rayon, bordure invisible, curseur). Comment le partager entre .btn-primaire et .btn-secondaire sans dupliquer le CSS produit ?

Voir une solution

Le placeholder %btn-base n'est pas généré seul ; @extend regroupe les deux boutons sur la règle commune (.btn-primaire, .btn-secondaire { ... }), et chacun ajoute ses couleurs. Comme le socle ne varie pas, @extend est ici plus économe qu'un mixin recopié.

Exercice 3Défi

Assemble ce que tu as appris : à partir d'une map de couleurs de thème, génère pour chacune une classe de bouton (fond = la couleur, survol 10 % plus sombre, texte blanc), en réutilisant un mixin. Explique pourquoi tu choisis @each + mixin ici.

Voir une solution

On choisit @each parce qu'on veut une classe par entrée d'une source centralisée (la map du thème) : ajouter une couleur ne demande qu'une ligne. Et on choisit un mixin (plutôt qu'un placeholder) parce que chaque bouton varie selon la couleur passée en argument, et qu'on calcule le survol à partir d'elle. C'est la combinaison gagnante : map + @each pour la répétition pilotée par les données, mixin paramétré pour la part variable. Tout le système de boutons tient en une dizaine de lignes et se régénère depuis une seule map.
