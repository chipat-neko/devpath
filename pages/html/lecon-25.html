Module 08 · Pour aller plus loin — Leçon 25

Performance de chargement : livrer une page rapide

~36 min Avancé Leçon 16 recommandée

À la fin de cette leçon, tu sauras

  • expliquer le chemin critique qui retarde le premier affichage ;
  • charger le JavaScript sans bloquer la page avec defer et async ;
  • différer les images hors écran avec loading="lazy" ;
  • anticiper les ressources clés avec preconnect, preload et prefetch ;
  • assembler un cours entier dans un mini-projet.
Sommaire de la leçon

Une page correcte mais lente perd ses visiteurs : on sait qu'un chargement qui traîne fait fuir les internautes et pèse sur le référencement. La bonne nouvelle : une grande partie de la vitesse se joue dans le HTML, avec quelques attributs bien placés. Pas besoin de JavaScript compliqué : defer, loading, <link rel="preload"> font l'essentiel.

Le chemin critique du rendu

Avant d'afficher quoi que ce soit, le navigateur doit récupérer le HTML, puis les ressources dont il dépend pour peindre l'écran : la feuille de style, souvent le JavaScript. Tant qu'une ressource bloquante n'est pas arrivée, l'écran reste blanc. C'est le chemin critique : plus il est court, plus la page s'affiche vite.

Le pire ennemi : un <script> ordinaire placé dans le <head>. Le navigateur arrête de lire le HTML, télécharge le script, l'exécute, puis reprend. Pendant ce temps, rien ne s'affiche.

Charger le JavaScript sans bloquer : defer et async

Deux attributs libèrent le chemin critique :

  • defer — le script se télécharge en parallèle de l'analyse HTML et s'exécute après, dans l'ordre d'apparition. Idéal pour le script principal, qui manipule la page une fois construite.
  • async — téléchargement en parallèle aussi, mais exécution dès que prêt, sans ordre garanti. Réservé aux scripts indépendants (statistiques, widget isolé).

Bonne pratique

Toutes les leçons de ce site chargent leur JavaScript avec defer (regarde la fin du code source !). Dans le doute, choisis defer : l'ordre est préservé et la page reste réactive pendant le téléchargement.

Charger les images au bon moment : loading="lazy"

Une page peut contenir vingt images, mais l'internaute n'en voit que deux ou trois au départ. Charger les dix-huit autres tout de suite gaspille de la bande passante et retarde l'affichage. L'attribut loading="lazy" dit au navigateur : « charge cette image seulement quand elle approche de l'écran ».

Erreur fréquente

Ne mets pas loading="lazy" sur la grande image du haut (la plus visible) : la différer retarderait justement l'élément le plus important. Le lazy, c'est pour ce qui est sous la ligne de flottaison. Et garde toujours width/height pour réserver la place et éviter les sauts de mise en page.

Anticiper : preconnect, preload, prefetch

Le <link> sert aussi à donner des indices au navigateur sur ce qui va être utile. Ces « indices de ressources » vont du plus léger au plus engageant :

Beaucoup de sites déclarent un preconnect vers fonts.gstatic.com pour que les polices Google arrivent plus vite. Ce site a choisi l'autre voie : ses polices sont servies depuis son propre dossier, donc il n'a aucune connexion tierce à ouvrir.

Cas réel

Un site e-commerce affiche une grande image de héros et charge sa police depuis un serveur externe. Au départ, le titre clignote (texte invisible le temps que la police arrive) et l'image met une seconde à apparaître. Deux lignes suffisent : un <link rel="preconnect"> vers le serveur de polices et un fetchpriority="high" sur l'image de héros. Résultat : le plus gros élément visible s'affiche nettement plus tôt, sans changer une seule image ni ligne de JavaScript.

Régler la priorité : fetchpriority

À ressources égales, le navigateur devine l'ordre d'importance ; on peut le corriger avec fetchpriority. high pour l'image principale, low pour ce qui peut attendre.

Pour aller plus loin

Mesure avant d'optimiser : les outils Lighthouse (dans les outils de développement du navigateur) et PageSpeed Insights notent la vitesse et pointent les ressources qui bloquent. Vise les Core Web Vitals : le LCP (rapidité d'affichage du plus gros élément), le CLS (stabilité visuelle, d'où width/height) et l'INP (réactivité). Côté serveur, la compression (gzip/Brotli) et le cache HTTP complètent le travail fait dans le HTML.

Antisèche

Glossaire

Chemin critique
Suite des ressources indispensables au premier affichage ; le raccourcir accélère l'apparition de la page.
Ressource bloquante
Fichier (CSS, script sans defer) qui empêche le rendu tant qu'il n'est pas chargé.
defer
Attribut de <script> : téléchargement en parallèle, exécution après l'analyse HTML, dans l'ordre.
async
Attribut de <script> : exécution dès que le script est prêt, sans ordre garanti.
Lazy loading
Chargement différé (loading="lazy") d'une image jusqu'à ce qu'elle approche de l'écran.
preconnect
Indice de ressource ouvrant à l'avance la connexion vers un serveur tiers (polices, API).
preload
Indice demandant de télécharger immédiatement une ressource critique découverte tard.
Core Web Vitals
Trio d'indicateurs de vitesse et de stabilité (LCP, CLS, INP) suivis par les moteurs de recherche.

Récap et vérification

  • Le chemin critique retarde l'affichage ; les ressources bloquantes l'allongent.
  • defer (ordre garanti) et async (indépendant) évitent de bloquer sur le JavaScript.
  • loading="lazy" diffère les images hors écran ; jamais sur l'image du haut.
  • preconnect, preload, prefetch et fetchpriority préparent et priorisent les ressources.
  • On mesure (Lighthouse, Core Web Vitals) avant d'optimiser.

Mini-projet fil rouge — une page de profil

Pour clore ce cours, construisons une page web complète et bien structurée : une page de profil (mini-CV). Elle réunit le squelette du document, les repères sémantiques (header, nav, main, footer), la hiérarchie des titres, une liste, un tableau et un formulaire accessible — l'essentiel du cours en une seule page.

Ce que tu vas construire

Une page HTML5 valide et autonome présentant un profil : en-tête avec navigation interne, sections de contenu (parcours en tableau, compétences en liste), formulaire de contact et pied de page.

Étapes

Le squelette du document

Pose le <!DOCTYPE html>, la balise <html lang="fr">, un <head> avec charset, viewport et <title>, puis le <body>.

En-tête et navigation

Dans un <header>, place le <h1> et une <nav> contenant une liste de liens d'ancrage (href="#parcours"…).

Contenu principal sémantique

Regroupe le contenu dans un <main> découpé en <section> titrées, en respectant la hiérarchie <h1> puis <h2>.

Liste et tableau

Présente les compétences en <ul> et le parcours en <table> avec <caption>, <thead> et <tbody>.

Formulaire accessible et pied de page

Ajoute un <form> où chaque champ a son <label for="..."> (avec <input type="email" required>), puis un <footer>.

ProjetFil rouge

Assemble les cinq étapes en une page complète. Essaie d'abord par toi-même, puis compare avec la solution de référence.
