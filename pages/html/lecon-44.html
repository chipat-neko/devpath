Dessiner avec l'élément canvas

~36 min Avancé Bases de JavaScript utiles

À la fin de cette leçon, tu sauras

  • comprendre ce qu'est <canvas> — une toile bitmap pilotée par script — et sa différence avec SVG ;
  • obtenir le contexte 2D et dessiner formes, chemins, texte et images ;
  • rendre net sur écran Retina grâce à devicePixelRatio ;
  • animer avec requestAnimationFrame, réagir au clic et exporter le dessin en image.
Sommaire de la leçon

Jusqu'ici, tu as dessiné avec des éléments : des <div>, du CSS, du SVG. Le navigateur mémorise chacun et le redessine tout seul. L'élément <canvas> propose l'inverse : une zone de pixels vierge sur laquelle ton JavaScript peint directement. Pas d'objets, pas de mémoire : tu ordonnes « trace un rectangle ici, un cercle là », et il ne reste que des pixels.

C'est la technologie derrière les graphiques de Chart.js, les jeux 2D dans le navigateur, les éditeurs d'image, les zones de signature manuscrite. On va partir de la toile vierge, apprendre à peindre formes et texte, régler le piège du flou sur écran haute densité, puis animer et exporter.

Canvas : une toile de pixels, pas des objets

Le balisage est minimal : <canvas width="300" height="150">. Les attributs width et height définissent le nombre de pixels de la toile (pas sa taille CSS : on y reviendra). Rien n'apparaît tant que du JavaScript ne dessine pas. Là est la différence fondamentale avec SVG : SVG conserve un arbre d'objets que tu peux réinterroger et animer ; canvas, lui, est un mode immédiat et sans mémoire — une fois le pixel posé, il ne « sait » plus qu'il représentait un cercle.

Le contexte 2D et le système de coordonnées

Pour peindre, on récupère un contexte de rendu avec canvas.getContext('2d'). Cet objet porte toutes les méthodes de dessin. Le repère a son origine (0, 0) en haut à gauche ; l'axe x va vers la droite, l'axe y vers le bas (attention, le y descend, contrairement aux maths).

Les formes de base

Trois méthodes gèrent les rectangles directement, sans passer par un chemin : fillRect (rempli), strokeRect (contour) et clearRect (efface une zone, la rend transparente). Les couleurs se règlent avant de dessiner, via fillStyle et strokeStyle ; l'épaisseur du trait via lineWidth.

Les chemins : au-delà des rectangles

Pour toute autre forme, on trace un chemin. On ouvre avec beginPath(), on déplace le « crayon » avec moveTo(x, y), on trace des segments avec lineTo(x, y), des arcs avec arc(cx, cy, rayon, début, fin) (angles en radians), puis on referme avec closePath(). Enfin, fill() remplit ou stroke() dessine le contour.

Piège fréquent

Oublier beginPath() avant une nouvelle forme est l'erreur classique : sans elle, le nouveau tracé s'ajoute au précédent, et un stroke() repasse sur tout le chemin accumulé — d'où des lignes fantômes et des couleurs qui débordent. Une forme = un beginPath().

Texte et images

Le contexte sait aussi écrire du texte (fillText, réglé par font et textAlign) et recopier une image, une vidéo ou même un autre canvas avec drawImage.

Le piège du flou : devicePixelRatio

Sur un écran Retina, un pixel CSS couvre 2 (ou 3) pixels physiques. Si ta toile fait 300×150 pixels de buffer mais s'affiche en 300×150 CSS, le navigateur l'agrandit et ton dessin devient flou. La parade : dimensionner le buffer en multipliant par window.devicePixelRatio, garder la taille CSS d'origine, puis scale() le contexte.

Animer avec requestAnimationFrame

Une animation, c'est une boucle : effacer la toile, dessiner la scène un cran plus loin, redemander une image. On n'utilise pas setInterval mais requestAnimationFrame(callback) : le navigateur synchronise l'appel avec le rafraîchissement de l'écran (≈ 60 fois par seconde) et met en pause quand l'onglet est caché — plus fluide et plus économe.

Réagir au clic et exporter

Le canvas ne connaît pas les formes : pour savoir où l'utilisateur a cliqué, on convertit les coordonnées de la souris avec getBoundingClientRect(). Et pour récupérer le dessin, toDataURL() renvoie une URL d'image (base64) et toBlob() un fichier binaire — pratique pour télécharger ou envoyer au serveur.

Cas réel

Chart.js et beaucoup de bibliothèques de graphiques dessinent leurs courbes et barres sur un canvas : des milliers de points se redessinent sans saturer le DOM. Les zones de signature des livreurs et des banques (« signez ici avec le doigt ») capturent le tracé via les événements pointeur puis l'exportent avec toDataURL(). Les jeux 2D du navigateur reposent dessus, tout comme les éditeurs à la Excalidraw (canvas pour le rendu, plus une couche logique pour l'interaction). Quand le nombre d'objets explose ou change 60 fois par seconde, le canvas bat le DOM.

Astuce

Le canvas est un dessin opaque pour les technologies d'assistance : un lecteur d'écran ne « voit » rien. Fournis toujours un contenu de repli entre les balises (<canvas>Graphique des ventes 2026</canvas>) ou une description via aria-label, et propose une alternative textuelle (un tableau de données) quand le canvas porte de l'information.

Pour aller plus loin

Le contexte '2d' a un grand frère : 'webgl' / 'webgl2', qui exploite le GPU pour la 3D et les effets massifs (c'est ce qu'utilise Figma pour son rendu). Regarde aussi OffscreenCanvas (dessiner dans un Web Worker sans bloquer la page), les dégradés (createLinearGradient), les transformations (translate, rotate, save/restore) et l'API Path2D qui mémorise un chemin réutilisable.

Glossaire

canvas
Élément HTML offrant une zone de pixels vierge sur laquelle on dessine par script. Mode immédiat : aucun objet n'est conservé après le tracé.
contexte de rendu
Objet renvoyé par getContext('2d') (ou 'webgl') qui porte toutes les méthodes de dessin et l'état courant (couleur, épaisseur…).
chemin (path)
Suite de segments et d'arcs entre beginPath() et fill()/stroke(). Toute forme non rectangulaire passe par un chemin.
devicePixelRatio
Rapport entre pixels physiques et pixels CSS d'un écran (2 ou 3 sur Retina). On multiplie le buffer par cette valeur pour un rendu net.
requestAnimationFrame
Fonction qui programme un appel juste avant le prochain rafraîchissement de l'écran : base de toute animation fluide, mise en pause quand l'onglet est caché.
toDataURL()
Méthode du canvas qui sérialise le dessin en URL d'image encodée (base64), pour le télécharger, l'afficher ou l'envoyer au serveur.
mode immédiat
Modèle de dessin où l'on émet des ordres qui modifient directement les pixels, sans arbre d'objets réinterrogeable (l'opposé du mode « retenu » de SVG/DOM).

Récap et vérification

  • <canvas> est une toile bitmap : on obtient un contexte avec getContext('2d') et on peint dessus. Sans mémoire d'objets, contrairement à SVG.
  • Repère : origine en haut à gauche, y vers le bas. fillRect/strokeRect pour les rectangles, un chemin (beginPath → arc/lineTo → fill/stroke) pour le reste.
  • Sur Retina, dimensionne le buffer avec devicePixelRatio puis scale() pour rester net.
  • Anime avec la boucle requestAnimationFrame : effacer → dessiner → redemander. Convertis les clics avec getBoundingClientRect().
  • Exporte avec toDataURL() ou toBlob() ; pense au repli textuel pour l'accessibilité.
