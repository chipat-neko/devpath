Module 10 · Web Components — Leçon 30

Les custom elements

~34 min Avancé Leçon 04 recommandée

À la fin de cette leçon, tu sauras

  • savoir définir un custom element avec customElements.define et un nom valide ;
  • savoir orchestrer le cycle de vie (connectedCallback, disconnectedCallback, attributeChangedCallback) ;
  • savoir observer et synchroniser attributs et propriétés ;
  • savoir distinguer un custom element autonome d'un custom element customisé.
Sommaire de la leçon

Tu connais les balises natives : <article>, <dialog>, <input>. La plateforme web te laisse aussi définir les tiennes, avec leur propre comportement encapsulé dans une classe JavaScript. C'est la brique de base des Web Components : une balise réutilisable, autonome, qui réagit à son insertion dans le DOM et à ses attributs, sans framework.

Dans cette leçon, tu apprends à enregistrer un custom element, à maîtriser son cycle de vie, à synchroniser attributs et propriétés, et à choisir entre élément autonome et élément customisé. Le Shadow DOM (l'isolation du style et du markup interne) fait l'objet de la leçon suivante : ici, on reste sur le DOM « clair ».

Définir une nouvelle balise

On enregistre un custom element avec customElements.define(nom, classe). La classe étend HTMLElement, et le nom devient utilisable comme n'importe quelle balise.

Une fois ce code exécuté, <mon-compteur></mon-compteur> dans le HTML est « upgradé » : le navigateur instancie la classe et appelle ses callbacks.

Piège fréquent

Le nom doit contenir un tiret (mon-compteur, pas moncompteur). C'est la règle qui distingue tes éléments des futures balises natives. customElements.define("compteur", ...) lève une DOMException « not a valid custom element name ».

Le cycle de vie

Chaque instance traverse une série de réactions. Tu redéfinis les méthodes qui t'intéressent :

  • constructor() : initialisation de l'objet. Pas d'accès au DOM enfant ni aux attributs ici — l'élément peut ne pas encore être parsé. Réserve-le à super() et aux états internes.
  • connectedCallback() : l'élément vient d'être inséré dans le document. C'est ici qu'on rend (on écrit le contenu, on attache les écouteurs).
  • disconnectedCallback() : l'élément est retiré du DOM. On nettoie (timers, écouteurs globaux, observers).
  • attributeChangedCallback(nom, ancien, nouveau) : un attribut observé change. Il faut le déclarer via static get observedAttributes().

Note

attributeChangedCallback est aussi appelé au démarrage pour chaque attribut observé déjà présent dans le HTML : tu reçois la valeur initiale « gratuitement », pendant l'upgrade, avant même connectedCallback.

Attributs et propriétés

Un attribut est une chaîne dans le markup (getAttribute/setAttribute). Une propriété est un membre JavaScript de l'objet. La convention native (pense à input.value vs value="...") est d'exposer une propriété qui reflète l'attribut, pour que l'API soit agréable des deux côtés.

Écrire el.valeur = 5 en JS met à jour l'attribut, ce qui déclenche attributeChangedCallback, donc le rendu. Une seule source de vérité : l'attribut.

Autonome vs customisé

Il existe deux familles de custom elements :

  • Autonome : extends HTMLElement, utilisé comme une nouvelle balise <compteur-clic>. C'est le cas le plus courant et le mieux supporté.
  • Customisé (built-in) : extends HTMLButtonElement (ou autre élément natif), utilisé via l'attribut is sur la balise native : <button is="mon-bouton">. Tu hérites du comportement natif (clavier, sémantique, focus du <button>) en l'enrichissant.

Note

Les éléments customisés (is="...") ne sont pas supportés par Safari, qui a refusé de les implémenter. En pratique, on privilégie les éléments autonomes et on recrée la sémantique manquante via les rôles ARIA ou un Shadow DOM contenant un vrai <button>.

Cas réel

GitHub tient son interface avec des custom elements autonomes. Le site publie en open source des balises comme <relative-time> (qui affiche « il y a 3 heures » et se réactualise seule), <clipboard-copy> (le bouton « copier ») ou <details-menu>. Toutes enrichissent progressivement du HTML déjà présent : si le JavaScript ne charge pas, <relative-time> affiche quand même la date brute qu'il contient. Ce choix — des éléments autonomes, réutilisables entre pages et indépendants de tout framework — illustre pourquoi l'API standard survit aux modes : le composant est une balise, pas une dépendance.

Pièges fréquents

  • Nom sans tiret : customElements.define("compteur", ...) est refusé. Toujours un tiret, en minuscules.
  • Manipuler les enfants ou les attributs dans le constructor : la spécification l'interdit (ajouter des enfants ou poser un attribut y lève une erreur), et l'élément peut ne pas être encore parsé. Déplace tout rendu dans connectedCallback.
  • Oublier observedAttributes : sans cette liste statique, attributeChangedCallback n'est jamais appelé, même si l'attribut change.
  • Ne pas nettoyer dans disconnectedCallback : un setInterval ou un écouteur sur window survit au retrait de l'élément → fuite mémoire.

Piège fréquent

connectedCallback peut être appelé plusieurs fois (déplacement, ré-insertion). Si tu y crées des enfants sans vérifier, tu les dupliques. Garde un drapeau ou vérifie this.childElementCount avant de construire.

Pour aller plus loin

Pour aller plus loin

Le Shadow DOM (leçon suivante) encapsule markup et styles pour que ton élément ne fuie pas sur la page. Les form-associated custom elements (static formAssociated = true + ElementInternals) participent aux formulaires comme un <input>. Côté SSR, l'hydratation et les Declarative Shadow DOM rendent ces composants côté serveur. Enfin, des bibliothèques comme Lit ajoutent le rendu réactif et les templates par-dessus cette API standard.

Antisèche : l'API des custom elements

Glossaire

Custom element
Balise HTML que tu définis via une classe JavaScript étendant HTMLElement ; c'est la brique de base des Web Components.
customElements.define
Enregistre un nom de balise et sa classe. Le nom doit comporter un tiret (mon-x), sinon une DOMException est levée.
Upgrade
Moment où le navigateur, une fois la balise définie, instancie la classe pour chaque élément correspondant déjà présent dans le document.
Lifecycle callbacks
Méthodes appelées automatiquement : constructor, connectedCallback, disconnectedCallback, attributeChangedCallback.
connectedCallback
Appelé quand l'élément entre dans le DOM : on y peint le contenu et on attache les écouteurs (peut être rappelé lors d'une ré-insertion).
observedAttributes
Getter statique renvoyant la liste des attributs à surveiller ; seuls ceux-ci déclenchent attributeChangedCallback.
Reflet attribut/propriété
Exposer une propriété JS (get/set) qui lit et écrit l'attribut, pour une API agréable et une source de vérité unique.
Autonome vs customisé
Autonome : nouvelle balise extends HTMLElement. Customisé : on étend un élément natif + is="…" (non supporté par Safari).

Récap et vérification

  • customElements.define("x-y", classe) enregistre une balise ; le nom exige un tiret.
  • Cycle de vie : constructor (init, sans DOM), connectedCallback (rendu), disconnectedCallback (nettoyage), attributeChangedCallback (réaction).
  • static get observedAttributes() conditionne l'appel d'attributeChangedCallback.
  • Reflète l'attribut dans une propriété (get/set) pour une API agréable et une source de vérité unique.
  • Autonome (extends HTMLElement) vs customisé (extends HTMLButtonElement + is="...", non supporté Safari).
