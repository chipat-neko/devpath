Module 10 · Web Components — Leçon 29

template et slot

~30 min Avancé Module 1 recommandé

À la fin de cette leçon, tu sauras

  • comprendre pourquoi le contenu d'un <template> n'est ni rendu ni exécuté avant clonage ;
  • savoir cloner un patron avec content.cloneNode(true) pour générer des éléments répétés ;
  • savoir déclarer et remplir un <slot>, nommé ou par défaut, avec un contenu de repli ;
  • savoir choisir entre clonage de template et concaténation de chaînes innerHTML.
Sommaire de la leçon

Tu sais déjà composer du HTML sémantique. Mais dès qu'il faut générer dynamiquement des dizaines de cartes ou de lignes identiques, deux réflexes s'opposent : concaténer des chaînes innerHTML, ou décrire une fois le patron et le cloner. La plateforme web offre pour cela deux éléments natifs, <template> et <slot>, qui sont aussi les fondations des Web Components que tu verras dans les leçons suivantes.

Dans cette leçon, tu apprends à écrire un patron inerte, à le cloner proprement en JavaScript, et à comprendre le rôle de <slot> comme emplacement à remplir. On reste sur l'essentiel : le mariage template + custom element arrive juste après.

<template> : un patron inerte

Le contenu placé dans un <template> est parsé par le navigateur, mais reste inerte : il n'est ni rendu à l'écran, ni exécuté. Les images ne se chargent pas, les <script> ne tournent pas, les styles ne s'appliquent pas tant que tu n'as pas cloné ce contenu dans le document vivant. C'est exactement ce qu'on attend d'un patron : une description, pas une instance.

Le contenu du <template> existe dans le DOM mais ne produit aucun rendu.

Astuce

Clique sur « 👁 Aperçu » sur chaque bloc HTML de cette leçon : tu verras de tes yeux que le contenu d'un <template> reste invisible, puis qu'il apparaît une fois cloné par le script.

Cloner le patron en JavaScript

Le contenu d'un template n'est pas accessible via template.children ni template.innerHTML comme un élément normal : ses childNodes sont toujours vides. Le balisage vit dans une propriété spéciale, template.content, un DocumentFragment. Pour l'utiliser, on en fait une copie profonde avec cloneNode(true), puis on insère cette copie dans le document.

Trois lignes : sélectionner, cloner le content, insérer la copie.

L'argument true est crucial : il demande une copie profonde, c'est-à-dire le fragment et tous ses descendants. Avec false (ou rien), tu ne copierais qu'un fragment vide. Note aussi qu'après append, le DocumentFragment se « vide » en transférant ses nœuds : c'est pour cela qu'on clone à chaque itération, sans jamais toucher au template d'origine.

Note

Un DocumentFragment est un conteneur léger sans parent. Quand tu l'insères, ce sont ses enfants qui rejoignent le DOM, pas le fragment lui-même : aucun nœud parasite ne s'ajoute.

Pourquoi un patron plutôt qu'une chaîne

On pourrait écrire container.innerHTML += "<li>…</li>". Mais cloner un template est souvent préférable : le balisage reste écrit en HTML réel (coloré, validé par l'éditeur, sans guillemets imbriqués), le navigateur ne re-parse pas toute une chaîne à chaque ajout, et surtout tu évites les injections : tu insères du texte via textContent sur les nœuds clonés au lieu d'interpoler des chaînes non échappées.

On clone, on remplit chaque champ via textContent, puis on insère.

Cas réel

La liste de commentaires qui exécutait le pseudo des visiteurs. Un site communautaire affichait ses commentaires en concaténant liste.innerHTML += "<li>" + pseudo + " : " + message + "</li>". Un visiteur s'est inscrit sous le pseudo <img src=x onerror=alert(1)> : à chaque affichage de la liste, le navigateur interprétait la chaîne et exécutait le script — une faille XSS stockée. Le correctif : cloner un <template> de ligne et injecter le texte via textContent. Le pseudo malveillant s'est alors affiché littéralement, jamais exécuté. Bonus : sur une liste de 500 commentaires, on ne re-parse plus tout l'innerHTML à chaque ajout — le rendu est devenu nettement plus fluide.

<slot> : un emplacement à remplir

Là où <template> décrit une structure complète, <slot> réserve un trou que du contenu extérieur viendra remplir. Le slot ne prend tout son sens qu'à l'intérieur du shadow DOM d'un Web Component (leçons 5 et 6) : c'est lui qui « projette » le contenu de l'élément hôte aux bons endroits du gabarit interne.

On distingue le slot par défaut (sans nom, qui reçoit tout contenu non assigné) et les slots nommés. Un slot nommé porte un attribut name ; côté contenu, on cible ce slot avec l'attribut slot="…".

Le <h2 slot="titre"> va dans <slot name="titre"> ; le <p> va dans le slot par défaut.

Voir un slot fonctionner

Un <slot> n'a d'effet que dans un shadow DOM ; pour le prévisualiser, il faut donc un composant minimal qui attache un arbre fantôme et y clone un template. Cet exemple complet est volontairement réduit : la leçon suivante détaille les custom elements. Clique sur « 👁 Aperçu » : le titre projeté remplace le repli, et le slot par défaut affiche le paragraphe de l'hôte.

Le composant clone son gabarit dans un shadow DOM ; les <slot> projettent alors le contenu de l'hôte.

Contenu de repli d'un slot

Ce que tu écris entre les balises d'un <slot> sert de contenu de repli (fallback) : il s'affiche uniquement si aucun contenu n'est projeté pour ce slot. Dès qu'un nœud est assigné, le repli disparaît au profit du contenu fourni.

Si l'hôte ne fournit pas d'élément slot="avatar", l'image de repli est utilisée.

Pièges fréquents

Piège fréquent

Croire qu'un <template> s'affiche tout seul. Non : tant que tu ne clones pas son content, rien n'est rendu. C'est une fonctionnalité, pas un bug.

Piège fréquent

Oublier cloneNode(true) et passer false (ou rien) : tu insères un fragment vide. La copie doit être profonde pour emporter les descendants.

Piège fréquent

Insérer directement template.content (sans cloner) : tu déplaces les nœuds hors du template, qui se vide. À la deuxième itération, il ne reste plus rien à insérer.

Piège fréquent

Utiliser <slot> hors d'un shadow DOM. Dans du HTML léger ordinaire, un <slot> ne projette rien : il n'a d'effet que dans l'arbre fantôme d'un composant.

Pour aller plus loin

Pour aller plus loin

La leçon suivante combine <template> et custom element : le composant clonera son propre patron dans un shadow DOM, où les <slot> prendront enfin tout leur sens. Côté performance, cloner un fragment évite le re-parsing complet qu'impose innerHTML répété, surtout dans une boucle. Explore aussi slotchange pour réagir aux changements de contenu projeté, et les slots nommés multiples pour structurer des composants riches (en-tête, corps, pied).

Antisèche : template et slot

Glossaire

<template>
Élément dont le contenu est parsé mais inerte : ni affiché, ni exécuté, jusqu'à ce qu'on clone son content dans le document.
DocumentFragment
Conteneur léger et sans parent qui porte le contenu du template ; à l'insertion, ce sont ses enfants qui rejoignent le DOM, sans nœud enveloppe.
.content
Propriété d'un <template> exposant son DocumentFragment ; le balisage n'est accessible ni via innerHTML ni via children.
Clonage profond
cloneNode(true) copie un nœud et toute sa descendance. Avec false, on ne copie que le nœud seul : un fragment vide.
<slot>
Emplacement réservé dans le shadow DOM d'un composant, que du contenu de l'hôte vient remplir. Hors shadow DOM, il ne projette rien.
Slot nommé
<slot name="x"> côté gabarit ; l'hôte y dirige un élément portant slot="x". Sans nom, le slot est celui « par défaut ».
Contenu de repli
Ce qu'on écrit entre les balises d'un <slot> : affiché seulement si aucun contenu n'est projeté pour ce slot.
Projection (light → shadow)
Le contenu reste dans le light DOM de l'hôte ; le slot ne fait que l'afficher à l'emplacement voulu du gabarit interne.

Récap et vérification

  • <template> décrit un patron inerte : ni rendu, ni exécuté avant clonage.
  • On accède au contenu via template.content (un DocumentFragment), jamais via innerHTML.
  • content.cloneNode(true) fait une copie profonde qu'on insère dans le DOM.
  • Cloner un patron évite les chaînes innerHTML : plus lisible, plus sûr, souvent plus rapide.
  • <slot> réserve un emplacement projeté dans le shadow DOM ; name + slot="…" pour les slots nommés.
  • Le contenu écrit dans un <slot> est un repli affiché en l'absence de contenu projeté.

Vérifie ta compréhension

  1. Pourquoi le contenu d'un <template> n'apparaît-il pas à l'écran tant qu'on ne le clone pas ?
  2. Que se passe-t-il si tu appelles cloneNode() sans l'argument true ?
  3. Comment diriges-tu un élément vers un slot nommé "titre", et où s'affiche le contenu de repli d'un slot ?
