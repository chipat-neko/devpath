Les champs de saisie

~34 min Débutant Leçon 08 recommandée

À la fin de cette leçon, tu sauras

  • savoir choisir le bon type d'<input> (email, password, number, date, color…) pour adapter clavier et validation ;
  • savoir créer des cases à cocher et des boutons radio en regroupant ces derniers par un name commun ;
  • savoir construire une zone multiligne (<textarea>) et une liste déroulante (<select> / <option>) ;
  • savoir distinguer placeholder (un simple indice) du <label> et utiliser value correctement.
Sommaire de la leçon

Dans la leçon précédente, tu as vu comment poser un formulaire avec <form> et un premier champ de texte. Mais un formulaire, ce n'est presque jamais une seule case : tu as besoin de demander un e-mail, un mot de passe, une date, un choix unique, plusieurs cases à cocher… HTML offre toute une palette de champs prête à l'emploi.

Bonne nouvelle : la plupart de ces champs sont juste des variantes de la balise que tu connais déjà, <input>. On va les passer en revue, du plus simple au plus pratique, et tu pourras voir chaque rendu en cliquant sur « 👁 Aperçu ».

La balise <input> et ses types

Une seule balise, <input>, change complètement de comportement selon son attribut type. Choisir le bon type, c'est offrir au visiteur le bon clavier sur mobile et une validation automatique.

Cinq types différents : chacun affiche un contrôle adapté (sélecteur de date, pipette de couleur…).

Cas réel

Sur ton téléphone, un champ type="email" fait apparaître un clavier avec la touche @ ; un type="tel" affiche le pavé numérique ; un type="date" ouvre un calendrier. Choisir le bon type, c'est éviter à l'utilisateur de chercher les bonnes touches — un détail qui change tout sur mobile.

Les types les plus utiles à connaître : text, email, password, number, tel, url, search, date, time, color, range (un curseur), file (un fichier) et hidden (un champ invisible transmis avec le formulaire). Tu n'as pas à tous les retenir : retiens surtout que le type change le clavier et la validation.

Astuce

Sur chaque bloc de code, clique sur « 👁 Aperçu » pour voir le rendu en direct : change type="email" en type="color" et observe comment le champ se transforme. C'est la meilleure façon de comprendre ces types.

Cases à cocher et boutons radio

Pour proposer des choix, deux contrôles très différents. Les cases à cocher (type="checkbox") permettent de cocher plusieurs options indépendantes. Les boutons radio (type="radio") ne laissent choisir qu'une seule option dans un groupe : ce qui les regroupe, c'est un name commun.

Les deux radios partagent name="niveau" : cocher l'un décoche l'autre. Le <fieldset> et sa <legend> regroupent et titrent proprement.

La zone de texte multiligne

Un <input> ne tient que sur une ligne. Pour un message, un avis, une description, on utilise <textarea>, qui est une balise avec ouverture et fermeture. Les attributs rows (lignes) et cols (colonnes) fixent sa taille initiale.

Attention : rien ne doit se trouver entre les balises, sinon ce texte apparaîtrait déjà écrit dans la zone.

La liste déroulante <select>

Quand les choix sont nombreux, une liste déroulante prend moins de place que des radios. Elle s'écrit avec <select> et une <option> par choix. Chaque option porte un value (la valeur envoyée). On peut ranger les options par <optgroup> et présélectionner l'une d'elles avec selected.

France est présélectionné grâce à selected. Les <optgroup> créent des sous-titres non sélectionnables.

Suggestions avec <datalist>

Tu veux laisser le visiteur taper librement tout en lui proposant des suggestions ? C'est le rôle de <datalist>. On relie un <input> à la liste via l'attribut list, qui pointe vers l'id de la datalist.

Contrairement à <select>, on peut quand même saisir une ville absente de la liste.

placeholder et value : bien les distinguer

Deux attributs souvent confondus. placeholder affiche un indice grisé qui disparaît dès qu'on tape : ce n'est qu'une aide, jamais une donnée. value donne une valeur initiale réelle, déjà présente dans le champ et envoyée si on n'y touche pas.

Note

Le <label> reste toujours visible et décrit le champ ; le placeholder n'est qu'un complément. Les deux ne jouent pas le même rôle.

Pièges fréquents

Piège fréquent

Utiliser un placeholder à la place du <label>. L'indice disparaît dès qu'on tape (impossible de se relire) et il est mal lu par les lecteurs d'écran : garde toujours un vrai <label>.

Piège fréquent

Des boutons radio sans name commun : ils deviennent indépendants et l'on peut tous les cocher. Pour un choix unique, le même name sur tout le groupe est obligatoire. Pense aussi à mettre un value sur chaque <option>, sinon la valeur envoyée est imprévisible. Enfin, évite type="text" pour tout : tu perds le clavier adapté et la validation.

Pour aller plus loin

Pour aller plus loin

Explore autocomplete (le navigateur propose les valeurs déjà connues), inputmode (affiner le clavier mobile sans changer le type), accept pour limiter les fichiers d'un type="file" (ex. accept="image/*"), et multiple pour autoriser plusieurs fichiers ou e-mails. Plus tard, le CSS te permettra de styler entièrement ces contrôles.

Glossaire

type (input)
Attribut définissant la nature du champ (email, password, number…) ; adapte le clavier et la validation.
checkbox / radio
Case(s) à cocher (choix multiples) / boutons exclusifs partageant un name (choix unique).
textarea
Champ de texte sur plusieurs lignes (attributs rows, cols).
select / option
Liste déroulante et ses choix ; selected présélectionne une option.
datalist
Liste de suggestions reliée à un input (list) tout en autorisant la saisie libre.
placeholder
Indice grisé affiché dans un champ vide ; il disparaît à la saisie et n'est jamais envoyé.
value
Valeur initiale réellement présente dans le champ et transmise si on n'y touche pas.

Récap et vérification

  • <input> change de comportement selon son type (email, password, number, date, color, range, file…) : clavier et validation adaptés.
  • Checkbox = plusieurs choix indépendants ; radio = un seul choix, regroupé par un name commun.
  • <textarea> pour le texte multiligne ; <select> + <option> (et <optgroup>, selected) pour une liste déroulante.
  • <datalist> propose des suggestions tout en laissant taper librement.
  • placeholder = indice qui disparaît ; value = valeur initiale réelle ; ni l'un ni l'autre ne remplace le <label>.

Vérifie ta compréhension

  1. Quel attribut faut-il partager entre plusieurs boutons radio pour qu'un seul puisse être coché à la fois ?
  2. Quelle différence concrète y a-t-il entre placeholder et value dans un champ ?
  3. Quelle balise utilises-tu pour un message sur plusieurs lignes, et pourquoi pas un <input> ?
