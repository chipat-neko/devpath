Module 01 · Structurer en HTML — Leçon 01

Structurer une page en HTML

~32 min Débutant Aucun prérequis

À la fin de cette leçon, tu sauras

  • écrire le squelette minimal d'une page HTML valide ;
  • utiliser les balises sémantiques (<header>, <main>, <footer>) plutôt qu'une soupe de <div> ;
  • hiérarchiser le contenu avec les titres et les paragraphes ;
  • ajouter des liens, des images avec alt et des listes.
Sommaire de la leçon

Avant de rendre une page jolie, il faut décrire ce qu'elle contient. C'est exactement le rôle du HTML : organiser le sens du contenu (un titre, un paragraphe, un lien, une image) pendant que l'apparence, elle, sera traitée plus tard avec le CSS. Dans cette leçon, tu vas apprendre à poser la structure complète d'une page, de son squelette jusqu'aux listes.

On part du plus simple — une seule balise — pour arriver, étape par étape, à une page « à propos » bien structurée. À la fin, tu sauras lire et écrire le HTML qui sert de fondation à tout site web.

Qu'est-ce que le HTML

HTML signifie HyperText Markup Language : un langage de balisage. Il ne décrit pas l'apparence (les couleurs, les marges, la police), mais le sens du contenu. Tu n'écris pas « ce texte est gros et gras », tu écris « ce texte est un titre ». C'est le navigateur, aidé du CSS, qui décidera ensuite de l'allure.

Cette idée est centrale : HTML = le sens, CSS = l'apparence, JavaScript = le comportement. Garder cette séparation en tête t'évitera la moitié des erreurs de débutant. On peut comparer une page web à une maison : le HTML est le gros œuvre (murs, pièces, escaliers), le CSS la décoration (peinture, meubles), et le JavaScript l'électricité (ce qui réagit quand on appuie sur un interrupteur). Pour marquer le sens, on entoure le contenu de balises.

Une balise

Une balise vient le plus souvent par paire : une balise ouvrante et une balise fermante qui encadrent le contenu. La fermante se reconnaît à sa barre oblique. L'ensemble « ouvrante + contenu + fermante » forme un élément.

Certaines balises n'ont pas de contenu à encadrer : elles sont auto-fermantes. Une image ou un saut de ligne ne contiennent rien, on les écrit donc d'un seul tenant.

Une balise peut aussi porter des attributs : des informations supplémentaires écrites dans la balise ouvrante, sous la forme nom="valeur". Par exemple, un lien a besoin de savoir vers où il pointe grâce à l'attribut href.

Cas réel

Le bouton « Ajouter au panier » d'un site marchand, c'est souvent ceci : <button type="submit">Ajouter au panier</button>. Une balise (<button>), un attribut (type="submit") et un contenu (le texte). Tout le web est fait de cet assemblage simple, répété des milliers de fois.

Titres et paragraphes

Le HTML offre six niveaux de titre, de <h1> (le plus important) à <h6> (le plus secondaire). Le texte courant, lui, va dans des <p> (paragraph).

Deux règles d'or. Un seul <h1> par page : c'est le sujet principal, comme le titre d'un livre. Et la hiérarchie doit être logique : un <h3> est une sous-partie d'un <h2>, exactement comme dans la table des matières d'un livre. On choisit un niveau pour son sens, jamais pour la taille du texte affiché — ça, c'est l'affaire du CSS.

Bonne pratique

Avant d'écrire la moindre balise, fais le plan de ta page comme une table des matières : un titre principal, des sections, des sous-sections. Ta hiérarchie de <h1>→<h6> en découlera naturellement, et ta page sera lisible autant par les humains que par les moteurs de recherche.

Pour trois raisons concrètes : l'accessibilité (les lecteurs d'écran annoncent « navigation », « contenu principal » et permettent d'y sauter directement), le référencement (les moteurs de recherche comprennent mieux la structure), et la lisibilité du code (toi et tes collègues vous y retrouvez bien plus vite).

Astuce

Demande-toi toujours : « cette zone a-t-elle un rôle connu ? » Si oui (en-tête, menu, contenu, pied), prends la balise sémantique. Le <div> reste utile, mais seulement pour les regroupements purement techniques sans signification.

Liens, images et listes

Un lien se crée avec <a> et son attribut href, qui indique la destination (une autre page de ton site, ou une adresse externe).

Une image utilise <img> avec src (le chemin du fichier) et surtout alt (une description textuelle). Le alt n'est pas facultatif : il est lu à voix haute pour les personnes malvoyantes et s'affiche si l'image ne charge pas.

Enfin, les listes. Une liste non ordonnée (<ul>, à puces) quand l'ordre n'a pas d'importance ; une liste ordonnée (<ol>, numérotée) quand il compte. Dans les deux cas, chaque élément est un <li> (list item).

Pièges fréquents

Quelques erreurs reviennent sans cesse chez les débutants. Les connaître à l'avance te fera gagner beaucoup de temps.

Erreur fréquente

Oublier de fermer une balise. Un <p> sans son </p> et la mise en page peut se casser de façon inexplicable. Vérifie toujours que chaque balise ouvrante a sa fermante.

  • Image sans alt : inaccessible et pénalisée par le référencement. Si l'image est purement décorative, mets un alt vide (alt=""), mais ne l'omets jamais.
  • Abuser des <div> là où une balise sémantique existe : tu perds tous les bénéfices d'accessibilité et de SEO.
  • Plusieurs <h1> sur une même page : la structure devient ambiguë. Un seul titre principal, toujours.
  • Sauter des niveaux de titre (passer d'un <h2> directement à un <h4>) : la hiérarchie devient incohérente. Descends les niveaux un par un.

Pour aller plus loin

Cette leçon pose les bases du contenu. La suite naturelle, c'est de comprendre la grande séparation des rôles du web : le HTML pour le contenu, le CSS pour la présentation (couleurs, mises en page, polices), et le JavaScript pour le comportement (interactions, animations). Ces trois langages restent dans des fichiers distincts, ce qui rend le code plus simple à maintenir.

Pour aller plus loin

Un avant-goût de class, qui prendra tout son sens au module CSS : <p class="intro">...</p>. Côté CSS, on pourra alors écrire une règle ciblant .intro pour, par exemple, agrandir ce paragraphe. Pense aussi à valider ton HTML avec le validateur du W3C : il repère les balises mal fermées ou mal imbriquées.

Antisèche : les balises de cette leçon

À garder sous la main : un récapitulatif des balises vues, leur rôle et un exemple minimal.

Glossaire

Balise (tag)
Mot-clé entre chevrons (<p>) qui marque le début ou la fin d'un élément. Le plus souvent par paire (ouvrante / fermante).
Élément
L'ensemble « balise ouvrante + contenu + balise fermante », par exemple <p>Bonjour</p>.
Attribut
Information supplémentaire placée dans la balise ouvrante, sous la forme nom="valeur" (ex. href, src, alt, lang).
Imbrication
Le fait d'emboîter des éléments les uns dans les autres, comme des poupées russes. L'indentation rend cette hiérarchie lisible.
Balise auto-fermante
Balise sans contenu à encadrer, écrite d'un seul tenant (ex. <img>, <br>).
Sémantique
Le choix de balises qui décrivent le sens du contenu (<nav>, <article>) plutôt qu'un <div> neutre.

Récap et vérification

  • Le HTML décrit le sens du contenu, pas son apparence.
  • Une balise encadre du contenu ; certaines sont auto-fermantes ; les attributs ajoutent des infos.
  • Le squelette : <!DOCTYPE html>, <html lang>, <head> (meta, title) et <body>.
  • Un seul <h1>, une hiérarchie de titres logique, du texte dans des <p>.
  • Les balises sémantiques (header, nav, main, article, footer) valent mieux qu'une soupe de <div>.
  • Liens (<a href>), images (<img> avec alt) et listes (<ul>/<ol> + <li>).

Vérifie ta compréhension

  2. Pourquoi préférer <nav> à un simple <div> pour un menu ?
  3. Que se passe-t-il si tu oublies l'attribut alt sur une image, et que mettre si elle est décorative ?
