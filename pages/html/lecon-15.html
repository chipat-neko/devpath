Module 05 · Accessibilité, métadonnées & qualité — Leçon 15

Bonnes pratiques, validation & structure

~32 min Débutant Leçon 14 recommandée

À la fin de cette leçon, tu sauras

  • valider une page avec le validateur du W3C et comprendre pourquoi un code valide est plus robuste ;
  • soigner la structure des titres (un seul <h1>, hiérarchie cohérente) et la lisibilité du code ;
  • déclarer l'encodage UTF-8, écrire les caractères spéciaux et respecter la séparation HTML / CSS / JS ;
  • dérouler une checklist de qualité avant de publier une page.
Sommaire de la leçon

Tu sais maintenant écrire des pages HTML complètes : structure, textes, listes, liens, images, tableaux, formulaires, métadonnées et accessibilité. Il te manque un dernier réflexe, celui des pros : écrire un code propre, valide et maintenable. C'est ce qui fait la différence entre une page qui « marche par chance » et une page solide, lisible des mois plus tard, et qui fonctionne partout.

Dans cette leçon de clôture, on rassemble les bonnes habitudes et on regarde la suite de ton parcours. Bonne nouvelle : tu connais déjà presque tout, il s'agit surtout de mettre de l'ordre.

1. Un HTML valide

Le HTML « valide », c'est du HTML qui respecte les règles du langage : balises bien fermées, imbriquées dans le bon ordre, attributs corrects. Un navigateur tolère beaucoup d'erreurs et « devine » ce que tu voulais dire, mais ces devinettes varient d'un navigateur à l'autre. Un code valide, lui, se comporte partout pareil : il est plus robuste et plus compatible.

Pour vérifier, on passe sa page au validateur du W3C (le site validator.w3.org). Il lit ton code et liste les erreurs avec le numéro de ligne. Voici une page valide minimale que tu peux tester :

Une page valide n'a pas besoin d'être longue : elle doit juste respecter les règles.

Cas réel

Une balise mal fermée ou un attribut oublié peut « marcher » sur ton navigateur mais casser sur un autre, ou perturber un lecteur d'écran. Passer sa page au validateur du W3C avant de publier, c'est comme relire une lettre avant de l'envoyer : on repère les fautes invisibles à l'œil. Beaucoup d'équipes l'intègrent même dans leurs vérifications automatiques.

Astuce

Sur chaque bloc de code de cette leçon, clique le bouton « 👁 Aperçu » pour voir le rendu en direct. Modifie un titre, relance l'aperçu, observe : c'est la meilleure façon d'ancrer ce que tu apprends.

2. Une bonne structure de titres

Les titres <h1> à <h6> dessinent le plan de ta page, comme la table des matières d'un livre. Deux règles d'or : un seul <h1> par page (le titre principal), et une hiérarchie cohérente qui ne saute pas de niveau (pas de <h4> juste après un <h2>). Cette structure aide les moteurs de recherche et les lecteurs d'écran à comprendre ta page.

Le plan se lit dans les titres : un h1, puis des h2, puis des h3 imbriqués proprement.

3. Un code lisible

Un code lisible se relit et se corrige facilement. Cinq habitudes suffisent : indenter (décaler les éléments imbriqués), écrire les balises et attributs en minuscules, mettre les valeurs d'attributs entre guillemets, fermer chaque balise, et ajouter des commentaires avec <!-- ... --> pour t'y retrouver.

Le commentaire n'apparaît pas dans la page : il sert à toi (et à ton équipe).

Note

« Fermer chaque balise » concerne les balises qui ont un contenu (comme <p>...</p>). Quelques balises sont vides par nature et n'ont pas de balise de fermeture : <meta>, <img>, <br>, <hr> ou <link>. C'est normal, et c'est valide.

4. L'encodage UTF-8 et les caractères spéciaux

Pour que les accents (é, à, ç), les emojis et les symboles s'affichent correctement, ta page doit déclarer l'encodage UTF-8 tout en haut du <head> avec <meta charset="UTF-8">. Sans ça, tu risques de voir des « Ã© » à la place des « é ».

Certains caractères ont un sens spécial en HTML et doivent s'écrire sous forme d'entité : &lt; pour <, &gt; pour >, &amp; pour &, ou encore &copy; pour le symbole ©.

Lance l'aperçu : tu verras « 3 < 5 », « & » et « © » s'afficher correctement.

Le <meta charset> d'abord, tout en haut du <head>

Le navigateur a besoin de connaître l'encodage avant de décoder le reste de la page. Si <meta charset="UTF-8"> arrive après un <title> accentué, ce titre peut s'afficher de travers. La règle : place cette balise en première ligne du <head>, dans les tout premiers octets du document.

5. Séparer structure, présentation et comportement

Le web repose sur trois langages aux rôles distincts : HTML pour la structure (le contenu), CSS pour la présentation (les couleurs, la mise en page), JavaScript pour le comportement (l'interactivité). Garde-les séparés : ne mélange pas le style dans ton HTML, mets le CSS dans des fichiers à part. On charge le CSS dans le <head> et le JS avec l'attribut defer pour qu'il s'exécute après le chargement de la page.

Le CSS via <link> dans le head, le JS via <script ... defer> : chacun son fichier, chacun son rôle. (Dans l'aperçu, le titre et le paragraphe s'affichent ; styles.css et script.js sont juste des noms d'exemple.)

6. Des bases de performance

Une page rapide est une page agréable. Sans entrer dans les détails, deux réflexes faciles : utiliser des images optimisées (de la bonne taille, avec un attribut alt et, si possible, loading="lazy" pour ne charger les images qu'au moment où on les voit) et différer les scripts avec defer pour ne pas bloquer l'affichage.

Les attributs width et height évitent aussi que la page « saute » pendant le chargement. Dans l'aperçu, comme l'image n'existe pas, c'est le texte alt qui s'affiche : preuve qu'un bon alt compte.

Et après ?

Tu maîtrises désormais le HTML : tu sais structurer le contenu de n'importe quelle page. La suite naturelle, c'est de la mettre en forme avec le CSS — couleurs, polices, mises en page, animations. C'est l'objet du cours CSS de Syntaxe, qui prend le relais exactement là où on s'arrête.

Plus tard, JavaScript ajoutera de l'interactivité (menus, formulaires dynamiques, jeux). Mais une chose à la fois : un HTML solide est la fondation de tout le reste. Tu as posé cette fondation. Bravo, et continue !

Checklist de qualité

Avant de publier une page, déroule cette liste. Si tout est coché, tu peux mettre en ligne l'esprit tranquille.

  • La page commence par <!DOCTYPE html> et déclare la langue avec <html lang="fr">.
  • L'encodage <meta charset="UTF-8"> est présent en haut du <head>, et il y a un <title>.
  • Il y a un seul <h1> et la hiérarchie des titres est cohérente (pas de saut de niveau).
  • Toutes les balises sont fermées (sauf les balises vides comme <img> ou <br>), en minuscules, avec les valeurs d'attributs entre guillemets.
  • Chaque image a un attribut alt pertinent ; chaque champ de formulaire a un <label>.
  • Le code est indenté et lisible ; aucun style écrit en dur dans le HTML.
  • La page passe le validateur du W3C sans erreur.
  • Les liens fonctionnent et pointent vers les bonnes adresses.

Glossaire

HTML valide
Code respectant les règles du langage (balises fermées, bien imbriquées) ; se comporte pareil partout.
DOCTYPE
Première ligne d'une page (<!DOCTYPE html>) : elle déclare le HTML5 et fait interpréter la page en mode standard.
Validateur du W3C
Outil en ligne (validator.w3.org) qui liste les erreurs HTML d'une page, avec leur numéro de ligne.
Hiérarchie des titres
Plan de la page formé par h1→h6 ; un seul h1, sans saut de niveau.
Entité HTML
Écriture d'un caractère réservé (&lt; pour <, &amp; pour &, &copy; pour ©).
UTF-8
Encodage des caractères permettant accents, symboles et emojis ; à déclarer en haut du head.
Séparation des préoccupations
Garder HTML (structure), CSS (présentation) et JS (comportement) dans des fichiers distincts.
defer
Attribut d'un <script> qui diffère son exécution après le chargement de la page.

Récap et vérification

  • Un code valide (vérifié au validateur du W3C) est plus robuste et compatible.
  • Une page a un seul <h1> et une hiérarchie de titres cohérente.
  • Un code lisible : indentation, minuscules, guillemets, balises fermées, commentaires.
  • <meta charset="UTF-8"> et les entités (&lt;, &amp;, &copy;) pour les caractères spéciaux.
  • HTML = structure, CSS = présentation (dans le head), JS = comportement (avec defer).
  • Performance : images optimisées avec alt et loading="lazy", scripts différés.
