Composants réutilisables : template et Web Components

~34 min Avancé Leçon 22 recommandée

À la fin de cette leçon, tu sauras

  • préparer un gabarit inerte avec <template> et le cloner à la demande ;
  • définir un élément personnalisé (une nouvelle balise) avec customElements.define ;
  • expliquer ce qu'encapsule le shadow DOM ;
  • projeter du contenu dans un composant avec <slot>.
Sommaire de la leçon

Sur un site, le même bout d'interface revient partout : une carte produit, un avatar, un encart d'alerte. Le copier-coller multiplie ce HTML : dix cartes, dix blocs identiques à maintenir. Le jour où le design change, il faut corriger dix endroits. Le web propose des briques natives pour fabriquer un composant une fois et le réutiliser : le gabarit <template>, les éléments personnalisés et le shadow DOM. Ensemble, on les appelle les Web Components.

Ce sont des standards du navigateur : aucun framework à installer. On touche ici au JavaScript, mais l'idée reste du HTML — créer ses propres balises.

Le gabarit inerte : <template>

Un <template> contient du HTML qui n'est pas affiché et reste inerte : les images ne se chargent pas, les scripts ne s'exécutent pas, le contenu n'apparaît nulle part. C'est un moule qui dort dans la page. On le clone quand on en a besoin, autant de fois qu'on veut, puis on insère la copie dans le document.

Bonne pratique

Le gabarit se lit via .content (un fragment de document), et cloneNode(true) copie tout l'intérieur (le true = clone profond). Sans true, tu ne copierais qu'une coquille vide.

Créer sa propre balise : l'élément personnalisé

Un élément personnalisé (custom element) est une nouvelle balise que tu inventes, avec son propre comportement. Tu l'enregistres avec customElements.define("nom-balise", classe). La classe hérite de HTMLElement ; sa méthode connectedCallback() s'exécute dès que la balise entre dans la page.

Règle absolue : le nom doit contenir un trait d'union (-). C'est ce qui distingue tes balises des futures balises natives : le navigateur garantit qu'il ne créera jamais de balise standard avec un tiret, donc <user-card> ne risque aucune collision.

Désormais, écrire <badge-nouveau></badge-nouveau> n'importe où dans le HTML affiche le badge, avec son comportement intégré — comme une balise native.

Erreur fréquente

Un nom en un seul mot (customElements.define("badge", …)) lève une erreur : le nom doit contenir un tiret. Deux mots au minimum, reliés par - : badge-nouveau, ma-carte, app-header.

Le shadow DOM : encapsuler

Par défaut, le CSS de la page peut atteindre l'intérieur de ton composant, et inversement : c'est fragile. Le shadow DOM crée un petit arbre isolé attaché à ton élément. Les styles définis dedans ne fuient pas vers la page ; les styles de la page n'entrent pas. Le composant devient une bulle autonome.

Cas réel

Tu utilises déjà des shadow DOM sans le savoir : un <video controls>, un <input type="range"> ou un <details> cachent leurs boutons internes dans un shadow DOM du navigateur. Les grands design systems (comme les bibliothèques de composants d'entreprise) s'appuient sur les Web Components pour livrer des composants agnostiques du framework : la même <ui-button> fonctionne dans une page React, Vue ou sans framework du tout.

Projeter du contenu avec <slot>

Un composant fermé serait rigide. Le <slot> est un emplacement à l'intérieur du shadow DOM où le navigateur projette le contenu que l'utilisateur a écrit entre les balises. Le composant définit la structure ; l'utilisateur fournit le contenu.

Le texte écrit entre <encart-info> et sa fermeture est projeté dans le <slot>, à l'intérieur de la boîte encadrée du composant.

Quand les utiliser (et quand s'abstenir)

Les Web Components brillent pour des composants réutilisables et partagés, surtout entre projets ou frameworks différents. Pour une petite page, un simple <template> cloné suffit souvent : inutile de sortir l'artillerie du shadow DOM.

Pour aller plus loin

Explore attributeChangedCallback (réagir quand un attribut change), disconnectedCallback (nettoyage au retrait), les slots nommés (<slot name="titre">) pour plusieurs emplacements, et les bibliothèques légères (Lit) qui rendent l'écriture de Web Components plus confortable. Côté style, :host cible le composant lui-même et ::part() expose des morceaux stylables depuis la page.

Antisèche

Glossaire

Web Components
Ensemble de standards du navigateur (<template>, éléments personnalisés, shadow DOM) pour créer des composants réutilisables sans framework.
<template>
Balise dont le contenu reste inerte et non affiché ; sert de moule à cloner.
Élément personnalisé
Nouvelle balise définie par customElements.define ; son nom contient obligatoirement un trait d'union.
connectedCallback
Méthode d'un élément personnalisé, appelée dès que la balise est insérée dans le document.
Shadow DOM
Arbre isolé attaché à un élément : ses styles n'affectent pas la page et ne subissent pas le CSS global.
Clone profond
Copie d'un nœud et de tout son contenu, obtenue par cloneNode(true).
<slot>
Emplacement, dans le shadow DOM, où le navigateur projette le contenu fourni par l'utilisateur du composant.

Récap et vérification

  • Un <template> est un moule inerte qu'on clone (content.cloneNode(true)) au lieu de copier-coller du HTML.
  • Un élément personnalisé est une nouvelle balise (customElements.define) ; son nom doit contenir un tiret.
  • Le shadow DOM isole les styles du composant dans les deux sens.
  • Le <slot> projette le contenu de l'utilisateur à l'intérieur du composant.
  • À réserver aux composants vraiment réutilisables ; un simple <template> suffit souvent.

Vérifie ta compréhension

  1. Pourquoi le contenu d'un <template> ne s'affiche-t-il pas ?
  2. Que copie exactement cloneNode(true) ?
  3. Pourquoi le nom d'un élément personnalisé doit-il contenir un tiret ?
  4. Qu'est-ce que le shadow DOM isole ?
