Module 1 · Penser fonctionnel — Leçon 02

Types et fonctions pures

~50 min Avancé Prérequis : leçon 1

À la fin de cette leçon, tu sauras

  • Savoir lire et écrire une signature de type (double :: Int -> Int) et comprendre l'inférence ;
  • Savoir reconnaître une fonction pure et expliquer pourquoi l'absence d'effet de bord facilite le raisonnement et les tests ;
  • Savoir utiliser la curryfication et l'application partielle pour fabriquer de nouvelles fonctions ;
  • Savoir structurer une expression avec let, where, if/then/else et les gardes.
Sommaire de la leçon

Dans la leçon précédente, tu as installé GHC et lancé GHCi. Tu vas maintenant rencontrer le cœur de Haskell : un système de types statique qui vérifie ton programme avant qu'il ne tourne, et une notion de fonction beaucoup plus stricte que celle à laquelle Python, JavaScript ou Java t'ont habitué. Bonne nouvelle : cette rigueur n'est pas une corvée, c'est un filet de sécurité qui attrape tes erreurs pendant que tu écris.

Le fil rouge de ce cours : Haskell t'apprend à penser autrement. Les types et les fonctions pures sont les deux premières briques de ce changement de mentalité, et ce sont des idées qui irriguent ensuite tous les langages que tu écriras.

Les types de base

Tout en Haskell a un type, connu à la compilation. Dans GHCi, la commande :t (pour :type) te montre le type de n'importe quelle expression. C'est ton meilleur outil d'exploration.

Le symbole :: se lit « a pour type ».

Voici les types que tu croiseras dès le premier jour :

  • Int : entier de taille fixe (rapide, mais qui déborde silencieusement au-delà d'environ 9 trillions).
  • Integer : entier à précision arbitraire. Il grandit autant que ta mémoire le permet.
  • Double : nombre à virgule flottante double précision.
  • Bool : True ou False (avec une majuscule !).
  • Char : un caractère unique, entre apostrophes : 'a'.
  • String : une chaîne, entre guillemets : "abc". C'est en réalité un alias pour [Char], une liste de caractères.

:info (abrégé :i) révèle qu'une String n'est qu'un autre nom pour une liste de Char.

Note

Les noms de types commencent toujours par une majuscule (Int, Bool). Les noms de fonctions et de variables, eux, commencent par une minuscule. Cette règle n'est pas cosmétique : le compilateur s'en sert pour distinguer les deux.

Cas réel — le compteur qui a débordé

En 2014, le clip Gangnam Style a dépassé 2 147 483 647 vues — la limite d'un entier signé sur 32 bits. Le compteur de YouTube, codé sur ce type, a débordé, forçant Google à repasser ses compteurs en 64 bits. C'est exactement le piège de Int : rapide, mais borné. Quand un calcul peut dépasser ces limites (cryptographie, factorielles, comptages massifs), Haskell offre Integer, à précision arbitraire : product [1..100] :: Integer calcule 100! sans broncher, là où Int renverrait un résultat faux, silencieusement.

Les signatures de type

Une signature déclare le type d'une fonction avant sa définition. Lis la signature de double ci-dessous comme une phrase : « double prend un Int et rend un Int ».

La flèche -> sépare l'entrée de la sortie. Tu n'es pas obligé d'écrire la signature : Haskell la devine (on verra l'inférence juste après). Mais on l'écrit presque toujours, pour trois raisons :

  • C'est de la documentation vérifiée : si ton code ne respecte pas la signature, ça ne compile pas.
  • Ça localise les erreurs : sans signature, une erreur de type peut être signalée loin de sa vraie cause.
  • Ça guide ta pensée : en Haskell, on écrit souvent le type d'abord, le code ensuite.

L'inférence : le compilateur devine

Haskell sait déduire le type de presque tout, seul. Tu peux donc écrire une fonction sans signature et demander à GHCi ce qu'il en a déduit.

Surpris par Num a => a -> a ? C'est le type le plus général possible. Le compilateur n'a pas vu de raison de fixer Int : il dit « triple marche pour n'importe quel type a, à condition que a soit un nombre (Num a) ». La partie avant => est une contrainte. On creusera ces classes de types plus tard ; pour l'instant, retiens que l'inférence vise toujours la généralité.

Astuce

Écris ta fonction sans signature, demande :t à GHCi, puis recopie le type proposé au-dessus de ta définition. C'est une façon rapide et fiable d'apprendre à typer juste.

Les fonctions pures

Une fonction est pure quand elle respecte deux règles : pour une même entrée elle rend toujours la même sortie, et elle ne produit aucun effet de bord (pas d'écriture de fichier, pas d'affichage, pas de modification d'une variable globale, pas d'appel réseau). En Haskell, toutes les fonctions « ordinaires » sont pures par construction : le type t'avertit dès qu'une fonction touche au monde extérieur.

Compare avec un compteur en Python qui dépend d'un état caché : compteur() rend 1, puis 2, puis 3… Même appel, résultats différents. En Haskell, ce comportement ne peut pas se glisser dans une fonction ordinaire sans apparaître dans son type.

Pourquoi est-ce libérateur ?

  • Raisonnement local : pour comprendre une fonction pure, tu n'as qu'à la lire. Rien d'extérieur ne peut la faire dévier.
  • Tests faciles : une entrée, une sortie attendue. Pas de base de données à monter, pas d'état à réinitialiser.
  • Parallélisme : deux fonctions pures ne se marchent jamais dessus. On peut les exécuter en parallèle sans crainte de course de données.

Tu viens de fabriquer une fonction neuve sans écrire de nouveau corps. C'est un outil que tu utiliseras constamment, notamment avec map et compagnie dans les prochaines leçons.

Définitions locales : let et where

Pour nommer une valeur intermédiaire, deux outils. let … in … est une expression ; where attache des définitions à la fin d'une équation.

Les deux sont équivalents ici. On préfère souvent where pour lire d'abord la formule principale, les détails ensuite ; let sert quand on veut une définition au fil d'une expression. (En vrai, Haskell fournit déjà pi dans son prélude ; on le redéfinit ici juste pour l'exemple.)

if/then/else et les gardes

En Haskell, if/then/else est une expression qui rend une valeur : le else est donc obligatoire (une expression doit toujours produire un résultat). Pour enchaîner plusieurs cas, les gardes (les |) sont bien plus lisibles.

otherwise n'est pas un mot-clé magique : c'est juste un nom défini dans le prélude qui vaut True, donc la dernière garde attrape tous les cas restants.

Pièges fréquents

Piège fréquent

Oublier le else. Comme if est une expression qui doit rendre une valeur dans tous les cas, if cond then x seul est une erreur. Si tu veux « faire quelque chose ou rien », c'est que tu raisonnes encore en impératif : en Haskell on choisit toujours entre deux valeurs.

Piège fréquent

Mélanger Int et Double. Haskell ne convertit pas tout seul. (3 :: Int) + 2.5 ne compile pas ; il faut convertir explicitement avec fromIntegral. La rigueur du typage t'oblige à expliciter ce qu'un langage dynamique masquerait.

Pour aller plus loin

Pour aller plus loin

La curryfication permet une écriture dite « point-free » : double' = (* 2) ne nomme même plus son argument. Tu peux aussi composer des fonctions avec l'opérateur . (par exemple (+ 1) . (* 2), qui multiplie par 2 puis ajoute 1). On y reviendra ; pour l'instant, contente-toi de reconnaître l'idée quand tu la croiseras.

Antisèche — types et fonctions

Glossaire

Signature de type
Ligne nom :: … qui déclare le type d'une fonction avant sa définition ; documentation vérifiée par le compilateur.
Inférence
Capacité du compilateur à déduire seul le type d'une expression, en visant le plus général possible.
Fonction pure
Fonction qui, pour les mêmes entrées, rend toujours la même sortie et ne produit aucun effet de bord.
Effet de bord
Action sur le monde extérieur (affichage, fichier, réseau, mutation d'un état) ; en Haskell, signalé dans le type (IO).
Curryfication
Le fait que toute fonction à plusieurs arguments soit une chaîne de fonctions à un seul argument (a -> b -> c = a -> (b -> c)).
Application partielle
Fournir une partie seulement des arguments d'une fonction pour en obtenir une nouvelle (ex. ajoute 5).
Section
Opérateur partiellement appliqué entre parenthèses : (+ 1), (* 2), (/ 2).
Garde
Condition introduite par | dans une définition ; les gardes sont testées de haut en bas, otherwise attrapant le reste.

Récap et vérification

  • Chaque expression a un type statique ; :t te le révèle dans GHCi.
  • Types de base : Int, Integer (précision arbitraire), Double, Bool, Char, String (= [Char]).
  • Une signature (double :: Int -> Int) documente, localise les erreurs et guide la pensée ; l'inférence la déduit sinon.
  • Une fonction pure : même entrée, même sortie, zéro effet de bord. D'où raisonnement local, tests faciles, parallélisme.
  • La curryfication fait de toute fonction à n arguments une chaîne de fonctions à un argument : d'où l'application partielle et les sections ((+ 1)).
  • let/where nomment des valeurs locales ; if/then/else est une expression (else obligatoire) ; les gardes | enchaînent les cas.

Vérifie ta compréhension

  1. Pourquoi écrit-on une signature de type alors que le compilateur sait l'inférer ?
  2. Que signifie réellement la signature Int -> Int -> Int, et qu'est-ce que ça autorise ?
  3. Donne deux raisons concrètes pour lesquelles une fonction pure est plus facile à tester qu'une fonction à effet de bord.
