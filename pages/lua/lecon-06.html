Module 2 · Les tables — Leçon 06

Les tables comme dictionnaires et structures

~50 min Intermédiaire Prérequis : leçon 5

À la fin de cette leçon, tu sauras

  • créer et lire une table-dictionnaire avec t.nom et t["nom"], et la parcourir avec pairs ;
  • ajouter, modifier et supprimer des entrées (t.cle = nil), et modéliser des données réelles avec des tables imbriquées et mixtes ;
  • regrouper données et fonctions dans une même table pour en faire un objet ou un module ;
  • comprendre pourquoi la table est la fondation unique de tout en Lua.
Sommaire de la leçon

Dans la leçon précédente, tu as utilisé la table comme une liste : des valeurs rangées sous des indices 1, 2, 3…. Mais ce n'était que la moitié de l'histoire. En réalité, une table Lua est avant tout un dictionnaire : une collection de paires clé → valeur, où la clé peut être presque n'importe quoi. La séquence numérique n'est qu'un cas particulier de ce mécanisme plus général.

C'est le moment de bien saisir cette idée, parce qu'elle est centrale : en Lua, il n'existe qu'une seule structure de données composite, la table. Pas de classe, pas de struct, pas de dictionnaire séparé, pas de set. Tout — les objets, les modules, et bientôt les classes — se construit avec cet unique outil. Voyons comment.

Une table, des clés nommées

Au lieu d'indices, on associe à chaque valeur une clé de ton choix. La syntaxe la plus courante utilise des clés qui ressemblent à des noms de variables.

Remarque le dernier print : interroger une clé qui n'existe pas ne déclenche aucune erreur, Lua répond simplement nil. C'est une constante du langage — une clé absente et une clé valant nil, c'est exactement la même chose.

Deux syntaxes d'accès, équivalentes

Il existe deux façons de lire ou d'écrire une entrée. La notation pointée t.nom est un raccourci pour la notation entre crochets t["nom"] : les deux désignent la clé chaîne "nom".

Note

Quand utiliser quoi ? La notation pointée pour les clés fixes et lisibles écrites dans ton code (config.debug). Les crochets quand la clé est dans une variable (t[k]), ou qu'elle contient des caractères interdits pour un identifiant.

Des clés de tout type

Une clé n'est pas forcément une chaîne. Tu peux indexer une table par des nombres, des booléens, et même d'autres tables ou fonctions. Les seules clés interdites sont nil et le flottant NaN (le « pas-un-nombre », par exemple le résultat de 0/0).

Piège fréquent

Affecter nil à une clé ne la met pas « à vide » : ça la supprime. Et utiliser nil comme clé est une erreur : t[nil] = 1 lève table index is nil.

Ajouter, modifier, supprimer

Une table est vivante : on la fait grandir et rétrécir après sa création. Ajouter une clé, c'est simplement lui affecter une valeur. La supprimer, c'est lui affecter nil.

Il n'y a pas de fonction ajouter ou supprimer pour la partie dictionnaire : tout passe par l'affectation. C'est cette simplicité revendiquée qui fait que la table est partout.

Parcourir avec pairs

Pour visiter toutes les paires clé → valeur, on utilise la boucle générique for ... in pairs(t). À chaque tour, elle te donne une clé et sa valeur.

Piège fréquent

pairs ne respecte aucun ordre. Ne suppose jamais que les clés ressortiront dans l'ordre d'insertion ou alphabétique. Si tu as besoin d'un ordre, parcours une séquence numérique (ipairs ou for i = 1, #t), ou trie les clés à part.

À retenir : pairs traverse toute la table (clés chaînes, nombres, tout), alors que ipairs — vu à la leçon précédente — ne suit que la séquence 1, 2, 3… jusqu'au premier trou.

Tables imbriquées : modéliser le réel

La valeur associée à une clé peut être… une autre table. C'est ainsi qu'on représente des données structurées, comme un objet JSON.

On chaîne les accès : joueur.position.x lit la clé position (une table), puis la clé x dans cette table. Aucune limite de profondeur.

Tables mixtes : séquence + hachage

Rien n'interdit de mélanger, dans une même table, une partie séquence (indices 1, 2, 3…) et une partie hachage (clés nommées). Lua gère les deux côte à côte.

Note

L'opérateur # et ipairs ne voient que la partie séquence ; les clés nommées sont invisibles pour eux. Pour tout voir, il faut pairs.

La table comme objet, namespace et module

Puisqu'une clé peut valoir une fonction, on peut regrouper dans une même table des données et les fonctions qui les manipulent. C'est la première marche vers les objets et les modules de Lua.

La table geo joue ici le rôle de namespace : elle évite de polluer l'espace global et range proprement des fonctions liées. Quand tu écris string.upper ou table.insert, c'est exactement ce mécanisme — string et table sont des tables remplies de fonctions. Tu retrouveras ce motif tel quel dans la leçon sur les modules.

Cas réel

Quand un service en Lua (Redis, OpenResty, un jeu qui sauvegarde sa progression) échange du JSON, une bibliothèque comme cjson traduit chaque objet JSON en table-dictionnaire et chaque tableau JSON en séquence. D'où un piège célèbre : une table vide {} est ambiguë — cjson ne peut pas deviner si elle doit se réencoder en [] (tableau) ou en {} (objet), et choisit {} par défaut. Les API exposent donc une sentinelle (cjson.empty_array) pour lever le doute. Comprendre que « objet » et « tableau » sont la même table sous deux usages explique ce genre de surprise.

Pièges fréquents

  • Confondre clé absente et erreur. Lire une clé inexistante renvoie nil, jamais une exception. C'est à toi de tester si besoin.
  • "42" n'est pas 42. Une clé chaîne et une clé nombre de même apparence sont deux clés distinctes. Méfie-toi quand une clé vient d'une saisie texte.
  • Compter une table mixte avec #. #t ne mesure que la partie séquence ; les paires nommées ne sont jamais comptées. Pour les dénombrer, boucle avec pairs.
  • Attendre un ordre de pairs. L'ordre de parcours est imprévisible et peut changer d'une exécution à l'autre.

Pour aller plus loin

Pour aller plus loin

La fonction pairs s'appuie sur la primitive next(t, cle), qui renvoie la paire suivante de la table (et nil quand il n'y en a plus). next(t) sans deuxième argument donne la première paire ; si la table est vide, il renvoie directement nil — c'est d'ailleurs la façon idiomatique de tester une table vide : if next(t) == nil then ... end (car #t == 0 ignore la partie hachage). Plus tard, les métatables te permettront de personnaliser ce qui se passe quand une clé est absente.

Antisèche

Glossaire

Dictionnaire (table de hachage)
Une table vue comme une collection de paires clé → valeur, où la clé peut être de presque tout type. C'est la nature profonde de toute table Lua.
Clé / valeur
Dans t[k] = v, k est la clé (l'étiquette d'accès) et v la valeur associée. Une clé absente et une clé valant nil sont indiscernables.
Notation pointée
t.nom, sucre syntaxique pour t["nom"]. Réservée aux clés qui sont des identifiants valides.
pairs
Parcourt toutes les paires d'une table, dans un ordre non garanti (à opposer à ipairs, limité à la séquence).
next
La primitive derrière pairs : next(t) donne la première paire, next(t) == nil teste si la table est vide.
Table mixte
Une même table portant à la fois une partie séquence (indices 1, 2, 3…) et une partie hachage (clés nommées). # et ipairs n'en voient que la séquence.
Namespace / module
Une table qui regroupe des fonctions liées sous un nom (comme string ou table), pour ranger le code et éviter les globales.
NaN
Le flottant « pas-un-nombre » (p. ex. 0/0). Comme nil, il est interdit comme clé de table.

Récap et vérification

  • Une table est un dictionnaire de paires clé → valeur ; la séquence numérique n'en est qu'un cas particulier.
  • t.nom et t["nom"] sont équivalents ; les crochets sont obligatoires pour les clés variables ou non-identifiants.
  • Les clés peuvent être de presque tout type (sauf nil et NaN) ; "42" et 42 sont distinctes.
  • On ajoute/modifie par affectation, on supprime avec t.cle = nil.
  • pairs parcourt toute la table sans ordre garanti ; ipairs et # ne voient que la séquence.
  • Données + fonctions dans une même table = objet, namespace ou module : la fondation de tout en Lua.

Vérifie ta compréhension

  1. Quelle est la différence entre t.nom et t["nom"] ? Quand est-on obligé d'utiliser les crochets ?
  2. Que renvoie la lecture d'une clé absente, et comment supprime-t-on une clé existante ?
  3. Pourquoi ne faut-il pas se fier à l'ordre de parcours de pairs, et que vaut #t sur une table qui mélange séquence et clés nommées ?
