Module 1 · Les bases de Lua — Leçon 04

Fonctions et portée

~45 min Débutant Prérequis : leçon 3

À la fin de cette leçon, tu sauras

  • savoir déclarer une fonction avec local function et comprendre pourquoi la privilégier ;
  • savoir exploiter les retours multiples et les arguments variables (...) propres à Lua ;
  • savoir manipuler les fonctions comme des valeurs : les passer en argument, écrire des fonctions anonymes et des closures ;
  • comprendre la portée lexicale et éviter le piège des variables globales accidentelles.
Sommaire de la leçon

En Lua, la fonction n'est pas un mot-clé un peu à part : c'est une valeur, au même titre qu'un nombre ou une chaîne. Tu peux la ranger dans une variable, la passer en argument, la renvoyer depuis une autre fonction. Cette idée — les fonctions de première classe — est au cœur du style Lua, et elle explique pourquoi ce tout petit langage se glisse aussi bien dans les jeux, les outils et l'embarqué : avec une poignée de concepts, tu fais énormément.

Dans cette leçon, tu vas voir comment déclarer des fonctions proprement, exploiter les retours multiples et les arguments variables (deux particularités fortes de Lua), puis comprendre la portée lexicale et les fameuses closures. Au passage, on désamorce le piège n°1 du débutant en Lua : la variable globale créée par accident.

Déclarer une fonction : local function d'abord

La forme de base est function nom(params) ... end. Mais écrite telle quelle, elle crée une variable globale — visible partout dans le programme. En Lua idiomatique, on préfère presque toujours la version locale.

Écrire local function carre(...) est un raccourci pour local carre = function(...), avec un bonus : le nom carre est déjà déclaré avant le corps, ce qui rend la récursivité possible. Garde ce réflexe : tout est local sauf raison contraire.

Retours multiples : une particularité de Lua

Une fonction Lua peut renvoyer plusieurs valeurs d'un coup, sans tableau ni structure spéciale. Tu les listes après return, séparées par des virgules, et tu les récupères avec une affectation multiple.

Note

Beaucoup de fonctions standard exploitent ce mécanisme. Par exemple string.find renvoie l'indice de début et de fin : local i, j = string.find("hello", "ll") donne 3 et 4.

Attention à un détail : si tu places un appel à retours multiples au milieu d'une liste, Lua n'en garde que la première valeur. Seul un appel en dernière position « déroule » toutes ses valeurs.

Arguments variables : le vararg ...

Pour accepter un nombre quelconque d'arguments, déclare ... (trois points) comme dernier paramètre. À l'intérieur, ... représente tous les arguments surnuméraires.

Le piège de {...} : dès qu'un argument vaut nil, il crée un trou dans la table, et ipairs s'arrête à ce trou tandis que l'opérateur de longueur # devient peu fiable. Pour compter les arguments de façon sûre, nil compris, utilise select("#", ...) ou table.pack.

Les fonctions sont des valeurs

Puisqu'une fonction est une valeur, tu peux la stocker, la copier, la passer. C'est ce qui rend possible un style très souple, par exemple écrire un map maison qui applique une fonction à chaque élément.

Ici double est passée comme n'importe quelle donnée. La fonction map ne connaît rien de son contenu : elle se contente de l'appeler. C'est la base de la programmation par ordre supérieur.

Fonctions anonymes

Quand une fonction n'est utilisée qu'à un seul endroit, inutile de lui donner un nom. Tu peux l'écrire directement à la volée — c'est une fonction anonyme.

Closures et upvalues : le compteur

Une fonction Lua « capture » les variables locales visibles à l'endroit où elle est définie. Ces variables capturées s'appellent des upvalues, et la fonction qui les retient est une closure. Chaque closure garde sa propre upvalue vivante, même après la fin de la fonction englobante.

n n'est visible nulle part en dehors : c'est un état privé, conservé par la closure. C'est l'outil idiomatique en Lua pour encapsuler de l'état sans objet ni classe.

Cas réel

Un serveur web en OpenResty (nginx + Lua) doit attribuer un identifiant unique à chaque requête. Plutôt qu'une globale compteur (partagée, écrasable, source de collisions), on fabrique une closure : local nouvel_id = (function() local n = 0; return function() n = n + 1; return n end end)(). Le compteur n est privé, impossible à modifier de l'extérieur, et chaque module peut avoir le sien. C'est le patron « module à état privé » de Lua, bâti uniquement sur des closures — sans objet ni classe.

Portée lexicale et récursivité

La portée en Lua est lexicale : une fonction voit les variables locales déclarées avant elle dans le texte du programme (le bloc englobant), pas celles de l'endroit d'où on l'appelle. Cela rend la résolution des noms prévisible à la simple lecture.

Pour la récursivité, l'ordre de déclaration compte. local function déclare le nom avant le corps, donc la fonction peut s'appeler elle-même.

Note

Un appel en queue est un return f(...) où l'appel est la toute dernière action. Lua garantit qu'il ne consomme pas de pile supplémentaire : tu peux récurser un million de fois sans déborder, là où la factorielle classique — qui multiplie après l'appel — finirait par planter sur de très grandes valeurs.

Pièges fréquents

Piège fréquent

Oublier local crée une globale silencieuse. compteur = 0 dans une fonction pollue tout le programme et provoque des bugs difficiles à traquer (deux fonctions qui écrasent le même nom). Réflexe : déclare toujours local compteur = 0.

Piège fréquent

Un appel à retours multiples placé ailleurs qu'en dernière position est tronqué à une seule valeur. print(f(), "x") jette tout sauf le premier retour de f. Si tu veux toutes les valeurs, mets l'appel en dernier, ou range-les via table.pack(f()).

Pour aller plus loin

Pour aller plus loin

Les closures sont la fondation du « modèle objet » de Lua quand on veut de l'état privé sans tables ni métatables. Plus tard, tu verras que les méthodes sur tables (function obj:methode()) ne sont qu'une autre façon d'organiser des fonctions de première classe, avec un paramètre self implicite. Tout part d'ici.

Antisèche

Glossaire

Fonction de première classe
Une fonction est une valeur comme une autre : on peut la ranger dans une variable, la passer en argument, la renvoyer.
local function
Déclare une fonction locale ; le nom est visible dès le corps, ce qui permet la récursivité. À préférer à function f() (global).
Retours multiples
Une fonction peut renvoyer plusieurs valeurs (return a, b). Elles ne se déroulent toutes qu'en dernière position d'une liste.
Vararg (...)
Le paramètre spécial qui capte un nombre quelconque d'arguments ; on le compte sûrement avec select("#", ...) ou table.pack.
Fonction anonyme
Une fonction écrite sans nom, à la volée, souvent passée directement en argument (à table.sort, map…).
Closure
Une fonction qui capture des variables locales de son environnement ; elle conserve cet état privé même après la fin de la fonction englobante.
Upvalue
Une variable locale capturée par une closure. Chaque closure possède ses propres upvalues, indépendantes des autres.
Appel en queue (tail call)
Un return f(...) où l'appel est la toute dernière action : Lua réutilise la pile, permettant une récursion illimitée sans débordement.

Récap et vérification

  • local function par défaut : évite les globales et permet la récursivité.
  • Une fonction peut renvoyer plusieurs valeurs ; seul un appel en dernière position déroule tous ses retours.
  • ... capte les arguments variables ; compte-les avec select("#", ...) ou table.pack pour gérer les nil.
  • Les fonctions sont des valeurs : stockables, passables en argument, anonymes possibles.
  • Une closure capture des upvalues et conserve un état privé ; la portée est lexicale.

Vérifie ta compréhension

  1. Pourquoi privilégie-t-on local function f() plutôt que function f() ?
  2. Que vaut le deuxième résultat affiché par print(diviser(17, 5), "fin") et pourquoi le reste disparaît-il ?
  3. Dans le compteur, où est stocké n et pourquoi c1 et c2 ne se marchent-ils pas dessus ?
