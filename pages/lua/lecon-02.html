Module 1 · Les bases de Lua — Leçon 02

Types, variables et chaînes

~45 min Débutant Prérequis : leçon 1

À la fin de cette leçon, tu sauras

  • citer les 8 types de Lua et utiliser type(x) pour les inspecter ;
  • déclarer des variables avec local et comprendre que toute variable non définie vaut nil ;
  • appliquer la règle de vérité de Lua (seuls nil et false sont faux) ;
  • construire et transformer des chaînes avec .. et la bibliothèque string.
Sommaire de la leçon

Lua est un tout petit langage : huit types, un seul mot-clé pour déclarer une variable, une seule structure de données. Cette économie est revendiquée — c'est ce qui rend Lua si rapide à charger et si facile à glisser dans un jeu, un serveur ou une puce embarquée. Mais cette simplicité cache quelques surprises qui piègent tous les débutants venus d'un autre langage.

Dans cette leçon, tu vas faire le tour des types de Lua, apprendre à déclarer proprement tes variables, comprendre la règle de vérité (qui n'est pas celle que tu crois) et manipuler les chaînes de caractères. Chaque exemple montre sa sortie en commentaire --, pour que tu suives le raisonnement ligne à ligne.

Les huit types de Lua

Lua ne connaît que huit types de valeurs. C'est tout. Tu peux interroger le type d'une valeur avec la fonction type, qui renvoie une chaîne.

Les deux derniers — userdata et thread — sont plus rares. userdata représente des données venues de C (un objet exposé par le programme hôte qui embarque Lua), et thread désigne une coroutine. Tu les croiseras plus tard ; pour l'instant, retiens les six premiers, et surtout que la table est la seule structure de données du langage (listes, dictionnaires, objets : tout passe par elle).

Note

Les valeurs ont un type, pas les variables. Une même variable peut recevoir un nombre, puis une chaîne, puis une table sans la moindre erreur. Lua est dynamiquement typé.

Déclarer une variable : toujours local

En Lua, si tu écris simplement x = 10, tu crées une variable globale, visible partout dans le programme. C'est rarement ce que tu veux : les globales polluent l'espace de noms, ralentissent l'accès et provoquent des collisions sournoises. La règle d'or de la communauté Lua tient en un mot : local.

Tu peux déclarer plusieurs variables d'un coup, et même les affecter en parallèle. Lua évalue d'abord toutes les valeurs de droite, puis les distribue : l'échange de deux variables sans temporaire en découle directement.

Astuce

Prends l'habitude de taper local par réflexe, comme une ponctuation. Quand tu n'en mets pas, c'est que tu veux explicitement une globale — un cas qui se compte sur les doigts d'une main.

nil : l'absence de valeur

nil est le type de l'absence. Une variable qui n'a jamais reçu de valeur ne déclenche pas d'erreur quand tu la lis : elle vaut tout simplement nil. C'est une différence majeure avec les langages qui hurlent « variable non définie ».

Ce comportement est pratique mais traître : une faute de frappe dans un nom de variable ne plante pas, elle renvoie silencieusement nil. Et utiliser cette valeur plus loin, par exemple nil + 1, produira l'erreur à un endroit éloigné de la vraie cause.

number : un seul type, deux sous-formes

Lua n'a qu'un seul type numérique, number. Pas de distinction visible entre entiers et flottants à l'usage courant — tu écris des nombres, point. Depuis Lua 5.4, le moteur distingue toutefois en interne un sous-type integer et un sous-type float, ce que tu peux voir avec math.type.

Retiens deux opérateurs qui surprennent : / donne toujours un float (même 4 / 2 vaut 2.0), tandis que // est la division entière. Pour le reste, l'arithmétique est classique : +, -, *, % (modulo) et ^ (puissance).

La vérité en Lua : seuls nil et false sont faux

Voici le piège le plus fréquent pour qui arrive d'un autre langage. En Lua, dans un test, seules deux valeurs sont fausses : nil et false. Tout le reste est vrai, y compris 0 et la chaîne vide "".

Piège fréquent

Si tu viens de C, Python ou JavaScript, ton réflexe « 0 est faux » est faux ici. Pour tester qu'un nombre vaut zéro, écris explicitement if n == 0 then — n'écris jamais if not n then en croyant attraper le zéro.

Cas réel

Dans un jeu écrit avec Love2D (moteur 2D en Lua), un développeur code if joueur.mana then lancer_sort() end pour n'autoriser le sort que si le joueur a du mana. Le bug : quand la réserve est vide, joueur.mana vaut 0… et 0 est vrai en Lua. Le sort part quand même et le mana passe en négatif. Le test correct est if joueur.mana > 0 then. Ce piège vient tout droit des réflexes venus du C ou de JavaScript, où 0 est faux.

Les opérateurs logiques se nomment and, or et not (pas && ni ||). Et ils ne renvoient pas un booléen, mais l'une des opérandes — ce qui permet l'idiome classique de valeur par défaut.

Les chaînes de caractères

Une chaîne se délimite avec des guillemets simples ou doubles, au choix (les deux sont strictement équivalents). Pour un texte sur plusieurs lignes, ou contenant des guillemets, utilise les doubles crochets [[ ... ]].

La concaténation se fait avec l'opérateur .. (deux points), jamais avec +. L'opérateur + est réservé à l'arithmétique ; l'utiliser sur des chaînes provoque une erreur (sauf si elles contiennent des nombres, que Lua tente alors de convertir).

L'opérateur # donne la longueur d'une chaîne (en octets), et la bibliothèque string regroupe les fonctions de manipulation. Les plus courantes : string.upper, string.sub (extrait une portion), string.find, string.gsub (remplace) et string.format (formate).

Note

Comme pour les indices de table, les positions de chaîne commencent à 1, pas à 0. string.sub(s, 1, 1) donne le premier caractère. Tu peux aussi écrire s:upper() à la place de string.upper(s) : c'est la même chose, en notation « méthode ».

Convertir entre nombres et chaînes

Lua ne convertit pas tout automatiquement. Pour passer d'une chaîne à un nombre, utilise tonumber ; pour l'inverse, tostring. tonumber renvoie nil si la conversion échoue, ce qui en fait un bon outil de validation.

Pièges fréquents

  • Oublier local. Sans lui, tu crées une globale silencieuse qui peut entrer en collision ailleurs. Mets local par défaut.
  • Croire que 0 ou "" sont faux. Non : seuls nil et false le sont. Teste explicitement avec == 0 ou == "".
  • Concaténer avec +. Pour coller des chaînes, c'est ... Le + est arithmétique uniquement.
  • Une faute de frappe sur un nom de variable ne plante pas : elle renvoie nil, et l'erreur surgit plus loin. Relis tes noms.
  • Compter à partir de 0 dans string.sub ou les indices : en Lua, tout commence à 1.

Pour aller plus loin

Pour aller plus loin

La fonction string.find accepte des motifs (patterns), un mini-langage de recherche propre à Lua, plus simple que les expressions régulières mais très efficace. De même, string.format reprend la syntaxe de printf en C. Tu exploreras les deux en détail dans le module dédié aux chaînes ; pour l'heure, garde en tête qu'ils existent et qu'ils couvrent l'essentiel des besoins de manipulation de texte.

type(x)

L'ensemble des fonctions de manipulation de texte (upper, sub, find, gsub, format), utilisables aussi en notation méthode s:upper().

Récap et vérification

  • Lua a huit types : nil, boolean, number, string, table, function, userdata, thread — et la table est la seule structure de données.
  • On déclare avec local, toujours ; une variable non définie vaut nil sans erreur.
  • number est unique, mais 5.4 distingue integer et float (/ donne un float, // un entier).
  • Seuls nil et false sont faux ; 0 et "" sont vrais.
  • On concatène avec .., on mesure avec #, on manipule avec la bibliothèque string, on convertit avec tonumber / tostring.

Vérifie ta compréhension

  1. Que renvoie type pour la valeur {}, et pourquoi ce type est-il central en Lua ?
  2. Le test if "" then ... end exécute-t-il son bloc ? Justifie.
  3. Quelle est la différence entre 10 / 2 et 10 // 2, tant sur la valeur que sur le sous-type ?
  4. Quel opérateur colle deux chaînes, et que se passe-t-il si tu utilises + à la place ?
