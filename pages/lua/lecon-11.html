Module 3 · Lua en pratique — Leçon 11

Lua embarqué et écosystème

~50 min Intermédiaire Prérequis : leçon 10

À la fin de cette leçon, tu sauras

  • comprendre pourquoi et comment Lua est embarqué dans un programme hôte (C/C++) via la pile et l'API C ;
  • expliquer ce qui rend Lua idéal pour ce rôle : petit, rapide, sandboxable ;
  • situer Lua dans son écosystème réel (Roblox/Luau, WoW, Love2D, Neovim, Redis, OpenResty) et savoir ce qu'apporte LuaJIT ;
  • reconnaître que l'API disponible dépend de l'hôte et non du langage lui-même.
Sommaire de la leçon

Jusqu'ici, tu as appris à écrire des scripts Lua autonomes, lancés depuis un terminal avec lua mon_script.lua. Mais ce n'est pas là que Lua brille le plus. Son vrai super-pouvoir, celui qui explique pourquoi un si petit langage est partout, c'est d'être embarqué : glissé à l'intérieur d'un autre programme, écrit en C ou C++, qui lui délègue toute la partie « logique de jeu », « configuration » ou « personnalisation par l'utilisateur ».

Dans cette leçon, on prend de la hauteur. On ne va pas écrire de C — rassure-toi — mais comprendre conceptuellement comment Lua s'imbrique dans un hôte, pourquoi ça marche si bien, et où tu croises déjà Lua sans le savoir : Roblox, World of Warcraft, Neovim, Redis, nginx. À la fin, tu auras une carte de l'écosystème et un plan pour continuer.

Pourquoi embarquer un langage ?

Imagine que tu écris un jeu en C++. Le moteur — affichage, physique, son — doit être ultra-rapide : C++ est parfait. Mais le contenu du jeu (le comportement d'un monstre, le déroulé d'une quête, l'équilibrage des dégâts) change tous les jours pendant la production. Recompiler tout le moteur C++ à chaque ajustement de gameplay, c'est des minutes perdues à chaque fois.

La solution : écrire le moteur en C++ une fois, et écrire le gameplay en scripts Lua qu'on peut modifier et recharger à chaud, sans recompiler. Le moteur C++ est l'hôte ; Lua est le langage invité.

Ce script suppose que l'hôte a exposé spawn_enemy à Lua. C'est tout l'enjeu de la suite : comment les deux mondes se parlent.

La pile Lua/C : comment les deux mondes se parlent

Lua et C n'ont pas la même façon de stocker les valeurs. Pour échanger sans se marcher dessus, ils utilisent un intermédiaire : une pile (stack). C'est un tableau de valeurs partagé. Quand le C veut appeler une fonction Lua, il empile la fonction puis ses arguments, déclenche l'appel, et récupère les résultats au sommet de la pile. Et inversement.

Ce qui rend Lua parfait pour l'embarqué

Pourquoi Lua plutôt que Python ou JavaScript pour ce rôle ? Trois raisons reviennent toujours :

  • Petit : l'interpréteur compilé pèse quelques centaines de kilo-octets. Il tient sur un microcontrôleur, dans un jeu mobile, dans un binaire embarqué.
  • Rapide : Lua est l'un des langages interprétés les plus rapides, et avec LuaJIT (on y vient) il rivalise avec du code compilé.
  • Sandboxable : on peut donner à un script Lua un environnement restreint, où il n'a accès qu'aux fonctions qu'on choisit. Indispensable quand des inconnus (les joueurs, les modders) écrivent du code qui tournera chez tout le monde.

On reparlera de load et des environnements dans une leçon dédiée ; retiens ici l'idée : l'hôte contrôle exactement ce que le script peut toucher.

Astuce

Le quatrième argument de load (ici bac_a_sable) est l'environnement global vu par le code chargé. Le troisième, "t", force le mode « texte seul » : on interdit le bytecode précompilé, qui pourrait contourner la sandbox. Pour exécuter du code venu de l'extérieur, garde toujours ce "t".

Le tour de l'écosystème : où tu croises déjà Lua

Une fois qu'on sait reconnaître Lua embarqué, on le voit partout. Petit tour des hôtes les plus connus.

Roblox / Luau — La plateforme de jeux Roblox laisse des millions de créateurs écrire la logique de leurs jeux en Luau, un dialecte de Lua avec typage graduel. C'est sans doute aujourd'hui le plus grand vivier de développeurs Lua au monde.

World of Warcraft — Les fameux addons du jeu sont du Lua. L'interface entière est scriptable : barres de sort, alertes de raid, inventaires améliorés… tout passe par une API Lua exposée par Blizzard.

Love2D — Un framework adoré pour faire des jeux 2D. Tu écris uniquement du Lua, le framework (en C) gère le reste. La structure tient en quelques fonctions de rappel (callbacks) que le moteur appelle pour toi :

Neovim — L'éditeur se configure et s'étend désormais en Lua (le fichier init.lua), avec une API native rapide. Des centaines de plugins modernes sont écrits en Lua.

Redis — La base de données en mémoire permet d'exécuter des scripts Lua côté serveur, de façon atomique, pour faire en un aller-retour ce qui demanderait plusieurs commandes.

nginx / OpenResty — OpenResty embarque LuaJIT dans le serveur web nginx : on programme la logique de requêtes (authentification, routage, limites de débit) en Lua, au cœur d'un des serveurs les plus rapides du monde.

Cas réel

Un usage très concret côté serveur : la limite de débit (rate limiting) dans Redis. Pour empêcher qu'une même adresse IP fasse mille requêtes par seconde, on veut « lire un compteur, l'incrémenter, le rejeter s'il dépasse le seuil » — le tout sans qu'une autre requête ne s'intercale au milieu. LuaJIT : quand Lua devient (très) rapide

LuaJIT est une implémentation alternative de Lua avec un compilateur « juste-à-temps » (Just-In-Time). Au lieu d'interpréter le code, il le traduit en instructions machine natives pendant l'exécution, pour les portions les plus sollicitées. Le résultat : des performances proches du C sur du code numérique intensif.

Note

Le même fichier .lua tourne sur l'interpréteur standard et sur LuaJIT : tu n'as rien à changer pour gagner en vitesse. Une nuance : LuaJIT est resté largement aligné sur Lua 5.1, donc quelques nouveautés de 5.4 (comme les entiers natifs ou l'opérateur //) n'y sont pas ; on en reparlera si besoin.

Panorama emploi : où Lua paie

Lua est rarement le langage principal d'une offre d'emploi, mais c'est souvent le détail qui fait la différence. Trois grands domaines :

  • Jeux vidéo : studios utilisant Lua pour le gameplay (avec un moteur C++), écosystème Roblox, jeux indépendants en Love2D.
  • Embarqué et réseau : objets connectés, équipements réseau, OpenResty/nginx, Redis. Lua y est apprécié pour sa légèreté.
  • Outils et infrastructure : configuration et plugins (Neovim, Wireshark, gestionnaires de paquets), extension d'applications existantes.

Dans tous les cas, le profil recherché sait écrire du Lua propre et comprendre comment il s'intègre à un hôte. C'est exactement ce que tu construis depuis le début de ce cours.

Pièges fréquents

Piège fréquent

Croire que « Lua » est partout le même. L'API disponible dépend de l'hôte : dans WoW tu as CreateFrame, dans Love2D tu as love.graphics, dans Neovim tu as vim.api. Le langage est identique ; les fonctions exposées changent du tout au tout. Lis toujours la doc de l'hôte concerné.

Piège fréquent

Dans un environnement sandboxé, des fonctions que tu crois acquises peuvent manquer. Un script de raid WoW ne peut pas faire io.open pour écrire un fichier : l'hôte a coupé l'accès au système pour des raisons de sécurité. Si os ou io sont absents, ce n'est pas un bug : c'est voulu.

Pour aller plus loin

Pour aller plus loin

Si l'embarqué t'attire, le livre Programming in Lua (de Roberto Ierusalimschy, le créateur de Lua) consacre toute une partie à l'API C : pile, fonctions exposées, gestion mémoire. Pour pratiquer sans C, installe Love2D et fais bouger un cercle à l'écran en dix minutes : c'est la porte d'entrée la plus agréable vers Lua « en situation ».

Antisèche

Glossaire

Embarqué (embedded)
Lua exécuté à l'intérieur d'un autre programme plutôt que lancé seul : l'hôte lui délègue une partie de la logique.
Hôte / invité
L'hôte est le programme d'accueil (souvent en C/C++) ; l'invité est l'interpréteur Lua qu'il embarque et pilote.
Pile Lua/C
Le tableau de valeurs partagé par lequel le C et Lua échangent : on y empile arguments et fonction, on en dépile les résultats.
API C
Le petit jeu de fonctions C (lua_getglobal, lua_pushnumber, lua_call…) qui permet à l'hôte de dialoguer avec Lua.
Sandbox
Environnement restreint donné à un script : il ne voit que les fonctions choisies par l'hôte. Indispensable pour exécuter du code d'inconnus.
LuaJIT
Implémentation alternative de Lua avec compilation juste-à-temps : des performances proches du C sans modifier le code (restée alignée sur Lua 5.1).
JIT (just-in-time)
Traduction du code en instructions machine pendant l'exécution, ciblant les portions les plus sollicitées.
Luau
Le dialecte de Lua créé par Roblox, avec typage graduel ; sans doute le plus grand vivier de développeurs Lua aujourd'hui.

Récap et vérification

Cette leçon clôt ta vision d'ensemble de Lua. Récapitulons le chemin parcouru depuis le début du cours : tu es parti des valeurs et de nil, tu as découvert la table comme unique structure de données (avec ses indices qui commencent à 1), les fonctions et les closures, la gestion d'erreurs avec pcall, et la programmation objet par tables et métatables. Et te voilà capable de situer Lua dans le monde réel.

  • Lua brille surtout embarqué dans un programme hôte (C/C++).
  • Les deux mondes échangent via une pile partagée et une petite API C.
  • Lua est choisi parce qu'il est petit, rapide et sandboxable.
  • On le croise dans Roblox/Luau, WoW, Love2D, Neovim, Redis, OpenResty.
  • LuaJIT apporte des performances proches du C, sans changer ton code.
  • L'API disponible dépend toujours de l'hôte, pas du langage.

Vérifie ta compréhension

  1. Pourquoi un studio écrirait-il son moteur en C++ mais son gameplay en Lua ?
  2. À quoi sert la « pile » dans la communication entre Lua et le programme hôte ?
  3. Cite deux raisons qui font de Lua un bon choix pour être embarqué, et explique ce qu'apporte le sandboxing.
  4. Le même fichier .lua donne-t-il accès aux mêmes fonctions dans WoW et dans Neovim ? Pourquoi ?
