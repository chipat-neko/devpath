NoSQL : les bases de données non relationnelles

Quand le relationnel atteint ses limites — à très grande échelle, avec des données variées —, les bases NoSQL prennent le relais. Ce cours transversal, complément du cours SQL, t'explique pourquoi elles existent, leurs familles (document, clé-valeur, colonnes, graphe), et surtout laquelle choisir.

Bien s'équiper

Les extensions VS Code pour les bases NoSQL

Avant de te lancer, ouvre le panneau Extensions de VS Code (Ctrl+Shift+X) et installe ces incontournables : ils permettent d'explorer et d'interroger tes bases depuis l'éditeur.

À installer pour le NoSQL

  • MongoDB for VS Code (MongoDB) — explorer et interroger MongoDB.
  • Database Client (cweijan) — Redis, MongoDB et autres en un endroit.
  • Prettier - Code formatter (Prettier) — mise en forme des documents JSON.
  • YAML (Red Hat) — pour les fichiers de configuration.

Pour qui ?

Idéal après le cours SQL : le NoSQL se comprend par contraste avec le relationnel. Le cours Formats de données (JSON) aide aussi, puisque les documents sont du JSON. Aucune base à installer : on apprend les concepts.

Ce que tu vas apprendre

Comprendre, comparer, choisir

À la fin du cours, tu sauras

  • expliquer pourquoi le NoSQL existe (échelle, schéma flexible, scalabilité horizontale) ;
  • comparer SQL et NoSQL via ACID, BASE et le théorème CAP ;
  • reconnaître les quatre familles : document, clé-valeur, colonnes, graphe ;
  • modéliser par les requêtes et choisir la bonne base (persistance polyglotte).

Pour qui, et pourquoi

Le NoSQL fait partie du paysage de toute application moderne à l'échelle : réseaux sociaux, e-commerce, objets connectés, cache, recommandations. Savoir quand et comment l'employer — sans tomber dans la mode ni le rejet — est une compétence recherchée, qui complète la maîtrise du SQL.

Ce cours est conceptuel et indépendant d'un produit : on cite MongoDB, Redis, Cassandra, Neo4j en exemples, mais l'objectif est de comprendre les modèles et les compromis, transférables à n'importe quelle base.
