Projet de synthèse — un inventaire de bout en bout

~55 min Avancé Synthèse de tout le cours

À la fin de cette leçon, tu sauras

  • modéliser un domaine avec data class et sealed interface ;
  • décoder du JSON en objets Kotlin avec kotlinx.serialization ;
  • analyser une collection avec les lambdas (sumOf, groupBy, maxByOrNull) ;
  • gérer l'échec avec un résultat typé et un when exhaustif.
Sommaire de la leçon

Voici le moment de tout assembler. Nous allons construire un petit gestionnaire d'inventaire qui lit des produits au format JSON, calcule quelques statistiques, et renvoie soit un rapport, soit une erreur — proprement typée. En moins de cinquante lignes, ce projet mobilise l'essentiel du cours : data class, sealed interface, null-safety, lambdas de collection, @Serializable et when exhaustif.

Le cahier des charges

Le programme reçoit un texte JSON (comme s'il venait d'une API ou d'un fichier). Il doit : décoder la liste de produits, calculer la valeur totale du stock, le total par catégorie et le produit le plus cher, puis rapporter le résultat — ou une erreur claire si le JSON est invalide. Voici le trajet des données :

Modéliser : data class + sealed interface

On commence par les données. Un Produit est une data class sérialisable, avec une propriété calculée valeur. Le résultat de l'analyse est une sealed interface à deux cas — succès ou erreur — ce qui obligera le when à traiter les deux.

La valeur par défaut categorie = "divers" rend la lecture tolérante (leçon 19) ; la sealed interface (leçon 9) garantit que le when couvrira tous les cas — sans else fourre-tout.

Analyser avec des lambdas

Le cœur du programme est une fonction pure : elle prend une liste et renvoie un Rapport, sans rien afficher ni modifier. On y retrouve le trio sumOf, groupBy et maxByOrNull (leçons 5 à 7).

Charger — et gérer l'échec

La coquille entoure la logique pure : elle décode le JSON (opération qui peut échouer) et traduit tout problème en Resultat.Erreur plutôt qu'en plantage. Le main déballe le résultat avec un when, forcément exhaustif.

Remarque le ?.nom ?: "—" (leçon 2) : si le stock est vide, plusChere vaut null et l'on affiche un tiret plutôt que de planter. Chaque brique du cours joue ici son rôle exact.

Astuce

Sépare toujours le pur de l'impur : analyser ne fait aucune entrée-sortie, chargerEtAnalyser concentre le décodage et les erreurs, main concentre l'affichage. Tu peux ainsi tester analyser avec une simple List<Produit>, sans JSON ni fichier.

Attention

Un when sur une sealed interface utilisé comme expression (à droite d'un = ou d'un return) est vérifié comme exhaustif par le compilateur : ajouter un cas Resultat et oublier de le traiter devient une erreur de compilation, pas un bug silencieux. C'est tout l'intérêt des types scellés.

Un cas réel

Cas réel — la forme d'un vrai client d'API

Cette structure minuscule est exactement celle d'un vrai client mobile ou serveur. Une application de e-commerce reçoit du JSON depuis son API : elle le décode en data class (@Serializable), calcule des agrégats avec des lambdas (total du panier, remises par catégorie), et représente les réponses par une sealed — Chargement, Succes, Erreur — que l'interface consomme avec un when. Le résultat : pas de valeur ambiguë, pas d'exception non gérée qui remonte jusqu'à l'écran, et un cœur de logique testable sans réseau. En Kotlin Multiplateforme (leçon 20), ce même cœur est partagé tel quel entre Android et iOS. Ce que tu viens d'écrire est un modèle réduit — mais fidèle — de la production.

Pour aller plus loin

Pour aller plus loin

Fais grandir le projet : charge le JSON depuis un vrai fichier ou une API avec Ktor ; rends le chargement suspend et observe l'inventaire avec un Flow (leçons 13 et 17) ; persiste le stock avec SQLDelight ; écris des tests de analyser avec kotlin.test (leçon 16) ; expose une petite DSL de construction d'inventaire (leçon 18). Chaque brique du cours a sa suite naturelle.

Glossaire

Projet de synthèse
Exercice final qui réunit les notions d'un cours dans un programme cohérent et complet.
Fonction pure
Fonction dont le résultat ne dépend que de ses arguments et qui ne produit aucun effet de bord : facile à tester.
Propriété calculée
Propriété sans champ de stockage, définie par un get() (ici valeur = prix * quantite).
sealed interface
Interface dont toutes les implémentations sont connues : un when les couvre toutes, sans else.
when exhaustif
when utilisé comme expression sur un type scellé : le compilateur exige que tous les cas soient traités.
groupBy
Fonction de collection regroupant les éléments par clé, produisant une Map<K, List<T>>.
maxByOrNull
Renvoie l'élément qui maximise un critère, ou null si la collection est vide.
decodeFromString<T>
Reconstruit un objet (ou une List<T>) typé à partir d'un texte JSON.

Récap et vérification

  • Le domaine se modélise avec data class (les données) et sealed interface (les résultats possibles).
  • Le JSON se décode en objets avec @Serializable et decodeFromString<List<Produit>>.
  • L'analyse s'écrit avec des lambdas pures : sumOf, groupBy/mapValues, maxByOrNull.
  • L'échec devient une valeur (Resultat.Erreur), déballée par un when exhaustif — pas d'exception qui remonte.

Vérifie ta compréhension

  1. Pourquoi représenter le résultat par une sealed interface plutôt que par un booléen + un message ?
  2. Quelle expression décode une liste de produits depuis un texte JSON ?
  3. Comment obtenir le total de valeur par catégorie en deux étapes ?

Exercices

Exercice 1Échauffement

Écris une fonction nbArticles(stock: List<Produit>): Int qui renvoie la somme des quantite de tous les produits.

Voir une solution

sumOf accepte une projection Int et renvoie un Int — ici la quantité de chaque produit.

Exercice 2Application

Écris categorieLaPlusRiche(stock: List<Produit>): String? qui renvoie la catégorie dont le total de valeur est le plus élevé (ou null si le stock est vide).

Voir une solution

On regroupe, on totalise chaque groupe, on prend l'entrée la plus haute, puis ?.key en extrait la catégorie — null si la Map est vide.

Exercice 3Défi

Modifie chargerEtAnalyser pour renvoyer Resultat.Erreur("stock vide") lorsque la liste décodée est vide, sans lever d'exception.

Voir une solution

Le cas « liste vide » n'est pas une exception : c'est une règle métier, donc on la traduit en Resultat.Erreur explicite, comme les autres échecs.

Mini-projet fil rouge — un inventaire

Pour clore ce cours, écrivons un petit inventaire. Il réunit une data class, une fonction à expression unique, une liste (listOf), la boucle for, les gabarits de chaîne et une fonction d'ordre supérieur (sumOf) — un condensé de Kotlin idiomatique.

Ce que tu vas construire

Une data class Produit (nom, prix, quantité) avec une méthode valeur(), une liste de produits, et le total du stock calculé avec sumOf.

Étapes

La data class Produit

Déclare data class Produit(val nom: String, val prix: Double, val quantite: Int).

Une méthode valeur

Ajoute fun valeur(): Double = prix * quantite (fonction à expression unique).

Une liste de produits

Construis le stock avec listOf(...).

Parcourir

Affiche chaque produit avec une boucle for et un gabarit "${p.nom}".

Le total

Calcule le total avec stock.sumOf { it.valeur() }.
