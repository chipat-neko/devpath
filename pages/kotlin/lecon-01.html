Module 1 · Les bases de Kotlin — Leçon 01

Découvrir Kotlin

~40 min Débutant Prérequis : bases de la programmation

À la fin de cette leçon, tu sauras

  • savoir situer Kotlin face à Java et expliquer pourquoi Google en a fait le langage officiel d'Android ;
  • savoir écrire et lire un premier programme avec fun main() et println ;
  • savoir déclarer des variables avec val et var en t'appuyant sur l'inférence de type ;
  • savoir compiler un fichier .kt avec kotlinc et appliquer les conventions de nommage officielles.
Sommaire de la leçon

Si tu as déjà écrit du Java, tu connais cette sensation : dix lignes de cérémonie pour afficher une phrase. Kotlin part d'un constat simple — on peut garder toute la puissance de la JVM et la sécurité d'un typage fort, mais en écrivant beaucoup moins de code rituel. C'est exactement ce que ce cours va te montrer, leçon après leçon.

Dans cette première leçon, on plante le décor : d'où vient Kotlin, pourquoi Google l'a adopté pour Android, comment l'essayer en trente secondes, et à quoi ressemble un premier programme. Tu vas aussi rencontrer deux mots-clés que tu utiliseras des milliers de fois : val et var.

Pourquoi Kotlin existe

Kotlin est né en 2011 chez JetBrains, l'éditeur d'IntelliJ IDEA. L'entreprise écrivait des millions de lignes de Java et voulait un langage plus expressif, plus sûr, mais qui reste 100 % interopérable avec l'écosystème Java existant : pas question de jeter vingt ans de bibliothèques. Le nom vient d'une île près de Saint-Pétersbourg — un clin d'œil à Java, qui est aussi le nom d'une île.

Le tournant a lieu en 2017 : Google annonce que Kotlin devient langage officiel pour Android, puis recommande en 2019 une approche « Kotlin first » — les nouvelles API Android sont pensées pour Kotlin d'abord. Aujourd'hui, la grande majorité des applications Android du top 1000 contiennent du Kotlin.

Techniquement, Kotlin compile vers du bytecode JVM : le même format que Java, exécuté par la même machine virtuelle. Une classe Kotlin peut appeler une classe Java et inversement, sans pont ni adaptateur. Et ce n'est pas tout : avec Kotlin Multiplatform, le même code peut aussi cibler iOS, le navigateur (JavaScript/Wasm) ou du natif — on en reparlera, mais retiens que la JVM n'est qu'une cible parmi d'autres.

Tout ce qui a disparu — la classe obligatoire, public static, le paramètre args dont tu ne te sers pas, le point-virgule — n'apportait aucune information. Kotlin appelle ça réduire le boilerplate : le code rituel qu'on recopie sans réfléchir. Au-delà de la concision, Kotlin ajoute des garanties que Java n'a pas, en premier lieu la null-safety : le compilateur distingue les valeurs qui peuvent être null de celles qui ne le peuvent pas, et t'empêche dès la compilation de provoquer la fameuse NullPointerException. On y consacrera une leçon entière.

Essayer Kotlin : trois options

Tu n'as rien à installer pour suivre cette leçon : ouvre play.kotlinlang.org, le bac à sable officiel. Tu tapes ton code, tu l'exécutes, c'est tout.

Pour travailler sérieusement, deux options s'offrent à toi :

  • IntelliJ IDEA (Community Edition, gratuite) : l'IDE de JetBrains embarque Kotlin nativement. Crée un nouveau projet, choisis Kotlin, et tu es prêt. C'est le choix recommandé pour ce cours.
  • kotlinc, le compilateur en ligne de commande, installable via SDKMAN!, Homebrew ou les archives GitHub. Pratique pour comprendre ce qui se passe sous le capot — on s'en sert un peu plus bas.

Astuce

Le playground en ligne suffit largement pour tout le premier module. Installe IntelliJ quand on attaquera les projets multi-fichiers : tu profiteras de l'autocomplétion et des suggestions du compilateur en direct.

Trois détails à noter :

  • pas de point-virgule en fin de ligne : il est autorisé mais inutile, et les conventions officielles demandent de l'omettre ;
  • si tu as besoin des arguments de la ligne de commande, tu peux écrire fun main(args: Array<String>) — mais quand tu ne t'en sers pas, la version sans paramètre est la forme idiomatique.

val et var : l'immuable d'abord

Kotlin propose deux mots-clés pour déclarer une variable. val (pour value) déclare une référence immuable : une fois affectée, elle ne peut plus être réassignée. var (pour variable) déclare une référence mutable, réassignable à volonté.

La règle idiomatique est simple : val par défaut, et var uniquement quand la valeur doit vraiment changer. Moins une donnée peut bouger, moins il y a d'états possibles à garder en tête — et plus le compilateur peut t'aider. Quand IntelliJ voit un var jamais réassigné, il te suggère d'ailleurs de le transformer en val.

Tu as peut-être remarqué qu'aucun type n'apparaît dans ces déclarations. C'est l'inférence de type : le compilateur déduit le type à partir de la valeur. La variable est bel et bien typée — statiquement, fortement — mais tu n'as pas besoin de l'écrire quand c'est évident :

Note

Inférence ne veut pas dire typage dynamique. Contrairement à JavaScript ou Python, le type est figé à la compilation : après val ville = "Lyon", écrire ville = 42 serait refusé pour deux raisons (réassignation d'un val et type incompatible). Tu gardes toute la sécurité de Java, sans la verbosité.

De .kt au bytecode JVM

Que se passe-t-il quand tu exécutes ton code ? Le compilateur kotlinc transforme ton fichier .kt en bytecode JVM — des fichiers .class, exactement comme ceux produits par javac. La JVM les exécute sans savoir (ni se soucier) qu'ils viennent de Kotlin. Tu peux le faire toi-même en ligne de commande :

L'option -include-runtime embarque la bibliothèque standard de Kotlin dans le jar, pour qu'il soit exécutable seul avec java -jar.

C'est cette compilation vers un format commun qui rend l'interopérabilité si naturelle : côté JVM, du Kotlin et du Java compilés sont indistinguables. Dans un vrai projet, tu ne taperas pas ces commandes à la main — un outil de build comme Gradle s'en charge — mais savoir ce qu'elles font t'évitera de voir la chaîne de compilation comme de la magie.

Les conventions qui comptent dès le premier fichier

Kotlin a un guide de style officiel, et l'écosystème le suit de près. Trois règles suffisent pour démarrer du bon pied :

  • camelCase pour les fonctions, variables et propriétés : compteurEssais, calculerTotal() ;
  • PascalCase pour les types (classes, interfaces, objets) : CompteBancaire, HttpClient ;
  • indentation de 4 espaces, jamais de tabulations — et pas de point-virgule.

Pièges fréquents

Piège fréquent

Croire que val rend l'objet entièrement figé. val empêche la réassignation de la référence, pas la modification de l'objet pointé : un val liste = mutableListOf(1, 2) accepte très bien liste.add(3). L'immuabilité profonde viendra des types eux-mêmes (comme listOf), qu'on verra dans la leçon sur les collections.

Piège fréquent

Garder les réflexes Java : envelopper main dans une classe, semer des points-virgules, écrire String nom = ... au lieu de val nom: String = ... (en Kotlin, le type vient après le nom, séparé par :). Le code compile parfois quand même, mais il n'est pas idiomatique — et les leçons suivantes supposent les bonnes habitudes.

Pour aller plus loin

Pour aller plus loin

La documentation officielle (kotlinlang.org/docs) est excellente et propose un parcours « Get started » interactif. Si la curiosité te pique, regarde la page Kotlin Multiplatform : le même langage que tu viens d'apprendre peut produire une appli iOS native ou du JavaScript. Enfin, garde un œil sur les coroutines, la réponse de Kotlin à la programmation asynchrone — on les abordera en fin de cours.

Un cas réel

Cas réel — adopter Kotlin sans tout réécrire

Quand Google officialise Kotlin en 2017, aucune grande application Android n'est réécrite du jour au lendemain. Des équipes comme celles de Pinterest, Uber ou Evernote profitent de l'interopérabilité pour avancer fichier par fichier : un nouvel écran en .kt cohabite avec l'ancien code .java dans le même projet, puisque tout finit en bytecode JVM. Cette migration graduelle, sans big bang risqué, explique en bonne partie la vitesse d'adoption de Kotlin — et c'est exactement le levier que JetBrains avait prévu dès le départ.

Glossaire

JVM
Java Virtual Machine : la machine virtuelle qui exécute le bytecode, cible commune de Kotlin et Java.
Bytecode
Format intermédiaire (fichiers .class) produit par le compilateur et exécuté par la JVM.
Interopérabilité
Capacité de Kotlin et Java à s'appeler mutuellement sans adaptateur, grâce au bytecode commun.
Boilerplate
Code rituel répétitif sans réelle information ; Kotlin en supprime une grande partie.
val / var
val déclare une référence immuable (le défaut idiomatique), var une référence mutable réassignable.
Inférence de type
Déduction automatique du type d'une variable à partir de sa valeur, sans perdre le typage statique.
Null-safety
Garantie du compilateur distinguant les valeurs possiblement null, pour éviter la NullPointerException.
KDoc
Format des commentaires de documentation (/** … */), l'équivalent Kotlin de la Javadoc.

Récap et vérification

  • Kotlin est créé par JetBrains en 2011, adopté par Google comme langage officiel d'Android en 2017, et compile vers le bytecode JVM (entre autres cibles).
  • Il est 100 % interopérable avec Java, mais supprime la cérémonie : pas de classe obligatoire, pas de point-virgule, null-safety intégrée.
  • Le point d'entrée est fun main() ; println affiche une ligne.
  • val déclare une référence immuable (le défaut idiomatique), var une référence mutable ; l'inférence de type évite d'écrire les types évidents sans rien perdre du typage statique.
  • kotlinc App.kt -include-runtime -d app.jar puis java -jar app.jar compilent et exécutent un fichier à la main.
  • Conventions : camelCase pour variables et fonctions, PascalCase pour les types, indentation de 4 espaces.
