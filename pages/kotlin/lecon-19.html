Sérialisation avec kotlinx.serialization

~48 min Avancé Data classes (leçon 9) requises

À la fin de cette leçon, tu sauras

  • rendre une classe sérialisable avec @Serializable ;
  • convertir un objet en JSON et l'inverse ;
  • gérer les objets imbriqués et les listes ;
  • renommer un champ avec @SerialName et rendre la lecture robuste.
Sommaire de la leçon

Dès qu'une application sauvegarde des données, appelle une API ou envoie un message, elle doit transformer ses objets en texte — le plus souvent du JSON — puis refaire le chemin inverse. C'est la sérialisation (objet → texte) et la désérialisation (texte → objet). Kotlin fournit pour cela une bibliothèque officielle, kotlinx.serialization : elle génère le code à la compilation, fonctionne sur toutes les plateformes, et reste entièrement typée.

@Serializable et JSON

On marque la classe d'une annotation @Serializable. Ensuite, l'objet Json convertit dans les deux sens : encodeToString produit le texte, decodeFromString le relit.

Tout est type-safe : decodeFromString<Utilisateur> reconstruit un vrai Utilisateur, avec ses types vérifiés. Si le JSON ne correspond pas (champ manquant, mauvais type), une exception claire est levée plutôt qu'une valeur bancale.

Objets imbriqués et listes

La sérialisation est récursive : il suffit que chaque type impliqué soit @Serializable. Les listes, maps et objets imbriqués sont pris en charge automatiquement.

Aucune plomberie à écrire : une Commande contenant une List<Ligne> se sérialise d'un bloc, et se relit avec decodeFromString<Commande>(json). C'est là toute la valeur d'une bibliothèque qui génère le code : tu décris tes données, elle s'occupe du reste.

Ajuster et fiabiliser le JSON

Le JSON du monde réel ne colle pas toujours à tes noms de propriétés. @SerialName relie une propriété Kotlin à une clé JSON différente. Et l'objet Json se configure pour un rendu lisible et une lecture tolérante.

Attention

kotlinx.serialization repose sur un plugin de compilation : il faut l'ajouter au build (plugins { kotlin("plugin.serialization") }) en plus de la dépendance. Et seule une classe annotée @Serializable peut être (dé)sérialisée : oublier l'annotation provoque une erreur de compilation explicite, pas un plantage à l'exécution.

Un cas réel

Cas réel — consommer une API météo sans y laisser sa santé mentale

Une application affiche la météo. Elle interroge une API publique qui répond par un gros JSON : des dizaines de champs, nommés en anglais et en snake_case (feels_like, wind_speed…), dont l'application n'utilise qu'une poignée. Avec kotlinx.serialization, on déclare une data class qui ne contient que les champs utiles : @SerialName("feels_like") val ressenti: Double traduit le nom, ignoreUnknownKeys = true fait ignorer tout le reste, et des valeurs par défaut couvrent les champs parfois absents. En une ligne — Json.decodeFromString<Meteo>(reponse) — le texte brut devient un objet Kotlin propre, avec auto-complétion et vérification de types. Le jour où l'API ajoute un champ, rien ne casse : la clé inconnue est ignorée. Ce trio data class + @SerialName + ignoreUnknownKeys est le standard pour parler à n'importe quel service REST, et il remplace des centaines de lignes de lecture manuelle fragile.

Pour aller plus loin

Pour aller plus loin

kotlinx.serialization ne se limite pas au JSON : des modules gèrent Protobuf et CBOR (formats binaires compacts). Étudie la sérialisation polymorphe (sealed class + @SerialName pour un champ discriminant), les sérialiseurs personnalisés (pour un LocalDate, par exemple), l'option encodeDefaults, et l'intégration avec le client HTTP Ktor, qui (dé)sérialise automatiquement corps de requête et de réponse.

Glossaire

Sérialisation
Conversion d'un objet en une représentation textuelle ou binaire (ici du JSON) pour le stocker ou l'envoyer.
Désérialisation
Opération inverse : reconstruire un objet à partir de sa représentation (texte JSON → objet Kotlin).
@Serializable
Annotation qui demande au plugin de générer, à la compilation, le code de (dé)sérialisation d'une classe.
encodeToString
Fonction de Json produisant le texte JSON d'un objet.
decodeFromString<T>
Fonction de Json reconstruisant un objet de type T à partir d'un texte JSON, avec vérification de types.
@SerialName
Annotation associant une propriété Kotlin à une clé JSON de nom différent.
ignoreUnknownKeys
Option de Json { } qui fait ignorer les clés absentes du modèle au lieu d'échouer : robustesse face aux API qui évoluent.
JSON
JavaScript Object Notation : format texte universel d'échange de données, à base d'objets {} et de tableaux [].

Récap et vérification

  • On marque une classe @Serializable, puis Json convertit dans les deux sens.
  • encodeToString sérialise (objet → texte) ; decodeFromString<T> désérialise (texte → objet).
  • Listes et objets imbriqués sont gérés automatiquement si chaque type est @Serializable.
  • @SerialName renomme un champ ; ignoreUnknownKeys et les valeurs par défaut fiabilisent la lecture.

Vérifie ta compréhension

  1. Quelle annotation faut-il poser sur une classe pour pouvoir la (dé)sérialiser ?
  2. Quelle fonction transforme un objet en texte JSON ? Et l'inverse ?
  3. Comment lire sans erreur un JSON qui contient des clés que ton modèle ne connaît pas ?
