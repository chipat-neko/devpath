Module 1 · Les bases de Kotlin — Leçon 03

Conditions, boucles et when

~45 min Débutant Prérequis : leçon 2

À la fin de cette leçon, tu sauras

  • Savoir utiliser if et when comme des expressions qui renvoient une valeur ;
  • Savoir classifier des valeurs avec when : valeurs multiples, ranges, tests de type et forme sans argument ;
  • Savoir construire des ranges avec .., ..<, downTo et step ;
  • Savoir parcourir collections et indices avec for, withIndex(), while et repeat.
Sommaire de la leçon

Tu sais déclarer des variables et des fonctions ; il est temps de faire décider ton programme. En Kotlin, le contrôle de flux ressemble à ce que tu connais de Java ou JavaScript… en surface. En profondeur, deux idées changent tout : if et when sont des expressions qui renvoient une valeur, et when est un switch tellement plus puissant qu'il en devient un outil de modélisation.

Fil rouge de cette leçon : un petit programme qui classifie des notes d'examen sur 20. Tu verras qu'avec when et les ranges, ce genre de logique s'écrit presque comme on la dicterait à voix haute. C'est tout l'esprit de Kotlin — la sécurité d'un typage fort, sans la cérémonie de Java.

if/else est une expression

En Java, if est une instruction : il fait quelque chose, mais ne vaut rien. Pour produire une valeur conditionnelle, tu dois passer par l'opérateur ternaire cond ? a : b. Kotlin supprime cette dualité : if renvoie une valeur, celle de la branche choisie.

Conséquence directe : Kotlin n'a pas d'opérateur ternaire, et tu ne le regretteras pas. if (a) x else y est à peine plus long que a ? x : y, se lit en français, et s'enchaîne sans devenir cryptique. Note aussi que quand tu utilises if comme expression, la branche else est obligatoire : le compilateur exige une valeur dans tous les cas.

Astuce

Réflexe idiomatique : au lieu de déclarer une var puis de l'affecter dans chaque branche, écris directement val resultat = if (…) … else …. Une val, une expression, zéro état mutable.

when : le switch surpuissant

when est le cousin du switch de Java, débarrassé de ses défauts : pas de break à oublier (aucun « fall-through » accidentel), des branches qui acceptent bien plus que des constantes, et — comme if — c'est une expression. Commençons le fil rouge : transformer une note en mention.

Deux choses à remarquer. D'abord, le test d'appartenance in 18..20 : la branche est prise si la note est dans l'intervalle. Ensuite, comme when est ici utilisé en expression (c'est le corps de la fonction), il doit être exhaustif : toutes les valeurs possibles doivent être couvertes, d'où le else. On peut aussi lister plusieurs valeurs sur une seule branche, séparées par des virgules — par exemple 0, 1, 2 -> "Très faible".

when sur les types et sans argument

when sait aussi tester le type d'une valeur avec is. Et grâce au smart cast, dans la branche la valeur est automatiquement traitée comme étant de ce type — pas de cast manuel comme en Java.

Dernière forme, peut-être la plus utile au quotidien : when sans argument. Chaque branche est alors une condition booléenne quelconque — c'est une chaîne de if / else if bien plus lisible, où les conditions sont alignées verticalement.

Note

Les branches sont évaluées de haut en bas et la première qui correspond gagne. Ordonne donc tes conditions de la plus spécifique à la plus générale.

Les ranges : des intervalles de première classe

Tu viens d'utiliser 18..20 dans un when : c'est un range, un vrai objet Kotlin qui représente un intervalle. Les ranges servent partout — tests d'appartenance, boucles, validation.

Retiens la nuance clé : a..b inclut b, tandis que a..<b (ou a until b) l'exclut — idéal pour parcourir des indices de 0 à taille - 1. Et il n'existe pas de 10..1 qui descend tout seul : pour descendre, c'est downTo, explicitement.

La boucle for : sur les éléments, pas sur un compteur

Première surprise pour qui vient de Java ou C : Kotlin n'a pas de boucle for (int i = 0; i < n; i++). La boucle for de Kotlin itère toujours sur quelque chose : une collection, un range, n'importe quel itérable. Et franchement, on ne regrette rien : le for classique mélange trois préoccupations (initialisation, condition, incrément) avec trois occasions de se tromper d'un cran. Le for … in dit directement ce qu'on parcourt.

notes.indices est simplement le range 0..<notes.size — impossible de déborder d'un cran. withIndex() fournit des paires (indice, valeur) qu'on déstructure directement dans l'en-tête de la boucle. Choisis toujours la forme la plus haute : éléments si possible, withIndex() s'il te faut l'indice en plus, indices seulement si tu n'as besoin que de lui.

while, do-while et repeat

while et do-while fonctionnent exactement comme en Java : le premier teste avant d'entrer, le second exécute au moins une fois. On les réserve aux cas où le nombre d'itérations n'est pas connu d'avance.

repeat(n) { … } est la façon idiomatique de dire « fais ça n fois » : pas de variable de boucle à inventer, pas de condition à relire.

break, continue et les labels (survol)

Comme partout, break sort de la boucle courante et continue saute à l'itération suivante. Dans des boucles imbriquées, Kotlin permet d'étiqueter une boucle pour la viser explicitement — utile à connaître, rare en pratique (souvent, extraire la boucle dans une fonction est plus clair).

Pièges fréquents

Piège fréquent

val x = if (cond) "a" sans else ne compile pas : une expression doit valoir quelque chose dans tous les cas. Même logique pour un when utilisé en expression : il doit être exhaustif (else, ou couverture complète des cas).

Piège fréquent

for (i in 0..liste.size) va un cran trop loin : .. inclut la borne haute, donc tu accèdes à un indice hors limites. Écris 0..<liste.size, ou mieux, liste.indices.

Piège fréquent

for (i in 10..1) compile… mais ne fait rien : un range décroissant écrit avec .. est simplement vide, donc aucune itération, sans erreur ni avertissement à l'exécution. Pour descendre, utilise 10 downTo 1.

Pour aller plus loin

Pour aller plus loin

L'exhaustivité de when prend toute sa puissance avec les enum class et les sealed class (modules suivants) : le compilateur sait alors énumérer tous les cas possibles, et un when sans else qui les couvre tous devient un filet de sécurité — ajoute un cas à l'enum, et chaque when devenu incomplet refuse de compiler. Côté boucles, tu verras aussi que les opérations fonctionnelles (map, filter, sumOf…) remplacent une bonne partie des for du quotidien.

Un cas réel

Cas réel — le compilateur qui n'oublie aucun état

Dans une application, un écran passe souvent par plusieurs états : chargement, succès, erreur, vide. En modélisant ces états par un type fermé et en les aiguillant avec un when exhaustif, on obtient une garantie précieuse : le jour où un développeur ajoute un cinquième état, le compilateur signale en rouge tous les when qui ne le traitent pas encore. Impossible d'oublier de gérer un cas — une classe de bugs entière (l'écran figé sur un état non prévu) disparaît avant l'exécution. C'est l'exhaustivité mise au service de la fiabilité, très utilisée dans les architectures d'interface Android modernes.

Glossaire

Expression
Bout de code qui produit une valeur ; en Kotlin, if et when en sont, contrairement à Java.
when
Aiguillage multi-branches : par valeur, par range (in), par type (is) ou sans argument (conditions).
Exhaustivité
Obligation, pour un when utilisé en expression, de couvrir tous les cas (souvent via else).
Smart cast
Après is Type, la valeur est automatiquement traitée comme ce type, sans cast manuel.
Range
Objet représentant un intervalle : a..b (inclusif), a..<b (exclusif), avec downTo et step.
for … in
Boucle qui itère toujours sur quelque chose (collection, range, itérable), jamais sur un compteur brut.
withIndex()
Fournit des paires (indice, valeur) déstructurables dans l'en-tête du for.
repeat(n) / label
repeat répète un bloc n fois ; un label nom@ permet à break/continue de viser une boucle externe.

Récap et vérification

  • if/else est une expression : val statut = if (age >= 18) "majeur" else "mineur" — pas d'opérateur ternaire, pas besoin.
  • when accepte des valeurs multiples, des ranges (in 10..20), des types (is String avec smart cast) et une forme sans argument pour chaîner des conditions.
  • Utilisé en expression, when doit être exhaustif (souvent via else).
  • Ranges : 1..10 (inclusif), 0..<10 / until (borne haute exclue), downTo, step.
  • for itère sur des éléments, des ranges, indices ou withIndex() — pas de for(;;) à la C.
  • while/do-while pour les itérations au nombre inconnu, repeat(n) pour « n fois », labels pour break/continue dans les boucles imbriquées.

Vérifie ta compréhension

  1. Pourquoi Kotlin n'a-t-il pas d'opérateur ternaire ? :, et par quoi le remplace-t-on ?
  2. Quelle est la différence entre 0..5 et 0..<5 ? Et comment itérer de 5 vers 0 ?
  3. Dans quel cas un when exige-t-il une branche else ?
