Module 2 · Collections et lambdas — Leçon 06

Lambdas et fonctions d'ordre supérieur

~50 min Intermédiaire Prérequis : leçon 5

À la fin de cette leçon, tu sauras

  • savoir écrire une lambda avec ou sans le paramètre implicite it, et reconnaître la trailing lambda ;
  • savoir transformer une collection avec map, filter, fold et leurs cousines plutôt qu'avec une boucle for ;
  • savoir lire et utiliser un type fonction comme (Int) -> Int et passer une fonction existante avec :: ;
  • savoir écrire sa propre fonction d'ordre supérieur.
Sommaire de la leçon

Tu connais déjà les fonctions nommées avec fun. Kotlin te permet d'aller plus loin : une fonction peut être une valeur comme une autre — stockée dans une variable, passée en argument, renvoyée par une autre fonction. Une fonction qui accepte (ou renvoie) une fonction s'appelle une fonction d'ordre supérieur, et la petite fonction anonyme qu'on lui passe s'appelle une lambda.

C'est le cœur de tout le travail sur les collections en Kotlin : au lieu d'écrire des boucles for qui décrivent comment parcourir, tu décris quoi faire avec des appels comme filter ou map. Là où Java a attendu sa version 8 pour ajouter les lambdas (avec une syntaxe plus verbeuse), Kotlin les a placées au centre du langage dès le départ. La sécurité d'un typage fort, sans la cérémonie de Java.

La lambda : une fonction qui tient dans la main

Une lambda s'écrit entre accolades : d'abord les paramètres, puis une flèche ->, puis le corps. Pas de mot-clé return : la dernière expression du corps est la valeur renvoyée, dans la droite ligne du « tout est expression » de Kotlin.

Ici le type des paramètres est annoté dans la lambda, parce que le compilateur n'a aucun autre indice. Mais dès qu'une lambda est passée à une fonction qui en déclare le type, l'inférence fait tout le travail — tu le verras dans la section suivante.

it et la trailing lambda : l'idiome le plus visible de Kotlin

Quand une lambda n'a qu'un seul paramètre, tu peux omettre sa déclaration et l'appeler it. Et quand une lambda est le dernier argument d'une fonction, tu peux la sortir des parenthèses — c'est la trailing lambda. Si c'est le seul argument, les parenthèses disparaissent complètement.

Cette dernière forme est partout en Kotlin : on dirait presque que filter { … } est une structure du langage, alors que c'est un simple appel de fonction. C'est ce qui permet à Kotlin de créer des « mini-langages » lisibles sans syntaxe spéciale.

Astuce

Réserve it aux lambdas courtes et évidentes. Dès que le corps dépasse une ligne ou que des lambdas s'imbriquent, nomme le paramètre : clients.filter { client -> … } se relit beaucoup mieux six mois plus tard.

Accumuler avec fold et reduce

Quand tu veux réduire toute une collection à une seule valeur (une somme, un produit, une chaîne concaténée…), c'est le travail de fold et reduce. Les deux font passer un accumulateur d'élément en élément ; la différence est que fold part d'une valeur initiale que tu fournis, alors que reduce part du premier élément.

Pour une simple somme, sache quand même que depenses.sum() existe — fold brille surtout pour les accumulations sur mesure.

Les types fonction et les références ::

Puisqu'une fonction est une valeur, elle a un type. Il s'écrit avec les types des paramètres entre parenthèses, une flèche, puis le type de retour : (Int) -> Int, (String, Int) -> Boolean, ou () -> Unit pour « aucun paramètre, ne renvoie rien d'utile ».

La référence ::estPair dit « passe cette fonction telle quelle », là où { estPair(it) } créerait une lambda intermédiaire juste pour la rappeler. Les deux marchent ; la référence est plus directe quand la fonction existe déjà.

Note

Tu croiseras le mot-clé inline devant ce genre de fonctions : il demande au compilateur de recopier le corps de la lambda au point d'appel pour éviter le coût d'un objet fonction — c'est une optimisation, et filter, map et compagnie en profitent déjà sans que tu aies rien à faire.

Pièges fréquents

Piège fréquent

reduce sur une liste vide lève une UnsupportedOperationException à l'exécution, car il n'a pas de premier élément pour démarrer. Si la liste peut être vide, préfère fold (la valeur initiale sert de résultat) ou reduceOrNull.

Piège fréquent

Dans des lambdas imbriquées, le it intérieur masque celui de l'extérieur — et le code devient illisible, voire faux. Dès qu'il y a imbrication, nomme les paramètres : equipes.forEach { equipe -> equipe.joueurs.forEach { joueur -> … } }.

Piège fréquent

filter et map ne modifient jamais la liste d'origine : ils en renvoient une nouvelle. Écrire nombres.filter { it > 0 } sans récupérer le résultat ne fait donc rien d'utile — il faut val positifs = nombres.filter { it > 0 }.

Piège fréquent

N'écris pas return dans une lambda pour « renvoyer sa valeur » : la dernière expression suffit. Un return nu dans une lambda passée à forEach tente de sortir de la fonction englobante (retour non local) — un comportement subtil que nous garderons pour plus tard.

Pour aller plus loin

Pour aller plus loin

Chaque maillon d'une chaîne filter/map crée une liste intermédiaire. Sur de très grosses collections, asSequence() rend la chaîne paresseuse : les éléments traversent toutes les étapes un par un, sans listes temporaires. Tu découvriras aussi bientôt les lambdas avec récepteur (apply, let, run…), où la lambda gagne un this — la mécanique derrière les DSL Kotlin comme les scripts Gradle.

Un cas réel

Cas réel — le rapport de ventes en une seule chaîne

Dans un back-end e-commerce, calculer le chiffre d'affaires du mois se dit d'une traite : commandes.filter { it.payee }.map { it.montant }.sum(). Besoin du panier moyen ? .average(). Des cinq meilleurs clients ? .sortedByDescending { it.total }.take(5). Écrite avec des boucles for et des maps mutables, la même logique s'étalerait sur vingt lignes truffées d'accumulateurs — autant d'occasions de se tromper d'un cran ou d'oublier une remise à zéro. La version en chaîne de fonctions d'ordre supérieur se lit comme l'énoncé du besoin, se teste étape par étape et se modifie sans risque. C'est le pain quotidien des tableaux de bord, de l'analyse de logs et des traitements de données : on décrit quoi obtenir, la bibliothèque s'occupe du comment.

Glossaire

Lambda
Petite fonction anonyme écrite entre accolades : { x -> x * 2 } ; sa dernière expression est sa valeur de retour.
it
Nom implicite du paramètre unique d'une lambda, qui permet d'omettre sa déclaration : filter { it > 0 }.
Trailing lambda
Lambda passée en dernier argument : elle se place hors des parenthèses, qui disparaissent si elle est seule.
Fonction d'ordre supérieur
Fonction qui reçoit ou renvoie une autre fonction (filter, map, ou la tienne).
Type fonction
Type d'une fonction-valeur : (Int) -> Int, (String, Int) -> Boolean, () -> Unit.
Référence de fonction (::)
Passe une fonction existante telle quelle : ::estPair, String::uppercase, ::println.
fold / reduce
Réduisent une collection à une seule valeur via un accumulateur ; fold part d'une valeur initiale, reduce du premier élément.
inline
Modificateur qui fait recopier le corps de la lambda au point d'appel, évitant la création d'un objet fonction.

Récap et vérification

  • Une lambda s'écrit { x -> x * 2 } ; sa dernière expression est sa valeur renvoyée, sans return.
  • Un paramètre unique peut s'appeler implicitement it ; une lambda en dernier argument sort des parenthèses : list.filter { it > 0 }.
  • filter sélectionne sur un critère, map transforme, forEach agit ; fold/reduce condensent en une valeur ; sortedBy, maxByOrNull, count, any/all/none, take/drop complètent la panoplie.
  • Une fonction a un type, comme (Int) -> Int ; une fonction existante se passe avec ::nom ou String::uppercase.
  • Ta propre fonction d'ordre supérieur se déclare avec un paramètre de type fonction : fun mesurer(bloc: () -> Unit).

Vérifie ta compréhension

  1. Quelles sont les trois écritures possibles de nombres.filter({ n -> n > 0 }), et laquelle est idiomatique ?
  2. Quelle est la différence entre fold et reduce, et lequel des deux est sans risque sur une liste vide ?
  3. Que signifie le type (String, Int) -> Boolean, et comment passerais-tu la fonction existante estPair à filter sans écrire de lambda ?
