Méthodes et tableaux

~28 min Intermédiaire Leçon 3 recommandée

À la fin de cette leçon, tu sauras

  • Savoir déclarer une méthode avec sa signature (type de retour, nom, paramètres) et utiliser return ou void ;
  • Savoir distinguer une méthode static d'une méthode d'instance et comprendre le passage par valeur ;
  • Savoir employer la surcharge et les varargs pour assouplir tes méthodes ;
  • Savoir créer, parcourir et outiller des tableaux (1D, 2D) avec .length et la classe Arrays.
Sommaire de la leçon

Jusqu'ici, tu écrivais tout ton code dans un seul gros bloc. Mais dès qu'un programme grossit, deux besoins apparaissent : réutiliser un morceau de logique sans le recopier, et stocker plusieurs valeurs ensemble. Java répond à ces besoins avec les méthodes (des blocs de code nommés et réutilisables) et les tableaux (des collections de taille fixe).

Dans cette leçon, tu vas apprendre à découper ton code en méthodes propres, à comprendre la subtilité du passage d'arguments, puis à manipuler des tableaux à une et deux dimensions avec les outils modernes de Java. Le code se compile avec javac et s'exécute sur la JVM : chaque sortie console est montrée en commentaire dans le code.

Écrire une méthode : signature, return, void

Une méthode est un bloc de code nommé que tu peux appeler autant de fois que tu veux. Sa signature se compose d'un type de retour, d'un nom (en camelCase) et d'une liste de paramètres entre parenthèses.

Le mot-clé return a deux rôles : il fournit la valeur de sortie et il termine immédiatement la méthode. Une méthode void ne renvoie aucune valeur : elle agit (afficher, modifier) puis se termine. Tu peux quand même y écrire return; seul pour sortir plus tôt.

static contre méthode d'instance (teaser POO)

Tu as remarqué le mot static devant chaque méthode. Une méthode static appartient à la classe elle-même : on l'appelle sans créer d'objet. Une méthode d'instance (sans static) appartient à un objet précis et agit sur ses données.

Note

Pour l'instant, mets static sur toutes tes méthodes appelées depuis main (lui-même static). Tu découvriras les méthodes d'instance et les objets dans le module sur la POO.

Le passage d'arguments : toujours par valeur

En Java, les arguments sont toujours passés par valeur : la méthode reçoit une copie. Modifier un paramètre dans la méthode ne change pas la variable d'origine.

Nuance capitale : pour un objet (ou un tableau), c'est la référence qui est copiée, pas l'objet lui-même. Les deux références pointent donc vers le même objet en mémoire : modifier son contenu via la méthode est bien visible à l'extérieur.

La surcharge (overloading)

La surcharge consiste à donner le même nom à plusieurs méthodes, à condition que leurs paramètres diffèrent (nombre ou types). Java choisit la bonne version selon les arguments fournis. Attention : le seul type de retour ne suffit pas à les distinguer.

Les varargs : un nombre variable d'arguments

Quand tu ignores combien d'arguments seront passés, utilise les varargs avec la syntaxe type.... À l'intérieur, le paramètre se comporte comme un tableau.

Astuce

Le paramètre varargs doit toujours être le dernier de la liste. On écrit par exemple void log(String niveau, String... messages), jamais l'inverse.

Les tableaux : déclaration, accès, parcours

Un tableau stocke plusieurs valeurs du même type dans une structure de taille fixe. On peut le créer vide avec new (les cases valent alors 0, false ou null), ou directement avec un littéral entre accolades.

Les index vont de 0 à length - 1. Le tout premier élément est notes[0], le dernier notes[notes.length - 1].

Tableaux à deux dimensions

Un tableau peut contenir d'autres tableaux : c'est un tableau 2D, idéal pour une grille ou une matrice. On accède à une case avec deux index : grille[ligne][colonne].

La classe utilitaire Arrays

Afficher ou trier un tableau « à la main » est fastidieux. La classe java.util.Arrays fournit des méthodes toutes prêtes : toString pour afficher, sort pour trier, copyOf pour copier ou redimensionner.

Note

Un simple System.out.println(valeurs) sur un tableau affiche quelque chose comme [I@1b6d3586 (le type et une adresse), pas le contenu. Utilise toujours Arrays.toString(...) pour voir les valeurs.

Cas réel — le tri qui saccageait les données de l'appelant

Une méthode mediane(int[] valeurs) appelait Arrays.sort(valeurs) pour trouver la valeur du milieu. Problème : sort trie sur place, et le tableau reçu n'est qu'une copie de la référence vers le tableau de l'appelant (le passage par valeur d'un objet, vu plus haut). Résultat : après le calcul de la médiane, la liste affichée ailleurs n'était plus dans l'ordre de saisie mais triée ! Le correctif tient en une ligne : trier une copie — int[] copie = Arrays.copyOf(valeurs, valeurs.length); Arrays.sort(copie); — pour ne jamais toucher au tableau d'origine.

Pièges fréquents

Piège fréquent

Accéder à un index hors borne lève une ArrayIndexOutOfBoundsException. Pour int[] t = new int[3];, les index valides sont 0, 1, 2 — écrire t[3] plante à l'exécution.

Piège fréquent

Sur un tableau, la taille est l'attribut tab.length (sans parenthèses). Sur une String, c'est la méthode texte.length() (avec parenthèses). Confondre les deux est une erreur de compilation classique.

Piège fréquent

Passer un objet à une méthode ne le copie pas en profondeur : c'est la référence qui est dupliquée. La méthode peut donc modifier le contenu de ton tableau ou de ton objet. Si tu veux protéger l'original, copie-le toi-même (par exemple avec Arrays.copyOf).

Pour aller plus loin

Pour aller plus loin

Un tableau a une taille fixe : quand le nombre d'éléments varie, on préfère les collections comme List (vue dans une prochaine partie), redimensionnable. Explore aussi Arrays.asList(...) pour transformer un tableau en liste, les tableaux d'objets (par exemple String[]), et System.arraycopy(...) pour copier efficacement une portion de tableau.

Antisèche

Glossaire

Méthode
Bloc de code nommé et réutilisable, appelable autant de fois que voulu. On lui passe des arguments, elle peut renvoyer une valeur.
Signature
Identité d'une méthode : son nom et la liste (types) de ses paramètres. C'est ce qui permet la surcharge ; le type de retour seul n'en fait pas partie.
static
Modificateur d'une méthode (ou d'un champ) appartenant à la classe et non à un objet : on l'appelle sans instancier.
Passage par valeur
Règle de Java : une méthode reçoit une copie de l'argument. Pour un objet/tableau, c'est la référence qui est copiée (le même objet est partagé).
Surcharge
Overloading : définir plusieurs méthodes de même nom mais aux paramètres différents. Le compilateur choisit la bonne selon les arguments.
Varargs
Paramètre type... acceptant un nombre variable d'arguments ; il se comporte comme un tableau et doit être le dernier de la liste.
Tableau
Structure de taille fixe stockant plusieurs valeurs du même type, indexées à partir de 0. Taille via l'attribut .length.
Index
Position d'un élément dans un tableau, de 0 à length - 1. Sortir de ces bornes lève une ArrayIndexOutOfBoundsException.

Récap et vérification

  • Une méthode a une signature : type de retour, nom, paramètres ; return renvoie une valeur et sort, void ne renvoie rien.
  • static = méthode de classe (appelée sans objet) ; les méthodes d'instance agissent sur un objet (POO à venir).
  • Les arguments passent par valeur ; pour les objets et tableaux, c'est la référence qui est copiée.
  • La surcharge réutilise un nom avec des paramètres différents ; les varargs (int...) acceptent un nombre libre d'arguments.
  • Un tableau a une taille fixe : new int[n] ou {...}, accès par index dès 0, taille via .length, parcours for ou for-each.
  • Arrays.toString, Arrays.sort et Arrays.copyOf simplifient l'affichage, le tri et la copie.

Vérifie ta compréhension

  1. Quelle est la différence entre une méthode void et une méthode qui renvoie un int ?
  2. Pourquoi doubler(n) sur un int ne change pas n, alors qu'une méthode peut modifier le contenu d'un tableau qu'on lui passe ?
  3. Pour un tableau de 4 éléments, quels sont les index valides, et que se passe-t-il si tu accèdes à l'index 4 ?
