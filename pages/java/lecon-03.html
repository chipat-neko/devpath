Conditions et boucles

~32 min Intermédiaire Leçon 2 recommandée

À la fin de cette leçon, tu sauras

  • savoir écrire des conditions avec if / else if / else, l'opérateur ternaire et les opérateurs booléens (&&, ||, !) ;
  • savoir utiliser le switch classique et le switch expression moderne (->, yield) en évitant le fall-through ;
  • savoir répéter du code avec for, while, do...while et for-each, et piloter le flux avec break et continue ;
  • savoir repérer les pièges courants (boucle infinie, off-by-one, == sur des objets) et comprendre la portée des variables de boucle.
Sommaire de la leçon

Jusqu'ici, ton programme s'exécutait de haut en bas, ligne après ligne. Mais un vrai programme doit décider (faire ceci ou cela selon une situation) et répéter (recommencer tant qu'il le faut). C'est ce qu'on appelle contrôler le flux d'exécution.

Dans cette leçon, tu vas voir les conditions (if, l'opérateur ternaire, switch) puis les boucles (for, while, do...while, for-each), avec break et continue. On utilise Java moderne (Java 17+) tout en expliquant les formes classiques que tu croiseras partout. Tous les exemples se compilent avec javac et s'exécutent sur la JVM ; la sortie console est donnée en commentaire.

1. if / else if / else

Un if exécute un bloc seulement si une condition est vraie. Une condition est une expression booléenne : elle vaut true ou false. On enchaîne avec else if (autre cas) et else (sinon, dans tous les cas restants).

Les conditions se combinent avec && (ET), || (OU) et ! (NON). Les comparaisons utilisent ==, !=, <, >, <=, >=.

Note

En Java, la condition d'un if doit être un vrai boolean. Contrairement à certains langages, un nombre comme 0 ou 1 n'est jamais accepté à la place de false ou true : le compilateur refuse.

2. L'opérateur ternaire : condition ? a : b

Quand un if/else ne sert qu'à choisir une valeur, le ternaire fait ça en une ligne. Il se lit : « si condition alors a sinon b ».

Astuce

Garde le ternaire pour des choix simples. Si tu commences à l'imbriquer (a ? b : c ? d : e), un if/else if classique sera bien plus lisible.

3. switch : classique et expression moderne

Le switch compare une valeur à plusieurs case. Dans la forme classique, chaque case doit finir par break, sinon l'exécution « tombe » dans le cas suivant : c'est le fall-through.

Depuis Java 14, le switch expression avec -> est plus sûr : pas de fall-through, et il peut renvoyer une valeur qu'on affecte à une variable. Plusieurs étiquettes se regroupent avec des virgules.

Si une branche a besoin de plusieurs lignes, on ouvre un bloc { ... } et on renvoie la valeur avec yield.

Note

Dans un switch expression utilisé comme valeur (affecté à une variable), tous les cas possibles doivent être couverts. C'est pourquoi default est presque toujours présent : le compilateur garantit ainsi qu'une valeur est toujours renvoyée.

Cas réel — le break oublié qui double les journaux

Sur un service, un développeur route les niveaux de log avec un switch classique : case "WARN": écrit un avertissement, case "INFO": écrit une info. Il oublie le break après WARN. Résultat : chaque message WARN « tombe » dans le case "INFO" et s'écrit deux fois dans les journaux. Le bug est passé inaperçu en test (peu de WARN) puis a noyé la production de doublons. Réécrit en switch expression avec ->, le problème disparaît par construction : chaque étiquette n'exécute que sa propre branche.

4. Les boucles : for, while, do...while

La boucle for classique a trois parties séparées par des ; : l'initialisation, la condition de continuation, et le pas (ce qui se passe après chaque tour).

La boucle while répète tant que la condition est vraie ; elle teste avant chaque tour. La boucle do...while teste après : son corps s'exécute donc au moins une fois.

5. Le for-each pour parcourir

Pour parcourir tous les éléments d'un tableau (ou d'une liste) sans gérer d'indice, on utilise le for-each : for (Type element : collection). Lis-le « pour chaque element de collection ».

Note

Le for-each est idéal pour lire les éléments. Si tu as besoin de l'indice (la position) ou de modifier une case du tableau, reviens au for classique avec un i.

6. break, continue et labels

break sort immédiatement de la boucle. continue saute le reste du tour courant et passe directement au tour suivant.

Avec des boucles imbriquées, un label (une étiquette suivie de :) permet de préciser quelle boucle break ou continue vise. À connaître, mais à utiliser avec parcimonie.

7. La portée des variables de boucle

Une variable déclarée dans l'en-tête ou le corps d'une boucle n'existe que dans cette boucle : c'est sa portée (sa zone de vie). En dehors, elle n'est plus accessible.

Limiter la portée au strict nécessaire est une bonne habitude : moins de variables traînent, moins tu risques de bugs.

Pièges fréquents

Piège fréquent

Oublier break dans un switch classique : l'exécution « tombe » dans les cas suivants (fall-through). Le switch expression avec -> supprime ce risque.

Piège fréquent

Confondre = (affectation) et == (comparaison). Heureusement, en Java, écrire if (x = 5) provoque une erreur de compilation (sauf si x est un boolean) : le compilateur t'aide.

Piège fréquent

La boucle infinie : oublier de faire avancer la condition (par exemple un compteur++ manquant dans un while). Et l'erreur off-by-one : i <= notes.length au lieu de i < notes.length sort du tableau et lève une ArrayIndexOutOfBoundsException.

Piège fréquent

Comparer des objets (surtout des String) avec == dans une condition. == compare les références, pas le contenu. Pour comparer le contenu, utilise equals : if (nom.equals("Noah")).

Pour aller plus loin

Pour aller plus loin

Le switch fonctionne aussi sur les String et sur les enum (types énumérés). Java 21 va plus loin avec le pattern matching de switch (tester le type d'un objet directement dans les case). Enfin, les streams remplacent élégamment certaines boucles : Arrays.stream(notes).sum() calcule un total sans for. On verra tout cela plus tard.

Glossaire

Condition booléenne
Expression qui vaut true ou false. En Java, un if exige un vrai boolean (jamais un nombre).
Opérateur ternaire
condition ? a : b : renvoie a si la condition est vraie, sinon b. Pratique pour choisir une valeur en une ligne.
switch expression
Forme moderne (Java 14+) utilisant -> : elle peut renvoyer une valeur et n'exécute qu'une seule branche.
Fall-through
Dans le switch classique, enchaînement d'un case au suivant faute de break : source de bugs, évitée par la forme ->.
Itération
Un passage (un « tour ») dans le corps d'une boucle.
for-each
Boucle for (Type e : collection) qui parcourt chaque élément sans manipuler d'indice ; idéale pour lire.
break / continue
break quitte la boucle immédiatement ; continue saute le reste du tour et passe au suivant.
Portée
Zone du code où une variable existe. Une variable déclarée dans une boucle n'est plus accessible en dehors.

Récap et vérification

  • if / else if / else exécute du code selon des conditions booléennes (&&, ||, !).
  • L'opérateur ternaire condition ? a : b choisit une valeur en une ligne.
  • switch classique exige break ; le switch expression (->, yield) est plus sûr et renvoie une valeur.
  • for, while et do...while répètent ; le do...while s'exécute au moins une fois.
  • Le for-each parcourt une collection sans gérer d'indice.
  • break quitte la boucle, continue passe au tour suivant ; les labels visent une boucle précise.
  • Une variable de boucle n'existe que dans sa portée.

Vérifie ta compréhension

  1. Pourquoi le switch expression avec -> évite-t-il le piège du fall-through ?
  2. Quelle différence de comportement y a-t-il entre while et do...while quand la condition est fausse dès le départ ?
  3. Pourquoi faut-il écrire if (nom.equals("Noah")) plutôt que if (nom == "Noah") ?
