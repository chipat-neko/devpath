Module 04 · Java moderne — Leçon 13

Fichiers, dates et utilitaires

~28 min Intermédiaire Leçon 12 recommandée

À la fin de cette leçon, tu sauras

  • savoir lire et écrire un fichier avec java.nio.file (Path, Files) et gérer les exceptions d'E/S ;
  • savoir manipuler dates et durées avec l'API java.time (LocalDate, Duration, Period) et les formater ;
  • savoir formater du texte avec printf, String.format et les text blocks ;
  • savoir calculer proprement avec Math et BigDecimal, et utiliser var et StringBuilder.
Sommaire de la leçon

Tu sais maintenant écrire des classes et organiser ton code. Mais un vrai programme ne vit pas dans le vide : il lit des fichiers, manipule des dates, formate des montants, génère du texte. Tout cela existe déjà, prêt à l'emploi, dans la bibliothèque standard de Java (le JDK). Pas besoin d'installer quoi que ce soit.

Dans cette leçon, on fait le tour des outils du quotidien : lire et écrire des fichiers, manipuler des dates avec l'API moderne java.time, formater proprement du texte et des nombres, et quelques utilitaires bien pratiques. Tout est en Java 17+, mais on explique aussi les bases. Rappel : Java se compile avec javac puis tourne sur la JVM ; les sorties console sont montrées ici en commentaire.

Lire et écrire des fichiers avec java.nio.file

Le point d'entrée moderne, c'est la classe Path (un chemin de fichier) et la classe utilitaire Files (qui contient les opérations). Pour un petit fichier texte, deux méthodes suffisent : Files.writeString pour écrire et Files.readString pour tout lire d'un coup.

Tu remarques le throws IOException sur main : toute opération sur un fichier peut échouer (disque plein, fichier absent, droits manquants). Java t'oblige à gérer ce risque. Ici on le « propage » avec throws ; on verra plus bas comment le capturer avec try.

Pour un gros fichier, ne charge pas tout en mémoire : Files.lines renvoie un stream paresseux. Mais ce stream ouvre le fichier : il faut le fermer. On utilise un try-with-resources, qui ferme automatiquement la ressource à la fin du bloc, même en cas d'erreur.

Note

L'ancienne API java.io.File existe encore, mais java.nio.file (« NIO.2 », depuis Java 7) est plus claire et plus complète. Préfère toujours Path et Files.

Les dates avec java.time

Avant Java 8, manipuler des dates était un cauchemar (Date, Calendar mutables et déroutants). L'API java.time les remplace par des classes immuables et lisibles. Les principales :

  • LocalDate — une date seule (2026-06-10).
  • LocalTime — une heure seule (14:30).
  • LocalDateTime — date + heure, sans fuseau.
  • Instant — un point précis sur la ligne du temps (UTC), idéal pour horodater.
  • Duration — une durée en secondes/heures (entre deux instants).
  • Period — une durée en années/mois/jours (entre deux dates).

Formater du texte : printf et text blocks

Pour assembler une chaîne avec des valeurs, String.format (qui renvoie une String) et System.out.printf (qui affiche directement) utilisent des marqueurs : %s pour une chaîne, %d pour un entier, %.2f pour un décimal à 2 chiffres, %n pour un saut de ligne.

Pour du texte multi-lignes, les text blocks (Java 15+) évitent les \n à répétition. On ouvre et ferme avec trois guillemets """ ; l'indentation commune (calée sur le """ de fin) est retirée automatiquement :

Les nombres : Math, parsing et BigDecimal

La classe Math regroupe les opérations mathématiques : Math.max, Math.min, Math.abs, Math.sqrt, Math.round, Math.PI… Toutes sont statiques.

Pour transformer une chaîne en nombre, chaque type a sa méthode de parsing : Integer.parseInt, Double.parseDouble, etc. Si la chaîne n'est pas un nombre valide, elles lèvent une NumberFormatException.

Pour de l'argent, n'utilise jamais double : les nombres à virgule flottante font des erreurs d'arrondi (0.1 + 0.2 ne donne pas exactement 0.3). Utilise BigDecimal, qui calcule de façon exacte — et crée-le toujours depuis une chaîne, pas un double.

Cas réel

Un logiciel de caisse additionne des centaines de lignes de tickets. En double, les arrondis s'accumulent : en fin de journée le total affiché diffère d'un centime du total réel — et la comptabilité ne tombe jamais juste. La correction tient en une règle : montants en BigDecimal créés depuis des String, dates de vente en LocalDate, et rendu du ticket via un text block formaté avec Locale.FRENCH (pour un « 19,99 € » correct). Trois outils de la bibliothèque standard, zéro dépendance externe.

var pour des déclarations locales lisibles

Depuis Java 10, var laisse le compilateur deviner le type d'une variable locale d'après sa valeur. Le code reste fortement typé : var n'est pas « n'importe quel type », c'est juste un raccourci d'écriture, surtout utile quand le type est long.

Astuce

Utilise var quand le type est évident ou long (var iter = map.entrySet().iterator();). Garde le type explicite quand il clarifie l'intention. var ne marche que pour les variables locales avec une valeur initiale : pas pour les champs, ni les paramètres, ni une variable non initialisée.

Quelques utilitaires : StringBuilder, Random, wrappers

Concaténer des String dans une boucle est coûteux, car chaque + crée une nouvelle chaîne (les String sont immuables). StringBuilder construit le texte par morceaux et ne produit la chaîne finale qu'à la fin.

Enfin, les wrappers (Integer, Double, Boolean…) sont les versions « objet » des types primitifs (int, double, boolean). L'autoboxing convertit automatiquement entre les deux. C'est pratique, mais cela cache un piège qu'on voit juste après.

Pièges fréquents

Piège fréquent

Comparer deux Integer avec == compare les références, pas les valeurs. Java met en cache les petits entiers (-128 à 127), donc ça « marche » par hasard pour les petites valeurs et échoue pour les grandes ! Compare toujours avec .equals (ou des int primitifs).

Autres pièges à connaître :

  • L'ancienne API Date/Calendar est mutable et pénible (les mois commencent à 0 !). Utilise java.time partout.
  • Oublier la gestion des exceptions d'E/S : toute opération Files peut lever une IOException. Le compilateur t'oblige à la traiter (try/catch ou throws).
  • Le formatage dépendant de la locale : sans Locale explicite, le rendu d'une date et d'un nombre (printf("%.2f") donne 17,50 ou 17.50 selon la machine) change d'un poste à l'autre. Précise la locale pour un résultat stable.
  • BigDecimal depuis un double : new BigDecimal(0.1) garde l'imprécision du double. Passe toujours une String : new BigDecimal("0.1").

Antisèche

Glossaire

Path
Représentation d'un chemin de fichier ou de dossier (Path.of("notes.txt")) ; ne lit rien par elle-même, elle désigne l'emplacement.
Files
Classe utilitaire de java.nio.file regroupant les opérations sur les fichiers (readString, writeString, readAllLines, lines…).
try-with-resources
Forme try (ressource) { … } qui ferme automatiquement la ressource (stream, fichier) à la fin du bloc, même en cas d'erreur.
java.time
API moderne (Java 8+) de dates et durées, à base de types immuables (LocalDate, Instant, Duration, Period).
Period vs Duration
Period mesure un écart de calendrier (années/mois/jours) ; Duration un écart d'horloge (heures/minutes/secondes).
DateTimeFormatter
Objet qui convertit une date en texte selon un motif (dd/MM/yyyy) et, si besoin, une Locale.
BigDecimal
Type de calcul décimal exact, obligatoire pour l'argent ; à créer depuis une String pour éviter l'imprécision du double.
Autoboxing
Conversion automatique entre un type primitif (int) et son wrapper objet (Integer) ; comparer les wrappers avec .equals, jamais ==.

Récap et vérification

  • Path.of(...) + Files.readString/writeString/readAllLines/lines pour les fichiers ; try-with-resources ferme les streams.
  • java.time (immuable) : LocalDate, LocalDateTime, Instant, Duration, Period, ChronoUnit, formaté par DateTimeFormatter.
  • printf/String.format avec %s %d %.2f %n (précise la Locale pour un rendu stable) ; text blocks """ pour le multi-lignes.
  • Math, parsing (Integer.parseInt), et BigDecimal (depuis une String) pour la monnaie.
  • var pour les variables locales ; StringBuilder, Random, wrappers et autoboxing (attention au ==).
