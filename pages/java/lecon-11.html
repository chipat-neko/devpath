Les collections (List, Set, Map)

~35 min Intermédiaire Leçon 10 recommandée

À la fin de cette leçon, tu sauras

  • savoir choisir entre List, Set et Map selon le besoin (ordre, unicité, accès par clé) ;
  • savoir utiliser les méthodes clés (add, get, put, getOrDefault, computeIfAbsent) et parcourir une collection ;
  • savoir pourquoi equals/hashCode sont indispensables pour HashSet et HashMap ;
  • savoir éviter la ConcurrentModificationException et la mutation des collections immuables.
Sommaire de la leçon

Jusqu'ici, pour stocker plusieurs valeurs, tu connais surtout le tableau (int[]). Mais un tableau a une taille fixe et très peu de méthodes. Dans la vraie vie, on a besoin de listes qui grandissent, d'ensembles sans doublons, de dictionnaires clé → valeur. Java fournit tout cela dans le Collections Framework : un ensemble cohérent d'interfaces et d'implémentations prêtes à l'emploi.

Dans cette leçon, tu vas apprendre les trois grandes familles — List, Set et Map —, leurs implémentations principales, comment choisir la bonne, et les pièges classiques (notamment la fameuse ConcurrentModificationException).

Le framework Collections : interfaces et implémentations

L'idée centrale du framework : on sépare le contrat (l'interface, ce que la structure sait faire) de la réalisation (la classe concrète, comment c'est fait). Les trois interfaces à retenir :

  • List : une séquence ordonnée, indexée, qui accepte les doublons (ex. ArrayList).
  • Set : un ensemble sans doublon (ex. HashSet).
  • Map : un dictionnaire qui associe une clé à une valeur (ex. HashMap). Techniquement, Map n'hérite pas de Collection, mais on l'étudie avec.

La bonne pratique est de déclarer par l'interface et d'instancier par la classe. On peut ainsi changer d'implémentation sans toucher au reste du code.

Le <String> est un générique : il garantit que la liste ne contient que des String.

List : ArrayList et LinkedList

Une List garde l'ordre d'insertion et donne accès par index. L'implémentation par défaut est ArrayList : elle est rapide en accès par index (get(i)) car basée sur un tableau interne. LinkedList (liste chaînée) est rarement plus efficace en pratique — préfère ArrayList sauf besoin précis.

Note

Attention à remove : remove(int index) retire par position, tandis que remove(Object) retire par valeur. Sur une List<Integer>, list.remove(2) retire l'élément d'index 2, pas la valeur 2 !

Set : HashSet, LinkedHashSet, TreeSet

Un Set refuse les doublons. Trois variantes selon l'ordre voulu :

  • HashSet : le plus rapide, aucun ordre garanti.
  • LinkedHashSet : conserve l'ordre d'insertion.
  • TreeSet : maintient les éléments triés.

Pour des objets de tes propres classes, l'unicité repose sur deux méthodes : equals (comparer deux objets) et hashCode (les ranger dans des « casiers »). Si tu les oublies, le HashSet considérera deux objets pourtant « égaux » comme différents. Bonne nouvelle : un record les génère automatiquement.

Map : HashMap, TreeMap, LinkedHashMap

Une Map associe des clés uniques à des valeurs. C'est la structure idéale pour un annuaire, un comptage, un cache. HashMap est l'implémentation par défaut.

Deux méthodes très utiles : getOrDefault évite le null, et computeIfAbsent crée une valeur seulement si la clé manque — parfait pour construire des listes groupées.

Comme pour Set, les clés d'une HashMap dépendent de equals/hashCode. TreeMap garde les clés triées ; LinkedHashMap garde l'ordre d'insertion.

Choisir la bonne structure

Pose-toi trois questions dans l'ordre :

  • J'associe une clé à une valeur ? → Map (HashMap, ou TreeMap si trié).
  • Je veux interdire les doublons ? → Set (HashSet, LinkedHashSet pour l'ordre, TreeSet pour trier).
  • Sinon, une séquence ordonnée avec doublons → List (ArrayList).

Astuce

En cas de doute, commence par ArrayList ou HashMap. Ce sont les choix par défaut les plus performants dans la grande majorité des cas. Tu pourras toujours changer d'implémentation plus tard, car tu déclares par l'interface.

Utilitaires et fabriques immuables

La classe Collections fournit des outils : sort (trier une List), reverse, max, ou unmodifiableList (vue en lecture seule). Depuis Java 9, les fabriques List.of, Set.of et Map.of créent des collections immuables (non modifiables) en une ligne.

Piège fréquent

Une collection issue de List.of(...) est immuable. Appeler .add() ou .remove() dessus lève UnsupportedOperationException à l'exécution. Pour une liste modifiable, enveloppe-la : new ArrayList<>(List.of(...)).

Itérer sans casser : la ConcurrentModificationException

Le piège le plus courant : modifier une collection pendant qu'on la parcourt avec un for-each. Java le détecte et lève une ConcurrentModificationException.

La solution propre : utiliser un Iterator explicite et appeler iterator.remove(). Plus simple encore en Java moderne : removeIf.

Cas réel — le HashSet qui ne dédoublonnait pas

Un traitement par lots gardait les commandes déjà traitées dans un HashSet<Commande>, où Commande était une classe ordinaire sans equals ni hashCode. Résultat : deux objets Commande portant le même identifiant étaient considérés comme différents. Le Set ne dédoublonnait donc rien : il enflait sans fin, la même commande était retraitée en boucle, et la mémoire montait jusqu'au plantage nocturne. Le correctif : transformer Commande en record (ou implémenter equals/hashCode sur l'id). D'un coup, le Set a retrouvé son rôle : une commande, une entrée.

Pièges fréquents

  • Modifier en itérant avec un for-each → ConcurrentModificationException. Utilise Iterator.remove() ou removeIf.
  • Oublier equals/hashCode pour tes propres classes utilisées dans un HashSet/HashMap : les doublons ne seront pas détectés. Préfère un record.
  • Muter une collection immuable (List.of, Map.of) → UnsupportedOperationException.
  • Choisir LinkedList par réflexe : ArrayList est presque toujours plus rapide et plus économe.
  • NullPointerException sur le résultat d'un get qui renvoie null pour une clé absente. Utilise getOrDefault.

Piège fréquent

map.get(cle) renvoie null si la clé est absente. Si tu enchaînes une opération dessus (par ex. map.get(cle) + 1 sur un Integer), tu peux déclencher une NullPointerException. Sécurise avec getOrDefault(cle, 0).

Glossaire

Collections Framework
Ensemble cohérent d'interfaces (List, Set, Map…) et d'implémentations fournies par Java pour stocker et manipuler des groupes d'objets.
List
Séquence ordonnée et indexée acceptant les doublons ; implémentation usuelle ArrayList.
Set
Ensemble sans doublon ; HashSet (sans ordre), LinkedHashSet (ordre d'insertion), TreeSet (trié).
Map
Dictionnaire associant des clés uniques à des valeurs ; HashMap par défaut. N'hérite pas de Collection.
equals / hashCode
Couple de méthodes qui définit l'égalité et le rangement d'un objet ; indispensable comme clé de HashSet/HashMap.
Immuable
Collection non modifiable (issue de List.of, Map.of…) ; toute tentative de modification lève UnsupportedOperationException.
Iterator
Objet parcourant une collection élément par élément ; seul iterator.remove() permet de supprimer sans risque pendant l'itération.
ConcurrentModificationException
Erreur levée quand on modifie une collection pendant un for-each ; à éviter avec removeIf ou Iterator.remove().

Récap et vérification

  • List = séquence ordonnée indexée avec doublons → ArrayList par défaut.
  • Set = pas de doublon → HashSet (sans ordre), LinkedHashSet (insertion), TreeSet (trié).
  • Map = clé→valeur → HashMap, avec getOrDefault et computeIfAbsent.
  • equals/hashCode sont indispensables pour HashSet/HashMap ; un record les fournit.
  • Ne modifie pas une collection en la parcourant : Iterator.remove() ou removeIf.
  • List.of/Map.of sont immuables ; Collections.sort trie une liste modifiable.

Vérifie ta compréhension

  1. Tu veux stocker des identifiants uniques sans te soucier de l'ordre : quelle structure choisis-tu, et pourquoi pas une List ?
  2. Pourquoi nombres.remove(n) dans un for-each plante-t-il, et comment corriger proprement ?
  3. Quelle est la différence entre map.get("x") et map.getOrDefault("x", 0) quand la clé « x » est absente ?
