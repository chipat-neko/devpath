Module 01 · Les bases de Java — Leçon 02

Variables, types primitifs et opérateurs

~33 min Intermédiaire Leçon 1 recommandée

À la fin de cette leçon, tu sauras

  • savoir déclarer une variable typée et choisir le bon type parmi les 8 primitifs ;
  • savoir manipuler les String (concaténation, equals, text blocks) et distinguer types primitifs et types référence ;
  • savoir utiliser les opérateurs en maîtrisant la division entière et les affectations composées ;
  • savoir convertir des types par cast et reconnaître le débordement silencieux.
Sommaire de la leçon

Programmer, c'est avant tout stocker des données et les transformer. En Java, chaque donnée a un type : un entier, un nombre à virgule, un caractère, un texte… Et contrairement à des langages comme Python ou JavaScript, Java est statiquement typé : tu annonces le type d'une variable au moment de la déclarer, et le compilateur le vérifie avant même d'exécuter le programme. C'est plus verbeux, mais ça attrape énormément d'erreurs très tôt.

Dans cette leçon, tu vas apprendre à déclarer des variables, connaître les 8 types primitifs, manipuler le texte avec String, utiliser les opérateurs et éviter les pièges classiques comme la division entière ou le débordement. Le code ci-dessous se compile avec javac et s'exécute sur la JVM ; les sorties console sont indiquées en commentaire // ….

Déclarer une variable typée

La forme de base est type nom = valeur;. Le type vient en premier, puis le nom, puis éventuellement une valeur initiale.

Une fois le type fixé, il ne change jamais. Si tu tentes d'y mettre une valeur d'un autre type, le programme ne compile même pas. Note aussi qu'une variable locale doit être initialisée avant d'être lue : Java refuse de lire une variable locale qui n'a jamais reçu de valeur.

Note

En Java, chaque instruction se termine par un point-virgule ;. Les noms de variables s'écrivent en camelCase (estActif, prixTotal) par convention.

Les 8 types primitifs

Java possède exactement 8 types primitifs : ce sont des valeurs « brutes », stockées directement, par opposition aux objets. Voici les quatre familles.

En pratique, tu utiliseras surtout int pour les entiers, long pour les très grands entiers (au-delà de ~2 milliards), double pour les décimaux, boolean et char. Les _ dans les nombres sont des séparateurs purement visuels (Java 7+) : 2_000_000 vaut 2000000.

Piège fréquent

Un littéral entier est un int par défaut. long x = 9_000_000_000; ne compile pas car neuf milliards dépasse la capacité d'un int : il faut le suffixe L pour en faire un littéral long. De même, float f = 3.14; échoue sans le suffixe f, car 3.14 est un double.

Le mot-clé var (inférence de type)

Depuis Java 10, tu peux remplacer le type par var quand il est évident d'après la valeur. Le compilateur déduit le type tout seul ; la variable reste fortement typée, ce n'est pas du « tout-venant » comme en JavaScript.

Utilise var quand le type est clair et que ça réduit la répétition (par exemple var liste = new ArrayList<String>();). Garde le type explicite quand il rend le code plus lisible. var ne fonctionne que pour les variables locales (dans une méthode), pas pour les attributs de classe ni les paramètres.

Types primitifs et types référence

Une variable primitive contient directement sa valeur. Une variable de type référence (tout ce qui est un objet, comme String) contient l'adresse d'un objet rangé en mémoire. La grande différence : une référence peut valoir null, c'est-à-dire « ne pointe vers rien ».

Appeler une méthode sur une référence null provoque la fameuse NullPointerException. Les primitifs, eux, ne peuvent jamais être null : un int non initialisé en attribut vaut 0, un boolean vaut false.

Les String : texte immuable

Une String représente une chaîne de caractères. Point crucial : une String est immuable. Les méthodes ne modifient jamais la chaîne d'origine, elles en renvoient une nouvelle.

Piège fréquent

Sur les objets, == compare les références (la même case mémoire ?), pas le contenu. new String("a") == new String("a") vaut false alors que les textes sont identiques. Sournois : deux littéraux identiques comme "a" == "a" peuvent valoir true (réutilisation du pool de chaînes), ce qui fait croire que == marche… jusqu'au jour où il échoue. Pour le contenu, c'est toujours equals.

Les opérateurs

Les opérateurs arithmétiques sont classiques : + - * / et % (le reste, ou modulo). Attention au cas de la division entre deux entiers.

Les opérateurs logiques && et || sont « court-circuités » : si la première partie de && est fausse, la seconde n'est même pas évaluée. C'est pratique pour vérifier qu'une référence n'est pas null avant de l'utiliser, par exemple nom != null && nom.length() > 0.

Piège fréquent

La division entière : 5 / 2 vaut 2, pas 2.5, car les deux opérandes sont des int. Pour obtenir un résultat décimal, force au moins un opérande en double : 5.0 / 2 ou (double) 5 / 2.

Le casting et le débordement

Convertir une valeur d'un type vers un autre s'appelle un cast. Quand il n'y a aucun risque de perte (un petit type vers un plus grand), Java le fait implicitement. Dans l'autre sens, il faut un cast explicite entre parenthèses, et tu acceptes une éventuelle perte.

Le cast (int) tronque vers zéro : 3.9 devient 3, et -3.9 devient -3. Le débordement est sournois : dépasser la capacité d'un int ne lève aucune exception, la valeur « boucle » vers le négatif. Si tu manipules de grands nombres, passe à long.

Cas réel — Ariane 5, un débordement à des centaines de millions

Le 4 juin 1996, 37 secondes après le décollage, le vol inaugural de la fusée Ariane 5 explose. La cause : une valeur liée à la vitesse, stockée sur un flottant 64 bits, est convertie vers un entier 16 bits. Le nombre dépasse la capacité de la petite case, la conversion déborde, et le code — non protégé contre ce cas — provoque une panne en chaîne du guidage. C'est exactement le piège de cette section : un dépassement de capacité silencieux. La parade tient en une habitude : choisir un type assez large et se méfier des conversions vers un type plus petit.

Les constantes final

Une variable marquée final ne peut recevoir sa valeur qu'une seule fois : c'est une constante. Toute tentative de réaffectation est rejetée à la compilation.

Par convention, les constantes « globales » (attributs static final) s'écrivent en MAJUSCULES_AVEC_UNDERSCORES. Utiliser final rend ton intention claire et empêche des modifications accidentelles.

Pièges fréquents

  • Division entière : moyenne = (a + b) / 2 perd les décimales si a et b sont des int. Caste en double.
  • == sur les String : compare les références, pas le texte. Utilise equals.
  • Débordement d'int : un calcul qui dépasse ~2,1 milliards donne un résultat faux sans erreur. Passe en long.
  • Précision float/double : 0.1 + 0.2 ne vaut pas exactement 0.3 (représentation binaire). Pour de l'argent, vois BigDecimal.
  • Suffixe L oublié : un grand littéral entier dépassant l'int ne compile pas sans L.

Pour aller plus loin

Pour aller plus loin

Pour les calculs monétaires, BigDecimal évite les erreurs d'arrondi du double. Un char est en réalité un code Unicode (un nombre), donc 'A' + 1 vaut 66. Les wrappers (Integer, Double…) emballent un primitif en objet et permettent le null ; l'autoboxing convertit automatiquement entre int et Integer. Enfin, pour construire de longues chaînes en boucle, StringBuilder est bien plus efficace que la concaténation répétée de String.

Antisèche

Glossaire

Type primitif
Valeur « brute » stockée directement dans la variable (int, double, char, boolean…) ; ne peut jamais valoir null.
Type référence
Variable qui contient l'adresse d'un objet rangé en mémoire (comme String) ; peut valoir null (« ne pointe vers rien »).
null
Absence de référence. Appeler une méthode sur une variable null lève une NullPointerException à l'exécution.
Inférence (var)
Déduction automatique du type par le compilateur d'après la valeur initiale ; la variable reste fortement typée.
Immuable
Se dit d'un objet qu'on ne peut pas modifier après sa création. Une String est immuable : ses méthodes renvoient une nouvelle chaîne.
Cast
Conversion d'un type vers un autre. Implicite quand il n'y a pas de perte (int → long), explicite entre parenthèses sinon ((int) 3.9), auquel cas la partie décimale est coupée.
Débordement
Overflow : dépasser la capacité d'un type numérique. Silencieux pour un int, qui « boucle » vers le négatif sans erreur.
final
Modificateur rendant une variable non réaffectable : une constante. Par convention en MAJUSCULES_AVEC_UNDERSCORES pour les constantes de classe.

Récap et vérification

  • Java est statiquement typé : type nom = valeur;, et le type ne change plus.
  • 8 primitifs : byte short int long (entiers), float double (décimaux), char, boolean. Suffixes L et f.
  • var infère le type local quand il est évident, sans rien perdre du typage fort.
  • Les String sont immuables ; on les compare avec equals, jamais ==.
  • Division entière, débordement silencieux et cast explicite (int) qui tronque sont les principaux pièges.
  • final crée une constante qu'on ne peut affecter qu'une fois.

Vérifie ta compréhension

  1. Que vaut 9 / 4 et que vaut 9 % 4 en Java ? Pourquoi ?
  2. Pourquoi prenom == "Noah" peut-il valoir false alors que le texte semble identique ? Que faut-il écrire à la place ?
  3. Pourquoi long x = 9_000_000_000; ne compile-t-il pas, et comment corriger ?
