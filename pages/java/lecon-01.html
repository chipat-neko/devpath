Module 01 · Les bases de Java — Leçon 01

Découvrir Java et la JVM

~30 min Intermédiaire Aucun prérequis strict

À la fin de cette leçon, tu sauras

  • comprendre ce qu'est Java et le rôle de la JVM (« écris une fois, exécute partout ») ;
  • distinguer JDK, JRE et JVM, et suivre la chaîne .java → .class → exécution ;
  • écrire, compiler avec javac et lancer avec java un premier programme ;
  • appliquer les conventions de nommage et les commentaires Java.
Sommaire de la leçon

Bienvenue dans ce cours de programmation orientée objet en Java. Avant d'écrire des classes et des objets, il faut comprendre ce qu'est Java, comment ton code passe du texte que tu tapes à un programme qui s'exécute, et quels outils interviennent. C'est l'objet de cette première leçon.

Si tu connais déjà les variables et les boucles dans un autre langage, tu retrouveras des repères familiers. Mais Java a une particularité : il se compile puis s'exécute sur une machine virtuelle. On va décortiquer ça pas à pas. Note bien : Java ne tourne pas dans un navigateur ni dans un éditeur en ligne ; tu utiliseras un terminal avec les commandes javac et java.

Java en bref

Java est un langage orienté objet (tout s'organise autour de classes et d'objets), typé statiquement (le type de chaque variable est connu et vérifié à la compilation, avant l'exécution) et conçu autour d'une promesse : « écris une fois, exécute partout » (write once, run anywhere). Concrètement, le même programme compilé tourne sur Windows, macOS ou Linux sans le réécrire, grâce à la JVM que l'on verra juste après.

On trouve Java partout : dans les back-ends d'entreprise (banques, assurances, e-commerce), dans le développement Android, et dans le big data (des outils comme Hadoop ou Spark reposent sur la JVM). C'est un langage mûr, très répandu et recherché sur le marché.

Note

« Typé statiquement » veut dire que tu déclares le type d'une variable (par exemple un entier ou un texte) et que le compilateur refuse de la traiter autrement. Cela attrape beaucoup d'erreurs avant même de lancer le programme.

Cas réel — Minecraft et le « ça tourne partout »

L'édition Java de Minecraft est livrée sous forme de bytecode empaqueté dans un fichier .jar. Le studio ne recompile pas le jeu pour chaque système : le même fichier est téléchargé par des millions de joueurs sur Windows, macOS et Linux, et c'est la JVM installée sur chaque machine qui l'exécute. Quand tu tapes javac puis java sur ton petit Main.java, tu empruntes exactement la même chaîne .java → bytecode → JVM que ce jeu : c'est ça, « écris une fois, exécute partout ».

La chaîne : du code source à l'exécution

Comprendre cette chaîne est essentiel. Ton code de départ est un simple fichier texte avec l'extension .java. Il passe par trois étapes :

  1. Tu écris du code source dans un fichier Main.java.
  2. Le compilateur javac le traduit en bytecode, un format intermédiaire stocké dans un fichier Main.class. Ce n'est ni du texte lisible, ni du code machine spécifique à ton processeur.
  3. La JVM (machine virtuelle Java) lit ce bytecode et l'exécute. C'est elle qui adapte le bytecode au système d'exploitation réel.

C'est cette étape intermédiaire (le bytecode + la JVM) qui permet le « écris une fois, exécute partout » : le .class est le même partout, seule la JVM change d'une plateforme à l'autre.

Trois sigles reviennent sans cesse, ne les confonds pas :

  • JVM (Java Virtual Machine) : la machine virtuelle qui exécute le bytecode.
  • JRE (Java Runtime Environment) : la JVM + les bibliothèques standard nécessaires pour exécuter un programme Java.
  • JDK (Java Development Kit) : le kit complet de développement. Il contient le JRE plus les outils pour développer, dont le compilateur javac.

Pour développer, il te faut le JDK (il inclut tout le reste). Une version moderne et recommandée est Java 17 ou plus récent.

Décortiquons sans tout dévoiler (on approfondira dans les leçons suivantes) :

  • public class Main déclare une classe nommée Main. En Java, tout code vit dans une classe. public signifie qu'elle est accessible de l'extérieur.
  • public static void main(String[] args) est la méthode main, le point d'entrée : c'est elle que la JVM appelle au démarrage. void indique qu'elle ne renvoie rien ; static qu'elle s'utilise sans créer d'objet ; String[] args est un tableau de textes recevant d'éventuels arguments de la ligne de commande.
  • System.out.println(...) affiche le texte entre guillemets puis passe à la ligne. Chaque instruction se termine par un point-virgule ;.

Note

Ne t'inquiète pas si static, void ou public restent flous pour l'instant : ce sont des notions de POO qu'on déroulera tranquillement. Retiens juste que main est l'endroit où ton programme démarre.

Compiler et lancer

Java se manipule au terminal. Place-toi dans le dossier qui contient Main.java, puis enchaîne deux commandes : d'abord compiler, ensuite exécuter.

javac compile et produit Main.class ; java Main demande à la JVM d'exécuter la classe Main (sans extension !).

Astuce

Moyen mnémotechnique : javac avec un « c » comme compile. java tout court, c'est l'exécution.

Les conventions de nommage

Java a des conventions très suivies. Les respecter rend ton code lisible par tous les développeurs Java :

  • Classes : PascalCase (chaque mot commence par une majuscule) — par exemple Main, CompteBancaire.
  • Méthodes et variables : camelCase (première lettre minuscule, puis majuscule à chaque mot) — par exemple calculerTotal, nomClient.
  • Constantes : MAJUSCULES_AVEC_UNDERSCORES — par exemple TAUX_TVA.

Pièges fréquents

Piège fréquent

Le nom du fichier doit correspondre exactement (casse comprise) à la classe publique. Main.java pour public class Main, sinon erreur de compilation.

Piège fréquent

Oublier String[] args dans la signature de main. La JVM cherche précisément public static void main(String[] args) ; sans cette signature exacte, elle ne trouve pas le point d'entrée et lève une erreur au lancement (main method not found).

Piège fréquent

Confondre les outils : javac compile (et veut Main.java), java exécute (et veut Main, sans extension). Et ne confonds pas le JDK (pour développer) avec le JRE (pour seulement exécuter) : pour coder, installe le JDK.

Pour aller plus loin

Pour aller plus loin

Un IDE comme IntelliJ IDEA ou Eclipse automatise compilation et exécution et te signale les erreurs en direct. JShell est un REPL livré avec le JDK pour tester des bouts de code interactivement (tape jshell dans un terminal). Côté versions, repère les LTS (Long-Term Support, par exemple 17 et 21), plus stables et suivies plus longtemps pour la production. Enfin, GraalVM est une JVM alternative capable de compiler en exécutables natifs très rapides à démarrer.

Glossaire

Bytecode
Format intermédiaire portable produit par javac (fichier .class) : ni texte lisible, ni code machine d'un processeur précis. C'est ce que la JVM exécute.
JVM
Java Virtual Machine : la machine virtuelle qui lit le bytecode et l'adapte au système réel. Une JVM différente par plateforme, le même .class partout.
JRE
Java Runtime Environment : la JVM plus les bibliothèques standard nécessaires pour exécuter un programme Java (mais pas pour le compiler).
JDK
Java Development Kit : le kit de développement. Il contient le JRE et les outils pour coder, dont le compilateur javac. C'est lui qu'on installe.
javac
Le compilateur Java : il traduit un .java en .class (le « c » final aide à retenir compile).
Classe
Unité de base du code Java : tout vit dans une classe. Une classe public doit résider dans un fichier portant exactement son nom.
Méthode main
Point d'entrée du programme, de signature public static void main(String[] args) : c'est là que la JVM démarre l'exécution.
LTS
Long-Term Support : versions de Java (17, 21…) suivies et corrigées plus longtemps, privilégiées en production.

Récap et vérification

  • Java est orienté objet, typé statiquement et portable grâce à la JVM.
  • Chaîne : .java → javac → bytecode .class → JVM exécute.
  • JDK (développer) inclut le JRE (exécuter) qui inclut la JVM.
  • Point d'entrée : public static void main(String[] args).
  • javac Main.java compile, java Main exécute ; depuis Java 11, java Main.java fait les deux.
  • Le fichier porte le nom de sa classe publique ; classes en PascalCase, méthodes et variables en camelCase.
