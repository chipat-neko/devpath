Module 02 · Programmation orientée objet — Leçon 08

Énumérations, records et classes internes

~32 min Intermédiaire Leçon 7 recommandée

À la fin de cette leçon, tu sauras

  • savoir définir et utiliser un enum, y compris avec champs, constructeur et méthodes ;
  • savoir créer un record immuable et le valider avec un constructeur compact ;
  • savoir distinguer classes internes static, inner, locales et anonymes ;
  • savoir choisir entre record, classe et hiérarchie scellée (sealed).
Sommaire de la leçon

Jusqu'ici tu as écrit des classes « classiques » avec des champs, un constructeur et des méthodes. Mais Java propose des types spécialisés qui modélisent certaines situations bien plus proprement : les énumérations (un ensemble fini de valeurs), les records (des porteurs de données immuables) et les classes internes (des classes définies à l'intérieur d'une autre). Bien utilisés, ils suppriment des dizaines de lignes répétitives et rendent ton intention évidente.

Dans cette leçon, tu vas découvrir chacun de ces outils, comprendre ce que Java génère pour toi, et savoir lequel choisir selon le problème. Tout est en Java moderne (17+), mais on explique aussi ce qui se passe « en dessous ».

Les enum : un ensemble fini de constantes typées

Une énumération (enum) déclare une liste fermée de valeurs possibles. Au lieu d'utiliser des entiers magiques (0 = lundi, 1 = mardi…) ou des chaînes fragiles ("LUNDI"), tu obtiens un vrai type vérifié par le compilateur.

Chaque constante est en fait un objet unique. On peut donc comparer avec == en toute sécurité, et le compilateur refuse une valeur qui n'existe pas : Jour j = Jour.LUNDX; ne compile pas, alors qu'un int ou une String erronés passeraient inaperçus.

Un enum dans un switch

Les enum brillent dans un switch. En Java moderne, on utilise les switch expressions avec la flèche -> : pas de break à oublier, et le compilateur vérifie que tu traites tous les cas.

Dans un case, on écrit SAMEDI sans le préfixe Jour. : le compilateur sait déjà de quel enum il s'agit. Astuce : si tu listes explicitement toutes les constantes (au lieu d'un default), le compilateur t'avertira le jour où tu en ajoutes une nouvelle non traitée.

Enum avancés : champs, constructeur, méthodes

Un enum peut être bien plus qu'une liste de noms. Chaque constante peut transporter des données et l'enum peut avoir des méthodes. Le constructeur est forcément privé (implicitement) puisque tu ne crées jamais de nouvelles valeurs toi-même.

Remarque le point-virgule après la dernière constante (MARS(...);) : il est obligatoire dès qu'on ajoute des champs ou des méthodes après la liste.

Cas réel — le statut de commande codé en entier qui laissait tout passer

Un service de commandes stockait l'état sous forme d'int : 0 = panier, 1 = payée, 2 = expédiée, 3 = livrée. Un bug de calcul a fini par écrire statut = 7 dans un cas limite : une valeur qui ne correspondait à rien, mais que le compilateur acceptait sans broncher. Résultat : des commandes « fantômes », invisibles dans tous les filtres. Le refactor vers enum Statut { PANIER, PAYEE, EXPEDIEE, LIVREE } a rendu l'erreur impossible : on ne peut affecter qu'une des quatre constantes, et un switch sans default force à traiter chaque cas. L'ensemble était fini, connu et vérifiable : un enum depuis le début.

Les records : des data classes immuables en une ligne

Très souvent, on a besoin d'une classe qui ne fait que transporter des données : un point, une coordonnée, une ligne de résultat. Avant Java 16, il fallait écrire le constructeur, les accesseurs, equals, hashCode et toString à la main. Un record génère tout ça automatiquement.

Pour cette seule ligne, le compilateur génère : un constructeur Point(int x, int y), deux accesseurs x() et y(), ainsi que equals, hashCode et toString cohérents. Les champs sont finaux : un record est immuable, on ne peut pas changer ses valeurs après construction.

Note

Les paramètres entre parenthèses (int x, int y) s'appellent les composants du record. Pour « modifier » un record, tu en crées une nouvelle copie : new Point(a.x() + 1, a.y()).

Valider un record avec le constructeur compact

Comment vérifier les données à la construction sans réécrire tout le constructeur ? Avec le constructeur compact : tu donnes seulement le corps de validation, sans liste de paramètres ni affectations. Java affecte les champs automatiquement après ton bloc.

Record ou classe : quand choisir quoi ?

Un record est parfait quand l'objet est défini par ses données et qu'il est immuable : DTO, clé de cache, résultat de calcul, valeur dans une collection. Une classe classique reste préférable quand :

  • l'objet doit pouvoir changer d'état (champs modifiables) ;
  • tu veux cacher ou transformer la représentation interne (encapsulation forte) ;
  • l'objet a une identité propre, indépendante de ses valeurs (deux comptes bancaires distincts même avec le même solde) ;
  • tu as besoin d'hériter d'une autre classe (un record ne peut pas extends une classe).

Astuce

Règle simple : si tu te demandes « est-ce que deux objets avec les mêmes valeurs sont identiques ? » et que la réponse est oui, c'est probablement un record.

Les classes internes : static, inner, locales et anonymes

Une classe interne est une classe déclarée à l'intérieur d'une autre. Il en existe quatre variantes, à bien distinguer.

La différence clé entre static class et class : une inner class garde une référence cachée vers l'instance qui l'a créée (elle peut donc lire valeur). Une static nested class est autonome, exactement comme une classe normale rangée à l'intérieur d'une autre pour l'organisation.

Les classes anonymes servaient à implémenter une interface à une seule méthode sur place. Aujourd'hui, une lambda fait la même chose en bien plus court : Runnable r = () -> System.out.println("...");.

Les classes scellées : des hiérarchies fermées

Depuis Java 17, le mot-clé sealed permet de déclarer une hiérarchie fermée : tu listes explicitement les seules sous-classes autorisées. Combiné aux records et au pattern matching dans un switch (stabilisé en Java 21), c'est l'outil idéal pour modéliser un ensemble fini de cas.

Comme Forme est sealed et ne permet que Cercle et Rectangle, le compilateur sait que le switch est exhaustif : aucun default requis. Si tu ajoutes une troisième forme plus tard, le code ne compilera plus tant que tu n'auras pas traité le nouveau cas — une sécurité précieuse.

Pièges fréquents

Piège fréquent

Utiliser des int ou des String comme pseudo-énumérations (int statut = 1;) prive le compilateur de tout contrôle : rien n'empêche un 42 invalide. Dès qu'un ensemble de valeurs est fini et connu, c'est un enum.

Piège fréquent

Un record est immuable : il n'y a pas de « setter ». Chercher à muter un composant (a.x = 5;) ne compile pas, et oublier la validation dans le constructeur compact laisse passer des données invalides. Valide systématiquement quand l'invariant compte.

Piège fréquent

Une inner class (non static) retient une référence vers son instance englobante : si tu la stockes longtemps, tu empêches le ramasse-miettes de libérer l'englobante (fuite mémoire). Si la classe interne n'a pas besoin de l'englobante, déclare-la static. Et n'abuse pas des classes anonymes quand une simple lambda suffit.

Pour aller plus loin

Pour aller plus loin

La combinaison sealed + record + pattern matching forme ce qu'on appelle des types algébriques : une façon élégante de modéliser « un de ces cas, chacun avec ses données ». Explore aussi EnumMap et EnumSet, des collections optimisées pour les clés enum, et compare classes anonymes et lambdas pour bien sentir quand chacune s'impose.

Glossaire

enum
Type dont les valeurs forment une liste fermée de constantes, chacune un objet unique vérifié par le compilateur.
Constante d'enum
Chacune des valeurs déclarées d'un enum ; peut porter des champs et répondre à des méthodes. Créée une seule fois (constructeur privé).
record
Classe immuable définie par ses composants ; le compilateur génère constructeur, accesseurs, equals, hashCode et toString.
Composant (record)
Paramètre déclaré entre les parenthèses d'un record (ex. int x) ; devient un champ final et un accesseur du même nom.
Constructeur compact
Forme abrégée du constructeur d'un record, réduite au bloc de validation ; l'affectation des champs est automatique.
Classe interne (inner)
Classe non static déclarée dans une autre ; elle retient une référence vers l'instance englobante et accède à ses membres privés.
Classe imbriquée static
Classe déclarée static dans une autre : autonome, sans lien avec une instance englobante ; sert surtout à organiser le code.
sealed
Modificateur fermant une hiérarchie : seules les sous-classes listées après permits sont autorisées, ce qui rend un switch exhaustif.

Récap et vérification

  • Un enum est un type à valeurs finies ; il peut porter champs, constructeur et méthodes, et brille dans un switch.
  • Un record est une data class immuable qui génère constructeur, accesseurs, equals, hashCode et toString ; valide via le constructeur compact.
  • Choisis un record pour des objets définis par leurs données, une classe pour un état mutable, une identité propre ou de l'héritage.
  • Les classes internes existent en quatre formes (static, inner, locale, anonyme) ; static par défaut sauf besoin de l'instance englobante.
  • sealed ferme une hiérarchie et rend les switch exhaustifs.
