Module 4 · Fortran avancé et haute performance — Leçon 14

Projet de synthèse — assembler ce qu'on a appris

~56 min Avancé Prérequis : leçons 1 à 13

À la fin de cette leçon, tu sauras

  • mener un projet Fortran de bout en bout ;
  • structurer un calcul en module à interface publique ;
  • combiner procédures pures, tableaux allocatables et opérations globales ;
  • assembler toutes les briques du cours dans un programme complet.
Sommaire de la leçon

Treize leçons t'ont donné les briques : types et précision, contrôle, tableaux, procédures, modules, fichiers, performance, parallélisme, interopérabilité. Il est temps de tout assembler. Cette leçon finale montre la démarche d'un projet Fortran, construit une petite bibliothèque de statistiques propre et réutilisable, puis te confie un mini-projet fil rouge à réaliser toi-même.

La démarche d'un projet Fortran

Un projet, même petit, suit toujours le même fil : concevoir (quels types, quel découpage), écrire les modules (le cœur réutilisable), assembler le programme principal, compiler (à la main ou avec fpm), puis tester et valider. Séparer le calcul (dans des modules) du pilotage (le programme) est la clé d'un code lisible et réutilisable.

Le projet : une petite bibliothèque de statistiques

Construisons un module stats qui calcule la moyenne et l'écart-type d'un tableau. Il réunit presque tout le cours : un module à interface publique, des fonctions pures, des arguments tableaux à forme supposée, et des opérations globales (sum, size) qui évitent toute boucle.

Le programme principal reste mince : il déclare un tableau allocatable, le remplit (l'affectation alloue toute seule) et appelle le module. Tout le savoir-faire numérique est dans stats, réutilisable ailleurs.

Cas réel

C'est exactement l'organisation des vrais codes scientifiques : un cœur de calcul en modules Fortran (procédures pures, tableaux, opérations globales), un programme ou une couche de pilotage minces, et une suite de tests (souvent via fpm test) qui vérifient les résultats sur des cas connus — ici, la moyenne de [2,4,4,4,5,5,7,9] vaut 5 et l'écart-type 2, une valeur qu'on peut recalculer à la main pour valider. C'est cette discipline « calcul isolé + tests » qui permet à des codes de plusieurs décennies de rester fiables.

Astuce

Marque tes fonctions de calcul pure dès que possible : une fonction pure ne modifie rien en dehors d'elle-même. Le compilateur peut alors l'optimiser plus librement (y compris la paralléliser dans un do concurrent), et surtout tu la testes facilement, puisque son résultat ne dépend que de ses arguments.

Antisèche — les briques du cours

Glossaire

implicit none
Directive imposant la déclaration explicite de chaque variable : à mettre en tête de tout programme et module.
Module
Unité regroupant constantes, types et procédures réutilisables ; public/private contrôlent ce qui est exposé.
Fonction pure
Fonction sans effet de bord : son résultat ne dépend que de ses arguments, ce qui facilite tests et parallélisation.
intent
Déclare le rôle d'un argument (in, out, inout) : documente l'intention et laisse le compilateur vérifier.
Tableau allocatable
Tableau dont la taille est fixée à l'exécution (allocate ou affectation), libéré automatiquement.
Forme supposée
Argument tableau déclaré x(:) : la procédure s'adapte à toute taille reçue.
Opération globale
Expression sur des tableaux entiers (x - m, sum…) appliquée sans boucle explicite.
Projet de synthèse
Exercice final assemblant les notions du cours en un programme complet et cohérent.

Récap et vérification

  • Un projet suit une démarche : concevoir, écrire les modules, assembler, compiler, tester.
  • Le calcul vit dans des modules à interface étroite ; le programme ne fait que piloter.
  • Les fonctions pures + opérations globales + tableaux allocatables donnent un code concis et rapide.
  • Valider sur un cas connu (moyenne = 5, écart-type = 2) est le réflexe qui fiabilise un code scientifique.

Vérifie ta compréhension

  1. Pourquoi mettre le calcul dans un module plutôt que tout dans le programme ?
  2. Que signifie l'argument real, intent(in) :: x(:) ?
  3. Comment calcule-t-on une moyenne sans boucle ?

Exercices

Exercice 1Échauffement

Ajoute au module stats une fonction pure somme(x) qui renvoie la somme d'un tableau.

Voir une solution

N'oublie pas d'ajouter somme à la liste public du module pour qu'elle soit visible.

Exercice 2Application

Ajoute une fonction pure maximum(x) qui renvoie la plus grande valeur, en réutilisant une intrinsèque.

Voir une solution

maxval est l'intrinsèque de réduction qui donne le plus grand élément — aucune boucle nécessaire.

Exercice 3Défi

Écris un programme qui alloue un tableau de 5 mesures, le remplit, et affiche moyenne et écart-type via le module stats.

Voir une solution

L'affectation v = [...] alloue le tableau à la bonne taille ; le module fait tout le calcul.

Mini-projet fil rouge — un inventaire

Pour clore ce cours, écrivons un petit inventaire. Il réunit implicit none, un type dérivé, son constructeur, un tableau, la boucle do, l'accès aux composants % et print avec format — un condensé de Fortran.

Ce que tu vas construire

Un type produit (nom, prix, quantité), un tableau de produits, et l'affichage de chaque valeur puis du total.

Étapes

Le type dérivé

Déclare un type :: produit avec character(len=10), real, integer.

Le tableau

Déclare type(produit) :: stock(2) et remplis-le avec le constructeur produit(...).

La boucle

Parcours avec do i = 1, 2 … end do.

La valeur

Accède aux composants avec stock(i)%prix * stock(i)%quantite.

Afficher

Utilise print '(A, F6.2)', ... et trim(...)//" : ", puis cumule le total.

ProjetFil rouge

Assemble les cinq étapes en un programme complet. Essaie d'abord par toi-même, puis compare avec la solution de référence.
