Interopérabilité avec le C

~52 min Avancé Prérequis : leçon 12

À la fin de cette leçon, tu sauras

  • charger iso_c_binding et utiliser les types interopérables ;
  • appeler une fonction C depuis Fortran avec bind(c) ;
  • exposer une procédure Fortran à C (passage par value) ;
  • éviter les pièges : ordre des tableaux, chaînes terminées par zéro.
Sommaire de la leçon

Un cœur de calcul en Fortran, une interface en Python, une bibliothèque en C : le logiciel scientifique est polyglotte. Depuis Fortran 2003, le langage possède un pont normalisé vers le C — et, par ricochet, vers presque tout le reste, puisque la plupart des langages savent parler C. Ce pont, c'est le module iso_c_binding.

Pourquoi un pont vers le C

Le C est le langage commun des systèmes : son interface binaire (ABI) est ce que tout le monde sait appeler. Savoir relier Fortran et C permet deux choses : réutiliser une bibliothèque C existante depuis Fortran, et exposer un calcul Fortran rapide à d'autres langages (Python via NumPy, C++, Julia…). C'est ainsi que du Fortran des années 1970 tourne aujourd'hui sous des outils modernes.

Les types comme c_int ou c_double ne sont pas de nouveaux types : ce sont des paramètres de précision qui garantissent que ton integer(c_int) a exactement la taille de l'int du compilateur C voisin. Sans cette garantie, un entier Fortran et un entier C pourraient ne pas coïncider en mémoire.

Appeler une fonction C depuis Fortran

Pour appeler du C, on décrit sa signature dans un bloc interface, avec l'attribut bind(c, name="…") qui donne le nom exact du symbole C. Soit une fonction C : double c_hypot(double a, double b);

Deux points clés : import rend visibles dans l'interface les noms du module (ici c_double), et surtout l'attribut value. Par défaut Fortran passe ses arguments par référence (il transmet l'adresse) ; or une fonction C attend ici ses scalaires par valeur. L'attribut value rétablit la bonne convention.

Exposer du Fortran à C

Le sens inverse est tout aussi utile : rendre une procédure Fortran appelable depuis C (ou Python). On met bind(c, name="…") sur la procédure, et value sur les arguments d'entrée scalaires.

Côté C, on l'appelle avec le prototype void ajoute(double a, double b, double *s); — la sortie s est un pointeur, d'où l'absence de value.

Attention

Trois pièges classiques : (1) les chaînes C sont terminées par un octet nul ; Fortran non — il faut ajouter //c_null_char. (2) Les indices commencent à 1 en Fortran, à 0 en C. (3) Les tableaux 2D ne sont pas rangés dans le même ordre (voir ci-dessous). Ignorer l'un de ces trois points donne un programme qui compile mais lit la mémoire de travers.

Le piège des tableaux 2D

Fortran range une matrice colonne par colonne (column-major) ; C la range ligne par ligne (row-major). Le même tableau logique occupe donc la mémoire dans un ordre différent. En passant une matrice entre les deux langages, il faut soit la transposer, soit inverser l'ordre des indices.

Cas réel

Quand tu importes un module Fortran dans Python avec f2py (livré avec NumPy), c'est exactement iso_c_binding qui travaille sous le capot : f2py lit les signatures, respecte les conventions d'appel et l'ordre des tableaux, et t'expose une fonction Python. De même, quand NumPy appelle LAPACK, il passe des tableaux en tenant compte du column-major de Fortran. Maîtriser ces conventions, c'est comprendre pourquoi tant de bibliothèques scientifiques mêlent Fortran, C et Python sans friction.

Pour aller plus loin

Pour les pointeurs, c_loc(x) donne l'adresse d'une variable Fortran (un type(c_ptr)), et c_f_pointer(cptr, fptr, [n]) fait l'inverse : transformer un pointeur C en tableau Fortran utilisable. Ces deux outils, avec iso_c_binding, suffisent à envelopper la plupart des bibliothèques C (GSL, zlib, HDF5…) depuis Fortran.

Glossaire

iso_c_binding
Module standard fournissant les types et outils garantissant l'interopérabilité avec le C.
bind(c)
Attribut liant une procédure ou une variable Fortran à un symbole C, avec la même convention d'appel (name="…" fixe le nom exact).
value
Attribut d'argument imposant le passage par valeur (une copie), au lieu du passage par référence par défaut de Fortran.
c_int / c_double
Paramètres de précision garantissant la taille exacte de l'int et du double du C.
Interface (bloc)
Déclaration de la signature d'une procédure externe (ici en C) pour que le compilateur vérifie l'appel.
c_ptr
Type représentant un pointeur C (void *) ; c_loc l'obtient, c_f_pointer le reconvertit en Fortran.
column-major
Rangement des tableaux colonne par colonne (Fortran) ; le C est row-major (ligne par ligne).
c_null_char
Constante valant l'octet nul terminant les chaînes C (\0), à ajouter aux chaînes Fortran transmises.

Récap et vérification

  • Le module iso_c_binding fournit des types de taille garantie compatibles avec le C.
  • bind(c, name="…") lie une procédure à un symbole C ; value ajuste la convention d'appel.
  • Attention aux chaînes (octet nul), aux indices (1 vs 0) et à l'ordre des tableaux (colonne vs ligne).
  • C'est ce pont qui fait dialoguer Fortran, C et Python (f2py, NumPy, LAPACK).

Exercices

Exercice 1Échauffement

Déclare, avec les types interopérables, un entier n compatible int et un réel x compatible double.

Voir une solution

c_int et c_double garantissent la même taille que les types C correspondants.

Exercice 2Application

Écris le bloc interface pour appeler la fonction C double c_carre(double x); depuis Fortran.

Voir une solution

L'argument x porte value (C le veut par valeur) ; import rend c_double visible dans l'interface.

Exercice 3Défi

Expose à C une subroutine norme(a, b, r) qui calcule r = sqrt(a*a + b*b). Quel prototype C obtient-on ?

Voir une solution

Prototype C : void norme(double a, double b, double *r);. Les entrées a et b sont par valeur ; la sortie r, par référence, devient un pointeur.
