Modules et organisation

~50 min Avancé Prérequis : leçon 5

À la fin de cette leçon, tu sauras

  • regrouper code et données dans des modules ;
  • importer avec use et contrôler la visibilité (public/private) ;
  • obtenir des interfaces explicites (vérification des arguments) ;
  • compiler un projet multi-fichiers.
Sommaire de la leçon

Un vrai programme scientifique se compte en milliers de lignes réparties sur plusieurs fichiers. L'outil d'organisation de Fortran moderne, c'est le module : il regroupe données et procédures liées, contrôle ce qui est visible, et — avantage majeur — donne des interfaces explicites qui font vérifier tes appels par le compilateur.

Définir un module

Un module va de module à end module. Les déclarations (constantes, types) viennent d'abord ; les procédures après contains.

parameter déclare une constante : pi ne pourra pas être modifié.

Utiliser un module : use

On importe avec use, placé tout en haut de l'unité de programme (avant implicit none). Tout ce que le module rend public devient disponible.

Importer avec parcimonie : only

Pour ne prendre que ce dont on a besoin (et documenter les dépendances), on précise only. On peut aussi renommer avec =>.

Contrôler la visibilité : public et private

Par défaut, tout est public. On peut rendre certains éléments private (internes au module) pour exposer une interface propre et cacher les détails d'implémentation.

L'avantage des interfaces explicites

Quand une procédure vit dans un module, le compilateur connaît exactement sa signature. Si tu l'appelles avec un mauvais type ou un mauvais nombre d'arguments, il le détecte à la compilation — au lieu d'un bug silencieux. C'est la raison numéro un de toujours ranger ses procédures en modules.

Compiler plusieurs fichiers

On compile d'abord les modules (qui produisent des fichiers .mod), puis le programme qui les utilise.

Cas réel

Les fichiers .mod ne sont pas portables : leur format est propre à chaque compilateur, et souvent à chaque version. Passer de gfortran 12 à gfortran 13, ou de GNU à Intel, oblige à tout recompiler — un .mod incompatible provoque une erreur du type « wrong version of module ». C'est pourquoi les gros projets scientifiques distribuent leur code source et le recompilent chez l'utilisateur, plutôt que des .mod précompilés.

Pièges fréquents

Piège fréquent

Compiler les fichiers dans le mauvais ordre : le module doit être compilé avant le programme qui l'utilise (sinon le .mod n'existe pas encore). Un outil de build (leçon 9) gère cet ordre automatiquement.

Pour aller plus loin

Pour aller plus loin

Les modules peuvent aussi définir des types dérivés (type :: particule … end type) — l'équivalent des structures — et leurs procédures associées, jusqu'à une vraie programmation orientée objet (Fortran 2003+). Le module est l'unité de base de l'architecture.

Glossaire

Module
Unité qui regroupe constantes, types et procédures liés, et contrôle leur visibilité.
use
Instruction qui importe le contenu public d'un module ; placée avant implicit none.
only
Clause de use qui limite l'importation aux noms cités, gardant les dépendances explicites.
public / private
Attributs de visibilité : public expose, private réserve l'usage à l'intérieur du module.
parameter
Attribut déclarant une constante nommée, non modifiable après initialisation.
Interface explicite
Signature d'une procédure connue du compilateur (via un module), qui fait vérifier les appels.
Fichier .mod
Fichier produit à la compilation d'un module, décrivant son interface pour les unités qui l'utilisent.
Type dérivé
Type composite défini par l'utilisateur (type :: … end type), l'équivalent d'une structure.

Récap et vérification

  • Un module regroupe constantes, types et procédures liés.
  • On importe avec use (et only pour cibler, => pour renommer).
  • private/public contrôlent ce que le module expose.
  • Les procédures en module ont une interface explicite : les appels sont vérifiés.

Vérifie ta compréhension

  2. Comment n'importer qu'une seule fonction d'un module ?
  3. Dans quel ordre compiler module et programme ?
