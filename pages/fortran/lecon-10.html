Types dérivés et objets

~50 min Avancé Prérequis : leçon 9

À la fin de cette leçon, tu sauras

  • définir des types dérivés pour regrouper des données ;
  • attacher des procédures liées au type (méthodes) ;
  • étendre un type par héritage (extends) ;
  • exploiter le polymorphisme (class, select type).
Sommaire de la leçon

Jusqu'ici, tes données étaient des variables séparées et des tableaux. Mais un vrai programme scientifique manipule des entités : une particule (position, vitesse, masse), un maillage, un résultat d'expérience. Fortran permet de les regrouper en un seul objet cohérent grâce aux types dérivés, et — depuis Fortran 2003 — de leur attacher des méthodes et de bâtir des hiérarchies. C'est la programmation orientée objet, version Fortran.

Regrouper des données : le type dérivé

Un type dérivé (l'équivalent d'un struct en C ou d'une classe minimale) assemble plusieurs composants sous un même nom. On le déclare avec type … end type, on crée une variable de ce type, et on accède à chaque composant avec l'opérateur %.

Un type dérivé se manipule comme n'importe quel type : on peut en faire un tableau (type(Vecteur3D) :: essaim(1000)), le passer à une procédure, ou l'imbriquer (un composant peut lui-même être un type dérivé). Le constructeur Vecteur3D(...) porte le nom du type et remplit les composants dans l'ordre de déclaration.

Attention

Le constructeur positionnel dépend de l'ordre des composants : Vecteur3D(1.0, 2.0, 3.0) suppose x, y, z dans cet ordre. Si tu réorganises la déclaration, tous les appels changent de sens silencieusement. Préfère le constructeur à mots-clés — Vecteur3D(x=1.0, z=3.0, y=2.0) — plus lisible et robuste au réordonnancement.

Attacher des méthodes : les procédures liées au type

Depuis Fortran 2003, un type peut embarquer ses propres procédures : les type-bound procedures. On les déclare après un contains à l'intérieur du type, et on les appelle avec la même notation %. La procédure reçoit l'instance comme premier argument (par convention nommé self ou this), déclaré class(...).

La donnée et le comportement vivent désormais ensemble : c'est l'idée centrale de l'objet. v%norme() se lit « la norme de v », et Fortran passe v comme argument self automatiquement.

Réutiliser par héritage : extends

Un type peut étendre un autre : il hérite de tous ses composants et de ses méthodes, puis en ajoute. On écrit type, extends(Base) :: Derive. C'est la base de la réutilisation : on décrit le général une fois, on spécialise ensuite.

Polymorphisme : class et select type

Une variable déclarée class(Base) (au lieu de type(Base)) est polymorphe : elle peut contenir la base ou n'importe lequel de ses types dérivés. Utile pour traiter uniformément une collection de formes, de particules, de cellules. Pour agir selon le type réel, on utilise select type.

Le class default capte tous les autres cas. C'est le dispatch dynamique : le même code s'adapte au type réel de l'objet à l'exécution. Associé aux procédures liées, il permet d'écrire un cœur de simulation qui manipule des « objets » sans connaître leur type exact.

Cas réel

Les grands codes de simulation modernes — modèles climatiques, solveurs d'éléments finis, dynamique moléculaire — sont passés des tableaux parallèles anonymes (un tableau pour x, un pour y, un pour la masse…) aux types dérivés. Une bibliothèque comme PETSc ou les cœurs de calcul de codes météo organisent maillages et champs en types dérivés avec méthodes : le code décrit le domaine (une cellule, un élément) au lieu de jongler avec des indices. Résultat : moins de bugs d'alignement entre tableaux, et un code qu'un physicien relit sans peine.

Pour aller plus loin

Fortran orienté objet va plus loin : types abstraits et procédures deferred (des méthodes que chaque type dérivé doit implémenter, comme une interface), procédures génériques liées au type (surcharge d'opérateurs via generic :: operator(+) => ...), et finalizers (final) appelés à la destruction. Fortran 2023 ajoute même des templates génériques. À creuser une fois les bases des types dérivés bien en main.

Antisèche

Glossaire

Type dérivé
Type défini par l'utilisateur regroupant plusieurs composants sous un même nom (type … end type).
Composant
Champ d'un type dérivé, accédé avec l'opérateur % (ex. v%x).
Constructeur
Expression Nom(...) qui crée une instance en remplissant ses composants (par position ou par mots-clés).
Type-bound procedure
Procédure liée à un type (méthode), déclarée après contains dans le type et appelée via %.
class
Déclaration d'une variable polymorphe pouvant contenir un type ou l'un de ses descendants ; requis pour l'argument self d'une méthode.
extends
Mot-clé d'héritage : le type dérivé reprend composants et méthodes du type de base, puis les complète.
select type
Construction qui exécute une branche selon le type réel d'une variable polymorphe (dispatch dynamique).
Polymorphisme
Capacité d'un même code à traiter des objets de types différents apparentés par héritage.

Récap et vérification

  • Un type dérivé regroupe des composants ; on y accède par %.
  • Une procédure liée (procedure :: après contains) attache un comportement au type : v%m().
  • extends fait hériter composants et méthodes ; on spécialise en ajoutant.
  • class(Base) + select type donnent le polymorphisme et le dispatch selon le type réel.

Vérifie ta compréhension

  1. Quelle est la différence entre type(Nom) et class(Nom) ?
  2. Comment une procédure liée reçoit-elle l'instance sur laquelle elle agit ?
  3. Que garantit extends au type dérivé ?
