Les fichiers indexés (VSAM)

~46 min Intermédiaire Prérequis : leçon 7

À la fin de cette leçon, tu sauras

  • déclarer un fichier ORGANIZATION INDEXED avec sa RECORD KEY ;
  • choisir l'ACCESS MODE (séquentiel, aléatoire, dynamique) ;
  • lire, écrire, mettre à jour et supprimer par clé ;
  • vérifier chaque opération avec le FILE STATUS.
Sommaire de la leçon

Les fichiers séquentiels de la leçon 7 se lisent du premier au dernier enregistrement. Parfait pour un traitement par lots complet ; catastrophique pour retrouver un client parmi cinq millions. Les fichiers indexés résolvent ce problème : ils maintiennent un index qui mène directement à l'enregistrement voulu, par sa clé. Sur mainframe, cette organisation porte un nom : VSAM.

Séquentiel ou indexé ?

Pour trouver le client n°450123, un fichier séquentiel doit potentiellement lire tous les enregistrements qui le précèdent. Un fichier indexé consulte son index — trié — et saute directement à la bonne position. La différence, sur de gros volumes, se compte en ordres de grandeur.

Déclarer un fichier indexé

Tout se décide dans la SELECT (ENVIRONMENT DIVISION) : l'organisation, la clé, le mode d'accès, et un champ pour recevoir le code retour de chaque opération.

  • ORGANIZATION IS INDEXED : le fichier maintient un index ;
  • RECORD KEY IS CLI-NUMERO : la clé unique d'accès ;
  • ACCESS MODE : SEQUENTIAL (dans l'ordre des clés), RANDOM (accès direct), ou DYNAMIC (les deux) ;
  • FILE STATUS IS WS-STATUT : un champ à 2 caractères renseigné après chaque opération.

Attention

Ne confonds pas WRITE (ajouter un nouvel enregistrement) et REWRITE (remplacer un enregistrement existant, préalablement lu). Un WRITE sur une clé déjà présente échoue avec un FILE STATUS à 22.

Cas réel

Quand tu consultes ton solde à un guichet ou à un distributeur, un programme COBOL, souvent sous CICS, exécute un READ indexé sur un fichier VSAM par ton numéro de compte. La réponse arrive en quelques millisecondes : aucune chance de balayer des dizaines de millions de comptes à chaque consultation. Le VSAM d'IBM, apparu en 1973, structure encore aujourd'hui l'écrasante majorité des données transactionnelles des banques — un demi-siècle de service et toujours au cœur du réacteur.

Glossaire

Fichier indexé
Fichier associant à chaque enregistrement une clé indexée, permettant l'accès direct sans tout parcourir.
VSAM
Virtual Storage Access Method : la méthode d'accès aux fichiers d'IBM sur z/OS ; le KSDS est son fichier indexé à clé.
RECORD KEY
Champ servant de clé unique d'accès à un enregistrement.
ACCESS MODE
Mode de parcours : SEQUENTIAL (ordre des clés), RANDOM (direct), DYNAMIC (les deux).
READ / WRITE / REWRITE / DELETE
Lire par clé, ajouter, remplacer un existant, supprimer : les opérations de base d'un fichier indexé.
START
Positionne le curseur sur une clé (sans lire) pour enchaîner des READ NEXT.
FILE STATUS
Code à deux caractères renseigné après chaque opération fichier ; 00 = succès, sinon diagnostic.
INVALID KEY
Clause déclenchée quand une opération par clé échoue (clé absente en lecture, déjà présente en écriture).

Récap et vérification

  • Un fichier indexé accède directement par clé, là où le séquentiel parcourt tout.
  • La SELECT fixe ORGANIZATION INDEXED, RECORD KEY, ACCESS MODE et FILE STATUS.
  • READ, WRITE, REWRITE, DELETE, START couvrent la vie du fichier.
  • On teste le FILE STATUS après chaque opération : 00 = succès.

La clé existe déjà : on a tenté d'ajouter un enregistrement dont la RECORD KEY est déjà présente. Il fallait sans doute faire un REWRITE (mise à jour) plutôt qu'un WRITE.
