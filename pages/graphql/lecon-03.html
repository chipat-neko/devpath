Les requêtes (queries)

~35 min Intermédiaire Leçon 02

À la fin de cette leçon, tu sauras

  • écrire une query avec des champs imbriqués ;
  • passer des arguments à un champ ;
  • paramétrer une requête avec des variables ;
  • utiliser alias et fragments.
Sommaire de la leçon

Le schéma posé, place à la pratique : interroger l'API. Une requête GraphQL se lit comme la forme des données voulues. Voyons comment la rendre précise, paramétrée et réutilisable.

Champs et imbrication

Une query sélectionne des champs ; un champ qui renvoie un objet se déplie à son tour entre accolades. On descend ainsi dans le graphe, champ par champ.

On ne reçoit que ce qu'on demande

Aucun champ « par défaut » : si tu ne demandes pas email, tu ne le reçois pas. C'est ce qui élimine la sur-récupération — et oblige à être explicite.

Les arguments

Un champ peut accepter des arguments pour préciser la demande : un identifiant, un filtre, une pagination. Ils s'écrivent entre parenthèses.

Les variables

Coder « 42 » en dur dans la requête n'est pas réutilisable. Les variables paramètrent une requête : on les déclare après le nom de l'opération (avec leur type), puis on les passe à part, en JSON.

Toujours préférer les variables

Nommer l'opération (GetUser) et passer les valeurs par variables rend la requête réutilisable, lisible et plus sûre (pas de concaténation de chaînes). C'est la bonne pratique dès qu'une valeur change.

Alias et fragments

Deux outils de confort. Un alias renomme un champ dans la réponse — indispensable pour demander deux fois le même champ avec des arguments différents. Un fragment regroupe un ensemble de champs réutilisable, pour ne pas se répéter.

Ici, premier et second sont des alias (sinon les deux user entreraient en conflit dans la réponse), et carte est un fragment partagé.

Cas réel

Dans les grandes applications React, les clients GraphQL comme Apollo et Relay poussent l'idée du fragment très loin : chaque composant d'interface déclare, à côté de son code, un fragment listant exactement les champs dont il a besoin (une carte d'avatar demande name et avatarUrl, un badge demande role…). L'outil assemble automatiquement tous ces fragments en une seule requête pour l'écran. Avantage : si l'on supprime un composant, les champs qu'il réclamait disparaissent de la requête — plus de sur-récupération « fantôme ». C'est la colocation des données et de l'affichage.

Pièges fréquents

  • Oublier de descendre dans un objet. Demander user sans préciser ses champs est invalide : il faut sélectionner au moins un champ scalaire.
  • Coder les valeurs en dur. Préfère les variables dès qu'une valeur change.
  • Deux mêmes champs sans alias. Sans alias, les clés se chevauchent dans la réponse.
  • Se répéter. Un fragment évite de réécrire les mêmes champs partout.

Pour aller plus loin

GraphQL propose aussi des directives comme @include(if: ...) et @skip(if: ...) pour inclure ou non un champ selon une variable, et un troisième type d'opération, les subscriptions, pour recevoir des mises à jour en temps réel. De quoi explorer une fois les bases acquises.

Antisèche : anatomie d'une query

Glossaire

Query
Opération de lecture ; sélectionne un arbre de champs à recevoir.
Champ
Élément demandé dans une requête ; scalaire (feuille) ou objet (qui se déplie).
Argument
Valeur passée à un champ entre parenthèses pour préciser la demande (identifiant, filtre, pagination).
Variable
Paramètre typé d'une opération nommée (ex. $id: ID!), dont la valeur est fournie à part en JSON.
Alias
Nom de rechange donné à un champ dans la réponse ; permet de demander deux fois le même champ avec des arguments différents.
Fragment
Ensemble de champs nommé et réutilisable (fragment X on Type), pour ne pas se répéter.
Directive
Modificateur comme @include(if:) ou @skip(if:) qui inclut ou non un champ selon une condition.

Récap et vérification

  • Une query sélectionne des champs ; les objets se déplient en sous-champs.
  • Les arguments précisent un champ (id, filtre, pagination).
  • Les variables ($id: ID!) paramètrent une opération nommée — la bonne pratique.
  • Alias = renommer dans la réponse ; fragment = champs réutilisables.

Vérifie ta compréhension

  2. Pourquoi préférer une variable à une valeur codée en dur ?
