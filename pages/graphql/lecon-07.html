Module 04 · GraphQL avancé — Leçon 07

Fragments, variables et directives

~38 min Avancé Prérequis : leçon 06

À la fin de cette leçon, tu sauras

  • paramétrer une requête avec des variables ($id) ;
  • factoriser des champs avec des fragments (nommés et inline) ;
  • rendre une requête conditionnelle avec @include et @skip ;
  • renommer un champ dans la réponse avec un alias.
Sommaire de la leçon

Tu sais écrire des requêtes et des mutations. Reste à les rendre réutilisables et dynamiques. GraphQL fournit pour cela quatre outils que tout client sérieux emploie : les variables, les fragments, les directives et les alias. Ce sont eux qui distinguent une requête bricolée d'une requête de production.

Les variables : ne jamais concaténer

Coller une valeur directement dans le texte d'une requête est fragile et risqué (injection, cache cassé). On déclare plutôt des variables typées, passées à part dans un objet JSON. La requête devient un modèle réutilisable.

Le ! après le type (ID!, Boolean!) signale une variable obligatoire. Le serveur valide les types avant d'exécuter : passer un nombre là où un ID est attendu est refusé proprement.

Les fragments : factoriser des champs

Quand plusieurs endroits d'une requête demandent le même ensemble de champs, on les regroupe dans un fragment défini sur un type, puis on l'insère avec ...NomDuFragment. Un seul endroit à maintenir.

Les fragments inline : choisir selon le type

Quand un champ renvoie une interface ou une union (leçon 2), la forme dépend du type concret. Le fragment inline ... on Type sélectionne des champs propres à chaque cas ; __typename révèle le type réel.

Les directives : @include et @skip

Une directive modifie l'exécution d'un champ. Les deux directives natives sont @include(if:) — garder le champ seulement si vrai — et @skip(if:) — l'omettre si vrai. Pilotées par une variable, elles rendent une requête conditionnelle sans en écrire deux versions.

Astuce

Besoin d'appeler deux fois le même champ avec des arguments différents dans une seule requête ? Utilise un alias : premier: user(id: "1") { name } et second: user(id: "2") { name }. Sans alias, les deux user entreraient en collision dans la réponse ; l'alias renomme la clé du résultat.

Cas réel

L'API publique de GitHub v4 est entièrement en GraphQL. Ses clients s'appuient massivement sur variables et fragments : un même fragment on Repository décrit la « carte dépôt » réutilisée dans la recherche, le profil et les listes. Mieux : en production, on envoie souvent une persisted query — le client transmet un simple hash qui identifie une requête connue du serveur, plutôt que son texte complet. Cela réduit la bande passante et permet au serveur de n'autoriser qu'une liste blanche de requêtes : variables et fragments rendent ce modèle possible.

Pièges fréquents

Piège fréquent

Un fragment est lié à un type précis : fragment X on User ne peut s'insérer que là où un User est attendu. L'y mettre sur un autre type est une erreur de validation. Autre piège : une variable déclarée mais jamais utilisée (ou l'inverse) fait échouer la requête entière — GraphQL est strict, et c'est tant mieux : l'erreur tombe à la validation, pas en production.

Antisèche

Glossaire

Variable
Paramètre typé d'une requête ($id: ID!), fourni à part dans un objet JSON ; évite de concaténer des valeurs dans le texte.
Fragment
Bloc de champs nommé et défini sur un type, réutilisable par ...NomDuFragment.
Fragment inline
... on Type { … } : sélectionne des champs propres à un type concret quand un champ renvoie une interface ou une union.
__typename
Champ méta disponible partout ; renvoie le nom du type concret de l'objet.
Directive
Annotation (@nom(arg:)) qui modifie l'exécution ; les natives sont @include et @skip.
@include / @skip
Gardent (ou omettent) un champ selon un booléen, en général une variable : une requête conditionnelle sans doublon.
Alias
Renomme la clé d'un champ dans la réponse (a: champ) ; indispensable pour appeler deux fois le même champ.
Persisted query
Requête pré-enregistrée côté serveur, appelée par un hash plutôt que par son texte ; économise la bande passante et permet une liste blanche.

Récap et vérification

  • Les variables ($id: ID!) paramètrent une requête sans concaténer.
  • Les fragments factorisent des champs ; ... on Type gère interfaces et unions.
  • @include/@skip rendent une requête conditionnelle.
  • Un alias renomme un champ et permet de l'appeler plusieurs fois.

  2. Quand a-t-on besoin d'un fragment inline (... on Type) ?
  3. Que fait @skip(if: $x) et d'où vient $x ?
