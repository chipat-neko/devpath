Le schéma & les types

~33 min Intermédiaire Leçon 01

À la fin de cette leçon, tu sauras

  • expliquer le rôle du schéma comme contrat typé ;
  • définir un type d'objet et ses champs ;
  • utiliser les scalaires, les listes et le non-null (!) ;
  • reconnaître le type racine Query.
Sommaire de la leçon

Tout, en GraphQL, repose sur le schéma : un contrat typé qui décrit les données disponibles et les opérations possibles. Le serveur l'expose, les clients s'y fient. Comprendre le schéma, c'est tenir le fil de tout le reste.

Le schéma, un contrat typé

Le schéma liste les types de l'API et leurs champs. Il est écrit dans un langage dédié, le SDL (Schema Definition Language). Comme il est typé, le serveur peut valider chaque requête avant de l'exécuter : un champ inexistant ou mal typé est rejeté immédiatement, avec un message clair.

Le schéma est la source de vérité

Outils d'autocomplétion, validation, documentation, explorateur interactif… tout est généré à partir du schéma. C'est le point de rencontre entre l'équipe back-end et les clients.

Cas réel

L'API GraphQL de GitHub publie son schéma en clair et le rend interrogeable par introspection : n'importe quel outil peut demander à l'API « quels types et champs proposes-tu ? ». C'est ce qui permet à l'explorateur GitHub (et à ton éditeur) d'offrir l'autocomplétion et de valider ta requête avant l'envoi. Quand GitHub veut retirer un champ, le schéma le marque d'abord déprécié (avec un message et une date) au lieu de casser silencieusement les clients : le contrat typé sert aussi à faire évoluer l'API sans surprise.

Scalaires, listes et non-null

Trois notations à lire correctement :

  • Scalaires : les types de base — Int, Float, String, Boolean, ID (un identifiant). Les feuilles de l'arbre de données.
  • Liste : des crochets. [Post] = une liste de Post.
  • Non-null : un point d'exclamation !. String! = ne sera jamais nul ; sans !, la valeur peut être absente (null).

Lire [Post!]!

De l'intérieur vers l'extérieur : Post! = des éléments jamais nuls ; [...]! = la liste elle-même n'est jamais nulle (au pire vide). Donc « une liste garantie, sans trou à l'intérieur ».

Le type racine Query

Un type spécial, Query, est le point d'entrée des lectures : il liste ce qu'on peut demander à la racine. Chaque champ de Query peut prendre des arguments (un identifiant, un filtre…).

Une requête cliente part toujours d'un champ de Query : user(id: "42") { name } correspond exactement au champ user déclaré ci-dessus.

Au-delà : enums et types d'entrée

Le schéma offre d'autres briques utiles : les enums (un ensemble fixe de valeurs, ex. Role: ADMIN | USER) et les input types (des objets passés en argument, très utiles pour les mutations, à venir). On les survole ici ; l'essentiel est de savoir lire un type d'objet.

Pièges fréquents

  • Oublier le !. Sans lui, un champ peut être null ; avec lui, il est garanti. C'est un choix de conception, pas un détail.
  • Confondre liste et non-null. [Post], [Post!], [Post!]! ne disent pas la même chose.
  • Croire qu'ID est un nombre. ID est un identifiant (souvent une chaîne) ; il n'est pas fait pour l'arithmétique.
  • Ignorer Query. Toute lecture commence par un champ déclaré dans le type Query.

Pour aller plus loin

Le schéma se prête à l'introspection : on peut interroger l'API pour qu'elle décrive son propre schéma. C'est ce qui alimente les explorateurs comme GraphiQL et l'autocomplétion de l'éditeur. Une API GraphQL est, en un sens, auto-documentée.

Pour aller plus loin

On peut documenter chaque type et champ avec des descriptions (entre guillemets, au-dessus de la déclaration). Ces descriptions apparaissent dans les explorateurs : un schéma bien commenté est un cadeau pour les clients.

Glossaire

Schéma
Contrat typé décrivant tous les types et opérations d'une API GraphQL ; il permet de valider les requêtes et sert de source de vérité.
SDL (Schema Definition Language)
Langage dédié dans lequel s'écrit le schéma GraphQL.
Type d'objet
Description d'une forme de données (ex. User) composée de champs typés.
Scalaire
Type de base et feuille de l'arbre : Int, Float, String, Boolean, ID.
Non-null (!)
Marque un champ ou type dont la valeur est garantie (jamais null).
Query
Type racine listant les opérations de lecture disponibles à la racine.
Introspection
Capacité d'une API GraphQL à décrire son propre schéma ; alimente explorateurs et autocomplétion.
Input type
Type d'objet destiné à être passé en argument (données reçues), distinct d'un type de sortie.

Récap et vérification

  • Le schéma (en SDL) est le contrat typé : il permet de valider les requêtes.
  • Un type d'objet a des champs typés ; les scalaires (Int, String, ID…) sont les types de base.
  • [ ] = liste ; ! = non-null (valeur garantie).
  • Le type Query liste les lectures possibles à la racine.

Vérifie ta compréhension

  1. À quoi sert le schéma, et que permet son typage ?
  2. Que signifie le ! après un type ?
  3. Quel type liste les opérations de lecture ?

Exercice 2Application

Explique la différence entre [String], [String!] et [String!]!.

Voir une solution

[String] : la liste peut être nulle, et peut contenir des éléments nuls. [String!] : la liste peut être nulle, mais ses éléments ne le sont jamais. [String!]! : la liste n'est jamais nulle (au pire vide) et ses éléments ne sont jamais nuls. Le ! intérieur porte sur les éléments, le ! extérieur sur la liste.

Exercice 3Défi

Ajoute au type Query un champ permettant de chercher des livres par auteur, renvoyant une liste garantie de Book.

Voir une solution

L'argument author est une chaîne non nulle ; le retour [Book!]! garantit une liste (éventuellement vide) sans élément nul.
