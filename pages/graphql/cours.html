GraphQL : des API flexibles

GraphQL est un langage de requête pour les API : au lieu de multiplier les URL, le client demande exactement les données dont il a besoin, en une seule requête, sur un schéma typé. Ce cours te mène de la comparaison avec REST jusqu'à une API GraphQL complète — schéma, requêtes, mutations et résolveurs.

Prérequis

Il est utile de connaître les bases de HTTP et du JSON, et d'avoir vu les API REST : GraphQL se compare naturellement à elles. Pour pratiquer côté serveur, un environnement Node.js est le plus courant.

Ce que tu vas apprendre

Objectifs du cours

À la fin du cours, tu sauras

  • expliquer ce que GraphQL résout par rapport à REST ;
  • lire et écrire un schéma typé (types, champs, scalaires) ;
  • écrire des requêtes qui demandent juste les bons champs ;
  • modifier des données avec des mutations ;
  • comprendre les résolveurs qui relient le schéma aux données ;
  • assembler une API GraphQL complète de bout en bout.

Pour qui, et pourquoi

Ce cours est pour toi si tu construis ou consommes des API et que tu veux une alternative souple au REST. GraphQL brille quand les clients (web, mobile) ont des besoins de données variés : chacun demande sa forme exacte, sans surcharge ni allers-retours multiples.

Le fil conducteur est le schéma : un contrat typé, partagé entre le serveur et les clients, qui décrit tout ce qu'on peut demander. Une fois ce contrat posé, le reste s'enchaîne naturellement.

Astuce

Avec GraphQL, il n'y a qu'un seul point d'entrée (endpoint). Ce n'est pas l'URL qui change selon la donnée voulue, mais le contenu de la requête. C'est le renversement clé par rapport à REST.

Récapitulatif

À retenir & glossaire

Les points clés du cours, puis les termes essentiels à connaître.

À retenir

  • GraphQL : le client demande exactement les champs voulus, en une requête.
  • Tout repose sur un schéma typé : le contrat entre serveur et clients.
  • Une query lit des données ; une mutation les modifie.
  • Les résolveurs relient chaque champ du schéma à sa source de données.
  • Un seul endpoint HTTP : c'est la requête qui varie, pas l'URL.
Schéma
Le contrat typé qui décrit tous les types et opérations disponibles dans l'API.
Type
Une forme de données (ex. User) composée de champs typés.
Champ (field)
Une propriété d'un type, qu'un client peut demander.
Scalaire
Un type de base : Int, Float, String, Boolean, ID.
Query
Une opération de lecture : demander des données.
Mutation
Une opération d'écriture : créer, modifier ou supprimer.
Résolveur (resolver)
La fonction serveur qui fournit la valeur d'un champ.
Endpoint
L'unique URL par laquelle passent toutes les requêtes GraphQL.
Argument
Un paramètre passé à un champ pour préciser la demande (ex. un id).
Introspection
La capacité d'interroger le schéma lui-même pour le découvrir.
Sur-récupération
(over-fetching) Recevoir plus de données que nécessaire — ce que GraphQL évite.
