Module 03 · Pratique — Leçon 06

Construire une API GraphQL

~40 min Intermédiaire Tout le cours

À la fin de cette leçon, tu sauras

  • assembler schéma + résolveurs en un serveur GraphQL ;
  • exposer des queries et des mutations ;
  • tester ton API dans un explorateur ;
  • comprendre le rôle de la bibliothèque serveur (Apollo, Yoga).
Sommaire de la leçon

Le moment d'assembler : relier les briques vues jusqu'ici. Un serveur GraphQL = un schéma (ce qui existe) + des résolveurs (comment l'obtenir), assemblés par une bibliothèque qui expose l'endpoint HTTP. Construisons-en un, petit mais complet.

Cas réel

En 2016, GitHub a publié son API v4 entièrement en GraphQL, après des années d'API REST v3. La raison : les apps mobiles et les tableaux de bord devaient enchaîner plusieurs appels REST (le dépôt, puis ses issues, puis leurs auteurs…). Avec GraphQL, une seule requête décrit tout l'arbre voulu et le serveur le renvoie en une fois. Shopify (Storefront & Admin API), Netflix ou Meta ont fait des choix similaires. Le schéma que tu vas écrire ici est, en miniature, exactement ce que ces API exposent : un contrat typé + des résolveurs derrière chaque champ.

Glossaire

Schéma exécutable
L'assemblage du schéma (SDL) et des résolveurs qu'une bibliothèque transforme en API interrogeable.
Apollo Server
Bibliothèque Node.js très répandue qui monte un serveur GraphQL à partir d'un schéma et de résolveurs.
typeDefs
Le schéma écrit en SDL, passé à la bibliothèque (souvent sous ce nom).
Endpoint
L'URL unique du serveur GraphQL, appelée en POST ; c'est la requête qui varie, pas l'adresse.
Explorateur
Interface web (Apollo Sandbox, GraphiQL) servie sur l'endpoint pour écrire et tester des requêtes.
Subscription
Troisième type racine (après Query/Mutation) pour recevoir des données en temps réel (push).
Fédération
Technique qui compose plusieurs services GraphQL en un seul schéma unifié.
Payload
Type de retour d'une mutation transportant l'objet modifié et d'éventuelles informations d'erreur.

Récap et vérification

  • Un serveur GraphQL = schéma + résolveurs, assemblés par une bibliothèque (Apollo, Yoga).
  • Le schéma déclare Query (lectures) et Mutation (écritures) ; les résolveurs les implémentent.
  • L'explorateur intégré permet de tester sans client.
  • Pour aller plus loin : base de données, auth, gestion d'erreurs, subscriptions.

Vérifie ta compréhension

  1. De quoi est composé un serveur GraphQL ?
  2. Dans quel ordre le serveur traite-t-il une requête, et quelle forme a sa réponse ?
