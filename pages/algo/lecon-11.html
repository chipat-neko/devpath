Tas et file de priorité

~32 min Avancé Leçon 10 recommandée

À la fin de cette leçon, tu sauras

  • comprendre le rôle d'une file de priorité et pourquoi un tas binaire la réalise efficacement ;
  • naviguer dans un tas-min stocké en tableau avec les formules d'index parent/enfants ;
  • implémenter inserer (remontée) et extraireMin (descente) en O(log n) et justifier la complexité ;
  • appliquer un tas à des problèmes concrets comme la recherche des K plus grands éléments.
Sommaire de la leçon

Imagine une salle d'urgences : on ne soigne pas les patients dans l'ordre d'arrivée, mais selon leur gravité. Une file ordinaire (FIFO) ne suffit plus : il te faut une structure qui, à tout instant, sait te rendre l'élément le plus prioritaire, quelle que soit la date de son insertion. C'est exactement le rôle d'une file de priorité.

L'idée clé : plutôt que de garder les données entièrement triées (coûteux à maintenir), on utilise une structure qui maintient juste assez d'ordre pour que le minimum (ou le maximum) soit toujours accessible en tête. Cette structure, c'est le tas binaire (binary heap) : insertion et extraction en O(log n), consultation du minimum en O(1).

Le besoin : une file de priorité

Une file de priorité expose trois opérations : insérer un élément, consulter l'élément prioritaire, et le défiler (l'extraire). La « priorité » est ici l'ordre naturel des valeurs ; nous construirons un tas-min, où l'élément prioritaire est le plus petit.

Comment l'implémenter naïvement ? Avec un tableau trié, l'extraction du min est en O(1) mais l'insertion en O(n) (il faut décaler). Avec un tableau non trié, l'insertion est en O(1) mais l'extraction en O(n) (il faut chercher le min). Le tas binaire offre un compromis bien meilleur : O(log n) des deux côtés.

Le tas binaire : un arbre complet dans un tableau

Un tas-min est un arbre binaire qui respecte deux propriétés. D'abord il est complet : tous les niveaux sont remplis de gauche à droite, sans trou (le dernier niveau peut être partiel, mais seulement à droite). Ensuite il respecte la propriété de tas : chaque parent est inférieur ou égal à ses enfants. Conséquence directe : la racine contient toujours le minimum global.

Attention, le tas n'est pas trié : deux frères ne sont pas ordonnés entre eux, et un nœud profond peut être plus petit qu'un nœud d'un autre sous-arbre. La seule garantie est la relation parent-enfant le long de chaque branche.

Comme l'arbre est complet, on n'a pas besoin de pointeurs ni d'objets nœuds : on le range tel quel dans un tableau, niveau par niveau, de gauche à droite. La racine est à l'index 0.

Les index dans le tableau

C'est l'astuce qui rend le tas si efficace. Pour un nœud à l'index i :

  • enfant gauche : 2 * i + 1
  • enfant droit : 2 * i + 2
  • parent : Math.floor((i - 1) / 2)

Vérifions sur le tableau [1, 3, 2, 8, 9, 5, 7]. Le nœud d'index 1 (valeur 3) a pour enfants les index 3 et 4 (valeurs 8 et 9), et pour parent l'index 0 (valeur 1). Tout est cohérent : 1 ≤ 3, 3 ≤ 8, 3 ≤ 9. La navigation dans l'arbre devient de la pure arithmétique d'index, sans la moindre allocation.

Insérer : ajouter puis remonter

Pour insérer, on ajoute la nouvelle valeur à la fin du tableau : l'arbre reste complet. Mais la propriété de tas peut être violée si l'élément est plus petit que son parent. On le fait alors remonter (percolate up / sift up) : tant qu'il est plus petit que son parent, on les échange. On s'arrête dès qu'il est ≥ à son parent, ou qu'il atteint la racine.

La remontée parcourt au pire toute la hauteur de l'arbre. Un arbre binaire complet de n nœuds a une hauteur de l'ordre de log₂(n), d'où une insertion en O(log n).

Extraire le min : remplacer puis descendre

Le minimum est la racine (index 0). On ne peut pas simplement la retirer : cela laisserait un trou. La technique :

  1. mémoriser la racine (le min à renvoyer) ;
  2. retirer le dernier élément du tableau et le placer à la racine : l'arbre reste complet ;
  3. faire descendre ce nouvel élément (percolate down / sift down) : tant qu'il est plus grand que l'un de ses enfants, on l'échange avec le plus petit des deux enfants.

Pourquoi le plus petit enfant ? Parce qu'il doit devenir le nouveau parent, il faut donc qu'il soit ≤ à l'autre enfant : on remonte le plus petit. Là encore on parcourt au pire la hauteur de l'arbre : extraction en O(log n).

Implémentation : la classe TasMin

Le champ privé #tas garantit que personne ne casse les invariants de l'extérieur. Toute la logique passe par inserer et extraireMin.

Déroulé pas à pas

Insérons successivement 5, 3, 8, 1 dans un tas-min vide.

  • inserer(5) : tableau [5]. Rien à remonter.
  • inserer(3) : on pousse → [5, 3]. L'index 1 (3) a pour parent l'index 0 (5). 3 < 5 → échange → [3, 5].
  • inserer(8) : on pousse → [3, 5, 8]. L'index 2 (8) a pour parent l'index 0 (3). 8 ≥ 3 → rien. Tableau [3, 5, 8].
  • inserer(1) : on pousse → [3, 5, 8, 1]. L'index 3 (1) a pour parent l'index 1 (5). 1 < 5 → échange → [3, 1, 8, 5]. Le 1 est maintenant à l'index 1, parent index 0 (3). 1 < 3 → échange → [1, 3, 8, 5].

État final : [1, 3, 8, 5], la racine vaut bien 1. Maintenant extraireMin() :

  • min = 1. On retire le dernier (5) et on le met à la racine → [5, 3, 8].
  • Descente depuis l'index 0 (5) : enfants index 1 (3) et index 2 (8). Le plus petit est 3 < 5 → échange → [3, 5, 8].
  • Le 5 est à l'index 1, sans enfant valide (index 3 et 4 hors tableau) → arrêt.

On renvoie 1, le tas devient [3, 5, 8] dont la racine 3 est le nouveau minimum. Tout est cohérent.

Analyse de complexité : temps et espace

La hauteur d'un tas de n éléments est ⌊log₂(n)⌋. Remontée et descente parcourent au pire cette hauteur, en faisant un travail constant par niveau (une comparaison, un échange).

OpérationTempsPourquoi
voirMinO(1)simple lecture de l'index 0
insererO(log n)remontée sur la hauteur de l'arbre
extraireMinO(log n)descente sur la hauteur de l'arbre
tailleO(1)length du tableau

Espace : O(n) : on stocke uniquement les n valeurs dans le tableau, sans nœuds ni pointeurs supplémentaires. La remontée et la descente sont écrites en boucle itérative : leur espace auxiliaire est O(1) (une version récursive coûterait O(log n) de pile). Trier d'abord puis défiler coûterait O(n log n) ; le tas distille ce coût opération par opération.

Variantes et usages

Un tas-max s'obtient en inversant les comparaisons (parent ≥ enfants), ou plus simplement en insérant les valeurs négatives dans un tas-min. Pour des objets, on remplace les comparaisons directes par une fonction de priorité (ex. a.priorite - b.priorite).

Les files de priorité sont partout : l'algorithme de Dijkstra (plus court chemin) extrait à chaque étape le sommet le plus proche encore non traité ; un ordonnanceur de tâches élit la tâche la plus urgente ; le problème des top-K éléments (les K plus grands) se résout avec un tas-min de taille K ; la fusion de k listes triées garde un tas des k têtes de listes courantes.

Cas réel — GPS, compression et ordonnancement

La file de priorité est le moteur discret de beaucoup d'outils quotidiens. Ton GPS calcule un itinéraire avec l'algorithme de Dijkstra, qui pioche à chaque étape, dans un tas-min, le carrefour le plus proche encore non traité — sans tas, le calcul sur un réseau routier entier serait inutilisable. La compression ZIP, JPEG ou MP3 construit un code de Huffman en fusionnant à répétition les deux symboles les moins fréquents, extraits d'un tas-min. Enfin, un ordonnanceur de système d'exploitation ou une file de jobs élit la tâche la plus prioritaire via un tas. À chaque fois, la même promesse : le prochain élément prioritaire en O(log n), quel que soit le volume.

Pièges fréquents

Piège fréquent

Se tromper dans les formules d'index. Le parent est Math.floor((i - 1) / 2), pas i / 2 : avec une racine à l'index 0, c'est le - 1 qui rétablit l'arithmétique. Vérifie toujours sur un petit exemple : l'enfant gauche de la racine (i=0) doit être l'index 1, et le parent de l'index 1 doit retomber sur l'index 0.

Piège fréquent

Oublier de rétablir la propriété de tas. Après un push, il faut remonter ; après avoir mis le dernier élément à la racine, il faut descendre. Sans cela, la structure n'est plus un tas et voirMin renvoie n'importe quoi. Et à la descente, on échange avec le plus petit des deux enfants, jamais le premier venu : sinon on risque de placer un parent supérieur à l'autre enfant.

Note

Ne confonds pas le tas (heap, la structure de données vue ici) avec le « tas » mémoire (heap au sens allocation dynamique, opposé à la pile/stack). Même mot français, deux notions sans rapport.

Pour aller plus loin

Pour aller plus loin

On peut construire un tas en O(n) (et non O(n log n)) : c'est le heapify de Floyd. On part du tableau brut et on applique descendre à tous les nœuds internes, du dernier vers la racine ; l'analyse fine montre que la somme des coûts est linéaire. Ce heapify alimente le tri par tas (heap sort) : on heapifie, puis on extrait le min n fois → tri en O(n log n) avec O(1) d'espace auxiliaire. Au-delà du tas binaire, les tas d-aires (d enfants par nœud) réduisent la hauteur au prix d'une descente plus coûteuse, et les tas de Fibonacci offrent une diminution de clé amortie en O(1), utile pour accélérer Dijkstra en théorie.

Récap et vérification

  • Une file de priorité défile l'élément le plus prioritaire ; un tas binaire l'implémente efficacement.
  • Tas-min = arbre binaire complet où chaque parent ≤ ses enfants ; rangé dans un tableau, racine en 0.
  • Index pour un nœud i : enfants 2i+1 et 2i+2, parent Math.floor((i-1)/2).
  • Insérer = pousser en fin puis remonter : O(log n). Extraire le min = racine, mettre le dernier à la racine puis descendre : O(log n).
  • Consulter le min : O(1). Espace : O(n), avec remontée/descente itératives en O(1) auxiliaire.
  • Usages : Dijkstra, ordonnancement, top-K, fusion de k listes triées.

Vérifie ta compréhension

  1. Dans un tableau-tas, quel est l'index du parent du nœud à l'index 7 ? Et ses deux enfants ?
  2. Après extraireMin, pourquoi place-t-on le dernier élément à la racine plutôt qu'un des enfants de la racine ?
  3. Pourquoi l'insertion et l'extraction sont-elles en O(log n) et non en O(n) ?

Glossaire

File de priorité
Structure abstraite qui rend toujours l'élément le plus prioritaire (ici le plus petit), quelle que soit sa date d'insertion.
Tas binaire (heap)
Arbre binaire complet respectant la propriété de tas ; réalise une file de priorité efficace.
Tas-min / tas-max
Tas où chaque parent est ≤ (min) ou ≥ (max) ses enfants ; la racine est donc le minimum (ou le maximum) global.
Arbre complet
Arbre dont tous les niveaux sont remplis de gauche à droite, sans trou ; c'est ce qui permet le rangement en tableau.
Propriété de tas
Relation parent-enfant (parent ≤ enfants) le long de chaque branche ; elle n'ordonne pas les frères entre eux.
Remontée (sift-up)
Après un ajout en fin, échange de l'élément avec son parent tant qu'il est plus petit ; rétablit la propriété de tas en O(log n).
Descente (sift-down)
Après avoir placé le dernier élément à la racine, échange avec le plus petit enfant tant que nécessaire ; O(log n).
Heapify
Construction d'un tas à partir d'un tableau brut en O(n) (algorithme de Floyd), base du tri par tas.
