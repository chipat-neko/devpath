Projets JavaScript : apprendre en construisant

La théorie ne suffit pas — il faut construire. Ce cours te fait bâtir quinze applications de A à Z. Pour chaque projet, on commence par la logique (que tu testes en direct dans l'éditeur intégré), puis on la branche à une interface.

Bien s'équiper

Les extensions VS Code pour tes projets JavaScript

Avant de te lancer, ouvre le panneau Extensions de VS Code (Ctrl+Shift+X) et installe ces incontournables : ils apportent la coloration, l'auto-complétion (IntelliSense) et les outils adaptés à ce cours.

À installer pour tes projets

  • ESLint (Microsoft) — qualité du code en continu.
  • Prettier - Code formatter (Prettier) — mise en forme automatique.
  • Live Server (Ritwick Dey) — aperçu live de ton application web.
  • Path Intellisense (Christian Kohler) — complète les chemins.
  • npm Intellisense (Christian Kohler) — complète les imports de paquets.

Prérequis

Ces projets supposent les bases du cours « des bases au niveau confirmé » : fonctions, tableaux, objets, DOM et événements. On ne réexplique pas ces notions, on les met en pratique.

Éditeur intégré

Sur les exemples de logique, un bouton « ▶ Tester » apparaît : tu peux modifier le code et l'exécuter directement dans la page, et voir le résultat dans la console. Idéal pour expérimenter chaque fonction avant de la brancher à l'interface.

Ce que tu vas construire

Quinze applications, une méthode

À la fin du cours, tu auras construit

  • une calculatrice (logique d'évaluation + interface au clavier) ;
  • un quiz interactif (moteur de questions, score, progression) ;
  • un gestionnaire de budget (modèle de données, totaux, persistance) ;
  • un générateur de mots de passe (aléatoire, options, robustesse) ;
  • un jeu de morpion (état du plateau, détection de victoire) ;
  • un minuteur Pomodoro (machine à états, cycles travail/pause) ;
  • une application météo (consommer une API, fetch et affichage) ;
  • un jeu du serpent (logique de jeu, rendu canvas et boucle animée) ;
  • trois projets bonus autour des API du navigateur : un éditeur de dessin (Canvas), un visualiseur audio (Web Audio) et un tableau Kanban en glisser-déposer ;
  • un jeu du pendu et un jeu de Memory (état, mélange non biaisé, verrou) ;
  • une liste de tâches filtrable (vues dérivées, formulaire, persistance) ;
  • en projet final, un suivi d'habitudes qui assemble toute la méthode (modèle, statistiques dérivées, grille, localStorage).

La méthode : logique d'abord, interface ensuite

Chaque projet se construit en deux temps. D'abord la logique pure : des fonctions claires, testables et indépendantes de l'affichage — c'est là que l'éditeur intégré prend tout son sens, puisque tu exécutes et ajustes ton code à la volée. Ensuite seulement, on branche l'interface (DOM, événements, parfois localStorage) pour rendre l'application vivante.

Cette séparation n'est pas qu'un confort pédagogique : c'est une bonne pratique professionnelle. Une logique isolée est plus simple à comprendre, à tester et à réutiliser.
