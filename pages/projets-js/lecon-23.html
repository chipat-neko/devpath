Une liste de tâches filtrable

~35 min Intermédiaire Cours Projets recommandé

À la fin de cette leçon, tu sauras

  • modéliser une liste de tâches par un tableau d'objets { id, texte, faite } ;
  • ajouter une tâche via un formulaire avec preventDefault, la basculer et la supprimer ;
  • filtrer l'affichage (tous / actifs / terminés) sans jamais toucher aux données ;
  • persister l'ensemble dans localStorage et tout redessiner depuis l'état.
Sommaire de la leçon

La liste de tâches est le « hello world » de la construction d'applications : assez simple pour tenir dans une leçon, assez riche pour révéler la bonne architecture. Ce n'est pas un hasard si le célèbre projet TodoMVC l'a choisie pour comparer des dizaines de frameworks — tout le monde sait à quoi ça doit ressembler, donc on juge le code, pas l'idée.

On y retrouve le fil conducteur de tout ce cours : un état qui est la seule vérité, et une fonction rendre() qui reconstruit l'affichage à partir de lui. La nouveauté de cette leçon, c'est la notion de vue dérivée : un filtre ne modifie pas les données, il choisit seulement ce qu'on montre.

Le modèle : un tableau de tâches

Chaque tâche est un petit objet : un identifiant stable, un texte, et un booléen « faite ? ». L'identifiant compte : c'est lui qu'on manipulera pour basculer ou supprimer, jamais la position dans le tableau (qui change quand on supprime).

Le trim() retire les espaces en trop et le garde-fou if (propre === "") refuse une tâche vide : deux réflexes qui évitent des lignes fantômes dans la liste.

Basculer et supprimer par identifiant

Deux opérations pures agissent sur l'état. Basculer retourne le drapeau faite d'une tâche ; supprimer reconstruit le tableau sans elle. On repère toujours la tâche par son id.

Attention

Ne supprime jamais une tâche par sa position (taches.splice(2, 1)) au moment d'un clic : dès qu'une tâche a été retirée plus haut, les indices se décalent et tu effaces la mauvaise ligne. L'identifiant reste stable : c'est lui la bonne clé.

Les filtres : des vues dérivées

Voici l'idée centrale de la leçon. On veut trois affichages : tous, seulement les actifs, seulement les terminés. La tentation du débutant est de supprimer des tâches de la liste pour « cacher » celles qui ne correspondent pas. C'est une erreur : on perdrait les données. Le bon réflexe : garder toutes les tâches en mémoire et calculer, à l'affichage, le sous-ensemble visible.

Le formulaire d'ajout

On saisit une tâche dans un champ, on valide avec la touche Entrée ou un bouton. Un <form> déclenche par défaut un rechargement de la page : il faut l'empêcher avec event.preventDefault(), sinon l'application repart de zéro à chaque ajout.

Astuce

Écoute l'événement submit du formulaire, pas le click du bouton : ainsi la touche Entrée valide aussi, gratuitement. Un formulaire bien fait est accessible au clavier sans effort supplémentaire.

Dessiner depuis l'état

Une seule fonction rendre() reconstruit la liste. Elle lit la vue filtrée, crée une ligne par tâche, et met à jour le compteur de tâches restantes. Pour le texte saisi par l'utilisateur, on utilise textContent (jamais innerHTML) : aucun risque d'injection de code.

Brancher les boutons de filtre

Trois boutons changent la variable filtre puis redessinent. On marque le bouton actif d'une classe pour le style. Comme rendre() relit filtre à chaque fois, l'affichage se met à jour tout seul.

Cas réel — TodoMVC, l'étalon des frameworks

Le projet TodoMVC (todomvc.com) réimplémente exactement cette application — ajout, bascule, suppression, filtres « All / Active / Completed », persistance — dans React, Vue, Svelte, Angular et des dizaines d'autres. Pourquoi cette liste de tâches précise ? Parce qu'elle contient juste ce qu'il faut de logique d'état, de vues dérivées et de persistance pour comparer honnêtement deux outils. La comprendre en JavaScript pur, comme ici, c'est déjà comprendre ce que ces frameworks automatisent pour toi.

Persister dans localStorage

Comme le budget et le Kanban, on rend la liste durable. localStorage ne stocke que du texte : on sérialise avec JSON.stringify à l'écriture, et on relit avec JSON.parse, en se protégeant du premier lancement (rien de stocké) et d'une donnée illisible.

Pièges fréquents

Piège fréquent

Filtrer en supprimant les tâches non concernées : on perd les données. Le filtre doit rester une vue calculée ; les données complètes ne bougent pas.

Piège fréquent

Oublier preventDefault() dans le submit : la page se recharge, la tâche semble « disparaître » et l'état repart à zéro. Le réflexe : première ligne du gestionnaire.

Piège fréquent

Injecter le texte avec innerHTML : une tâche nommée <img onerror=…> deviendrait du code exécuté. textContent traite tout comme du texte : sûr par défaut.

Pour aller plus loin

Pour aller plus loin

Ajoute l'édition en place (double-clic sur une tâche pour la renommer), un bouton « effacer les terminées » (taches = taches.filter(t => !t.faite)), le glisser-déposer pour réordonner (revois le Kanban de la leçon 19), ou une synchronisation entre onglets avec l'événement storage. Pour l'accessibilité, remplace le clic sur le texte par une vraie case à cocher (<input type="checkbox">) reliée à un <label>.

Antisèche — la liste de tâches

Glossaire

Vue dérivée
Affichage calculé à partir de l'état sans le modifier ; ici, la liste filtrée renvoyée par tachesVisibles() selon le filtre courant.
Identifiant (id)
Clé stable attachée à chaque tâche pour la retrouver de façon fiable, indépendamment de sa position dans le tableau.
filter
Méthode de tableau qui renvoie un nouveau tableau des éléments satisfaisant une condition ; sert à supprimer une tâche et à calculer les vues.
preventDefault()
Appel qui annule le comportement par défaut d'un événement ; sur un submit, empêche le rechargement de la page.
textContent
Propriété qui lit ou écrit le texte d'un élément sans interpréter de HTML ; sûre contre l'injection, contrairement à innerHTML.
Sérialisation
Transformation d'une structure (tableau, objet) en texte avec JSON.stringify pour la stocker, puis relue avec JSON.parse.

Récap et vérification

  • Une tâche est un objet { id, texte, faite } ; on la manipule par son id.
  • Les filtres sont des vues dérivées : on garde toutes les données, on calcule ce qu'on montre.
  • Le formulaire d'ajout appelle preventDefault() pour ne pas recharger la page.
  • Une seule fonction rendre() reconstruit l'affichage ; le texte passe par textContent.
  • La liste survit au rechargement grâce à localStorage et à JSON.

Vérifie ta compréhension

  1. Pourquoi filtrer sans supprimer de tâches du tableau ?
  2. Que se passe-t-il si on oublie preventDefault() dans le submit ?
  3. Pourquoi manipuler les tâches par leur id et non par leur position ?
