Module 01 · Les bases de Go — Leçon 01

Découvrir Go

~28 min Intermédiaire Des bases en programmation aident

À la fin de cette leçon, tu sauras

  • expliquer ce qui fait la philosophie de Go (simplicité, compilation native, un seul binaire) ;
  • écrire, compiler et lancer un premier programme avec go run et go build ;
  • comprendre le rôle de package main, func main et de gofmt ;
  • distinguer un nom exporté (Majuscule) d'un nom non exporté (minuscule).
Sommaire de la leçon

Bienvenue dans le monde de Go (souvent écrit Golang pour les recherches). Go est un langage volontairement petit : on peut tenir sa grammaire en tête, il se lit presque comme de l'anglais, et il compile en un clin d'œil vers un binaire autonome. Si tu viens d'un autre langage, oublie un instant tes habitudes : ici, on cherche le chemin le plus simple, pas le plus malin.

Dans cette première leçon, tu vas écrire, compiler et lancer ton premier programme, puis découvrir l'outillage qui rend Go si agréable au quotidien. Aucune ligne ne s'exécute dans le navigateur : Go se compile et tourne en natif sur ta machine, dans un terminal.

Go en bref

Go est né chez Google en 2009, pensé par des ingénieurs qui voulaient un langage rapide à compiler, simple à lire, et taillé pour les serveurs modernes. Quelques traits marquants :

  • Compilé et rapide : ton code devient du code machine natif, pas besoin d'interpréteur à l'exécution.
  • Simple : très peu de mots-clés (25), une seule façon de faire les choses la plupart du temps.
  • Un binaire autonome : go build produit un exécutable unique, sans dépendances à installer chez l'utilisateur.
  • Garbage collector : la mémoire est gérée pour toi, sans free manuel.

On le retrouve partout dans le cloud et l'infrastructure : Docker et Kubernetes sont écrits en Go, comme une grande partie des services back-end et des outils en ligne de commande (CLI) modernes.

Note

Go moderne (depuis la version 1.21) inclut les génériques et un outillage très mûr. Dans ce cours, on suppose toujours une version récente : pense à mettre à jour si la tienne date.

  • package main : tout fichier Go appartient à un package. Le package main est spécial : c'est lui qui produit un programme exécutable.

Astuce

Retiens la règle simple : go run pour essayer vite pendant que tu codes, go build pour produire un exécutable à livrer.

gofmt : le formatage imposé

Dans la plupart des langages, on débat sans fin du style : tabulations ou espaces, accolade sur la même ligne ou non… Go tranche pour toi avec gofmt, un formateur officiel qui réécrit ton code dans l'unique style canonique. Plus de débat, plus de guerre de virgules.

Écris ton code un peu de travers, lance go fmt, et il ressort parfaitement aligné. Tous les projets Go du monde se ressemblent : c'est ce qui les rend si faciles à lire d'un dépôt à l'autre. La plupart des éditeurs lancent gofmt automatiquement à chaque sauvegarde.

Note

Go utilise des tabulations pour l'indentation, pas des espaces. C'est gofmt qui décide, donc tu n'as pas à y penser.

La philosophie de Go

Si tu ne devais retenir qu'une chose : Go privilégie la simplicité et la lisibilité sur l'astuce. Le code Go est fait pour être lu par d'autres humains, des années plus tard, sans surprise. Quelques principes que tu croiseras tout au long du cours :

  • Un seul moyen de faire les choses : peu de sucre syntaxique, peu d'options. Tu passes moins de temps à choisir.
  • Les erreurs sont des valeurs explicites : pas d'exceptions cachées. On vérifie une erreur juste après l'appel, en clair.
  • « Accept interfaces, return structs » : un idiome courant qui consiste à accepter des interfaces en paramètre (souple) mais à renvoyer des types concrets (clairs). On y reviendra avec les interfaces.

Packages et noms exportés

Go n'a pas de mots-clés public ou private. La visibilité dépend d'une règle d'une simplicité désarmante : la première lettre du nom.

  • Un nom qui commence par une Majuscule est exporté : visible depuis d'autres packages (l'équivalent de « public »).
  • Un nom qui commence par une minuscule reste interne au package (l'équivalent de « privé »).

C'est pour cela que tu écris fmt.Println avec un grand P : Println est exporté par le package fmt. Un nom en minuscule comme println ne serait pas accessible de l'extérieur.

Cette convention te donne instantanément la frontière publique d'un package, juste en lisant les noms. Encore une fois : une règle, pas dix.

Pièges fréquents

Piège fréquent

Oublier package main ou func main() : sans eux, Go ne sait pas produire d'exécutable. Le compilateur se plaint d'un point d'entrée manquant ou d'un package inattendu.

Go est strict, et c'est volontaire. Deux erreurs de compilation surprennent souvent les débutants :

  • Import non utilisé : si tu importes un package sans t'en servir, le code ne compile pas.
  • Variable non utilisée : déclarer une variable locale sans jamais la lire est aussi une erreur de compilation.

Ce n'est pas une brimade : ces règles gardent ton code propre, sans imports morts ni variables fantômes. Supprime simplement la ligne en trop, et tout compile.

Piège fréquent

Confondre go run et go build : go run ne laisse aucun fichier derrière lui, alors que go build crée un exécutable sur le disque. Si tu cherches ton binaire après un go run, tu ne le trouveras pas.

Pour aller plus loin

Pour aller plus loin

Explore le Go Playground (go.dev/play) pour tester du code en ligne sans rien installer, et la commande go doc fmt.Println pour lire la documentation d'une fonction directement dans le terminal.

  • Modules : les projets Go modernes utilisent les modules (un fichier go.mod créé par go mod init), qui ont remplacé l'ancien système GOPATH. On les verra bientôt.
  • Outillage intégré : Go fournit tout dans une seule commande. go vet repère des erreurs courantes, go test lance tes tests, go fmt formate. Pas de configuration interminable.

Un cas réel : le binaire unique qui simplifie tout

Cas réel

Une équipe distribuait un petit outil en ligne de commande écrit en Python. À chaque installation chez un client, la même corvée : installer le bon Python, créer un environnement virtuel, résoudre les versions de bibliothèques — et parfois « ça marche chez moi » mais pas sur le serveur du client. En réécrivant l'outil en Go, tout a changé : go build produit un seul fichier exécutable, sans dépendance externe. On le copie sur la machine cible et il tourne, point. Mieux : en fixant GOOS et GOARCH, la même source se compile pour Windows, macOS et Linux depuis un unique poste. Ce n'est pas un cas isolé : si Docker et Kubernetes sont écrits en Go, c'est en grande partie pour cette raison — livrer un binaire autonome, portable et rapide, sans imposer d'installer un runtime. La leçon : le « un seul binaire » de Go n'est pas un détail, c'est souvent la raison de le choisir.

Glossaire

Go (Golang)
Langage compilé né chez Google en 2009 : simple, rapide à compiler, produit un binaire natif autonome ; très utilisé pour le cloud et les outils CLI.
Package
Unité d'organisation du code Go ; tout fichier appartient à un package. Le package main est celui qui produit un exécutable.
func main()
Point d'entrée du programme : la fonction exécutée au lancement, dans le package main.
go run
Compile et exécute en une fois, sans écrire de fichier : pratique pour tester pendant le développement.
go build
Compile et écrit un binaire autonome sur le disque, lançable et distribuable sans Go installé.
gofmt
Formateur officiel qui réécrit le code dans l'unique style canonique : fin des débats de mise en forme, tous les projets Go se ressemblent.
Nom exporté
Identifiant commençant par une majuscule, visible depuis d'autres packages (l'équivalent de « public ») ; en minuscule, il reste interne.
Garbage collector
Mécanisme qui libère automatiquement la mémoire inutilisée : en Go, pas de free manuel à écrire.

Récap et vérification

  • Go est compilé, simple, et produit un binaire autonome ; il sert surtout pour les services cloud et les outils CLI.
  • Un programme exécutable commence par package main et une fonction func main().
  • go run compile et exécute d'un coup ; go build produit un exécutable réutilisable.
  • gofmt impose un style unique : fin des débats de mise en forme.
  • Un import ou une variable non utilisé provoque une erreur de compilation.
  • Un nom en Majuscule est exporté (public), en minuscule il reste interne au package.
