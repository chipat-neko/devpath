Module 01 · Les bases de Go — Leçon 02

Types, variables et fonctions

~28 min Intermédiaire Leçon 1 recommandée

À la fin de cette leçon, tu sauras

  • Savoir déclarer des variables avec var et la forme courte :=, et connaître les valeurs zéro ;
  • Savoir écrire des fonctions Go, y compris avec retours multiples et valeurs nommées ;
  • Savoir utiliser const, iota et la conversion explicite de types ;
  • Savoir manipuler closures, defer et pointeurs (&, *).
Sommaire de la leçon

Go cherche la simplicité : peu de mots-clés, une syntaxe régulière, et un compilateur qui te force à rester propre. Dans cette leçon, tu poses les fondations : comment déclarer des variables, quels types existent, comment écrire des fonctions, et deux outils typiquement Go que tu croiseras partout — defer et les pointeurs.

Tout le code se compile avec go build (ou go run) et s'exécute en natif. On montre la sortie attendue directement en commentaire (// ...) pour que tu puisses comparer.

Les variables : var et la forme courte :=

La déclaration complète utilise var, avec un type explicite et une valeur optionnelle. Mais en pratique, à l'intérieur d'une fonction, tu écriras presque toujours la déclaration courte :=, qui déclare la variable et infère son type d'après la valeur.

Les trois formes coexistent, mais := est la plus idiomatique dans une fonction.

Note

Le := ne fonctionne qu'à l'intérieur d'une fonction. Au niveau du package (en dehors de toute fonction), tu dois utiliser var.

Les types de base et les valeurs zéro

Go propose des types numériques (int, float64...), bool, string, et deux alias utiles : byte (un octet, alias de uint8) et rune (un point de code Unicode, alias de int32). Particularité Go : une variable déclarée sans valeur reçoit sa valeur zéro. Pas de variable « non initialisée », pas de surprise.

La valeur zéro vaut 0, "" ou false — jamais nil pour ces types de base.

Go ne convertit jamais les types implicitement. Pour mélanger un int et un float64, tu dois convertir explicitement avec type(valeur).

float64(i) transforme l'int en float64 avant l'addition.

Les constantes et iota

Une const est figée à la compilation. Le mot-clé iota sert à générer des séries d'entiers : il vaut 0 sur la première ligne d'un bloc const et s'incrémente à chaque ligne suivante.

iota évite de numéroter les constantes à la main.

Les fonctions et les retours multiples

Une fonction se déclare avec func, ses paramètres typés, puis son type de retour. Quand plusieurs paramètres partagent le même type, tu peux factoriser : func add(a, b int). L'idiome le plus marquant de Go, ce sont les retours multiples — c'est ainsi que Go renvoie un résultat et une erreur.

divmod renvoie deux valeurs, récupérées en une seule ligne avec q, r :=.

Tu peux aussi nommer les valeurs de retour. Elles se comportent alors comme des variables locales initialisées à leur valeur zéro, et un return nu les renvoie.

Pratique pour documenter ce que la fonction renvoie, mais à utiliser avec parcimonie pour rester lisible.

La fonction comme valeur, les closures

En Go, une fonction est une valeur comme une autre : tu peux la stocker dans une variable, la passer en argument, ou en renvoyer une. Une fonction anonyme qui capture des variables de son entourage est une closure.

Chaque appel à nouveauCompteur crée un total indépendant : la closure le garde vivant entre les appels.

defer : différer un appel

defer reporte l'exécution d'un appel jusqu'à la fin de la fonction englobante. On l'utilise surtout pour les nettoyages (fermer un fichier, libérer une ressource) — le code de libération reste juste à côté de l'ouverture. Si plusieurs defer s'empilent, ils s'exécutent dans l'ordre inverse (le dernier déclaré part en premier).

Les defer se dépilent à la sortie de main, dans l'ordre inverse de leur déclaration.

Les pointeurs : & et *

Un pointeur stocke l'adresse d'une variable. En Go, ils restent simples : &x donne l'adresse de x, et *p donne (ou modifie) la valeur pointée. Il n'y a pas d'arithmétique de pointeurs comme en C — c'est volontaire, pour la sûreté.

Passer &x permet à la fonction de modifier la variable d'origine, et non une copie.

Astuce

Laisse gofmt (ou go fmt) formater ton code automatiquement : indentation par tabulations, alignement, espaces. Tout le code Go du monde se ressemble, et c'est une force.

Pièges fréquents

Piège fréquent

Une variable déclarée mais jamais utilisée est une erreur de compilation, pas un simple avertissement. Pareil pour un import inutilisé. Go t'oblige à garder le code propre.

  • := hors fonction : interdit. Au niveau du package, utilise var.
  • Oublier la conversion explicite : int + float64 ne compile pas. Convertis avec float64(x).
  • Ignorer une valeur de retour : si une fonction renvoie deux valeurs et que tu n'en veux qu'une, utilise le blank identifier _ pour jeter l'autre : q, _ := divmod(17, 5).
  • Confondre := et = : := déclare une nouvelle variable, = assigne à une variable existante. Réutiliser := sans aucune nouvelle variable à gauche provoque une erreur.

Un cas réel : le defer qui a tari une fuite de ressources

Cas réel

Un service Go ouvrait une connexion à la base à chaque requête, puis la fermait à la fin de la fonction. Tout allait bien… jusqu'aux chemins d'erreur. Quand une requête échouait en cours de route, la fonction faisait un return anticipé — en sautant le Close() écrit tout en bas. Sous forte charge, ces connexions non fermées s'accumulaient : au bout de quelques heures, le pool était épuisé et le service refusait toute nouvelle requête. Le correctif a tenu en une ligne : placer defer conn.Close() juste après l'ouverture. Le defer garantit l'exécution du Close() à la sortie de la fonction, quel que soit le chemin — succès, erreur, return anticipé ou même panique. La fuite a disparu. C'est exactement pourquoi l'idiome Go veut qu'on écrive la libération collée à l'acquisition : f, _ := os.Open(...) puis defer f.Close() à la ligne suivante. On ne peut plus l'oublier.

Glossaire

Déclaration courte (:=)
Déclare une variable et infère son type d'après la valeur ; utilisable uniquement dans une fonction. Au niveau du package, on emploie var.
Valeur zéro
Valeur par défaut de toute variable déclarée sans initialisation : 0 pour les nombres, "" pour les chaînes, false pour les booléens.
iota
Compteur du bloc const qui vaut 0 sur la première ligne et s'incrémente ensuite : pratique pour générer des séries d'entiers.
Retours multiples
Une fonction Go peut renvoyer plusieurs valeurs ; l'idiome (résultat, error) est la façon standard de signaler une erreur.
Closure
Fonction anonyme qui capture des variables de sa portée englobante et les garde vivantes entre les appels (chaque closure a son propre état).
defer
Diffère un appel jusqu'à la fin de la fonction englobante ; les defer empilés se dépilent en ordre inverse (LIFO). Idéal pour libérer une ressource.
Pointeur (&, *)
&x donne l'adresse de x ; *p lit ou modifie la valeur pointée. Pas d'arithmétique de pointeurs, pour la sûreté.
Blank identifier (_)
Reçoit et écarte une valeur dont on ne veut pas, sans créer de variable inutilisée (qui serait une erreur de compilation).

Récap et vérification

  • var déclare partout, := déclare et infère uniquement dans une fonction.
  • Chaque type a une valeur zéro : 0, "", false.
  • Aucune conversion implicite : convertis avec float64(x), int(f)...
  • const et iota génèrent des constantes, notamment des séries.
  • Les fonctions peuvent renvoyer plusieurs valeurs (idiome Go) et nommer leurs retours.
  • Les closures capturent leur environnement ; defer diffère un appel ; les pointeurs (&, *) restent simples, sans arithmétique.
