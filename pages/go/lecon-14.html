JSON et sérialisation

~36 min Intermédiaire Leçon 4 recommandée

À la fin de cette leçon, tu sauras

  • encoder une valeur Go en JSON avec json.Marshal et contrôler la sortie avec les tags de struct ;
  • décoder du JSON dans une struct ou une map avec json.Unmarshal, et gérer les champs absents ou inconnus ;
  • traiter un flux JSON avec json.Encoder et json.Decoder ;
  • sérialiser correctement les dates (time.Time, RFC 3339) et éviter les pièges de casse et de champs non exportés.
Sommaire de la leçon

Dès qu'un programme Go parle au monde extérieur — une API web, un fichier de configuration, un message entre services — il échange presque toujours du JSON. La bibliothèque standard fournit tout ce qu'il faut dans un seul package : encoding/json. Cette leçon en fait le tour : transformer une valeur Go en texte JSON (sérialiser) et reconstruire une valeur Go depuis du texte JSON (désérialiser).

Tout se compile avec go run main.go et n'utilise que la stdlib. Les sorties sont mises en commentaire dans le code.

Sérialiser : de la struct au JSON avec Marshal

json.Marshal prend n'importe quelle valeur et renvoie une slice d'octets ([]byte) contenant sa représentation JSON, plus une erreur.

Deux points essentiels dès maintenant : Marshal renvoie des octets (on les convertit en string pour les afficher), et seuls les champs exportés (qui commencent par une majuscule) sont encodés. Un champ en minuscule est invisible pour le package json.

Piège fréquent

Un champ non exporté (minuscule) n'est jamais sérialisé et reste vide au décodage. Si ton JsON sort « vide » ou s'il manque des champs, vérifie d'abord les majuscules. C'est l'erreur numéro un des débutants en Go.

Les tags de struct : contrôler le JSON produit

Par défaut, la clé JSON reprend le nom du champ Go (Nom, Prix…). Or les API attendent presque toujours du snake_case ou du camelCase. Les tags de struct, écrits entre backticks après le type, pilotent ce rendu.

  • json:"nom" renomme la clé.
  • omitempty supprime la clé si le champ vaut sa valeur zéro (0, "", false, nil).
  • json:"-" exclut totalement le champ, même exporté.

Astuce

MarshalIndent est parfait pour un fichier de config lisible ou du débogage, mais pèse plus d'octets. Pour une API à fort trafic, garde Marshal (compact) : chaque octet d'espace envoyé est du réseau gaspillé multiplié par le nombre de requêtes.

Désérialiser : du JSON à la struct avec Unmarshal

Le sens inverse : json.Unmarshal prend des octets JSON et un pointeur vers la valeur à remplir. Le pointeur est indispensable — sinon Go ne pourrait pas modifier ta variable.

Le décodage est insensible à la casse pour apparier les clés : "nom", "Nom" ou "NOM" rempliront tous le champ taggé nom. Les clés du JSON absentes de la struct sont ignorées silencieusement ; les champs de la struct absents du JSON gardent leur valeur zéro.

Quand la forme est inconnue : map et any

Parfois tu ne connais pas la structure à l'avance (réponse hétérogène, JSON exploratoire). Tu peux décoder dans une map[string]any.

Piège fréquent

Dans une map[string]any, tout nombre JSON devient un float64, jamais un int. Une assertion m["prix"].(int) paniquera. Préfère toujours une struct typée quand tu connais la forme : c'est plus sûr, plus rapide et auto-documenté.

Encoder et Decoder : travailler en flux

Marshal et Unmarshal chargent tout en mémoire. Pour lire ou écrire directement depuis un flux (une requête HTTP, un fichier, l'entrée standard), Go fournit json.NewEncoder(w) et json.NewDecoder(r), qui travaillent sur n'importe quel io.Writer ou io.Reader.

C'est exactement ce qu'on utilise dans un handler HTTP : json.NewEncoder(w).Encode(reponse) écrit la réponse sans jamais construire de gros tampon. Côté lecture, json.NewDecoder(r.Body).Decode(&v) lit et décode le corps de la requête.

Le temps et les types personnalisés

time.Time sait déjà se sérialiser : il produit une chaîne au format RFC 3339 (une norme de date ISO). C'est parce qu'il implémente les interfaces json.Marshaler et json.Unmarshaler.

Tu peux donner ce même pouvoir à tes propres types en implémentant MarshalJSON() ([]byte, error). C'est ainsi qu'on encode par exemple une énumération sous forme de texte plutôt que de nombre.

Note

La stdlib ne valide pas les champs « obligatoires » : un JSON sans la clé id laisse simplement ID à 0, sans erreur. Pour exiger des champs ou des formats précis, on ajoute une bibliothèque de validation (comme go-playground/validator) ou on vérifie à la main après décodage.

Un cas réel : le champ fantôme

Cas réel

Une équipe branche un nouveau service Go sur une API partenaire. En test, tout marche ; en production, le champ montant arrive systématiquement à 0. Après une heure de logs, le coupable : la struct déclarait montant float64 — en minuscule. Le champ n'étant pas exporté, encoding/json l'ignorait purement et simplement, sans la moindre erreur. Une majuscule et un tag json:"montant" plus tard, tout rentrait dans l'ordre. La morale : en Go, un décodage JSON silencieusement vide est presque toujours une histoire de majuscule manquante ou de nom de clé qui ne correspond pas. Quand un doute subsiste, décode d'abord dans une map[string]any pour voir ce que l'API envoie vraiment.

Glossaire

Sérialiser / désérialiser
Transformer une valeur en mémoire en texte (ici JSON) et l'opération inverse. En Go : Marshal et Unmarshal.
json.Marshal
Encode une valeur Go en JSON et renvoie une slice d'octets ([]byte) plus une erreur.
json.Unmarshal
Décode des octets JSON dans une valeur Go ; exige un pointeur pour pouvoir écrire dedans.
Champ exporté
Champ dont le nom commence par une majuscule ; seul un champ exporté est visible par encoding/json.
Tag de struct
Métadonnée entre backticks (`json:"nom,omitempty"`) qui pilote la clé et les options d'encodage d'un champ.
omitempty
Option de tag qui retire la clé de la sortie quand le champ vaut sa valeur zéro (0, "", false, nil).
json.Encoder / Decoder
Variantes en flux qui écrivent sur un io.Writer ou lisent depuis un io.Reader, sans tampon complet en mémoire.
RFC 3339
Format texte normalisé des dates (2026-07-22T14:30:00Z) que time.Time produit et lit automatiquement en JSON.

Récap et vérification

  • json.Marshal encode (→ []byte), json.Unmarshal décode (→ exige un pointeur).
  • Seuls les champs exportés (majuscule) sont sérialisés ; les tags renomment les clés et ajoutent des options (omitempty, -).
  • Pour une forme inconnue, map[string]any — mais tout nombre y devient un float64.
  • json.Encoder/Decoder travaillent en flux, idéals pour HTTP et les fichiers.
  • time.Time se sérialise en RFC 3339 ; tes types peuvent faire pareil via MarshalJSON.
