Module 01 · Les bases de Go — Leçon 04

Structures et méthodes

~35 min Intermédiaire Leçon 3 recommandée

À la fin de cette leçon, tu sauras

  • Savoir définir une structure avec type ... struct et la créer avec des champs nommés ;
  • Savoir attacher une méthode à un type via un récepteur et choisir entre récepteur valeur et pointeur ;
  • Savoir composer des types par embedding plutôt que par héritage ;
  • Savoir écrire un constructeur idiomatique NewT(...) et reconnaître les tags de struct.
Sommaire de la leçon

En Go, il n'y a pas de classes. Pour modéliser une donnée — un point, un rectangle, un utilisateur — tu assembles des champs dans une structure (struct). Pour lui donner du comportement, tu attaches des méthodes : ce sont de simples fonctions avec un récepteur. C'est tout. Pas d'héritage, pas de hiérarchie compliquée : juste des données et des fonctions, organisées simplement.

Dans cette leçon, tu vas apprendre à définir des structs, à leur attacher des méthodes, à choisir entre récepteur par valeur et par pointeur, à composer des types par embedding, et à écrire des constructeurs idiomatiques. Tout cela se compile avec go build et s'exécute en natif.

Définir et créer une structure

Une struct regroupe plusieurs champs sous un même type. Le mot-clé type donne un nom à ce regroupement. Les champs de même type peuvent être déclarés sur une seule ligne.

Une struct créée avec des champs nommés. Les champs omis prennent leur valeur zéro.

Astuce

Préfère toujours les champs nommés (Point{X: 1, Y: 2}) à l'ordre positionnel (Point{1, 2}). Si quelqu'un ajoute un champ plus tard, ton code positionnel casse ; le code nommé continue de compiler. Au passage, gofmt indente avec des tabulations : laisse-le formater, c'est la norme partagée par tout le code Go.

Attacher une méthode

Une méthode est une fonction avec un récepteur placé entre func et le nom. Le récepteur indique sur quel type la méthode s'applique. Go n'a pas de classes : la méthode vit à côté du type, pas dedans.

La méthode Distance s'appelle avec la notation pointée p.Distance().

Note

Le récepteur se nomme par convention par une ou deux lettres du type (ici p pour Point). Évite this ou self : ce n'est pas idiomatique en Go. À noter aussi : on ne peut définir une méthode que sur un type déclaré dans le même package que la méthode.

Récepteur par valeur ou par pointeur

C'est le choix le plus important. Un récepteur par valeur (p Point) reçoit une copie : modifier ses champs ne change pas l'original. Un récepteur par pointeur (p *Point) reçoit l'adresse : les modifications affectent l'original.

Valeur = copie jetée. Pointeur = modification réelle de l'original.

La règle pratique : utilise un récepteur pointeur si la méthode doit modifier le récepteur, ou si la struct est grosse (pour éviter une copie coûteuse à chaque appel). Sinon, un récepteur valeur convient pour les types petits et immuables. Et surtout : reste cohérent sur un même type — soit tout en pointeur, soit tout en valeur.

Pointeurs vers struct et accès automatique

Go simplifie l'usage des pointeurs sur les structs. Pas besoin de déréférencer manuellement avec (*p).X : Go le fait pour toi. p.X fonctionne que p soit une valeur ou un pointeur.

L'accès aux champs et l'appel de méthode marchent indifféremment sur valeur ou pointeur.

Note

Cette conversion automatique entre p et &p ne marche que sur une valeur adressable (une variable). Tu ne peux pas appeler une méthode pointeur directement sur un résultat temporaire comme Point{X: 1}.Deplacer(...) : le compilateur refuse.

Composer par embedding

Plutôt que l'héritage, Go propose la composition via l'embedding : tu intègres un type dans un autre sans lui donner de nom de champ. Les champs et méthodes du type intégré deviennent accessibles directement, comme s'ils appartenaient au type englobant.

L'embedding « remonte » champs et méthodes du type intégré vers le type englobant.

Piège fréquent

L'embedding n'est pas de l'héritage. Personne n'est pas un sous-type d'Adresse : c'est une Personne qui contient une Adresse. Pense « a une » (composition), pas « est une » (héritage). Si le type englobant définit un champ ou une méthode du même nom, c'est lui qui l'emporte : il faut alors qualifier explicitement, par exemple p.Adresse.Ville.

Constructeurs idiomatiques

Go n'a pas de constructeur intégré. La convention est d'écrire une fonction NewT(...) (exportée, en Majuscule) qui valide les données, applique des valeurs par défaut, et renvoie souvent un pointeur *T.

Un constructeur valide les entrées et renvoie (*Compte, error) de façon explicite.

Les tags de struct (survol)

Chaque champ peut porter un tag : une chaîne entre backticks qui décrit comment le champ doit être traité par certaines bibliothèques, notamment encoding/json. C'est une simple métadonnée, lue par réflexion.

Les tags json:"..." contrôlent le nom des clés et leur omission.

Note

Pour que encoding/json voie un champ, il doit être exporté (en Majuscule) : json.Marshal ignore les champs non exportés, tag ou pas. Le tag ne fait que renommer la clé, pas exposer un champ caché.

Pièges fréquents

Piège fréquent

Utiliser un récepteur valeur alors qu'on veut modifier la struct : l'original reste inchangé, la modification part avec la copie. Si une méthode mute le récepteur, elle doit être en pointeur (p *T).

  • Mélanger valeur et pointeur sur un même type sème la confusion (et complique l'implémentation d'interfaces). Choisis l'un ou l'autre et garde-le pour toutes les méthodes du type.
  • Copier une grosse struct par valeur à chaque appel coûte cher en mémoire et en temps. Passe par pointeur dès que la struct grossit.
  • Struct vide vs nil : une struct{} (ou une struct à zéro) n'est pas nil ; seul un pointeur de struct peut valoir nil. Déréférencer un pointeur nil avec p.X provoque une panique.
  • Croire que l'embedding est de l'héritage : c'est de la composition. Pas de polymorphisme par classe parente ; pour le polymorphisme, on utilise les interfaces (leçon suivante).

Pour aller plus loin

Pour aller plus loin

Les interfaces (leçon suivante) donnent du polymorphisme à tes structs. Le package encoding/json exploite les tags pour la sérialisation. L'embedding fonctionne aussi avec des interfaces, et c'est le cœur du débat « composition vs héritage » : Go choisit résolument la composition.

Un cas réel : la méthode qui ne sauvegardait jamais rien

Cas réel

Dans une boutique en ligne écrite en Go, la méthode func (p Panier) Ajouter(a Article) ajoutait bien l'article à p.Articles… mais le panier restait toujours vide à l'affichage. La cause : le récepteur était une valeur (p Panier), donc chaque appel travaillait sur une copie du panier, jetée aussitôt. Pire, certains tests unitaires passaient (ils inspectaient une copie renvoyée), ce qui masquait le bug jusqu'à l'intégration. Une seule lettre a tout corrigé : func (p *Panier) Ajouter(...), récepteur pointeur, qui modifie le panier réel. Depuis, l'équipe applique la règle : si une méthode mute le récepteur, elle est en pointeur — et par cohérence, tout le jeu de méthodes du type l'est aussi.

Antisèche

Glossaire

Structure (struct)
Type qui regroupe plusieurs champs nommés sous un même nom : l'équivalent Go d'un enregistrement. Go n'a pas de classes.
Champ
Variable membre d'une struct, accessible avec le point (p.X) ; un champ non renseigné prend la valeur zéro de son type.
Méthode
Fonction attachée à un type via un récepteur placé entre func et le nom ; s'appelle avec la notation pointée p.Methode().
Récepteur
Paramètre spécial d'une méthode qui indique le type sur lequel elle s'applique ; par valeur (copie) ou par pointeur (original).
Récepteur pointeur
Récepteur de forme (p *T) : la méthode reçoit l'adresse et peut modifier le récepteur ou éviter de copier une grosse struct.
Embedding
Intégration d'un type dans un autre sans nom de champ ; les champs et méthodes du type intégré sont promus. C'est de la composition, pas de l'héritage.
Constructeur idiomatique
Fonction NewT(...) (*T, error) qui valide les données et renvoie une valeur prête à l'emploi ; Go n'a pas de constructeur intégré.
Tag de struct
Chaîne entre backticks accolée à un champ (`json:"nom"`), lue par réflexion pour piloter des bibliothèques comme encoding/json.

Récap et vérification

  • Une struct regroupe des champs ; on la crée avec des champs nommés et on accède aux champs avec ..
  • Une méthode est une fonction avec un récepteur ; Go n'a pas de classes.
  • Récepteur valeur = copie (ne modifie pas) ; récepteur pointeur = modifie l'original. Reste cohérent par type.
  • Go déréférence automatiquement : p.X et p.Methode() marchent sur valeur comme sur pointeur adressable.
  • L'embedding compose les types (remonte champs et méthodes) : c'est de la composition, pas de l'héritage.
  • Le constructeur idiomatique est une fonction NewT(...) (*T, error) qui valide les données.
