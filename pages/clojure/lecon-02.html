Module 1 · Les bases de Clojure — Leçon 02

Données et S-expressions

~50 min Avancé Prérequis : leçon 1

À la fin de cette leçon, tu sauras

  • manier les types de base (nombres, chaînes, booléens, nil) ;
  • utiliser les keywords (:cle) et les symboles ;
  • comprendre l'évaluation et le quote ;
  • lire la notation préfixe et l'imbrication.
Sommaire de la leçon

Avant d'écrire des programmes, il faut connaître la matière première de Clojure : ses données. Là où d'autres langages séparent nettement la syntaxe (mots-clés, opérateurs) des valeurs, Clojure efface presque cette frontière. Le code que tu écris est une structure de données. Cette leçon explore les littéraux de base et la règle d'évaluation qui les anime.

Tout ce que tu tapes dans le REPL est une expression : Clojure la lit, l'évalue, et te rend une valeur. Comprendre cette règle, c'est comprendre 80 % du langage.

Les nombres, chaînes et booléens

Clojure dispose des types scalaires usuels, avec quelques particularités héritées de la JVM : les entiers sont des long (64 bits), et il existe des entiers arbitrairement grands (BigInt, suffixe N) et des rationnels exacts.

Le rationnel 1/3 est une vraie nouveauté : (+ 1/3 1/3 1/3) donne exactement 1, sans erreur d'arrondi. Précieux pour les calculs exacts.

Des nombres qui ne mentent pas

En JavaScript, 0.1 + 0.2 donne 0.30000000000000004 (arrondi binaire des flottants). Clojure évite ce piège quand on utilise les rationnels : (+ 1/10 2/10) vaut exactement 3/10. Pour des calculs où la précision compte (finance, comptages), les fractions exactes et les BigInt (suffixe N) sont un vrai filet de sécurité — à condition de rester dans le rationnel et de ne pas repasser en double.

Les keywords : l'étiquette de Clojure

Un keyword (mot-clé) commence par deux-points : :nom, :age, :ville. C'est une valeur constante, qui se représente elle-même, idéale comme clé dans une map ou comme étiquette symbolique. On les croise partout en Clojure.

Pense aux keywords comme à des « noms qui ne valent qu'eux-mêmes » : pas besoin de les déclarer, ils existent dès qu'on les écrit, et deux keywords identiques sont la même valeur (économie de mémoire, comparaison instantanée).

Les symboles

Un symbole est un nom sans deux-points : x, +, println. Normalement, évaluer un symbole renvoie ce à quoi il réfère (la valeur liée à ce nom).

Distinction clé : :age (keyword) vaut toujours :age ; age (symbole) vaut ce qu'on lui a lié. L'un est une donnée constante, l'autre est une référence.

La règle d'évaluation

Voici le cœur de Clojure. Quand le langage évalue une expression :

  • un nombre, une chaîne, un keyword, un booléen, nil s'évaluent en eux-mêmes ;
  • un symbole s'évalue en la valeur à laquelle il est lié ;
  • une liste (f a b) est un appel : on évalue f (qui doit être une fonction), puis les arguments, puis on applique.

Empêcher l'évaluation : le quote

Parfois, on veut une liste comme donnée, sans l'appeler. On la quote avec une apostrophe ' : Clojure renvoie alors la liste littérale au lieu de l'évaluer.

Cette dualité — une liste est tantôt du code, tantôt une donnée — est l'homoiconicité. C'est elle qui rendra les macros possibles (leçon 8).

Cas réel

Cette dualité code/donnée n'est pas une curiosité théorique : dans un vrai projet Clojure, le fichier de configuration deps.edn (ou project.clj) est littéralement une donnée Clojure — une map de keywords, de vecteurs et de chaînes. Là où d'autres écosystèmes inventent un format à part (YAML, TOML, JSON), Clojure réutilise sa propre notation : configurer un projet, c'est écrire de la donnée du langage. Un même lecteur sert au code, aux données échangées (EDN) et à la config — une seule syntaxe à apprendre.

Pièges fréquents

Piège fréquent

Confondre :nom (keyword, donnée constante) et nom (symbole, référence). Si tu écris (println age) sans avoir lié age, Clojure proteste : « Unable to resolve symbol ». Avec un keyword :age, aucun souci : il vaut toujours lui-même.

Pour aller plus loin

Pour aller plus loin

Le format EDN (Extensible Data Notation) est le « JSON de Clojure » : il utilise exactement cette même syntaxe de données (nombres, chaînes, keywords, vecteurs, maps) pour échanger ou stocker des données. Comme le code et les données partagent la même notation, lire un fichier de configuration Clojure, c'est lire de la donnée Clojure native.

Glossaire

Scalaire
Valeur atomique : nombre, chaîne, caractère, booléen ou nil.
Rationnel
Nombre représenté comme une fraction exacte (1/3), sans erreur d'arrondi, contrairement à un flottant.
Keyword (mot-clé)
Valeur constante préfixée par : (:age) qui se désigne elle-même ; idéale comme clé de map.
Symbole
Nom sans deux-points (x, +) qui, évalué, renvoie la valeur à laquelle il est lié.
nil
L'absence de valeur en Clojure (équivalent de null) ; considéré comme « faux » dans un test.
Quote (')
Marque qui empêche l'évaluation : '(+ 1 2) renvoie la liste littérale au lieu de l'appeler.
Homoiconicité
Propriété selon laquelle le code a la même forme que les données (des listes) ; fondement des macros.
EDN
Extensible Data Notation : le format de données de Clojure (le « JSON de Clojure »), même syntaxe que le code.

Récap et vérification

  • Scalaires : entiers (long, BigInt en N), rationnels exacts (1/3), chaînes, nil.
  • Keywords (:cle) : constantes qui valent elles-mêmes, parfaites comme clés.
  • Symboles (x) : noms qui réfèrent à une valeur liée.
  • Règle : une liste est un appel ; le quote ' la rend comme donnée.

Vérifie ta compréhension

  1. Quelle différence entre :age et age ?
  2. Que vaut '(+ 1 2) et pourquoi ?
  3. Pourquoi (+ 1/3 1/3 1/3) donne-t-il exactement 1 ?

Exercice 3Défi

Sans l'exécuter, explique pourquoi (1 2 3) provoque une erreur mais '(1 2 3) non.

Voir une solution

(1 2 3) est une liste, donc Clojure tente de l'appeler : il prend 1 pour une fonction et applique 2 et 3 — or 1 n'est pas une fonction, d'où l'erreur. '(1 2 3) est quotée : Clojure la traite comme une simple donnée (une liste de trois nombres), sans tenter d'appeler quoi que ce soit.
