Polymorphisme : protocols et records

~50 min Avancé Prérequis : leçon 9

À la fin de cette leçon, tu sauras

  • définir une abstraction avec defprotocol ;
  • créer un type avec defrecord ;
  • comprendre les multimethods (defmulti/defmethod) ;
  • choisir entre protocols et multimethods.
Sommaire de la leçon

Jusqu'ici, on a modélisé nos données avec des maps et manipulé tout par des fonctions. C'est souple, mais quand un programme grandit, on a besoin d'abstractions et de polymorphisme : faire qu'un même appel se comporte différemment selon le type de donnée. Clojure offre trois outils pour cela, chacun à sa place : les protocols, les records et les multimethods. Cette leçon t'apprend à structurer du code polymorphe à la manière de Clojure.

Les protocols : des interfaces

Un protocol déclare un ensemble de fonctions que différents types pourront implémenter — exactement comme une interface dans d'autres langages. On le définit avec defprotocol.

Le protocol Forme annonce deux opérations, aire et perimetre, sans dire comment les calculer. Chaque type qui adopte Forme devra les fournir. C'est un contrat partagé.

Les records : des types de données

Un record (defrecord) crée un type concret avec des champs nommés. Contrairement à une map ordinaire, un record est plus rapide et peut implémenter des protocols directement.

->Cercle est le constructeur généré automatiquement. Chaque record implémente Forme à sa façon. L'appel (aire c) est polymorphe : Clojure choisit la bonne implémentation selon le type de c. Un record reste une map : on accède à ses champs par keyword ((:rayon c)).

Les multimethods : répartir sur une valeur calculée

Les protocols répartissent sur le type du premier argument. Mais parfois, on veut choisir l'implémentation selon une valeur arbitraire (un champ, une combinaison). Les multimethods le permettent : on fournit une fonction de répartition qui calcule une clé, et on définit une méthode par clé.

Ici, decrire répartit sur :type. La grande force : la fonction de dispatch peut être n'importe quoi — on pourrait répartir sur (juxt :type :age), sur une plage, etc. Les multimethods offrent un polymorphisme bien plus libre que la répartition sur le seul type.

Protocols ou multimethods ?

Deux outils, deux usages :

  • Protocols : répartition sur le type, très rapides, idéaux pour un ensemble d'opérations sur des types fermés (comme une interface). C'est le choix par défaut.
  • Multimethods : répartition sur une valeur calculée, plus lents mais plus flexibles, parfaits quand le critère n'est pas le type (par ex. une étiquette dans une map).

Un cas concret

Cas réel

Un service reçoit des webhooks de plateformes externes (Stripe, GitHub…). Chaque message porte un champ :event — "payment.succeeded", "issue.opened", etc. Un multimethod (defmulti traiter :event) route chaque type d'événement vers sa defmethod dédiée. Le gain : prendre en charge un nouvel événement, c'est ajouter une defmethod, sans toucher au code existant ni gonfler un énorme case. Chaque équipe peut même ajouter ses méthodes depuis son propre fichier : l'expression problem résolu en douceur.

Un record reste une map

On lit ses champs par keyword ((:rayon c)) et on le met à jour par assoc (ce qui préserve le type record). Attention toutefois : faire dissoc d'un champ déclaré le fait « retomber » en map ordinaire. En pratique, commence toujours par une simple map ; ne passe au record que si tu as besoin d'implémenter un protocol ou d'un gain de performance mesuré.

Pièges fréquents

Piège fréquent

Atteindre trop vite les records et protocols par réflexe « orienté objet ». En Clojure, on modélise par défaut avec des maps simples et des fonctions : c'est plus souple et plus composable. Les protocols/records ne se justifient que lorsqu'on a besoin de polymorphisme performant ou d'interopérer avec Java. Ne crée pas une hiérarchie de types là où une map et quelques fonctions suffisent.

Pour aller plus loin

Pour aller plus loin

Les protocols résolvent un problème célèbre, le « expression problem » : pouvoir ajouter à la fois de nouveaux types et de nouvelles opérations sans modifier le code existant. Avec extend-protocol, on peut même faire qu'un type déjà existant (y compris une classe Java) implémente un protocol après coup. Cette extensibilité ouverte est l'une des forces discrètes de Clojure.

Glossaire

Polymorphisme
Faire qu'un même appel se comporte différemment selon la donnée reçue.
Protocol
Ensemble d'opérations (une interface) que des types implémentent ; répartition sur le type du premier argument.
Record
Type concret à champs nommés (defrecord), plus rapide qu'une map et capable d'implémenter des protocols ; reste une map.
Multimethod
Fonction polymorphe (defmulti/defmethod) qui répartit sur une valeur calculée.
Fonction de dispatch
Fonction qui, pour un multimethod, calcule la clé servant à choisir la defmethod.
:default
Méthode d'un multimethod utilisée quand aucune clé ne correspond.
Expression problem
Pouvoir ajouter à la fois de nouveaux types et de nouvelles opérations sans modifier le code existant ; ce que permettent protocols et multimethods.
extend-protocol
Fait implémenter un protocol par un type déjà existant (y compris une classe Java) après coup.

Récap et vérification

  • Protocol (defprotocol) : une interface (ensemble d'opérations) répartie sur le type.
  • Record (defrecord) : un type concret à champs nommés, rapide, qui implémente des protocols ; constructeur ->Nom.
  • Multimethod (defmulti/defmethod) : répartition sur une valeur calculée (très flexible).
  • Par défaut, modéliser avec des maps + fonctions ; protocols/records seulement si polymorphisme/perf le justifient.
