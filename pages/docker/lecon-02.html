Module 1 · Les conteneurs — Leçon 02

Images et conteneurs en pratique

~35 min Débutant Leçon 01 requise

À la fin de cette leçon, tu sauras

  • récupérer une image avec docker pull ;
  • lancer un conteneur avec docker run (et ses options) ;
  • lister et inspecter avec ps, entrer avec exec ;
  • arrêter, supprimer et nettoyer.
Sommaire de la leçon

Assez de théorie : lançons des conteneurs. Docker se pilote presque entièrement depuis le terminal, avec une poignée de commandes que tu utiliseras tous les jours. Cette leçon te fait manipuler des images et des conteneurs réels — récupérer, lancer, inspecter, nettoyer. C'est le vocabulaire de base de tout utilisateur de Docker.

Récupérer et lancer

La commande docker run est centrale : elle crée et démarre un conteneur à partir d'une image. Si l'image n'est pas présente localement, Docker la télécharge d'abord depuis le Docker Hub (équivalent d'un docker pull implicite).

docker run suit la forme docker run [options] IMAGE [commande]. Sans commande, l'image exécute son programme par défaut. Le couple -it est l'idiome pour entrer interactivement dans un conteneur : indispensable pour explorer.

Les options qui comptent

Quelques options de run reviennent constamment :

Décortiquons : -d rend la main au terminal (le serveur tourne en fond) ; -p hôte:conteneur relie un port de ta machine à un port du conteneur (on y revient en leçon 4) ; --name évite d'avoir à retenir l'identifiant aléatoire généré par Docker. Sans --name, Docker invente un nom rigolo comme nostalgic_einstein.

Lister et inspecter

Pour voir ce qui tourne et ce qui est installé :

docker ps est le tableau de bord : il montre l'identifiant, l'image, le statut et les ports de chaque conteneur actif. docker logs est ton premier réflexe de débogage : c'est là que s'affichent les messages et les erreurs de l'application conteneurisée.

Entrer dans un conteneur

Pour exécuter une commande à l'intérieur d'un conteneur qui tourne déjà, on utilise docker exec. C'est l'outil pour inspecter ou déboguer en direct.

Différence importante avec run : run crée un nouveau conteneur, tandis que exec agit sur un conteneur déjà lancé. On entre ainsi dans un service vivant pour vérifier un fichier, tester une connexion ou lire une configuration.

Cas réel : diagnostiquer un service qui répond mal

Un site conteneurisé renvoie des erreurs 502. Le réflexe : d'abord docker logs -f web pour lire les messages en direct ; puis docker exec -it web bash pour entrer dans le conteneur vivant et vérifier qu'un fichier de configuration existe, qu'un dossier est bien monté, ou tester une connexion à la base avec curl. Ce duo logs + exec résout la grande majorité des incidents sans jamais toucher au conteneur en le recréant.

Arrêter et nettoyer

Les conteneurs et images s'accumulent vite. Voici comment faire le ménage :

Un conteneur arrêté n'est pas supprimé : il reste listé par docker ps -a et occupe de l'espace. docker rm l'efface ; docker system prune fait un grand ménage d'un coup. Prends l'habitude de nettoyer : sinon, le disque se remplit d'anciens conteneurs et d'images obsolètes.

Piège fréquent

Après un docker stop web, tu relances docker run -d -p 8080:80 --name web nginx et Docker refuse : le nom web est déjà pris. C'est trompeur, car docker ps ne montre plus rien : le conteneur arrêté existe toujours et n'apparaît que dans docker ps -a. Pour repartir, fais docker start web, qui relance l'existant, ou supprime-le d'abord avec docker rm web : run crée toujours un conteneur neuf.

Le conteneur jetable : --rm

Pour un test rapide, ajoute --rm : docker run --rm -it python:3.12 python. Le conteneur se supprime tout seul à sa sortie : aucun résidu à nettoyer ensuite. Idéal pour essayer une image, lancer un script ponctuel ou ouvrir un interpréteur, sans polluer docker ps -a.

Données éphémères

Par défaut, tout ce qu'un conteneur écrit dans son propre système de fichiers disparaît quand on le supprime. C'est voulu : un conteneur est jetable. Pour conserver des données (une base, des fichiers), il faut des volumes — l'objet de la leçon 4. Ne stocke jamais de données précieuses dans un conteneur sans volume.

Glossaire

run
Crée et démarre un nouveau conteneur à partir d'une image (qu'elle télécharge au besoin).
pull
Télécharge une image depuis un registre sans lancer de conteneur.
Détaché (-d)
Mode « arrière-plan » : le conteneur tourne et le terminal reste libre.
Publication de port (-p)
Relie un port de l'hôte à un port du conteneur, au format hôte:conteneur ; sans elle, le service est injoignable de l'extérieur.
exec
Exécute une commande (souvent un shell) dans un conteneur déjà en cours, sans en créer un nouveau.
logs
Affiche la sortie du conteneur (sortie standard et sortie d'erreur) ; avec -f, la suit en direct : premier réflexe de débogage.
prune
Élague d'un coup les ressources inutilisées (conteneurs arrêtés, réseaux, images orphelines) pour libérer le disque.
Conteneur jetable (--rm)
Conteneur qui se supprime automatiquement à sa sortie : parfait pour un test ponctuel.

Récap et vérification

  • docker run [options] IMAGE crée et démarre un conteneur (télécharge l'image au besoin).
  • Options clés : -d (arrière-plan), -p hôte:conteneur (ports), -it (interactif), --name.
  • docker ps/ps -a listent ; docker logs affiche la sortie ; docker exec -it … bash entre dans un conteneur vivant.
  • stop/rm/rmi arrêtent et suppriment ; system prune nettoie. Les données d'un conteneur sont éphémères.

Vérifie ta compréhension

  1. Que fait docker run -d -p 8080:80 nginx ?
  2. Quelle différence entre docker run et docker exec ?
  3. Pourquoi docker ps ne montre-t-il pas un conteneur arrêté ?

Exercice 3Défi

Voir une solution

Il faut d'abord stop (un conteneur en cours ne peut pas être supprimé directement sans -f), puis rm. system prune efface ensuite les conteneurs arrêtés, réseaux et images orphelins.
