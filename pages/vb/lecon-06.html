Collections et gestion d'erreurs

~45 min Intermédiaire Prérequis : leçon 5

À la fin de cette leçon, tu sauras

  • utiliser Collection et Dictionary ;
  • gérer les erreurs en VBA (On Error) ;
  • gérer les erreurs en VB.NET (Try/Catch) ;
  • écrire du code robuste.
Sommaire de la leçon

Les tableaux gèrent bien des séries numérotées, mais on a souvent besoin de structures plus souples : une liste qui grandit toute seule, ou un annuaire qui associe une clé à une valeur. Visual Basic offre pour cela les collections et les dictionnaires. Et puisqu'un programme réel rencontre toujours des imprévus — un fichier absent, une saisie incorrecte — cette leçon couvre aussi la gestion des erreurs, indispensable pour un code robuste.

La collection : une liste flexible

Une Collection stocke une suite d'éléments sans qu'on ait à fixer sa taille : on ajoute, on retire, on parcourt. Pratique quand le nombre d'éléments varie.

Attention : une Collection est indexée à partir de 1 (et non 0). .Add ajoute, .Count compte, .Remove retire. For Each la parcourt élégamment.

Le dictionnaire : associer clé et valeur

Un Dictionary associe une clé à une valeur — idéal pour un annuaire, un comptage, une table de correspondance. En VBA, il provient de la bibliothèque Microsoft Scripting Runtime.

L'accès par clé (ages("Ada")) est immédiat, sans parcourir toute la structure. .Exists teste la présence d'une clé ; c'est l'outil parfait pour « ai-je déjà vu cette valeur ? » — par exemple dédoublonner une liste.

Gérer les erreurs en VBA : On Error

VBA utilise un mécanisme historique : On Error. On indique vers quelle étiquette sauter en cas d'erreur, et on traite le problème là-bas.

L'objet Err décrit l'erreur (Err.Description, Err.Number). Le Exit Sub avant l'étiquette évite d'exécuter la gestion quand tout s'est bien passé. Variante : On Error Resume Next ignore l'erreur et continue — à utiliser avec prudence.

Gérer les erreurs en VB.NET : Try / Catch

VB.NET dispose du mécanisme moderne Try … Catch … Finally, bien plus structuré : le code risqué va dans Try, le traitement de l'erreur dans Catch, et le nettoyage éventuel dans Finally.

Le bloc Finally s'exécute dans tous les cas (erreur ou non) : parfait pour fermer un fichier ou libérer une ressource. C'est l'approche à privilégier en VB.NET.

Le Dictionary joue le rôle d'un « ensemble » : .Exists empêche d'ajouter deux fois la même clé, et vus.Count donne à la fin le nombre de valeurs distinctes. Ce motif est au cœur de presque toutes les macros de nettoyage de données.

Pièges fréquents

Piège fréquent

Abuser de On Error Resume Next en VBA pour « faire taire » les erreurs. Cela masque les problèmes au lieu de les traiter : le code continue dans un état incohérent, et le bug réapparaît plus loin, indéchiffrable. Réserve Resume Next aux cas précis où une erreur est attendue et bénigne, et réactive aussitôt la gestion avec On Error GoTo 0. Sinon, traite l'erreur explicitement.

Pour aller plus loin

Pour aller plus loin

Le Dictionary est souvent l'outil qui transforme une macro lente en macro instantanée. Pour rapprocher deux listes (par exemple retrouver, pour chaque client, sa commande), une double boucle naïve compare tout à tout — coûteux. En chargeant une liste dans un Dictionary indexé par clé, chaque recherche devient immédiate. C'est l'équivalent VBA du RECHERCHEV d'Excel, mais programmable et bien plus rapide sur de gros volumes.

Glossaire

Collection
Objet VBA stockant une suite d'éléments de taille variable, indexée à partir de 1 (.Add, .Count, .Remove).
Dictionary
Structure associant une clé unique à une valeur ; accès direct par la clé, sans parcours.
Clé / valeur
Dans un dictionnaire, la clé est l'identifiant de recherche (unique), la valeur est la donnée qui lui est associée.
Exists
Méthode d'un Dictionary renvoyant True si une clé est présente — pratique pour dédoublonner ou compter.
On Error GoTo
Mécanisme de gestion d'erreurs de VBA : détourne l'exécution vers une étiquette dès qu'une erreur survient.
Err
Objet VBA décrivant la dernière erreur : Err.Number (code) et Err.Description (message).
Try / Catch / Finally
Gestion d'erreurs structurée de VB.NET : code risqué dans Try, traitement dans Catch, nettoyage garanti dans Finally.
Exception
Objet représentant une erreur en VB.NET ; ex.Message en donne la description lisible.

Récap et vérification

  • Collection : liste flexible, indexée à partir de 1 (.Add, .Count, For Each).
  • Dictionary : associe clé→valeur ; accès immédiat, .Exists teste une clé.
  • Erreurs en VBA : On Error GoTo + objet Err ; en VB.NET : Try/Catch/Finally.
  • Finally s'exécute toujours ; éviter d'abuser de On Error Resume Next.
