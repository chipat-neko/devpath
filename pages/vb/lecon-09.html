Module 3 · VB en pratique — Leçon 09

Outils, écosystème et au-delà

~40 min Avancé Prérequis : leçon 8

À la fin de cette leçon, tu sauras

  • utiliser Visual Studio et l'éditeur VBA ;
  • situer l'avenir et les usages de VB ;
  • comparer VB et C# ;
  • savoir où continuer.
Sommaire de la leçon

Tu as couvert l'essentiel de Visual Basic : la syntaxe, les structures, l'automatisation Office avec VBA et les applications VB.NET. Pour clore ce cours, prenons du recul : quels outils utiliser, quel est l'avenir de VB, comment il se compare à C#, et comment continuer. De quoi situer ce que tu as appris dans le paysage réel.

Les outils : éditeur VBA et Visual Studio

Selon que tu fais du VBA ou du VB.NET, l'environnement diffère :

  • pour VBA : l'éditeur intégré à Office, ouvert par Alt+F11 dans Excel, Word ou Access. Rien à installer : il est déjà là ;
  • pour VB.NET : Visual Studio (l'édition Community est gratuite), un environnement complet avec concepteur visuel, débogueur et complétion intelligente.

L'éditeur VBA reste rustique mais suffisant pour les macros ; Visual Studio est un outil professionnel de premier plan.

L'enregistreur de macros, encore

On l'a évoqué : en VBA, l'enregistreur de macros (onglet Développeur d'Excel) génère du code à partir de tes actions. C'est à la fois un gain de temps et un excellent professeur : enregistre, lis le code, comprends, nettoie. Beaucoup d'automaticiens chevronnés ont commencé ainsi.

L'avenir de Visual Basic

Soyons clairs : Microsoft a annoncé que VB.NET resterait stable mais n'évoluerait plus activement ; les nouveautés du langage vont à C#. Cela ne signifie pas la mort de VB :

  • VBA reste solidement intégré à Office et n'est pas près de disparaître : trop de macros en dépendent ;
  • VB.NET continue de fonctionner et d'être supporté ; l'immense parc d'applications existantes doit être maintenu ;
  • la lisibilité de VB en fait toujours un bon premier langage et un outil d'automatisation accessible.

Apprendre VB reste donc utile : pour automatiser ton travail, maintenir l'existant, et aborder en douceur des concepts qu'on retrouve partout.

VB.NET ou C# ?

Les deux partagent la même plateforme .NET : ils sont équivalents en puissance, seule la syntaxe change. Comparons une même idée :

Pour de nouveaux projets .NET, C# est aujourd'hui le choix par défaut (plus de ressources, d'évolutions, d'offres d'emploi). Mais comme les concepts sont identiques, ton apprentissage de VB.NET se transpose presque directement : c'est notre cours C# qui t'attend pour franchir le pas.

Pour continuer

  • Automatiser une tâche réelle de ton quotidien avec une macro VBA — le meilleur exercice qui soit.
  • Installer Visual Studio Community et créer une petite application Windows Forms.
  • Explorer le modèle objet d'Excel (la documentation Microsoft est complète).
  • Comparer ton code VB avec son équivalent C# pour préparer la transition.

Cas réel : le rapport du lundi matin

Cas réel — une heure gagnée chaque semaine

Dans un service comptable, un employé passait chaque lundi près d'une heure à consolider un fichier Excel : importer l'export de la semaine, nettoyer les colonnes, calculer les totaux, mettre en forme. Une macro VBA — quelques dizaines de lignes réunissant ce que tu as vu dans ce cours (boucles, Range/Cells, Split, un Dictionary) — fait désormais tout en trois secondes, d'un seul clic. Sur une année, c'est près d'une cinquantaine d'heures rendues à un travail plus utile. Voilà le vrai retour sur investissement de VBA : pas des applications spectaculaires, mais des corvées quotidiennes qui disparaissent.

Pièges fréquents

Piège fréquent

Croire qu'apprendre VB est « dépassé » et donc inutile. C'est une erreur de perspective : VBA est l'un des moyens les plus rentables d'automatiser un travail de bureau aujourd'hui, sur n'importe quel poste équipé d'Office. Et les concepts que tu as appris — variables typées, boucles, procédures, objets, événements — sont universels. Tu ne perds rien : tu acquiers des bases solides, transférables à C#, Python ou n'importe quel langage.

Pour aller plus loin

Pour aller plus loin

De plus en plus, on combine VBA avec d'autres outils : appeler une API web depuis une macro, piloter Excel depuis Python (via des bibliothèques comme openpyxl ou xlwings), ou utiliser Office Scripts (en TypeScript) dans Excel sur le web. Connaître VBA reste la porte d'entrée vers toutes ces approches d'automatisation : tu comprends le modèle objet d'Office, et c'est lui le vrai savoir réutilisable.

Glossaire

Éditeur VBA
Environnement intégré à Office (ouvert par Alt+F11) où l'on écrit et exécute les macros.
Visual Studio
Environnement de développement complet de Microsoft pour VB.NET et C# (l'édition Community est gratuite).
Enregistreur de macros
Fonction d'Excel générant le code VBA équivalent à des actions faites à la souris.
CLR
Common Language Runtime : l'environnement qui exécute le code .NET, commun à VB.NET et C#.
IL (code intermédiaire)
Langage bas niveau vers lequel VB.NET et C# compilent avant d'être exécutés par le CLR.
C#
Autre langage de la plateforme .NET, aujourd'hui le choix par défaut pour les nouveaux projets ; concepts identiques à VB.NET, syntaxe différente.
xlwings / Office Scripts
Approches modernes pour piloter Excel depuis Python ou en TypeScript, au-delà de VBA.

Récap et vérification

  • Outils : éditeur VBA (Alt+F11, intégré à Office) et Visual Studio (VB.NET).
  • L'enregistreur de macros génère du code et fait apprendre.
  • Avenir : VB stable mais peu évolué ; VBA reste incontournable pour Office.
  • VB.NET et C# partagent .NET : concepts identiques, transition facile.

Exercice 2Application

En une phrase, explique pourquoi VB.NET et C# sont « équivalents ».

Voir une solution

Parce qu'ils s'exécutent sur la même plateforme .NET et accèdent aux mêmes bibliothèques : ils ont la même puissance et les mêmes concepts, seule leur syntaxe diffère (mots-clés et End If pour VB, accolades pour C#).

Exercice 3Défi

Résume en trois points ce que t'a apporté ce cours de Visual Basic.

Voir une solution

Réponses possibles : (1) la capacité d'automatiser Office avec VBA (macros Excel, Word…), un gain de temps immédiat ; (2) les fondations universelles de la programmation (variables typées, boucles, procédures, objets, événements), transférables à tout langage ; (3) une porte d'entrée vers .NET et C#, dont VB.NET partage la plateforme et les concepts.
