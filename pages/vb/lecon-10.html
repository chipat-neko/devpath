POO en VB.NET : héritage et interfaces

~50 min Avancé Prérequis : leçon 8

À la fin de cette leçon, tu sauras

  • réutiliser du code par l'héritage (Inherits) ;
  • redéfinir un comportement (Overridable/Overrides) ;
  • exploiter le polymorphisme ;
  • définir un contrat avec une interface.
Sommaire de la leçon

Tu sais créer des classes et des objets (leçon 8). Pour bâtir de vraies applications, la programmation orientée objet offre deux outils de structuration essentiels : l'héritage (réutiliser et spécialiser une classe) et les interfaces (définir un contrat que plusieurs classes respectent). Ensemble, ils permettent d'écrire du code souple, sans duplication.

Réutiliser par l'héritage

L'héritage permet à une classe (la classe dérivée) de reprendre les propriétés et méthodes d'une autre (la classe de base), puis d'y ajouter ou d'en modifier. On évite ainsi de réécrire ce qui est commun. Le mot-clé est Inherits.

Chien hérite de Nom et de Crier sans les réécrire. Il redéfinit seulement Crier. La relation se lit « un Chien est un Animal » : c'est le test qui indique qu'un héritage est justifié.

Redéfinir : Overridable et Overrides

Par défaut, une méthode ne peut pas être redéfinie. Pour l'autoriser, la classe de base la marque Overridable ; la classe dérivée la remplace avec Overrides. Depuis la version redéfinie, MyBase permet d'appeler la version d'origine.

Préférer la composition quand « est un » ne tient pas

L'héritage n'est justifié que si la dérivée est un cas particulier de la base. Sinon, préfère la composition : mettre un objet en propriété plutôt que d'hériter. Une Voiture n'est pas un Moteur : elle a un moteur (Property Moteur As Moteur).

Le polymorphisme

Le polymorphisme (« plusieurs formes ») est la conséquence la plus utile de l'héritage : une variable de type Animal peut contenir n'importe quelle dérivée, et l'appel de méthode choisit automatiquement la bonne version.

La boucle ne connaît que le type Animal, mais chaque objet exécute sa version de Crier. Ajouter un Oiseau demain ne changera pas cette boucle : c'est la grande force de l'orienté objet.

Les interfaces : un contrat

Une interface déclare des membres sans code : un pur contrat. Toute classe qui Implements l'interface s'engage à fournir ces membres. Contrairement à l'héritage (une seule classe de base), une classe peut implémenter plusieurs interfaces.

Par convention, les interfaces commencent par I (IExportable, IComparable…). Le mot-clé Implements apparaît deux fois : sur la classe (elle adhère au contrat) et sur chaque membre (il réalise tel élément du contrat).

Classes et membres particuliers

Attention aux classes qu'on ne peut pas instancier

Une classe MustInherit (abstraite) ne peut pas être créée avec New : elle sert uniquement de base. Une méthode MustOverride n'a pas de corps et oblige chaque dérivée à la définir. À l'inverse, NotInheritable interdit tout héritage. Utiliser New sur une classe MustInherit provoque une erreur de compilation.

Pour aller plus loin

Pour aller plus loin

La règle d'or moderne : « préférer la composition à l'héritage », et « programmer vers une interface, pas vers une implémentation ». Les interfaces rendent le code testable (on peut fournir une fausse implémentation) et modulaire. C'est le fondement de l'injection de dépendances, omniprésente dans les applications .NET professionnelles.

Glossaire

Héritage
Mécanisme par lequel une classe dérivée reçoit les membres d'une classe de base, qu'elle peut compléter ou redéfinir.
Classe de base / dérivée
La classe dont on hérite (base) et celle qui hérite (dérivée). Relation « est un ».
Overrides
Redéfinition, dans une classe dérivée, d'une méthode Overridable de la base.
MyBase
Référence à la classe de base, pour appeler sa version d'un membre depuis la dérivée.
Polymorphisme
Capacité d'une variable d'un type de base à exécuter la version appropriée de la méthode selon l'objet réel qu'elle contient.
Interface
Contrat listant des membres sans code ; toute classe qui l'implémente doit les fournir.
Implements
Clause indiquant qu'une classe (et chacun de ses membres) réalise une interface.
MustInherit
Classe abstraite : ne peut pas être instanciée avec New, sert seulement de base.

Récap et vérification

  • L'héritage (Inherits) réutilise une classe de base ; à réserver aux relations « est un ».
  • Overridable/Overrides permettent de redéfinir un comportement ; MyBase rappelle la base.
  • Le polymorphisme exécute la bonne version automatiquement selon l'objet réel.
  • Une interface est un contrat ; une classe peut en implémenter plusieurs (Implements).
