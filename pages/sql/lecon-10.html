Module 04 · Manipuler et structurer — Leçon 10

Insérer, modifier, supprimer

~32 min Débutant Module 3 recommandé

À la fin de cette leçon, tu sauras

  • savoir insérer des lignes avec INSERT INTO … VALUES, y compris plusieurs d'un coup ;
  • savoir modifier des données ciblées avec UPDATE … SET … WHERE et supprimer avec DELETE FROM … WHERE ;
  • savoir appliquer le réflexe de sécurité : vérifier sa condition avec un SELECT avant toute écriture ;
  • savoir reconnaître les contraintes et le rôle des transactions pour annuler une erreur.
Sommaire de la leçon

Jusqu'ici, tu as seulement lu des données avec SELECT … FROM. Mais une base de données n'est pas un musée : on y ajoute des clients, on corrige une adresse, on supprime une commande annulée. Dans cette leçon, tu vas apprendre les trois commandes qui écrivent dans la base : INSERT (ajouter), UPDATE (modifier) et DELETE (supprimer).

Ces commandes sont puissantes : contrairement à un SELECT qui ne fait que regarder, elles changent réellement le contenu des tables. Une petite erreur peut donc faire de gros dégâts. On va aussi voir le réflexe de prudence qui sépare les débutants des pros. Travaillons sur une table clients toute simple :

idnomvillepoints
1CamilleLyon120
2HugoParis50
3InèsLyon0

Notre table de départ clients.

Ajouter des lignes avec INSERT

Pour insérer une ligne, tu indiques la table, la liste des colonnes que tu remplis, puis les valeurs correspondantes avec VALUES. L'ordre des valeurs doit suivre l'ordre des colonnes.

On ajoute une cliente. On ne précise pas id : il est souvent généré automatiquement par la base.

Après cette requête, la table contient une ligne de plus :

idnomvillepoints
1CamilleLyon120
2HugoParis50
3InèsLyon0
4LéaNantes30

La ligne 4 vient d'apparaître.

Note

Si tu omets la liste des colonnes (INSERT INTO clients VALUES (…)), tu dois fournir une valeur pour chaque colonne, dans l'ordre exact de la table. C'est fragile : nomme toujours tes colonnes, ta requête restera correcte même si la table évolue.

Insérer plusieurs lignes d'un coup

Inutile de répéter INSERT dix fois : sépare simplement chaque groupe de valeurs par une virgule. C'est plus rapide et plus lisible.

Modifier des données avec UPDATE

UPDATE change la valeur d'une ou plusieurs colonnes sur les lignes choisies. La structure est : la table, ce qu'on change avec SET, et — point capital — quelles lignes avec WHERE.

On donne 100 points au client dont l'id vaut 2 (Hugo), et à lui seul.

idnomvillepoints
1CamilleLyon120
2HugoParis100
3InèsLyon0

Seule la ligne 2 a changé.

Tu peux modifier plusieurs colonnes à la fois (sépare-les par des virgules) et même calculer à partir de la valeur actuelle :

Tous les clients parisiens gagnent 10 points et déménagent à Marseille.

Piège fréquent

Sans WHERE, UPDATE clients SET points = 0 met tous les clients à zéro. Le WHERE n'est pas optionnel dans la pratique : c'est lui qui limite les dégâts.

Supprimer des lignes avec DELETE

DELETE FROM efface des lignes entières. Là encore, le WHERE décide lesquelles.

On supprime les clients qui n'ont aucun point. Inès (ligne 3) disparaît.

idnomvillepoints
1CamilleLyon120
2HugoParis50

Après la suppression, il ne reste que deux lignes.

Attention : DELETE retire des lignes, pas des colonnes ni des valeurs isolées. Pour « vider » une seule case, tu utilises plutôt un UPDATE qui met la colonne à NULL.

Note

Pour vider entièrement une table d'un coup, il existe TRUNCATE TABLE clients (PostgreSQL, MySQL), plus rapide que DELETE sans WHERE. SQLite ne connaît pas TRUNCATE et utilise DELETE FROM clients. Dans les deux cas, la table reste mais devient vide.

Le réflexe de sécurité : SELECT d'abord

Voici la meilleure habitude à prendre dès aujourd'hui. Avant un UPDATE ou un DELETE, écris d'abord un SELECT avec exactement la même condition WHERE. Tu vois ainsi quelles lignes seront touchées, sans rien casser. (Reprenons la table juste après nos insertions multiples : Inès garde l'id 3 et Tom a reçu l'id 5.)

On lit d'abord. Le résultat nous montre les lignes concernées.

idnompoints
3Inès0
5Tom10
7Noé0

Trois lignes correspondent. C'est bien ce qu'on voulait.

Même WHERE que le SELECT : aucune surprise.

Astuce

Si le SELECT renvoie 200 lignes alors que tu n'en visais qu'une, c'est le signal d'alarme : ta condition est trop large. Corrige-la avant de lancer l'écriture.

Cas réel

En production, un UPDATE ou un DELETE lancé sans WHERE (ou avec une condition trop large) fait partie des incidents les plus redoutés : en une seconde, toute une table de comptes, de commandes ou de mots de passe se retrouve écrasée. Les équipes s'en protègent par trois habitudes : le SELECT de contrôle systématique, l'exécution dans une transaction (pour pouvoir ROLLBACK), et des sauvegardes régulières. La règle d'or : ne jamais taper un DELETE sur la base de production sans avoir vu, juste avant, ce qu'il va toucher.

Les transactions : pouvoir annuler

Et si tu as déjà lancé un mauvais DELETE ? Une transaction te permet de regrouper des modifications et de décider à la fin : les valider (COMMIT) ou tout annuler (ROLLBACK) comme si rien ne s'était passé.

Tant que tu n'as pas fait COMMIT, ROLLBACK remet la table dans son état initial.

La forme standard (ANSI) est START TRANSACTION ; BEGIN fonctionne sous SQLite et PostgreSQL, et MySQL accepte les deux. On détaillera les transactions à la leçon 12. Retiens pour l'instant qu'elles sont ton filet de sécurité : hors transaction (en « auto-commit »), un UPDATE ou un DELETE est définitif dès qu'il s'exécute.

L'UPSERT : insérer ou mettre à jour

Parfois tu veux insérer une ligne… mais si elle existe déjà, la mettre à jour plutôt que d'échouer. C'est l'UPSERT (contraction d'« update » et « insert »). La syntaxe varie selon la base :

Si l'id 2 existe déjà, on met à jour ses points au lieu de provoquer une erreur. excluded (PostgreSQL/SQLite) et VALUES(...) (MySQL) désignent la valeur qu'on essayait d'insérer.

Pièges fréquents

  • Oublier le WHERE. Le piège n°1. Un UPDATE ou DELETE sans WHERE touche toute la table. Prends le réflexe du SELECT de contrôle.
  • Modifier hors transaction. Sans BEGIN … ROLLBACK, l'écriture est immédiate et irréversible. Pour les opérations importantes, encadre-les d'une transaction.
  • Violer une contrainte. Insérer un id déjà pris (UNIQUE), laisser vide une colonne NOT NULL, ou supprimer un client encore référencé par une commande (clé étrangère) déclenche une erreur et la requête est refusée.
  • Types incompatibles. Mettre 'beaucoup' dans une colonne numérique, ou oublier les guillemets simples autour d'un texte, provoque une erreur. Respecte le type de chaque colonne.

Pour aller plus loin

Les transactions en détail (leçon 12) ; la clause RETURNING de PostgreSQL pour récupérer les lignes insérées ou modifiées ; les déclencheurs (triggers) qui réagissent automatiquement à une écriture ; et l'insertion en masse performante (COPY, LOAD DATA) pour charger des milliers de lignes.

Glossaire

INSERT
Ajoute une ou plusieurs lignes à une table (INSERT INTO … VALUES ou INSERT … SELECT).
UPDATE
Modifie la valeur de colonnes sur les lignes choisies par WHERE (SET col = …).
DELETE
Supprime des lignes entières ; les colonnes et la table subsistent.
Clause WHERE (en écriture)
Restreint UPDATE/DELETE aux lignes visées ; l'oublier applique l'opération à toute la table.
Transaction
Groupe d'écritures traité comme un tout : soit validé (COMMIT), soit annulé (ROLLBACK).
COMMIT / ROLLBACK
Valide définitivement, respectivement annule, les écritures d'une transaction en cours.
UPSERT
Insertion qui se transforme en mise à jour si la ligne existe déjà (ON CONFLICT, ON DUPLICATE KEY).
Contrainte
Règle vérifiée à l'écriture (UNIQUE, NOT NULL, clé étrangère…) ; sa violation fait échouer la requête.

Récap et vérification

  • INSERT INTO … VALUES (…) ajoute une ou plusieurs lignes ; INSERT … SELECT copie des données existantes.
  • UPDATE … SET … WHERE … modifie des lignes ciblées ; sans WHERE, il modifie tout.
  • DELETE FROM … WHERE … supprime des lignes ; TRUNCATE vide rapidement une table entière.
  • Le réflexe : un SELECT avec la même condition avant chaque UPDATE ou DELETE.
  • Les transactions (BEGIN … COMMIT / ROLLBACK) permettent d'annuler une erreur.

Vérifie ta compréhension

  1. Pourquoi un UPDATE sans WHERE est-il dangereux ?
  2. Quelle requête écris-tu avant un DELETE pour vérifier les lignes visées ?
  3. À quoi sert ROLLBACK dans une transaction ?
