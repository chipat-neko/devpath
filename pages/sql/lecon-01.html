Module 01 · Lire des données — Leçon 01

SELECT : interroger une table

~30 min Débutant Aucun prérequis

À la fin de cette leçon, tu sauras

  • écrire une requête SELECT qui lit une ou plusieurs colonnes d'une table ;
  • renommer des colonnes avec AS et supprimer les doublons avec DISTINCT ;
  • comprendre pourquoi SELECT * dépanne mais ne convient pas en production ;
  • trier un résultat avec ORDER BY et reconnaître les pièges de syntaxe les plus courants.
Sommaire de la leçon

Une base de données, c'est avant tout un endroit où des informations sont rangées de façon ordonnée. Pour lire ces informations, on n'ouvre pas un fichier à la main : on pose une question à la base avec un langage dédié, le SQL. La toute première chose à savoir faire, c'est interroger une table : demander « montre-moi telles colonnes de telle table ». C'est le rôle du mot-clé SELECT, et c'est l'objectif de cette leçon.

Tu connais déjà les tableaux : une feuille de calcul, un carnet d'adresses, une liste de courses en colonnes. Une table SQL, c'est exactement cette idée, mais avec des règles précises. Partons de ce que tu connais pour arriver à ta première vraie requête.

Une base, des tables

Une base de données relationnelle range les données dans des tables. Chaque table a un nom (par exemple clients) et se présente comme un tableau :

  • les colonnes sont les champs : ce qu'on enregistre pour chacun (le nom, la ville, l'âge…). Une colonne a un nom et un type ;
  • les lignes sont les enregistrements : une ligne = un client réel.

Imaginons une table clients avec quatre colonnes : id (un numéro unique), nom, ville et age. Elle contient quatre lignes :

  • la ligne 1 — Alice, à Lyon, 30 ans ;
  • la ligne 2 — Bruno, à Paris, 25 ans ;
  • la ligne 3 — Chloé, à Lyon, 42 ans ;
  • la ligne 4 — David, à Paris, 38 ans.

Garde bien ce petit tableau en tête : toutes les requêtes de la leçon s'appuient dessus. Quand tu interroges la table, la base parcourt ces lignes et te renvoie ce que tu as demandé. Une requête ne modifie rien : SELECT lit les données, il ne les change pas. Tu peux donc l'essayer sans crainte.

Note

La colonne id sert à identifier chaque ligne de façon unique. Deux clients peuvent avoir le même nom, mais jamais le même id. On en reparlera dans une leçon dédiée aux clés.

SELECT de base

La requête la plus simple demande une seule colonne. Lis-la à voix haute : « sélectionne le nom depuis clients ».

Résultat : une seule colonne contenant Alice, Bruno, Chloé, David. La base lit chaque ligne et n'en ressort que le champ nom. Deux conventions à retenir dès maintenant :

  • les mots-clés du langage (SELECT, FROM…) s'écrivent en MAJUSCULES. Ce n'est pas obligatoire pour la machine, mais c'est la convention qui rend une requête lisible ;
  • la requête se termine par un point-virgule ;. Il marque la fin de l'instruction.

Plusieurs colonnes

Pour demander plusieurs colonnes, tu les listes après SELECT, séparées par des virgules. L'ordre dans lequel tu les écris est l'ordre dans lequel elles s'afficheront.

Résultat : deux colonnes côte à côte. Pour la ligne d'Alice, tu obtiens Alice | Lyon ; pour Bruno, Bruno | Paris, et ainsi de suite. Si tu écrivais SELECT ville, nom, tu aurais les mêmes données mais avec la ville en premier : c'est toi qui décides de la présentation.

Toutes les colonnes avec *

Quand tu veux voir tout sans tout taper, l'étoile * représente « toutes les colonnes ».

C'est parfait pour explorer une table inconnue : en une ligne, tu découvres sa structure et son contenu. En revanche, évite SELECT * dans une application en production : tu transportes des colonnes inutiles (plus lent), et ton code casse si quelqu'un ajoute ou réordonne une colonne. La règle : * pour explorer, colonnes nommées pour le code durable.

Astuce

Prends l'habitude de toujours nommer tes colonnes, même pour deux d'entre elles. Tu liras ta requête comme une phrase et tu sauras exactement ce qui en sort, sans surprise.

Renommer avec AS

Le nom d'une colonne dans la table n'est pas toujours celui que tu veux afficher. Avec AS, tu donnes un alias : un nom d'affichage, valable le temps de la requête. La table, elle, n'est pas modifiée.

Le résultat est identique en contenu, mais les en-têtes de colonnes affichent désormais client et localite. C'est utile pour rendre un résultat plus parlant ou pour nommer une colonne calculée (tu en feras plus tard). Le mot AS est d'ailleurs souvent facultatif (nom client fonctionne aussi), mais l'écrire rend l'intention limpide. Si ton alias doit contenir un espace ou une majuscule particulière, entoure-le de guillemets doubles : nom AS "Nom du client".

Éviter les doublons avec DISTINCT

Demande la colonne ville seule : tu obtiens Lyon, Paris, Lyon, Paris. Lyon et Paris apparaissent deux fois, car deux clients habitent chacune de ces villes. Si ta vraie question est « quelles villes sont représentées ? », ces répétitions parasitent la réponse. Le mot-clé DISTINCT ne garde qu'un exemplaire de chaque valeur.

Résultat : Lyon et Paris, une seule fois chacune. DISTINCT se place juste après SELECT et s'applique à l'ensemble des colonnes listées : il élimine les lignes de résultat identiques, pas seulement une colonne. Ainsi, SELECT DISTINCT ville, age ne supprimerait que les paires (ville, age) rigoureusement identiques.

Trier avec ORDER BY

Par défaut, l'ordre des lignes renvoyées n'est pas garanti : ne compte jamais dessus. Pour imposer un ordre, ajoute ORDER BY suivi de la colonne de tri. ASC trie en ordre croissant (par défaut), DESC en décroissant.

Résultat : Chloé (42), David (38), Alice (30), Bruno (25). ORDER BY se place à la fin de la requête, après FROM. Remplace DESC par ASC (ou supprime-le) pour obtenir l'ordre inverse, du plus jeune au plus âgé.

Note

Trier, c'est bien ; mais on veut souvent aussi filtrer (« seulement les clients de Lyon », « de plus de 30 ans »). C'est le rôle de WHERE, que tu verras dans la prochaine leçon. ORDER BY et WHERE se combinent très bien.

Cas réel — le menu déroulant « Ville »

Sur un site de petites annonces, le filtre « Ville » affiche une liste sans doublon et triée. Personne ne saisit ces villes à la main : elles sortent de la base avec SELECT DISTINCT ville FROM annonces ORDER BY ville;. Quand une annonce paraît dans une ville encore absente, elle apparaît toute seule dans le menu. DISTINCT supprime les répétitions, ORDER BY rend la liste parcourable : deux mots-clés de cette leçon, sur un écran que tu utilises tous les jours.

Pièges fréquents

Piège fréquent

Oublier le point-virgule. Selon l'outil, la requête ne s'exécute pas ou semble « attendre la suite ». Prends le réflexe de terminer chaque instruction par ;.

  • SELECT * en production. Il alourdit les échanges et fragilise ton code dès qu'une colonne change. Réserve-le à l'exploration.
  • Confondre nom de colonne et texte. SELECT 'nom' FROM clients (avec guillemets simples) n'affiche pas les noms : il répète la chaîne littérale « nom » sur chaque ligne. Sans guillemets, nom désigne bien la colonne. En SQL standard, les guillemets simples entourent une valeur texte, les guillemets doubles un nom de colonne ou de table.
  • Casse des mots-clés vs casse des données. select ou SELECT reviennent au même pour le moteur. Mais les valeurs, elles, peuvent être sensibles à la casse : Lyon et lyon ne sont pas forcément considérés comme égaux selon le SGBD. À garder en tête dès qu'on filtrera.

Pour aller plus loin

Deux idées pour élargir ta vision :

  • SQL est un langage déclaratif : tu décris le résultat voulu (« ces colonnes, triées ainsi »), pas la manière de l'obtenir. C'est le moteur qui choisit comment parcourir les données efficacement. Tu te concentres sur le « quoi », pas sur le « comment ».
  • Il existe plusieurs SGBD (systèmes de gestion de bases de données) : PostgreSQL, MySQL, SQLite, et d'autres. Ils partagent un cœur commun — tout ce que tu viens d'apprendre fonctionne partout — avec quelques différences de détail (fonctions, types). Apprends le tronc commun d'abord.

Pour aller plus loin

Ceci est une leçon d'exemple du cours SQL. La suite arrive bientôt : tu y filtreras les lignes avec WHERE, combineras les conditions, puis regrouperas et compteras les données. Tout part de ce que tu viens d'apprendre ici.

Glossaire

Base de données relationnelle
Ensemble de données organisées en tables ; on l'interroge avec le langage SQL.
Table
Grille nommée de données : des colonnes (les champs) et des lignes (les enregistrements).
Requête
Instruction adressée à la base pour lire ou manipuler des données ; ici, une lecture avec SELECT.
SELECT
Mot-clé qui lit des colonnes d'une table sans rien modifier — le cœur de toute interrogation.
Alias
Nom d'affichage temporaire donné à une colonne avec AS, le temps de la requête.
DISTINCT
Option de SELECT qui élimine les lignes de résultat identiques.
ORDER BY
Clause de tri du résultat : ASC (croissant, par défaut) ou DESC (décroissant), placée en fin de requête.
SGBD
Système de gestion de bases de données (PostgreSQL, MySQL, SQLite…) qui stocke les tables et exécute les requêtes.

Récap et vérification

  • Une base relationnelle range les données en tables (lignes = enregistrements, colonnes = champs).
  • SELECT colonnes FROM table; lit les colonnes voulues ; * les prend toutes (pour explorer).
  • AS renomme une colonne à l'affichage ; DISTINCT supprime les lignes en double.
  • ORDER BY colonne ASC|DESC trie le résultat, et se place en fin de requête.

Vérifie ta compréhension

  1. Quelle est la différence entre SELECT * et SELECT nom, ville, et quand préférer chacun ?
  2. Que renvoie SELECT DISTINCT ville FROM clients; sur notre table, et pourquoi ?
  3. Où place-t-on ORDER BY dans une requête, et que change DESC par rapport à ASC ?
