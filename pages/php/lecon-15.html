Module 05 · Le web avec Laravel — Leçon 15

Découvrir Laravel : routes, contrôleurs, Blade et Eloquent

~45 min Intermédiaire Cours PHP (POO + PDO) requis

À la fin de cette leçon, tu sauras

  • créer un projet Laravel et lancer son serveur ;
  • déclarer des routes et les brancher sur des contrôleurs ;
  • afficher des données dans une vue Blade ;
  • interroger la base avec l'ORM Eloquent.
Sommaire de la leçon

Tu sais écrire du PHP moderne : POO, PDO, une API à la main. Mais en entreprise, on ne réécrit pas le routing, la sécurité et l'accès aux données à chaque projet : on s'appuie sur un framework. Laravel est le plus populaire dans le monde PHP — élégant, complet, très documenté. Il prend en charge le routing, les vues, la base de données, l'authentification, les files d'attente… Cette leçon te fait découvrir ses quatre pièces maîtresses ; la suivante ajoutera l'authentification et la validation.

Créer un projet

Laravel s'installe avec Composer (le gestionnaire de dépendances PHP vu au module 3). Une commande, et tu as une application structurée, prête à tourner.

artisan est l'outil en ligne de commande de Laravel : il sert à tout (lancer le serveur, générer du code, jouer les migrations). On le retrouvera à chaque étape. La structure est conventionnelle : routes/, app/Http/Controllers/, app/Models/, resources/views/, database/.

Les routes

Une route associe une URL et un verbe HTTP à du code. Le fichier routes/web.php les déclare. La forme la plus simple répond directement ; la forme propre délègue à un contrôleur.

Comme avec Rails, Route::resource déclare d'un coup les sept routes REST (lister, afficher, créer, éditer, mettre à jour, supprimer). Le {id} est un paramètre d'URL transmis à la méthode du contrôleur.

Les contrôleurs

Un contrôleur regroupe les actions liées à une ressource. On le génère avec artisan, puis on remplit ses méthodes.

Chaque méthode prépare des données et renvoie une vue (via view()) en lui passant un tableau de variables. findOrFail illustre une commodité Laravel : si l'article n'existe pas, il déclenche automatiquement une réponse 404.

Les vues Blade

Blade est le moteur de gabarits de Laravel. Un fichier .blade.php est du HTML enrichi de directives @… et d'affichages {{ }}. Les vues vivent dans resources/views/.

{{ $article->titre }} affiche une valeur ; les directives @forelse … @empty … @endforelse bouclent avec un cas « liste vide » intégré. Blade gère aussi @if, @foreach, et l'héritage de gabarits (@extends, @section) pour partager une mise en page.

Échappement par défaut

La syntaxe {{ $valeur }} échappe le HTML automatiquement : protection contre les failles XSS offerte de base. Pour afficher du HTML brut (rarement, et seulement si tu as confiance dans la source), il faut explicitement {!! $valeur !!}. La sécurité est l'option par défaut ; la désactiver demande un geste conscient.

L'ORM Eloquent

Eloquent est l'ORM de Laravel : comme ActiveRecord en Rails, il fait correspondre une classe à une table et te permet d'interroger la base en PHP, sans SQL. Un modèle Article pilote la table articles par convention.

Les requêtes Eloquent sont chaînables (where()->orderBy()->get()) et renvoient des objets PHP. $fillable est l'équivalent des strong parameters : il liste les champs qu'on autorise à remplir en masse depuis un formulaire — une sécurité contre l'affectation de champs non prévus.

Astuce

Pour créer la table d'un modèle, on utilise une migration (php artisan make:migration), un fichier PHP versionné qui décrit la structure, puis php artisan migrate l'applique. Versionner le schéma comme du code, c'est pouvoir le rejouer à l'identique sur chaque machine et chaque serveur.

Pour aller plus loin

Pour aller plus loin

Laravel va bien au-delà : associations Eloquent (hasMany, belongsTo), migrations et seeders, files d'attente et jobs, e-mails, tâches planifiées, et un écosystème riche (Breeze/Jetstream pour l'auth, Livewire/Inertia pour des interfaces réactives, Sail pour Docker). La prochaine leçon ajoute l'authentification, la validation des formulaires et les middlewares.

Un cas réel : de l'artisanat au framework

Cas réel

Une petite agence maintenait cinq sites PHP « faits main » : chacun avait son propre routing bricolé, sa gestion de connexion réinventée, ses requêtes SQL éparpillées. Reprendre un projet écrit par un collègue partait deux jours : où sont les routes ? comment fonctionne l'authentification ? En migrant vers Laravel, tous les projets ont adopté la même structure conventionnelle — routes/web.php, app/Models/, resources/views/. Un nouveau développeur, déjà familier de Laravel, est devenu productif en une matinée au lieu d'une semaine, parce qu'il retrouvait des repères connus. L'authentification, autrefois recodée (et parfois trouée) sur chaque site, est passée à Breeze en une commande. La leçon : la vraie valeur d'un framework populaire n'est pas seulement technique, elle est humaine — la convention partagée rend le code lisible par toute une communauté, et un projet ne dépend plus de la personne qui l'a écrit.

Glossaire

Framework
Socle logiciel qui prend en charge les tâches communes (routing, sécurité, accès aux données) selon des conventions, pour qu'on n'ait à écrire que la logique propre au projet.
Laravel
Le framework PHP le plus populaire : routing, vues Blade, ORM Eloquent, authentification, files d'attente, le tout très documenté.
Artisan
L'outil en ligne de commande de Laravel (php artisan …) : lance le serveur, génère du code, joue les migrations.
Route
Association d'une URL et d'un verbe HTTP à du code (une fermeture ou une méthode de contrôleur), déclarée dans routes/web.php.
Contrôleur
Classe regroupant les actions liées à une ressource ; chaque méthode prépare des données et renvoie une vue.
Blade
Moteur de gabarits de Laravel : du HTML enrichi de {{ }} (affichage échappé) et de directives @… (@if, @forelse, @extends).
Eloquent
L'ORM de Laravel : fait correspondre une classe de modèle à une table et permet d'interroger la base en PHP, sans écrire de SQL.
Affectation de masse
Remplir plusieurs champs d'un modèle d'un coup depuis un formulaire ; $fillable liste les champs autorisés pour éviter d'affecter une colonne non prévue.

Récap et vérification

  • composer create-project laravel/laravel crée le projet ; php artisan serve le lance.
  • Les routes (routes/web.php) branchent une URL sur un contrôleur ; Route::resource crée les 7 routes REST.
  • Une méthode de contrôleur renvoie une vue Blade avec view('nom', [...]).
  • Blade : {{ }} affiche (échappé), @forelse/@if/@foreach portent la logique.
  • Eloquent interroge la base en PHP : all, find, where, create, save ; $fillable protège l'affectation de masse.

Vérifie ta compréhension

  1. Que fait Route::resource('articles', ArticleController::class) ?
  2. Pourquoi {{ }} est-il plus sûr que d'afficher du HTML brut ?
  3. À quoi sert la propriété $fillable d'un modèle Eloquent ?
