Projet : un carnet de tâches en ligne de commande

~40 min Intermédiaire Leçon 19 recommandée

À la fin de cette leçon, tu sauras

  • écrire un script PHP en ligne de commande qui lit ses arguments ($argv) ;
  • persister des données entre deux exécutions dans un fichier JSON ;
  • structurer un petit outil autour de commandes et de codes de sortie ;
  • assembler un projet complet qui réunit l'essentiel du cours PHP.
Sommaire de la leçon

Pour clore le cours, construisons un vrai outil : un carnet de tâches (todo) qui s'utilise dans le terminal. Il réunit ce que tu as appris — tableaux, fonctions, fichiers (leçon 19), JSON (leçon 20), dates (leçon 18) — dans un programme utile en une centaine de lignes. Au passage, tu découvriras que PHP n'est pas réservé au web : il fait aussi de l'outillage en ligne de commande.

PHP en ligne de commande

Lancé avec php mon-script.php, PHP s'exécute dans le terminal (interface CLI) au lieu de répondre à une requête web. Les arguments passés après le nom du script arrivent dans le tableau $argv ; $argc en donne le nombre. Le script communique via echo (sortie standard), STDERR (erreurs) et un code de sortie (exit(0) = succès, tout le reste = échec).

L'opérateur ?? est précieux ici : un argument peut manquer, et $argv[2] ?? '' évite le warning « index indéfini ». Le code de sortie permet à un autre programme (ou un script shell) de savoir si ton outil a réussi.

Le cahier des charges

Notre carnet gère trois commandes : ajouter une tâche, lister les tâches, et faire (marquer terminée). Les tâches doivent survivre à la fermeture du terminal : on les enregistre dans un fichier taches.json. À chaque exécution, le script charge le fichier, agit, puis le réécrit.

Les étapes

Étapes

Charger et sauver

Deux fonctions : charger() lit taches.json (ou renvoie [] s'il n'existe pas), sauver($t) écrit le tableau en JSON.

Lire la commande

Récupère $argv[1] (avec ?? 'lister' par défaut) pour choisir l'action.

Ajouter

Empile un tableau ['libelle', 'faite' => false, 'creee' => date(...)] puis sauve.

Lister

Parcours les tâches avec foreach et affiche une case [ ] ou [x].

Faire

Passe faite à true pour l'indice donné ; gère l'indice inexistant avec STDERR et exit(1).

Un JSON lisible avec JSON_PRETTY_PRINT

Par défaut, json_encode écrit tout sur une ligne. Ajoute les drapeaux JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE pour obtenir un fichier indenté et des accents lisibles (é au lieu de la séquence échappée \u00e9). Précieux quand tu ouvres taches.json à la main pour vérifier.

Voir la solution complète

Tout le cours est là : des fonctions (charger/sauver), un tableau associatif par tâche, la lecture/écriture de fichier et le JSON, une date d'horodatage, le contrôle de flux (switch), et la gestion des erreurs (STDERR + exit(1)). Pour aller plus loin : une commande supprimer, un filtre --faites, ou une bibliothèque comme Symfony Console.

Toujours prévoir le premier lancement

Au tout premier appel, taches.json n'existe pas encore. Si charger() ne teste pas file_exists, file_get_contents échoue et le script plante. La règle : un outil doit démarrer proprement à vide. De même, un json_decode sur un fichier corrompu renvoie null : le ?? [] garantit qu'on repart d'un tableau valide.

Un cas réel : du script jetable à l'outil d'équipe

Cas réel

Dans une petite agence, un développeur en avait assez de recopier à la main la liste des déploiements du jour. Il a écrit, en une soirée, un script PHP en ligne de commande du même genre que celui-ci : php deploiement.php ajouter "site client X", avec un fichier JSON pour l'historique et la date automatique. D'abord un outil personnel, il l'a partagé sur le dépôt Git de l'équipe ; ses collègues l'ont adopté, ont ajouté une commande rapport qui exportait un CSV pour le chef de projet, puis un appel d'API (leçon 20) qui postait le résumé dans leur canal de discussion. En quelques semaines, le petit script était devenu l'outil de suivi officiel. La morale : la barre pour créer un outil utile est basse. Quelques dizaines de lignes — arguments, un fichier JSON, une boucle — suffisent souvent à automatiser une corvée récurrente. PHP, qu'on croit cantonné au web, est parfait pour ça.

Antisèche

Glossaire

CLI
Command-Line Interface : exécution d'un programme dans le terminal (php script.php), sans navigateur ni serveur web.
$argv
Tableau des arguments de la ligne de commande. $argv[0] est le nom du script, les suivants sont les arguments saisis.
$argc
Nombre d'éléments de $argv (script compris) : pratique pour vérifier qu'un argument attendu est bien présent.
Persistance
Conservation des données entre deux exécutions. Ici, un fichier JSON tient lieu de mémoire durable, sans base de données.
Code de sortie
Entier renvoyé par exit : 0 = succès, non nul = échec. Il permet d'enchaîner les scripts et d'automatiser.
STDERR
Flux de sortie réservé aux messages d'erreur, distinct de la sortie normale (STDOUT/echo).
Capstone
Projet de synthèse : il réunit et met en pratique l'ensemble des notions du cours dans une réalisation concrète.

Récap et vérification

  • En CLI, les arguments arrivent dans $argv ([0] = script) ; ?? gère les arguments absents.
  • Un fichier JSON (json_decode/json_encode) suffit à persister l'état d'un petit outil.
  • Un outil renvoie un code de sortie (exit(0)/exit(1)) et écrit ses erreurs sur STDERR.
  • Le projet réunit fonctions, tableaux, fichiers, JSON et dates : l'essentiel du cours en un programme.

Vérifie ta compréhension

  1. Que contient $argv[0] ?
  2. Comment le carnet conserve-t-il ses tâches d'une exécution à l'autre ?
  3. Que renvoie exit() pour signaler une erreur ?

Exercice 3Défi

Pourquoi charger() teste-t-il file_exists avant de lire, et pourquoi termine-t-on par ?? [] ? Que se passerait-il sans ces garde-fous au tout premier lancement ?

Voir une solution

Au premier lancement, taches.json n'existe pas encore. Sans le test file_exists, file_get_contents échouerait (warning + false), et json_decode(false, true) renverrait null : la suite du script, qui attend un tableau, planterait. Le ?? [] couvre en plus le cas d'un fichier présent mais corrompu ou vide (où json_decode renvoie aussi null). Ensemble, ces deux garde-fous garantissent que charger() renvoie toujours un tableau exploitable : l'outil démarre proprement à vide, ce qui est la marque d'un programme robuste.
