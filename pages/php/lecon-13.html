Module 04 · PHP en profondeur — Leçon 13

POO avancée et fonctionnalités du langage

~35 min Intermédiaire Leçon 12 recommandée

À la fin de cette leçon, tu sauras

  • Savoir exploiter les closures, fonctions fléchées et générateurs (yield) pour un code paresseux et économe ;
  • Savoir modéliser des données avec les enums et annoter ton code avec des attributs lus par réflexion ;
  • Savoir faire dialoguer tes objets avec le langage via ArrayAccess, Countable, Iterator et Stringable ;
  • Savoir tirer parti de readonly, des types union/intersection et d'une hiérarchie d'exceptions personnalisées.
Sommaire de la leçon

Tu connais désormais la POO de PHP, les namespaces, PDO et Composer. Cette leçon te fait franchir un cap : on entre dans les fonctionnalités qui font la différence entre du code « qui marche » et du code qu'un framework moderne pourrait héberger. Closures, générateurs paresseux, enums, attributs lus par réflexion, interfaces du langage : ce sont les briques qui équipent Symfony, Laravel ou Doctrine sous le capot.

On reste en PHP 8.3. Chaque section montre un exemple commenté avec sa sortie en commentaire (//). Rappel important : PHP s'exécute côté serveur, donc tout ce code tournerait via php fichier.php en ligne de commande ou derrière un serveur web — jamais dans le navigateur directement.

Closures et fonctions fléchées en profondeur

Une closure est une fonction anonyme stockable dans une variable. Sa particularité : elle peut capturer des variables de son contexte via use. Une fonction fléchée (fn) capture automatiquement, mais par valeur uniquement.

La capture use fige la valeur au moment de la définition. Pour suivre les changements ultérieurs, capture par référence avec & :

Une closure peut aussi être liée à un objet avec bindTo() (ou Closure::bind()), ce qui change la valeur de $this à l'intérieur. Pratique pour injecter un comportement dans une classe.

Enfin, un callable est tout ce qui s'appelle : une closure, un nom de fonction ('strtoupper'), un tableau [$objet, 'methode'], ou la syntaxe de première classe PHP 8.1 strtoupper(...).

Générateurs : produire des valeurs paresseusement

Un générateur est une fonction qui contient yield. Au lieu de construire et retourner tout un tableau en mémoire, il produit ses valeurs une à une, à la demande. Idéal pour parcourir des millions de lignes sans saturer la RAM.

La différence est invisible ici, mais énorme sur un gros volume : range(1, 10_000_000) alloue dix millions d'entiers d'un coup, alors qu'un générateur n'en garde qu'un seul en mémoire à la fois. On peut aussi yield des paires clé⇒valeur, et déléguer à un autre itérable avec yield from.

Piège fréquent

Un générateur ne se consomme qu'une seule fois. Après un foreach complet, il est épuisé : un second foreach sur le même objet générateur lève une exception (Cannot traverse an already closed generator). Ce message vient de l'ouverture du parcours, qui refuse un générateur déjà fermé : rewind() n'est même pas appelé. La méthode rewind(), elle, a son propre message — Cannot rewind a generator that was already run — et ne vise qu'un générateur encore ouvert, avancé au-delà du premier yield (typiquement après un break). Si tu dois reparcourir, rappelle la fonction pour obtenir un générateur frais.

Les enums : modéliser un ensemble fini

Les enums (PHP 8.1) remplacent les vieilles constantes de classe pour représenter un ensemble fixe de valeurs. Un enum simple n'a pas de valeur scalaire ; un backed enum associe chaque cas à un string ou un int (utile pour la base de données ou le JSON).

Un enum peut aussi implémenter une interface, ce qui le rend interchangeable avec d'autres objets. La méthode statique cases() renvoie tous les cas — parfait pour générer un menu déroulant.

Les attributs : des métadonnées lues par réflexion

Les attributs (PHP 8) sont des annotations natives écrites #[...] que tu attaches à une classe, une méthode ou une propriété. Seuls, ils ne font rien : c'est la réflexion qui les lit à l'exécution. C'est exactement ainsi que les frameworks implémentent le routage (#[Route]), la validation ou l'injection.

Note

La classe qui sert d'attribut doit elle-même porter #[Attribute]. Le paramètre Attribute::TARGET_METHOD restreint où on peut l'utiliser ; combine avec | (par exemple TARGET_CLASS | TARGET_METHOD) pour autoriser plusieurs cibles.

Les interfaces du langage : se comporter comme un tableau

PHP expose des interfaces qui font dialoguer tes objets avec la syntaxe du langage. Implémente ArrayAccess et Countable, et ton objet réagit à $obj[$cle] et count($obj). Ajoute IteratorAggregate pour le rendre parcourable avec foreach, et Stringable pour le convertir en chaîne.

readonly, promotion, types union/intersection et never

La promotion de propriétés déclare et initialise les propriétés directement dans le constructeur. Couplée à readonly, elle crée des objets immuables : une propriété readonly ne peut être écrite qu'une fois, depuis l'intérieur de la classe.

Les types union (int|string) acceptent plusieurs types ; les types intersection (Countable&ArrayAccess) exigent qu'une valeur implémente toutes les interfaces listées. Le type de retour never indique qu'une fonction ne rend jamais la main (elle lève une exception ou termine le script).

Gestion d'erreurs moderne : une hiérarchie d'exceptions

En PHP, tout ce qui se jette implémente l'interface Throwable, déclinée en Exception (erreurs applicatives) et Error (erreurs du moteur). La bonne pratique consiste à créer tes propres exceptions hiérarchisées pour les attraper sélectivement.

Catcher CommandeException attrape aussi StockInsuffisantException et PaiementRefuseException, puisqu'elles en héritent. Tu peux donc raisonner par famille d'erreurs. Depuis PHP 8, tu peux aussi capturer plusieurs types d'un coup avec catch (TypeA|TypeB $e).

Pièges fréquents

  • Capture par valeur involontaire dans use : si tu veux qu'une closure modifie une variable externe, n'oublie pas le & (use (&$total)). Sans lui, tu travailles sur une copie figée.
  • Consommer un générateur deux fois : il est épuisé après le premier parcours complet. Rappelle la fonction pour repartir de zéro.
  • Confondre enum simple et backed : ->value, from() et tryFrom() n'existent que sur les backed enums. Sur un enum simple, ces appels lèvent une erreur.
  • Lire un attribut sans réflexion : un #[Route] posé sur une méthode ne s'active jamais tout seul. Il faut getAttributes() puis newInstance().
  • Implémenter ArrayAccess partiellement : les quatre méthodes (offsetExists, offsetGet, offsetSet, offsetUnset) sont obligatoires, sinon l'interface n'est pas satisfaite et PHP refuse la classe.
  • Muter une propriété readonly : toute écriture après initialisation lève une Error. Pour « changer » une valeur, renvoie un nouvel objet.

Pour aller plus loin

Pour aller plus loin

Les fibers (PHP 8.1) permettent de suspendre et reprendre une pile d'exécution complète : c'est le socle de l'asynchrone (ReactPHP, Amp, Swoole). La réflexion en profondeur (ReflectionClass, ReflectionMethod, ReflectionParameter) ouvre la voie aux conteneurs d'injection de dépendances qui résolvent automatiquement les arguments d'un constructeur. Explore ensuite les design patterns classiques (Strategy, Observer, Factory) et la façon dont les frameworks combinent attributs et réflexion pour le routage, la sérialisation et la validation.

Un cas réel : l'export qui saturait la mémoire

Cas réel

Un script nocturne exportait tout le fichier clients en CSV. Écrit avec $tous = $pdo->query(…)->fetchAll(); puis une boucle, il chargeait des centaines de milliers de lignes d'un seul coup en mémoire. Tant que la base restait modeste, tout passait. Le jour où le volume a doublé, le script est mort sur Fatal error: Allowed memory size of 512M exhausted, laissant chaque nuit un export à moitié écrit — donc inexploitable. Le correctif n'a touché qu'à la structure : remplacer le fetchAll() par un générateur qui fait yield d'une ligne à la fois (while ($row = $stmt->fetch()) { yield $row; }). Résultat : une seule ligne en mémoire à l'instant t, une empreinte plate, et un script qui encaisse désormais n'importe quel volume. La leçon : dès qu'on itère sur « beaucoup », on ne matérialise pas tout en tableau — on produit à la demande.

Glossaire

Closure
Fonction anonyme stockable dans une variable ; capture des variables du contexte via use, par valeur ou par référence (&).
Fonction fléchée (fn)
Closure concise d'une seule expression, avec capture automatique du contexte par valeur.
Générateur (yield)
Fonction qui produit ses valeurs une à une, à la demande ; empreinte mémoire minime, mais ne se consomme qu'une fois.
Enum adossé (backed)
Énumération dont chaque cas porte une valeur string/int ; expose ->value, from(), tryFrom(), cases().
Attribut
Métadonnée native #[...] attachée au code ; inerte tant que la réflexion ne la lit pas.
Réflexion
API (ReflectionClass…) qui inspecte le code à l'exécution : lit les attributs, les méthodes, les paramètres.
readonly
Modificateur rendant une propriété immuable : écrite une seule fois, depuis l'intérieur de la classe ; sinon une Error.
Type union / intersection
int|string accepte l'un OU l'autre ; Countable&ArrayAccess exige toutes les interfaces à la fois.

Récap et vérification

  • Les closures capturent par valeur (use ($x)) ou par référence (use (&$x)) ; les fonctions fléchées fn capturent automatiquement, par valeur.
  • Les générateurs (yield, yield from) produisent des valeurs à la demande, économisant la mémoire — mais ne se consomment qu'une fois.
  • Les enums modélisent un ensemble fini ; les backed enums portent une valeur, peuvent avoir des méthodes et implémenter des interfaces.
  • Les attributs (#[...]) sont des métadonnées inertes, activées uniquement par la réflexion.
  • ArrayAccess, Countable, IteratorAggregate et Stringable font réagir tes objets à la syntaxe du langage.
  • readonly rend les objets immuables ; les types union/intersection et never précisent tes signatures ; une hiérarchie d'exceptions permet d'attraper par famille.

Vérifie ta compréhension

  1. Quelle différence de comportement obtiens-tu entre use ($x) et use (&$x) dans une closure ?
  2. Pourquoi un générateur économise-t-il la mémoire face à un tableau, et que se passe-t-il si tu le parcours deux fois ?
  3. Un attribut #[Route('/x')] posé sur une méthode déclenche-t-il quelque chose tout seul ? Que faut-il pour le lire ?
  4. Quelles méthodes dois-tu implémenter pour que $obj['clé'] et count($obj) fonctionnent ?
