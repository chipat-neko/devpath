Module 01 · Les bases de PHP — Leçon 01

Découvrir PHP

~29 min Débutant Un peu de HTML aide

À la fin de cette leçon, tu sauras

  • comprendre que PHP s'exécute sur le serveur et renvoie du HTML au navigateur ;
  • savoir écrire et imbriquer les balises <?php ?> et l'écho court <?= ?> dans une page ;
  • savoir afficher du texte avec echo et terminer une instruction par un point-virgule ;
  • savoir lancer une page PHP avec le serveur intégré php -S.
Sommaire de la leçon

Tu connais déjà un peu de HTML : tu sais écrire une page, mais elle est figée. Chaque visiteur voit exactement la même chose. PHP change la donne : c'est un langage qui génère du HTML à la volée, différent selon l'heure, le visiteur ou les données. Et le plus surprenant pour commencer : ce code ne tourne pas dans le navigateur, mais sur le serveur, avant même que la page n'arrive chez le visiteur.

Dans cette première leçon, tu vas comprendre où vit PHP, comment une page se fabrique, à quoi servent les balises <?php ?>, et comment lancer ta toute première page sur ta machine.

PHP en bref

PHP est un langage de programmation pensé pour le web. Son rôle principal : produire des pages HTML dynamiques. Là où une page HTML pure est toujours identique, une page PHP peut afficher la date du jour, le nom de l'utilisateur connecté, ou une liste de produits tirée d'une base de données.

Ce n'est pas un langage de niche : une énorme partie du web tourne grâce à PHP. WordPress (qui propulse une grande part des sites du monde) et Wikipédia sont écrits en PHP. Apprendre PHP, c'est apprendre à fabriquer le « côté serveur » d'un site.

Note

« Côté serveur » veut dire : le code s'exécute sur l'ordinateur qui héberge le site, pas sur celui du visiteur. À l'opposé, le JavaScript s'exécute « côté client », dans le navigateur du visiteur.

Le cycle : qui exécute quoi

Voici ce qui se passe quand quelqu'un visite une page PHP, étape par étape :

  1. Le navigateur du visiteur demande une page (par exemple index.php).
  2. Le serveur reçoit la demande, voit que c'est du PHP, et l'exécute.
  3. Le PHP produit du HTML (du texte ordinaire, comme tu en écris à la main).
  4. Le serveur renvoie ce HTML au navigateur, qui l'affiche.

Le point essentiel à retenir : le visiteur ne reçoit jamais ton code PHP. Il reçoit seulement le HTML que ce code a fabriqué. C'est exactement comme une cuisine : le client mange le plat (le HTML), il ne voit pas la recette ni le cuisinier (le PHP sur le serveur).

Note

Si tu fais « Afficher le code source de la page » dans ton navigateur, tu verras du HTML, jamais du PHP. C'est la preuve que le code a bien été exécuté côté serveur.

Les balises PHP

Un fichier .php est, par défaut, du HTML normal. Pour passer en mode PHP, on encadre le code par des balises : on ouvre avec <?php et on ferme avec ?>. Tout ce qui est entre ces deux balises est exécuté par le serveur ; tout ce qui est en dehors est envoyé tel quel comme du HTML.

Le PHP s'imbrique au milieu du HTML : on entre et on sort autant de fois qu'on veut.

Il existe aussi un écho court, très pratique pour insérer une seule valeur : <?= ... ?>. C'est un raccourci pour <?php echo ... ?>.

Sortie HTML envoyée au navigateur : <p>Bonjour, nous sommes le 11/06/2026.</p>

Afficher avec echo et le point-virgule

Le mot-clé echo est ta première instruction PHP : il affiche (écrit dans le HTML produit) ce qu'on lui donne. Le texte se met entre guillemets. Et chaque instruction PHP se termine par un point-virgule ; — c'est le « point final » d'une phrase de code.

Sortie produite : Bonjour tout le monde ! — les deux echo s'écrivent à la suite.

Astuce

Tu peux mettre du HTML directement dans le texte affiché : echo "<strong>Important</strong>"; produira du gras dans la page. Pour PHP, c'est juste du texte ; c'est le navigateur qui l'interprète ensuite.

Lancer une page PHP

Un fichier .php n'est interprété que s'il est servi par un serveur. Le plus simple pour débuter : le serveur intégré fourni avec PHP. Place-toi dans le dossier de ton fichier, puis lance cette commande dans un terminal.

Démarre un petit serveur. Ouvre ensuite http://localhost:8000 dans ton navigateur.

Tant que cette commande tourne, ton site est accessible à l'adresse localhost:8000. Pour l'arrêter, fais Ctrl + C dans le terminal. Plus tard, en production, c'est un serveur comme Apache ou Nginx qui jouera ce rôle, mais le principe reste le même : un serveur exécute ton PHP.

Piège fréquent

Si tu ouvres ton fichier .php par un double-clic (adresse qui commence par file://), aucun serveur ne l'exécute : tu verras le code brut, pas la page. Il faut toujours passer par http://localhost:8000.

Les commentaires

Un commentaire est une note dans le code, ignorée par PHP. Elle sert à t'expliquer à toi-même (ou aux autres) ce que fait ton code. PHP propose trois formes.

Rien de ce qui est commenté n'apparaît dans la page : ces notes sont pour toi, pas pour le visiteur.

Pièges fréquents

Piège fréquent

Oublier le point-virgule. Chaque instruction doit se terminer par ;. Sans lui, PHP affiche une erreur de syntaxe (syntax error, unexpected ...) et la page ne s'affiche pas.

Piège fréquent

Mal fermer ou mal imbriquer les balises. Si tu ouvres <?php sans jamais écrire ?> avant de revenir à du HTML, tout le HTML suivant sera pris pour du PHP. Vérifie que chaque ouverture imbriquée a sa fermeture.

Piège fréquent

Croire que le visiteur voit ton PHP. Non : il voit le HTML produit. Ton code et ta logique restent sur le serveur, invisibles depuis le navigateur.

Piège fréquent

Des espaces ou lignes vides avant <?php. Tout ce qui précède la balise (même un simple espace) est envoyé comme du HTML. Dans une page qui mélange HTML et PHP ce n'est pas grave, mais pour des fichiers 100 % PHP cela cause plus tard des bugs (« sortie prématurée »). Commence donc tes fichiers directement par <?php.

Pour aller plus loin

Pour aller plus loin

PHP se règle via un fichier de configuration, php.ini. Les versions de PHP comptent beaucoup : vise PHP 8.1 ou plus récent, qui apporte des outils modernes que tu découvriras au fil du cours. Bonne pratique : dans un fichier qui ne contient que du PHP, on ne met pas la balise fermante ?> à la fin, justement pour éviter toute sortie accidentelle après.

Un cas réel : quand le serveur oublie d'exécuter le PHP

Cas réel

Si le visiteur ne voit jamais ton PHP, c'est précisément ce qui permet d'y écrire des secrets — comme le mot de passe de la base de données. Mais il arrive régulièrement, après une mauvaise configuration serveur (module PHP désactivé, mauvaise extension de fichier, migration d'hébergeur bâclée), qu'un serveur se mette à servir les fichiers .php en texte brut au lieu de les exécuter. Le résultat est catastrophique : n'importe qui, via « Afficher la source », lit alors le code et les identifiants en clair. C'est arrivé à de vrais sites, parfois de grande taille. La leçon de cette toute première leçon prend soudain tout son sens : un .php n'a de valeur que exécuté par un serveur correctement configuré ; servi tel quel, ce n'est plus un programme, c'est une fuite de données. D'où la règle : on teste toujours via http://localhost:8000, jamais par un double-clic.

Glossaire

Côté serveur / côté client
« Côté serveur » : le code s'exécute sur la machine qui héberge le site (cas de PHP). « Côté client » : il s'exécute dans le navigateur du visiteur (cas de JavaScript).
PHP
Langage de programmation pensé pour le web, dont le rôle principal est de produire du HTML dynamique depuis le serveur (WordPress, Wikipédia en sont écrits).
Balises PHP
Marqueurs <?php et ?> qui délimitent le code exécuté ; hors d'elles, le contenu est traité comme du HTML ordinaire.
echo
Instruction qui affiche (écrit dans le HTML produit) le texte ou la valeur qu'on lui donne. Chaque instruction se termine par ;.
Écho court <?= ?>
Raccourci de <?php echo … ?>, pratique pour insérer une seule valeur au milieu du HTML.
Serveur web intégré
Petit serveur fourni avec PHP, lancé par php -S localhost:8000 : il exécute tes fichiers .php en développement, sans installer Apache ou Nginx.
Concaténation
Assemblage de deux textes avec l'opérateur . (point) : "Il est " . $heure produit une seule chaîne.
Commentaire
Note dans le code, ignorée par PHP (//, # ou /* … */) : elle explique le code sans jamais apparaître dans la page.

Récap et vérification

  • PHP s'exécute sur le serveur et produit du HTML ; le visiteur ne voit que ce HTML.
  • Le cycle : navigateur demande, serveur exécute le PHP, puis renvoie du HTML.
  • On écrit du PHP entre <?php et ?> ; l'écho court <?= ?> insère une valeur.
  • echo affiche du texte ; chaque instruction finit par ;.
  • On lance une page avec php -S localhost:8000, jamais par un double-clic sur le fichier.
  • Trois formes de commentaires : //, # et /* ... */.

Vérifie ta compréhension

  1. Où le code PHP s'exécute-t-il, et que reçoit finalement le navigateur du visiteur ?
  2. Quelles balises encadrent du code PHP, et que fait l'écho court <?= ?> ?
  3. Quelle commande lance le serveur intégré, et pourquoi ouvrir le fichier par double-clic ne fonctionne-t-il pas ?
