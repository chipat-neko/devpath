Module 06 · PHP en pratique — Leçon 19

Fichiers, flux et téléversement

~36 min Intermédiaire Leçon 5 recommandée

À la fin de cette leçon, tu sauras

  • lire et écrire un fichier simplement (file_get_contents, file_put_contents) ;
  • traiter un gros fichier en flux, ligne par ligne, sans saturer la mémoire ;
  • lire et produire du CSV avec fgetcsv / fputcsv ;
  • gérer un téléversement de fichier de façon sécurisée ($_FILES, finfo, move_uploaded_file).
Sommaire de la leçon

Lire un fichier de configuration, écrire un journal, exporter un tableau en CSV, recevoir la photo de profil d'un utilisateur : manipuler des fichiers est le quotidien du développement serveur. PHP offre deux niveaux d'accès : le tout-en-un (pratique pour les petits fichiers) et le flux (indispensable pour les gros). Et parce qu'un téléversement expose ton serveur, cette leçon insiste sur la sécurité. On reste en PHP 8.3.

Lire et écrire simplement

Pour un fichier de taille raisonnable, deux fonctions suffisent : file_get_contents charge tout dans une chaîne, file_put_contents écrit une chaîne d'un coup. La fonction file renvoie directement un tableau de lignes.

C'est parfait pour un fichier de quelques kilo-octets. Mais file_get_contents a un défaut majeur sur les gros fichiers : il charge tout en mémoire. Un journal de 2 Go essaiera d'occuper 2 Go de RAM… et fera planter le script.

Traiter un gros fichier en flux

La solution : ouvrir un flux avec fopen et lire ligne par ligne avec fgets. La mémoire reste constante, quelle que soit la taille du fichier : on ne garde qu'une ligne à la fois.

Le trio fopen / fgets / fclose est le cœur du travail en flux. Alternative orientée objet plus élégante : SplFileObject, qui s'itère directement avec foreach.

Petit fichier → tout-en-un ; gros fichier → flux

La question à te poser avant de lire un fichier : « sa taille peut-elle grossir sans limite ? » Un modèle d'e-mail ? file_get_contents convient. Un journal, un export, un import client ? Passe en flux (fopen/fgets ou SplFileObject), sinon la mémoire explosera un jour en production.

Le cas du CSV

Le CSV (valeurs séparées par des virgules) est le format d'échange universel des tableurs. Ne le découpe pas à la main avec explode(',', …) : une valeur peut contenir une virgule entre guillemets. Utilise fgetcsv (lire) et fputcsv (écrire), qui gèrent l'échappement.

Les flux ne sont pas que des fichiers

PHP unifie fichiers, réseau et mémoire derrière la notion de flux. On ouvre php://stdin (l'entrée clavier d'un script en ligne de commande), php://temp ou php://memory (un « fichier » en RAM, pratique pour les tests), ou même https://… avec un contexte. Les mêmes fonctions fgets/fwrite fonctionnent sur tous.

Le téléversement de fichiers

Quand un utilisateur envoie un fichier via un formulaire enctype="multipart/form-data", PHP le dépose dans un emplacement temporaire et remplit le tableau $_FILES. Ton travail : vérifier, puis déplacer le fichier temporaire vers sa destination définitive avec move_uploaded_file.

Ne fais jamais confiance à $_FILES['type'] ni au nom

Le type MIME et le nom du fichier sont fournis par le navigateur : un attaquant les falsifie trivialement. Il peut nommer photo.jpg un script .php et le faire exécuter s'il atterrit dans un dossier servi par le web. Vérifie toujours le type par le contenu (finfo), renomme avec une valeur aléatoire, et stocke hors de la racine web.

Un cas réel : l'avatar qui était un webshell

Cas réel

Un petit réseau social laissait ses membres choisir un avatar. Le code se contentait de vérifier l'extension du nom envoyé (.jpg) et déplaçait le fichier dans /public/avatars/, un dossier servi directement par le web. Un attaquant a envoyé un fichier nommé chat.jpg dont le contenu était en réalité du code PHP ; comme le serveur exécutait tout .php — et qu'une faille de configuration laissait passer la double extension chat.php.jpg — il a pu ouvrir la page de son « avatar » et exécuter des commandes sur le serveur : un webshell. Le correctif a appliqué les cinq règles : vérification du vrai type via finfo, nom regénéré aléatoirement, extension déduite du MIME réel, et surtout stockage hors de la racine web, les images étant ensuite servies par un script contrôlé. Un téléversement mal filtré est l'une des portes d'entrée les plus classiques ; les cinq garde-fous ne sont pas optionnels.

Antisèche

Glossaire

Flux (stream)
Abstraction PHP d'une source de données lue/écrite morceau par morceau (fichier, réseau, mémoire), sans tout charger d'un coup.
Wrapper (protocole)
Préfixe qui indique le type de flux : file://, php://memory, php://stdin, https://… Les mêmes fonctions marchent sur tous.
Descripteur de fichier
La « poignée » renvoyée par fopen, à passer à fgets/fwrite puis à refermer avec fclose.
CSV
Format texte de tableau (valeurs séparées par des virgules). À lire/écrire avec fgetcsv/fputcsv, jamais avec explode.
$_FILES
Superglobale contenant les fichiers reçus : name, type (peu fiables), tmp_name, size, error.
Type MIME
Étiquette de format (image/png, application/pdf). À déterminer par le contenu via finfo, pas par l'extension.
move_uploaded_file
Déplace en sécurité un fichier téléversé de son emplacement temporaire vers sa destination ; vérifie qu'il provient bien d'un upload HTTP.
Racine web (webroot)
Dossier public servi par le serveur. On stocke les fichiers reçus en dehors pour qu'ils ne puissent pas être exécutés.

Récap et vérification

  • Petit fichier : file_get_contents / file_put_contents / file.
  • Gros fichier : flux fopen/fgets/fclose ou SplFileObject — mémoire constante.
  • CSV : fgetcsv / fputcsv gèrent l'échappement des virgules et guillemets.
  • Un fichier reçu arrive dans $_FILES ; seuls tmp_name/size/error sont fiables.
  • Sécurité upload : vérifier le vrai type (finfo), renommer aléatoirement, stocker hors racine web.

Exercices

Exercice 1Échauffement

Ajoute une ligne "Connexion réussie\n" à la fin d'un fichier journal.log sans écraser son contenu existant.

Voir une solution

Sans FILE_APPEND, file_put_contents écraserait tout le fichier.

Exercice 2Application

Compte le nombre de lignes contenant le mot ERROR dans un gros fichier app.log, en le lisant en flux.

Voir une solution
Exercice 3Défi

Écris la validation minimale d'un téléversement d'image : refuse si l'erreur n'est pas UPLOAD_ERR_OK, si la taille dépasse 1 Mo, ou si le vrai type n'est pas image/png.

Voir une solution

On contrôle successivement le code d'erreur, la taille, puis le vrai type via finfo — jamais l'extension ni $_FILES['type'].
