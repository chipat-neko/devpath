Module 4 · CI/CD en pratique — Leçon 08

Cache, artefacts et matrices

~36 min Intermédiaire Leçon 03 recommandée

À la fin de cette leçon, tu sauras

  • mettre en cache les dépendances avec une clé fondée sur le lockfile ;
  • distinguer un cache (accélération) d'un artefact (livrable) ;
  • transmettre des fichiers d'un job à l'autre malgré leur isolation ;
  • tester plusieurs versions ou systèmes en parallèle avec une matrice.
Sommaire de la leçon

Un pipeline qui met dix minutes à chaque commit finit par être contourné : on pousse sans attendre, on ignore les échecs. La vitesse est donc une vraie fonctionnalité. Trois outils font l'essentiel du travail : le cache évite de retélécharger les dépendances à chaque fois, les artefacts transportent des fichiers d'un job à l'autre, et les matrices multiplient un job pour couvrir plusieurs versions en parallèle. Bien réglés, ils font passer un pipeline de plusieurs minutes à quelques dizaines de secondes.

Mettre les dépendances en cache

À chaque exécution, le runner démarre d'une machine vierge : aucune dépendance installée. Sans cache, il retélécharge tout (des centaines de paquets) à chaque commit. Le cache conserve ce dossier de dépendances entre les exécutions, repéré par une clé. On fonde la clé sur l'empreinte du lockfile : tant que les dépendances ne changent pas, la clé reste identique et le cache est réutilisé.

Cas réel

Sur un projet front-end moyen, npm ci à froid prend deux à trois minutes ; avec le cache des paquets, il tombe à quinze ou vingt secondes. Multiplié par des dizaines de commits par jour et par les jobs d'une matrice, le gain se compte en heures de calcul économisées — et en retour plus rapide pour les développeurs, ce qui est le vrai bénéfice : un pipeline court, on le regarde ; un pipeline long, on le fuit.

Transmettre des fichiers : les artefacts

Chaque job s'exécute sur sa propre machine isolée : ce que build produit n'existe pas pour deploy. Pour faire passer un fichier d'un job à l'autre — ou le conserver après le run pour le télécharger — on utilise un artefact : upload-artifact dans le job producteur, download-artifact dans le consommateur.

Astuce — ne confonds pas cache et artefact

Le cache est une optimisation best-effort : il peut être vidé ou manqué, et ton pipeline doit fonctionner sans lui. L'artefact est un livrable garanti : un binaire, un rapport de couverture, un site compilé, que tu veux transmettre ou télécharger à coup sûr. Règle simple : cache pour aller plus vite, artefact pour produire un résultat.

Les matrices : multiplier un job

Ta bibliothèque doit marcher sur Node 18, 20 et 22 ? Ton app sur Linux, macOS et Windows ? Plutôt que d'écrire neuf jobs, tu déclares une matrice : le pipeline génère automatiquement un job par combinaison, tous exécutés en parallèle.

fail-fast: false laisse toutes les cases finir même si l'une échoue : précieux pour voir tous les environnements qui cassent, pas seulement le premier. include ajoute une combinaison précise, exclude en retire une ; les deux affinent la grille sans la réécrire.

Piège fréquent

Une matrice explose vite : 3 OS × 4 versions × 2 bases de données = 24 jobs, autant de minutes facturées et de files d'attente. Garde des axes utiles : teste les versions que tu supportes vraiment, et réserve les grandes grilles au workflow nocturne plutôt qu'à chaque commit.

Glossaire

Cache
Copie conservée entre exécutions (souvent les dépendances) pour éviter de la reconstruire ; optimisation best-effort.
Clé de cache
Identifiant du cache, typiquement l'empreinte du lockfile : si elle change, le cache est reconstruit.
Cache trouvé / manqué
La clé existe (on restaure) ou non (on installe puis on enregistre).
restore-keys
Liste de préfixes de repli utilisés quand aucune clé exacte ne correspond.
Artefact
Fichier ou dossier livrable, téléversé par un job et récupérable par un autre ou après le run ; transfert garanti.
Isolation des jobs
Chaque job tourne sur une machine vierge : rien n'est partagé sans cache ni artefact.
Matrice
Définition qui génère un job par combinaison d'axes (OS, version…), exécutés en parallèle.
fail-fast
À true, un échec annule les autres jobs de la matrice ; à false, tous finissent.

Récap et vérification

  • Le cache (clé sur le lockfile) évite de réinstaller : cache trouvé = quelques secondes au lieu de minutes.
  • Un artefact transmet un livrable entre jobs isolés (upload / download + needs:).
  • Cache = accélération best-effort ; artefact = résultat garanti. Ne pas confondre.
  • Une matrice génère un job par combinaison, en parallèle ; fail-fast: false pour tout voir.
  • Attention à l'explosion combinatoire : garde des axes utiles.
