Module 2 · Mémoire et structures — Leçon 07

La gestion d'erreurs

~50 min Avancé Prérequis : leçon 6

À la fin de cette leçon, tu sauras

  • définir et renvoyer des erreurs (error, !T) ;
  • propager avec try et traiter avec catch ;
  • nettoyer en cas d'erreur avec errdefer ;
  • comprendre l'absence d'exceptions.
Sommaire de la leçon

Comment signaler qu'une opération a échoué ? La plupart des langages utilisent des exceptions — un mécanisme caché, au flux invisible, parfois coûteux. Fidèle à sa philosophie, Zig fait autrement : les erreurs sont des valeurs ordinaires, visibles dans les types, propagées explicitement. Pas d'exception, pas de surprise.

Définir des erreurs

On regroupe des erreurs dans un error set, comme un enum d'erreurs.

Composer et regrouper les erreurs

Deux error sets se fusionnent avec l'opérateur || : const Toutes = ErreurFichier || ErreurReseau; réunit toutes leurs variantes en un seul ensemble. À l'opposé, anyerror est l'ensemble universel — « n'importe quelle erreur » : commode pour prototyper, mais un set nommé documente bien mieux ce qui peut réellement échouer.

Les error unions

Une fonction qui peut échouer renvoie une error union, notée !T (où T est le type en cas de succès). Le ! dit : « soit un T, soit une erreur ». Le type le dit, impossible d'ignorer la possibilité d'échec.

Le !i32 (sans error set précisé) laisse Zig déduire l'ensemble des erreurs possibles.

try : propager l'erreur

Le mot-clé try devant un appel signifie : « si ça échoue, renvoie l'erreur tout de suite ». C'est la façon idiomatique de faire remonter une erreur sans s'en occuper localement.

C'est pourquoi main est souvent déclaré !void : pour pouvoir utiliser try à l'intérieur.

catch : traiter l'erreur

Pour gérer l'erreur sur place (au lieu de la propager), on utilise catch. On peut fournir une valeur de repli, ou capturer l'erreur pour réagir.

try n'est qu'un raccourci

try f() se lit exactement comme f() catch |err| return err : en cas d'erreur, on la renvoie telle quelle à l'appelant. Vu ainsi, try ne « capte » rien — il ne fait que déléguer vers le haut. Dès que tu veux réagir sur place plutôt que propager, c'est catch qu'il te faut.

switch sur les erreurs

Pour traiter chaque erreur différemment, on combine catch et switch.

errdefer : nettoyer en cas d'échec seulement

Variante de defer : errdefer ne s'exécute que si la fonction sort sur une erreur. Parfait pour annuler une allocation faite avant qu'une étape ultérieure n'échoue.

Cas réel — ouvrir un fichier de configuration au démarrage

Un outil en ligne de commande tente de lire son fichier de réglages. S'il est absent, pas de plantage : const cfg = lireConfig("app.toml") catch Config.defaut; retombe sur des valeurs par défaut. Mais si le fichier existe et qu'une allocation échoue en plein milieu de l'analyse, l'errdefer libère ce qui avait déjà été réservé — l'outil ne laisse derrière lui aucune structure à moitié initialisée. C'est exactement la discipline des vrais programmes système : un chemin d'erreur qui nettoie, sans pile d'exception à dérouler.

Pièges fréquents

Piège fréquent

Ignorer la valeur d'une fonction qui peut échouer : Zig refuse de compiler si tu n'as pas traité l'erreur (par try ou catch). C'est une force : impossible d'oublier un échec silencieusement, contrairement aux codes de retour qu'on néglige en C.

Pour aller plus loin

Pour aller plus loin

Comme les erreurs sont de simples valeurs (pas de pile d'exception à dérouler), la gestion d'erreur de Zig est très peu coûteuse — souvent un simple test de registre. C'est ce qui la rend adaptée au code haute performance et temps réel.

Glossaire

Error set
Ensemble nommé d'erreurs possibles, déclaré avec error{ … } ; s'apparente à un enum d'erreurs.
Error union (!T)
Type « soit un T, soit une erreur » : le retour d'une fonction faillible. L'appelant doit traiter l'erreur avant d'accéder à la valeur.
anyerror
L'ensemble d'erreurs universel : anyerror!T accepte n'importe quelle erreur. Commode pour prototyper, mais moins précis qu'un error set nommé qui énumère les échecs vraiment possibles.
try
Devant un appel faillible : en cas d'erreur, la propage immédiatement à la fonction appelante.
catch
Traite l'erreur sur place : fournit une valeur de repli (f() catch v) ou capture l'erreur dans un bloc (catch |e| { … }).
errdefer
Comme defer, mais l'action ne s'exécute que si la portée se termine sur une erreur ; sert à annuler une initialisation partielle.
Exception
Mécanisme d'autres langages où l'erreur « saute » hors du flux normal ; Zig ne l'utilise pas : ses erreurs sont des valeurs ordinaires.
Propagation
Faire remonter une erreur de fonction en fonction jusqu'à un endroit capable de la traiter ; réalisée par try.

Récap et vérification

  • Les erreurs sont des valeurs (error set) ; une fonction faillible renvoie une error union !T.
  • try propage l'erreur ; catch la traite (repli ou capture |err|).
  • errdefer nettoie uniquement en cas d'échec.
  • Le compilateur force à traiter chaque erreur : pas d'échec silencieux.
