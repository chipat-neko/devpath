Module 2 · Mémoire et structures — Leçon 05

Structs, enums et unions

~55 min Avancé Prérequis : leçon 4

À la fin de cette leçon, tu sauras

  • définir des structs avec champs et méthodes ;
  • utiliser les enums et les unions étiquetées ;
  • faire du pattern matching avec switch ;
  • comprendre que les types sont des valeurs.
Sommaire de la leçon

Pour modéliser des données, Zig offre les structs (regrouper des champs), les enums (un choix parmi des variantes) et les unions étiquetées (une valeur qui peut être de plusieurs types). Combinés au switch, ils donnent un système de types expressif et sûr — sans la lourdeur de la POO classique.

Les structs

Un struct regroupe des champs nommés. On peut lui donner des valeurs par défaut, et même des méthodes (des fonctions définies à l'intérieur).

On construit avec .{ .champ = valeur } ; une méthode reçoit self en premier argument.

La syntaxe .{ … } d'initialisation

On construit une instance en préfixant chaque champ d'un point : Point{ .x = 3, .y = 4 }. Ce point rappelle qu'on nomme le champ (aucune position à deviner). Quand le type est déjà connu (paramètre, valeur de retour), on peut même écrire .{ .x = 3, .y = 4 } : Zig complète le nom du type tout seul.

Les types sont des valeurs

Concept déroutant mais puissant : en Zig, un type est une valeur comme une autre, qu'on peut stocker dans une const. C'est pourquoi const Point = struct {…} ressemble à une affectation : on assigne un type à un nom. Cette idée est la clé de la généricité (leçon 8).

Les enums

Un enum définit un type à valeurs limitées. Le switch sur un enum est exhaustif : le compilateur exige tous les cas.

Dans le switch, on peut écrire .vert sans répéter le nom du type : Zig le déduit.

Les unions étiquetées

Une union étiquetée (tagged union) représente une valeur qui peut être de plusieurs types, mais d'un seul à la fois — l'équivalent des types somme. Chaque variante peut porter une donnée.

Le switch déballe la donnée de chaque variante via la capture |r|.

Le pattern résultat

Les unions étiquetées servent à modéliser des états ou des résultats de façon sûre : chaque cas est traité explicitement, impossible d'en oublier un.

Cas réel — l'état d'un chargement, sans cas oublié

Une interface qui récupère des données passe par des états distincts : chargement, succès (avec les données), échec (avec le message d'erreur). En modélisant cela par une union(enum), le switch t'oblige à dessiner chaque état — impossible d'afficher un écran blanc parce qu'on a oublié le cas « erreur ». C'est exactement le type Result/Loadable qu'on retrouve dans Rust, Elm ou les composants React.

Pièges fréquents

Piège fréquent

Accéder à la mauvaise variante d'une union : lire f.rectangle alors que f est un .cercle est une erreur (détectée en mode debug). Passe toujours par un switch qui te donne la bonne donnée pour le bon cas.

Pour aller plus loin

Pour aller plus loin

Zig n'a pas d'héritage de classe. Pour partager du comportement, on compose des structs et on utilise les unions et la généricité comptime. Cette absence est délibérée : elle évite la complexité et les hiérarchies fragiles de la POO classique.

Glossaire

struct
Type qui regroupe des champs nommés, éventuellement des valeurs par défaut et des méthodes.
Méthode
Fonction définie dans un struct et recevant self en premier argument ; appelée instance.methode().
enum
Type à valeurs limitées : une valeur est exactement l'une des variantes listées.
Union étiquetée
union(enum) : une valeur qui est de l'un de plusieurs types, avec une étiquette (tag) indiquant lequel est actif.
Type somme
Type « soit… soit… » (l'union étiquetée), par opposition au « et… et… » du struct.
tag
L'étiquette qui mémorise, dans une union, quelle variante est actuellement active.
Pattern matching
Traitement d'une valeur cas par cas via switch, en déballant la donnée de chaque variante avec |x|.
Type-valeur
En Zig, un type est une valeur manipulable à la compilation (comptime), ce qui fonde la généricité.

Récap et vérification

  • Un struct regroupe des champs et peut avoir des méthodes (self en premier).
  • En Zig, un type est une valeur (const Point = struct{…}).
  • Les enums limitent les valeurs ; le switch dessus est exhaustif.
  • Les unions étiquetées (union(enum)) modélisent des types somme ; on les déballe par switch.
