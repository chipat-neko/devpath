Module 1 · Les bases de Zig — Leçon 03

Conditions, boucles et optionnels

~50 min Avancé Prérequis : leçon 2

À la fin de cette leçon, tu sauras

  • écrire des conditions et boucles (if, while, for) ;
  • utiliser if/switch comme expressions ;
  • manier les optionnels (?T) au lieu de null ;
  • déballer avec if (opt) |valeur| et orelse.
Sommaire de la leçon

Le contrôle du flux en Zig est familier — if, while, for — mais avec deux raffinements : ce sont souvent des expressions (qui renvoient une valeur), et Zig remplace le dangereux null du C par les optionnels, un type qui rend l'absence de valeur explicite et sûre.

if / else

Pas de parenthèses obligatoires autour de la condition ? Si, en Zig elles le sont. Mais le if peut renvoyer une valeur, comme un ternaire.

while

La boucle while répète tant que la condition tient. Une clause : (expr) permet d'exécuter une mise à jour à chaque tour (pratique comme un for du C).

La clause de continuation

La clause : (j += 1) après la condition s'exécute à la fin de chaque tour, même quand on saute au suivant avec continue. C'est le while qui remplace le for (…;…;…) du C : la mise à jour du compteur reste visible en tête de boucle, jamais oubliée au fond du corps.

for

for parcourt un tableau ou un slice, en liant chaque élément à une variable entre barres verticales |x|.

La syntaxe |valeur| (capture) revient partout en Zig : dans les boucles, les optionnels, les erreurs.

Les optionnels : en finir avec null

Voici un apport clé. Une valeur qui peut être absente a un type optionnel, noté ?T. Impossible de l'utiliser sans avoir vérifié sa présence : le compilateur t'y oblige. Fini les déréférencements de pointeur nul du C.

orelse : une valeur de repli

Pour fournir une valeur par défaut quand l'optionnel est absent : orelse.

Cas réel — une valeur de configuration par défaut

Un programme lit souvent un réglage qui peut être absent : un numéro de port dans une variable d'environnement, une option de ligne de commande… On modélise « peut-être présent » par un optionnel, et orelse fournit le repli en une ligne : const port = lire_port() orelse 8080;. Aucun null qui traîne, aucun plantage : soit la valeur lue, soit 8080.

switch : exhaustif

switch est une expression puissante : il doit couvrir tous les cas (exhaustivité vérifiée par le compilateur), avec else pour le reste.

Pièges fréquents

Piège fréquent

Vouloir utiliser un optionnel comme une valeur normale : maybe + 1 échoue tant que tu n'as pas déballé l'optionnel. C'est voulu : ça t'oblige à traiter le cas « absent », éliminant les plantages liés au null.

Pour aller plus loin

Pour aller plus loin

Un switch sur un enum sans else force à traiter chaque variante : si tu ajoutes une variante plus tard, le compilateur signale tous les switch à mettre à jour. Une sécurité que les langages à null n'offrent pas.

Glossaire

Expression
Bout de code qui produit une valeur. En Zig, if et switch sont des expressions : on peut en affecter le résultat.
Clause de continuation
La partie : (i += 1) d'un while, exécutée à la fin de chaque tour ; joue le rôle du 3ᵉ terme du for du C.
Capture
La syntaxe |x| qui lie un élément à un nom : dans les boucles for, le déballage d'optionnels, la gestion d'erreurs.
Optionnel
Type ?T qui contient soit une valeur de type T, soit null ; il rend l'absence explicite et sûre.
null
L'absence de valeur. En Zig, elle n'existe qu'au sein d'un optionnel : impossible de déréférencer un null par accident.
orelse
Opérateur qui déballe un optionnel s'il est présent, sinon renvoie l'expression de droite (valeur de repli).
switch exhaustif
switch qui doit couvrir tous les cas possibles ; le compilateur refuse un cas oublié (surtout sur un enum).
Déballer
Extraire la valeur contenue dans un optionnel (ou une union) après avoir vérifié qu'elle est présente.

Récap et vérification

  • if, while (avec clause : (…)), for (capture |x|) ; if et switch sont des expressions.
  • Les optionnels ?T remplacent null et obligent à vérifier la présence.
  • On déballe avec if (opt) |v| et on fournit un repli avec orelse.
  • switch est exhaustif : tous les cas doivent être couverts.

Vérifie ta compréhension

  1. Que signifie le type ?i32 ?
  2. Comment fournir une valeur par défaut à un optionnel absent ?
  3. Pourquoi le switch exhaustif est-il une sécurité ?
