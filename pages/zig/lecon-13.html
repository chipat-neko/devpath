Module 4 · Zig en profondeur — Leçon 13

build.zig et cross-compilation

~45 min Avancé Prérequis : leçon 12

À la fin de cette leçon, tu sauras

  • écrire un build.zig (cibles, options) ;
  • cross-compiler vers une autre plateforme en une commande ;
  • utiliser Zig comme compilateur C ;
  • saisir pourquoi la cross-compilation est si simple en Zig.
Sommaire de la leçon

Zig a un argument qui, à lui seul, séduit beaucoup de développeurs : la cross-compilation triviale. Produire un exécutable pour Windows depuis un Mac, ou pour un Raspberry Pi depuis un PC, tient en une seule option de ligne de commande — là où c'est un calvaire dans la plupart des écosystèmes. Derrière cela : un système de build intégré (build.zig) et un compilateur qui embarque tout ce qu'il faut. Cette leçon te montre comment construire et cibler n'importe quelle plateforme.

Le système de build : build.zig

Zig n'utilise ni Makefile, ni CMake, ni outil externe : le build se décrit dans un fichier build.zig… écrit en Zig. On y déclare ses exécutables, ses bibliothèques, ses options. La logique de build est donc un vrai programme, pas un format de configuration figé.

On lance le tout avec zig build. Les commandes courantes : zig build (compile), zig build run (compile et exécute), zig build test (lance les tests).

La cross-compilation en une commande

Voici l'atout phare. Pour cibler une autre plateforme, on ajoute simplement l'option -Dtarget. Pas de chaîne de compilation croisée à installer, pas de bibliothèques système à récupérer : Zig embarque tout.

Une cible Zig s'écrit architecture-os (parfois -abi). Que tu sois sur Linux, Windows ou Mac, tu produis un binaire pour n'importe quelle autre plateforme. Cette simplicité est, pour beaucoup, la raison d'essayer Zig.

Les modes d'optimisation

Zig propose quatre modes, choisis explicitement : on décide du compromis entre sûreté, vitesse et taille.

  • Debug (défaut) : compilation rapide, toutes les vérifications de sûreté actives ;
  • ReleaseSafe : optimisé mais avec les vérifications de sûreté (débordements, accès hors bornes) ;
  • ReleaseFast : vitesse maximale, vérifications retirées ;
  • ReleaseSmall : binaire le plus petit possible.

Zig comme compilateur C

Bonus inattendu : le compilateur Zig est aussi un excellent compilateur C, avec la même cross-compilation triviale. zig cc peut remplacer gcc/clang et compiler du C pour n'importe quelle cible, sans installer de toolchain croisée.

Beaucoup de projets utilisent zig cc uniquement pour cette capacité, sans écrire une ligne de Zig : c'est dire la qualité de son outillage de compilation.

Cas réel — Uber cross-compile son code C avec zig cc

Les projets Go qui appellent du C (via cgo) doivent embarquer un compilateur C pour chaque plateforme visée : un casse-tête d'installation et de maintenance. Les équipes d'Uber ont remplacé cette pile par un simple zig cc : un seul outil, quelques dizaines de mégaoctets, qui cross-compile le C vers Linux, macOS et Windows depuis n'importe quelle machine de CI. Ni Uber ni ces projets n'écrivent de Zig : ils empruntent uniquement son compilateur C et sa cross-compilation intégrée. C'est l'illustration la plus parlante que l'outillage de Zig vaut à lui seul le détour.

Pourquoi c'est si simple en Zig

La cross-compilation est difficile ailleurs parce qu'il faut, pour chaque cible, la bonne chaîne d'outils et les bibliothèques système correspondantes. Zig fait un choix d'ingénierie : il embarque les en-têtes et bibliothèques nécessaires et gère lui-même la génération de code pour chaque architecture. La complexité a été absorbée une fois pour toutes dans le compilateur — pour que toi, tu n'aies qu'une option à taper.

Pièges fréquents

Piège fréquent

Confondre build.zig (le programme de build, en Zig) et build.zig.zon (le manifeste de dépendances, au format données). Le premier décrit comment construire ; le second liste les paquets dont le projet dépend. Et n'oublie pas que Zig est encore jeune (avant la version 1.0) : la syntaxe de build.zig a évolué entre versions. Vérifie toujours que la documentation que tu suis correspond à ta version de Zig.

Pour aller plus loin

Pour aller plus loin

Le cours ne s'arrête pas là : le module suivant « Zig avancé » aborde les tests intégrés, les pointeurs façon système, les threads et la généricité, avant le projet final où tu assembleras tout dans un vrai outil en ligne de commande. En attendant, entraîne-toi : compile un même programme pour trois plateformes et compare les binaires produits — tu mesureras concrètement ce que « cross-compilation triviale » veut dire. Suis aussi l'évolution du langage : Zig n'a pas encore atteint sa version 1.0, et chaque version affine l'outillage. C'est un langage jeune, mais dont les idées (pas d'allocation cachée, comptime, cross-compilation) influencent déjà toute une génération.

Glossaire

build.zig
Fichier décrivant la construction du projet, écrit en Zig ; la logique de build est un vrai programme, lancé par zig build.
build.zig.zon
Manifeste listant les dépendances du projet (format de données « ZON ») ; à ne pas confondre avec build.zig.
Cross-compilation
Produire, depuis une machine, un exécutable destiné à une autre plateforme ; en Zig, une simple option -Dtarget.
Cible (target)
Plateforme visée, écrite architecture-os (parfois -abi), par ex. aarch64-linux ou x86_64-windows.
Mode d'optimisation
Compromis de compilation choisi explicitement : Debug, ReleaseSafe, ReleaseFast, ReleaseSmall.
ReleaseSafe
Mode optimisé qui conserve les vérifications de sûreté (débordements, accès hors bornes) ; souvent le meilleur défaut en production.
ReleaseFast
Mode visant la vitesse maximale ; les vérifications de sûreté sont retirées.
zig cc
Le compilateur Zig employé comme compilateur C ; remplace gcc/clang avec la même cross-compilation triviale.

Récap et vérification

  • Le build se décrit dans build.zig, écrit en Zig ; zig build, zig build run, zig build test.
  • Cross-compilation en une option : -Dtarget=arch-os ; Zig embarque tout le nécessaire.
  • Quatre modes d'optimisation : Debug, ReleaseSafe, ReleaseFast, ReleaseSmall.
  • zig cc compile aussi du C avec la même cross-compilation ; Zig est jeune (avant la 1.0).

Exercice 3Défi

En une phrase, pourquoi la cross-compilation est-elle plus simple en Zig que dans la plupart des autres écosystèmes ?

Voir une solution

Parce que Zig embarque lui-même les en-têtes, les bibliothèques système et la génération de code pour chaque architecture : il n'y a aucune chaîne d'outils croisée ni bibliothèque cible à installer séparément. La complexité a été absorbée une fois dans le compilateur, si bien qu'il suffit d'une option (-Dtarget=…) pour viser n'importe quelle plateforme.
