Module 3 · Administrer le système — Leçon 12

Bonnes pratiques et écosystème

~45 min Intermédiaire Prérequis : leçon 11

À la fin de cette leçon, tu sauras

  • adopter les bonnes pratiques (verbes approuvés, sortie objet, idempotence) ;
  • tester ton code avec Pester ;
  • comprendre PowerShell 7 (Core) et le multiplateforme ;
  • situer l'écosystème (DSC, Azure, CI/CD) pour continuer.
Sommaire de la leçon

Tu sais désormais scripter, structurer, administrer. Cette leçon consolide ta pratique : les bonnes habitudes qui rendent un script lisible et fiable, les tests avec Pester, et l'horizon de PowerShell — multiplateforme, présent dans le cloud et l'automatisation moderne. Les modules suivants approfondissent ensuite le texte, le Web, les classes et la sécurité, jusqu'au projet final.

Des verbes approuvés, des noms au singulier

Pour que tes commandes s'intègrent à l'écosystème, respecte la convention : un verbe approuvé (liste donnée par Get-Verb) et un nom au singulier. Get-, Set-, New-, Remove- couvrent l'essentiel.

Sortir des objets, viser l'idempotence

Deux principes d'or. Renvoie des objets (pas du texte) pour que ton script s'enchaîne avec d'autres. Et vise l'idempotence : relancer le script doit donner le même état final, sans casse — vérifie avant d'agir.

Tester avec Pester

Pester est le cadre de tests de PowerShell. On décrit un comportement attendu avec Describe/It et on l'affirme avec Should.

Des tests transforment chaque modification en filet de sécurité.

PowerShell 7 : multiplateforme

Il existe deux PowerShell. Windows PowerShell 5.1 est figé, lié au .NET Framework et à Windows. PowerShell 7 (commande pwsh) est open source, basé sur .NET moderne, et tourne sur Windows, macOS et Linux. Pour tout nouveau projet, privilégie PowerShell 7.

Quelques différences à connaître

PowerShell 7 apporte le parallélisme (-Parallel), les opérateurs ternaire (?:) et de chaînage (&&, ||), et un meilleur support du réseau. La majorité du code 5.1 fonctionne en 7, mais quelques cmdlets liées à Windows n'existent qu'en 5.1.

L'écosystème pour continuer

PowerShell est partout : Azure (module Az pour piloter le cloud), CI/CD (scripts d'intégration continue), DSC (Desired State Configuration, pour décrire l'état d'une machine), administration de Microsoft 365, conteneurs… Les compétences de ce cours t'ouvrent toutes ces portes.

Un cas réel — un test qui sauve un déploiement

Cas réel : Pester dans l'intégration continue

Une équipe versionne ses modules PowerShell. À chaque commit, un pipeline d'intégration continue lance Invoke-Pester. Le jour où une modification casse le calcul d'une remise, un test Should -Be échoue : le pipeline passe au rouge et bloque le déploiement avant que le bug n'atteigne la production.

Chaque test devient un garde-fou permanent, rejoué à chaque changement — l'idempotence et la sortie objet rendent d'ailleurs le code plus facile à tester.

Pièges fréquents

Piège fréquent

Écrire un script qui ne marche qu'en 5.1 (avec Write-Host partout et des cmdlets Windows) puis vouloir le porter sur Linux. Pense multiplateforme dès le départ : sortie objet, chemins via Join-Path, et pwsh comme cible.

Pour aller plus loin

Pour aller plus loin

Installe l'extension PowerShell de VS Code : coloration, débogage pas à pas, exécution sélective et analyse statique avec PSScriptAnalyzer, qui repère verbes non approuvés, alias dans les scripts et autres mauvaises habitudes.

Glossaire

Verbe approuvé
Verbe de la liste officielle (Get-Verb) recommandé pour nommer une commande.
Idempotence
Propriété d'une opération dont la répétition donne le même état final, sans effet de bord.
Pester
Cadre de tests standard de PowerShell (Describe/It/Should).
Should
Assertion Pester vérifiant qu'un résultat correspond à ce qui est attendu.
Windows PowerShell 5.1
Édition Windows, figée, bâtie sur le .NET Framework.
PowerShell 7 (Core)
Édition open source et multiplateforme ; commande pwsh.
DSC
Desired State Configuration : décrit l'état voulu d'une machine, appliqué automatiquement.
PSScriptAnalyzer
Analyseur statique repérant verbes non approuvés, alias et autres mauvaises pratiques.

Récap et vérification

  • Respecte les verbes approuvés (Get-Verb) et les noms au singulier.
  • Renvoie des objets et vise l'idempotence.
  • Pester (Describe/It/Should) teste ton code.
  • PowerShell 7 (pwsh) est multiplateforme : à privilégier pour tout nouveau projet.

  2. Qu'est-ce que l'idempotence et pourquoi la viser ?
  3. Quelle est la principale différence entre PowerShell 5.1 et 7 ?
