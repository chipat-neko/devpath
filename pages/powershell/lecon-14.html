Module 4 · PowerShell en pratique — Leçon 14

Dialoguer avec le Web : REST et JSON

~52 min Intermédiaire Prérequis : leçon 13

À la fin de cette leçon, tu sauras

  • appeler une API web avec Invoke-RestMethod et obtenir des objets ;
  • inspecter une réponse brute avec Invoke-WebRequest (statut, en-têtes) ;
  • envoyer des données en POST avec -Body et t'authentifier via -Headers ;
  • convertir dans les deux sens avec ConvertTo-Json et ConvertFrom-Json.
Sommaire de la leçon

Automatiser, ce n'est pas seulement piloter sa machine : c'est aussi dialoguer avec les services web — une API de météo, le dépôt GitHub d'un projet, une passerelle de paiement, un webhook de messagerie. PowerShell propose pour cela des cmdlets de première classe qui transforment le JSON du web en objets exploitables au pipeline.

Invoke-RestMethod : l'API en une ligne

Invoke-RestMethod (souvent abrégé irm) envoie une requête HTTP et — c'est là sa magie — désérialise automatiquement la réponse JSON en objets PowerShell. Plus besoin de découper du texte : on accède directement aux propriétés.

Invoke-WebRequest : la réponse brute

Quand on a besoin du détail de la réponse — code de statut, en-têtes, contenu non interprété — on utilise Invoke-WebRequest (alias iwr). Il renvoie un objet réponse complet.

Lequel choisir ?

API JSON et tu veux les données ? Invoke-RestMethod. Tu veux inspecter la réponse HTTP (statut, en-têtes) ou télécharger un fichier brut ? Invoke-WebRequest.

Envoyer des données : POST, corps et en-têtes

Créer une ressource se fait en POST. On passe le corps avec -Body (souvent du JSON produit par ConvertTo-Json) et l'on précise le type avec -ContentType. L'authentification passe presque toujours par un en-tête Authorization.

Attention : ne code jamais un secret en dur

Un jeton d'API écrit dans un script finit dans l'historique Git et les journaux. Lis-le depuis une variable d'environnement ($env:API_TOKEN) ou un gestionnaire de secrets. On revient sur la manipulation sûre des identifiants dans la leçon suivante.

JSON dans les deux sens

Deux cmdlets font le pont entre objets et texte JSON : ConvertTo-Json (objet → texte, pour l'envoi) et ConvertFrom-Json (texte → objet, quand tu as déjà la chaîne). Invoke-RestMethod fait le second pour toi ; les deux te servent avec des fichiers locaux.

Piège fréquent : la profondeur par défaut

ConvertTo-Json ne descend que de 2 niveaux par défaut ; au-delà, il remplace le contenu par sa simple représentation texte — @{ville=Lyon} pour un [pscustomobject], System.Collections.Hashtable pour une table de hachage, et les valeurs collées par une espace pour un tableau ("alertes": "pluie vent"). Pour un objet imbriqué, augmente -Depth (par exemple -Depth 10).

Un cas réel — surveiller les versions d'un outil

Cas réel : la dernière version publiée d'un projet

Une équipe veut être prévenue quand une nouvelle version d'un outil sort. L'API publique de GitHub expose la dernière release : un appel Invoke-RestMethod suffit, et le résultat est un objet dont on lit le numéro de version et la date.

À planifier chaque matin (leçon 11) pour recevoir une alerte quand la version change.

Pour aller plus loin

Pour aller plus loin

Beaucoup d'API paginent leurs résultats. En PowerShell 7, Invoke-RestMethod -FollowRelLink suit tout seul les liens « page suivante ». Pense aussi à gérer le code 429 (trop de requêtes) en respectant l'en-tête Retry-After, et enveloppe tes appels dans un try/catch (leçon 8) pour traiter les erreurs réseau.

Glossaire

API
Interface par laquelle un service expose des données ou des actions, souvent via HTTP.
REST
Style d'API utilisant les verbes HTTP (GET, POST…) et, le plus souvent, le format JSON.
JSON
Format texte d'échange de données structurées (objets, tableaux, nombres, chaînes).
Invoke-RestMethod
Cmdlet qui appelle une API et désérialise automatiquement le JSON en objets.
Invoke-WebRequest
Cmdlet renvoyant la réponse HTTP complète (statut, en-têtes, contenu).
Sérialiser
Transformer un objet en texte (ici JSON) pour l'envoyer ou le stocker.
En-tête (header)
Métadonnée d'une requête HTTP, dont Authorization pour l'authentification.
Jeton (token)
Secret prouvant l'identité de l'appelant auprès d'une API, transmis en en-tête.

Récap et vérification

  • Invoke-RestMethod appelle une API et renvoie directement des objets ; Invoke-WebRequest donne la réponse brute.
  • On envoie avec -Method Post, -Body et -ContentType ; on s'authentifie via -Headers.
  • ConvertTo-Json / ConvertFrom-Json font le pont objet ⇄ texte — pense à -Depth.
  • Jamais de secret en dur : variable d'environnement ou gestionnaire de secrets.
