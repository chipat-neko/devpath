Module 2 · Scripts et fonctions — Leçon 08

Gestion des erreurs

~50 min Intermédiaire Prérequis : leçon 7

À la fin de cette leçon, tu sauras

  • distinguer erreurs terminantes et non terminantes ;
  • capturer avec try/catch/finally et -ErrorAction Stop ;
  • piloter le comportement via $ErrorActionPreference et $Error ;
  • lever ses propres erreurs (throw, Write-Error).
Sommaire de la leçon

Un script qui automatise une tâche réelle doit savoir réagir aux problèmes : un fichier absent, un service injoignable, une saisie aberrante. PowerShell a un modèle d'erreurs particulier qu'il faut comprendre pour écrire du code robuste : la distinction entre erreurs terminantes et non terminantes.

Deux familles d'erreurs

Une erreur non terminante signale un souci mais laisse le script continuer (par exemple, un fichier introuvable parmi plusieurs). Une erreur terminante interrompt l'exécution. La plupart des cmdlets émettent des erreurs non terminantes par défaut : un try/catch ne les attrapera donc pas… sauf si on les transforme en terminantes.

try / catch / finally

Le bloc try contient le code risqué ; catch s'exécute si une erreur terminante survient ; finally s'exécute toujours (nettoyage). Pour capturer une erreur de cmdlet, force-la en terminante avec -ErrorAction Stop.

Dans le catch, $_ est l'enregistrement d'erreur ; $_.Exception.Message en donne le texte.

-ErrorAction et $ErrorActionPreference

Le paramètre commun -ErrorAction règle le comportement d'une commande : Stop (lève une terminante), SilentlyContinue (ignore en silence), Continue (défaut). La variable $ErrorActionPreference fixe le comportement global du script.

Capturer une erreur ciblée

On peut prévoir plusieurs catch, par type d'exception, pour réagir différemment selon le problème.

Lever ses propres erreurs

throw déclenche une erreur terminante ; Write-Error émet une erreur non terminante. Utilise throw quand la situation empêche de poursuivre.

Inspecter les erreurs passées

La variable automatique $Error est une liste des erreurs récentes, la plus récente en tête ($Error[0]). Pratique pour déboguer après coup.

La gestion d'erreurs dans un vrai script

Cas réel : une sauvegarde robuste par lot

Un script copie chaque soir une liste de fichiers vers un dossier de secours. Un fichier manquant ne doit pas faire tout échouer : on entoure chaque copie d'un try/catch (avec -ErrorAction Stop), on mémorise les échecs et on poursuit. À la fin, un bilan indique ce qui reste à reprendre.

Sans -ErrorAction Stop, l'erreur de copie resterait non terminante et le catch ne verrait jamais l'échec : le bilan serait faussement vide.

Pièges fréquents

Piège fréquent

Entourer une cmdlet d'un try/catch sans -ErrorAction Stop : comme l'erreur est non terminante, le catch ne se déclenche jamais et tu crois à tort que tout va bien. Pense toujours à -ErrorAction Stop dans un try.

Pour aller plus loin

Pour aller plus loin

Pour les opérations en masse, -ErrorVariable maVar collecte les erreurs dans une variable sans interrompre le traitement. Tu traites le lot, puis tu examines $maVar pour les échecs.

Glossaire

Erreur terminante
Erreur qui interrompt l'exécution ; seule sorte attrapée par catch.
Erreur non terminante
Erreur signalée mais qui laisse le script continuer (défaut de nombreuses cmdlets).
try / catch / finally
Structure de gestion : code risqué, rattrapage, nettoyage systématique.
-ErrorAction
Paramètre commun réglant la réaction d'une commande (Stop, SilentlyContinue…).
$ErrorActionPreference
Variable fixant le comportement d'erreur pour tout le script.
throw
Lève une erreur terminante immédiate avec un message.
Write-Error
Émet une erreur non terminante sans arrêter l'exécution.
$Error
Liste automatique des erreurs récentes, la plus récente en $Error[0].

Récap et vérification

  • Les erreurs sont terminantes ou non terminantes ; un try/catch n'attrape que les terminantes.
  • -ErrorAction Stop force une cmdlet à lever une erreur terminante.
  • try/catch/finally structure la gestion ; $_ y porte l'erreur.
  • throw (terminante) et Write-Error (non terminante) signalent tes propres problèmes.

Vérifie ta compréhension

  1. Pourquoi un try/catch n'attrape-t-il parfois pas l'erreur d'une cmdlet ?
  2. Quand utiliser throw plutôt que Write-Error ?
  3. À quoi sert le bloc finally ?
