Module 1 · Les bases de Dart — Leçon 02

Types, null safety et chaînes

~50 min Débutant Prérequis : leçon 1

À la fin de cette leçon, tu sauras

  • Savoir manipuler les types de base (int, double, num, bool, String) et les convertir explicitement ;
  • Savoir lire et exploiter la sound null safety : String?, ?., ??, ??=, !, late et la promotion de type ;
  • Savoir composer des chaînes avec l'interpolation $nom et ${expr}, les littéraux multilignes et les méthodes utiles ;
  • Savoir reconnaître un record de Dart 3 et préférer Object? à dynamic.
Sommaire de la leçon

Dans la leçon précédente, tu as écrit et exécuté ton premier programme Dart. Place maintenant aux fondations du langage : son système de types. Dart est typé statiquement, mais sa vraie signature, ce qui le distingue de JavaScript ou même de versions plus anciennes de Java, c'est la sound null safety : le type d'une variable t'indique, à la lecture, si elle peut valoir null ou non. Le compilateur s'en sert pour t'empêcher d'écrire le bug le plus courant de toute l'histoire du logiciel : déréférencer une valeur nulle.

Dans cette leçon, on parcourt les types de base, on apprend à composer des chaînes proprement, puis on plonge au cœur de Dart 3 : la null safety, et un premier regard sur les records. À la fin, tu sauras lire un type Dart comme une phrase qui te dit exactement à quoi t'attendre.

Les types de base

Dart propose un petit jeu de types numériques et primitifs. Les deux types numériques concrets sont int (entier) et double (flottant) ; ils héritent tous deux de num, le type commun quand tu acceptes l'un ou l'autre. À cela s'ajoutent bool (strictement true ou false, jamais une valeur « truthy ») et String pour le texte.

Remarque : quelconque est déclaré num, donc on peut l'additionner à un double sans broncher. En pratique, on déclare rarement les types à la main quand le compilateur peut les deviner : final nom = 'Dart'; infère String automatiquement. On y revient dans une prochaine leçon.

Conversions explicites

Dart ne convertit jamais les types numériques implicitement. Un int n'est pas un String, et écrire '3' + 4 est une erreur de compilation (l'opérateur + d'une String attend une autre String), pas une concaténation surprise. Tu convertis donc à la main, ce qui rend les bugs visibles tôt.

Astuce

Préfère int.tryParse / double.tryParse à parse dès que l'entrée vient de l'extérieur (utilisateur, réseau, fichier). Tu obtiens un int? au lieu d'une exception, et le type te force ensuite à gérer le cas nul.

Les chaînes et l'interpolation

On compose les chaînes en Dart non pas avec + mais avec l'interpolation. Pour insérer une variable, on écrit $nom ; pour insérer une expression, on l'entoure d'accolades : ${expr}. C'est l'idiome officiel : plus lisible et plus rapide que la concaténation.

Les String exposent une riche API : length, toUpperCase(), trim(), split(), contains(), replaceAll(), substring()… Comme en Java ou JS, une String est immuable : chaque méthode renvoie une nouvelle chaîne plutôt que de modifier l'originale.

Sound null safety : le type dit tout

Voici le cœur de Dart 3. Par défaut, un type ne peut pas contenir null. Une String est toujours une vraie chaîne. Si tu veux autoriser l'absence de valeur, tu ajoutes un ? au type : String? est « une chaîne ou null ». Le type devient une documentation que le compilateur fait respecter.

« Sound » (sain) signifie que la garantie tient à la fois à la compilation (le compilateur refuse le code douteux) et à l'exécution : il n'existe aucun moyen de glisser un null dans un type non-nullable par une porte dérobée. Tu peux donc faire confiance au type sans relire tout le code qui a produit la valeur.

Cas réel

En 2009, l'informaticien Tony Hoare — l'inventeur de la référence nulle en 1965 — l'a publiquement qualifiée de « erreur à un milliard de dollars », tant les NullPointerException et autres « null is not an object » ont provoqué de plantages et de failles pendant un demi-siècle. La null safety de Dart est la réponse directe à ce fléau : en marquant le nullable dans le type, elle transforme un crash à l'exécution (que subit l'utilisateur) en une erreur de compilation (que voit le développeur). C'est le même choix qu'ont fait Kotlin, Swift et Rust.

Travailler avec le nullable : ?. ?? ??= et la promotion

Puisque le compilateur refuse d'accéder directement à un membre d'un String?, Dart te donne des outils pour le faire en sécurité.

La promotion de type est la voie idiomatique : un simple if (x != null) et, dans le bloc, Dart sait que x n'est plus nul. Tu accèdes alors à ses membres sans cérémonie.

! et late : à manier avec soin

L'opérateur ! est une assertion non-null : tu jures au compilateur que la valeur n'est pas null. S'il s'avère qu'elle l'est, le programme plante à l'exécution. C'est une promesse que tu fais à la place du compilateur : à éviter sauf certitude absolue.

Le mot-clé late répond à un autre besoin : une variable non-nullable dont tu connais la valeur plus tard, mais à coup sûr avant le premier usage. Tu promets une initialisation différée garantie.

Note

late a un second usage utile : l'initialisation paresseuse. late final x = calculCouteux(); n'exécute calculCouteux() qu'au premier accès à x, jamais si x n'est pas lu.

Un avant-goût des records (Dart 3)

Dart 3 a introduit les records : des regroupements légers et immuables de plusieurs valeurs, sans déclarer de classe. Le type s'écrit avec des parenthèses, par exemple (int, String). C'est parfait pour renvoyer plusieurs valeurs d'une fonction.

On approfondira les records (champs nommés, motifs de destructuration) plus tard ; retiens pour l'instant qu'ils existent et qu'ils remplacent avantageusement les vieux retours multiples bricolés avec des List ou des classes jetables.

dynamic vs Object? : éviter le premier

Deux types semblent « accepter n'importe quoi », mais ils sont très différents. Object? est le sommet de la hiérarchie : tout est un Object?, y compris null. Mais le compilateur t'oblige à vérifier le type réel avant d'appeler une méthode. dynamic, lui, désactive toute vérification statique : tu retrouves le comportement de JavaScript, et les erreurs n'apparaissent qu'à l'exécution.

Règle simple : préfère Object? quand tu manipules une valeur de type inconnu, et garde la vérification de type que le compilateur t'impose. Réserve dynamic aux rares cas d'interopérabilité (JSON brut, ponts JS) où tu n'as pas le choix.

Pièges fréquents

Piège fréquent

Abuser de l'opérateur ! pour « faire taire » le compilateur transforme une erreur de compilation (que tu vois) en plantage à l'exécution (que ton utilisateur voit). Chaque ! est une dette : préfère if (x != null), ?? ou ?..

Piège fréquent

La promotion de type ne fonctionne pas sur les champs d'instance non-final (un autre code pourrait les modifier entre le test et l'usage). Copie alors la valeur dans une variable locale : final v = monChamp; if (v != null) { ... }.

Glossaire

num
Type numérique parent de int et double ; à utiliser quand on accepte l'un ou l'autre.
Sound null safety
Système qui garantit, à la compilation et à l'exécution, qu'un type non-nullable ne contiendra jamais null.
Type nullable (?)
Type suffixé de ? (ex. String?) autorisant explicitement la valeur null.
Promotion de type
Après if (x != null), Dart considère x comme non-nullable dans le bloc : on accède à ses membres sans opérateur.
Opérateur ??
Fournit une valeur de repli quand l'opérande de gauche est null.
Assertion non-null (!)
Affirme au compilateur qu'une valeur n'est pas null ; provoque une erreur à l'exécution si elle l'est.
late
Déclare une variable non-nullable initialisée après coup, ou de façon paresseuse au premier accès.
Record
Regroupement léger et immuable de plusieurs valeurs (Dart 3), écrit avec des parenthèses ; idéal pour un retour multiple.

Récap et vérification

  • int, double (tous deux num), bool et String forment les types de base ; aucune conversion numérique n'est implicite.
  • On convertit explicitement avec int.parse / tryParse et toString().
  • L'interpolation $nom et ${expr} est l'idiome pour composer des chaînes ; les triples guillemets gèrent le multiligne.
  • La sound null safety : T exclut null, T? l'autorise ; garanties à la compilation et à l'exécution.
  • Outils du nullable : ?., ??, ??=, la promotion via if (x != null), et avec parcimonie ! et late.
  • Les records regroupent plusieurs valeurs sans classe ; préfère Object? à dynamic.
