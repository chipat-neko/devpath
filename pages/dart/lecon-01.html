Module 1 · Les bases de Dart — Leçon 01

Découvrir Dart

~40 min Débutant Prérequis : bases de la programmation

À la fin de cette leçon, tu sauras

  • Comprendre pourquoi Dart existe et comment il compile (AOT natif et JavaScript) ;
  • Écrire un premier programme avec main() et print, sur DartPad ou via le SDK ;
  • Choisir entre var, final et const et saisir l'idée de typage sound ;
  • Appliquer les conventions officielles de nommage et de commentaires dès la première ligne.
Sommaire de la leçon

Bienvenue dans ce cours sur Dart. Si tu connais déjà un langage à accolades comme JavaScript ou Java, tu vas te sentir chez toi très vite : la syntaxe te paraîtra familière. Mais Dart a sa propre philosophie, et c'est elle qui le rend agréable. Dart est un langage typé et sain, pensé pour le client — les applications mobiles, web et desktop — et propulsé par Flutter, le framework d'interface de Google.

Dans cette première leçon, on ne construit pas encore d'application : on pose les fondations. Tu vas comprendre pourquoi Dart existe, écrire ton premier programme, découvrir comment déclarer des variables proprement, et adopter dès maintenant les conventions que toute la communauté respecte. C'est court, mais ce sont les réflexes qui vont t'accompagner jusqu'à Flutter.

Pourquoi Dart ?

Dart est né chez Google en 2011. À l'origine, il visait à remplacer JavaScript dans le navigateur ; ce pari-là n'a pas pris, mais le langage a trouvé sa vocation quelques années plus tard en devenant le langage de Flutter. Aujourd'hui, c'est ce qui fait sa force : un seul langage, une seule base de code, pour viser Android, iOS, le web, Windows, macOS et Linux.

Ce qui rend Dart particulier, c'est sa double capacité de compilation. En développement, il s'appuie sur un compilateur rapide qui permet le hot reload (tu modifies ton code et tu vois le résultat presque instantanément). En production, il compile en code machine natif (AOT, ahead-of-time) pour des applications rapides au démarrage, ou en JavaScript pour le web. Un même code, plusieurs cibles.

Note

Dart est optimisé pour les interfaces : son ramasse-miettes et son modèle d'exécution sont taillés pour redessiner des écrans soixante fois par seconde sans à-coups. C'est pour ça qu'il fait si bon ménage avec Flutter.

Cas réel

Cette promesse d'un code unique n'est pas théorique. La banque brésilienne Nubank, l'app de paie Google Pay, Alibaba ou encore BMW ont réécrit des applications entières en Dart/Flutter. Le gain répété par ces équipes : une seule base de code livrée en même temps sur iOS et Android, là où il fallait auparavant deux équipes et deux langages (Swift + Kotlin). Le hot reload, lui, transforme le quotidien : on ajuste une couleur ou un espacement et l'écran se met à jour en une fraction de seconde, sans redémarrer l'app.

Où essayer Dart ?

Le plus simple pour commencer, c'est DartPad (dartpad.dev) : un éditeur en ligne, zéro installation, qui exécute ton code Dart directement dans le navigateur. Idéal pour expérimenter un bout de code en quelques secondes.

Quand tu voudras travailler sur de vrais projets, tu installeras le SDK Dart (souvent fourni avec le SDK Flutter). Tu disposeras alors de la commande dart en ligne de commande.

Ton premier programme

Comme dans beaucoup de langages, l'exécution d'un programme Dart commence à une fonction nommée main. Voici le plus petit programme possible.

Décortiquons. void indique que la fonction ne renvoie aucune valeur. main() est le point d'entrée : Dart cherche cette fonction pour démarrer. Les accolades { } délimitent le corps. print(...) affiche un texte dans la console, et chaque instruction se termine par un point-virgule ;. Les chaînes de caractères s'écrivent de préférence avec des guillemets simples '...' en Dart, même si les guillemets doubles fonctionnent aussi.

Note

La sortie attendue est indiquée en commentaire // Salut sous chaque exemple : tu peux ainsi comparer ce que produit le programme sans avoir à le lancer. C'est la convention qu'on suivra dans tout le cours.

Variables : var, final et const

Dart te propose trois façons principales de déclarer une variable, et le choix entre elles n'est pas anodin. La règle d'or de la communauté : privilégie final et const, et n'utilise var que quand la valeur doit vraiment changer.

La différence subtile entre final et const : final est fixé une fois au moment de l'exécution (sa valeur peut être calculée, par exemple l'heure actuelle), tandis que const doit être connue dès la compilation (une vraie constante littérale). Toute valeur const est forcément final, mais l'inverse n'est pas vrai.

Un typage optionnel mais sound

Dans les exemples précédents, on n'a jamais écrit le type explicitement : Dart l'a inféré tout seul. Tu peux écrire les types quand ça clarifie le code, mais ce n'est pas obligatoire. Ce qui compte, c'est que Dart est un langage sound (sain) : une fois qu'une variable a un type, elle le garde, et le compilateur refusera tout usage incohérent.

Tu remarques aussi l'interpolation de chaîne : $ville insère la valeur de la variable directement dans le texte. Pour une expression plus complexe, on utilise des accolades : '${age + 1}'. C'est plus lisible que la concaténation avec +.

Note

Dart moderne (3.x) active la sound null safety : par défaut, une variable ne peut pas valoir null sans que tu l'autorises explicitement avec un ?. On y consacrera une leçon entière, mais retiens dès maintenant que c'est l'une des grandes forces du langage : beaucoup de bugs sont éliminés avant même de lancer le programme.

Commentaires

Dart offre trois styles de commentaires. Les deux premiers te sont sûrement familiers ; le troisième est propre à la documentation.

Le commentaire /// est spécial : il sert à documenter une fonction, une classe ou une variable, et les outils Dart (comme la génération de documentation ou l'aide de l'éditeur) savent le lire. Prends l'habitude de l'utiliser pour expliquer le quoi et le pourquoi de tes éléments publics.

Pièges fréquents

Piège fréquent

Confondre final et const. Si la valeur est calculée à l'exécution (un appel à DateTime.now(), une lecture utilisateur…), seul final convient ; const exige une valeur connue à la compilation. Réflexe : utilise const quand tu le peux, final sinon.

Piège fréquent

Oublier le point-virgule en fin d'instruction, ou la fonction main. Sans main, Dart ne sait pas par où démarrer et renvoie : Error: Couldn't find a 'main' method.

Glossaire

Dart
Langage typé et sain créé par Google (2011), pensé pour le client ; c'est le langage de Flutter.
Flutter
Framework d'interface de Google qui utilise Dart pour viser mobile, web et desktop depuis une seule base de code.
AOT (ahead-of-time)
Compilation en code machine natif avant l'exécution ; produit des applications rapides à démarrer.
JIT · hot reload
Compilation à la volée pendant le développement ; permet de voir le résultat d'une modification presque instantanément.
Typage sound (sain)
Garantie qu'une variable ne contiendra jamais une valeur d'un autre type, y compris à l'exécution.
Null safety
Par défaut, une variable ne peut pas valoir null sans autorisation explicite (?), ce qui élimine de nombreux bugs.
Inférence de type
Dart déduit seul le type d'une variable à partir de sa valeur initiale, sans qu'on l'écrive.
Interpolation
Insertion d'une valeur dans une chaîne via $variable ou ${expression}, plus lisible que la concaténation.

Récap et vérification

  • Dart, créé par Google en 2011, est le langage de Flutter ; il compile en natif (AOT) et en JavaScript.
  • On l'essaie sans rien installer sur dartpad.dev, ou via le SDK avec dart run et dart compile exe.
  • Tout programme démarre à void main() ; print affiche dans la console.
  • var (modifiable), final (fixé une fois à l'exécution), const (constante de compilation) — privilégie final et const.
  • Le typage est optionnel mais sound, avec la null safety active par défaut.
  • Conventions : lowerCamelCase, UpperCamelCase, lowercase_with_underscores pour les fichiers ; commentaires //, /* */, ///.
