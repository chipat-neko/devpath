Module 1 · Les bases de Dart — Leçon 03

Conditions, boucles et collections

~45 min Débutant Prérequis : leçon 2

À la fin de cette leçon, tu sauras

  • savoir écrire des conditions avec if/else, l'opérateur ternaire et un switch expression exhaustif (Dart 3) ;
  • savoir parcourir des données avec for, for-in, while, do-while et maîtriser break/continue ;
  • savoir manipuler une List, un Set et une Map, et accéder à une clé nullable en toute sécurité ;
  • savoir construire des littéraux avec collection if, collection for et le spread ....
Sommaire de la leçon

Un programme qui ne sait que dérouler des instructions de haut en bas reste limité : il faut décider, répéter, et regrouper des données. Dart te donne pour cela un appareillage classique (if, for, while) que tu reconnaîtras au premier coup d'œil, mais aussi des outils modernes empruntés aux langages fonctionnels : un switch qui renvoie une valeur, du pattern matching avec vérification d'exhaustivité, et des littéraux de collection capables d'inclure des conditions et des boucles directement à l'intérieur.

Cette dernière famille d'idiomes n'est pas un gadget : en Flutter, tu construiras des listes de widgets exactement de cette façon. Maîtriser dès maintenant collection if, collection for et le spread ..., c'est gagner un temps précieux plus tard. On part des conditions, on monte jusqu'aux collections et à leurs méthodes.

Conditions : if/else et ternaire

La syntaxe du if/else est identique à celle de Java ou JavaScript. La différence vient de la rigueur de Dart : la condition doit être un bool. Pas de if (0) ni de if ("texte") : ces écritures ne compilent pas, là où JavaScript se contenterait d'une valeur « truthy ».

Note l'opérateur ?? (si-null), très lié au null safety : a ?? b renvoie a s'il n'est pas null, sinon b. On le reverra avec les Map, où il est indispensable.

Le switch expression de Dart 3

Dart connaît encore le switch classique en instruction (avec ses case et ses blocs), mais sa version moderne est le switch expression : il renvoie une valeur, sépare les cas par => et des virgules, et utilise _ comme cas par défaut. Surtout, le compilateur vérifie l'exhaustivité : si tu oublies un cas possible, il refuse de compiler.

Comme les trois valeurs de l'enum Feu sont couvertes, pas besoin de _ dans action. Si tu ajoutais Feu.clignotant à l'enum, le compilateur signalerait aussitôt que le switch n'est plus exhaustif : une sécurité précieuse pour faire évoluer un code sans rien oublier. Les motifs >= 16 sont des motifs relationnels, évalués de haut en bas : le premier qui correspond gagne.

Les boucles

Dart offre la panoplie habituelle. Le for classique pour un index, le for-in pour parcourir un itérable, et while/do-while pour les conditions. break sort de la boucle, continue saute à l'itération suivante.

Pour un parcours simple, il existe aussi forEach, une méthode qui prend une fonction. Pratique, mais on ne peut y utiliser ni break ni continue : pour interrompre un parcours, garde le for-in. La convention officielle (effective Dart) recommande d'ailleurs le for-in par défaut, et de réserver forEach aux cas où tu passes une fonction déjà nommée.

Les listes : List<T>

Une List est une séquence ordonnée et indexée. Le type des éléments se note entre chevrons : List<int>. Avec un littéral, Dart infère souvent le type tout seul.

Ensembles et dictionnaires : Set et Map

Un Set<T> stocke des valeurs uniques : parfait pour dédoublonner. Une Map<K, V> associe des clés à des valeurs. Point crucial du null safety : accéder à map[cle] renvoie un type nullable (V?), car la clé peut être absente.

Note

Comme map[cle] est de type nullable, le compilateur t'oblige à gérer le cas null avant d'utiliser la valeur (avec ??, un if, ou ! si tu es certain). C'est exactement le rôle du null safety : rendre l'absence de valeur visible dans le type, plutôt que de la découvrir par un plantage.

Collection if, collection for et spread

Voici l'idiome le plus distinctif de Dart. À l'intérieur d'un littéral de liste (ou de set/map), tu peux écrire un if, un for et un spread ... pour insérer des éléments conditionnellement, en boucle, ou en dépliant une autre collection. C'est précisément ainsi qu'on assemble des listes de widgets en Flutter.

Cas réel

Ces idiomes ne sont pas décoratifs : en Flutter, l'écran d'un profil se construit littéralement comme une liste de widgets. On y déplie un en-tête commun avec ..., on affiche un bouton « Modifier » seulement au propriétaire avec if (estMoi), et on génère une carte par publication avec for (final post in posts) — le tout dans un unique children: [ ... ]. Sans collection if, il faudrait bricoler des listes temporaires et des .add() conditionnels bien moins lisibles. C'est l'une des raisons pour lesquelles le code d'interface Flutter reste déclaratif et facile à lire.

Mutabilité : final vs const

Attention à une nuance qui surprend souvent. final list empêche de réaffecter la variable, mais le contenu de la liste reste modifiable. const list, lui, gèle la liste entière : toute modification déclenche une erreur à l'exécution.

Avant-première : map, where, reduce

Les itérables disposent de méthodes fonctionnelles qu'on approfondira plus tard. En aperçu : map transforme chaque élément, where filtre, reduce agrège en une seule valeur. Elles renvoient un Iterable paresseux ; on le matérialise souvent avec toList().

Pièges fréquents

Piège fréquent

Oublier que map[cle] est nullable. Écrire int total = stock['pomme'] + 1; ne compile pas : int? n'a pas d'opérateur +. Utilise (stock['pomme'] ?? 0) + 1 pour repasser en int non nullable avant le calcul.

Piège fréquent

Confondre final et const sur une collection. Une final list reste modifiable en contenu ; seule une const list est réellement immuable. Appeler .add() sur une const compile, mais plante à l'exécution.

Glossaire

switch expression
Forme moderne du switch qui renvoie une valeur, avec cas séparés par => et défaut _.
Exhaustivité
Garantie, vérifiée à la compilation, que tous les cas possibles sont traités ; un oubli devient une erreur.
Motif relationnel
Motif de comparaison dans un switch (ex. >= 16), évalué de haut en bas ; le premier qui correspond gagne.
List
Collection ordonnée et indexée ; l'accès se fait par position, à partir de l'index 0.
Set
Collection de valeurs uniques ; insérer un doublon n'a aucun effet.
Map
Collection d'associations clé → valeur ; map[cle] renvoie un type nullable, car la clé peut manquer.
Spread (...)
Opérateur qui déplie les éléments d'une collection dans un littéral ; ...? ignore une collection nulle.
Collection if / for
Insertion d'éléments dans un littéral selon une condition ou une boucle, sans code intermédiaire.

Récap et vérification

  • La condition d'un if est obligatoirement un bool ; le ternaire ?: renvoie une valeur.
  • Le switch expression renvoie une valeur, sépare par =>, et vérifie l'exhaustivité à la compilation.
  • Boucles : for, for-in, while, do-while ; break/continue pour le contrôle fin.
  • List ordonnée et indexée, Set de valeurs uniques, Map dont l'accès map[cle] est nullable.
  • collection if, collection for et spread ... construisent des littéraux expressifs.
  • final bloque la réaffectation ; const gèle aussi le contenu.

Vérifie ta compréhension

  1. Pourquoi if (1) ne compile-t-il pas en Dart, alors que cela passe en JavaScript ?
  2. Que garantit l'exhaustivité d'un switch expression sur un enum, et qu'arrive-t-il si tu ajoutes une valeur à l'enum ?
  3. Quel type renvoie stock['banane'] si la clé est absente, et comment obtenir un int non nullable ?
  4. Quelle est la différence concrète entre final list et const list quand on appelle .add() ?
