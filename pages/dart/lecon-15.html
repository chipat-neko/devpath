Réseau et données : JSON et HTTP

~52 min Intermédiaire Prérequis : leçons 07 et 11

À la fin de cette leçon, tu sauras

  • envoyer une requête avec le paquet http et lire son statusCode ;
  • transformer une réponse JSON en objets Dart avec jsonDecode ;
  • modéliser une entité avec un constructeur factory fromJson ;
  • afficher des données réseau proprement avec FutureBuilder.
Sommaire de la leçon

Une application isolée est rare : une météo interroge un service, un fil d'actualité charge des articles, un panier synchronise ses prix. Presque toujours, ce dialogue passe par une API web qui répond en JSON. Cette leçon relie trois briques : envoyer une requête (le paquet http), décoder la réponse (jsonDecode), puis l'afficher (FutureBuilder, déjà croisé en leçon 11).

Une requête HTTP avec le paquet http

Dart n'inclut pas de client réseau « confortable » dans son cœur : on ajoute le paquet http. Une requête est asynchrone — le réseau prend du temps — donc on l'await. La réponse porte un statusCode (200 = OK, 404 = introuvable…) et un body (le texte reçu).

Du texte JSON aux objets Dart : jsonDecode

Le body est une simple chaîne. Pour en tirer des données manipulables, on la décode avec jsonDecode, fourni par la bibliothèque intégrée dart:convert (aucun paquet à installer). Un objet JSON devient une Map<String, dynamic> ; un tableau JSON devient une List<dynamic>.

Modéliser : un constructeur factory fromJson

Manipuler des Map anonymes partout est risqué. On préfère une classe typée et un constructeur factory nommé fromJson qui reçoit la map et en tire des champs propres. Le reste du code manipule alors des Produit, pas des dictionnaires.

Astuce

Un nombre JSON sans point (1) est décodé en int ; avec point (1.5) en double. Écrire json['prix'] as double plante donc si le serveur renvoie 1. Le réflexe robuste : (json['prix'] as num).toDouble(), qui accepte les deux.

Afficher avec FutureBuilder

On assemble : une fonction async qui charge et décode, puis un FutureBuilder qui reflète les trois états possibles — en attente, erreur, données prêtes. C'est le patron vu en leçon 11, appliqué à de vraies données réseau.

Attention

Ne crée jamais le Future directement dans build (ex. future: chargerCatalogue()) : build peut être rappelé des dizaines de fois, et chaque appel relancerait une requête réseau. Crée-le une fois dans initState et stocke-le dans un champ (_futureCatalogue).

Cas réel

Une app météo interroge un service comme OpenWeatherMap : GET /weather?q=Lyon renvoie un gros objet JSON (température, humidité, icône, prévisions…). L'app n'en garde que quelques champs via un Meteo.fromJson, ignore le reste, et gère les cas « ville inconnue » (404) ou « hors ligne » (exception réseau) par un message clair plutôt qu'un écran blanc. Ce trio requête → modèle → FutureBuilder est la colonne vertébrale de la quasi-totalité des applis connectées.

Pour aller plus loin

Pour aller plus loin

Écrire les fromJson à la main devient vite fastidieux : json_serializable les génère à partir d'annotations. Pour des besoins réseau avancés (intercepteurs, timeout, annulation), le paquet dio complète http. Enfin, pour garder les données entre deux lancements, regarde shared_preferences (petites valeurs) ou sqflite/drift (base locale) — le pas suivant après « charger » : « mettre en cache ».

Glossaire

API web
Service accessible par le réseau qui répond à des requêtes, le plus souvent en JSON.
Paquet http
Bibliothèque à ajouter au pubspec.yaml pour envoyer des requêtes HTTP (http.get, http.post…).
statusCode
Code numérique du résultat : 200 (OK), 404 (introuvable), 500 (erreur serveur)…
JSON
Format texte d'échange : objets { }, tableaux [ ], chaînes, nombres, booléens, null.
jsonDecode
Fonction de dart:convert qui transforme une chaîne JSON en Map/List Dart.
factory fromJson
Constructeur factory qui construit un objet typé à partir d'une map décodée.
FutureBuilder
Widget qui reconstruit l'UI selon l'état d'un Future : en attente, erreur ou données.
Sérialisation
Convertir un objet en texte (JSON) et l'inverse (désérialisation) pour le transporter ou le stocker.

Récap et vérification

  • Le paquet http envoie la requête ; on await et on vérifie le statusCode avant de lire body.
  • jsonDecode (de dart:convert) transforme le texte en Map/List de valeurs dynamic.
  • Un factory fromJson range ces valeurs dans une classe typée — fini les fautes de clés invisibles.
  • FutureBuilder reflète les trois états : attente, erreur, données.

Vérifie ta compréhension

  1. Pourquoi vérifier statusCode avant de faire confiance au body ?
  2. En quoi un factory fromJson est-il plus sûr que manipuler la Map partout ?
  3. Quels sont les trois états qu'un FutureBuilder doit prévoir ?

Exercices

Exercice 1Échauffement

Écris la fonction chargerTexte qui fait un GET sur https://api.example.com/ping et renvoie le body si statusCode vaut 200, sinon lève une exception.

Voir une solution

On await la requête, on filtre sur le statusCode, puis on renvoie ou on lève.

Exercice 2Application

À partir de {"ville":"Lyon","temp":21}, écris un factory Meteo.fromJson pour une classe Meteo à deux champs final : ville (String) et temp (double).

Voir une solution

(j['temp'] as num).toDouble() accepte que le serveur envoie 21 comme 21.0.

Exercice 3Défi

Le corps reçu est un tableau JSON de villes météo. Écris List<Meteo> meteosDepuis(String corps) qui décode et mappe chaque élément vers Meteo.fromJson.

Voir une solution

On décode d'abord en List<dynamic>, puis map transforme chaque map en Meteo, et toList matérialise le résultat.
