Module 1 · Les bases de Dart — Leçon 04

Fonctions et closures

~45 min Débutant Prérequis : leçon 3

À la fin de cette leçon, tu sauras

  • savoir déclarer une fonction avec type de retour, syntaxe fléchée => et les trois familles de paramètres (positionnels, optionnels, nommés required) ;
  • savoir manipuler les fonctions comme des valeurs de première classe et écrire des closures qui capturent leur environnement ;
  • savoir transformer des itérables avec map, where, reduce, fold et expand via des closures ;
  • savoir nommer un type de fonction avec typedef et relier ces notions aux callbacks Flutter comme onPressed.
Sommaire de la leçon

Tu connais déjà les fonctions : un nom, des paramètres, un corps. En Dart, deux choses méritent toute ton attention. D'abord, les paramètres nommés, omniprésents dans le code Flutter, qui rendent les appels lisibles même avec dix arguments. Ensuite, le fait que les fonctions sont des valeurs comme les autres : tu peux les stocker, les passer en argument et les retourner. C'est exactement ce mécanisme qui se cache derrière un onPressed: () { ... } dans un bouton Flutter.

Dans cette leçon, on part de la déclaration d'une fonction pour arriver aux closures et au traitement des collections avec map, where et fold. À la fin, tu liras un callback Flutter sans hésiter une seconde.

Déclarer une fonction : type de retour et flèche

Une fonction Dart annonce son type de retour devant son nom, puis ses paramètres typés. Quand le corps tient en une seule expression, la syntaxe fléchée => remplace les accolades et le return.

fn => expr est strictement équivalent à fn { return expr; }. On ne met pas d'accolade après la flèche : elle attend une expression, pas un bloc.

Trois familles de paramètres

Dart distingue les paramètres positionnels obligatoires, les positionnels optionnels (entre crochets [ ]) et les nommés (entre accolades { }). C'est la grande différence avec Java ou JavaScript, et le cœur de l'ergonomie Flutter.

Les paramètres optionnels positionnels sont pratiques mais limités : on doit les fournir dans l'ordre. Dès qu'il y en a plusieurs, on préfère presque toujours les paramètres nommés.

Paramètres nommés : l'idiome Dart/Flutter

Les paramètres nommés s'écrivent entre accolades et s'appellent par leur nom, dans n'importe quel ordre. Par défaut ils sont optionnels ; le mot-clé required rend un paramètre nommé obligatoire. C'est cette syntaxe qui donne aux appels Flutter leur lisibilité.

Note

En Dart 3, la sound null safety est toujours active. Un paramètre nommé de type non-nullable (comme String) doit donc être soit required, soit muni d'une valeur par défaut. Si tu veux qu'il puisse être omis sans valeur par défaut, déclare-le nullable (String?) : il vaudra null en l'absence d'argument.

Cas réel

Ouvre le code d'un widget Flutter et tu ne verras presque que ça. Un ElevatedButton, un Container ou un TextField se configure via une dizaine de paramètres nommés — onPressed:, padding:, decoration:, style:… — dont un petit nombre seulement est required. Grâce à eux, l'appel se lit comme une fiche : chaque valeur porte son étiquette, l'ordre est libre, et les options non fournies prennent un défaut raisonnable. Le même widget en paramètres positionnels serait un mur de virgules illisible du genre Button(null, 8, true, false, …). C'est un choix de conception délibéré de Flutter, directement permis par cette syntaxe du langage.

Fonctions de première classe

En Dart, une fonction est une valeur de type Function. Tu peux l'affecter à une variable, la mettre dans une liste, ou la passer à une autre fonction. C'est ce qui rend les callbacks possibles.

Le type int Function(int) se lit « une fonction qui prend un int et renvoie un int ». On écrit doubler sans parenthèses pour désigner la fonction ; doubler() l'appellerait.

Fonctions anonymes, imbriquées et closures

Une fonction sans nom s'écrit (params) { ... } ou en version fléchée (params) => expr. Quand une fonction (anonyme ou non) capture des variables de son environnement, on parle de closure : elle « emporte » ces variables avec elle.

Chaque appel à compteur() crée une nouvelle variable n, capturée par la closure renvoyée. Les deux compteurs ne partagent rien : c'est toute la puissance de la capture par référence. (On a typé le retour int Function() plutôt que le vague Function pour profiter de la vérification de types.)

Astuce

Une fonction imbriquée a accès à toutes les variables de sa fonction englobante. Utilise-les pour découper un long corps en étapes nommées, sans polluer l'espace global.

Closures et itérables : map, where, fold

Les méthodes des itérables prennent des closures en argument. map transforme chaque élément, where filtre, expand aplatit, et reduce/fold agrègent. Comme elles sont paresseuses, on termine souvent par toList().

fold est le couteau suisse : sa valeur initiale fixe le type du résultat (ici String via fold<String>), là où reduce reste cantonné au type des éléments et plante sur une liste vide.

typedef et le lien avec Flutter

Un type de fonction long se répète vite. typedef lui donne un nom réutilisable. Et dans Flutter, chaque widget interactif attend justement une closure : onPressed n'est rien d'autre qu'un paramètre nommé de type fonction.

Quand tu écris onPressed: () { ... }, tu passes une fonction anonyme à un paramètre nommé. Tout ce qu'on vient de voir s'applique tel quel à Flutter.

Pièges fréquents

Piège fréquent

Confondre passer une fonction et l'appeler. onPressed: maMethode passe la fonction ; onPressed: maMethode() l'exécute immédiatement et passe son résultat (souvent null), ce qui désactive le bouton. Pour des arguments, enveloppe : onPressed: () => maMethode(42).

Piège fréquent

reduce lance une StateError sur une liste vide, car il n'a pas de valeur de départ. Si la liste peut être vide, utilise fold avec une valeur initiale : liste.fold(0, (a, b) => a + b) renvoie 0 sans broncher.

Pour aller plus loin

Glossaire

Syntaxe fléchée (=>)
Abrège une fonction dont le corps tient en une seule expression ; équivaut à { return expr; }.
Paramètre nommé
Argument appelé par son nom, entre accolades ; optionnel par défaut, rendu obligatoire par required.
required
Mot-clé qui impose la fourniture d'un paramètre nommé à l'appel.
Fonction de première classe
Une fonction est une valeur (type Function) : on peut la stocker, la passer et la retourner.
Closure
Fonction qui capture et emporte les variables de son environnement, avec un état propre à chaque création.
Fonction anonyme
Fonction sans nom, écrite (params) { … } ou (params) => expr ; typique des callbacks.
fold
Agrège un itérable à partir d'une valeur initiale (qui fixe le type) ; gère les listes vides, contrairement à reduce.
typedef
Donne un nom réutilisable à un type de fonction, pour des signatures plus lisibles.

Récap et vérification

  • Le type de retour précède le nom ; => abrège un corps d'une seule expression.
  • Trois familles de paramètres : positionnels obligatoires, optionnels [ ], et nommés { } avec required et valeurs par défaut.
  • Les fonctions sont des valeurs (Function) : on les stocke, les passe et les retourne.
  • Une closure capture les variables de son environnement, chaque création ayant son propre état.
  • map, where, expand, reduce et fold prennent des closures ; fold gère la valeur initiale et les listes vides.
  • typedef nomme un type de fonction ; les callbacks Flutter comme onPressed sont des paramètres nommés de type fonction.

Vérifie ta compréhension

  2. Pourquoi onPressed: faire() est-il un bug, et comment le corriger ?
  3. Que renverrait un second compteur() appelé indépendamment du premier, et pourquoi ?
