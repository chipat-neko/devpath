Sécurité applicative : comprendre et prévenir les failles

Un logiciel peut être correct et pourtant dangereux. Ce cours défensif t'apprend à reconnaître les failles les plus critiques — injections, XSS, CSRF, défauts d'authentification, contrôle d'accès — pour les prévenir. Un savoir transversal, structuré autour de l'OWASP Top 10.

Bien s'équiper

Les extensions VS Code pour la sécurité

Avant de te lancer, ouvre le panneau Extensions de VS Code (Ctrl+Shift+X) et installe ces incontournables : ils repèrent les failles et les secrets au plus tôt, dans l'éditeur.

À installer pour la sécurité

  • Snyk Security (Snyk) — détecte les vulnérabilités du code et des dépendances.
  • SonarQube for IDE (SonarSource) — analyse qualité et sécurité (ex-SonarLint).
  • GitGuardian (GitGuardian) — repère les secrets exposés avant le commit.
  • DotENV (mikestead) — manipuler les variables sensibles avec soin.

Un cours strictement défensif

On étudie les failles pour les corriger, jamais pour nuire : chaque exemple montre le code vulnérable et sa version sûre. Les notions web des cours API REST, PHP ou Node.js aident, mais le cours part des principes.

Ce que tu vas apprendre

Penser et coder en sécurité

À la fin du cours, tu sauras

  • adopter un état d'esprit défensif et ne jamais faire confiance à l'entrée ;
  • prévenir les injections (SQL, commande) et le XSS/CSRF ;
  • sécuriser l'authentification : hachage des mots de passe, sessions, 2FA ;
  • appliquer un contrôle d'accès correct, gérer les secrets et la défense en profondeur.

Pour qui, et pourquoi

La sécurité est l'affaire de tout développeur : la majorité des failles naissent dans le code applicatif ordinaire, et se préviennent avec des réflexes simples. Maîtriser ces bases te rendra meilleur développeur — tu écriras du code robuste par défaut — et c'est une compétence très recherchée.

Ce cours est défensif et éducatif : il vise la prévention. Applique toujours ces connaissances à des systèmes dont tu as l'autorisation, dans un cadre légal (tes propres projets, environnements d'apprentissage prévus pour cela).

À retenir & glossaire

Les points clés du cours, puis les termes essentiels à connaître.

À retenir

  • Hacher les mots de passe (bcrypt/Argon2), jamais en clair.
  • Requêtes préparées contre l'injection SQL.
  • Échapper les sorties contre le XSS.
  • Cookies HttpOnly / Secure / SameSite.
  • Défense en profondeur : empiler les protections.
Hachage
Transformation à sens unique d'un mot de passe.
Injection SQL
Insertion de SQL malveillant via une entrée non filtrée.
XSS
Injection de script dans une page (Cross-Site Scripting).
CSRF
Action forcée à l'insu d'un utilisateur connecté.
HttpOnly
Cookie inaccessible au JavaScript (anti-vol de session).
Défense en profondeur
Empiler plusieurs couches de protection.
