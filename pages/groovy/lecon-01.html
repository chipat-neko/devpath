Module 1 · Les bases de Groovy — Leçon 01

Découvrir Groovy

~40 min Intermédiaire Prérequis : des bases de programmation (Java utile mais non requis)

À la fin de cette leçon, tu sauras

  • comprendre ce qu'est Groovy : Java en plus souple, sur la JVM ;
  • situer Groovy (scripts, Gradle, Jenkins) ;
  • écrire et lancer un premier script ;
  • apprécier la concision par rapport à Java.
Sommaire de la leçon

Groovy, c'est Java sans la cérémonie. Imagine un langage qui tourne sur la même machine virtuelle que Java (la JVM), utilise les mêmes bibliothèques, mais débarrassé de toute la lourdeur : plus de types obligatoires partout, plus de point-virgules forcés, une syntaxe concise et expressive. Conçu en 2003, Groovy est devenu le langage de scripts par excellence de l'univers Java — et celui qui fait tourner des outils que tout développeur croise : Gradle et Jenkins. Cette première leçon te le présente.

Java, en plus souple

Groovy a un super-pouvoir : il est presque compatible avec Java. La plupart du code Java valide est aussi du code Groovy valide. Mais Groovy ajoute par-dessus une foule de raccourcis et de fonctionnalités dynamiques. On peut donc l'apprendre progressivement : écrire du « Java simplifié » au début, puis adopter les idiomes Groovy qui rendent le code bien plus concis.

Un script, pas forcément une classe

Groovy peut s'écrire comme un script : on tape des instructions directement, sans structure de classe. Le fichier .groovy s'exécute de haut en bas, ce qui le rend idéal pour l'automatisation et les petits utilitaires.

Sur la JVM, avec tout Java

Comme Groovy tourne sur la JVM, il accède à toutes les bibliothèques Java existantes : des millions de classes prêtes à l'emploi. On peut mélanger code Groovy et code Java dans un même projet. Groovy se compile d'ailleurs en bytecode JVM, exactement comme Java : pour la machine, à l'arrivée, c'est la même chose.

Où Groovy travaille

Groovy brille dans plusieurs niches :

  • Gradle : l'outil de build de référence pour Java/Android utilise Groovy pour ses fichiers de configuration ;
  • Jenkins : les pipelines d'intégration continue s'écrivent en Groovy ;
  • scripts et automatisation : idéal pour les tâches rapides sur la JVM ;
  • tests : le framework Spock (leçon 9) rend les tests très lisibles.

Tout développeur de l'écosystème Java finit par croiser Groovy, ne serait-ce qu'en éditant un build.gradle.

Cas réel

Ouvre n'importe quel projet Android un peu ancien : à la racine, un fichier build.gradle en Groovy décrit les dépendances, les versions et les tâches de compilation. Des millions de développeurs éditent du Groovy sans forcément le savoir. Côté serveur, les équipes qui utilisent Jenkins versionnent un Jenkinsfile — un script Groovy — qui décrit tout le pipeline : compiler, tester, déployer. Netflix, LinkedIn et la plupart des grandes plateformes Java ont piloté leur CI/CD ainsi pendant des années. Groovy est l'un de ces langages qu'on croise partout dès qu'on touche à l'outillage de l'écosystème Java.

Pièges fréquents

Piège fréquent

Croire que « tout Java fonctionne tel quel en Groovy ». C'est presque vrai, mais quelques différences existent : en Groovy, == compare les valeurs (comme equals en Java), pas les références ; certaines règles de « vérité » diffèrent ; et le typage dynamique change le comportement. Ne suppose pas une compatibilité à 100 % : Groovy est un sur-ensemble proche, pas identique.

Pour aller plus loin

Pour aller plus loin

Groovy a ouvert la voie à toute une génération de langages alternatifs sur la JVM : Kotlin, Scala, Clojure… L'idée — garder la puissance de l'écosystème Java tout en améliorant la syntaxe — s'est révélée si féconde que Kotlin a fini par concurrencer Groovy jusque sur son terrain (Gradle propose désormais une syntaxe Kotlin). Mais Groovy reste irremplaçable pour le scripting dynamique et les DSL, sa vraie spécialité.

Antisèche : Groovy en un coup d'œil

Glossaire

Groovy
Langage dynamique de la JVM (2003), pensé comme un « Java sans la cérémonie » : concis, souple, compatible avec les bibliothèques Java.
JVM
Java Virtual Machine : la machine virtuelle qui exécute le bytecode. Groovy, Java, Kotlin, Scala… y tournent tous.
Bytecode
Code intermédiaire (.class) produit par la compilation et exécuté par la JVM ; Groovy et Java génèrent le même.
Script
Fichier .groovy d'instructions exécutées de haut en bas, sans classe ni méthode main.
def
Mot-clé déclarant une variable au type non précisé (typage dynamique).
Interpolation
Insertion d'une valeur dans une chaîne à guillemets doubles via $variable ou ${expression} (les GString).
Gradle
Outil de build de l'écosystème Java/Android dont les fichiers de configuration s'écrivent en Groovy.
Jenkins
Serveur d'intégration continue dont les pipelines (Jenkinsfile) sont décrits en Groovy.

Récap et vérification

  • Groovy = Java sans la cérémonie : dynamique, concis, sur la JVM, compatible avec les bibliothèques Java.
  • S'écrit comme un script (pas besoin de classe ni de main) ; println affiche.
  • Typage optionnel (def), interpolation de chaînes ($variable).
  • Usages phares : Gradle, Jenkins, scripts, tests.

Voir une solution

Groovy permet d'écrire bien plus concis tout en gardant l'accès complet à l'écosystème Java (mêmes bibliothèques, même JVM) : on supprime la verbosité de Java (classes enveloppantes, types obligatoires, cérémonie) sans rien perdre de sa puissance, ce qui le rend idéal pour les scripts, l'automatisation et les configurations comme Gradle.
