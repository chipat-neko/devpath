Module 4 · Groovy avancé — Leçon 14

Projet de synthèse : un gestionnaire d'inventaire

~55 min Avancé Prérequis : tout le cours

À la fin de cette leçon, tu sauras

  • assembler classes, collections et closures en un programme réel ;
  • regrouper et agréger des données avec groupBy et sum ;
  • exporter un résultat en JSON ;
  • situer chaque brique du cours dans un projet de bout en bout.
Sommaire de la leçon

Te voilà au bout du cours. Tu as vu la syntaxe concise, les closures, les collections, les classes (POGO), la métaprogrammation, les traits, le JSON et les DSL. Il est temps de tout assembler dans un projet unique et réaliste : un petit gestionnaire d'inventaire de boutique, du modèle de données jusqu'au rapport exporté. Rien de neuf ici — juste l'art de faire tenir ensemble ce que tu maîtrises déjà.

Ce que tu vas construire

Une classe Produit (nom, prix, quantité, catégorie), une liste de produits, puis : l'affichage de chaque ligne, le total du stock, le regroupement par catégorie avec sous-totaux, le repérage des ruptures, et enfin un export JSON. Un condensé de tout le cours.

L'architecture : quatre briques du cours

Le programme empile quatre couches, chacune couverte par une leçon. Garder cette carte en tête aide à savoir « où mettre quoi ».

Étape 1 — Le modèle

Une classe POGO (leçon 6) : quatre champs typés et une méthode valeur(). Groovy génère seul accesseurs et constructeur à arguments nommés.

Étape 2 — Les données

Une liste (leçon 5) construite avec les arguments nommés (leçon 6) : lisible comme un tableau.

Étape 3 — Traiter avec des closures

Le cœur de Groovy : filtrer, regrouper, agréger en quelques appels enchaînés (leçons 4 et 5). groupBy partitionne la liste selon une clé ; collectEntries transforme chaque groupe en son sous-total ; findAll repère les ruptures.

Étape 4 — Restituer : affichage et JSON

On affiche avec l'interpolation (leçon 2), puis on exporte le résultat en JSON lisible (leçon 11) — prêt à être envoyé à une API ou écrit dans un fichier.

À toi de jouer

Étapes

Le modèle

Écris la classe Produit (4 champs typés + double valeur()).

Les données

Crée stock, une liste de produits via les arguments nommés.

Le total

def total = stock.sum { it.valeur() }.

Par catégorie

groupBy { it.categorie } puis un sous-total par groupe.

Les ruptures

findAll { it.quantite == 0 }.

Le rapport

Affiche chaque ligne, le total, puis exporte un rapport en JSON.

ProjetFil rouge

Assemble les six étapes en un programme complet. Cherche d'abord par toi-même, puis compare avec la solution de référence.

Voir une solution complète

Une classe, une liste, une poignée de closures et deux lignes de JSON : un outil complet, concis et lisible. C'est toute la promesse de Groovy tenue en une page.

Pour aller plus loin

Pour aller plus loin

Tu peux enrichir le projet avec ce que tu as vu en fin de cours : écrire une spec Spock (leçon 12) qui vérifie que total == 308.4 ou que ruptures == ["Souris"] ; exposer un petit DSL (leçon 13) pour saisir le stock (produit "Stylo", prix: 1.5, quantite: 40) ; ou factoriser le calcul de valeur dans un trait (leçon 10) partagé avec d'autres entités. Chaque extension réutilise, sans exception, une brique déjà apprise.

Cas réel — le même code en production

Cas réel

Ce schéma données → closures → JSON est exactement celui de milliers de scripts d'exploitation : un pipeline Jenkins (leçon 8) lit l'état de déploiements, les regroupe par service avec groupBy, calcule des agrégats, puis publie un rapport JSON consommé par un tableau de bord. Le « petit projet » de cette leçon est, à l'échelle près, le pain quotidien de l'automatisation sur la JVM.

Antisèche — les idiomes du cours

Glossaire

Capstone
Projet de synthèse final qui réunit les notions du cours en une réalisation cohérente et autonome.
POGO
Plain Old Groovy Object : classe simple à champs, dont Groovy génère accesseurs et constructeur à arguments nommés.
groupBy
Méthode de collection qui partitionne les éléments en une map clé → sous-liste selon la closure fournie.
collectEntries
Construit une map en transformant chaque élément (ou entrée) en une paire [clé, valeur].
Agrégat
Valeur résumant une collection (total, moyenne, comptage) ; ici obtenue avec sum.
Pipeline
Enchaînement de transformations où la sortie de chaque étape alimente la suivante (groupBy puis collectEntries).
Séparation en couches
Organisation d'un programme en niveaux distincts — modèle, données, traitement, sortie — pour la clarté et l'évolutivité.
Interpolation
Insertion d'une expression dans une chaîne à guillemets doubles avec ${…} (ou $var), évaluée à l'exécution ; sert ici à afficher chaque ligne du stock.

Récap et vérification

  • Un projet réel empile modèle (POGO), données (liste), traitement (closures) et sortie (JSON).
  • groupBy + collectEntries + sum = regrouper puis agréger.
  • findAll repère des cas (ruptures) ; l'interpolation et JsonOutput restituent.
  • Spock, DSL et traits prolongent le projet — toujours avec des briques déjà connues.

Vérifie ta compréhension

  1. Quelle méthode partitionne une liste selon une clé ?
  2. Comment calcule-t-on la valeur totale du stock ?
  3. Quelle classe produit le JSON du rapport ?
