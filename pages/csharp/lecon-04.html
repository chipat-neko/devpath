Module 01 · Les bases de C# — Leçon 04

Méthodes et tableaux

~32 min Intermédiaire Leçon 3 recommandée

À la fin de cette leçon, tu sauras

  • Savoir déclarer une méthode avec sa signature (type de retour, nom, paramètres), return/void et la forme expression-bodied (=>) ;
  • Savoir choisir le bon mode de passage de paramètres : par valeur, ref, out, in et params ;
  • Savoir employer les arguments nommés et optionnels ainsi que la surcharge pour assouplir tes méthodes ;
  • Savoir créer, parcourir et outiller des tableaux (1D, 2D) avec .Length, et découvrir List<T>.
Sommaire de la leçon

Jusqu'ici, tu écrivais ton code dans un seul bloc avec les top-level statements. Mais dès qu'un programme grossit, deux besoins apparaissent : réutiliser un morceau de logique sans le recopier, et stocker plusieurs valeurs ensemble. C# répond à ces besoins avec les méthodes (des blocs de code nommés et réutilisables) et les tableaux (des collections de taille fixe).

Dans cette leçon, tu vas apprendre à découper ton code en méthodes propres, à maîtriser les différents modes de passage d'arguments (la grande spécificité de C#), puis à manipuler des tableaux à une et deux dimensions. Le code se compile et s'exécute sur .NET avec dotnet run : chaque sortie console est montrée en commentaire dans le code.

Écrire une méthode : signature, return, void

Une méthode est un bloc de code nommé que tu peux appeler autant de fois que tu veux. Sa signature se compose d'un type de retour, d'un nom (en PascalCase en C#) et d'une liste de paramètres entre parenthèses.

Le mot-clé return a deux rôles : il fournit la valeur de sortie et il termine immédiatement la méthode. Une méthode void ne renvoie aucune valeur : elle agit (afficher, modifier) puis se termine. Tu peux quand même y écrire return; seul pour sortir plus tôt.

Note

Avec les top-level statements de .NET 8, ces méthodes déclarées dans Program.cs sont des fonctions locales. Le compilateur génère pour toi la classe et le Main en coulisses : tu peux appeler une méthode définie plus bas dans le fichier sans souci.

Les méthodes expression-bodied (=>)

Quand une méthode tient en une seule expression, C# propose une écriture compacte : on remplace les accolades et le return par une flèche =>. C'est un membre à corps d'expression (expression-bodied member).

Les deux versions sont strictement équivalentes. Réserve la flèche aux méthodes courtes et évidentes ; pour une logique sur plusieurs lignes, garde les accolades, c'est plus lisible.

Les paramètres : valeur, ref, out, in, params

Par défaut, les arguments sont passés par valeur : la méthode reçoit une copie. Modifier le paramètre ne change pas la variable d'origine.

Pour qu'une méthode modifie réellement la variable de l'appelant, utilise ref (passage par référence). Il faut alors écrire ref des deux côtés : à la déclaration et à l'appel.

Le mot-clé out sert à renvoyer une valeur par un paramètre (la variable n'a pas besoin d'être initialisée avant l'appel, mais la méthode doit obligatoirement lui affecter une valeur). C'est le mécanisme derrière int.TryParse.

Le mot-clé in passe par référence mais en lecture seule : la méthode ne peut pas modifier le paramètre. C'est surtout utile pour éviter de copier une grosse structure. Enfin, params accepte un nombre variable d'arguments, regroupés dans un tableau.

Astuce

Le paramètre params doit toujours être le dernier de la liste. On écrit void Log(string niveau, params string[] messages), jamais l'inverse.

Arguments nommés et paramètres optionnels

Un paramètre optionnel a une valeur par défaut : on peut omettre l'argument à l'appel. Les arguments nommés permettent de préciser nom: valeur, dans n'importe quel ordre, ce qui rend les appels plus lisibles.

Note l'appel Cadre("Hi", bordure: true) : grâce à l'argument nommé, on a pu fixer bordure sans toucher à remplissage, qui garde sa valeur par défaut.

La surcharge (overloading)

La surcharge consiste à donner le même nom à plusieurs méthodes, à condition que leurs paramètres diffèrent (nombre ou types). C# choisit la bonne version selon les arguments fournis. Attention : le seul type de retour ne suffit pas à les distinguer.

Cas réel

Tu utilises la surcharge depuis la première leçon sans le savoir : Console.WriteLine existe en dix-huit versions dans .NET — une par type d'argument (int, double, bool, string, object…). C'est pourquoi tu peux écrire Console.WriteLine(42) comme Console.WriteLine("texte") sans jamais convertir toi-même : le compilateur choisit la bonne surcharge selon ce que tu passes. Même principe pour Math.Max(int, int) et Math.Max(double, double).

Note

L'affichage d'un double avec Console.WriteLine dépend de la culture de la machine : en français, le séparateur décimal est la virgule, d'où 12,56636 (et non 12.56636). Pour un format fixe quelle que soit la machine, on utilise CultureInfo.InvariantCulture, vu plus tard.

static contre méthode d'instance (teaser POO)

Une méthode static appartient à la classe elle-même : on l'appelle sans créer d'objet, comme Math.Max(...). Une méthode d'instance appartient à un objet précis et agit sur ses données, comme .ToUpper() sur une chaîne.

Note

Pour l'instant, tes fonctions locales et les méthodes que tu appelles depuis Program.cs sont essentiellement statiques. Tu découvriras les objets et les méthodes d'instance que tu écris toi-même dans le module sur la POO.

Les tableaux : déclaration, accès, parcours

Un tableau stocke plusieurs valeurs du même type dans une structure de taille fixe. On peut le créer vide avec new (les cases valent alors 0, false ou null), ou directement avec un littéral.

Les index vont de 0 à Length - 1. Le premier élément est notes[0], le dernier notes[notes.Length - 1] (ou, plus moderne, notes[^1] avec l'index depuis la fin).

Tableaux à deux dimensions

C# offre un vrai tableau 2D (une matrice rectangulaire) avec la syntaxe int[,]. On accède à une case avec deux index séparés par une virgule : grille[ligne, colonne].

Note

Sur un tableau 2D, .Length renvoie le nombre total de cases (ici 6). Pour la taille d'une dimension précise, utilise GetLength(0) (lignes) ou GetLength(1) (colonnes).

Aperçu de List<T>

Un tableau a une taille fixe : impossible d'y ajouter une case après coup. Quand le nombre d'éléments varie, on préfère List<T>, une collection redimensionnable (détaillée dans un module ultérieur).

Retiens la différence clé : un tableau expose sa taille via la propriété .Length, une List via .Count. Le <string> indique le type des éléments contenus (un type générique).

Pièges fréquents

Piège fréquent

Accéder à un index hors borne lève une IndexOutOfRangeException. Pour int[] t = new int[3];, les index valides sont 0, 1, 2 — écrire t[3] plante à l'exécution.

Piège fréquent

Avec ref et out, le mot-clé est obligatoire des deux côtés : à la déclaration et à l'appel. Oublier out dans int.TryParse("42", out int n) ne compile pas.

Piège fréquent

Un paramètre params int[] n'est pas un tableau « normal » : on l'appelle en passant les valeurs séparées (Somme(1, 2, 3)), pas un tableau enveloppé. Et ne choisis pas un tableau de taille fixe quand le nombre d'éléments varie : une List<T> conviendra mieux. Attention enfin à .Length (tableau) contre .Count (List) — les confondre est une erreur de compilation classique.

Glossaire

Méthode
Bloc de code nommé et réutilisable, appelable avec des arguments ; limite la duplication.
Signature
Type de retour, nom et liste des paramètres d'une méthode ; c'est ce qui l'identifie (le type de retour seul ne distingue pas deux surcharges).
return / void
return fournit la valeur de sortie et termine la méthode ; void signale une méthode qui n'en renvoie aucune.
Expression-bodied
Écriture compacte d'un membre tenant en une expression : => remplace les accolades et le return.
Passage par valeur / ref
Par valeur, la méthode reçoit une copie (l'original est intact) ; avec ref, elle reçoit un alias et modifie l'original.
out / params
out renvoie une valeur via un paramètre (comme int.TryParse) ; params accepte un nombre variable d'arguments regroupés en tableau.
Surcharge
Plusieurs méthodes de même nom distinguées par leurs paramètres ; le compilateur choisit la bonne selon les arguments.
Tableau
Collection de taille fixe d'éléments d'un même type, indexée à partir de 0 ; taille via .Length. Pour une taille variable : List<T>.

Récap et vérification

  • Une méthode a une signature : type de retour, nom, paramètres ; return renvoie une valeur et sort, void ne renvoie rien.
  • La forme expression-bodied (=>) compacte une méthode d'une seule expression.
  • Passage de paramètres : par valeur (défaut), ref (modifiable), out (renvoi), in (lecture seule), params (nombre variable). ref et out se mettent des deux côtés.
  • Les arguments nommés/optionnels et la surcharge rendent les appels plus souples et lisibles.
  • static = méthode de classe ; les méthodes d'instance agissent sur un objet (POO à venir).
  • Un tableau a une taille fixe : new int[n] ou {...}, index dès 0, taille via .Length (GetLength(d) en 2D). Une List<T> est redimensionnable et expose .Count.

Vérifie ta compréhension

  1. Quelle est la différence entre une méthode void et une méthode qui renvoie un int ?
  2. Pourquoi faut-il écrire out à la fois dans la déclaration de la méthode et au moment de l'appel ?
  3. Pour un tableau de 4 éléments, quels sont les index valides, et que se passe-t-il si tu accèdes à l'index 4 ? Quelle propriété donne sa taille, et celle d'une List<T> ?
