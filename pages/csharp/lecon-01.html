Module 01 · Les bases de C# — Leçon 01

Découvrir C# et .NET

~26 min Intermédiaire Aucun prérequis strict

À la fin de cette leçon, tu sauras

  • Distinguer C# (le langage) de .NET (la plateforme) et savoir où C# est utilisé
  • Comprendre le rôle du SDK, du CLR et de la compilation IL puis JIT
  • Créer et lancer un projet console avec dotnet new, dotnet build et dotnet run
  • Écrire un premier programme avec les top-level statements, Console.WriteLine, les using et les commentaires.
Sommaire de la leçon

Bienvenue dans ce premier cours ! Avant d'écrire ta première ligne de C#, il faut comprendre deux mots qu'on confond souvent : C# (le langage) et .NET (la plateforme qui le fait tourner). C'est un peu comme distinguer une recette de cuisine et la cuisine équipée dans laquelle tu la prépares.

Dans cette leçon, tu vas découvrir à quoi sert C#, comment fonctionne la plateforme .NET en coulisses, et tu vas créer puis lancer ton tout premier programme. On termine par des exercices pour mettre les mains dans le code.

C# en bref

C# (prononce « C sharp ») est un langage de programmation objet et moderne créé par Microsoft au début des années 2000. Aujourd'hui il est multiplateforme : le même code tourne sur Windows, Linux et macOS, grâce à .NET.

C# sert dans énormément de domaines :

  • Web : sites et API avec ASP.NET Core.
  • Bureau : applications Windows (WPF, WinForms).
  • Mobile et multiplateforme : applications avec .NET MAUI.
  • Jeux vidéo : le moteur Unity utilise C# pour les scripts.
  • Cloud : services hébergés sur Azure et ailleurs.

Autrement dit, apprendre C# t'ouvre la porte à beaucoup de types de projets très différents avec un seul langage de base.

Cas réel

Stack Overflow, l'un des sites les plus fréquentés par les développeurs, tourne depuis ses débuts sur C# et ASP.NET et sert des milliards de pages par mois depuis une poignée de serveurs. Côté grand public, plus de la moitié des jeux mobiles sont faits avec Unity, dont toute la logique s'écrit en C#. Le même langage propulse donc aussi bien un site à très fort trafic qu'un jeu sur ton téléphone.

Note

« Objet » veut dire qu'on organise le code autour d'objets (des données regroupées avec leurs comportements). Pas d'inquiétude : on commencera tranquillement par des choses simples avant d'aborder les classes.

La plateforme : .NET, SDK et CLR

Pour exécuter du C#, il te faut .NET. Le morceau que tu installes s'appelle le .NET SDK (Software Development Kit). Il contient tout le nécessaire : le compilateur, des bibliothèques de base, et l'outil en ligne de commande dotnet.

Quand tu compiles un programme C#, il ne devient pas directement du code machine. Voici le parcours :

  1. Ton code C# est compilé en IL (Intermediate Language), un code intermédiaire portable.
  2. Au moment de l'exécution, le CLR (Common Language Runtime), une sorte de machine virtuelle, prend le relais.
  3. Le CLR utilise un compilateur JIT (Just-In-Time) qui traduit l'IL en code machine juste avant de l'exécuter, adapté à ta machine.

C'est ce double passage (IL puis JIT) qui rend C# portable : le même IL tourne partout où il y a un CLR, donc sous Windows, Linux ou macOS.

Note

Pour vérifier que le SDK est installé, ouvre un terminal et tape dotnet --version. Tu devrais voir un numéro comme 8.0.x.

Trois commandes reviennent sans cesse :

  • dotnet new console crée un nouveau projet console (avec un Program.cs de départ).
  • dotnet build compile le projet (produit l'IL) sans le lancer.
  • dotnet run compile et exécute le programme en une seule étape.

Au démarrage, tu n'utiliseras quasiment que dotnet run.

Astuce

En C#, les noms de types et de méthodes s'écrivent en PascalCase (chaque mot commence par une majuscule) : Console, WriteLine, Program. Les variables locales, elles, s'écriront en camelCase.

Afficher et lire : WriteLine, Write, ReadLine

Pour communiquer avec la console, trois méthodes essentielles :

  • Console.WriteLine(...) affiche le texte puis passe à la ligne suivante.
  • Console.Write(...) affiche le texte sans passer à la ligne.
  • Console.ReadLine() lit une ligne tapée par l'utilisateur et la renvoie sous forme de texte.

Remarque comment les deux Write restent sur la même ligne, et c'est le WriteLine qui finit la première ligne. On reviendra sur ReadLine dans l'exercice 2.

Composer du texte : l'interpolation de chaîne

Très souvent, tu veux mêler du texte fixe et la valeur d'une variable. La façon moderne et lisible d'y arriver est l'interpolation de chaîne : on préfixe la chaîne d'un $, puis on glisse n'importe quelle expression entre accolades { }.

Sans le $, la chaîne "Bonjour {prenom}" afficherait littéralement les accolades. Avec, chaque {…} est remplacé par la valeur évaluée.

Astuce

L'interpolation remplace avantageusement la concaténation à coups de + ("Bonjour " + prenom + " !") : c'est plus court, plus lisible, et on n'oublie plus les espaces. On peut même formater : $"{prix:C}" affiche un montant en monnaie locale.

Espaces de noms : namespace et using

Le code de la bibliothèque .NET est rangé dans des espaces de noms (namespaces), comme des dossiers. Par exemple, Console vit dans l'espace de noms System. Pour utiliser un type sans écrire son chemin complet à chaque fois, on déclare un using en haut du fichier :

Note

Un namespace sert aussi à organiser ton propre code, pour éviter que deux types portant le même nom n'entrent en conflit. Tu en créeras toi-même plus tard dans le cours.

Pièges fréquents

Piège fréquent

Confondre .NET et C#. .NET est la plateforme (le SDK, le CLR, les bibliothèques) ; C# est le langage que tu écris. On code en C#, on exécute sur .NET.

Piège fréquent

Oublier dotnet run. Écrire du code ne suffit pas : il faut le compiler et le lancer. Si « rien ne se passe », vérifie que tu es bien dans le dossier du projet et que tu as tapé dotnet run.

Piège fréquent

Mélanger les deux styles. Si tu utilises les top-level statements, ne rajoute pas par-dessus une méthode Main classique : le compilateur ne saura plus quel est le point d'entrée. Choisis un seul style par fichier.

Piège fréquent

Confondre Write et WriteLine. Si tes affichages se collent les uns aux autres sur une même ligne, c'est sûrement que tu as utilisé Write au lieu de WriteLine.

Pour aller plus loin

Pour aller plus loin

Il existe d'autres modèles de projet que console : web (sites et API), classlib (bibliothèque réutilisable), et bien d'autres. On installe des bibliothèques externes via NuGet, le gestionnaire de paquets de .NET. Côté versions, vise une version LTS (Long-Term Support) comme .NET 8 pour la stabilité. Enfin, pour coder confortablement : Visual Studio (Windows), VS Code (léger, multiplateforme) ou Rider (JetBrains).

Antisèche

Glossaire

C#
Langage de programmation objet et moderne de Microsoft ; c'est la syntaxe que l'on écrit.
.NET
La plateforme qui exécute le C# : le runtime (CLR), une vaste bibliothèque standard et l'outillage (dotnet).
SDK
Software Development Kit : ce que l'on installe pour développer ; contient le compilateur, les bibliothèques de base et l'outil dotnet.
CLR
Common Language Runtime : la machine virtuelle de .NET qui charge et exécute l'IL, gère la mémoire (ramasse-miettes) et la sécurité.
IL
Intermediate Language : code intermédiaire portable produit par le compilateur C#, indépendant de la machine.
JIT
Just-In-Time : compilateur du CLR qui traduit l'IL en code machine juste avant l'exécution, adapté à la machine hôte.
Top-level statements
Écriture moderne où l'on met les instructions directement dans Program.cs, sans écrire soi-même la classe et la méthode Main.
Espace de noms (namespace)
Regroupement de types sous un préfixe (ex. System) ; on y accède via using.

Récap et vérification

  • C# est un langage objet moderne et multiplateforme ; .NET est la plateforme qui l'exécute.
  • Le code C# devient de l'IL, exécuté par le CLR via la compilation JIT.
  • On crée et lance un projet avec dotnet new console, dotnet build et dotnet run.
  • Les top-level statements remplacent la cérémonie class Program / Main.
  • Console.WriteLine affiche avec saut de ligne, Console.Write sans, Console.ReadLine lit une saisie.
  • Les using donnent accès aux espaces de noms ; certains sont implicites.
