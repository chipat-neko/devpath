Module 02 · POO en C# — Leçon 08

Énumérations, records et types modernes

~32 min Intermédiaire Leçon 7 recommandée

À la fin de cette leçon, tu sauras

  • définir et utiliser des enum, y compris combinables avec [Flags] ;
  • créer des record immuables et en produire des copies avec with ;
  • activer les nullable reference types pour éviter les NullReferenceException ;
  • déstructurer des tuples et exploiter le pattern matching positionnel sur des records.
Sommaire de la leçon

Jusqu'ici tu sais déclarer des variables, des classes et des méthodes. Mais bien souvent, un programme passe le plus clair de son temps à représenter des données : un jour de la semaine, une personne, un point dans un plan. C# moderne offre des types taillés exactement pour ça, qui rendent ton code plus court, plus sûr et plus lisible.

Dans cette leçon, tu vas découvrir les énumérations, les records, les nullable reference types, les tuples, et comment le pattern matching relie tout ça. L'idée commune : laisser le compilateur travailler pour toi plutôt que d'empiler des int et des string sans signification.

Les énumérations : des constantes nommées et typées

Un enum définit un ensemble fixe de valeurs nommées. Au lieu d'écrire int jour = 0; en espérant te souvenir que 0 veut dire « lundi », tu donnes un nom à chaque valeur. Le compilateur t'empêche alors d'y mettre n'importe quoi.

Chaque membre reçoit automatiquement une valeur entière : Lundi vaut 0, Mardi vaut 1, etc. Tu peux forcer ces valeurs (Lundi = 1) si besoin. Remarque le switch sous forme d'expression : il renvoie directement une valeur, et le _ (cas par défaut) le rend exhaustif.

Note

Le ToString() d'un enum affiche le nom du membre ("Vendredi"), pas le nombre. C'est pour cela que la chaîne interpolée plus haut écrit « Vendredi » et non « 4 ».

Les enum [Flags] : combiner des bits

Parfois une valeur peut cumuler plusieurs options à la fois (lecture et écriture, par exemple). L'attribut [Flags] indique que l'enum se manipule comme une combinaison de bits. On assigne alors des puissances de 2.

L'opérateur | combine les bits, HasFlag teste la présence d'une option, et & ~ en retire une. Sans [Flags], le code compile quand même mais l'affichage donnerait 3 au lieu du lisible Lecture, Ecriture : l'attribut sert à l'intention et au rendu.

Les records : des types pensés pour les données

Un record (C# 9) est un type de référence conçu pour transporter des données immuables. Dans sa forme la plus courte, dite positionnelle, une seule ligne suffit.

En une ligne, le compilateur t'a généré : les propriétés Nom et Age (en lecture seule, init-only), un ToString() lisible, l'égalité de valeur (== compare le contenu, pas l'adresse mémoire), un GetHashCode() cohérent, et la déconstruction. Écrire l'équivalent avec une classe « à la main » prendrait des dizaines de lignes.

with : copier en modifiant

Un record étant immuable, on ne modifie pas un objet existant : on en crée une copie avec quelques champs changés. C'est le rôle du mot-clé with (mutation non destructive).

L'original alice reste intact. with recopie tous les champs puis applique tes changements. Ce style « immuable + copie » évite quantité de bugs où une donnée est modifiée à un endroit sans qu'on s'y attende ailleurs.

record class vs record struct

Par défaut, record est un type de référence (équivalent de record class) : la variable contient une référence vers l'objet en mémoire. Tu peux aussi déclarer un record struct, qui est un type valeur : il est copié directement, ce qui convient à de petites données.

Les deux offrent l'égalité de valeur et la déconstruction. Retiens la règle simple : record class pour des objets que tu passes un peu partout, record struct pour de petites valeurs (un point, une couleur) où la copie est bon marché.

Note

Contrairement à un record class, un record struct est mutable par défaut (ses propriétés ont un setter). Ajoute le mot-clé readonly devant pour le rendre réellement immuable, comme dans l'exemple ci-dessus : c'est le réflexe recommandé.

Les nullable reference types : moins de NullReferenceException

La NullReferenceException est l'une des erreurs les plus courantes : on appelle une méthode sur une variable qui vaut null. En C# moderne, le contexte nullable (activé par défaut dans les projets .NET récents) fait analyser ça par le compilateur. Une référence est non nullable sauf si tu ajoutes ?.

Le compilateur te prévient avant l'exécution si tu risques un accès à null. L'opérateur ?. n'appelle .Length que si la valeur n'est pas null, et ?? fournit une valeur de repli. Tu ne supprimes pas les null, mais tu es forcé de les traiter.

Astuce

Plutôt que #nullable enable dans chaque fichier, active-le pour tout le projet avec <Nullable>enable</Nullable> dans le fichier .csproj. Les modèles dotnet new récents le font déjà pour toi.

Cas réel

En 2009, Tony Hoare — l'inventeur de la référence null en 1965 — l'a publiquement qualifiée d'« erreur à un milliard de dollars », tant les NullReferenceException ont coûté cher en pannes. C'est l'exception la plus fréquente en production sur la plateforme .NET. Les nullable reference types (C# 8, activés par défaut depuis .NET 6) attaquent le problème à la racine : le compilateur signale chaque accès risqué avant l'exécution. Les équipes qui activent le contexte nullable sur de grosses bases constatent une chute nette des plantages liés à null — le bug passe du client à 3 h du matin à un avertissement jaune dans l'éditeur.

Les tuples et la déconstruction

Un tuple regroupe plusieurs valeurs sans créer de type dédié. Très pratique pour qu'une méthode renvoie deux résultats à la fois. Donne des noms aux éléments pour rester lisible.

La méthode renvoie un tuple (int min, int max), et l'appelant le déstructure en deux variables d'un coup. C'est plus léger qu'un record quand le besoin est local et temporaire.

Le pattern matching enrichi

Le switch expression accepte des patterns bien plus expressifs que de simples valeurs. Les patterns de propriété testent des champs, et les patterns positionnels exploitent la déconstruction des records.

Le pattern ("Livre", _, > 100m) lit positionnellement les trois composantes du record (le _ ignore la quantité). Le pattern { Prix: < 10m } teste une propriété avec une comparaison. Records et pattern matching forment ainsi un duo très naturel pour exprimer des règles métier.

Pièges fréquents

Piège fréquent

Utiliser des const int au lieu d'un enum : tu perds la vérification du compilateur (n'importe quel entier passe) et la lisibilité du ToString(). Dès qu'un paramètre n'accepte qu'un jeu fixe de valeurs, fais-en un enum.

Piège fréquent

Confondre record (égalité de valeur) et class (égalité de référence). Deux objets class identiques champ par champ ne sont pas == par défaut ; deux records si. Vérifie toujours quel type tu compares.

Autres pièges courants : vouloir muter un record class (préfère with pour une copie) ; ignorer les avertissements nullable au lieu de gérer le cas null ; oublier [Flags] et des valeurs en puissances de 2 pour des combinaisons, ce qui casse HasFlag et l'affichage.

Pour aller plus loin

Pour aller plus loin

Explore le pattern matching exhaustif (le compilateur t'avertit si un cas manque), les records positionnels combinés au switch pour modéliser des hiérarchies de données, et le contexte nullable au niveau projet. Les unions discriminées, attendues dans une future version de C#, rendront ces modélisations encore plus sûres.

Glossaire

enum
Type dont les valeurs sont un jeu fixe de constantes nommées ; plus lisible et plus sûr que des const int épars.
[Flags]
Attribut signalant qu'un enum se combine bit à bit (options en puissances de 2) ; autorise |, & et HasFlag.
record
Type pensé pour la donnée : génère constructeur, propriétés init-only, égalité de valeur, ToString et déconstruction.
Égalité de valeur
Deux objets sont égaux s'ils ont le même contenu (records) ; s'oppose à l'égalité de référence des class ordinaires.
with
Expression créant une copie d'un record en changeant quelques champs ; l'original reste intact (mutation non destructive).
Nullable reference type
Référence marquée ? pouvant valoir null ; sans ?, le compilateur avertit de tout accès potentiellement nul.
Opérateurs ?. et ??
?. n'accède au membre que si l'objet n'est pas null (sinon renvoie null) ; ?? fournit une valeur de repli.
Tuple
Regroupement léger de plusieurs valeurs (souvent nommées) sans créer de type ; se déconstruit en variables : var (a, b) = ….

Récap et vérification

  • Un enum nomme un ensemble fixe de valeurs ; [Flags] + puissances de 2 permettent de les combiner.
  • Un record génère égalité de valeur, ToString(), GetHashCode() et déconstruction ; with en fait des copies modifiées.
  • record class = type référence (immuable), record struct = type valeur (ajoute readonly pour l'immuabilité).
  • Les nullable reference types (string?, ?., ??) font traquer les null par le compilateur.
  • Les tuples renvoient plusieurs valeurs ; le pattern matching (propriété et positionnel) exprime des règles concises.
