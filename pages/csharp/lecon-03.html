Module 01 · Les bases de C# — Leçon 03

Conditions et boucles

~30 min Intermédiaire Leçon 2 recommandée

À la fin de cette leçon, tu sauras

  • écrire des conditions avec if/else if/else et l'opérateur ternaire ;
  • utiliser le switch expression moderne et le pattern matching (is, when) ;
  • parcourir des collections avec for, while, do...while et foreach ;
  • maîtriser break, continue, la portée des variables et les conditions sur les nullables.
Sommaire de la leçon

Un programme qui exécute toujours les mêmes instructions dans le même ordre n'est pas très utile. Pour décider, répéter et réagir, il faut contrôler le flux d'exécution. En C#, cela passe par des conditions (exécuter du code seulement si une expression est vraie) et des boucles (répéter du code tant qu'une condition tient ou pour chaque élément d'une collection).

Dans cette leçon, on part du classique if/else et de l'opérateur ternaire, puis on découvre le switch moderne et le pattern matching, deux outils où C# brille particulièrement. On enchaîne sur les quatre boucles du langage, sur break et continue, sur la portée des variables, et enfin sur les conditions liées aux valeurs null.

if, else if, else et l'opérateur ternaire

Le if exécute un bloc si une expression booléenne (de type bool) vaut true. On enchaîne des cas avec else if, et on fournit un cas par défaut avec else. La condition se met toujours entre parenthèses.

Les conditions sont testées dans l'ordre : la première vraie l'emporte, les autres sont ignorées.

Quand il s'agit simplement de choisir entre deux valeurs, l'opérateur ternaire condition ? siVrai : siFaux est plus concis qu'un if/else.

Le ternaire est une expression : il produit une valeur qu'on peut affecter, alors que le if est une instruction.

Astuce

En C#, la condition d'un if doit être un bool. Écrire if (note) avec un entier ne compile pas, contrairement à C ou JavaScript : cela évite beaucoup de bugs silencieux.

C# moderne propose une forme bien plus élégante : le switch expression. Il retourne une valeur, utilise la flèche =>, sépare les bras par des virgules, et remplace default par le motif attrape-tout _.

Le mot-clé switch se place après la variable. Le motif 6 or 7 regroupe deux valeurs. _ couvre tout le reste.

Le pattern matching

Le pattern matching (filtrage par motif) teste la forme d'une valeur, pas seulement son égalité. L'opérateur is en est la porte d'entrée : il vérifie le type d'un objet et, au passage, déclare une variable du bon type.

Si valeur est bien une string, la variable texte devient utilisable immédiatement, déjà convertie.

Combiné au switch, le pattern matching gère le type, les propriétés et des conditions supplémentaires avec when. C'est très puissant pour classer une valeur.

La clause when n < 0 ajoute une condition au motif int n. L'ordre compte : le motif négatif doit précéder le motif int général.

Note

Ici Décrire est une méthode à corps d'expression (expression-bodied member) : on remplace les accolades et le return par =>. Pratique pour les petites méthodes qui ne font que retourner une valeur.

Cas réel

Dans un logiciel de dessin, chaque figure (cercle, rectangle, triangle) calcule son aire différemment. Plutôt qu'une cascade de if (x is Cercle) … else if (x is Rectangle) …, un seul switch expression sur le type fait le tri : forme switch { Cercle c => Math.PI * c.R * c.R, Rectangle r => r.L * r.H, _ => 0 }. Le code reste court, et le jour où l'on ajoute un type de figure, le compilateur aide à compléter les switch concernés. C'est le motif qu'on retrouve dans les analyseurs de code, les moteurs de règles et le traitement de messages réseau.

Les boucles : for, while, do...while

Le for sert quand on connaît le nombre de répétitions, ou qu'on a besoin d'un compteur. Ses trois parties : initialisation, condition de poursuite, incrément.

i++ ajoute 1 à i après chaque tour. La boucle continue tant que i <= 5 reste vrai.

Le while répète tant qu'une condition reste vraie, testée avant chaque tour. Le do...while teste après : le corps s'exécute donc au moins une fois.

% est le modulo (reste de division) : n % 2 == 0 teste si n est pair.

foreach : parcourir une collection

Le foreach est la boucle la plus utilisée en C#. Elle parcourt chaque élément d'une collection (tableau, List<T>, etc.) sans gérer d'index ni de condition d'arrêt. C'est plus sûr et plus lisible qu'un for avec index.

À chaque tour, fruit prend la valeur de l'élément courant. On peut écrire var fruit : le type est alors déduit automatiquement.

Piège fréquent

On ne peut pas modifier la collection (ajouter ou retirer un élément) pendant un foreach : cela lève une InvalidOperationException. Pour supprimer des éléments, parcours plutôt une copie, ou utilise un for à rebours.

break, continue et la portée des variables

Dans une boucle, break sort immédiatement, et continue passe directement au tour suivant en ignorant le reste du corps.

continue saute l'affichage pour 1, 3, 5... ; break coupe la boucle dès que i dépasse 6.

La portée (scope) d'une variable est le bloc { ... } où elle est déclarée. Une variable déclarée dans une boucle n'existe pas en dehors. Cela évite les collisions de noms et libère la mémoire au bon moment.

Tenter d'utiliser carré ou i après la boucle déclenche une erreur de compilation, pas d'exécution : le bug est attrapé tôt.

Les conditions sur les nullables

Une variable peut valoir null (absence de valeur). C# moderne t'aide à ne pas l'oublier grâce aux types référence nullables : string? indique « peut être null », et le compilateur t'avertit si tu l'utilises sans vérifier.

nom?.Length vaut null si nom est null (au lieu de lever une exception) ; nom ?? "(anonyme)" fournit une valeur de secours.

Note

is not null et is null sont la façon recommandée de tester la nullité : ils s'appuient sur le pattern matching et ne peuvent pas être détournés par une surcharge de l'opérateur ==.

Pièges fréquents

Piège fréquent

Confondre = (affectation) et == (comparaison). Écrire if (x = 5) n'est pas une comparaison ! Heureusement, comme la condition d'un if doit être un bool, le compilateur C# refuse cette erreur — sauf si x est déjà un bool, où elle passe inaperçue. Reste vigilant.

Piège fréquent

Dans le switch classique, oublier un break est une erreur de compilation en C# (le fall-through implicite à la C est interdit). Pour enchaîner volontairement deux cas, il faut un goto case — rarement utile et peu lisible. Dans le switch expression, le souci disparaît, mais n'oublie pas le motif _ : sans lui, si aucun cas ne correspond, une SwitchExpressionException est levée à l'exécution.

Pour aller plus loin

Pour aller plus loin

Le pattern matching va beaucoup plus loin : les property patterns testent des propriétés (p is { Age: >= 18 }), les positional patterns déconstruisent un tuple ou un record, et les relational patterns utilisent <, >=, etc. directement dans un motif. Les list patterns (C# 11) filtrent un tableau par sa forme ([1, .., 9]). Enfin, les index et ranges permettent tableau[^1] (dernier élément) et tableau[1..3] (une tranche). Tu rencontreras ces outils en manipulant collections et record dans les modules suivants.

Antisèche

Glossaire

Condition (booléenne)
Expression de type bool qui vaut true ou false ; en C#, un if exige une condition booléenne (pas un entier).
Opérateur ternaire
condition ? siVrai : siFaux : une expression qui produit l'une de deux valeurs ; plus concis qu'un if/else quand on choisit une valeur.
switch expression
Forme moderne du switch qui renvoie une valeur ; associe des motifs à des résultats via =>, avec _ comme attrape-tout.
Pattern matching
Filtrage par motif : teste la forme d'une valeur (type, propriétés, condition when) et peut déclarer une variable au passage (is).
Instruction vs expression
Une instruction exécute une action (if, switch classique) ; une expression produit une valeur (ternaire, switch expression).
foreach
Boucle qui parcourt chaque élément d'une collection sans gérer d'index ; la plus utilisée en C#.
break / continue
break quitte la boucle immédiatement ; continue passe au tour suivant en ignorant le reste du corps.
Portée (scope)
Le bloc { … } où une variable existe ; en dehors, elle est inaccessible, ce qui est vérifié à la compilation.

Récap et vérification

  • if/else if/else branchent selon des conditions bool ; le ternaire ? : choisit entre deux valeurs.
  • Le switch expression (var x = v switch { ... }) retourne une valeur ; _ est l'attrape-tout qui garantit l'exhaustivité : sans lui, le compilateur avertit et une SwitchExpressionException peut survenir à l'exécution.
  • Le pattern matching (is, motifs de type/propriété, when) teste la forme d'une valeur.
  • Quatre boucles : for (compteur), while (avant), do...while (au moins une fois), foreach (chaque élément).
  • break sort, continue saute un tour ; une variable n'existe que dans son bloc.
  • Pour les nullables : is null/is not null, ?. et ??.

Vérifie ta compréhension

  1. Quelle différence entre un if et l'opérateur ternaire ? Lequel produit une valeur ?
  2. Pourquoi le motif _ est-il important dans un switch expression ? Que se passe-t-il s'il manque ?
  3. Entre while et do...while, lequel garantit au moins une exécution du corps ? Pourquoi ?
