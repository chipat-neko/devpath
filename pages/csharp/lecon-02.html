Module 01 · Les bases de C# — Leçon 02

Variables, types et opérateurs

~28 min Intermédiaire Leçon 1 recommandée

À la fin de cette leçon, tu sauras

  • déclarer des variables typées avec int, double, decimal et l'inférence var ;
  • distinguer les types valeur des types référence (copie vs alias) et choisir decimal pour la monnaie ;
  • manipuler les string avec l'interpolation $"..." et combiner les opérateurs arithmétiques, de comparaison et logiques ;
  • gérer l'absence de valeur avec les types nullable (int?, string?), les opérateurs ?. et ??, et convertir avec int.TryParse et le cast.
Sommaire de la leçon

Tu sais déjà ce qu'est une variable : une boîte nommée qui contient une donnée. En C#, chaque boîte a un type figé à la compilation (typage statique) : une variable déclarée int contiendra toujours un entier, et le compilateur refusera d'y mettre du texte. C'est plus strict qu'en JavaScript ou Python, mais cette rigueur attrape une foule de bugs avant même que le programme ne tourne.

Dans cette leçon, tu vas voir comment déclarer et typer des variables, la différence fondamentale entre types valeur et types référence, pourquoi decimal est obligatoire pour l'argent, l'interpolation de chaînes, les opérateurs, puis comment gérer proprement l'absence de valeur avec les types nullable et convertir entre types.

Déclarer une variable : type explicite ou var

La forme de base écrit le type, le nom, puis la valeur initiale. Le nom d'une variable locale suit la convention camelCase (première lettre minuscule).

Quand le type est évident d'après la valeur à droite, tu peux écrire var : le compilateur déduit le type. Ce n'est pas du typage dynamique : age reste un int figé, tu évites juste de le réécrire.

Note

Cette leçon utilise les top-level statements de C# moderne : tu écris ton code directement dans Program.cs, sans class Program ni static void Main. Le compilateur les ajoute pour toi.

Types valeur et types référence

C'est la distinction la plus importante de la leçon. Les types valeur (int, long, double, decimal, bool, char) contiennent directement leur donnée. Quand tu les copies, tu copies la valeur : les deux variables deviennent indépendantes.

Les types référence (string, les tableaux, les objets de tes classes) contiennent une référence vers une donnée stockée ailleurs en mémoire. Copier la variable copie la référence, pas la donnée : les deux noms désignent alors le même objet.

Note

Image mentale : un type valeur, c'est la donnée écrite sur un papier que tu photocopies ; un type référence, c'est une adresse écrite sur le papier : deux papiers peuvent porter la même adresse et donc mener à la même maison.

decimal pour la monnaie, double pour le reste

double stocke les nombres à virgule en binaire : certaines valeurs décimales simples ne sont pas représentables exactement, d'où des erreurs d'arrondi. Pour de l'argent, c'est inacceptable. Utilise decimal (suffixe m), conçu pour le calcul décimal exact.

Règle simple : double pour la science, la physique, les graphismes ; decimal dès qu'il s'agit de prix, de comptabilité ou de taux.

Cas réel

Dans un logiciel de caisse, additionner des milliers de lignes de tickets en double fait dériver chaque centime d'une fraction infime ; multiplié par le volume, le total de la journée finit par différer de quelques centimes de la somme réelle — assez pour qu'un rapprochement comptable tombe en erreur et bloque la clôture. Le correctif tient en une lettre : passer les montants en decimal. C'est aussi pourquoi les bases de données offrent un type DECIMAL/NUMERIC dédié à l'argent.

Note

Les sorties ci-dessus utilisent la virgule comme séparateur décimal (0,3) car Console.WriteLine suit la culture de la machine, ici le français. Sur une machine configurée en anglais, tu verrais un point (0.3).

Les chaînes : immuables, interpolées, comparées par contenu

Une string est immuable : toute opération qui semble la modifier crée en réalité une nouvelle chaîne. Pour assembler du texte, l'interpolation $"..." est l'outil moderne : tu insères des variables entre accolades, directement dans la chaîne.

Bonne nouvelle si tu viens de Java : en C#, l'opérateur == sur des string compare le contenu, pas l'adresse mémoire.

Les opérateurs

Les opérateurs arithmétiques sont classiques (+ - * /), mais attention à la division : entre deux entiers, elle est entière (le reste est jeté). Le modulo % donne justement ce reste.

Les opérateurs de comparaison (==, !=, >, <, >=, <=) renvoient un bool. Les opérateurs logiques combinent des conditions : && (et), || (ou), ! (non).

L'absence de valeur : les types nullable, ?. et ??

Un type valeur comme int ne peut pas valoir null par défaut. Pour autoriser « pas de valeur », ajoute ? : int? est un entier nullable. Côté types référence, C# moderne active les nullable reference types : string ne doit pas être null, alors que string? l'autorise explicitement — le compilateur t'avertit si tu oublies de vérifier.

Deux opérateurs rendent la manipulation du null sûre. L'opérateur conditionnel ?. n'accède au membre que si l'objet n'est pas null (sinon il renvoie null, sans planter). L'opérateur ?? (null-coalescing) fournit une valeur de repli quand l'expression de gauche est null.

Conversion et casting

Passer d'un type à un autre demande une conversion explicite. Du texte vers un nombre : int.Parse ou, mieux, int.TryParse qui ne plante pas sur une entrée invalide. Entre types numériques, le cast (int) tronque la partie décimale.

Pièges fréquents

Piège fréquent

La division entière involontaire. 5 / 2 vaut 2, pas 2,5, car les deux opérandes sont des int. Pour une division réelle, force au moins un opérande en réel : 5.0 / 2 ou (double)a / b.

Piège fréquent

Utiliser double pour de l'argent. 0.1 + 0.2 ne donne pas exactement 0.3 : les centimes finissent par dériver. Toujours decimal (suffixe m) pour les montants.

Piège fréquent

La NullReferenceException : appeler un membre sur une référence null fait planter le programme. C'est pourquoi C# moderne utilise string? pour signaler ce qui peut être null, et l'opérateur ?. pour y accéder sans risque. De même, int.Parse("abc") lève une exception : pour une entrée incertaine, préfère int.TryParse.

Dernier classique : confondre type valeur et type référence. Copier un int donne deux variables indépendantes ; copier un tableau donne deux alias du même tableau. Modifier l'un modifie alors l'autre.

Pour aller plus loin

Pour aller plus loin

Les nullable reference types méritent un approfondissement : ils transforment les null en avertissements de compilation. Découvre aussi les tuples ((int, string) p = (1, "a");) pour regrouper des valeurs, les conversions implicites (sans perte, ex. int vers long) vs explicites (avec cast), le type BigInteger pour les entiers géants, et le pattern matching sur types avec is et les switch expressions.

Glossaire

Typage statique
Le type de chaque variable est fixé et vérifié à la compilation ; une erreur de type est signalée avant l'exécution.
var
Demande au compilateur de déduire le type à partir de la valeur initiale ; le type reste figé (ce n'est pas du dynamique).
Type valeur
Contient directement sa donnée (int, double, bool…) ; l'affectation en fait une copie indépendante.
Type référence
Contient une adresse vers une donnée stockée ailleurs (string, tableaux, objets) ; l'affectation copie l'adresse, pas l'objet.
decimal
Type numérique à virgule en base 10, exact pour les montants ; littéral suffixé m.
Immuable
Se dit d'une valeur qui ne peut pas changer après création ; les string le sont, toute « modification » crée une nouvelle chaîne.
Type nullable
Type autorisé à valoir null (int?, string?) ; matérialise l'absence de valeur.
?. / ??
Accès conditionnel (renvoie null au lieu de planter) et opérateur de coalescence des nuls (fournit une valeur de repli).

Récap et vérification

  • Le typage est statique ; var déduit le type sans le rendre dynamique.
  • Types valeur (copie indépendante) vs types référence (alias du même objet).
  • decimal (suffixe m) pour la monnaie ; double sinon.
  • Les string sont immuables, comparées par contenu avec ==, assemblées avec l'interpolation $"...".
  • Division entière 5 / 2 vaut 2 ; modulo % pour le reste ; logiques &&, ||, !.
  • Nullable : int?, string?, plus ?. (accès sûr) et ?? (valeur de repli).
  • Conversion : int.TryParse (sans exception), cast (int) qui tronque.
