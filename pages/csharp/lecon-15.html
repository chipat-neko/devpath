Module 05 · C# en profondeur — Leçon 15

Fonctionnalités avancées du langage

~35 min Avancé Leçon 14 recommandée

À la fin de cette leçon, tu sauras

  • savoir déclarer un event, gérer les multicast delegates et se désabonner pour éviter les fuites mémoire ;
  • savoir exploiter le pattern matching avancé (property, positional, relational, list patterns) et les switch expressions ;
  • savoir manipuler Span<T> et stackalloc sans allocation, et comprendre les expression trees ;
  • savoir utiliser les nouveautés C# 12 (required, primary constructors, collection expressions) et situer la réflexion et les source generators.
Sommaire de la leçon

Tu maîtrises maintenant les fondations de C# : la POO, les records, les génériques, LINQ, async/await. Cette leçon ouvre la boîte à outils des fonctionnalités avancées du langage — celles qui rendent C# expressif et performant, et qui se cachent derrière des bibliothèques comme Entity Framework ou System.Text.Json.

On y plonge dans les délégués et événements en profondeur, le pattern matching moderne, les records avancés, Span<T> pour la performance, les expression trees (« du code comme donnée »), un aperçu de la réflexion et des source generators, et enfin les nouveautés de C# 12. Chaque section montre un exemple compilable, avec la sortie en commentaire.

Délégués et événements approfondis

Un délégué est un type qui référence une méthode. Un event encapsule un délégué pour qu'un type expose un point d'abonnement sans laisser l'extérieur déclencher l'invocation. La convention .NET est le pattern EventHandler<TEventArgs>.

Un événement multicast appelle ses abonnés dans l'ordre d'inscription. L'opérateur -= retire exactement la même référence : pour pouvoir te désabonner, garde la lambda dans une variable.

Piège fréquent

Un abonné non désabonné maintient une référence forte vers son objet : c'est une fuite mémoire classique. Si l'éditeur vit longtemps (singleton, service statique), l'abonné ne sera jamais collecté tant qu'il reste inscrit.

Pattern matching avancé

Les patterns dépassent le simple test de type. Tu peux inspecter des propriétés, déconstruire des tuples et des records, et combiner des conditions relationnelles dans une switch expression.

Le list pattern [var premier, .., var dernier] capture le premier et le dernier élément en ignorant le milieu via le slice pattern ... Note que Classer(new Point(3, 3)) renvoie "diagonale" : la première branche qui matche l'emporte, l'ordre des cas compte.

Records avancés

Les records offrent une égalité de valeur en profondeur et la mutation non destructive via with. Ils supportent aussi l'héritage et la variante record struct (sémantique de valeur : copié à l'affectation au lieu d'être partagé par référence).

Piège fréquent

Un record est conçu pour être immuable. Évite d'ajouter des setters mutables : tu perdrais le bénéfice de l'égalité de valeur (deux instances « égales » pourraient diverger après coup) et tu risquerais des bugs de partage. Pour « changer » un champ, crée une copie avec with.

Span<T> et Memory<T> : performance sans allocation

Span<T> est une vue contiguë sur une zone mémoire (tableau, pile, mémoire native) qui permet de découper et lire sans copier ni allouer. Combiné à stackalloc, il évite de solliciter le ramasse-miettes dans les chemins chauds.

Span<T> est un ref struct : il vit sur la pile. C'est ce qui garantit l'absence d'allocation, mais aussi ce qui impose de fortes restrictions. Memory<T> est son équivalent stockable (champ, méthode async), avec en contrepartie moins de garanties sur la durée de vie.

Piège fréquent

Un Span<T> ne doit pas échapper à sa portée : il ne peut pas être un champ de classe, ni une variable locale capturée dans une méthode async ou un itérateur. Si tu en as besoin au-delà d'un appel, utilise Memory<T>.

Expression trees : du code comme donnée

Une lambda affectée à un Func<...> est compilée en code exécutable. Affectée à un Expression<Func<...>>, elle devient un arbre de données décrivant l'opération — que tu peux inspecter ou traduire (en SQL, par exemple). C'est le secret de LINQ to SQL et d'Entity Framework.

Un fournisseur de requêtes (comme EF) ne compile pas l'arbre : il le parcourt pour générer une requête SQL équivalente. La même lambda x => x * 2 est donc soit du code, soit une donnée selon le type cible.

Piège fréquent

Ne confonds pas un Expression<Func<...>> avec une lambda compilée. Dans EF, appeler une méthode C# arbitraire dans une requête IQueryable échoue à l'exécution si elle ne peut pas être traduite en SQL : l'arbre n'est jamais exécuté côté .NET.

Réflexion et aperçu des source generators

La réflexion inspecte les types à l'exécution via leurs métadonnées : lister des propriétés, lire des attributs, instancier dynamiquement. Les source generators font l'inverse — ils génèrent du code à la compilation, sans coût d'exécution.

Piège fréquent

La réflexion est coûteuse (pas d'inline, vérifications à l'exécution) et fragile (un renommage casse une chaîne magique). En contexte sensible à la performance ou compatible AOT, préfère un source generator qui produit le même code à la compilation.

Nouveautés C# 12

C# 12 raffine l'écriture des types. required impose l'initialisation d'une propriété, les primary constructors s'étendent à toutes les classes, et les collection expressions [...] unifient l'initialisation des collections avec l'opérateur de propagation ...

Omettre Nom à la construction est désormais une erreur de compilation, pas un bug silencieux à l'exécution. Les collection expressions choisissent la construction optimale selon le type cible.

Pièges fréquents

Piège fréquent

Récapitulatif des erreurs vues : oublier de se désabonner d'un event (fuite mémoire) ; muter un record au lieu d'utiliser with ; laisser un Span<T> échapper à sa portée (impossible comme champ ou en async) ; confondre un expression tree avec une lambda compilée ; abuser de la réflexion (coût et fragilité face aux renommages).

Un cas réel : l'événement qui retenait toutes les fenêtres

Cas réel

Une application de bureau ouvrait des fenêtres de détail qui s'abonnaient à un événement DonneesRafraichies d'un service singleton (vivant toute la session). À la fermeture d'une fenêtre, personne ne se désabonnait. Résultat : chaque fenêtre ouverte puis fermée restait en mémoire, car le service gardait une référence forte vers elle via le délégué. Après une journée d'utilisation, l'appli consommait plusieurs gigaoctets et ramait. Un profileur mémoire (dotMemory) a pointé des centaines d'instances de fenêtre censées être détruites, toutes retenues par le même événement. Le correctif : se désabonner (-=) à la fermeture, en gardant le gestionnaire dans un champ pour retirer exactement la bonne référence. Consommation mémoire stable ensuite.

Glossaire

Délégué
Type qui référence une méthode (comme Func ou Action) ; permet de passer un comportement en paramètre et de chaîner des appels.
Événement (event)
Délégué encapsulé qu'un type expose comme point d'abonnement (+=/-=) sans laisser l'extérieur le déclencher ; multicast, appelé dans l'ordre d'inscription.
Pattern matching
Tester la forme d'une valeur (type, propriétés, position, liste) dans un switch expression ; la première branche qui correspond l'emporte.
Record
Type à égalité de valeur en profondeur et mutation non destructive via with ; conçu immuable, il existe aussi en record struct.
Span<T> (ref struct)
Vue contiguë (pointeur + longueur) sur une mémoire existante, sans copie ni allocation ; contrainte à la pile — ni champ, ni async.
Expression tree
Lambda capturée sous forme d'arbre de données (Expression<Func<…>>) au lieu de code exécutable ; analysable et traduisible (EF → SQL).
Réflexion
Inspection des types à l'exécution via leurs métadonnées (propriétés, attributs, instanciation) ; puissante mais coûteuse et fragile aux renommages.
Source generator
Composant qui génère du code à la compilation (sans coût d'exécution) ; alternative à la réflexion, compatible Native AOT.

Récap et vérification

  • Un event encapsule un délégué multicast ; se désabonner avec -= évite les fuites mémoire.
  • Le pattern matching combine property, positional, relational et list patterns dans des switch expressions exhaustives.
  • Les records offrent égalité de valeur, mutation non destructive avec with, héritage et record struct.
  • Span<T> et stackalloc manipulent des tampons sans allocation, au prix de contraintes de portée.
  • Un Expression<Func<...>> est du code sous forme de données, traduisible (le cœur d'EF).
  • Réflexion et source generators inspectent ou génèrent du code ; required, primary constructors et collection expressions modernisent l'écriture.
