Fichiers, JSON et sérialisation

~34 min Intermédiaire Leçon 08 recommandée

À la fin de cette leçon, tu sauras

  • Lire et écrire des fichiers texte avec System.IO (File, Directory, Path) ;
  • Construire des chemins portables avec Path.Combine et les dossiers spéciaux ;
  • Sérialiser un objet C# en JSON et le désérialiser avec System.Text.Json ;
  • Régler la sérialisation (camelCase, indentation, [JsonPropertyName]) et travailler en asynchrone sur les gros fichiers.
Sommaire de la leçon

Un programme utile finit presque toujours par lire ou écrire des données : charger une configuration, sauvegarder l'état d'un jeu, exporter un rapport, dialoguer avec une API. Deux compétences se combinent ici. D'abord manipuler des fichiers (l'espace de noms System.IO). Ensuite convertir des objets C# en un format d'échange universel et inversement : c'est la sérialisation, et le format roi aujourd'hui est le JSON.

Bonne nouvelle : .NET fournit tout en standard, sans dépendance externe. Les fichiers passent par System.IO ; le JSON par System.Text.Json, rapide et intégré depuis .NET Core 3.

Lire et écrire des fichiers : System.IO

La classe statique File couvre les opérations courantes en une ligne. Pour un fichier de taille raisonnable, ReadAllText/WriteAllText (ou les variantes ...Lines) suffisent.

Trois classes se partagent le travail dans System.IO : File agit sur le contenu d'un fichier, Directory sur les dossiers (créer, lister, supprimer), et Path sur les chaînes de chemin (assembler, extraire l'extension). On les confond souvent : garde en tête « fichier / dossier / chemin ».

Des chemins portables : Path.Combine

Ne construis jamais un chemin en collant des chaînes avec un / ou un \ : le séparateur diffère entre Windows (\) et Linux/macOS (/). Path.Combine choisit le bon séparateur et évite les doublons. Pour les emplacements standard (données d'application, dossier temporaire), passe par Environment.SpecialFolder plutôt que par un chemin en dur.

Astuce

Pour désigner un fichier à côté de ton exécutable, combine avec AppContext.BaseDirectory. Et méfie-toi du répertoire courant (Directory.GetCurrentDirectory()) : il dépend d'où l'application est lancée, pas d'où elle est installée — source classique de « fichier introuvable » qui ne se reproduit pas sur ta machine.

Sérialiser en JSON : System.Text.Json

Le JSON (JavaScript Object Notation) est un format texte lisible qui représente objets, tableaux, nombres, chaînes et booléens. Sérialiser, c'est transformer un objet C# en ce texte ; désérialiser, l'inverse. La classe JsonSerializer fait les deux.

Les record (leçon 8) sont parfaits pour ça : immuables, concis, ils décrivent exactement la forme des données échangées. La correspondance se fait par nom de propriété : la propriété Nom devient la clé "Nom", et réciproquement.

Régler la sortie : options et attributs

Par défaut, System.Text.Json respecte la casse exacte des propriétés (PascalCase) et produit du JSON compact. Deux besoins reviennent : le rendre lisible, et respecter la convention camelCase des API web. On passe alors un JsonSerializerOptions.

Pour contrôler finement une propriété, on l'annote. [JsonPropertyName] fixe la clé JSON ; [JsonIgnore] l'exclut ; [JsonConverter] branche une conversion sur mesure.

Piège fréquent

La casse est la première cause de désérialisation « qui renvoie tout à zéro ». Une API web renvoie {"nom":"Café"} (minuscule) mais ta propriété s'appelle Nom : sans PropertyNameCaseInsensitive = true (ou une naming policy), System.Text.Json ne fait pas la correspondance et laisse la propriété à sa valeur par défaut (null, 0). Toujours aligner la casse entre le JSON et tes options.

Gros fichiers et asynchrone

ReadAllText charge tout le fichier en mémoire : parfait pour un fichier de config de quelques kilo-octets, catastrophique pour un export de 2 Go. Pour les gros volumes, on lit en flux (FileStream) et on désérialise directement depuis ce flux, sans matérialiser une énorme chaîne intermédiaire. Et comme un accès disque est une opération d'entrée/sortie, on utilise les variantes async (leçon 12) pour ne pas bloquer le thread.

Note

La désérialisation peut échouer si le JSON est mal formé ou incompatible : JsonSerializer lève alors une JsonException. Ne fais jamais aveuglément confiance à un fichier ou à une réponse réseau : entoure la lecture d'un try/catch (leçon 9) et prévois un comportement de repli (valeurs par défaut, message clair).

Un cas réel : l'API dont tous les champs revenaient vides

Cas réel

Une équipe consommait une API REST partenaire qui renvoyait {"firstName":"Ada","lastName":"Lovelace"}. Côté C#, la classe avait des propriétés FirstName/LastName (PascalCase). La désérialisation ne plantait pas : elle renvoyait un objet dont toutes les chaînes étaient à null, car System.Text.Json compare la casse par défaut et ne trouvait aucune correspondance entre firstName et FirstName. Le bug est passé en production : des e-mails « Bonjour null » sont partis aux clients. Le correctif tenait en une option — PropertyNameCaseInsensitive = true — plus un test de désérialisation sur un échantillon réel de la réponse. Depuis, l'équipe teste systématiquement la (dé)sérialisation contre un vrai payload, jamais contre un JSON réécrit « à la bonne casse ».

Antisèche

Glossaire

System.IO
Espace de noms des entrées/sorties : File (contenu), Directory (dossiers), Path (chemins), FileStream (flux).
Path.Combine
Assemble des morceaux de chemin avec le bon séparateur selon l'OS ; à préférer à toute concaténation manuelle de chaînes.
Sérialisation
Conversion d'un objet en mémoire vers un format d'échange (ici du texte JSON) ; la désérialisation fait l'inverse.
JSON
Format texte universel (objets, tableaux, nombres, chaînes, booléens) pour stocker et échanger des données.
JsonSerializer
Classe de System.Text.Json : Serialize (objet → texte) et Deserialize<T> (texte → objet).
JsonSerializerOptions
Réglages de (dé)sérialisation : WriteIndented, PropertyNamingPolicy (camelCase), PropertyNameCaseInsensitive.
[JsonPropertyName]
Attribut fixant la clé JSON d'une propriété quand elle diffère de son nom C# ; [JsonIgnore] l'exclut de la sérialisation.
Flux (Stream)
Lecture/écriture par morceaux successifs ; couplé à DeserializeAsync, il garde l'empreinte mémoire basse sur les gros fichiers.

Récap et vérification

  • System.IO : File (contenu), Directory (dossiers), Path (chemins). ReadAllText/WriteAllText pour l'essentiel.
  • Path.Combine et Environment.SpecialFolder pour des chemins portables ; jamais de séparateur en dur.
  • JsonSerializer.Serialize/Deserialize<T> convertissent objet ⇄ JSON ; les record décrivent bien la forme des données.
  • JsonSerializerOptions (camelCase, indenté, casse insensible) et les attributs [JsonPropertyName]/[JsonIgnore] règlent la sortie.
  • Gros fichiers : lecture en flux asynchrone (DeserializeAsync) ; toujours prévoir l'échec (JsonException).
