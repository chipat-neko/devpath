Module 08 · React en pratique — Leçon 25

Animations et transitions

~36 min Intermédiaire Leçon 6 recommandée

À la fin de cette leçon, tu sauras

  • animer un changement d'état en pilotant une classe CSS ;
  • comprendre pourquoi l'animation de sortie exige de retarder le démontage ;
  • distinguer useTransition (rendu concurrent) d'une transition CSS ;
  • garder l'interface réactive et respecter prefers-reduced-motion.
Sommaire de la leçon

React ne dessine pas d'animations à ta place : il met à jour le DOM, et c'est le plus souvent le CSS qui anime le passage d'un état à l'autre. Le rôle de React se résume alors à changer la bonne classe au bon moment. Cette leçon parcourt les trois situations qu'on rencontre vraiment : piloter le CSS avec l'état, orchestrer l'animation de sortie quand un composant disparaît, et le cas particulier — souvent mal compris — des transitions d'état concurrentes avec useTransition. Le tout sans jamais oublier les personnes sensibles au mouvement.

Animer, c'est piloter le CSS avec l'état

La façon la plus simple et la plus performante d'animer en React : laisser l'état décider d'une classe, et laisser le CSS interpoler entre les deux styles. React n'anime rien lui-même ; il bascule juste la classe, le navigateur fait le reste.

Anime transform et opacity

Ces deux propriétés sont compositées : le navigateur les anime sur le GPU sans recalculer la mise en page, ce qui tient facilement les 60 images par seconde. Animer width, height, top ou margin force au contraire un reflow à chaque image : c'est la première cause de saccades. Besoin d'agrandir ? Préfère transform: scale(...) à un changement de width.

Le problème du démontage

Animer une entrée est facile : on monte le composant, la classe déclenche la transition. Animer une sortie est le vrai piège. Quand une condition passe à false :

…le composant est retiré du DOM instantanément : il n'y a plus rien à animer, l'élément a déjà disparu. Pour voir une sortie, il faut retarder le démontage jusqu'à la fin de l'animation. À la main, cela demande de jouer la classe de sortie, d'écouter transitionend (ou un minuteur), puis de retirer l'élément — c'est fastidieux et source de bugs. En pratique on délègue à une bibliothèque conçue pour ça.

Laisse une bibliothèque gérer la sortie

Le composant <AnimatePresence> de Motion (ex-Framer Motion) enveloppe un élément conditionnel et retarde son démontage jusqu'à la fin de l'animation de sortie ; React Transition Group rend le même service de façon plus bas niveau. Écrire cette mécanique à la main est possible, mais rarement rentable : c'est un problème déjà résolu.

Transitions d'état ≠ transitions CSS : useTransition

Attention à un faux ami : le hook useTransition de React n'anime rien visuellement. Le mot « transition » désigne ici une transition d'état dans le rendu concurrent : le moyen de marquer une mise à jour comme non urgente, pour qu'elle ne bloque pas les interactions urgentes (comme la frappe au clavier).

La mise à jour du champ (setQ) reste prioritaire : chaque lettre s'affiche sans délai. Le recalcul coûteux de la liste, marqué par demarrerTransition, se fait en arrière-plan et peut être interrompu si l'utilisateur tape encore. Le drapeau enCours (souvent nommé isPending) permet d'afficher un indicateur discret. Sa variante useDeferredValue applique le même principe à une valeur dérivée plutôt qu'à une mise à jour.

Piège de nommage

useTransition et startTransition ne produisent aucune animation CSS. Pour animer visuellement, c'est toujours le CSS ou une bibliothèque. Le mot « transition » de React désigne une transition d'état (une mise à jour non urgente), pas un fondu ni un glissement. Deux notions, un même mot : ne les confonds pas.

Respecter prefers-reduced-motion

Certaines personnes règlent leur système sur « réduire les animations » (vertiges, troubles vestibulaires). On coupe alors les mouvements superflus — en CSS via la media query, ou en JS via matchMedia quand l'animation est pilotée par du code.

Cas réel

Une page de recherche filtrait une liste de plusieurs milliers de produits à chaque frappe. Résultat : la saisie « gelait » — chaque lettre attendait la fin du recalcul avant de s'afficher, et les utilisateurs croyaient l'application plantée. En marquant le filtrage avec useTransition (et en dérivant la liste affichée via useDeferredValue), le champ est redevenu instantané : les lettres apparaissent aussitôt, la liste se met à jour juste après avec un discret « Filtrage… ». Aucune animation ajoutée, aucun changement visuel du rendu : seule la priorité des mises à jour a changé.

Pour aller plus loin

Pour des animations riches et déclaratives : Motion (ex-Framer Motion) — composant <motion.div>, <AnimatePresence> pour les sorties, et animations de layout automatiques. Pour des transitions entre vues sans bibliothèque : la View Transitions API du navigateur, que React intègre progressivement. Et pour animer l'ajout/retrait d'éléments d'une liste en une ligne : AutoAnimate.

Antisèche

Glossaire

Transition CSS
Propriété transition qui interpole en douceur un style vers un autre quand une classe ou une valeur change ; c'est elle qui « anime », pas React.
Propriété compositée
Propriété (transform, opacity) que le navigateur anime sur le GPU sans recalculer la mise en page : fluide même sur mobile.
Reflow
Recalcul de la mise en page déclenché en animant width, height, top… ; coûteux à chaque image, cause fréquente de saccades.
Animation de sortie
Animation jouée quand un composant disparaît ; elle impose de retarder le démontage jusqu'à sa fin.
Démontage
Unmount : retrait d'un composant du DOM. Immédiat par défaut, ce qui empêche d'animer sa disparition sans orchestration.
useTransition
Hook du rendu concurrent qui marque une mise à jour comme non urgente ; il ne produit aucune animation visuelle.
useDeferredValue
Hook qui fournit une version « différée » d'une valeur, pour recalculer un rendu coûteux sans bloquer les interactions urgentes.
prefers-reduced-motion
Préférence système demandant de réduire les animations ; lisible en CSS (media query) ou en JS (matchMedia).

Récap et vérification

  • Le schéma de base : l'état choisit une classe, la transition CSS anime — React ne fait que basculer la classe.
  • Anime transform et opacity (compositées) plutôt que width/top pour rester fluide.
  • L'entrée s'anime seule ; la sortie exige de retarder le démontage (<AnimatePresence>).
  • useTransition n'anime pas : il priorise les mises à jour. On respecte toujours prefers-reduced-motion.

Vérifie ta compréhension

  1. Comment anime-t-on un simple changement d'état visuel en React ?
  2. Pourquoi l'animation de sortie est-elle plus délicate que l'entrée ?
  3. useTransition produit-il une animation ? À quoi sert-il ?

Exercice 2Application

On veut animer un panneau qui disparaît en glissant. Explique en une phrase pourquoi {ouvert && <Panneau />} ne suffit pas, et quelle est la solution.

Voir une solution

Avec {ouvert && <Panneau />}, dès que ouvert devient false le Panneau est retiré du DOM immédiatement : l'animation de sortie n'a pas le temps de se jouer. La solution est de retarder le démontage jusqu'à la fin de l'animation — le plus simple étant d'envelopper l'élément dans un <AnimatePresence> (Motion), qui garde le composant monté pendant sa transition de sortie puis le retire.
