JSX en profondeur

~33 min Intermédiaire Leçon 01 recommandée

À la fin de cette leçon, tu sauras

  • Comprendre que le JSX est du sucre syntaxique transpilé en appels React.createElement, et non du HTML ;
  • Savoir injecter des expressions JavaScript entre accolades et reconnaître ce qui n'en est pas une ;
  • Écrire correctement les attributs JSX (className, htmlFor, camelCase, style en objet) ;
  • Maîtriser les fragments, les balises auto-fermantes et les valeurs qui ne rendent rien.
Sommaire de la leçon

Tu sais déjà écrire un composant fonction qui renvoie du JSX. Mais le JSX n'est pas magique : ce n'est ni du HTML, ni une chaîne de caractères. C'est une syntaxe pratique que ton outil de build traduit en simple JavaScript. Comprendre cette traduction, c'est arrêter de deviner pourquoi class ne marche pas, pourquoi il faut un fragment, ou pourquoi un if dans le rendu provoque une erreur.

Dans cette leçon, on ouvre le capot. Tu vas voir ce que devient ton JSX une fois transpilé, comment y glisser des expressions, comment écrire les attributs, et quels réflexes éviter.

Le JSX est du sucre syntaxique

Quand tu écris une balise JSX, Babel (utilisé par Vite, Next.js, etc.) la transforme en un appel de fonction. Cette balise :

Le JSX que tu écris.

Le JavaScript réellement exécuté.

Le JSX produit donc des objets JavaScript ordinaires (des « éléments React », une description légère de ce qu'il faut afficher). React lit ensuite cette description pour construire le DOM. Retiens trois conséquences : le premier argument est le type (une chaîne pour les balises natives, une référence pour tes composants), le deuxième est l'objet de props, et les suivants sont les enfants.

Note

Comme un composant est référencé par son nom dans createElement, il doit commencer par une majuscule (PascalCase). Une balise en minuscules est interprétée comme une balise HTML native (une chaîne), pas comme ton composant.

Les expressions entre accolades

Pour insérer une valeur dynamique dans le JSX, tu utilises des accolades {}. Tout ce qui s'y trouve doit être une expression JavaScript : quelque chose qui produit une valeur. Variables, calculs, appels de fonction, opérateur ternaire : tout est permis tant que ça « rend une valeur ».

Variable, calcul et appel de fonction dans les accolades.

À l'inverse, une instruction (statement) ne produit pas de valeur : un if, une boucle for, une déclaration const. On ne peut pas les mettre directement entre accolades. Pour un affichage conditionnel, on utilise donc un ternaire ou l'opérateur && (que tu verras en détail à la leçon 5) :

Un ternaire est une expression, donc valide dans les accolades.

Les attributs JSX

Les attributs ressemblent à du HTML, mais ce sont en réalité les clés de l'objet props. Comme certains noms HTML sont des mots réservés en JavaScript, JSX impose des variantes :

  • className au lieu de class (class est un mot-clé JS) ;
  • htmlFor au lieu de for (sur un <label>) ;
  • les autres attributs et gestionnaires d'événements en camelCase : onClick, tabIndex, onChange, autoFocus.

className, htmlFor et camelCase.

L'attribut style est un cas à part : il n'attend pas une chaîne CSS mais un objet JavaScript, avec des propriétés en camelCase. D'où la double accolade : l'accolade externe ouvre une expression JSX, l'accolade interne décrit l'objet.

style attend un objet : double accolade et propriétés camelCase (backgroundColor, pas background-color).

Une seule racine : les fragments

Une expression JSX doit renvoyer un seul élément racine : souviens-toi que return renvoie une valeur, pas deux. Si tu veux retourner plusieurs éléments côte à côte sans ajouter de <div> superflu dans le DOM, utilise un fragment : la balise vide <>…</> (ou <Fragment>).

Le fragment regroupe sans polluer le DOM.

Astuce

La forme courte <>…</> suffit dans 99 % des cas. Utilise <Fragment key={...}> (importé depuis react) seulement quand tu dois passer une key, par exemple dans une liste.

Balises auto-fermantes et commentaires

En JSX, toute balise sans enfant doit être fermée. Les éléments HTML « vides » comme img, br, input ou hr s'écrivent donc avec une barre oblique finale, sinon le transpileur lève une erreur de syntaxe.

Balises auto-fermées et commentaire entre accolades.

Les commentaires s'écrivent {/* … */} : comme c'est une expression placée entre accolades, on y met un commentaire JavaScript classique.

Ce qui ne rend rien

Trois valeurs sont ignorées par React au rendu : false, null et undefined. Elles ne produisent aucun texte ni aucun nœud. C'est précisément ce qui rend l'affichage conditionnel propre.

Si message est absent, l'expression vaut undefined et n'affiche rien.

Piège fréquent

Le nombre 0, lui, s'affiche. Avec {liste.length && <Liste />}, si la liste est vide tu verras un 0 apparaître à l'écran ! Préfère un test explicite : {liste.length > 0 && <Liste />}.

Pièges fréquents

  • Écrire class au lieu de className. React l'ignore et affiche un avertissement en console ; ta classe CSS ne s'applique pas.
  • Oublier de fermer une balise. <img> ou <input> sans / provoque une erreur de compilation. Toujours <img />.
  • Plusieurs éléments racine sans fragment. Renvoyer deux balises sœurs sans les envelopper casse le rendu. Enveloppe-les dans <>…</>.
  • Mettre un if ou un for dans les accolades. Ce sont des instructions, pas des expressions. Calcule avant le return, ou utilise un ternaire / map.
  • Confondre {} et {{}}. Une seule accolade ouvre une expression ; la double accolade de style n'est qu'une expression qui contient un objet littéral.

Pour aller plus loin

Quand une expression devient longue (plusieurs ternaires imbriqués, un map complexe), extrais-la dans une variable avant le return. Le JSX final reste lisible :

Le if vit dans le corps de la fonction, pas dans le JSX.

Pour aller plus loin

Le transpileur (Babel via Vite) convertit chaque balise en React.createElement (ou en jsx() avec la nouvelle transformation automatique de React 17+). Bonus sécurité : React échappe automatiquement les valeurs injectées entre accolades, ce qui neutralise les injections de balises et te protège du XSS sans effort.

Cas réel

Le piège du 0 qui s'affiche a fait bugguer d'innombrables interfaces : une pastille de notifications écrite {nbMessages && <Pastille />} affiche un « 0 » tout nu dès que la boîte est vide, au lieu de disparaître. On corrige en testant explicitement {nbMessages > 0 && …}. C'est l'un des bugs les plus signalés chez les débutants React, justement parce que le code « a l'air » juste.

Antisèche

Glossaire

Sucre syntaxique
Écriture plus lisible qui se compile en une forme équivalente ; ici, le JSX devient des appels React.createElement.
Transpileur
Outil (Babel, esbuild) qui traduit le JSX en JavaScript standard exécutable par le navigateur.
Expression
Bout de code qui produit une valeur (variable, calcul, appel, ternaire) ; seule chose admise entre accolades.
Instruction (statement)
Code qui exécute une action sans produire de valeur (if, for, const) ; interdit entre accolades.
camelCase
Casse « chameau » des attributs JSX (onClick, tabIndex) car ils deviennent des clés d'un objet JavaScript.
style (objet)
En JSX, style reçoit un objet JS ({ color: "red" }), d'où la double accolade.
Échappement automatique
React neutralise le HTML injecté entre accolades, ce qui protège des injections (XSS) sans effort.
Valeur ignorée
false, null et undefined ne rendent rien ; attention, 0 s'affiche.

Récap et vérification

  • Le JSX est transpilé en appels React.createElement(type, props, ...enfants) qui produisent des objets, pas du HTML.
  • Les accolades {} accueillent des expressions (valeurs), jamais des instructions comme if ou for.
  • Les attributs s'écrivent en camelCase : className, htmlFor, onClick ; style attend un objet (double accolade).
  • Une seule racine par expression JSX : utilise un fragment <>…</>. Les balises vides se ferment (<img />).
  • false, null et undefined ne rendent rien ; attention au 0 qui, lui, s'affiche.

Vérifie ta compréhension

  1. En quoi se transforme <h1>Salut</h1> après transpilation ? Donne l'appel correspondant.
  2. Pourquoi le JSX impose-t-il className au lieu de class, et les attributs en camelCase ?
  3. Quelle est la différence entre {maVariable} et {{ color: "red" }} dans un attribut style ?
