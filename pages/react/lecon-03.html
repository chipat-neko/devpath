Les props

~33 min Intermédiaire Leçon 02 recommandée

À la fin de cette leçon, tu sauras

  • passer des données à un composant via des props (texte entre guillemets, valeur entre accolades) ;
  • destructurer les props dans la signature et leur donner des valeurs par défaut ;
  • respecter le flux descendant : les props sont en lecture seule, du parent vers l'enfant ;
  • composer avec props.children et transmettre un objet avec le spread.
Sommaire de la leçon

Jusqu'ici, tes composants affichaient toujours la même chose : leur JSX était figé. Mais un composant n'a d'intérêt que s'il est réutilisable avec des données différentes. Une Carte produit doit pouvoir afficher un casque audio comme un clavier, sans qu'on réécrive le composant à chaque fois.

Le mécanisme qui rend cela possible, ce sont les props (abréviation de properties). Un composant parent passe des données à un composant enfant via des props, exactement comme on passe des attributs à une balise HTML. Dans cette leçon, tu vas apprendre à les recevoir, les destructurer, leur donner des valeurs par défaut, et composer des composants avec children.

Recevoir des props

Un composant fonction reçoit un seul argument : un objet de props. React le construit à partir des attributs que tu écris dans le JSX. Une valeur texte se passe entre guillemets ; toute autre valeur (nombre, booléen, objet, variable) se passe entre accolades.

Le parent App passe titre (texte, entre guillemets) et prix (nombre, entre accolades). La carte rend : un titre « Casque audio » et un paragraphe « 129 € ».

Note

Le nom props est une convention, pas un mot-clé : c'est juste le premier paramètre de la fonction. Mais garde ce nom, tout le monde le reconnaît immédiatement.

Destructurer les props dans la signature

Écrire props.titre, props.prix partout devient vite répétitif. Comme props est un simple objet, tu peux le destructurer directement dans la signature du composant. C'est la pratique la plus courante en React moderne.

Le rendu est identique, mais le corps est plus lisible : on lit la liste des props attendues d'un coup d'œil, dans les accolades.

Un composant, plusieurs appels

Tout l'intérêt des props : réutiliser le même composant avec des données différentes. Le parent décide du contenu de chaque carte.

Trois cartes, un seul composant. Le rendu affiche trois articles côte à côte, chacun avec son titre et son prix.

Astuce

En pratique, on génère souvent ces cartes à partir d'un tableau de données avec map (vu dans une prochaine leçon). Le principe reste le même : chaque élément du tableau alimente les props d'une Carte.

Les props sont en lecture seule

Règle fondamentale de React : un composant ne doit jamais modifier ses props. Les données circulent dans un seul sens, du parent vers l'enfant : c'est le flux de données descendant. L'enfant reçoit, lit, affiche — mais ne réécrit pas.

On ne réassigne pas prix ; on dérive une variable locale prixTTC. La prop d'origine reste intacte.

Note

Ce flux descendant rend une application prévisible : pour comprendre ce qu'affiche un composant, tu regardes les props que son parent lui donne. Si une donnée doit changer dans le temps, ce n'est pas une prop : c'est de l'état (leçon 6).

Valeurs par défaut

Quand une prop peut être omise, donne-lui une valeur par défaut. En React moderne, on utilise simplement les paramètres par défaut de la destructuration — la syntaxe JavaScript que tu connais déjà.

Ici devise vaut '€' et enStock vaut true par défaut. La carte rend « 145 € » et « Disponible » sans qu'on ait à passer ces props.

props.children : la composition

Une prop spéciale existe : children. Elle contient tout ce que tu places entre les balises d'ouverture et de fermeture du composant. C'est la base de la composition : un composant qui en enveloppe d'autres sans rien savoir de leur contenu.

Le paragraphe et le bouton deviennent le children du Panneau. Le rendu : un titre « Mon compte », puis le texte de bienvenue et le bouton, encadrés par le panneau.

Astuce

children est idéal pour les composants « contenant » : carte, modale, mise en page, encadré. Le composant gère la structure et le style ; l'appelant fournit le contenu.

Passer des fonctions en props

Une prop n'est pas forcément une donnée d'affichage : ce peut être une fonction. C'est ainsi qu'un enfant remonte un événement à son parent. Tu approfondiras cela avec la gestion d'événements (leçon 7), mais voici le principe.

Le parent passe la fonction acheter via la prop onAchat. Au clic, l'enfant l'appelle : c'est le parent qui décide quoi faire. Le flux reste descendant (la fonction descend), mais l'action remonte vers le parent.

Transmettre un objet de props avec le spread

Quand tu as déjà un objet dont les clés correspondent aux props attendues, l'opérateur spread (...) les transmet d'un coup. Pratique pour relayer des props sans les énumérer.

Chaque clé de produit devient une prop de Carte. Le rendu est identique à un passage manuel des trois props.

Piège fréquent

Le spread est commode, mais à utiliser avec parcimonie : <Carte {...produit} /> masque quelles props sont réellement passées. Sur un composant que tu lis souvent, l'écriture explicite reste plus claire.

Pièges fréquents

Piège fréquent

Modifier une prop. Réassigner prix = ... ou faire props.titre = '...' dans l'enfant casse le flux descendant et rend le rendu imprévisible. Dérive une variable locale ou, si la valeur doit évoluer, utilise l'état.

Piège fréquent

Oublier les accolades pour une valeur non textuelle. prix="129" passe la chaîne « 129 », pas le nombre. Pour un nombre, un booléen ou un objet, il faut des accolades : prix={129}, actif={true}, style={objet}.

Piège fréquent

Confondre props et état. Les props viennent du parent et sont en lecture seule ; l'état est interne au composant et peut changer dans le temps (leçon 6). Si une donnée ne dépend que du parent, c'est une prop.

Piège fréquent

Mauvaise casse du composant. Un composant doit commencer par une majuscule (Carte, en PascalCase). En minuscule, <carte />, React croit que c'est une balise HTML native et ne rend pas ton composant.

Pour aller plus loin

Pour aller plus loin

Pour fiabiliser les props, on les type : autrefois avec PropTypes (vérification au runtime), aujourd'hui surtout avec TypeScript, qui décrit la forme des props à la compilation (y compris un children typé via ReactNode). Tu croiseras aussi les render props (passer une fonction qui renvoie du JSX comme children) et le débat composition vs configuration : vaut-il mieux empiler beaucoup de props de configuration, ou composer de petits composants via children ? La composition vieillit souvent mieux.

Cas réel

Sur un site e-commerce, une même <FicheProduit> affiche tout le catalogue : le composant est écrit une fois, puis alimenté par des props (titre, prix, image, enStock) tirées d'une base de données. Refondre la mise en page d'une fiche ? On modifie le seul composant, et les 10 000 produits suivent. Les props sont le « contrat » entre les données et l'affichage : c'est ce qui permet de faire évoluer le catalogue sans retoucher le design produit par produit.

Antisèche

Glossaire

props
Objet des données passées d'un composant parent à un enfant ; toujours en lecture seule.
Destructuration
Extraction directe des props dans la signature : function Carte({ titre, prix }).
Flux descendant (one-way data flow)
Les données circulent du parent vers l'enfant, jamais l'inverse ; c'est ce qui rend le rendu prévisible.
Lecture seule
Un composant ne réassigne jamais ses props ; il en dérive une variable locale si une valeur doit être calculée.
Valeur par défaut
Valeur donnée à une prop omise, via les paramètres par défaut : { devise = '€' }.
children
Prop spéciale contenant le contenu placé entre les balises d'ouverture et de fermeture du composant.
Composition
Construire une interface en imbriquant des composants, souvent via children : le contenant ignore le contenu.
Spread ({...obj})
Opérateur qui transmet toutes les clés d'un objet comme autant de props, d'un seul coup.

Récap et vérification

  • Un composant reçoit un objet de props ; on passe le texte entre guillemets et toute autre valeur entre accolades.
  • On destructure les props dans la signature : function Carte({ titre, prix }).
  • Les props sont en lecture seule : flux descendant, du parent vers l'enfant.
  • Les valeurs par défaut se déclarent avec les paramètres par défaut : { devise = '€' }.
  • children contient le contenu placé entre les balises du composant : c'est la composition.
  • On peut passer des fonctions en props, et transmettre un objet entier avec le spread {...obj}.

Vérifie ta compréhension

  2. Pourquoi ne doit-on jamais modifier une prop dans l'enfant, et que faire à la place ?
  3. Que contient props.children, et dans quel cas est-ce utile ?
