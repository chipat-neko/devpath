Le rendu conditionnel

~31 min Intermédiaire Module 1 recommandé

À la fin de cette leçon, tu sauras

  • afficher un élément sous condition avec l'opérateur && en évitant le piège du 0 ;
  • choisir entre deux rendus avec un ternaire condition ? A : B ;
  • sortir la logique complexe du JSX (variable ou early return) et rendre null pour n'afficher rien ;
  • gérer l'état vide d'une liste en combinant condition et map.
Sommaire de la leçon

Une interface n'affiche presque jamais la même chose en permanence. Selon l'état, tu montres un bouton « Connexion » ou « Déconnexion », un indicateur de chargement ou les données, un message « liste vide » ou les éléments. Décider quoi afficher selon une condition, c'est le rendu conditionnel.

Bonne nouvelle : tu n'apprends presque aucune syntaxe nouvelle. Le rendu conditionnel en React, c'est du JavaScript que tu connais déjà — l'opérateur &&, le ternaire ? :, une variable, un return anticipé — placé au bon endroit. Dans cette leçon, tu vas voir les trois techniques principales, quand choisir chacune, et les pièges classiques (dont le fameux piège du 0).

Pourquoi : afficher selon l'état

Reprends le réflexe de la leçon 1 : tu décris à quoi l'interface doit ressembler. Si cette description dépend d'une donnée — un booléen estConnecte, un nombre de messages, un tableau éventuellement vide — alors ton JSX doit produire un rendu différent selon cette donnée.

Les cas reviennent tout le temps : afficher un bandeau seulement si l'utilisateur est connecté, montrer un « Chargement… » tant que les données arrivent, ou afficher « Aucun résultat » quand une liste est vide. Voici la donnée de départ de nos exemples :

Rappel essentiel : en JSX, les valeurs false, null, undefined et true ne produisent rien à l'écran. C'est exactement ce qui rend le rendu conditionnel possible — on va s'arranger pour qu'une branche « ne rien afficher » vaille l'une de ces valeurs.

Le ET logique && : afficher si vrai

Quand tu veux afficher quelque chose ou rien (pas d'alternative), l'opérateur && est l'outil le plus direct. En JavaScript, condition && valeur renvoie valeur si la condition est vraie, et sinon la condition elle-même (par exemple false). En JSX, false n'affiche rien.

Lis l'accolade comme une phrase : « si estConnecte est vrai, affiche ce paragraphe ». C'est concis et lisible tant qu'il n'y a pas de branche « sinon ». Dès qu'il faut afficher A ou B, on passe au ternaire (section suivante).

Piège fréquent

Le piège du 0. Si tu écris {messages.length && <Liste />} et que la liste est vide, messages.length vaut 0. Or 0 && … renvoie 0… et React affiche le chiffre 0 à l'écran ! Convertis toujours en vrai booléen : {messages.length > 0 && …}.

Le ternaire ? : : choisir entre deux rendus

Quand tu dois afficher soit A, soit B, l'opérateur ternaire condition ? A : B est fait pour ça. Contrairement au &&, il a toujours une branche « sinon ».

Extraire dans une variable (ou un early return)

Dès que la condition devient touffue, glisser toute la logique dans le JSX le rend illisible. La parade idiomatique : calculer le rendu avant le return, dans une variable.

Ici tu utilises un vrai if/else — ce qui est impossible dans les accolades — parce qu'on est dans le corps de la fonction, avant le return. C'est la bonne place pour toute logique un peu sérieuse.

Rendre null pour n'afficher rien

Parfois, un composant ne doit rien produire du tout dans certains cas. Tu peux alors return null : React n'insère aucun nœud dans le DOM.

C'est très utile pour les composants « de garde » : un toast, une bannière, un badge qui n'existe que sous condition. Le parent peut toujours écrire <Alerte message={x} /> sans se soucier du cas vide : c'est le composant lui-même qui décide de disparaître.

Pièges fréquents

Piège fréquent

Le 0 qui s'affiche, encore lui. {panier.length && <Total />} affiche « 0 » quand le panier est vide. Toujours une vraie condition booléenne : {panier.length > 0 && <Total />}.

  • Ternaires imbriqués illisibles. {a ? (b ? X : Y) : Z} devient vite indéchiffrable. Au-delà d'un niveau, extrais la logique dans une variable ou un if/else avant le return.
  • Mettre un if dans le JSX. { if (x) … } ne compile pas : les accolades attendent une expression, pas une instruction. Sors le if avant le return, ou utilise un ternaire / un &&.
  • Oublier que false/null ne rendent rien. C'est une fonctionnalité, pas un bug : c'est précisément ce qui permet à {condition && …} et à return null de « ne rien afficher ».
  • Confondre && et ternaire. Si tu te surprends à écrire {x && A} juste à côté de {!x && B}, c'est qu'il te fallait un seul ternaire {x ? A : B}.

Pour aller plus loin

Pour aller plus loin

Trois pistes : les composants de garde (un petit composant qui fait son return null tout seul, comme Alerte plus haut) ; les patterns de chargement avec des squelettes (afficher une silhouette grise à la place du contenu en attente, plutôt qu'un simple « Chargement… ») ; et les error boundaries (composants spéciaux qui interceptent une erreur de rendu et affichent un repli). Côté lisibilité, retiens la règle d'or : si une condition ne tient pas confortablement sur une ligne dans le JSX, elle mérite une variable au-dessus du return.

Cas réel

Sur une vraie boutique en ligne, l'icône du panier porte souvent un badge avec le nombre d'articles : {panier.length && <Badge n={panier.length} />}. Tout va bien… jusqu'à ce qu'un client vide son panier : panier.length vaut alors 0, et un « 0 » disgracieux vient se coller à l'icône au lieu de disparaître. Le correctif tient en trois caractères : panier.length > 0 && …. Ce bug est arrivé en production sur d'innombrables sites : c'est le piège de rendu conditionnel le plus fréquemment signalé en revue de code.

Antisèche

Glossaire

Rendu conditionnel
Fait d'afficher un contenu différent selon l'état ou les props, en plaçant une expression JavaScript dans le JSX.
&& (ET logique)
Renvoie sa partie droite si la gauche est truthy, sinon la valeur de gauche ; sert à afficher « quelque chose ou rien ».
Ternaire ? :
Opérateur condition ? A : B qui choisit entre deux valeurs : la seule façon d'écrire un « si/sinon » comme expression dans le JSX.
Court-circuit
Évaluation qui s'arrête dès que le résultat est connu : && n'évalue la droite que si la gauche est vraie.
Valeur falsy
Valeur considérée comme fausse : false, 0, "", null, undefined, NaN. Attention : 0 et "" sont falsy mais s'affichent en JSX.
Early return
Retour anticipé en tête de composant pour traiter un cas (chargement, liste vide) avant le rendu principal.
return null
Fait qu'un composant ne rend aucun nœud : utile pour un badge, un toast ou une alerte qui n'existe que sous condition.
État vide
Rendu prévu quand une collection ne contient aucun élément (message « Aucun résultat »), plutôt qu'une zone silencieusement vide.

Récap et vérification

  • Afficher ou rien → {condition && <JSX />}, avec une condition vraiment booléenne (gare au 0).
  • Afficher A ou B → ternaire {condition ? A : B}.
  • Logique complexe → calcule le rendu dans une variable, ou fais un early return, avant le return principal.
  • Ne rien afficher → return null ; et souviens-toi que false/null/undefined ne produisent aucun nœud.
