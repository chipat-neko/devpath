Module 01 · Composants & JSX — Leçon 01

Premier composant & JSX

~35 min Intermédiaire Bases de JavaScript requises

À la fin de cette leçon, tu sauras

  • écrire un composant React sous forme de fonction qui renvoie du JSX ;
  • appliquer les règles de JSX (élément racine unique, className, camelCase, balises auto-fermées) ;
  • insérer des valeurs JavaScript dans le rendu grâce aux accolades ;
  • afficher un composant dans un autre et anticiper le passage de props.
Sommaire de la leçon

Tu connais déjà JavaScript : les fonctions, les variables, les expressions. React s'appuie exactement sur ces briques. Dans cette leçon, tu vas écrire ton tout premier composant et comprendre ce qu'est JSX, cette syntaxe qui ressemble à du HTML mais qui vit à l'intérieur du JavaScript.

L'objectif est concret : à la fin, tu sauras décrire un morceau d'interface comme une fonction réutilisable, y glisser des valeurs calculées, et l'afficher à l'écran. On avance un concept à la fois, du connu (une fonction qui renvoie une valeur) vers l'inconnu (cette valeur décrit une interface).

L'idée de React

Sans bibliothèque, mettre à jour une page revient à manipuler le DOM à la main : document.createElement, appendChild, modifier textContent… C'est verbeux et vite ingérable quand l'interface grandit.

React renverse l'approche. Tu ne décris plus les étapes pour modifier le DOM ; tu décris à quoi l'interface doit ressembler, sous forme de petits blocs appelés composants. React se charge ensuite de mettre le DOM à jour pour qu'il corresponde à ta description. Un composant est réutilisable : tu l'écris une fois, tu l'affiches autant de fois que nécessaire.

Note

Retiens cette phrase : tu décris, React met à jour. C'est le changement de mentalité le plus important du cours. Tout le reste en découle.

Un composant = une fonction

Un composant React, dans sa forme la plus simple, est une fonction JavaScript qui renvoie du JSX. Regarde :

Décortiquons pas à pas :

  • function Salutation() : une fonction normale, sans paramètre pour l'instant.
  • return <h1>Bonjour</h1>; : au lieu de renvoyer un nombre ou une chaîne, elle renvoie un élément qui ressemble à du HTML.

Un détail capital : le nom commence par une majuscule. Salutation, pas salutation. C'est cette majuscule qui dit à React « ceci est un composant », et non une simple balise HTML. On revient sur ce piège plus bas.

JSX, c'est quoi ?

Le <h1>Bonjour</h1> écrit en plein milieu du JavaScript, c'est du JSX. Ce n'est ni une chaîne de caractères, ni du vrai HTML : c'est une syntaxe qui ressemble au HTML mais que ton outil de build (Babel) transforme en appels JavaScript classiques.

Tu n'as pas à écrire React.createElement toi-même : le JSX est juste une façon plus lisible d'exprimer la même chose. Mais le savoir aide à comprendre les règles qui suivent.

Les règles de JSX

Comme le JSX devient du JavaScript, il obéit à quelques règles strictes. Les voici, avec un exemple correct pour chacune.

1. Un seul élément racine. Une fonction renvoie une seule valeur ; ton JSX doit donc avoir un seul élément parent. Si tu as plusieurs éléments côte à côte, enveloppe-les dans un fragment <>…</>, qui regroupe sans ajouter de balise dans le DOM.

2. className au lieu de class. En JavaScript, class est un mot réservé. JSX utilise donc className pour l'attribut de classe CSS.

3. Attributs en camelCase. Les attributs HTML composés s'écrivent en camelCase : htmlFor (et non for), tabIndex, onClick…

4. Balises auto-fermées. Les éléments sans contenu doivent se fermer eux-mêmes : <img />, <br />, <input />. Le / final est obligatoire.

Astuce

Quand ton JSX tient sur plusieurs lignes, entoure-le de parenthèses après le return. Ça évite un piège classique du JavaScript : un ; inséré automatiquement juste après return, qui renverrait undefined.

Insérer du JavaScript avec les accolades

Le JSX devient vraiment utile quand on y injecte des valeurs dynamiques. Pour cela, on utilise des accolades { } : tout ce qui est entre accolades est une expression JavaScript dont React affiche le résultat.

Le mot clé est expression : quelque chose qui produit une valeur. Une variable, un calcul, un appel de fonction, un opérateur ternaire — tout cela fonctionne. En revanche, une instruction comme if ou for ne produit pas de valeur : elle n'a pas sa place entre accolades (on verra plus tard comment contourner ça avec des ternaires ou map).

Afficher un composant

Une fois ton composant écrit, tu l'affiches comme une balise, en utilisant son nom : <Salutation />. Tu peux ainsi composer une interface en imbriquant des composants les uns dans les autres.

Ici, App affiche deux fois Salutation sans dupliquer son code : c'est tout l'intérêt de la réutilisation. Pour que ce composant racine apparaisse dans la page, on l'attache une seule fois au DOM, généralement ainsi : createRoot(document.getElementById("root")).render(<App />). On approfondira ce point dédié au rendu dans une leçon ultérieure.

Pièges fréquents

Piège fréquent

Écrire class au lieu de className. C'est l'erreur la plus courante en arrivant du HTML. Pense aussi à htmlFor à la place de for.

  • Plusieurs éléments racines. return <h1>…</h1><p>…</p>; échoue : enveloppe le tout dans un fragment <>…</>.
  • Nom de composant en minuscule. <salutation /> est interprété par React comme une balise HTML inconnue, pas comme ton composant. Mets toujours une majuscule : <Salutation />.
  • Mettre une instruction entre accolades. { if (x) … } ou { for (…) … } ne marchent pas : les accolades attendent une expression. Utilise un ternaire { x ? a : b }.
  • Un return seul sur sa ligne. Si tu écris return puis le JSX à la ligne suivante sans parenthèses, JavaScript insère un ; juste après return et la fonction renvoie undefined. Ouvre une parenthèse ( sur la même ligne que return.

Pour aller plus loin

Pour aller plus loin

Le JSX est du « sucre syntaxique » : un outil (Babel) le compile en appels React.createElement. Et un bon composant doit être pur : avec les mêmes props, il produit toujours le même rendu, sans effet de bord. Cette pureté est ce qui permet à React d'optimiser les mises à jour en toute confiance.

Cas réel

Sur une vraie application, un même composant <Bouton> est affiché des centaines de fois : connexion, panier, réglages… Les équipes de Meta, GitHub ou Airbnb maintiennent des design systems (des bibliothèques de composants) où chaque bouton, champ ou carte est écrit une seule fois, puis réutilisé partout. Corriger un défaut d'accessibilité dans ce seul composant le corrige d'un coup dans toute l'application : c'est tout le retour sur investissement de la réutilisation.

Antisèche

Glossaire

Composant
Fonction JavaScript au nom capitalisé qui renvoie du JSX décrivant un morceau d'interface ; réutilisable autant de fois que voulu.
JSX
Syntaxe proche du HTML, écrite au milieu du JavaScript, compilée en appels React.createElement.
Élément React
Objet léger produit par le JSX, décrivant ce qu'il faut afficher (type, props, enfants). Ce n'est ni du HTML, ni une chaîne.
Rendu (render)
Opération par laquelle React transforme tes composants en nœuds réels du DOM affichés à l'écran.
Fragment
Balise vide <>…</> qui regroupe plusieurs éléments sans ajouter de nœud dans le DOM.
Accolades JSX
Les { } qui insèrent une expression JavaScript (une valeur) dans le rendu.
Déclaratif
Style où l'on décrit le résultat voulu (le « quoi ») plutôt que les étapes (le « comment ») ; React s'occupe des étapes.
props
Données passées d'un composant parent à un enfant pour le personnaliser (détaillé à la leçon suivante).

Récap et vérification

  • Un composant est une fonction au nom capitalisé qui renvoie du JSX.
  • Le JSX ressemble au HTML mais est compilé en JavaScript : une seule racine, className, camelCase, balises auto-fermées.
  • Les accolades { } insèrent une expression JavaScript dans le rendu.
  • On affiche un composant avec <NomDuComposant />, et on lui passera des props pour le personnaliser.

Vérifie ta compréhension

  1. Pourquoi le nom d'un composant doit-il commencer par une majuscule ?
  2. Que faire quand ton composant doit renvoyer deux éléments côte à côte ?
  3. Quelle différence entre une expression et une instruction vis-à-vis des accolades { } en JSX ?
