Module 08 · React en pratique — Leçon 23

Des formulaires robustes

~36 min Intermédiaire Leçon 8 recommandée

À la fin de cette leçon, tu sauras

  • distinguer un champ contrôlé d'un champ non contrôlé et choisir le bon ;
  • lire un formulaire avec FormData et l'API action de React 19 ;
  • suivre l'état d'envoi avec useActionState et useFormStatus ;
  • valider en couches (navigateur, schéma, serveur) et situer React Hook Form.
Sommaire de la leçon

En leçon 8, tu as appris les champs contrôlés : chaque frappe met à jour un état, et l'<input> reflète cet état. C'est précis et pratique pour un petit formulaire. Mais sur un formulaire de vingt champs, faire re-rendre tout le composant à chaque touche devient lourd, et le code se remplit de useState. Cette leçon montre les autres outils du terrain : les champs non contrôlés, l'API action de React 19, et une validation solide.

Contrôlé ou non contrôlé ?

Un champ contrôlé a sa valeur pilotée par React (value={x} + onChange). La source de vérité, c'est l'état React. Un champ non contrôlé laisse le DOM garder sa propre valeur ; on la lit seulement quand on en a besoin (à l'envoi), via une ref ou via FormData.

Note le passage de value à defaultValue : un champ non contrôlé fixe seulement sa valeur initiale, puis laisse l'utilisateur (et le DOM) faire le reste.

Le bon réflexe : contrôlé quand tu as besoin de la valeur pendant la saisie (activer un bouton, filtrer une liste, valider en direct, formater) ; non contrôlé quand tu ne veux la valeur qu'à l'envoi — c'est plus léger et souvent suffisant.

Lire tout le formulaire d'un coup : FormData

Plutôt qu'une ref par champ, on peut lire tout le formulaire avec l'objet natif FormData, qui récupère chaque champ par son attribut name. C'est du HTML standard, indépendant de React.

L'API action de React 19

React 19 simplifie encore : on passe une fonction directement à <form action={…}>. React appelle cette fonction avec le FormData du formulaire, réinitialise le formulaire en cas de succès, et gère l'attente. Plus besoin de onSubmit ni de preventDefault.

Pour afficher l'état d'envoi (attente, message d'erreur, succès), React 19 fournit useActionState : il enveloppe l'action et renvoie l'état courant plus un booléen isPending.

Le bouton connaît l'attente

Un sous-composant bouton peut lire l'état d'envoi du formulaire parent avec useFormStatus() : const { pending } = useFormStatus();. Pratique pour un <BoutonEnvoi> réutilisable qui se désactive tout seul pendant l'envoi, sans qu'on lui passe de prop.

Valider en couches

Une validation robuste se joue à trois niveaux, du plus rapide au plus sûr. Chacun a un rôle ; aucun ne remplace les autres.

Piège fréquent

Faire confiance à la validation client. Un utilisateur peut désactiver JavaScript, modifier le HTML ou appeler ton API directement. La validation navigateur et le schéma améliorent l'expérience ; ils ne sécurisent rien. Revalide toujours côté serveur avant d'écrire en base.

Cas réel

Sur un tunnel de paiement, une équipe avait tout géré en champs contrôlés : à chaque frappe dans le formulaire de carte (une quinzaine de champs), toute la page se re-rendait, avec une saisie qui « laggait » sur mobile. Le passage à React Hook Form — qui garde les champs non contrôlés et ne re-rend que ce qui change — a supprimé les à-coups. Couplé à un schéma Zod partagé entre le client et le serveur, le même jeu de règles valide des deux côtés : messages instantanés pour l'utilisateur, garantie finale côté serveur.

Les bibliothèques : React Hook Form

Pour les formulaires ambitieux (beaucoup de champs, validation fine, tableaux de champs dynamiques), on s'appuie sur une bibliothèque dédiée. La référence est React Hook Form : elle garde les champs non contrôlés (donc rapides), branche un schéma de validation, et expose les erreurs prêtes à afficher.

Pour aller plus loin

Explore useOptimistic (React 19) pour afficher tout de suite le résultat attendu d'un envoi avant la confirmation serveur, les resolvers qui branchent Zod sur React Hook Form, et l'accessibilité des erreurs (aria-invalid, aria-describedby) — c'est justement le sujet de la leçon suivante.

Glossaire

Champ contrôlé
Champ dont la valeur est pilotée par l'état React (value + onChange) ; React est la source de vérité.
Champ non contrôlé
Champ dont le DOM garde la valeur ; on la lit à la demande via une ref ou FormData, avec defaultValue pour l'initial.
FormData
Objet natif du navigateur qui collecte les champs d'un formulaire par leur attribut name (data.get("email")).
action (React 19)
Fonction passée à <form action={…}> ; React l'appelle avec le FormData, gère l'attente et réinitialise le formulaire.
useActionState
Hook React 19 qui enveloppe une action et renvoie l'état courant, la fonction d'action et un booléen isPending.
useFormStatus
Hook lu par un sous-composant (bouton) pour connaître l'état d'envoi du formulaire parent (pending).
Schéma (Zod)
Description déclarative des règles de validation ; safeParse renvoie les données validées ou les erreurs par champ.
React Hook Form
Bibliothèque de gestion de formulaires fondée sur des champs non contrôlés ; performante sur les grands formulaires, avec validation intégrée.

Récap et vérification

  • Contrôlé = état React à chaque frappe (valeur utile pendant la saisie) ; non contrôlé = le DOM garde la valeur, lue à l'envoi.
  • FormData lit tout le formulaire par name ; React 19 passe ce FormData à la fonction action.
  • useActionState donne l'état et isPending ; useFormStatus renseigne un bouton enfant.
  • Valide en couches (navigateur, schéma, serveur) : seule la couche serveur protège vraiment.
