Génériques et extensions

~50 min Avancé Prérequis : leçon 8

À la fin de cette leçon, tu sauras

  • savoir écrire une fonction et un type génériques (func premier<T>, struct Pile<Element>)
  • savoir poser des contraintes de type (<T: Comparable>, clause where) et lire un associatedtype
  • savoir étendre un type existant avec une extension, y compris conditionnelle (extension Array where Element: Numeric)
  • comprendre pourquoi la généricité bat Any et comment Collection en est bâtie .
Sommaire de la leçon

Tu sais déjà écrire une fonction qui trouve le premier élément d'un tableau d'entiers. Mais si tu en veux une pour les String, une autre pour les Double… tu copies-colles. Les génériques règlent ce problème une fois pour toutes : tu écris l'algorithme une seule fois, en laissant le type « en blanc », et le compilateur le remplit pour chaque usage — sans jamais rien sacrifier sur la sûreté des types.

Dans cette leçon, on construit des fonctions et des types génériques, on apprend à les contraindre pour les rendre plus puissants, on survole les associatedtype des protocoles, puis on ajoute du comportement à des types existants (oui, même Int) avec les extensions. Tout cela, c'est exactement la mécanique sur laquelle est bâtie la bibliothèque standard de Swift.

Une fonction générique : écrire une fois, réutiliser partout

Le paramètre de type se déclare entre chevrons juste après le nom. Par convention on l'appelle T (pour Type) quand il n'a pas de rôle plus précis.

Une seule définition, et elle marche pour [Int], [String], [Double]… Le compilateur déduit T à partir de l'argument : pas besoin d'écrire premier<Int>(...). Le retour est T? car un tableau vide n'a pas de premier élément.

Note

Passer un optionnel directement à print déclenche un avertissement « expression implicitly coerced from 'Int?' to 'Any' ». Normal : print attend de l'Any, et Swift préfère que tu sois explicite sur la présence éventuelle d'un nil. Dans du vrai code, déballe d'abord (avec if let, guard let ou ??) ; ici on imprime l'optionnel tel quel juste pour voir sa forme.

Génériques vs Any : la sûreté gagne

On pourrait croire que [Any] ferait le même travail. Faux : Any efface le type, donc tu dois le récupérer à la main et tu peux te tromper.

La version générique conserve l'information : premier(de: [10, 20]) rend un vrai Int?, vérifié à la compilation. Any repousse les erreurs à l'exécution ; les génériques les attrapent avant, et te dispensent de tout as? hasardeux.

Un type générique : struct Pile<Element>

Les types aussi se paramètrent. Voici une pile (LIFO, dernier entré premier sorti). Ici on nomme le paramètre Element, plus parlant que T — c'est le style de la stdlib.

On a choisi une struct (un value type) : copier une pile la duplique vraiment, sans partage caché. C'est pour cela que les méthodes qui modifient le contenu sont marquées mutating. À l'usage, Pile<Int>() fixe Element = Int une bonne fois : y empiler une String serait refusé à la compilation.

Contraindre le type : <T: Comparable>

Un générique non contraint ne sait rien faire de ses valeurs : il ne peut pas les comparer, les additionner, ni même tester l'égalité. Pour débloquer une opération, tu exiges que T respecte un protocole.

T: Comparable se lit « T est n'importe quel type, à condition qu'il sache se comparer avec < ». La contrainte n'enferme pas le code, elle l'autorise à faire plus.

Contraindre une méthode : la clause where

Tu peux aussi contraindre une seule méthode d'un type générique, sans contraindre tout le type. Ici Pile reste utilisable avec n'importe quel Element, mais contient(_:) n'apparaît que si l'élément est Equatable.

La clause where exprime des conditions sur les paramètres de type. C'est l'outil clé de la généricité conditionnelle : un même type offre des capacités différentes selon ce qu'on y range.

Les associatedtype dans un protocole (survol)

Un protocole peut lui aussi avoir un « type en blanc », déclaré avec associatedtype. Le type conforme choisit ce que ce blanc vaut. C'est ainsi qu'est pensé un conteneur générique.

On ne déclare jamais Item explicitement : Swift le déduit (ici Item = String) à partir des signatures. Les associatedtype sont la version « protocole » des paramètres génériques — retiens surtout qu'ils existent et qu'ils rendent un protocole réutilisable pour n'importe quel type d'élément.

Les extensions : ajouter à un type existant

Une extension greffe méthodes, propriétés calculées et conformités sur un type déjà écrit — y compris ceux de la stdlib que tu ne possèdes pas, comme Int ou String.

Une extension ne peut pas ajouter de propriété stockée (pas de nouvelle case mémoire), mais les propriétés calculées et les méthodes sont libres. C'est l'outil idéal pour organiser ton code par thème plutôt que d'entasser tout dans une déclaration géante.

Extension conditionnelle : where Element: Numeric

On peut n'étendre un type générique que sous condition. Cette extension n'ajoute somme aux tableaux que lorsque leurs éléments sont numériques.

C'est exactement ce que fait la stdlib : Collection est un protocole générique, et des dizaines de méthodes (map, filter, reduce, sorted…) sont ajoutées par extensions, parfois conditionnelles. Quand tu écris [3, 1, 2].sorted(), tu utilises une extension de Sequence disponible uniquement parce que Int est Comparable — le même mécanisme que ci-dessus.

Cas réel

Tu utilises ce mécanisme à chaque ligne de Swift, sans y penser. Array<Element>, Set<Element> et Dictionary<Key, Value> sont des struct génériques de la bibliothèque standard. Leurs méthodes sont greffées par extensions conditionnelles : [3, 1, 2].sorted() ne fonctionne que parce que Int est Comparable ; sur un tableau d'un type non ordonné, sorted() n'apparaît même pas dans l'autocomplétion de Xcode. Les génériques et les extensions ne sont pas un sujet « avancé » réservé aux experts : c'est le tissu même du langage.

Note

Les opaque types (some) sont une autre facette : func faire() -> some Collection promet « un type concret précis, mais je ne te dis pas lequel ». Tu en croiseras partout en SwiftUI (var body: some View) — on y revient dans le module dédié.

Pièges fréquents

Piège fréquent

Appeler une opération sans la contrainte qui la rend légale. func tri<T>(_ t: [T]) -> [T] { t.sorted() } ne compile pas : il faut <T: Comparable>. Le message d'erreur te dit exactement quel protocole manque — lis-le, il nomme la contrainte à ajouter.

Piège fréquent

Vouloir ajouter une propriété stockée dans une extension : extension Int { var compteur = 0 } → error: extensions must not contain stored properties. Seules les propriétés calculées et les méthodes sont permises.

Pour aller plus loin

Pour aller plus loin

Explore comment la stdlib enchaîne Sequence → Collection → BidirectionalCollection → RandomAccessCollection : chaque protocole ajoute des garanties (et donc des méthodes) via associatedtype et extensions conditionnelles. Regarde aussi les generic where clauses sur les protocoles et le mot-clé some côté paramètre (func f(_ x: some Collection)), forme courte d'un générique contraint.

Glossaire

Générique
Code paramétré par un ou plusieurs types laissés « en blanc » (<T>, <Element>), remplis à l'usage.
Paramètre de type
Le nom symbolique (T, Element) qui tient lieu de type réel dans une définition générique.
Inférence de type
Déduction automatique du type concret par le compilateur à partir des arguments, sans l'écrire.
Contrainte de type
Exigence T: Protocole qui autorise sur T les opérations garanties par ce protocole.
Clause where
Condition sur les paramètres de type, appliquée à une méthode ou une extension précise.
associatedtype
Paramètre générique d'un protocole ; le type conforme choisit sa valeur concrète.
Extension
Ajout de méthodes, propriétés calculées, initialiseurs ou conformités à un type déjà existant.
Extension conditionnelle
Extension d'un type générique restreinte par where : n'ajoute ses membres que pour certains éléments.

Récap et vérification

  • Un générique (<T>, <Element>) écrit l'algorithme une fois en gardant le type intact — contrairement à Any qui l'efface.
  • Les fonctions et les types peuvent être génériques ; le compilateur déduit le type à l'appel.
  • Une contrainte (T: Comparable, clause where Element: Equatable) débloque les opérations qu'autorise un protocole.
  • Un associatedtype est le « type en blanc » d'un protocole, déduit par le type conforme.
  • Une extension ajoute méthodes et propriétés calculées à un type existant ; conditionnelle (where), elle reproduit la façon dont Collection est bâtie.
