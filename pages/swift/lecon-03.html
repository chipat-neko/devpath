Module 1 · Les bases de Swift — Leçon 03

Conditions, boucles et switch

~44 min Débutant Prérequis : leçon 2

À la fin de cette leçon, tu sauras

  • savoir écrire des conditions avec if/else et déballer un optionnel avec if let
  • savoir utiliser guard pour valider tôt et faire un early return
  • savoir exploiter la puissance de switch : exhaustivité, intervalles, tuples, where et value binding
  • savoir parcourir des données avec for-in, les ranges, stride, while et repeat-while .
Sommaire de la leçon

Tu sais déjà ce qu'est une condition ou une boucle dans un autre langage. En Swift, ces structures de contrôle existent bien sûr, mais elles sont taillées pour la sûreté et l'expressivité : le compilateur t'oblige à traiter tous les cas, t'aide à déballer les optionnels au bon endroit, et te pousse à sortir tôt d'une fonction quand quelque chose ne va pas. Tu vas aussi rencontrer un switch bien plus puissant que celui que tu connais sans doute.

Fil rouge de cette leçon : on classe des notes (de 0 à 20) en mentions. On commencera par un if, puis on verra comment switch rend ce genre de code à la fois plus court et plus sûr. À la fin, tu sauras choisir la bonne structure selon la situation.

if / else : la condition de base

Le if de Swift ressemble à ce que tu connais, avec deux différences : pas de parenthèses obligatoires autour de la condition, et les accolades sont obligatoires même pour une seule instruction. La condition doit être un vrai Bool — pas un entier, pas un optionnel « truthy ».

Tu combines les conditions avec && (et), || (ou) et ! (non). Les comparaisons usuelles sont là : <, >, <=, >=, ==, !=.

if let : déballer un optionnel en sécurité

Un optionnel (Int?, String?…) contient soit une valeur, soit nil. Pour t'en servir, tu dois le déballer (unwrap). Le if let fait exactement ça : si l'optionnel contient une valeur, il la lie à une nouvelle constante valable dans le bloc ; sinon, on passe au else.

Note

Tu peux enchaîner plusieurs liaisons et ajouter des conditions, séparées par des virgules : if let n = Int(saisie), n >= 0 { … }. Tout doit réussir pour entrer dans le bloc.

guard : valider tôt, sortir tôt

guard est l'idiome Swift pour le early return. Il dit : « cette condition doit être vraie pour continuer ; sinon, je quitte ». Son else est obligatoire et doit interrompre le flux (return, throw, break, continue). Avantage majeur : une valeur déballée par guard let reste disponible après le bloc, contrairement à if let.

Astuce

Utilise guard pour les préconditions en début de fonction. Le « chemin heureux » reste alors à plat, peu indenté, facile à lire — au lieu d'être noyé dans des if imbriqués.

switch : exhaustif et puissant

Le switch de Swift n'a rien à voir avec celui du C. Deux règles d'or : il doit être exhaustif (tous les cas possibles couverts, sinon erreur de compilation), et il n'y a pas de fallthrough implicite — chaque case s'arrête tout seul, pas besoin de break. Un case peut matcher plusieurs valeurs séparées par des virgules.

Note

Le mot-clé fallthrough existe si tu veux vraiment tomber dans le cas suivant, mais il est rare et explicite. Par défaut, l'absence de chute évite la classe de bugs la plus courante des switch en C.

Cas réel — l'exhaustivité qui rattrape un oubli

Imagine une app qui affiche l'état d'un téléchargement, modélisé par un type à quatre cas : enAttente, enCours, terminé, échec. Partout où tu écris switch état { … } sans default, le compilateur vérifie que les quatre cas sont traités. Le jour où l'équipe ajoute un cinquième état — annulé — la compilation échoue immédiatement à chaque switch devenu incomplet (switch must be exhaustive). Au lieu d'un bug silencieux découvert en production (un écran figé sur un état non géré), tu obtiens la liste exacte des endroits à compléter, avant même de lancer l'app. C'est l'exhaustivité transformée en filet de sécurité — la raison pour laquelle on évite un default passe-partout sur un ensemble de cas fini.

switch sur des intervalles, avec where

Voici la vraie puissance : un case peut matcher un intervalle (0...9), et une clause where peut ajouter une condition au matching. C'est l'outil idéal pour notre classement de notes. Les cas sont testés dans l'ordre : le premier qui matche gagne. Comme un Int couvre potentiellement des valeurs hors barème, on les écarte d'abord, puis on traite le reste avec un cas par défaut.

Le cas let n where n >= 8 lie la valeur testée à n puis la filtre avec where : on récupère ainsi la note exacte pour l'afficher. C'est le value binding combiné au pattern matching. Comme une clause where peut être fausse, le compilateur exige ici un default pour garantir l'exhaustivité.

switch sur des tuples

Tu peux matcher plusieurs valeurs d'un coup en les regroupant dans un tuple. Le _ signifie « n'importe quelle valeur, peu importe ». C'est très lisible pour croiser deux critères.

Astuce

Ici les booléens couvrent toutes les combinaisons, donc pas besoin de default : le compilateur le constate et accepte le switch. Si tu retires un cas, il te le signalera.

Les boucles : for-in, ranges et stride

La boucle reine en Swift est for x in collection : elle parcourt directement les éléments, sans index à gérer. Pour itérer sur des nombres, tu utilises des ranges : 1...10 est un intervalle fermé (inclut 10), 1..<10 est semi-ouvert (s'arrête à 9).

Note

Swift n'a pas de boucle C for (i = 0; i < n; i++) : elle a été retirée du langage en 2016 car source d'erreurs (off-by-one, mutation de l'index). for-in sur un range ou stride couvre tous les besoins de façon plus sûre et lisible. Besoin de l'index et de l'élément ? Utilise for (i, note) in notes.enumerated().

while, repeat-while, break et continue

Quand tu ne connais pas d'avance le nombre d'itérations, while teste la condition avant chaque tour, et repeat-while la teste après (le corps s'exécute donc au moins une fois, même si la condition est fausse dès le départ). break sort de la boucle ; continue passe au tour suivant.

Pièges fréquents

Piège fréquent

Confondre ... et ..<. 0...20 inclut 20 ; 0..<20 s'arrête à 19. Pour parcourir un tableau de n éléments par index, c'est 0..<n — utiliser 0...n provoque un crash d'« index out of range » au dernier tour.

Piège fréquent

Oublier que le else d'un guard doit quitter le scope. Écrire guard x else { print("oups") } sans return ne compile pas : error: 'guard' body must not fall through, consider using a 'return' or 'throw'.

Piège fréquent

Croire qu'un switch tombe d'un case au suivant comme en C. En Swift, chaque cas s'arrête seul. Un case vide est d'ailleurs interdit : error: 'case' label in a 'switch' should have at least one executable statement — utilise break si tu veux ne rien faire.

Pour aller plus loin

Pour aller plus loin

Le switch brille surtout avec les enums et les valeurs associées, où l'exhaustivité devient un vrai filet de sécurité (tu ajoutes un cas à l'enum, le compilateur te montre tous les switch à compléter). Regarde aussi if case / for case let … where … pour faire du pattern matching hors d'un switch. On approfondira tout ça dans le module sur les enums et la modélisation des données.

Antisèche

Glossaire

Condition (Bool)
Expression qui vaut true ou false ; Swift refuse un Int ou un optionnel à sa place.
guard / early return
Valide une précondition et quitte tôt sinon ; garde le « chemin heureux » peu indenté.
Exhaustivité
Un switch doit couvrir tous les cas possibles ; sinon le compilateur refuse.
fallthrough
Chute d'un case au suivant ; implicite en C, absente par défaut en Swift.
Value binding
Lier la valeur testée à une constante dans un case : case let n where ….
Intervalle fermé / semi-ouvert
a...b inclut b ; a..<b s'arrête juste avant.
stride
Suite de nombres espacés d'un pas : stride(from: 0, through: 20, by: 5).
break / continue
Interrompre la boucle entièrement / passer directement à l'itération suivante.

Récap et vérification

  • if/else exige un vrai Bool et des accolades ; if let déballe un optionnel pour le bloc.
  • guard impose une condition et quitte tôt sinon ; sa valeur déballée survit après le bloc.
  • switch est exhaustif, sans fallthrough implicite, et accepte intervalles, tuples, where et value binding.
  • for-in parcourt collections et ranges (1...10 fermé, 1..<10 semi-ouvert) ; stride gère le pas ; pas de boucle C à trois parties.
  • while teste avant, repeat-while après (au moins un tour) ; break sort, continue saute un tour.

Vérifie ta compréhension

  1. Pourquoi if compteur { … }, où compteur est un Int, ne compile-t-il pas en Swift, et comment exprimer l'intention ?
  2. Pourquoi switch couleur { case "vert": … } sur une String exige-t-il un default, alors qu'un switch sur deux Bool peut s'en passer ?
  3. Que produit for i in 0...arr.count sur un tableau de 3 éléments, et comment corriger ?
