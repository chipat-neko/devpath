Module 2 · Collections et valeurs — Leçon 05

Tableaux, ensembles et dictionnaires

~45 min Débutant Prérequis : leçon 4

À la fin de cette leçon, tu sauras

  • savoir créer et manipuler un Array, un Set et un Dictionary avec leurs méthodes idiomatiques ;
  • savoir exploiter les accès optionnels (first, last, dico[clé]) sans crash ;
  • savoir distinguer let et var et comprendre la value semantics qui copie réellement une collection ;
  • savoir transformer une collection avec map, filter, reduce, sorted et compactMap.
Sommaire de la leçon

Jusqu'ici tu as manipulé des valeurs isolées. Mais un programme réel jongle avec des collections : une liste de scores, un panier d'articles uniques, un annuaire associant des noms à des numéros. Swift propose trois collections fondamentales, toutes des value types (types valeur) : Array pour une suite ordonnée, Set pour un ensemble d'éléments uniques, et Dictionary pour des paires clé–valeur.

Ces trois collections partagent l'ADN de Swift : la sûreté avant tout. Accéder à un élément absent ne provoque pas une valeur indéterminée ni un null silencieux — tu obtiens un optionnel que tu dois ouvrir consciemment. Et comme ce sont des types valeur, les copier les copie vraiment, ce qui élimine toute une classe de bugs sournois. Découvrons tout ça.

Le tableau : une suite ordonnée

Un Array stocke des éléments dans l'ordre, accessibles par un indice qui commence à 0. Son type s'écrit [Int] (raccourci) ou Array<Int> (forme générique complète) — les deux sont strictement équivalents.

Le type est ici annoté [Int], mais Swift l'aurait inféré tout seul à partir du littéral. On l'écrit pour la clarté pédagogique ; au quotidien, var scores = [42, 17, 88] suffit.

Piège fréquent

L'accès par indice scores[10] n'est pas optionnel : si l'indice est hors limites, ton programme s'arrête net (fatal error: Index out of range). Vérifie toujours scores.count ou les bornes avant d'indexer une position incertaine.

first et last : des accès optionnels

Quel est le premier élément d'un tableau… vide ? La question n'a pas de réponse. Plutôt que d'inventer une valeur ou de planter, Swift renvoie un optionnel : scores.first est de type Int?, qui vaut nil si le tableau est vide.

C'est cohérent avec tout Swift : dès qu'une valeur peut légitimement manquer, le type le dit. Tu déballes l'optionnel avec if let, guard let ou l'opérateur ?? (vu au chapitre sur les optionnels).

L'ensemble : l'unicité garantie

Un Set<Int> stocke des éléments uniques, sans ordre défini. Insérer un doublon ne fait rien. C'est idéal pour répondre à « cet élément est-il présent ? » (le test contains y est très rapide) et pour les opérations d'ensemble mathématiques.

Note l'annotation Set<Int> : elle est obligatoire ici, car le littéral [1, 2, 3] serait sinon inféré comme un Array. Le type lève l'ambiguïté.

Le dictionnaire : associer clés et valeurs

Un Dictionary associe des clés à des valeurs. Son type s'écrit [String: Int] : ici, des noms (clés String) vers des âges (valeurs Int).

Point crucial : l'accès ages["Alice"] renvoie un optionnel Int?, car la clé peut être absente. C'est le même principe de sûreté que first.

La syntaxe dico[clé, default: valeur] est précieuse : elle te donne un Int non optionnel directement, parfait pour compter ou accumuler.

Modifier, parcourir, lister un dictionnaire

Au-delà de l'indexation, le dictionnaire offre des méthodes explicites et des vues sur ses clés et ses valeurs.

Note

Ni le Set ni le Dictionary ne garantissent un ordre de parcours. Ne t'appuie jamais dessus : si tu as besoin d'un ordre, trie explicitement avec sorted() ou utilise un Array.

let, var et la value semantics

Comme partout en Swift, let rend la collection immuable et var la rend mutable. Sur un let, ni append, ni l'écriture par indice, ni insert ne compilent.

Mais voici le point le plus important du chapitre, propre aux types valeur. Copier une collection en crée une copie indépendante. Modifier la copie ne touche jamais l'original. Dans un langage à références (Python, Java, JavaScript), le code ci-dessous produirait un bug ; en Swift, il fait exactement ce à quoi on s'attend.

Cette garantie vaut pour Array, Set et Dictionary (et aussi les struct que tu verras plus tard). Tu peux passer une collection à une fonction sans craindre qu'elle modifie ta donnée d'origine — elle ne reçoit qu'une copie. Sous le capot, Swift optimise avec une stratégie « copie à l'écriture » (copy-on-write) : la copie physique n'a lieu qu'au moment d'une modification, donc tu paies le coût uniquement quand c'est nécessaire.

Cas réel — le bug d'aliasing que Swift supprime

Dans un langage à références comme Python ou JavaScript, ce grand classique a piégé tous les développeurs : on récupère le panier d'un utilisateur, on en fait une « copie » pour simuler une promotion — simulation = panier — puis on modifie simulation… et le vrai panier change aussi, car les deux variables désignaient le même objet. Le bug se manifeste souvent loin de sa cause, à l'affichage, et coûte des heures de débogage. En Swift, Array, Set et Dictionary sont des types valeur : simulation = panier crée une copie réellement indépendante, et modifier l'une ne touche jamais l'autre. Toute cette catégorie de bugs disparaît par construction — la même philosophie que les optionnels face au nil. C'est aussi ce qui rend SwiftUI fiable, où chaque vue est une struct copiée plutôt que partagée.

Transformer : map, filter, reduce et compagnie

Plutôt que des boucles manuelles, Swift privilégie des transformations déclaratives. Elles renvoient une nouvelle collection (cohérent avec la value semantics) et se lisent comme une phrase. Le $0 désigne l'élément courant.

compactMap brille avec les optionnels : Int("abc") vaut nil (la conversion échoue), et compactMap jette automatiquement ces nil, te rendant un [Int] propre plutôt qu'un [Int?]. Ces méthodes se chaînent : nombres.filter { $0 % 2 == 0 }.map { $0 * 10 } filtre puis transforme.

Astuce

reduce(0, +) est encore plus court que reduce(0) { $0 + $1 } : on passe directement l'opérateur + comme fonction. Idiomatique et lisible pour les sommes et produits.

Pièges fréquents

  • Confondre accès optionnel et accès direct. dico[clé] et tableau.first sont optionnels ; tableau[indice] ne l'est pas et plante hors limites. Deux mécanismes à ne pas mélanger.
  • Oublier l'annotation d'un Set. let s = [1, 2, 3] crée un Array, pas un Set. Sans Set<Int>, tu n'auras ni l'unicité ni union.
  • Compter sur l'ordre d'un Set ou d'un Dictionary. Il n'existe pas. Trie explicitement si l'ordre compte.
  • Croire qu'une copie partage la donnée. Réflexe venu des langages à références : en Swift, copie = original est indépendant. Inutile de cloner manuellement.
  • Muter un let. append sur une constante ne compile pas. Choisis var dès que tu prévois de modifier.

Glossaire

Array
Suite ordonnée d'éléments accessibles par un indice à partir de 0.
Set
Ensemble d'éléments uniques, sans ordre ; test d'appartenance rapide.
Dictionary
Association de clés à des valeurs : [String: Int].
Accès optionnel
.first, dico[clé] renvoient un optionnel car la valeur peut manquer.
Type valeur / value semantics
Copier la donnée la copie vraiment ; pas de partage caché.
Copy-on-write
Optimisation : la copie physique n'a lieu qu'à la première modification.
Hashable
Capacité d'un type à servir de clé de Dictionary ou d'élément de Set.
compactMap
Transforme chaque élément et écarte les résultats nil.

Récap et vérification

  • Array ([Int]) : ordonné, indexé dès 0 ; append, insert(_:at:), remove(at:), count, contains.
  • first et last renvoient un optionnel — à déballer ; tableau[indice] plante hors limites.
  • Set<Int> : éléments uniques, union, intersection, subtracting ; annotation obligatoire.
  • Dictionary ([String: Int]) : dico[clé] est optionnel, dico[clé, default:] ne l'est pas ; updateValue, removeValue, keys, values.
  • let = immuable, var = mutable ; value semantics : une copie est réellement indépendante.
  • map, filter, reduce, sorted, compactMap renvoient une nouvelle collection.

Vérifie ta compréhension

  1. Pourquoi monTableau.first est-il de type Int? et non Int ?
  2. Quelle différence de résultat entre dico["x"] et dico["x", default: 0] quand la clé "x" est absente ?
  3. Après var b = a; b.append(9) sur des tableaux, que contient a et pourquoi ?
