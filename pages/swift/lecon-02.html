Module 1 · Les bases de Swift — Leçon 02

Types, chaînes et optionnels

~45 min Débutant Prérequis : leçon 1

À la fin de cette leçon, tu sauras

  • savoir utiliser les types fondamentaux de Swift (Int, Double, Bool, String, Character) et convertir explicitement entre eux
  • savoir manipuler les chaînes avec l'interpolation \(…), le multilignes et les méthodes courantes
  • savoir déclarer et déballer un optionnel avec if let, guard let et ?? ;
  • savoir reconnaître les pièges du déballage forcé ! et privilégier un déballage sûr.
Sommaire de la leçon

Dans la leçon précédente, tu as écrit tes premières lignes de Swift et découvert let et var. Place maintenant aux briques de base de tout programme : les types. Swift est un langage à typage statique et fort, ce qui veut dire que chaque valeur a un type connu à la compilation, et que ce type ne ment jamais. C'est exactement cette rigueur qui fait la réputation de sûreté de Swift.

Tu vas voir les types fondamentaux, la manipulation des chaînes (un domaine où Swift est particulièrement expressif), puis le concept central du langage : les optionnels. Si tu retiens une seule idée de cette leçon, que ce soit celle-ci : en Swift, c'est le type lui-même qui te dit si une valeur peut être absente.

Les types fondamentaux

Swift fournit un petit ensemble de types de base que tu utiliseras partout. Le compilateur les infère le plus souvent, mais tu peux toujours les écrire explicitement avec une annotation : Type.

Note qu'un littéral entier comme 3 devient un Int, et qu'un littéral avec un point décimal comme 19.5 devient un Double. Swift privilégie Double (64 bits) plutôt que Float pour les flottants : utilise Double par défaut.

Note

Le type Int s'adapte à l'architecture (64 bits sur les machines modernes). Il existe aussi Int8, UInt, etc., mais tu n'en as quasiment jamais besoin : utilise Int par défaut, même pour des valeurs qui ne seront jamais négatives.

Pas de conversion implicite

Voici un point qui surprend les gens venant de C, JavaScript ou Python : Swift n'effectue jamais de conversion numérique automatique. Tu ne peux pas additionner un Int et un Double directement. C'est volontaire : une conversion implicite peut perdre de la précision ou cacher un bug, alors Swift t'oblige à l'écrire.

Les conversions s'écrivent comme un appel : Double(x), Int(y), String(n). Ce sont des initialiseurs de type — tu construis une nouvelle valeur du type cible à partir d'une valeur source. Retiens que Int(3.99) tronque vers zéro, il n'arrondit pas.

Les chaînes et l'interpolation

L'interpolation de chaînes est l'idiome central pour composer du texte en Swift. Tu insères n'importe quelle expression dans une chaîne avec la syntaxe \(expression). C'est lisible, sûr (le type est vérifié) et bien plus agréable que la concaténation à coups de +.

Dans une chaîne multilignes """…""", les sauts de ligne réels sont conservés, et l'indentation est calée sur celle des guillemets de fermeture. C'est parfait pour des gabarits de texte ou du JSON lisible.

Les optionnels : le concept clé

On y est. En Swift, une variable ne peut pas contenir « rien » (l'absence de valeur) à moins que son type ne le permette explicitement. Un type normal comme String contient toujours une chaîne valide. Pour autoriser l'absence, on ajoute un ? : String? se lit « optionnel de String », et il peut valoir soit une chaîne, soit nil (l'absence).

La différence avec le null des autres langages est fondamentale. Ailleurs, n'importe quelle référence peut être nulle, et tu découvres le problème au moment du plantage à l'exécution. En Swift, le type lui-même dit si nil est possible. Le compilateur t'oblige à traiter le cas nil avant d'utiliser la valeur : les fameuses erreurs de pointeur nul deviennent quasi impossibles.

Cas réel — « l'erreur à un milliard de dollars »

En 2009, Tony Hoare — l'informaticien qui a introduit la référence null en 1965 — a publiquement qualifié son invention d'« erreur à un milliard de dollars ». Son raisonnement : parce que n'importe quelle référence pouvait être nulle, des générations de programmes ont planté sur des NullPointerException, des segfaults et des pannes en production, pour un coût cumulé colossal. Les optionnels de Swift sont une réponse directe à ce problème : en rendant l'absence visible dans le type (String vs String?), le compilateur t'empêche d'utiliser une valeur potentiellement absente sans l'avoir traitée. Toute une catégorie de plantages historiques disparaît — non par discipline du programmeur, mais par construction du langage.

Déballer un optionnel en sécurité

« Déballer » (unwrap), c'est extraire la valeur d'un optionnel en gérant le cas nil. Voici les outils, du plus courant au plus situationnel.

Le guard let est l'autre grand outil. Il sert au retour anticipé (early return) : on déballe en début de fonction, et si c'est nil on sort tout de suite. Avantage : la valeur déballée reste utilisable dans tout le reste de la fonction, sans imbrication.

Une bonne intuition : if let quand tu veux faire quelque chose dans le cas où la valeur existe ; guard let quand l'absence de valeur doit interrompre la suite.

Le déballage forcé, et pourquoi l'éviter

Il existe un raccourci : le point d'exclamation ! force le déballage. Mais si l'optionnel vaut nil, le programme plante. C'est un crash assumé, à réserver aux cas où tu as la certitude absolue que la valeur est présente.

Piège fréquent

Le ! est tentant parce qu'il fait taire le compilateur. Mais chaque ! est un plantage potentiel que tu signes. Règle saine : si tu écris un !, demande-toi si un if let, un guard let ou un ?? ne serait pas plus sûr. La réponse est presque toujours oui.

Tuples et typealias

Un tuple regroupe plusieurs valeurs en une seule, sans définir de type dédié. Pratique pour renvoyer deux choses d'une fonction ou décomposer un couple de coordonnées.

Les tuples sont parfaits pour un petit regroupement local et ponctuel. Dès qu'une structure de données prend de l'importance ou circule dans ton code, préfère une struct (qu'on verra bientôt) : elle nomme ses champs et porte un vrai type.

Pièges fréquents

  • Oublier qu'un optionnel n'est pas sa valeur. surnom.count ne compile pas si surnom est un String? ; il faut d'abord le déballer.
  • Confondre troncature et arrondi. Int(3.99) donne 3, pas 4. Pour arrondir, utilise (3.99).rounded() qui donne 4.0.
  • Abuser du !. Chaque déballage forcé est un crash en puissance.
  • Attendre une conversion numérique automatique. Int + Double ne compile pas : convertis explicitement avec Double(...).

Glossaire

Typage fort
Chaque valeur a un type fixe ; aucune conversion automatique entre types (ex. Int + Double refusé).
Interpolation
Insérer une expression dans une chaîne avec \(…) ; le type est vérifié à la compilation.
Optionnel
Type suffixé de ? qui autorise l'absence de valeur ; il vaut une valeur ou nil.
nil
L'absence de valeur ; ne peut être stockée que dans un type optionnel.
Déballage (unwrap)
Extraire la valeur d'un optionnel en gérant le cas nil.
if let / guard let
Déballage sûr : exécuter un bloc si la valeur existe / sortir de la fonction si elle est absente.
Nil-coalescing (??)
Fournit une valeur de repli quand l'optionnel vaut nil : saisie ?? "Anonyme".
Tuple
Regroupe plusieurs valeurs en une, sans définir de type dédié : (x: 3, y: 7).

Récap et vérification

  • Les types fondamentaux : Int, Double, Bool, String, Character, inférés ou annotés.
  • Aucune conversion implicite : convertis avec Double(...), Int(...) ; Int(...) tronque.
  • L'interpolation \(...) compose le texte ; """…""" pour le multilignes ; méthodes count, uppercased(), hasPrefix, contains.
  • Un optionnel T? vaut une valeur ou nil ; le type dit si l'absence est possible.
  • Déballe en sécurité avec if let, guard let, ??, ?. ; évite le !.
  • Un tuple regroupe des valeurs ; typealias nomme un type existant.
