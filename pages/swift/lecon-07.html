Module 2 · Collections et valeurs — Leçon 07

Énumérations et pattern matching

~50 min Intermédiaire Prérequis : leçon 6

À la fin de cette leçon, tu sauras

  • savoir déclarer un enum avec cas simples, valeurs brutes et valeurs associées
  • savoir faire un switch exhaustif qui extrait les valeurs associées d'un cas
  • savoir ajouter méthodes, propriétés calculées et CaseIterable à un enum pour modéliser un état ;
  • comprendre que Optional est lui-même un enum à deux cas some et none.
Sommaire de la leçon

Dans beaucoup de langages, une énumération n'est qu'une liste de constantes nommées : une façon élégante d'écrire 0, 1, 2. En Swift, l'enum est tout autre chose. C'est un type valeur à part entière qui peut transporter des données, exposer des méthodes, calculer des propriétés et se prêter à un switch que le compilateur vérifie pour toi. C'est l'un des outils les plus puissants du langage pour rendre les états impossibles à représenter de travers.

Dans cette leçon, on part des cas simples, on monte vers les valeurs associées (le vrai super-pouvoir), on modélise un état réaliste, puis on révèle une surprise : un type que tu utilises depuis le début, Optional, est lui-même un enum. Fil rouge habituel : Swift mise sur la sûreté et l'expressivité.

Cas simples : une liste finie de possibilités

Un enum de base définit un ensemble fermé de valeurs. Chaque case est une valeur distincte du type.

Remarque l'écriture pointée .est : dès que Swift connaît le type attendu, tu n'as plus à répéter Direction. Et le switch doit couvrir tous les cas, sinon le compilateur refuse de compiler. C'est la base de la sûreté : ajouter un cas plus tard fera échouer la compilation partout où tu l'avais oublié.

Note

Contrairement à un entier déguisé, un case de Swift n'a pas de valeur numérique implicite. Direction.nord n'est pas « 0 » : c'est juste nord. Si tu veux une valeur sous-jacente, il faut la demander explicitement avec une valeur brute (section suivante).

Valeurs brutes : associer une valeur fixe à chaque cas

Quand chaque cas correspond naturellement à une constante (un entier, une chaîne…), tu peux déclarer un type de valeur brute (raw value) après le nom de l'enum.

Pour un enum à valeurs String, chaque cas prend par défaut son propre nom comme valeur brute, ce qui est très pratique pour le décodage.

Piège fréquent

Valeur brute et valeur associée, ce n'est pas la même chose. Une valeur brute est fixe et la même pour tous les exemplaires d'un cas (Planete.mars.rawValue vaut toujours 4). Une valeur associée (section suivante) est fournie à la création et varie d'un exemplaire à l'autre. Un même enum ne peut d'ailleurs pas mélanger un type de valeur brute et des valeurs associées.

Valeurs associées : le vrai super-pouvoir

Ici Swift se distingue vraiment. Un case peut transporter des données propres à chaque instance. C'est ce qu'on appelle une union discriminée : la valeur sait dans quel cas elle est et embarque les données pertinentes pour ce cas.

Le switch fait deux choses d'un coup : il discrimine le cas et il extrait les valeurs associées en les liant à des constantes (let donnees, let code…). Quand tous les éléments extraits sont des let, tu peux factoriser le mot-clé devant le cas : case let .echec(code, message).

Astuce

Ce patron succes / echec est si courant que la bibliothèque standard fournit déjà Result<Success, Failure>, un enum générique prêt à l'emploi. Tu retrouveras exactement la même mécanique : deux cas, des valeurs associées, un switch pour les traiter.

Modéliser un état : un téléchargement

Les valeurs associées brillent pour représenter un état qui change de forme selon l'étape. Un téléchargement n'a pas de progression quand il est en attente, et pas de fichier tant qu'il n'est pas fini. L'enum encode ça précisément.

Le where ajoute une condition supplémentaire à un cas : on peut traiter « presque fini » différemment du reste de la progression. L'ordre compte, car Swift teste les cas de haut en bas et s'arrête au premier qui correspond — c'est pourquoi le .enCours avec where précède le .enCours général. Comme toujours, le compilateur vérifie que l'ensemble reste exhaustif. Tu as ici un type qui rend littéralement impossible d'avoir un « pourcentage » sur un téléchargement en attente : l'état illégal n'existe pas.

Cas réel

C'est exactement ainsi qu'on modélise l'état d'un écran qui charge des données réseau dans une vraie app iOS. Avec des booléens séparés (isLoading, hasError, data), rien n'empêche l'incohérence « en chargement et en erreur en même temps », source de bugs d'affichage classiques (un indicateur de chargement par-dessus un message d'erreur). Un seul enum État { case chargement; case chargé([Article]); case erreur(String) } rend ces combinaisons impossibles : la vue fait un switch et affiche, pour chaque cas, exactement ce qui a du sens. « Make illegal states unrepresentable » est un mantra de la communauté Swift.

Méthodes et propriétés calculées dans un enum

Un enum peut contenir des méthodes et des propriétés calculées, exactement comme une struct. À l'intérieur, self désigne le cas courant, sur lequel on fait un switch.

Le comportement vit ainsi avec les données qu'il décrit. On regroupe ces ajouts dans une extension pour garder la déclaration des cas bien lisible, mais ce n'est qu'une question de style : tu pourrais tout mettre dans le corps de l'enum.

CaseIterable : parcourir tous les cas

Quand un enum n'a pas de valeur associée, demande la conformité à CaseIterable et Swift te génère automatiquement allCases : la liste de tous les cas, dans l'ordre de déclaration.

Très pratique pour remplir un menu, générer des données de test, ou itérer sur toutes les options d'un réglage.

enum récursif et la révélation Optional

Un enum peut se contenir lui-même via une valeur associée, à condition de le marquer indirect (Swift sait alors qu'il faut une indirection en mémoire). On modélise par exemple une expression arithmétique.

Et voici la révélation promise. L'Optional que tu manipules depuis le début n'est pas magique : c'est un enum générique de la bibliothèque standard. En gros, et débarrassée de ses conformités à des protocoles, sa déclaration tient en deux cas.

nil n'est rien d'autre que Optional.none, et déballer une valeur, c'est extraire la valeur associée du cas some. Tout l'édifice des optionnels — if let, guard let, ? — repose sur ce simple enum à deux cas. Une fois ce déclic fait, les optionnels cessent d'être une syntaxe à part et deviennent un cas particulier de ce que tu sais déjà faire.

Note

Si tu viens de Kotlin, l'enum à valeurs associées de Swift joue le rôle des sealed classes ; en Rust ou TypeScript, c'est l'équivalent des unions discriminées. La différence avec un simple enum de C ou de Java : ici chaque cas peut porter sa propre charge de données, et le switch exhaustif est garanti par le compilateur.

Pièges fréquents

  • Oublier l'exhaustivité du switch. Si tu ne traites que quelques cas, Swift refuse de compiler. Ne mets pas un default par réflexe : sans default, ajouter un cas plus tard provoquera une erreur utile qui te rappelle de le traiter. Le default masque ce filet de sécurité.
  • Confondre valeur brute et valeur associée. rawValue n'existe que sur les enums à valeur brute ; les enums à valeurs associées n'en ont pas. Inversement, on n'extrait pas une valeur associée avec .rawValue mais via un motif dans un switch ou un if case.
  • Croire que l'initialiseur rawValue: renvoie toujours un cas. Il renvoie un Optional, car la valeur brute fournie peut ne correspondre à aucun cas. Il faut donc le déballer.
  • Oublier indirect sur un enum récursif. Sans ce mot-clé, un enum qui se contient lui-même ne compile pas (« recursive enum … is not marked 'indirect' »).

Piège fréquent

Pour tester un seul cas hors d'un switch, utilise if case : if case .enCours(let p) = etat { print(p) }. Écrire if etat == .enCours(...) ne compile pas tant que l'enum ne conforme pas à Equatable, et serait de toute façon impuissant à extraire p.

Glossaire

enum
Type valeur listant un ensemble fermé de cas ; peut porter méthodes et propriétés.
Valeur brute (raw value)
Constante fixe attachée à chaque cas (Int, String…), lue via .rawValue.
Valeur associée
Donnée transportée par un cas, fournie à la création et propre à chaque instance.
Union discriminée
Valeur qui sait dans quel cas elle est et embarque les données de ce cas.
switch exhaustif
Doit couvrir tous les cas ; le compilateur signale un cas oublié.
where
Clause qui ajoute une condition à un cas d'un switch.
CaseIterable
Protocole fournissant allCases, la liste de tous les cas.
indirect
Marque un enum récursif (un cas peut contenir le type lui-même).

Récap et vérification

  • Un enum Swift est un type valeur : il peut porter des valeurs associées, des méthodes et des propriétés calculées.
  • Une valeur brute (: Int, : String) est fixe par cas ; l'initialiseur rawValue: renvoie un Optional.
  • Le switch est exhaustif et extrait les valeurs associées par motif ; where affine un cas.
  • CaseIterable fournit allCases ; indirect autorise un enum récursif.
  • Optional est un enum à deux cas, none et some(Wrapped) — nil est .none.

Vérifie ta compréhension

  1. Quelle différence concrète y a-t-il entre une valeur brute et une valeur associée ?
  2. Pourquoi le compilateur t'oblige-t-il à couvrir tous les cas d'un switch, et pourquoi un default systématique est-il parfois une mauvaise idée ?
  3. Si nil vaut Optional.none, à quel cas correspond une valeur déballée par if let ?
