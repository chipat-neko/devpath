Module 1 · Les bases de Swift — Leçon 04

Fonctions et closures

~45 min Débutant Prérequis : leçon 3

À la fin de cette leçon, tu sauras

  • Savoir déclarer une fonction avec étiquettes d'arguments, valeurs par défaut et paramètres inout ;
  • Savoir retourner plusieurs valeurs avec un tuple nommé ;
  • Savoir écrire une closure, l'abréger avec $0 et la sortir en trailing closure ;
  • Savoir manipuler les fonctions comme des valeurs de première classe et lire un map/filter/reduce.
Sommaire de la leçon

Tu sais déjà ce qu'est une fonction : un bloc de code nommé qui reçoit des entrées et renvoie une sortie. En Swift, les fonctions gardent cette idée familière, mais elles y ajoutent deux traits très marqués : des étiquettes d'arguments qui font lire l'appel comme une phrase, et un système de closures (fonctions anonymes) si soigné qu'il devient le cœur de l'écriture idiomatique, du petit script jusqu'à l'app iOS.

Dans cette leçon, on part de la déclaration la plus simple et on monte progressivement : valeurs par défaut, passage par référence, retours multiples, puis les closures et leurs raccourcis. À la fin, tu sauras lire et écrire un map ou un filter sans broncher.

Déclarer une fonction

La forme de base : le mot-clé func, un nom, des paramètres typés entre parenthèses, puis une flèche -> suivie du type de retour.

Une fonction sans valeur de retour omet simplement la flèche (son type de retour est Void, c'est-à-dire le tuple vide ()).

Les étiquettes d'arguments, l'idiome Apple

C'est LA particularité de Swift. Chaque paramètre possède en réalité deux noms : une étiquette d'argument (visible à l'appel) et un nom de paramètre (utilisé dans le corps). Quand tu n'en écris qu'un seul, il sert pour les deux. Mais tu peux en écrire deux pour que l'appel se lise comme une phrase, à la façon des API d'Apple.

L'appel deplacer(de: a, vers: b) se lit presque en français. Pour omettre une étiquette à l'appel, on la remplace par un tiret bas _ : c'est ce qu'on a fait plus haut avec double(_ n: Int), appelé double(21) sans étiquette.

Note

Les API Design Guidelines d'Apple recommandent de nommer pour la lisibilité au site d'appel. On omet l'étiquette du premier argument quand il forme une phrase avec le verbe (add(_ item:)), et on l'écrit quand elle clarifie le rôle (move(from:to:)).

Valeurs par défaut

Tu peux donner une valeur par défaut à un paramètre : l'appelant peut alors l'omettre. C'est l'équivalent Swift des paramètres optionnels d'autres langages, sans avoir à écrire plusieurs surcharges.

inout : modifier l'argument d'origine

Par défaut, les paramètres sont des constantes à l'intérieur de la fonction : tu ne peux pas les réassigner, et modifier une copie n'affecte pas la variable d'origine. Pour qu'une fonction modifie réellement la variable passée par l'appelant, on marque le paramètre inout et on préfixe l'argument d'un & à l'appel.

Piège fréquent

Un argument inout doit être une var, jamais une let ni un littéral. echanger(&3, &4) ne compile pas : // erreur : cannot pass immutable value as inout argument. En Swift moderne, inout reste rare : on préfère retourner une nouvelle valeur plutôt que muter en place.

Retourner plusieurs valeurs avec un tuple

Plutôt que d'inventer une structure pour deux ou trois valeurs liées, Swift permet de retourner un tuple — un petit groupe ordonné de valeurs. En nommant ses composantes, le résultat reste parfaitement lisible.

Le type de retour est ici (min: Int, max: Int)? : un tuple optionnel, qui vaut nil si le tableau est vide. On accède aux composantes par leur nom (bornes.min) — bien plus clair que bornes.0.

Les closures : des fonctions anonymes

Une closure est un bloc de code qu'on peut stocker dans une variable, passer en argument ou retourner. C'est comme une fonction, mais sans nom. Sa syntaxe complète place tout entre accolades, avec le mot-clé in qui sépare la signature du corps.

Le vrai intérêt apparaît quand on passe une closure à une fonction. Prenons sorted(by:), qui trie un tableau selon un critère qu'on lui fournit. Swift sait déduire les types depuis le contexte, ce qui permet d'abréger l'écriture par étapes :

Les raccourcis $0, $1… désignent le premier, le deuxième argument, etc. On évite ainsi de nommer des paramètres évidents.

Astuce

Les trois formes t1, t2 et t3 produisent exactement le même résultat. Commence par écrire la version explicite quand un doute subsiste, puis abrège : tant que les types restent inférables par le compilateur, tu peux retirer la signature, le return, et nommer les arguments $0/$1.

Trailing closure : la closure sort des parenthèses

Quand le dernier (ou seul) argument d'une fonction est une closure, on peut la sortir des parenthèses et la coller après l'appel. C'est la trailing closure, omniprésente en Swift et SwiftUI.

Cas réel — les trailing closures, partout dans SwiftUI

Ouvre n'importe quelle app iOS moderne écrite en SwiftUI et tu verras des trailing closures à chaque ligne. Un bouton s'écrit Button("Valider") { envoyer() } : le texte est le premier argument, et l'action est une closure sortie des parenthèses. Idem pour .onTapGesture { … }, .sheet(isPresented: $ouvert) { VueDetail() } ou ForEach(articles) { article in … }. Ce style n'est pas cosmétique : il fait lire le code déclaratif comme une description d'interface. Les mêmes closures alimentent les completion handlers du réseau — URLSession.shared.dataTask(with: url) { data, réponse, erreur in … } — où la closure est cette fois @escaping, car elle s'exécute plus tard, quand la réponse arrive.

map, filter, reduce en avant-première

Ces trois méthodes prennent une closure et transforment une collection sans boucle explicite. map transforme chaque élément, filter garde ceux qui satisfont une condition, reduce combine tout en une seule valeur.

Pour reduce, le premier argument (0) est la valeur de départ, et la closure reçoit l'accumulateur courant et l'élément suivant. On y reviendra en détail dans le module sur les collections.

Fonctions de première classe et capture

En Swift, une fonction est une valeur comme une autre : elle a un type (par ex. (Int) -> Int), on peut la stocker, la passer, la retourner. Une fonction nommée s'utilise donc directement là où une closure est attendue.

Le mot « closure » (clôture) vient du fait qu'elle capture les variables de son environnement : elle les emporte avec elle. Une fonction qui renvoie une closure illustre bien ce mécanisme.

Chaque appel de suivant retrouve le même total : la closure a capturé la variable, qui survit à la fin de compteur().

Note

Par défaut, une closure passée en argument est non-échappante : elle s'exécute avant le retour de la fonction. Quand une closure est au contraire conservée au-delà de cet appel (stockée pour plus tard, exécutée de façon asynchrone), son paramètre doit être marqué @escaping : func charger(completion: @escaping (Data) -> Void). Le compilateur t'y oblige. On approfondira avec la concurrence et les API réseau.

Pièges fréquents

Piège fréquent

Oublier l'étiquette à l'appel. Si tu déclares func carre(de nombre: Int), alors carre(9) ne compile pas : // erreur : missing argument label 'de:' in call. Il faut écrire carre(de: 9). Pour pouvoir appeler sans étiquette, déclare le paramètre avec _.

Autres erreurs courantes :

  • Confondre étiquette d'argument (côté appel) et nom de paramètre (côté corps). Dans func deplacer(de origine: Point), le corps utilise origine, jamais de.
  • Oublier le & devant un argument inout : echanger(premier, second) donne // erreur : passing value ... use '&'.
  • Utiliser $0 dans une closure à plusieurs lignes où nommer les paramètres serait plus clair. Les raccourcis sont parfaits pour une ligne, lourds au-delà.
  • Croire qu'un paramètre normal est modifiable. func f(x: Int) { x += 1 } ne compile pas : les paramètres sont des constantes.

Pour aller plus loin

Pour aller plus loin

Swift propose les paramètres variadiques (func somme(_ valeurs: Int...), un nombre quelconque d'arguments), les fonctions imbriquées (déclarées dans une autre, utiles pour factoriser localement), et les closures @autoclosure. Tout cela se relie au type d'une fonction, qui est lui-même un type de première classe que tu pourras rendre générique dans un module ultérieur.

Récap et vérification

  • func nom(étiquette param: Type) -> Retour : deux noms par paramètre, _ pour omettre l'étiquette.
  • Valeurs par défaut (param: Type = valeur) pour rendre un argument optionnel à l'appel.
  • inout + & pour modifier la variable d'origine (à éviter quand on peut retourner une valeur).
  • Un tuple nommé pour retourner plusieurs valeurs liées.
  • Une closure { (x: Int) -> Int in … } s'abrège jusqu'à { $0 … }, et sort des parenthèses en trailing closure.
  • map/filter/reduce transforment une collection via une closure ; les fonctions sont des valeurs de première classe qui capturent leur environnement.

Vérifie ta compréhension

  1. Quelle est la différence entre l'étiquette d'argument et le nom de paramètre, et comment omettre l'étiquette à l'appel ?
  2. Pourquoi echanger(&3, &4) ne compile-t-il pas ?
  3. Réécris { (a: String, b: String) -> Bool in return a < b } dans sa forme la plus courte.
  4. Que signifie qu'une closure « capture » une variable ?
