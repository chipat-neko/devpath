Module 1 · Les bases de Swift — Leçon 01

Découvrir Swift

~40 min Débutant Prérequis : bases de la programmation

À la fin de cette leçon, tu sauras

  • savoir où et comment exécuter du Swift (Playgrounds, Xcode, REPL swift, Linux)
  • savoir écrire un premier programme avec print et commenter le code
  • savoir choisir entre let et var et comprendre l'inférence de type ;
  • savoir appliquer les conventions de nommage Swift (camelCase, point-virgule omis).
Sommaire de la leçon

Bienvenue dans le premier pas de ton voyage avec Swift. Si tu as déjà programmé ailleurs — variables, boucles, fonctions ne te font pas peur — tu vas te sentir vite à l'aise. Mais Swift a une personnalité bien à lui : il est obsédé par deux choses, la sûreté (il attrape un maximum d'erreurs avant même que ton programme tourne) et l'expressivité (du code court qui se lit comme une phrase).

Dans cette leçon, on plante le décor : d'où vient Swift, où l'essayer, ton tout premier programme, et les briques de base que tu utiliseras dans chaque fichier — constantes, variables, types et commentaires. C'est le fil rouge de tout le cours : on partira du petit script pour aller, leçon après leçon, jusqu'à une vraie app iOS avec SwiftUI.

D'où vient Swift, et pourquoi il existe

Swift a été présenté par Apple en 2014, conçu au départ par Chris Lattner (aussi à l'origine du compilateur LLVM). C'est le langage moderne de tout l'écosystème Apple : iOS, macOS, watchOS, tvOS et visionOS. Il a été pensé pour remplacer Objective-C avec un code plus sûr et plus lisible.

Trois idées à retenir dès maintenant :

  • Rapide : compilé en code natif, il vise des performances proches du C.
  • Sûr : le compilateur refuse une grande partie des erreurs classiques (oublier un cas, manipuler une valeur absente) avant l'exécution.
  • Open source : Swift ne se limite pas à Apple. Il tourne aussi sur Linux et sert à écrire des serveurs ou des outils en ligne de commande.

Note

Ce cours utilise Swift moderne (5.9+ et 6). On privilégie systématiquement le style idiomatique que recommande Apple : constantes par défaut, types sûrs, nommage clair. Tu prends de bonnes habitudes dès la première ligne.

Où écrire ton premier Swift

Tu as plusieurs portes d'entrée, selon ton matériel :

  • Swift Playgrounds : une app gratuite sur iPad et Mac, idéale pour expérimenter, on voit le résultat à côté de chaque ligne.
  • Xcode : l'environnement complet d'Apple (sur Mac), incontournable dès qu'on construit une vraie app.
  • Le REPL : dans un terminal, la commande swift ouvre une console interactive où tu tapes du code ligne par ligne.
  • Swift sur Linux : on installe la toolchain, et on compile/exécute des fichiers .swift comme des scripts.

Les deux façons les plus rapides d'exécuter du Swift en ligne de commande.

Note

Sur ce site, le code ne s'exécute pas tout seul. À chaque exemple, je te montre ce qu'il afficherait dans un commentaire //, comme si tu lisais la console. Recopie-le dans un Playground ou le REPL pour voir par toi-même.

Ton premier programme

Le rituel universel : afficher un message. En Swift, ça tient en une ligne.

Remarque ce qui n'est pas là : pas de fonction main visible, pas d'import, pas de point-virgule. Dans un script Swift, le code au niveau supérieur du fichier s'exécute de haut en bas, tout simplement. La fonction print écrit son argument sur la sortie standard, puis passe à la ligne.

Tu peux aussi lui passer plusieurs valeurs, séparées par des virgules : elles seront affichées avec un espace entre elles.

Constantes et variables : let et var

Pour stocker une valeur, Swift te donne deux mots-clés. La règle d'or, en Swift moderne : commence toujours par let, et passe à var seulement si tu as vraiment besoin de modifier la valeur.

  • let déclare une constante : sa valeur ne changera plus après l'affectation.
  • var déclare une variable : tu pourras lui réaffecter une nouvelle valeur.

Préférer let n'est pas une coquetterie : ça rend tes intentions claires (« cette valeur est figée ») et permet au compilateur de t'aider. Si tu tentes de modifier une constante, Swift refuse de compiler — l'erreur est attrapée avant que le programme tourne.

Astuce

Xcode te propose même un avertissement « variable was never mutated, consider changing to 'let' » quand tu déclares un var que tu ne modifies jamais. Écoute-le : c'est l'outil qui te pousse vers le style idiomatique.

Les types : inférence et annotation

Chaque valeur en Swift a un type (texte, entier, nombre à virgule…) et ce type est fixé une fois pour toutes. La bonne nouvelle : la plupart du temps, tu n'as pas besoin de l'écrire. Swift le déduit de la valeur que tu donnes — c'est l'inférence de type.

Tu peux aussi écrire le type explicitement, après un deux-points, juste après le nom. C'est utile pour lever une ambiguïté ou documenter ton intention.

Une fois le type fixé, Swift veille au grain : impossible de glisser un texte là où un nombre est attendu. Là encore, l'erreur est détectée à la compilation, pas en pleine exécution.

Commenter ton code

Les commentaires servent à t'expliquer, à toi ou à tes coéquipiers. Swift en propose deux formes, identiques à beaucoup d'autres langages.

Tout ce qui suit // jusqu'au bout de la ligne est ignoré par le compilateur, et tout ce qui est entre /* et */ aussi. C'est exactement ce mécanisme que j'utilise pour te montrer les sorties dans ces exemples.

Les conventions de nommage Swift

Swift suit les API Design Guidelines d'Apple : un nommage clair et cohérent fait partie du langage idiomatique. Quelques règles à adopter tout de suite :

  • camelCase pour les variables, constantes et fonctions : nombreDeJoueurs, calculerScore.
  • UpperCamelCase pour les types (qu'on verra bientôt) : Joueur, NombreComplexe.
  • Des noms parlants plutôt que courts : distanceEnMetres vaut mieux que d.
  • Le point-virgule est optionnel en fin d'instruction, et on l'omet par convention.

Aperçu du chemin

Tu viens de poser la première pierre. Dans les prochaines leçons, on enchaînera : les types fondamentaux et les opérateurs, les optionnels (la façon élégante dont Swift gère l'absence de valeur), les structures de contrôle, les fonctions, puis les value types (structures et énumérations) qu'on privilégie en Swift. De fil en aiguille, on remontera jusqu'à construire une interface avec SwiftUI — du petit script à l'app iOS.

Cas réel — Lyft réécrit son app en Swift

Dès 2015, un an après la sortie du langage, l'entreprise Lyft a réécrit intégralement son application iOS en Swift. Résultat rapporté par ses équipes : une base de code d'environ 75 000 lignes d'Objective-C ramenée à près de 25 000 lignes de Swift — soit trois fois moins de code, plus lisible et plus sûr, pour la même application. C'est exactement ce que promettent les deux obsessions de Swift : la concision (l'inférence de type, la syntaxe légère) et la sûreté (le compilateur qui attrape les erreurs avant la mise en production). Ces qualités que tu découvres sur un print sont les mêmes qui font tourner des apps utilisées par des millions de personnes.

Pièges fréquents

Piège fréquent

Réflexe d'autres langages : tout déclarer en var. En Swift, on commence par let et on ne passe à var que si la valeur doit vraiment changer. Modifier une constante let est une erreur de compilation, pas un avertissement qu'on peut ignorer.

Piège fréquent

Le type est figé. Une fois compteur inféré comme Int, tu ne peux plus lui affecter un String. Swift ne convertit pas en douce derrière ton dos — c'est volontaire, ça t'évite des bugs silencieux.

Pour aller plus loin

Pour aller plus loin

Le projet Swift est open source : le code source, l'évolution du langage (les Swift Evolution proposals) et la documentation officielle sont publics sur swift.org. Y jeter un œil, c'est voir comment un langage se construit au grand jour.

Glossaire

Swift
Langage d'Apple (2014), compilé, sûr et open source ; propulse iOS, macOS, watchOS, tvOS, visionOS.
Constante (let)
Valeur affectée une seule fois qui ne peut plus changer ; le choix par défaut en Swift moderne.
Variable (var)
Valeur que l'on peut réaffecter ; réservée aux cas où la donnée doit vraiment évoluer.
Inférence de type
Le compilateur déduit le type d'une valeur sans qu'on l'écrive (2014 → Int).
Annotation de type
Écriture explicite du type après le nom (nom: Type), pour lever une ambiguïté.
Typage statique
Le type de chaque valeur est fixé et vérifié à la compilation, avant l'exécution.
REPL
Console interactive (commande swift) où l'on exécute du code ligne par ligne.
camelCase
Convention de nommage : première minuscule puis majuscule à chaque mot (nombreDeJoueurs).

Récap et vérification

  • Swift est le langage moderne, rapide, sûr et open source de l'écosystème Apple.
  • On l'essaie via Swift Playgrounds, Xcode, le REPL swift ou sur Linux.
  • print(…) affiche un message ; dans un script, pas de main visible.
  • let = constante (par défaut), var = variable (si la valeur doit changer).
  • Le type est inféré de la valeur, ou annoté explicitement avec nom: Type.
  • Commentaires // et /* */ ; nommage camelCase ; point-virgule omis.
