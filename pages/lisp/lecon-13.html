Macros avancées : quasiquote et DSL

~60 min Avancé Prérequis : leçon 8

À la fin de cette leçon, tu sauras

  • construire du code avec la quasiquote (backquote) ;
  • percer des trous avec unquote , et splicing ,@ ;
  • écrire des macros utiles : unless, swap!, while ;
  • éviter la capture de variable avec gensym et entrevoir un DSL.
Sommaire de la leçon

La leçon 8 a posé l'idée fondatrice : en Lisp, le code est une donnée, et une macro transforme du code avant son exécution. Cette leçon te donne les outils pour écrire des macros lisibles et sûres : la quasiquote pour fabriquer du code comme un gabarit, le splicing pour insérer des listes, et gensym pour éviter les collisions de noms. Au bout : la capacité d'étendre le langage lui-même.

Rappel : deux temps distincts

Une macro s'exécute au temps d'expansion (pendant la lecture du code), et produit une nouvelle expression qui, elle, s'exécutera au temps d'exécution. Bien distinguer ces deux moments est la clé des macros.

La quasiquote : un gabarit de code

Écrire le code de sortie avec des list et des cons devient vite illisible. La quasiquote (backquote `) résout cela : elle fige une structure comme quote, mais autorise à « percer des trous ». Deux marqueurs :

  • unquote , : insère la valeur d'une expression dans le gabarit ;
  • splicing ,@ : insère les éléments d'une liste en les « éclatant ».

La capture de variable et gensym

Voici swap!, qui échange deux variables. Elle a besoin d'un temporaire. Si on le nomme tmp en dur, un utilisateur qui passe une variable nommée… tmp casse tout : c'est la capture de variable. La parade : gensym, qui fabrique un nom unique garanti.

Attention — la capture de variable

Un nom introduit « en dur » par une macro peut masquer ou être masqué par un nom du code appelant. C'est le bug le plus classique des macros. Règle : tout symbole que toi tu introduis (temporaires, compteurs) doit venir d'un gensym.

Cas réel — quand le langage est écrit dans le langage

La macro loop de Common Lisp, si lisible (loop for i from 1 to 10 …), est… une gigantesque macro écrite en Lisp : elle compile son mini-langage vers des do. Chez Scheme, define-syntax et syntax-rules offrent des macros hygiéniques (sans capture, sans gensym à écrire). Et toute la bibliothèque Racket — jusqu'à des langages entiers comme Typed Racket — est bâtie sur ce pouvoir : étendre le langage depuis le langage lui-même.

Vers un langage dédié (DSL)

Puisqu'on fabrique de la syntaxe, on peut créer un petit langage adapté à un domaine. Exemple : une macro qui décrit du HTML.

D'abord une fonction, une macro seulement si nécessaire

Une macro complique le débogage et ne se passe pas en argument. Ne l'emploie que pour ce qu'une fonction ne peut pas faire : contrôler l'évaluation (retarder, répéter, réécrire la syntaxe). Pour tout le reste, une fonction suffit.

Pour aller plus loin

Pour aller plus loin

Les macros hygiéniques de Scheme (syntax-rules, syntax-case) gèrent la capture automatiquement : plus besoin de gensym. À l'autre bout, la programmation par macros a inspiré la métaprogrammation de langages modernes : les macros de Rust (macro_rules!), les template haskell, ou encore les décorateurs et l'AST de Python en descendent, de près ou de loin.

Glossaire

Temps d'expansion
Le moment où les macros s'exécutent pour réécrire le code, avant le temps d'exécution.
Quasiquote (`)
Un quote « perçable » : fige une structure tout en autorisant des trous.
Unquote (,)
Insère la valeur d'une expression à l'intérieur d'une quasiquote.
Splicing (,@)
Insère les éléments d'une liste en les éclatant dans le gabarit.
Capture de variable
Bug où un nom introduit par la macro entre en collision avec un nom de l'appelant.
gensym
Génère un symbole unique pour éviter la capture de variable.
DSL
Domain-Specific Language : un mini-langage taillé pour un domaine, souvent bâti avec des macros.
Métaprogrammation
Écrire du code qui manipule ou génère du code ; les macros en sont la forme la plus directe et ont inspiré macro_rules! (Rust), Template Haskell, etc.

Récap et vérification

  • Une macro agit au temps d'expansion : elle réécrit le code, puis ce code s'exécute.
  • La quasiquote ` écrit le code de sortie comme un gabarit ; , insère une valeur, ,@ éclate une liste.
  • Une macro contrôle l'évaluation (retarder, répéter) : unless, while…
  • gensym évite la capture de variable ; les macros hygiéniques la règlent d'office.

Vérifie ta compréhension

  1. Quelle différence entre , et ,@ ?
  2. Pourquoi unless ne peut-il pas être une simple fonction ?
  3. À quoi sert gensym ?
