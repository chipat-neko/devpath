Programmation symbolique : eval et apply

~55 min Avancé Prérequis : leçon 8

À la fin de cette leçon, tu sauras

  • utiliser eval pour évaluer une donnée comme du code ;
  • utiliser apply pour déballer une liste en arguments ;
  • construire du code avec la quasiquote, puis l'exécuter ;
  • comprendre la boucle REPL et pourquoi eval est dangereux.
Sommaire de la leçon

Depuis la leçon 8, une idée te suit : en Lisp, le code est une donnée. Une expression comme (+ 1 2) est d'abord une simple liste de trois éléments. Jusqu'ici, les macros exploitaient cette idée avant l'exécution. Cette leçon franchit le dernier pas : évaluer une donnée comme du code, pendant l'exécution. Deux fonctions incarnent ce pouvoir : eval et apply. Ce sont les deux rouages qui, ensemble, forment le cœur de tout interpréteur Lisp — celui-là même que tu écriras au prochain projet.

eval : évaluer une donnée comme du code

Une liste citée avec ' reste inerte : c'est de la donnée. La fonction eval la prend et l'évalue comme si tu venais de la taper : la liste redevient du code vivant.

Le point remarquable : rien ne distingue une liste « donnée » d'une liste « programme ». C'est la même structure. eval décide simplement de la lire comme du code.

Un détail selon les dialectes

En Common Lisp, (eval expr) suffit. En Scheme (R7RS), eval attend un second argument, l'environnement d'évaluation : (eval expr (interaction-environment)). L'idée reste la même ; on garde ici la forme courte pour la lisibilité.

apply : déballer une liste en arguments

Parfois, tu as une fonction d'un côté et une liste d'arguments de l'autre, et tu veux les réunir. Écrire (f liste) passerait la liste comme un seul argument. apply « déballe » la liste : chaque élément devient un argument distinct.

apply vs map

Ne confonds pas : map applique une fonction à chaque élément (une fois par élément), tandis qu'apply l'appelle une seule fois avec tous les éléments comme arguments. (apply + '(1 2 3)) donne 6 ; (map (lambda (x) (+ x 1)) '(1 2 3)) donne (2 3 4).

La fonction comme valeur

En Common Lisp, on désigne la fonction avec #' : (apply #'+ '(1 2 3)). En Scheme, le nom seul suffit : (apply + '(1 2 3)). Dans les deux cas, la fonction est une valeur de première classe que l'on passe en argument (revois la leçon 6).

eval et apply, les deux faces de l'interpréteur

Ces deux fonctions ne sont pas de simples utilitaires : ce sont les deux rouages de l'évaluation Lisp. eval examine une expression et décide quoi en faire ; quand c'est un appel de fonction, il évalue les arguments puis passe la main à apply, qui exécute la fonction sur ces arguments. Puis apply peut avoir besoin d'eval pour le corps de la fonction… et ainsi de suite. Ils s'appellent mutuellement.

Construire du code, puis l'exécuter

La quasiquote (leçon 13) fabrique une expression ; eval l'exécute. Ensemble, ils permettent de générer un programme à la volée, à partir de valeurs connues seulement à l'exécution.

Attention — presque toujours, une autre voie existe

Générer puis évaluer du code est puissant, mais rarement nécessaire. Ici, une lambda ou une table de fonctions ferait le même travail sans eval, plus vite et plus sûrement. Garde eval pour les vrais cas : interpréteur, REPL, DSL chargé depuis un fichier.

La boucle REPL

Tu l'utilises depuis la leçon 1 : le REPL (Read-Eval-Print Loop). Son nom est son fonctionnement — une boucle de quatre étapes, dont eval est le cœur.

Le danger de eval

eval exécute tout ce qu'on lui donne. Si l'expression provient d'une source non maîtrisée (saisie utilisateur, réseau, fichier externe), c'est une porte ouverte : on parle d'injection de code.

Ne jamais évaluer une entrée non fiable

Faire (eval (read)) sur une donnée venue d'un utilisateur revient à lui laisser exécuter n'importe quel code sur ta machine — effacer des fichiers, lire des secrets… Pour évaluer une expression arithmétique venue de l'extérieur, écris un petit interpréteur restreint (le projet de la leçon 15 !) plutôt que d'appeler eval.

Cas réel — le même piège dans tous les langages

Le danger d'eval n'a rien de propre à Lisp. JavaScript (eval), Python (eval/exec), PHP (eval) ont exactement le même. Les guides de sécurité (OWASP) rangent l'appel d'eval sur une entrée utilisateur parmi les fautes graves. La règle est universelle : données et code doivent rester séparés — et n'évalue jamais ce que tu ne contrôles pas.

Pour aller plus loin

Pour aller plus loin

Le fait qu'eval et apply puissent s'écrire en Lisp lui-même a donné l'un des textes fondateurs de l'informatique : l'article de John McCarthy (1960) où Lisp se définit par sa propre fonction eval. C'est aussi le sommet de Structure and Interpretation of Computer Programs (SICP, chapitre 4) : l'évaluateur métacirculaire. Tu en construiras une version au prochain projet.

Antisèche

Glossaire

eval
Fonction qui prend une expression (une donnée) et l'évalue comme du code, produisant sa valeur.
apply
Fonction qui appelle une fonction en déballant une liste comme arguments : (apply + '(1 2)) ≡ (+ 1 2).
Programmation symbolique
Manipuler des programmes comme des données (symboles et listes), puis les évaluer.
REPL
Read-Eval-Print Loop : la boucle qui lit une expression, l'évalue et affiche le résultat.
Environnement
La table qui associe chaque symbole à sa valeur au moment de l'évaluation.
Injection de code
Faille où une entrée non fiable est exécutée comme du code ; le risque majeur d'eval.
Évaluateur métacirculaire
Un interpréteur d'un langage écrit dans ce même langage (Lisp en Lisp).

Récap et vérification

  • eval évalue une donnée comme du code ; quote fait l'inverse (fige le code en donnée).
  • apply déballe une liste en arguments : (apply f '(a b)) ≡ (f a b).
  • Ensemble, eval et apply forment le cœur de tout interpréteur ; ils s'appellent mutuellement.
  • Le REPL = read + eval + print + loop ; eval sur une entrée non fiable est une faille de sécurité.

Vérifie ta compréhension

  1. Quelle est la différence entre '(+ 1 2) et (eval '(+ 1 2)) ?
  2. Pourquoi (apply + '(1 2 3)) vaut-il 6 et non (1 2 3) ?
  3. Pourquoi ne faut-il jamais évaluer une entrée utilisateur avec eval ?
