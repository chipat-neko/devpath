Module 3 · La puissance de Lisp — Leçon 09

Structures de données et état

~50 min Intermédiaire Prérequis : leçon 8

À la fin de cette leçon, tu sauras

  • utiliser des vecteurs et des tables de hachage ;
  • modéliser des structures (records/structs) ;
  • gérer l'état mutable avec set! quand c'est justifié ;
  • comprendre quand préférer l'immuabilité.
Sommaire de la leçon

Les listes sont l'âme de Lisp, mais ce ne sont pas ses seules structures de données. Pour des accès rapides ou de gros volumes, on dispose de vecteurs et de tables de hachage. Et bien que Lisp privilégie l'immuabilité, il sait aussi gérer l'état mutable quand c'est justifié. Cette leçon élargit ta boîte à outils.

Les vecteurs

Une liste s'accède séquentiellement (le n-ième élément coûte n étapes). Un vecteur offre un accès direct par indice, en temps constant — comme un tableau.

Choisis le vecteur pour l'accès indexé, la liste pour le parcours et la construction récursive.

Les tables de hachage

Pour associer des clés à des valeurs avec une recherche rapide, on utilise une table de hachage (le dictionnaire moderne de Lisp).

La syntaxe exacte varie selon le dialecte (ici style Racket) ; l'idée est universelle.

Cas réel — les tables de hachage sont partout

La table de hachage est sans doute la structure la plus utilisée de l'informatique. Un interpréteur Lisp lui-même s'en sert pour sa table des symboles (associer chaque nom à sa valeur). La base de données Redis n'est, au fond, qu'une gigantesque table de hachage en mémoire ; l'objet Map de JavaScript et le dict de Python en sont d'autres visages. Et l'idiome (hash-ref t k défaut) — lire avec une valeur de repli — est la brique de base de la mémoïsation (garder en cache un résultat déjà calculé).

Modéliser une structure : les records

Pour des données nommées (un point, une personne), les dialectes offrent des structures (records). define-struct (Racket) crée un type avec constructeur et accesseurs.

L'état mutable : set!

Par défaut, on ne modifie pas une variable en Lisp : on en crée de nouvelles. Mais pour un état qui change vraiment (un compteur, un cache), set! réaffecte une variable. La convention : les opérations qui mutent finissent par !.

État encapsulé dans une fermeture

Idiome élégant : combiner fermeture (leçon 6) et set! pour créer un objet à état privé, invisible de l'extérieur — l'ancêtre de l'encapsulation objet.

Choisir la bonne structure

Un réflexe utile : liste pour construire et parcourir de façon récursive ; vecteur quand tu accèdes par indice ou modifies des cases ; table de hachage pour retrouver une valeur par une clé ; structure (record) pour des champs nommés stables (un point, une personne). Le bon choix rend le code plus court et plus rapide.

Quand préférer l'immuabilité

Le style fonctionnel privilégie l'immuabilité : pas de mutation, des fonctions pures, un code plus prévisible et parallélisable. Réserve set! et les opérations ! aux cas où l'état mutable simplifie vraiment (performance, ressources, état intrinsèquement changeant). Dans le doute, reste immuable.

Pièges fréquents

Piège fréquent

Utiliser set! par habitude impérative : en Lisp, beaucoup de problèmes se résolvent plus clairement sans mutation, par récursion ou par fold. Avant de muter, demande-toi si une transformation pure ne serait pas plus simple et plus sûre.

Pour aller plus loin

Pour aller plus loin

Clojure, le Lisp moderne sur la JVM, pousse l'immuabilité à l'extrême avec ses structures de données persistantes : « modifier » renvoie une nouvelle version partageant la structure de l'ancienne, sans copie coûteuse. Une réponse élégante à l'état partagé et à la concurrence.

Glossaire

Vecteur
Séquence à accès direct par indice en temps constant ; idéal pour l'indexation, moins pour l'ajout en tête.
Table de hachage
Associe des clés à des valeurs avec une recherche rapide ; le dictionnaire de Lisp.
Structure (record)
Type à champs nommés (struct) avec constructeur et accesseurs générés.
set!
Réaffecte une variable existante : un effet de bord. Par convention, les mutations finissent par !.
Mutabilité
Capacité d'une valeur ou variable à changer en place ; à opposer à l'immuabilité.
Immuabilité
On ne modifie pas : on produit de nouvelles valeurs. Code plus prévisible et parallélisable.
État encapsulé
Un état rendu privé par une fermeture : accessible seulement via les fonctions renvoyées.
Structure persistante
Structure immuable dont la « modification » renvoie une nouvelle version partageant l'ancienne (Clojure).

Récap et vérification

  • Les vecteurs offrent un accès indexé en temps constant ; les tables de hachage associent clés et valeurs.
  • Les structures (records) modélisent des données nommées.
  • set! mute une variable (convention !) ; une fermeture + set! = état privé.
  • Privilégie l'immuabilité ; réserve la mutation aux cas qui le justifient.
