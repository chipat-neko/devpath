Module 1 · Les bases d'Objective-C — Leçon 02

Types, variables et NSString

~50 min Avancé Prérequis : leçon 1

À la fin de cette leçon, tu sauras

  • distinguer types primitifs C et objets ;
  • comprendre les pointeurs d'objets et nil ;
  • utiliser NSString et les littéraux @"..." ;
  • manier NSNumber et les littéraux objets.
Sommaire de la leçon

Objective-C vit dans deux mondes à la fois : celui du C, avec ses types primitifs (int, float…), et celui des objets, manipulés par des pointeurs. Bien distinguer ces deux registres est la clé pour ne pas se perdre. Cette leçon explore les types, le rôle particulier de nil, et la classe de chaînes omniprésente : NSString.

Les objets et les pointeurs

Tout objet Objective-C se manipule par un pointeur — d'où l'astérisque * dans les déclarations. Une variable objet contient en réalité l'adresse de l'objet, pas l'objet lui-même.

Retiens la règle : type primitif → pas d'étoile (int age) ; objet → une étoile (NSString *nom). Cette étoile est systématique pour les objets ; l'oublier est l'une des premières erreurs du débutant.

nil : l'absence d'objet

Un pointeur d'objet qui ne pointe vers rien vaut nil — l'équivalent de « aucun objet ». C'est l'analogue du null d'autres langages, mais avec une particularité remarquable qu'on verra leçon 3 : en Objective-C, envoyer un message à nil ne plante pas.

NSString : la classe des chaînes

NSString est l'une des classes les plus utilisées. Ses objets sont immuables (on n'en modifie pas le contenu ; on en dérive de nouveaux). On crée une chaîne avec le littéral @"...", et on l'interroge par messages.

Pour construire une chaîne à partir de variables, on utilise stringWithFormat:, avec des marqueurs de format hérités du C (%@ pour un objet, %d pour un entier) :

Le marqueur %@ est spécifique à Objective-C : il insère la représentation textuelle de n'importe quel objet (ici, un NSString).

Les marqueurs de format à connaître

Dans NSLog et stringWithFormat:, chaque type a son marqueur : %@ pour un objet (le plus courant, y compris un NSNumber), %d pour un int, %ld pour un long/NSInteger, %f pour un float/double. Se tromper de marqueur — afficher un objet avec %d — donne une valeur absurde ou plante : aligne toujours le marqueur sur le type réel.

Pièges fréquents

Piège fréquent

Comparer deux NSString avec ==. L'opérateur == compare les pointeurs (les adresses), pas le contenu : deux chaînes identiques rangées à des endroits différents seraient jugées « différentes ». Pour comparer le contenu, il faut le message isEqualToString: : [chaine1 isEqualToString:chaine2]. C'est l'une des erreurs les plus classiques.

Cas réel

Le bug du == sur les chaînes est sournois parce qu'il marche parfois : quand les deux chaînes viennent de littéraux @"..." identiques, le compilateur les fusionne à la même adresse et == renvoie YES « par chance ». Mais dès qu'une chaîne provient d'une saisie utilisateur ou du réseau, elle occupe une autre adresse : le test échoue en silence. D'où ces bugs « impossibles à reproduire » qui n'apparaissent que sur l'appareil d'un utilisateur. Le réflexe isEqualToString: les élimine d'emblée.

Pour aller plus loin

Pour aller plus loin

NSString étant immuable, sa cousine NSMutableString permet de modifier une chaîne en place (ajouter, remplacer). Ce couple immuable/mutable est un patron récurrent de Foundation : NSArray/NSMutableArray, NSDictionary/NSMutableDictionary (leçon 8). On choisit la version immuable par défaut (plus sûre) et la mutable seulement quand on doit vraiment modifier l'objet.

Antisèche — types, littéraux et messages de chaîne

Glossaire

Type primitif
Type de base hérité du C (int, float, char, BOOL) : la variable contient directement la valeur, sans étoile.
Pointeur
Variable qui contient l'adresse d'un objet. En Objective-C, tout objet se manipule par pointeur, d'où l'étoile *.
nil
Valeur d'un pointeur qui ne désigne aucun objet (équivalent du null). Lui envoyer un message ne plante pas (leçon 3).
NSString
Classe de chaîne immuable de Foundation ; littéral @"…", interrogée par messages (length, uppercaseString…).
NSNumber
Objet qui emballe une valeur numérique primitive pour la ranger parmi les objets ; littéral @42.
Emballage (boxing)
Envelopper une valeur primitive dans un objet — et l'inverse, le déballage, avec intValue, doubleValue…
Immuable
Objet dont le contenu ne change pas après création ; toute « modification » produit un nouvel objet. Contraire : mutable (NSMutableString).
BOOL
Booléen d'Objective-C, de valeurs YES ou NO (et non true/false).

Récap et vérification

  • Types primitifs C (pas d'étoile) ; objets par pointeur (avec *).
  • Booléen BOOL avec YES/NO ; nil = absence d'objet.
  • NSString (immuable) : littéral @"...", stringWithFormat: avec %@, %d.
  • Comparer le contenu : isEqualToString:, pas == ; nombres emballés en NSNumber (@42).
