Module 3 · Objective-C en pratique — Leçon 09

Cohabiter avec Swift et au-delà

~45 min Avancé Prérequis : leçon 8

À la fin de cette leçon, tu sauras

  • utiliser Xcode et l'écosystème Apple ;
  • faire cohabiter Objective-C et Swift ;
  • situer Objective-C aujourd'hui (maintenance, legacy) ;
  • savoir où continuer.
Sommaire de la leçon

Tu as parcouru l'essentiel d'Objective-C : messages, classes, propriétés, protocoles, mémoire, blocks. Reste à situer ce savoir dans le monde réel d'aujourd'hui, où Swift est le langage de premier plan chez Apple. Cette dernière leçon présente les outils, explique comment Objective-C et Swift cohabitent, où Objective-C reste pertinent, et comment poursuivre.

Xcode : l'atelier Apple

Tout le développement Apple se fait dans Xcode, l'environnement gratuit de Microsoft… pardon, d'Apple : éditeur, compilateur (Clang/LLVM), concepteur d'interfaces, débogueur, simulateur iOS. C'est là qu'on écrit, compile et teste aussi bien l'Objective-C que le Swift. Xcode ne tourne que sur macOS : c'est une contrainte de l'écosystème Apple.

Pas de Mac sous la main ?

Xcode ne s'installe que sur macOS. Sans machine Apple, on peut tout de même s'exercer : en louant un Mac dans le nuage (les runners macOS des services d'intégration continue comme GitHub Actions), ou, pour la syntaxe pure du langage, avec le compilateur clang et GNUstep, une réimplémentation libre de Foundation qui fait tourner de l'Objective-C sur Linux ou Windows. Pour un vrai projet iOS, en revanche, un Mac reste incontournable.

Objective-C et Swift, côte à côte

Apple a conçu Swift pour cohabiter avec Objective-C : dans un même projet, les deux langages s'appellent mutuellement. C'est essentiel, car d'immenses bases de code mêlent les deux. Le pont se fait via des fichiers d'en-tête générés :

  • un bridging header expose le code Objective-C au Swift ;
  • un en-tête généré (-Swift.h) expose le code Swift compatible à l'Objective-C.

Cette interopérabilité signifie qu'on peut moderniser progressivement un projet : garder l'Objective-C existant et écrire les nouvelles parties en Swift, fichier par fichier.

Cas réel

Même une application 100 % Swift repose en permanence sur de l'Objective-C : les frameworks fondamentaux d'iOS et de macOS — UIKit, Foundation, AppKit — sont en grande partie écrits en Objective-C. Quand du Swift instancie UILabel() ou manipule un NSString, le pont fait le travail sans qu'on s'en aperçoive. C'est pourquoi Apple a soigné l'interopérabilité dès le premier jour de Swift : il fallait que le nouveau langage puisse parler à des décennies de code existant. Beaucoup de grandes applications de l'App Store ont d'ailleurs vécu des années en régime mixte, migrant écran par écran.

Où Objective-C reste pertinent

Même si Swift domine les nouveaux projets, Objective-C garde des usages bien réels :

  • maintenance : des millions de lignes en production à faire évoluer ;
  • frameworks : une part importante des bibliothèques Apple et tierces est en Objective-C ;
  • interopérabilité avec le C/C++ : Objective-C s'y mêle plus directement que Swift ;
  • runtime dynamique : certaines techniques avancées (introspection, swizzling) restent l'apanage d'Objective-C.

Le connaître, c'est pouvoir intervenir sur l'existant et comprendre en profondeur les plateformes Apple.

Objective-C ou Swift pour débuter ?

Pour un nouveau projet Apple, le choix est clair : Swift. Il est plus sûr (typage strict, optionnels), plus concis, et activement développé. Objective-C s'apprend aujourd'hui surtout pour lire et maintenir du code existant, et pour comprendre les fondations. Les concepts que tu as vus — objets, messages, protocoles, gestion mémoire par références — se retrouvent dans Swift, souvent sous une forme plus moderne. Notre cours Swift est la suite naturelle.

Pour continuer

  • Installer Xcode (sur un Mac) et créer un petit projet en ligne de commande.
  • Lire du code Objective-C réel (les frameworks open source d'Apple, des projets GitHub) pour s'habituer aux idiomes.
  • Comparer une même classe en Objective-C et en Swift pour voir les correspondances.
  • Explorer le runtime Objective-C (objc/runtime.h) pour les curieux du fonctionnement interne.

Pièges fréquents

Piège fréquent

Croire qu'Objective-C est « mort » et inutile à apprendre. C'est faux pour qui travaille dans l'écosystème Apple : une grande partie du code en production, et du code des frameworks, est en Objective-C. Beaucoup de postes consistent justement à maintenir et faire évoluer cet existant, ou à faire le pont avec du Swift neuf. Savoir lire l'Objective-C reste une compétence demandée — même si on écrit du neuf en Swift.

Pour aller plus loin

Pour aller plus loin

Beaucoup d'idées de Swift sont des réponses directes aux limites d'Objective-C : les optionnels rendent explicite le nil (qui était silencieux), le typage fort remplace le id « tout objet », la syntaxe se débarrasse des crochets et des en-têtes séparés. Connaître Objective-C te fait donc comprendre pourquoi Swift est ce qu'il est : chaque nouveauté de Swift résout un problème que tu as rencontré ici. C'est la meilleure préparation à Swift qui soit.

Antisèche — l'écosystème

Glossaire

Xcode
Environnement de développement d'Apple, sur macOS : sert à écrire, compiler et tester l'Objective-C comme le Swift.
Swift
Langage moderne d'Apple (2014), recommandé pour les nouveaux projets ; conçu pour cohabiter avec Objective-C.
Interopérabilité
Capacité de deux langages à s'appeler mutuellement dans un même projet.
Bridging header
Fichier d'en-tête qui rend les classes Objective-C visibles depuis le code Swift.
-Swift.h
En-tête généré automatiquement qui expose au code Objective-C les classes Swift compatibles.
Clang / LLVM
La chaîne de compilation qui traduit Objective-C (et C, C++, Swift) en code machine.
Runtime Objective-C
Moteur dynamique du langage : envoi de messages, introspection, swizzling à l'exécution.
Legacy (existant)
Code déjà en production qu'on maintient et fait évoluer ; principal usage actuel d'Objective-C.

Récap et vérification

  • Xcode (sur macOS) est l'outil de développement Apple, pour Objective-C comme Swift.
  • Objective-C et Swift cohabitent (bridging header, -Swift.h) : modernisation progressive possible.
  • Objective-C reste utile : maintenance, frameworks, interop C/C++, runtime dynamique.
  • Pour du neuf : Swift ; Objective-C éclaire ses fondations et l'existant.

Exercices

Exercice 1Échauffement

Quel logiciel utilise-t-on pour développer en Objective-C sur Mac ?

Voir une solution

Xcode, l'environnement de développement gratuit d'Apple (disponible uniquement sur macOS).

Exercice 2Application

En une phrase, pourquoi apprendre Objective-C reste utile aujourd'hui ?

Voir une solution

Parce qu'une immense quantité de code Apple en production (applications et frameworks) est écrite en Objective-C : savoir le lire et le maintenir est indispensable pour travailler sur l'existant et faire le pont avec du Swift moderne.

Exercice 3Défi

Résume en trois points ce que la connaissance d'Objective-C t'apporte.

Voir une solution

Réponses possibles : (1) la capacité de lire et maintenir l'immense base de code Apple existante ; (2) une compréhension profonde des concepts (objets, messages, protocoles, gestion mémoire par références) qui irriguent tout l'écosystème ; (3) une préparation idéale à Swift, dont chaque nouveauté répond à une limite d'Objective-C que tu as vue de l'intérieur.
