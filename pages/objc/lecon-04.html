Module 2 · Objets et classes — Leçon 04

Classes : interface et implémentation

~55 min Avancé Prérequis : leçon 3

À la fin de cette leçon, tu sauras

  • déclarer une classe (@interface) ;
  • l'implémenter (@implementation) ;
  • comprendre les fichiers .h et .m ;
  • créer un objet (alloc/init).
Sommaire de la leçon

Jusqu'ici, on a utilisé des objets existants (NSString, NSArray). Apprenons maintenant à créer nos propres classes. Objective-C suit une convention héritée du C : il sépare la déclaration d'une classe (ce qu'elle offre) de son implémentation (comment elle le fait), dans deux fichiers distincts. Cette leçon t'apprend à définir une classe, à l'implémenter, et à en créer des objets.

Deux fichiers : .h et .m

Une classe Objective-C s'écrit traditionnellement en deux parties :

  • le fichier d'en-tête .h : l'interface publique — ce que les autres voient (@interface) ;
  • le fichier d'implémentation .m : le code réel des méthodes (@implementation).

Cette séparation rappelle les .h/.c du C, ou l'interface/corps de Pascal et Ada : l'extérieur connaît le quoi, pas le comment.

Déclarer une classe : @interface

Dans le .h, on déclare la classe, sa classe parente (après les deux-points), ses propriétés et les en-têtes de ses méthodes.

Personne : NSObject signifie que Personne hérite de NSObject, la classe racine de presque tout en Objective-C (elle fournit alloc, init…). Les lignes @property déclarent des attributs (leçon 5) ; les lignes commençant par - sont des en-têtes de méthodes d'instance.

Implémenter la classe : @implementation

Dans le .m, on fournit le code des méthodes déclarées.

On importe son propre en-tête (#import "Personne.h"), puis on écrit chaque méthode. Le mot self désigne l'objet courant (comme this ailleurs) : self.nom accède à sa propriété nom.

Cas réel

La méthode description n'est pas décorative : c'est elle qu'appellent NSLog(@"%@", monObjet) et le débogueur de Xcode quand tu inspectes une variable. Une classe qui redéfinit description pour renvoyer @"Personne(Ada, 36 ans)" au lieu de l'illisible <Personne: 0x600000abcd> se débogue infiniment plus vite : c'est un réflexe que suit tout le code Cocoa.

Le signe de la méthode : - et +

Chaque méthode commence par un signe qui indique sa nature :

  • - (tiret) — méthode d'instance : s'envoie à un objet ;
  • + (plus) — méthode de classe : s'envoie à la classe elle-même.

Puis vient le type de retour entre parenthèses ((void) si rien, (NSString *) si une chaîne…), puis le nom. On approfondira en leçon 5.

Créer un objet : alloc et init

Pour fabriquer un objet, deux étapes : alloc réserve la mémoire, init l'initialise. On les enchaîne, et on a un objet prêt.

L'expression [[Personne alloc] init] se lit de l'intérieur : [Personne alloc] crée un objet vierge, puis init le prépare. C'est l'idiome de création le plus courant — tu le verras des milliers de fois.

Le raccourci new

[Personne new] est exactement équivalent à [[Personne alloc] init] : un raccourci pratique quand l'initialiseur est le init par défaut, sans argument. Dès qu'on veut un initialiseur personnalisé (initWithNom:…), on revient à la forme alloc/init imbriquée.

Pièges fréquents

Piège fréquent

Utiliser alloc sans init (ou l'inverse). Les deux vont toujours ensemble : alloc seul donne un objet non initialisé, inutilisable ; init doit être appelé sur le résultat d'alloc. L'expression complète est [[Classe alloc] init]. Oublier l'un des deux mène à des plantages ou des objets dans un état incohérent.

Pour aller plus loin

Pour aller plus loin

On personnalise souvent l'initialisation avec un initialiseur dédié, par exemple - (instancetype)initWithNom:(NSString *)nom age:(int)age, qui crée un objet déjà rempli : [[Personne alloc] initWithNom:@"Ada" age:36]. Le type de retour instancetype indique « une instance de cette classe ». C'est le patron standard pour fournir des objets prêts à l'emploi, plus sûr que de remplir les propriétés une à une après coup.

Glossaire

@interface
Bloc du .h qui déclare une classe : son parent, ses propriétés, les en-têtes de ses méthodes.
@implementation
Bloc du .m qui contient le code des méthodes déclarées dans l'@interface.
En-tête (.h)
Fichier d'interface publique, importé par les autres fichiers : le « contrat » de la classe.
Héritage
Relation Personne : NSObject : la classe récupère les capacités de son parent et peut en ajouter.
NSObject
Classe racine de presque tout en Objective-C ; fournit alloc, init, description…
alloc / init
alloc réserve la mémoire d'un objet vierge ; init l'initialise. On les enchaîne : [[X alloc] init].
self
Dans une méthode, référence l'objet courant sur lequel le message a été reçu.
instancetype
Type de retour d'un initialiseur signifiant « une instance de cette classe », plus précis que id.

Récap et vérification

  • Une classe se sépare en .h (@interface, public) et .m (@implementation, code).
  • : NSObject indique l'héritage ; self désigne l'objet courant.
  • Méthodes : - d'instance, + de classe ; type de retour entre parenthèses.
  • Créer un objet : [[Classe alloc] init] (les deux toujours ensemble).
