Module 04 · Responsive & dynamique — Leçon 11

Le responsive (media queries)

~34 min Débutant Module 3 recommandé

À la fin de cette leçon, tu sauras

  • comprendre le rôle de la balise viewport et du responsive ;
  • écrire une media query avec @media (min-width: …) ;
  • adopter l'approche mobile-first et choisir des points de rupture selon le contenu ;
  • limiter les media queries grâce aux unités fluides comme %, fr et la grille.
Sommaire de la leçon

Sur ton téléphone, ta tablette et ton ordinateur, l'écran n'a pas du tout la même largeur. Une page bien construite ne montre pas la même mise en page partout : elle s'adapte. Une seule colonne sur mobile, deux ou trois sur un grand écran. C'est ça, le responsive : un même fichier HTML, un même CSS, mais un rendu qui se réorganise selon la place disponible.

Dans cette leçon, tu vas découvrir l'outil clé du responsive : les media queries. Tu apprendras aussi la bonne méthode (le mobile-first) et tu verras que parfois… une simple unité fluide suffit, sans aucune media query.

Les media queries

Une media query est un bloc de CSS qui ne s'applique que si une condition est vraie — par exemple, à partir d'une certaine largeur de fenêtre. La syntaxe ressemble à une règle normale, mais englobée dans un @media :

Lis ça comme une phrase : « si la fenêtre fait au moins 768 px, alors applique ces règles ».

Deux conditions reviennent sans cesse :

  • min-width : « à partir de cette largeur » → on agrandit progressivement.
  • max-width : « jusqu'à cette largeur » → on part du grand écran et on rétrécit.

On va voir tout de suite pourquoi min-width est presque toujours le bon choix.

L'approche mobile-first

« Mobile-first » signifie : tu écris d'abord le style du mobile, en dehors de toute media query (ce sont tes styles par défaut). Puis, avec des @media (min-width: …), tu ajoutes ce qu'il faut quand l'écran grandit.

L'avantage : le mobile, le plus contraint, reçoit le CSS le plus simple. Les écrans larges, qui ont de la place, reçoivent les ajouts. On va du connu (une colonne) vers l'inconnu (plusieurs colonnes).

Le mobile a la version simple ; on enrichit ensuite vers le haut.

Cas réel

Plus de la moitié du trafic web vient des mobiles. C'est pourquoi les équipes conçoivent d'abord pour le téléphone (mobile-first), puis enrichissent pour les grands écrans. Google lui-même indexe surtout la version mobile d'un site : une page qui « casse » sur téléphone est pénalisée dans les résultats.

Choisir ses points de rupture

Un point de rupture (breakpoint) est la largeur à laquelle ta mise en page change. La tentation, c'est de viser des appareils précis (« 375 px pour l'iPhone, 768 px pour l'iPad… »). Mauvaise idée : il existe des centaines de tailles d'écran et de nouvelles sortent chaque année.

La bonne méthode : élargis la fenêtre de ton navigateur lentement et observe ta page. Dès qu'elle devient laide ou inconfortable (texte trop long, éléments à l'étroit), tu poses un point de rupture là. Tu choisis selon le contenu, pas selon le téléphone du voisin.

Note

Des valeurs comme 600px, 768px ou 1024px reviennent souvent : ce sont des repères pratiques, pas des règles obligatoires. L'important est que ça serve ton contenu.

Les unités fluides : moins de media queries

Souvent, on n'a même pas besoin d'une media query : une unité fluide s'adapte toute seule. Tu en connais déjà plusieurs :

  • % : une largeur relative au parent (50 % du conteneur, quelle que soit sa taille).
  • fr : en grid, partage l'espace disponible en fractions souples.
  • clamp() : une valeur qui s'adapte entre un minimum et un maximum (on la verra en détail en leçon 13).

Et la grille a un super-pouvoir : avec auto-fill et minmax(), elle calcule seule le nombre de colonnes qui tiennent. Zéro media query :

minmax(150px, 1fr) : chaque colonne fait au moins 150 px ; la grille en met autant que la largeur permet.

Avant d'écrire une media query, demande-toi toujours : « est-ce qu'une unité fluide ne ferait pas le travail toute seule ? »

Pièges fréquents

Piège fréquent

Oublier la balise viewport. Sans <meta name="viewport"…>, le mobile affiche ta page « dézoomée » et tes media queries ne se déclenchent jamais. C'est l'erreur n°1 : vérifie-la en premier si ton responsive ne marche pas.

Piège fréquent

Partir desktop-first (tout en max-width) est plus dur à maintenir : tu dois « défaire » des styles à chaque écran plus petit. Viser des appareils précis ou mettre une media query là où un % ou un fr suffirait alourdissent ton CSS pour rien.

Glossaire

Responsive
Une page qui s'adapte à la taille de l'écran (mobile, tablette, ordinateur).
viewport
Meta HTML indispensable pour que le mobile utilise sa vraie largeur (et non un faux écran large).
Media query
Bloc @media appliqué seulement si une condition (largeur, préférence…) est vraie.
min-width / max-width
« À partir de » / « jusqu'à » une largeur de fenêtre.
Mobile-first
Écrire le style mobile par défaut, puis ajouter via min-width pour les grands écrans.
Point de rupture (breakpoint)
Largeur à laquelle la mise en page change ; à choisir selon le contenu.
Unité fluide
Valeur qui s'adapte seule (%, fr, clamp()), évitant des media queries.
prefers-color-scheme
Condition media qui détecte si l'utilisateur préfère le thème sombre ou clair.

Récap et vérification

  • Le responsive = une même page qui se réorganise selon la largeur d'écran.
  • La balise <meta name="viewport"…> est indispensable.
  • Une media query applique du CSS sous condition : @media (min-width: 768px) { … }.
  • Mobile-first : style mobile par défaut, puis on ajoute avec min-width.
  • On choisit les points de rupture selon le contenu, pas selon des appareils.
  • Les unités fluides (%, fr, minmax()) évitent beaucoup de media queries.
