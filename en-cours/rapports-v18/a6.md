## 3. Ce que le passage a trouvé, et chaque correction avec sa preuve sur les deux formes

### 3.1 Les motifs multilignes : 34 fautes sur 153, dans cinq épreuves (commit `7811129`)

Cause : un motif qui porte sur deux lignes ou plus, écrit avec un simple `"\n"`, ne se trouve pas
dans un fichier en CRLF. Exactement le défaut corrigé deux fois à la main (`vexec` le
2026-09-10, `vexancr` au F1 du V16).

Correction : la parade vit désormais **une fois**, dans **`tools/lib/motif-souple.js`** (motif
cherché avec `\r?\n`, faute injectée avec les fins de ligne du fichier, remplacement par une
fonction pour qu'un `$&` ne soit pas interprété ; l'original reste restauré par chaque épreuve, à
l'octet près). Branchée dans `verif-execution-liens-mutations.js`, `verif-git-modele-mutations.js`,
`verif-git-graphe-mutations.js`, `verif-git-scenarios-mutations.js` (y compris la règle « motif
unique », comptée avec la même souplesse) et `verif-git-commandes-mutations.js`. Le module est
classé « autre » par `recense-chaine.js` (ni `verif-`, ni `preuves/`, ni `-mutations`) : aucune
déclaration hors chaîne n'est nécessaire.

Et **un témoin** dans les quatre épreuves git : elles comptaient « détectée » toute faute dont le
code de sortie n'est pas nul, si bien qu'un vérificateur cassé par le CRLF aurait fait passer
toutes leurs fautes pour vues. Chacune lance d'abord son vérificateur sur une copie **intacte**,
posée comme les copies mutées, et sort en 2 s'il n'est pas vert.

Preuves :
- contrôle à sec avec le module : **211 fautes sur 211** trouvées et posées sur les deux formes,
  0 faute qui ne change rien, 0 LF nu ajouté à un fichier CRLF ;
- vérificateur factice : tableau du § 2 ;
- passages réels : § 4.
