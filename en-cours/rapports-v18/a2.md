### 2. Les durcissements, et ce qui les a rendus nécessaires

1. **Une faute n'est « vue » que si la preuve la NOMME.** Le script V16 comptait toute sortie en
   code 1 (`if (r.code === 1) vues++`). Or les deux preuves rougissent aussi **sans aucune faute**
   quand la machine est chargée (mesures plus bas) : `git-graphe.js` sort en 1 **avant d'avoir lu
   les tables**, et `decodeur-lecons.js` écrit « AUCUN encart » pour une page lente. Chaque faute
   porte donc le message que la preuve doit imprimer (`attendu`) ; code 1 sans ce message =
   « rouge pour une autre raison » : relance, **5 tentatives au plus, chacune imprimée avec la fin
   de la sortie**, puis la faute compte comme **non vue**. Les témoins ont la même relance. Chaque
   message attendu doit être **absent de la sortie du témoin**, sinon il ne prouverait rien.
   Relancer ne peut pas faire passer une faute pour vue : seul son message le peut.
2. **Un message `interdit`**, qui annule le verdict s'il est imprimé. Ajouté pour la faute 4 (« la
   table n'est plus jamais consultée ») après qu'un **témoin** a montré, sous charge, que
   `decodeur-lecons.js` écrit « AUCUN encart » sans aucune faute. Le premier message attendu de la
   faute 4, « (hors index) : AUCUN encart du décodeur », était donc imitable par une page lente (la
   preuve l'écrit alors suivi de « — page jamais prête en 15 s ») : une faute 4 inopérante aurait pu
   être comptée vue. Il exige désormais la vraie signature de la faute — **toutes** les leçons de la
   table perdent leur encart (`leçons hors index (table D2) : 0 / N`) — et refuse « page jamais
   prête ». Les autres fautes n'en ont pas besoin : leurs messages viennent de la lecture statique
   des tables (1, 2, 3, 6, 7, 9), d'un encart lu en entier (5), ou d'une mesure qui rend `null` tant
   que la page n'est pas prête (8).
3. **Motifs robustes aux fins de ligne.** Parade `motifSouple` de `verif-execution-mutations.js`
   (`\r?\n` dans le motif) ; remplaçante écrite avec les fins de ligne **du fichier** (détection
   comme dans `execution-ancres-mutations.js`, et non `\r\n` forcé comme dans
   `verif-execution-mutations.js`) ; remplacement par une **fonction** (une chaîne interpréterait
   `$&`). **Avant tout lancement**, chaque faute est posée à sec sur trois versions du fichier — le
   disque, une version LF, une version CRLF — et doit s'y poser **exactement une fois**, changer le
   texte, y laisser la remplaçante, **sans mélanger** les fins de ligne. Sinon : NON APPLICABLE.
   `--a-sec` ne fait que cela (sans Chrome, sans rien écrire).
4. **Restauration à l'octet** : les octets lus sont gardés tels quels (Buffer, pas une chaîne
   réencodée), restaurés sur `exit`, `SIGINT`, `SIGTERM`, `SIGHUP`, `SIGBREAK` et exception non
   rattrapée ; l'égalité des octets est vérifiée **après chaque faute** et à la fin.
5. **Un verdict qui dit ce qui est arrivé.** Trouvé par l'épreuve de l'épreuve (contrôle 3) : la
   première version écrivait « … à chacune des 5 tentatives » en étendant la cause de la dernière
   tentative aux autres, alors que l'une d'elles avait rendu un code 2. Le verdict compte désormais
   les causes réellement survenues (« 5 × rouge pour une autre raison », « 4 × …, 1 × code 2 »).

Deux options : `--seules=6,9` (ne jouer que ces fautes ; les témoins tournent toujours) et
`--controle` (ajoute quatre fautes **sentinelles**, numérotées 10 à 13, qui doivent faire rougir
l'épreuve — l'épreuve de l'épreuve).
