## 1. Le contrôle statique : `tools/verif-domaines-interdits.js`

**Ce qu'il lit** : tout ce que le site sert ou distribue — `pages/**`, `index.html`, `sw.js`,
`js/**`, `css/**`, `assets/**`, `starter/**` — en `.html`, `.htm`, `.svg`, `.css`, `.js`, `.json`,
`.webmanifest`. Les `.md` (dont les deux README de Prism qui citent `cdnjs.cloudflare.com` comme
provenance), les polices et les licences ne sont pas lus : le navigateur ne les charge jamais
comme du code.

**Ce qu'il retient**, en lisant le fichier comme le navigateur : une URL (`//`, avec ou sans
schéma, puis l'hôte interdit ou un sous-domaine)
- dans **n'importe quel attribut d'une balise réelle** (un `<` suivi d'une lettre, hors
  commentaire) : `href`, `src`, `srcset`, `content`, `data-*`… ; `style` est lu comme du CSS,
  `on*` comme du JS ; les entités (`&#46;`, `&period;`…) sont décodées ;
- dans le contenu des `<script>` **exécutables** (sans type, `text/javascript`, `module`…, et
  `importmap`) et des `<style>` ;
- dans les `<script type="application/json">` (QCM, exercices), **seulement** sous une clé qui
  fabrique un lien (`href`, `src`, `url`…) : tout le reste y est échappé au rendu par
  `escapeHTML` (`js/lecon.js`, l. 159) ;
- dans les fichiers CSS (commentaires retirés), JS, JSON et `.webmanifest` (entiers, `\/` décodé).

**Ce qu'il écarte, en le comptant** : le texte des pages (prose, `<pre><code>` échappé), les
commentaires HTML, le contenu de `<textarea>`, `<title>`, `<iframe>`. Un `fonts.googleapis.com/x`
**sans** `//` est un chemin relatif (un fichier local en `file://`), pas un appel au réseau.

**Choix assumé** : dans un JS, un commentaire qui écrit l'URL complète est signalé. Retirer les
commentaires sans analyseur complet est dangereux (un `//` naïf coupe le `https://` d'une chaîne
et ferait disparaître la référence) : un faux rouge visible vaut mieux qu'un faux vert. Aucun JS
servi n'en contient aujourd'hui.

**Mesure sur l'arbre propre** (`node tools/verif-domaines-interdits.js`, code **0**, 0,717 s au
repos) :

## 8. Ce qui reste ouvert ou incertain

- **Ce que le statique ne voit pas** : une URL **calculée** (`"https://fonts." +
  "googleapis.com"`), un hôte encodé en `%xx`, un mot coupé par une entité
  (`goo&#103;leapis`) — ce dernier parce qu'un préfiltre par mots (`googleapis`, `gstatic`,
  `cloudflare`, `cdnjs`) écarte d'abord les fichiers qui ne les contiennent pas. C'est le rôle de
  la sonde, mais elle ne visite que **13 pages** (celles des blocs réseau), pas les 1 540 leçons.
- **La sonde ne voit pas un `dns-prefetch`** (§ 6), par construction.
- **Commentaires** : un commentaire HTML qui contient une `<link>` n'est pas signalé (ce n'est
  pas une balise réelle : consigne « balises et attributs réels seulement ») — témoin N4 ; un
  commentaire **JS** qui écrit l'URL l'est (§ 1, choix assumé).
- **`<script>` d'un type inconnu** (`text/plain`, `text/template`…) : ni exécuté ni lu comme
  données ; s'il contient une de ces URL, l'outil imprime « ⚠ non jugé » sans échouer. Aucun
  aujourd'hui.
- **Compteurs écrits à la main dans l'en-tête de `tools/verif.js`** (« 53 étapes » en rapide,
  71, 81, « 16 épreuves ») : périmés par ce seul point (54, 72, 82, 17, relus par
  `node tools/verif-chaine-declaree.js`, code 0). Je ne les ai pas touchés : A1 et A2 ajoutent
  eux aussi des étapes, le bon chiffre ne se connaît qu'après la fusion.
- **`--rapide` n'a pas été vert** sur cette copie : deux passages, code 1 les deux fois (854,1 s
  puis 1 753,1 s). Au second, 52 étapes sur 54 OK ; les deux rouges (`etudes`, `etude-6`) ont une
  cause prouvée étrangère à A3 et présente sur master extrait en LF (§ 7). `domaine` est OK dans
  les deux passages (5,4 s et 17,3 s).
- **Je n'ai pas lancé `--complet`** (la règle du plan le demande pour les points qui touchent la
  chaîne) : sous cette charge, `--rapide` seul a pris 29 min, et `--complet` mesurait 5 576,3 s au
  repos au F1 du V16. Ce que A3 ajoute à `--complet` est déjà joué ailleurs : `domaine` (dans tous
  les modes) et `clic-net` (trois passages verts par `--strict` et en direct, § 5).
