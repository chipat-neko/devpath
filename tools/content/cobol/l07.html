La vraie raison d'être de COBOL, c'est de traiter de gros volumes de données stockées dans des fichiers : relevés de comptes, paies, factures. Cette leçon t'apprend à déclarer, lire et écrire un fichier séquentiel — et la fameuse boucle de lecture, squelette de tout programme de traitement.

Associer un fichier : SELECT

Dans la division ENVIRONMENT, la section FILE-CONTROL relie un nom logique (utilisé dans le programme) à un fichier physique (sur le disque).

LINE SEQUENTIAL = un fichier texte, une ligne par enregistrement.

Décrire l'enregistrement : FD

Dans la FILE SECTION de la division DATA, la FD (File Description) décrit la structure d'un enregistrement du fichier.

Ouvrir, lire, fermer

On ouvre le fichier (OPEN INPUT pour lire), on lit avec READ, on ferme avec CLOSE. La clause AT END détecte la fin du fichier.

La boucle de lecture

Voici le patron universel du traitement de fichier : lire un premier enregistrement, puis boucler tant qu'on n'est pas à la fin, en traitant puis relisant. On utilise un indicateur de fin.

Ce schéma — ouvrir, boucler en lisant jusqu'à AT END, fermer — revient dans des milliers de programmes.

Écrire dans un fichier

Pour produire un fichier, on l'ouvre en OUTPUT, on remplit l'enregistrement, puis on WRITE.

Pour ajouter à un fichier existant sans l'écraser, on l'ouvre en EXTEND.

Pièges fréquents

Piège fréquent

Traiter l'enregistrement après avoir atteint la fin de fichier : à AT END, l'enregistrement ne contient plus de données valides. La clause NOT AT END garantit qu'on ne traite que les lectures réussies.

Pour aller plus loin

Pour aller plus loin

La variable FILE STATUS (déclarée dans le SELECT) reçoit un code après chaque opération de fichier : « 00 » = succès, « 10 » = fin de fichier, etc. Le code de production la teste systématiquement pour une gestion d'erreur robuste.

Récap et vérification

  • SELECT … ASSIGN relie un nom logique à un fichier physique ; la FD décrit l'enregistrement.
  • OPEN INPUT/OUTPUT/EXTEND, READ (avec AT END), WRITE, CLOSE.
  • La boucle de lecture (lire, traiter jusqu'à AT END) est le patron universel.
  • Un indicateur de fin (niveau 88) pilote proprement la boucle.

Vérifie ta compréhension

  1. Où relie-t-on le nom logique au fichier physique ?
  2. Que détecte la clause AT END ?
  3. Pourquoi traiter l'enregistrement sous NOT AT END ?
