Pour traiter des séries de données — douze montants mensuels, une liste de codes, un barème — COBOL utilise des tables, son nom pour les tableaux. La clause OCCURS les déclare, et on les parcourt avec le PERFORM VARYING vu à la leçon précédente. Les tables sont au cœur des traitements de gestion.

Déclarer une table avec OCCURS

OCCURS n TIMES répète un champ n fois. La table est décrite une fois ; COBOL réserve la place pour toutes les occurrences.

On a douze champs MOIS-VENTE, accessibles par un indice de 1 à 12.

Accéder à un élément

On indique l'indice entre parenthèses. Attention : en COBOL, les indices commencent à 1, pas à 0.

Parcourir une table

Le couple OCCURS + PERFORM VARYING est l'idiome de base : on fait varier un indice et on traite chaque élément.

Tables de structures

Un élément de table peut être un groupe : on modélise ainsi une liste d'enregistrements (par exemple un barème produit).

Rechercher avec SEARCH

Pour trouver un élément, SEARCH parcourt la table jusqu'à une correspondance. La table doit avoir un index déclaré (INDEXED BY).

SEARCH avance l'index jusqu'à la condition ; AT END gère le cas « non trouvé ».

Pièges fréquents

Piège fréquent

Dépasser les bornes de la table : accéder à MOIS-VENTE (13) d'une table de 12 corrompt la mémoire voisine, souvent sans erreur immédiate. Vérifie toujours que ton indice reste dans l'intervalle 1 à n.

Pour aller plus loin

Pour aller plus loin

Pour une table triée, SEARCH ALL effectue une recherche dichotomique (bien plus rapide qu'un parcours), à condition de déclarer la clé avec ASCENDING KEY. Un détail de performance qui compte sur de grandes tables.

Récap et vérification

  • OCCURS n TIMES déclare une table ; les indices commencent à 1.
  • On accède par indice : MOIS-VENTE (I).
  • PERFORM VARYING parcourt la table ; un élément peut être un groupe.
  • SEARCH (ou SEARCH ALL dichotomique) recherche un élément.

  2. Quelle clause déclare une table ?
  3. Quelle différence entre SEARCH et SEARCH ALL ?
