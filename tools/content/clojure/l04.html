Clojure repose sur quatre collections fondamentales : les listes, les vecteurs, les maps et les sets. Les maîtriser, c'est tenir l'essentiel du langage, car presque tout programme manipule des données structurées. Particularité majeure : ces collections sont immuables. On ne les modifie jamais ; on en dérive de nouvelles versions. Cette leçon les présente une à une.

Les listes

La liste est la structure historique du Lisp : une séquence chaînée, entre parenthèses. Comme une liste évaluée serait un appel, on la quote pour en faire une donnée.

Les listes sont optimisées pour l'ajout en tête. Pour des accès indexés, on préfère les vecteurs.

Les vecteurs : la collection du quotidien

Le vecteur, entre crochets [], est la collection la plus utilisée : accès rapide par index, ajout en queue efficace. C'est l'équivalent des tableaux/listes d'autres langages.

Détail élégant : un vecteur est lui-même une fonction de son indice. ([10 20 30] 1) renvoie 20. Et conj (« conjoindre ») ajoute là où c'est efficace : en queue pour un vecteur, en tête pour une liste.

Les maps : associer clé et valeur

La map, entre accolades {}, associe des clés à des valeurs — souvent avec des keywords pour clés. C'est la structure reine pour représenter un « objet » (une personne, une config…).

Trois façons équivalentes d'accéder à :nom. La plus idiomatique : (:nom ada) — le keyword sait se chercher lui-même dans une map. Une clé absente renvoie nil (ou la valeur par défaut fournie).

« Modifier » une map sans la modifier

Puisque tout est immuable, assoc et dissoc renvoient une nouvelle map ; l'originale est intacte.

update applique une fonction à une valeur existante : (update ada :age inc) incrémente l'âge. On ne mute rien ; on construit une version dérivée.

Les sets : des ensembles sans doublon

Le set, noté #{}, est une collection sans doublon, idéale pour tester l'appartenance.

Imbriquer les structures

Les collections se composent librement. Pour atteindre une valeur profonde, get-in ; pour la « modifier », assoc-in ou update-in.

Pièges fréquents

Piège fréquent

Croire qu'assoc modifie la map d'origine. Il ne la modifie jamais : il renvoie une nouvelle valeur. Si tu écris (assoc ada :age 37) sans réutiliser le résultat, le changement est perdu. Pense toujours : « je dérive une nouvelle valeur, je la nomme ou la passe ailleurs ».

Pour aller plus loin

Pour aller plus loin

Le polymorphisme de conj illustre une philosophie : il ajoute « à l'endroit naturel » de chaque structure (tête de liste, queue de vecteur). Beaucoup de fonctions Clojure agissent ainsi sur l'abstraction commune des collections plutôt que sur un type précis — c'est ce qui rend le langage si uniforme. On verra à la leçon 5 l'abstraction « séquence » qui unifie tout cela.

Récap et vérification

  • Liste '( ) (ajout en tête), vecteur [ ] (index, ajout en queue).
  • Map { } (clé→valeur) ; (:cle m) pour accéder, assoc/update pour dériver.
  • Set #{ } (sans doublon) ; contains? pour tester.
  • Tout est immuable : ces fonctions renvoient une nouvelle valeur.

Vérifie ta compréhension

  1. Quelle collection choisir pour un accès rapide par index ?
  2. Que renvoie (:nom {:nom "Ada"}) ?
  3. Après (assoc m :x 1), m a-t-elle changé ?
