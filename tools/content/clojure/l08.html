Nous arrivons à ce qui fait l'aura particulière des Lisps, et de Clojure en particulier : les macros. Elles permettent d'étendre le langage lui-même, d'écrire du code qui écrit du code. Dans le même temps, comme Clojure vit sur la JVM, il dialogue sans friction avec tout l'univers Java : des millions de bibliothèques à portée de main. Cette leçon relie ces deux superpouvoirs.

Rappel : code = données

On l'a vu en leçon 2 : une expression Clojure est une structure de données (une liste). (+ 1 2) est une liste de trois éléments : le symbole +, puis 1 et 2. Cette propriété — l'homoiconicité — signifie qu'un programme peut manipuler du code comme de la donnée avant qu'il ne soit exécuté. C'est précisément ce que font les macros.

Fonction ou macro ?

Une fonction reçoit des valeurs déjà évaluées. Une macro reçoit le code non évalué (sous forme de données), le transforme, et renvoie un nouveau code qui sera ensuite évalué à sa place. La macro agit donc avant l'exécution, à la compilation.

Beaucoup de « mots-clés » de Clojure (when, cond, ->, or…) ne sont pas câblés dans le langage : ce sont des macros écrites en Clojure. Le langage s'étend largement avec ses propres moyens.

Définir une macro simple

On définit une macro avec defmacro. À l'intérieur, on construit le code à produire. La quasi-quote ` (backtick) crée un gabarit de code ; ~ y insère une valeur calculée.

~@ (unquote-splicing) déverse une séquence d'expressions dans le gabarit. macroexpand révèle le code produit — outil précieux pour comprendre et déboguer une macro.

Quand écrire une macro ?

Les macros sont puissantes mais à manier avec parcimonie. La règle communautaire : n'écris une macro que si une fonction ne suffit pas. On a besoin d'une macro seulement quand il faut contrôler l'évaluation — par exemple ne pas évaluer un argument, ou introduire une nouvelle forme syntaxique. Pour tout le reste, une fonction est plus simple et composable.

Pièges fréquents

Piège fréquent

Abuser des macros. Comme elles agissent à la compilation et ne sont pas des valeurs ordinaires, on ne peut pas les passer à map ou les composer comme des fonctions. Le réflexe du débutant enthousiaste — « tout en macros ! » — produit du code rigide et difficile. Garde-les pour les cas où contrôler l'évaluation est réellement nécessaire ; préfère les fonctions partout ailleurs.

Pour aller plus loin

Pour aller plus loin

Le piège classique des macros est la capture de variable : un nom introduit par la macro qui entre en collision avec le code de l'utilisateur. Clojure y répond avec les symboles auto-générés via # (par ex. x# dans une quasi-quote), qui produisent un nom unique garanti. C'est l'hygiène des macros ; à explorer quand tu écriras des macros non triviales.

Récap et vérification

  • Macro : reçoit du code non évalué, le réécrit, agit à la compilation (defmacro, `, ~, ~@).
  • macroexpand montre le code généré ; n'écris une macro que si une fonction ne suffit pas.
  • Interop Java : Classe/methode, (Classe. …), (.methode obj …).
  • Accès complet à l'écosystème JVM : la force industrielle de Clojure.
