Avant la concurrence, il faut connaître la matière de base d'Erlang : ses données et le mécanisme qui les manipule, le pattern matching (filtrage par motif). Ce dernier est si central qu'il remplace à la fois l'affectation, la déstructuration et une partie du contrôle de flux. Bien le comprendre, c'est tenir l'une des clés du langage. Cette leçon explore les types de données et cette opération fondamentale.

Les types de base

Erlang propose un petit ensemble de types essentiels :

  • les nombres : entiers (de taille illimitée !) et flottants ;
  • les atomes : des constantes symboliques en minuscule (ok, error, true) ;
  • les tuples : des groupes de taille fixe, entre accolades ({1, 2, 3}) ;
  • les listes : des suites de taille variable, entre crochets ([1, 2, 3]) ;
  • les chaînes : en réalité des listes de codes de caractères.

Les atomes : des étiquettes constantes

Un atome est une valeur qui ne représente qu'elle-même : ok, error, undefined. On les utilise comme étiquettes ou drapeaux. C'est l'équivalent des symboles d'autres langages : deux atomes identiques sont la même valeur, comparables instantanément.

Ce patron {ok, Valeur} / {error, Raison} est omniprésent en Erlang : une fonction renvoie un tuple étiqueté qui dit si elle a réussi, et porte le résultat ou la cause de l'échec.

Les variables immuables

Une variable Erlang commence par une majuscule. Et — particularité déroutante — elle ne peut être liée qu'une seule fois : une fois qu'elle a une valeur, on ne peut plus la changer. Il n'y a pas de réaffectation.

Cette immuabilité totale surprend, mais elle est cohérente avec l'esprit fonctionnel : une variable est un nom pour une valeur, pas une boîte qu'on remplit et vide. C'est ce qui rend la concurrence sûre (leçon 1).

Le pattern matching avec =

Voici le concept central. En Erlang, le signe = n'est pas une affectation : c'est un filtrage par motif. Il tente de rendre les deux côtés identiques ; si la variable de gauche est libre, elle se lie à la valeur de droite ; si elle est déjà liée, il vérifie l'égalité.

Cette opération unique sert donc à la fois à lier une variable et à tester une valeur. C'est plus puissant qu'une simple affectation.

Déstructurer avec le pattern matching

La vraie magie : on peut filtrer des structures entières et extraire leurs morceaux en une seule opération.

La notation [T | Q] (tête | queue) est l'outil de base pour parcourir les listes par récursion (leçon 3). Le souligné _ est la variable anonyme : « peu importe ».

Pièges fréquents

Piège fréquent

Vouloir « réutiliser » une variable comme dans un langage impératif : X = 1, X = X + 1 échoue, car X est déjà lié à 1 et ne peut valoir 2. En Erlang, on introduit une nouvelle variable (X1, Compteur2…) à chaque étape. C'est inhabituel mais cohérent : les valeurs ne changent pas, on en nomme de nouvelles.

Pour aller plus loin

Pour aller plus loin

Erlang dispose aussi des maps (#{cle => valeur}), des structures clé-valeur ajoutées plus tard au langage, qui complètent tuples et listes pour modéliser des données plus riches. Et pour les données binaires (paquets réseau, protocoles), la syntaxe des binaries (<<...>>) permet de découper des octets avec une précision chirurgicale — un atout pour les télécoms, le domaine d'origine du langage.

Récap et vérification

  • Types : nombres, atomes (minuscule), tuples {}, listes [].
  • Patron {ok, V} / {error, R} omniprésent ; variables en majuscule, liées une seule fois.
  • = est un filtrage par motif : lie si libre, vérifie si déjà liée.
  • On déstructure tuples et listes par motif ; [T | Q] sépare tête et queue ; _ ignore.

Vérifie ta compréhension

  1. Que se passe-t-il si on lie deux fois une variable à des valeurs différentes ?
  2. Que valent T et Q dans [T|Q] = [1,2,3] ?
  3. À quoi sert le patron {error, Raison} ?
