F# brille dans le traitement de données : transformer, filtrer, agréger des jeux de données avec des pipelines lisibles. Et il offre une fonctionnalité quasi unique, les type providers, qui apportent le typage statique jusqu'aux sources de données externes. C'est un atout majeur en data science et en intégration.

Les pipelines de données

Le style pipeline (|>) est parfait pour enchaîner des transformations sur des données. On lit la chaîne comme une suite d'étapes.

List.sumBy additionne une projection ; List.averageBy, List.maxBy existent aussi.

Grouper et agréger

Le pattern « regrouper puis calculer » : List.groupBy partitionne par clé, puis on agrège chaque groupe.

Les type providers

Fonctionnalité signature de F# : un type provider génère des types à la compilation à partir d'une source externe (un fichier CSV, une base de données, une API JSON). Tu obtiens l'autocomplétion et la vérification de types sur des données qui n'existent pourtant qu'à l'extérieur.

Si le CSV a une colonne Montant de nombres, le provider crée un champ Montant de type float. Une faute de frappe sur un nom de colonne ? Erreur de compilation. Du jamais-vu dans la plupart des langages.

F# en data science

F# est apprécié en analyse de données : pipelines clairs, immuabilité (reproductibilité), accès aux bibliothèques .NET de calcul (Math.NET) et de machine learning (ML.NET). Les notebooks .NET Interactive permettent d'explorer des données en F# de façon interactive.

Vers le web : Fable

Fable compile F# vers JavaScript : on écrit le front-end web en F# (avec Elmish, une architecture inspirée de React/Elm). On peut ainsi partager des types et de la logique entre le serveur (.NET) et le navigateur (JS), tout en F#.

Pièges fréquents

Piège fréquent

Construire un pipeline avec des listes sur de très gros volumes : chaque étape crée une nouvelle liste en mémoire. Pour de gros flux, utilise Seq (paresseux) : les transformations s'enchaînent sans matérialiser les étapes intermédiaires.

Pour aller plus loin

Pour aller plus loin

Les type providers existent pour quantité de sources : SQL (le schéma de la base devient des types), JSON, XML, services REST… C'est l'une des raisons pour lesquelles F# est si productif en intégration de données : la frontière avec l'extérieur devient typée et sûre.

Récap et vérification

  • Les pipelines (|>) transforment, filtrent et agrègent les données lisiblement.
  • List.groupBy + agrégation pour le « regrouper puis calculer ».
  • Les type providers typent des sources externes (CSV, SQL, JSON) à la compilation.
  • F# en data science (ML.NET, notebooks) et au web (Fable vers JS) ; Seq pour les gros flux.
