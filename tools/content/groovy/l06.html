Groovy étant un langage objet sur la JVM, on y définit des classes comme en Java — mais avec beaucoup moins de cérémonie. Les POGO (Plain Old Groovy Objects) génèrent automatiquement accesseurs et constructeurs, ce qui élimine des pages de code répétitif. Et Groovy te laisse choisir, classe par classe, entre la souplesse du typage dynamique et la sécurité du typage statique. Cette leçon couvre l'objet en Groovy.

Définir une classe

Une classe Groovy ressemble à une classe Java, en plus léger. On déclare des propriétés (des champs) et des méthodes.

Pas de public partout, pas de getters/setters à écrire : Groovy s'en charge. On accède aux propriétés avec un simple point.

Les POGO : accesseurs automatiques

Un POGO (Plain Old Groovy Object) est une classe dont les propriétés bénéficient automatiquement de getters et setters générés. Quand tu écris p.nom, Groovy appelle en réalité getNom() ; p.nom = "Ada" appelle setNom("Ada"). Tu profites de l'encapsulation sans écrire le code.

Remarque le constructeur par map : new Produit(nom: "...", prix: ...). Groovy permet d'initialiser n'importe quel POGO en nommant ses propriétés, sans déclarer de constructeur. Très pratique.

L'héritage

L'héritage fonctionne comme en Java, avec extends. Une classe enfant hérite des propriétés et méthodes du parent.

Typage dynamique vs statique

Par défaut, Groovy est dynamique : les types sont vérifiés à l'exécution, ce qui offre flexibilité et métaprogrammation (leçon 7), au prix d'une moindre sécurité et de performances. Pour un code critique, on peut activer le typage statique avec l'annotation @CompileStatic : Groovy vérifie alors les types à la compilation, comme Java, et génère du bytecode plus rapide.

C'est un choix précieux : souplesse dynamique pour les scripts et les DSL, rigueur statique pour le code de production où l'on veut performance et détection précoce des erreurs.

Pièges fréquents

Piège fréquent

Écrire des getters/setters à la main « par habitude de Java » alors que Groovy les génère. Si tu déclares String nom dans une classe, n'écris pas aussi getNom()/setNom() : c'est redondant, et tu perds tout l'intérêt des POGO. Déclare juste la propriété ; n'ajoute un accesseur explicite que si tu veux un comportement spécial (validation, calcul). Laisse Groovy faire le reste.

Pour aller plus loin

Pour aller plus loin

Groovy offre des annotations de transformation qui génèrent encore plus de code pour toi : @ToString crée une méthode d'affichage lisible, @EqualsAndHashCode l'égalité, @Immutable une classe immuable complète, @Canonical combine tout cela. Une classe de données qui demanderait 50 lignes en Java se réduit à quelques lignes annotées. C'est la philosophie Groovy poussée à son terme : le langage écrit le code répétitif à ta place.

Récap et vérification

  • Les classes Groovy sont légères ; on accède aux propriétés par le point (p.nom).
  • Les POGO génèrent getters/setters ; constructeur par map (new C(a: 1)).
  • Un getter explicite crée une propriété calculée ; héritage avec extends.
  • Dynamique par défaut ; @CompileStatic pour le typage statique (sécurité, performance).
