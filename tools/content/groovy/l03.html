Le contrôle du flux en Groovy ressemble à celui de Java, mais avec des ajouts qui font gagner un temps précieux : un switch bien plus puissant, des ranges (plages) élégants, et surtout une poignée d'opérateurs ingénieux — Elvis, navigation sûre, vaisseau spatial — qui éliminent du code répétitif. Cette leçon couvre les conditions, les boucles et ces opérateurs caractéristiques.

La condition if et la « vérité » de Groovy

Le if est classique, mais Groovy a une notion étendue de ce qui est « vrai » (la truthiness). Au-delà de true, est considéré comme vrai : un nombre non nul, une chaîne non vide, une collection non vide, un objet non null.

Cette truthiness rend les conditions concises : if (liste) signifie « si la liste n'est pas vide », sans avoir à écrire if (liste != null && !liste.isEmpty()).

Le switch enrichi

Le switch de Groovy va bien au-delà des valeurs simples : il accepte des types, des plages, des listes, des expressions régulières… La correspondance se fait avec la méthode isCase.

Ce switch polyvalent remplace souvent des cascades de if/else if : on peut matcher sur « est dans cette plage », « est de ce type », « est dans cette liste ».

Les boucles et les ranges

Groovy offre les boucles habituelles, et des ranges (plages) avec la notation .., très lisibles pour itérer.

La plage 1..5 inclut les deux bornes ; 1..<5 exclut la dernière (1 à 4). Les méthodes times, upto, step sont des façons très « groovy » de répéter, qui utilisent des closures (leçon 4).

L'opérateur Elvis ?:

L'opérateur Elvis (ainsi nommé car ?: évoque la houppette d'Elvis) fournit une valeur par défaut quand une expression est « fausse » (null ou vide). Il remplace un if verbeux.

La navigation sûre ?.

L'opérateur de navigation sûre ?. évite l'erreur classique du « null pointer » : si l'objet est null, l'expression renvoie null au lieu de planter.

Combiné à l'Elvis, c'est un duo redoutable : def n = nom?.length() ?: 0 donne la longueur, ou 0 si nom est null. Concis et sûr.

L'opérateur spaceship <=>

Le vaisseau spatial <=> compare deux valeurs et renvoie -1, 0 ou 1 selon que la première est inférieure, égale ou supérieure. Idéal pour trier.

Pièges fréquents

Piège fréquent

Oublier que 0, la chaîne vide "" et la liste vide [] sont faux en Groovy. Si tu écris if (compteur) en pensant « si le compteur existe », sache que pour compteur = 0, la condition est fausse ! Pour tester l'existence d'une variable sans tomber dans ce piège, sois explicite : if (compteur != null). La truthiness est pratique, mais il faut connaître ce qu'elle considère comme faux.

Pour aller plus loin

Pour aller plus loin

Ces opérateurs « de confort » (Elvis, navigation sûre) ont eu un tel succès qu'ils ont été adoptés par d'autres langages : Kotlin a repris ?. et ?:, C# a son ?. et ??, Swift ses optionnels chaînés. Groovy a popularisé l'idée qu'écrire du code « null-safe » ne devrait pas être verbeux. Une bonne idée de syntaxe finit toujours par essaimer.

Récap et vérification

  • Truthiness : vrai = non null/non vide/non zéro ; faux = null, 0, "", [], false.
  • switch enrichi : matche valeurs, plages, types, listes ; ranges 1..5.
  • Opérateurs : Elvis ?: (défaut), navigation sûre ?. (anti-null), spaceship <=> (comparaison).
