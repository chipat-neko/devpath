Tu as parcouru tout Groovy : syntaxe concise, closures, collections, objets, métaprogrammation, et son rôle dans Gradle et Jenkins. Pour clore ce cours, situons l'écosystème : les outils, l'interopérabilité sans friction avec Java, les frameworks (Grails, Spock), et où Groovy s'emploie aujourd'hui. Tu repartiras avec une vue d'ensemble claire.

Les outils

Pour expérimenter, deux outils sont précieux :

  • groovyConsole : une mini-application graphique où l'on tape du Groovy et l'exécute instantanément — parfait pour apprendre et tester ;
  • groovysh : un shell interactif en ligne de commande.

Pour la gestion de dépendances dans un script, Grape permet de déclarer une bibliothèque directement dans le code (@Grab), sans configuration de projet : idéal pour les scripts autonomes.

L'interopérabilité avec Java

C'est l'atout fondateur de Groovy : l'interopérabilité totale avec Java. On peut : appeler n'importe quelle classe Java depuis Groovy, appeler du Groovy depuis Java, mélanger les deux dans un même projet, et utiliser toutes les bibliothèques Java. Groovy se compile en bytecode JVM identique à celui de Java : à l'exécution, ils sont indiscernables.

Cette compatibilité explique pourquoi Groovy s'est imposé : une équipe Java peut l'adopter progressivement, fichier par fichier, sans tout réécrire.

Les frameworks Groovy

Groovy a donné naissance à des frameworks remarquables :

  • Spock : un framework de test d'une lisibilité exceptionnelle, qui exploite les DSL Groovy. Beaucoup l'utilisent même pour tester du code Java ;
  • Grails : un framework web « à la Rails » pour la JVM, productif et conventionnel ;
  • Gradle et Jenkins (leçon 8), déjà vus, qui touchent presque tous les projets JVM.

Où Groovy s'emploie

Groovy occupe des niches solides :

  • build et CI/CD : Gradle et Jenkins, son usage le plus universel ;
  • tests : Spock, apprécié pour sa clarté ;
  • scripting et automatisation sur la JVM : petits outils, traitements de données ;
  • DSL métier : configurations et langages dédiés dans des applications d'entreprise.

Pièges fréquents

Piège fréquent

Opposer Groovy et Java comme s'il fallait « choisir ». En réalité, ils cohabitent : on garde Java pour le code de production typé et performant, et on ajoute Groovy là où sa souplesse brille (builds, scripts, tests, DSL). Beaucoup de projets Java utilisent Groovy sans même que leurs développeurs « fassent du Groovy » — ils éditent un build.gradle ou un test Spock. C'est un complément, pas un remplaçant.

Pour aller plus loin

Pour aller plus loin

Groovy a une place singulière dans l'histoire de la JVM : premier grand langage alternatif dynamique, il a prouvé qu'on pouvait améliorer Java sans quitter son écosystème. Même si Kotlin l'a dépassé en popularité pour le développement d'applications, Groovy reste irremplaçable pour le scripting et les DSL — précisément là où sa nature dynamique et ses closures font merveille. Le connaître, c'est maîtriser un outil que l'écosystème JVM continue d'utiliser quotidiennement.

Récap et vérification

  • Outils : groovyConsole, groovysh, @Grab (Grape) pour les dépendances de script.
  • Interopérabilité totale avec Java : adoption progressive, accès à tout l'écosystème.
  • Frameworks : Spock (tests), Grails (web), Gradle/Jenkins (build/CI).
  • Groovy complète Java ; sa spécialité reste le scripting et les DSL.

Exercice 3Défi

Résume en trois points ce qui fait la valeur de Groovy.

Voir une solution

Réponses possibles : (1) une syntaxe concise et expressive (typage optionnel, GString, closures, opérateurs de confort) qui allège énormément Java ; (2) une interopérabilité totale avec Java et son écosystème, permettant une adoption progressive ; (3) une nature dynamique (métaprogrammation, DSL) qui en fait l'outil idéal du scripting, des builds (Gradle), de la CI (Jenkins) et des tests (Spock) — des usages que tout développeur JVM rencontre.
