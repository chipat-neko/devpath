Voici le concept qui donne à Groovy sa puissance expressive : les closures. Une closure est un bloc de code qu'on peut stocker dans une variable, passer à une méthode, et exécuter plus tard. C'est l'équivalent Groovy des fonctions anonymes ou lambdas. Les closures sont partout en Groovy : parcourir une liste, configurer un build Gradle, définir un pipeline Jenkins — tout repose sur elles. Cette leçon les démystifie.

Définir une closure

Une closure s'écrit entre accolades { }. Elle peut prendre des paramètres (avant la flèche ->) et contient du code. On la stocke dans une variable et on l'appelle comme une fonction.

La syntaxe { parametre -> corps } définit la closure ; on l'appelle ensuite avec des parenthèses comme une méthode. C'est un objet à part entière qu'on peut manipuler.

Le paramètre implicite it

Quand une closure prend un seul paramètre, on peut omettre sa déclaration : Groovy le nomme automatiquement it. C'est un raccourci très courant.

it rend les closures à un argument extrêmement concises. On le verra partout dans le traitement des collections (leçon 5).

Passer une closure à une méthode

La vraie force des closures : les passer en argument. Beaucoup de méthodes Groovy attendent une closure pour décrire quoi faire.

Cette règle — « une closure en dernier argument peut sortir des parenthèses » — donne la syntaxe si reconnaissable de Groovy (et de Gradle), où des blocs { } suivent les appels de méthode.

Plusieurs paramètres

Une closure peut prendre plusieurs paramètres, séparés par des virgules avant la flèche.

La capture du contexte

Pourquoi « closure » (fermeture) ? Parce qu'une closure capture les variables de son environnement : elle « se referme » autour d'elles et peut les lire et les modifier, même après coup.

La closure incrementer garde un lien vivant avec la variable compteur du contexte : chaque appel la modifie. C'est ce qui permet, par exemple, d'accumuler un résultat ou de configurer un objet depuis un bloc.

Pièges fréquents

Piège fréquent

Confondre définir et appeler une closure. def f = { ... } ne fait qu'enregistrer le bloc de code, sans l'exécuter ; il faut f() pour le lancer. De même, liste.each { ... } exécute la closure pour chaque élément, mais def c = { ... } seul ne fait rien tant qu'on n'appelle pas c(). Une closure est une valeur ; son code ne tourne qu'à l'appel.

Pour aller plus loin

Pour aller plus loin

Les closures sont le fondement des DSL (langages dédiés) de Groovy. Quand tu écris dans un build.gradle un bloc dependencies { ... }, ce { ... } est une closure passée à la méthode dependencies ! Gradle, Jenkins et bien d'autres exploitent cette syntaxe pour offrir des configurations qui se lisent comme un langage de description, alors que ce n'est que du Groovy. On y reviendra leçon 8.

Récap et vérification

  • Une closure { params -> corps } est un bloc de code stockable et passable en argument.
  • it est le paramètre implicite d'une closure à un seul argument.
  • Une closure en dernier argument peut sortir des parenthèses (syntaxe à blocs).
  • Une closure capture les variables de son contexte (lecture et écriture).
