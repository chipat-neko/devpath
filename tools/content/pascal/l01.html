Pascal est sans doute le langage qui a appris à programmer à le plus de monde. Conçu en 1970 par le Suisse Niklaus Wirth, il fut pensé dans un seul but : enseigner la programmation structurée, proprement, sans mauvaises habitudes. Sa clarté est légendaire : un programme Pascal se lit presque comme un texte. Des décennies plus tard, à travers Turbo Pascal puis Delphi, il a aussi conquis l'industrie. Cette première leçon te fait découvrir son esprit et sa structure.

Un langage né pour enseigner

Wirth voulait un langage qui force à bien penser : découper un problème en étapes claires, nommer les choses, structurer le code en blocs nets. Pascal bannit les raccourcis obscurs au profit de mots-clés lisibles. On y apprend les bons réflexes — déclarer ses variables, typer ses données, organiser ses procédures — qui se transposent ensuite dans tous les langages.

La structure d'un programme

Tout programme Pascal suit le même squelette : un nom, d'éventuelles déclarations, puis un corps entre begin et end. Le point final après le dernier end est obligatoire.

program Bonjour; nomme le programme. Le bloc begin … end. contient les instructions. writeln affiche une ligne de texte. Remarque le point après le end final : il marque la toute fin du programme (un point-virgule sépare les instructions, le point clôt le tout).

Afficher du texte

Deux instructions servent à écrire : write affiche sans passer à la ligne, writeln ajoute un retour à la ligne. Le texte va entre apostrophes simples.

Les commentaires s'écrivent entre accolades { … } (ou (* … *)), et Pascal moderne accepte aussi // pour un commentaire de fin de ligne.

Une syntaxe qui se lit à voix haute

Pascal préfère les mots aux symboles. Là où d'autres langages utilisent des accolades { } pour délimiter un bloc, Pascal écrit begin … end. Les opérateurs logiques sont and, or, not. L'affectation s'écrit := (et l'égalité =), une distinction nette entre « donner une valeur » et « comparer ».

De Turbo Pascal à Delphi

Dans les années 1980, Turbo Pascal (de Borland) a rendu Pascal extrêmement populaire : compilateur rapide, environnement intégré, prix abordable. Puis Delphi l'a étendu à la programmation objet et au développement d'applications Windows visuelles, très utilisé en entreprise. Aujourd'hui, Free Pascal et l'IDE Lazarus perpétuent l'héritage, libres et multiplateformes (leçon 9).

Pièges fréquents

Piège fréquent

Oublier le point final après le dernier end, ou le confondre avec un point-virgule. La règle : le point-virgule sépare les instructions à l'intérieur du programme ; le point termine le programme entier (end.). C'est l'une des premières étourderies que le compilateur signalera — sans gravité, mais déroutante au début.

Pour aller plus loin

Pour aller plus loin

Niklaus Wirth, créateur de Pascal, est aussi connu pour une formule : « Algorithmes + Structures de données = Programmes », titre de son livre fondateur. C'est toute la philosophie du langage : bien choisir comment organiser ses données est aussi important que les calculs eux-mêmes. Une leçon qui dépasse largement Pascal et reste vraie dans n'importe quel langage.

Récap et vérification

  • Pascal est né pour enseigner la programmation structurée ; il est clair et lisible.
  • Structure : program Nom; … begin … end. (avec un point final).
  • writeln/write affichent ; commentaires { … } ou //.
  • := affecte, = compare ; Turbo Pascal puis Delphi l'ont porté dans l'industrie.

Vérifie ta compréhension

  1. Dans quel but Pascal a-t-il été conçu ?
  2. Que termine le point dans end. ?
  3. Quelle différence entre := et = ?
