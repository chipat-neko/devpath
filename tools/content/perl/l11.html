Tu connais désormais l'essentiel de Perl. Cette dernière leçon consolide ta pratique : les bonnes habitudes qui rendent ton code lisible et fiable, l'art des one-liners, les tests, et un panorama honnête de la place de Perl aujourd'hui — pour savoir où continuer.

Les fondations : strict, warnings, et une version

On le répète parce que c'est capital : tout script sérieux commence par use strict; use warnings;. Déclarer une version récente active aussi les fonctionnalités modernes (say, signatures…).

Un style lisible

La devise « plusieurs façons de faire » n'excuse pas le code illisible. Quelques principes : noms parlants, sous-programmes courts, déballage des arguments en première ligne, éviter les variables spéciales obscures dans le code partagé.

Le code se lit bien plus souvent qu'il ne s'écrit : privilégie la clarté.

Les one-liners : Perl en ligne de commande

Là où Perl reste imbattable : les one-liners, ces mini-programmes lancés directement depuis le terminal pour transformer du texte. Les options : -e (exécuter du code), -n (boucler sur les lignes), -p (boucler et imprimer), -i (modifier sur place).

La variable $. est le numéro de ligne courant. Ces commandes remplacent souvent un script entier.

Tester avec Test::More

Le module standard Test::More permet d'écrire des tests simples : on annonce un nombre de tests, puis on vérifie des conditions.

Où Perl s'emploie aujourd'hui

Perl a perdu sa position dominante des années 2000, mais reste solide dans plusieurs niches : administration système et automatisation, bio-informatique (BioPerl), traitement de texte et de journaux à grande échelle, et la maintenance d'un immense parc de code existant. Sa maîtrise des expressions régulières reste une référence.

Pièges fréquents

Piège fréquent

Céder à la tentation du code « golfé » (le plus court possible) pour impressionner : six mois plus tard, personne — pas même toi — ne le relit. La concision n'est une qualité que si elle reste claire.

Pour aller plus loin

Pour aller plus loin

Pour progresser : installe Perl::Critic (qui audite ton style selon le livre Perl Best Practices) et perltidy (qui reformate ton code). Lis perldoc perlstyle. Et explore metacpan pour découvrir les modules de référence de chaque domaine.

Récap et vérification

  • Commence chaque script par use strict; use warnings; et une version récente.
  • Privilégie la clarté à la concision ; le code se lit plus qu'il ne s'écrit.
  • Les one-liners (perl -ne, -pe, -i) transforment du texte en une commande.
  • Test::More teste ton code ; Perl::Critic et perltidy soignent le style.

Vérifie ta compréhension

  1. Que font les options -n et -p en ligne de commande ?
  2. Pourquoi la clarté prime-t-elle sur la concision ?
  3. Quel module de la bibliothèque standard sert à tester ?
