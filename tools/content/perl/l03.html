Tu sais stocker des données ; il te faut maintenant décider et répéter. Perl offre les structures de contrôle habituelles, mais avec deux spécificités très « perliennes » : les modificateurs d'instruction et, surtout, le contexte — une idée centrale qui change la valeur d'une expression selon l'endroit où on l'utilise.

Conditions : if, elsif, unless

La condition se place entre parenthèses, le bloc entre accolades (toujours obligatoires en Perl). unless est un if négatif, parfois plus lisible.

Comparaisons : nombres vs chaînes

Point crucial : Perl a deux jeux d'opérateurs. Pour les nombres : ==, !=, <, >, <=, >=. Pour les chaînes : eq, ne, lt, gt, le, ge. Se tromper donne des résultats surprenants.

Utilise == pour les nombres, eq pour les chaînes : une erreur classique et silencieuse.

Boucles

while répète tant qu'une condition tient ; for/foreach parcourt une liste (les deux mots sont interchangeables en Perl).

La variable spéciale $_

Perl a une variable « par défaut », $_, utilisée implicitement par de nombreuses fonctions. Dans un foreach sans variable nommée, c'est $_ qui prend chaque valeur.

Les modificateurs d'instruction

Très idiomatique : on peut placer la condition ou la boucle après l'instruction, sans accolades, pour les cas simples. C'est concis et lisible quand le corps tient en une ligne.

Le contexte : scalaire vs liste

Voici LE concept qui distingue Perl. Une même expression peut valoir des choses différentes selon le contexte dans lequel on l'utilise. Un tableau en contexte scalaire donne son nombre d'éléments ; en contexte liste, ses éléments.

Beaucoup de fonctions se comportent différemment selon le contexte. C'est puissant, mais source de surprises : garde l'idée en tête.

Pièges fréquents

Piège fréquent

Comparer des chaînes avec == : "chat" == "chien" renvoie vrai ! Car les deux chaînes valent 0 en contexte numérique. Pour comparer des chaînes, c'est toujours eq. use warnings t'avertira de ce genre d'erreur.

Pour aller plus loin

Pour aller plus loin

L'opérateur ternaire cond ? a : b existe aussi, et le given/when (équivalent du switch) a existé mais est aujourd'hui déconseillé : préfère une cascade de if/elsif ou une table de dispatch (un hachage de sous-programmes).

Récap et vérification

  • if/elsif/else/unless décident ; les accolades sont obligatoires.
  • Comparaisons numériques (==, <) vs chaînes (eq, lt) : ne pas confondre.
  • $_ est la variable par défaut ; les modificateurs (… if cond) condensent les cas simples.
  • Le contexte (scalaire vs liste) change la valeur d'une expression.

Vérifie ta compréhension

  1. Quel opérateur pour comparer deux chaînes ? Et deux nombres ?
  2. Que vaut my $n = @tableau; et pourquoi ?
  3. À quoi sert $_ ?
