Pour représenter des données réelles — une série de mesures, une fiche client, une position — on a besoin de structures qui regroupent plusieurs valeurs. Ada propose deux briques essentielles : les tableaux (des collections indexées d'éléments de même type) et les enregistrements (des groupes de champs nommés, possiblement de types différents). Combinées au typage fort, elles permettent de modéliser le monde avec précision. Cette leçon les détaille, et présente les puissants attributs d'Ada.

Les tableaux

Un tableau stocke une suite d'éléments indexés. On déclare son type d'indice et son type d'élément. Particularité d'Ada : l'indice peut commencer où l'on veut, et être de n'importe quel type discret.

L'agrégat (others => 0.0) initialise tous les éléments d'un coup. L'accès se fait par Tableau (Indice), avec des parenthèses — comme un appel de fonction, ce qui n'est pas un hasard : un tableau est conceptuellement une « fonction » de l'indice vers la valeur.

Les attributs : interroger un type

Ada attache aux types et tableaux des attributs, notés avec une apostrophe, qui renseignent sur leurs bornes. Ils rendent le code robuste : on ne code jamais les bornes « en dur ».

Écrire for I in Semaine'Range plutôt que for I in 1 .. 7 est une bonne habitude : si la taille du tableau change, la boucle s'adapte toute seule. Plus de désynchronisation entre les bornes et le code.

Les enregistrements

Un enregistrement (record) regroupe des champs nommés, éventuellement de types différents : parfait pour modéliser une entité.

On accède à un champ avec un point : P.Age. L'agrégat (Nom => …, Age => …) initialise tous les champs nommément — encore une fois, l'ordre importe peu et le code se documente lui-même.

Combiner les structures

Tableaux et records se composent librement : un tableau de records, un record contenant un tableau… On modélise ainsi des données complexes tout en gardant la sûreté du typage.

Les valeurs par défaut de champ

Un record peut donner des valeurs par défaut à ses champs : tout objet créé sans agrégat les reçoit automatiquement, ce qui évite les états non initialisés.

Pièges fréquents

Piège fréquent

Les chaînes String d'Ada ont une longueur fixe : String (1 .. 20) fait exactement 20 caractères, qu'il faut compléter par des espaces. C'est déroutant venant de langages à chaînes dynamiques. Pour des chaînes de longueur variable, Ada offre Unbounded_String (du paquet Ada.Strings.Unbounded), bien plus souple — à privilégier dès que la taille n'est pas connue d'avance.

Pour aller plus loin

Pour aller plus loin

Ada possède des enregistrements variants : un record dont les champs dépendent d'un discriminant, comme « une forme qui a un rayon si c'est un cercle, une largeur et une hauteur si c'est un rectangle ». Le compilateur garantit qu'on n'accède qu'aux champs valides pour la variante en cours — une union sûre, là où le C laisserait passer des accès dangereux.

Récap et vérification

  • Tableau : array (plage) of Type ; accès par T (I) ; agrégat (others => …).
  • Attributs : 'First, 'Last, 'Length, 'Range — pour ne jamais coder les bornes en dur.
  • Record : champs nommés (P.Champ) ; agrégats et valeurs par défaut.
  • Tableaux et records se composent ; les String sont de longueur fixe (sinon Unbounded_String).

Vérifie ta compréhension

  1. Que renvoie l'attribut 'Range d'un tableau ?
  2. Comment accède-t-on au champ Age d'un record P ?
  3. Pourquoi préférer for I in T'Range à for I in 1 .. 7 ?
