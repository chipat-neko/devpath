Un programme bien construit se découpe en sous-programmes : des unités nommées qui font une chose et la font bien. Ada en distingue deux sortes — les procédures (qui agissent) et les fonctions (qui calculent une valeur) — et offre un mécanisme remarquablement clair pour décrire comment les paramètres circulent : les modes. Cette leçon t'apprend à structurer ton code à la manière Ada.

Les procédures

Une procédure exécute une action sans renvoyer de valeur. On la déclare avec procedure, ses paramètres entre parenthèses, puis is … begin … end.

L'opérateur & concatène des chaînes. Le paramètre Nom est en mode in (lecture seule) : la procédure peut le lire, pas le modifier.

Les fonctions

Une fonction calcule et renvoie une valeur, dont on précise le type après return. Dans le corps, l'instruction return fournit le résultat.

Distinction nette : une procédure fait quelque chose, une fonction vaut quelque chose. On appelle une fonction là où on attend une valeur ; une procédure comme une instruction à part entière.

Les modes de paramètres : l'élégance d'Ada

Voici une idée propre à Ada, et très éclairante. Chaque paramètre porte un mode qui dit comment il est utilisé :

  • in — entrée seule (lecture) ; c'est le mode par défaut ;
  • out — sortie seule : la procédure y écrit un résultat ;
  • in out — entrée et sortie : lu puis modifié.

Le mode rend l'intention explicite et vérifiée : un paramètre in ne peut pas être modifié (le compilateur l'interdit) ; un out doit recevoir une valeur. On lit la signature et on sait immédiatement ce qui entre, ce qui sort, ce qui est transformé.

Nommer les paramètres à l'appel

Ada permet de nommer les arguments lors de l'appel : la correspondance ne dépend plus de l'ordre, et le code devient auto-documenté.

Pour un appel à plusieurs paramètres, cette notation Nom => Valeur évite les confusions du type « est-ce la largeur ou la hauteur en premier ? ».

Valeurs par défaut

Un paramètre in peut avoir une valeur par défaut, utilisée si l'appelant ne la fournit pas.

Pièges fréquents

Piège fréquent

Oublier qu'un paramètre out n'est pas lisible avant d'avoir été affecté : il sert à renvoyer une valeur, pas à en transmettre une. Si tu as besoin de lire et d'écrire un paramètre, c'est le mode in out qu'il te faut. Choisir le bon mode n'est pas une formalité : c'est une part du contrat que le compilateur fait respecter.

Pour aller plus loin

Pour aller plus loin

Les modes de paramètres rendent Ada plus sûr que les langages où l'on passe des pointeurs ambigus : on sait, rien qu'à la signature, ce qu'une procédure peut toucher. C'est aussi ce qui permet à l'analyse statique (et à SPARK, leçon 9) de prouver qu'une procédure n'a pas d'effet de bord caché — un atout décisif pour le logiciel critique.

Récap et vérification

  • Procédure : une action ; fonction : renvoie une valeur (return Type).
  • Modes : in (lecture, défaut), out (écriture), in out (les deux).
  • Le compilateur fait respecter les modes : intention explicite et vérifiée.
  • Appels par nom (Nom => Valeur) et valeurs par défaut.
