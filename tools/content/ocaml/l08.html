Pour organiser un programme à grande échelle, OCaml possède l'un des systèmes de modules les plus puissants qui soient. Un module regroupe types et fonctions ; une signature en décrit l'interface ; et les foncteurs — des modules paramétrés par d'autres modules — offrent une généricité d'une rare expressivité. C'est une marque de fabrique d'OCaml.

Les modules

Un module est un regroupement nommé de définitions. Tout fichier mon_module.ml définit automatiquement un module Mon_module. On peut aussi en définir explicitement avec module ... = struct ... end.

On accède aux membres d'un module avec un point : Pile.empiler.

Les signatures : cacher l'implémentation

Une signature (module type) décrit ce qu'un module expose, en cachant le reste. On peut ainsi rendre un type abstrait : l'extérieur sait qu'il existe, mais pas comment il est fait. C'est l'encapsulation, garantie par le typeur.

Désormais, l'extérieur ne peut plus traiter une Pile.t comme une liste : elle est abstraite. On peut changer l'implémentation sans casser le code client.

Ouvrir un module

open rend les membres d'un module accessibles sans préfixe. Pratique, mais à utiliser avec mesure pour ne pas masquer des noms.

Les foncteurs

Voici la pièce maîtresse : un foncteur est un module paramétré par un autre module. Donne-lui un module qui satisfait une certaine signature, il te renvoie un module construit dessus. C'est de la généricité au niveau des modules.

Le foncteur Ensemble fonctionne pour tout type comparable : on l'instancie avec Int, String, ou un type maison.

Pourquoi c'est puissant

Les foncteurs permettent d'écrire du code générique et réutilisable avec des garanties de types fortes. La bibliothèque standard les utilise abondamment : Map.Make et Set.Make sont des foncteurs qui fabriquent des dictionnaires et ensembles pour le type de clé que tu fournis.

Pièges fréquents

Piège fréquent

Abuser de open en tête de fichier : ouvrir plusieurs gros modules crée des conflits de noms et rend le code difficile à suivre (d'où vient cette fonction ?). Préfère le préfixe explicite (List.map) ou l'ouverture locale Module.(...).

Pour aller plus loin

Pour aller plus loin

Le système de modules d'OCaml est si expressif qu'il constitue presque un « langage dans le langage ». Les foncteurs servent à l'injection de dépendances, au paramétrage d'algorithmes, à la construction de bibliothèques modulaires — là où d'autres langages utilisent l'héritage ou les interfaces.

Récap et vérification

  • Un module regroupe types et fonctions ; chaque fichier est un module.
  • Une signature (module type) décrit l'interface et peut rendre un type abstrait.
  • Un foncteur est un module paramétré par un module : généricité de haut niveau.
  • Map.Make/Set.Make sont des foncteurs de la stdlib ; open avec parcimonie.

Vérifie ta compréhension

  1. À quoi sert une signature de module ?
  2. Qu'est-ce qu'un type abstrait et que protège-t-il ?
  3. Qu'est-ce qu'un foncteur ?
