Pour des données aux champs nommés, OCaml a les records. Et pour la sûreté, deux types fondamentaux remplacent les sources d'erreurs classiques : option bannit le null, result gère les erreurs sans exception cachée. Ensemble, ils éliminent une grande part des plantages habituels.

Les records

Un record regroupe des champs nommés et typés. On le définit avec des accolades, et on accède aux champs avec un point.

Mise à jour fonctionnelle

Un record est immuable. Pour en obtenir une version modifiée, on utilise la syntaxe with : elle crée un nouveau record en copiant l'ancien et en changeant certains champs.

Le type option : en finir avec null

Comment représenter « une valeur peut être absente » ? Pas avec null (source de plantages partout), mais avec le type option : soit Some valeur, soit None. Le type oblige à traiter le cas « absent ».

Manipuler une option

On déballe une option par filtrage, ou avec les fonctions du module Option.

Le type result : gérer les erreurs

Pour une opération qui peut échouer avec une raison, le type result : Ok valeur en cas de succès, Error raison en cas d'échec. L'erreur fait partie du type de retour : impossible de l'ignorer.

Les exceptions, avec parcimonie

OCaml a aussi des exceptions (raise, try ... with), mais l'usage idiomatique les réserve aux cas vraiment exceptionnels (erreurs de programmation). Pour les erreurs attendues, on préfère option ou result, visibles dans les types.

Pièges fréquents

Piège fréquent

Vouloir « sortir » la valeur d'une option sans traiter le None : c'est précisément ce qu'OCaml empêche. Tu dois gérer les deux cas (par match ou Option.value). Cette contrainte est une force : pas de plantage « valeur nulle » possible.

Pour aller plus loin

Pour aller plus loin

Pour enchaîner plusieurs opérations faillibles sans pyramide de match, on utilise les opérateurs de liaison (let*) ou Option.bind/Result.bind. C'est l'équivalent OCaml du ? de Rust : court-circuiter proprement à la première absence ou erreur.

Récap et vérification

  • Les records ont des champs nommés ; { r with champ = ... } crée une copie modifiée.
  • option (Some/None) remplace null : l'absence est dans le type.
  • result (Ok/Error) gère les erreurs attendues, visibles dans le type de retour.
  • Les exceptions existent mais sont réservées aux cas vraiment exceptionnels.
