Deux outils pour compléter ta boîte à outils Objective-C : les collections de Foundation, pour stocker et organiser des groupes d'objets, et les blocks, des fonctions anonymes qu'on peut passer de-ci de-là — l'équivalent Objective-C des closures. Ces deux mécanismes sont au cœur du code moderne : énumération, traitement asynchrone, callbacks. Cette leçon les met en main.

NSArray : le tableau d'objets

NSArray stocke une liste ordonnée d'objets (pas de types primitifs : d'où les NSNumber). Il est immuable : on ne le modifie pas après création. Le littéral moderne est @[...].

La notation fruits[0] est un raccourci moderne pour [fruits objectAtIndex:0]. Pour parcourir, for ... in (l'énumération rapide) est le plus lisible :

Versions mutables

Pour modifier une collection (ajouter, retirer), on utilise sa version mutable : NSMutableArray.

Règle générale de Foundation : la version immuable par défaut (sûre, partageable), la mutable seulement quand on doit changer le contenu.

NSDictionary : associer clé et valeur

NSDictionary associe des clés à des valeurs (toutes des objets). Le littéral est @{cle: valeur, ...}.

L'accès ages[@"Ada"] est immédiat : pas besoin de parcourir. C'est l'outil idéal pour une table de correspondance.

Les blocks : des fonctions anonymes

Un block est un bout de code qu'on peut stocker dans une variable, passer en argument, et exécuter plus tard. C'est l'équivalent Objective-C des closures ou des fonctions anonymes. Sa syntaxe se reconnaît au caret ^.

La déclaration se lit : int (^somme)(int, int) = « somme est un block prenant deux int et renvoyant un int ». Le corps suit le ^(...). On appelle ensuite le block comme une fonction : somme(3, 4).

Les blocks en action

Les blocks brillent comme callbacks (code à exécuter plus tard) et pour l'énumération. Beaucoup d'API Apple les utilisent pour le traitement asynchrone : « fais ceci, et quand c'est fini, exécute ce block ».

Le block reçoit chaque objet, son indice, et un drapeau stop pour interrompre. Ce style — passer du comportement en argument — préfigure les closures de Swift, qui en sont l'héritage direct.

Pièges fréquents

Piège fréquent

Quand un block capture self (par exemple pour accéder à une propriété), il le retient en strong — ce qui peut créer un cycle de rétention si l'objet retient aussi le block. La parade idiomatique : créer une référence faible avant le block (__weak typeof(self) weakSelf = self;) et utiliser weakSelf à l'intérieur. C'est l'un des pièges mémoire les plus fréquents avec les blocks.

Pour aller plus loin

Pour aller plus loin

Les blocks sont au cœur de Grand Central Dispatch (GCD), le système de concurrence d'Apple : on confie un block à une « file » (dispatch_async) et le système l'exécute sur un autre thread. C'est ainsi qu'on fait du travail en arrière-plan sans bloquer l'interface. Combinés aux collections, les blocks forment la base de la programmation asynchrone moderne sur les plateformes Apple.

Récap et vérification

  • NSArray (@[...]) liste d'objets ; NSDictionary (@{...}) clé→valeur ; versions mutables pour modifier.
  • Accès modernes : tableau[0], dico[@"cle"] ; parcours avec for ... in.
  • Un block (^) est une fonction anonyme stockable et passable en argument.
  • Blocks utilisés pour callbacks, énumération, asynchrone (GCD) ; attention à la capture de self.
