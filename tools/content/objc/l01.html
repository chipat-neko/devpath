Objective-C a été, pendant près de trente ans, le langage d'Apple. Tout le Mac, puis l'iPhone et l'iPad à leurs débuts, ont été bâtis avec lui. Né au début des années 1980, il ajoute au langage C une couche orientée objet inspirée de Smalltalk, avec une syntaxe immédiatement reconnaissable : les messages entre crochets. Depuis 2014, Swift l'a remplacé pour les nouveaux projets — mais des millions de lignes d'Objective-C tournent encore, et savoir le lire reste une compétence précieuse. Cette leçon te présente son esprit.

C, plus des objets

Objective-C est un sur-ensemble strict du C : tout programme C valide est aussi un programme Objective-C. On y retrouve les types C (int, float…), les pointeurs, les fonctions. Par-dessus, Objective-C greffe les objets et un système de messages dynamique emprunté à Smalltalk. C'est ce mélange — bas niveau du C, dynamisme objet — qui le caractérise.

La syntaxe à messages

La marque de fabrique d'Objective-C : au lieu d'appeler une méthode avec un point (objet.methode()), on envoie un message à un objet, entre crochets.

On lit [objet message] comme « envoie le message message à objet ». Cette notation déroute au début, mais elle devient vite naturelle : les crochets signalent immédiatement une interaction entre objets.

Ton premier programme

Un programme Objective-C importe le framework Foundation (la bibliothèque de base d'Apple) et utilise NSLog pour afficher.

Plusieurs éléments typiques : #import (comme le #include du C, mais sans double inclusion), le préfixe NS (pour « NeXTSTEP », le système dont Foundation est issu), et surtout le @ devant la chaîne : @"..." crée un objet NSString, distinct d'une chaîne C classique.

Le préfixe NS et l'héritage NeXT

Pourquoi tant de classes commencent-elles par NS ? Parce qu'Objective-C a été popularisé par NeXT, l'entreprise fondée par Steve Jobs après son départ d'Apple. Quand Apple a racheté NeXT en 1997, sa technologie est devenue le socle de Mac OS X, puis d'iOS. Les NS (NeXTSTEP) en sont la trace historique, toujours visible aujourd'hui.

Pourquoi l'apprendre encore ?

Swift est désormais recommandé pour le développement Apple, mais Objective-C garde son utilité :

  • maintenir l'immense base de code existante (apps, frameworks) ;
  • comprendre les frameworks Apple, dont beaucoup sont encore écrits en Objective-C ;
  • cohabiter avec Swift dans des projets mixtes (leçon 9) ;
  • saisir l'histoire et les concepts (messages, runtime dynamique) qui éclairent Swift.

Pièges fréquents

Piège fréquent

Oublier le @ devant une chaîne. "Bonjour" est une chaîne C (un tableau de caractères), tandis que @"Bonjour" est un objet NSString. La plupart des méthodes Objective-C attendent un NSString (donc avec @). Confondre les deux provoque des erreurs de type ou des comportements inattendus. Réflexe : dans le monde objet d'Objective-C, les chaînes portent un @.

Pour aller plus loin

Pour aller plus loin

La syntaxe à messages reflète une idée profonde : en Objective-C, on n'« appelle » pas une méthode, on envoie un message que l'objet décide de traiter à l'exécution. Ce runtime dynamique permet des choses impossibles dans des langages statiques : ajouter des méthodes à la volée, intercepter des messages, introspecter les objets. C'est cette souplesse qui a rendu possibles des frameworks aussi puissants que ceux d'Apple — et que Swift a dû, en partie, réinventer autrement.

Récap et vérification

  • Objective-C = C + objets (système de messages inspiré de Smalltalk).
  • Syntaxe à messages : [objet message:argument].
  • #import, framework Foundation, préfixe NS, NSLog pour afficher.
  • @"..." crée un objet NSString (≠ chaîne C "...").

Exercice 3Défi

Quelle différence entre "Bonjour" et @"Bonjour" en Objective-C ?

Voir une solution

"Bonjour" est une chaîne C classique (un tableau de char terminé par un zéro), héritée du langage C. @"Bonjour" est un objet NSString, la classe de chaînes du framework Foundation, sur lequel on peut envoyer des messages (length, uppercaseString…). La quasi-totalité du code Objective-C utilise des NSString, donc le @.
