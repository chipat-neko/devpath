Une classe sans données ni comportements serait une coquille vide. Cette leçon détaille les deux ingrédients qui la remplissent : les propriétés (les données qu'un objet possède) et les méthodes (ce qu'il sait faire). On verra comment Objective-C génère automatiquement les accesseurs, et la distinction importante entre méthodes d'instance et de classe.

Les propriétés : @property

Une propriété déclare un attribut de l'objet. On précise des attributs entre parenthèses qui décrivent son comportement mémoire et d'accès.

Les attributs courants :

  • nonatomic — accès non thread-safe mais plus rapide (le défaut en pratique) ;
  • strong — pour un objet : l'objet est « retenu » en mémoire (leçon 7) ;
  • assign — pour un type primitif (int, BOOL) : simple copie de valeur ;
  • weak — référence faible, pour éviter les cycles (leçon 7) ;
  • copy — fait une copie (fréquent pour NSString).

Les accesseurs générés

Magie d'Objective-C : déclarer une @property génère automatiquement les accesseurs — un getter pour lire, un setter pour écrire — ainsi qu'une variable d'instance sous-jacente. Tu n'as rien à écrire.

La notation pointée (p.nom) est un raccourci pour les messages d'accesseurs. Sous le capot, p.nom = @"Ada" envoie réellement le message setNom:. C'est plus lisible, et c'est l'usage recommandé.

Les méthodes d'instance

Une méthode d'instance (signe -) s'envoie à un objet particulier et agit sur ses données. Elle accède aux propriétés via self.

Les méthodes de classe

Une méthode de classe (signe +) s'envoie à la classe, pas à un objet. Elle sert souvent de fabrique : créer et renvoyer un objet prêt à l'emploi.

Les méthodes de classe que tu connais déjà : [NSString stringWithFormat:…], [NSArray array]. Elles fabriquent des objets sans qu'on écrive alloc/init soi-même.

self et super

self désigne l'objet courant (ou la classe courante dans une méthode +). super désigne la classe parente : on l'utilise pour appeler la version héritée d'une méthode, typiquement dans un initialiseur.

Note _age : la variable d'instance générée par la propriété age porte un tiret bas. Dans un initialiseur, on y accède souvent directement plutôt que par self.age.

Pièges fréquents

Piège fréquent

Confondre la propriété self.age et la variable d'instance _age. self.age passe par l'accesseur (le setter/getter, qui peut faire des traitements) ; _age accède directement à la donnée. La règle courante : utiliser self.propriete partout (pour bénéficier des accesseurs), sauf dans init et dealloc, où l'on préfère _variable directement, car l'objet n'est pas encore (ou plus) pleinement formé.

Pour aller plus loin

Pour aller plus loin

Tu peux redéfinir un accesseur à la main pour ajouter un comportement : par exemple, un setter setNom: qui met automatiquement le nom en majuscules, ou un getter calculé qui ne stocke rien. C'est ainsi qu'une propriété peut être « virtuelle » (calculée à la volée) plutôt que stockée. Cette flexibilité — entre donnée et comportement — est l'un des intérêts du modèle de propriétés d'Objective-C.

Récap et vérification

  • @property (attributs) Type nom; déclare un attribut ; attributs : nonatomic, strong/weak/assign/copy.
  • Les accesseurs (getter/setter) sont générés ; notation pointée p.nom ≡ messages d'accesseurs.
  • Méthodes : - d'instance (agit sur self), + de classe (souvent fabriques).
  • self = objet courant, super = parent ; variable d'instance _nom.
