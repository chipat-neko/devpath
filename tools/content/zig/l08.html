Voici la fonctionnalité la plus originale de Zig : comptime. L'idée est aussi simple que radicale : une partie du code peut s'exécuter à la compilation, pas à l'exécution. Du même langage, sans macros ni système de templates séparé. C'est ce qui donne à Zig sa généricité, sa métaprogrammation et une bonne part de sa puissance.

Calculer à la compilation

Le mot-clé comptime force l'évaluation d'une expression pendant la compilation. Le résultat est gravé dans le binaire ; aucun calcul à l'exécution.

Les types comme arguments

Rappelle-toi : en Zig, un type est une valeur. On peut donc passer un type en argument à une fonction — à condition que ce soit un argument comptime (connu à la compilation). C'est la base de la généricité.

La même fonction marche pour tout type : Zig compile une version spécialisée pour chaque T utilisé.

La généricité sans templates

Là où le C++ a un système de templates séparé et où Java a des génériques limités, Zig réutilise simplement comptime. Un conteneur générique est une fonction qui renvoie un type.

C'est exactement ainsi que ArrayList(i32) de la stdlib fonctionne : une fonction comptime qui fabrique un type.

inline : dérouler à la compilation

inline for et inline while déroulent la boucle à la compilation : chaque itération devient du code distinct, ce qui permet par exemple de parcourir les champs d'un type.

Pourquoi pas de macros ?

Beaucoup de langages ont des macros — un mini-langage séparé pour générer du code (le préprocesseur C, les macros Rust…). Zig les évite : tout ce qu'on ferait avec une macro, on le fait avec comptime, dans le même langage. Un seul ensemble de règles à apprendre, et du code généré qu'on peut lire et déboguer normalement.

Pièges fréquents

Piège fréquent

Vouloir passer un type calculé à l'exécution : un argument comptime T: type doit être connu à la compilation. Tu ne peux pas choisir un type selon une saisie utilisateur. Si tu as besoin de variabilité à l'exécution, c'est le rôle des unions étiquetées (leçon 5).

Pour aller plus loin

Pour aller plus loin

La réflexion via @typeInfo permet d'inspecter n'importe quel type à la compilation (ses champs, ses méthodes) et de générer du code en conséquence : c'est ainsi que Zig implémente l'affichage formaté, la sérialisation, etc., sans annotations ni génération de code externe.

Récap et vérification

  • comptime exécute du code à la compilation ; le résultat est gravé dans le binaire.
  • Un type est une valeur : on le passe en argument comptime pour la généricité.
  • Un conteneur générique est une fonction qui renvoie un type (comme ArrayList).
  • Zig n'a pas de macros : comptime + @typeInfo font tout, dans le même langage.
