Si un seul trait définit Zig, c'est comptime (compile-time) : la capacité d'exécuter du code Zig pendant la compilation. Là où d'autres langages ont des macros (un langage à part) ou des templates (une syntaxe spéciale), Zig répond : « c'est le même langage, simplement exécuté plus tôt ». De cette idée unique découlent la généricité, la génération de code et la métaprogrammation — sans nouvelle syntaxe à apprendre. Cette leçon approfondit ce qui fait la singularité de Zig.

L'idée : du Zig exécuté à la compilation

Le mot-clé comptime force l'évaluation d'une expression au moment de la compilation. Le résultat est alors une constante, calculée avant même que le programme ne tourne.

Ici, la boucle ne s'exécute pas à l'exécution : elle est déroulée par le compilateur, et TAILLE arrive dans le binaire comme la constante 1024. Tout ce qui peut être calculé tôt l'est.

Les types sont des valeurs

Voici la clé qui débloque tout : en Zig, un type est une valeur de type type, manipulable à la compilation. On peut donc passer un type à une fonction, comme on passe un nombre.

Le paramètre comptime T: type reçoit un type connu à la compilation. C'est la brique des fonctions génériques.

Les fonctions génériques

Une fonction générique en Zig n'est qu'une fonction qui prend un comptime T: type et l'utilise. Le compilateur génère une version spécialisée pour chaque type appelé — sans syntaxe de template dédiée.

Une seule définition, spécialisée à la compilation pour chaque type. C'est l'équivalent des templates C++ ou des generics Rust, mais exprimé avec le langage lui-même.

Générer des types

Puisqu'une fonction peut renvoyer un type, on génère des types à la demande — c'est ainsi que sont écrites les structures de données génériques de la bibliothèque standard (par ex. ArrayList(T)).

Paire(i32) est un type, construit à la compilation. C'est exactement ainsi que std.ArrayList(T) et les conteneurs génériques fonctionnent : une fonction qui prend un type et renvoie un type.

comptime vs macros vs templates

La grande élégance : une seule notion remplace plusieurs mécanismes des autres langages.

  • Pas de macros (C, Rust) : pas de langage de macros à part, pas de préprocesseur ; on écrit du Zig normal exécuté plus tôt.
  • Pas de syntaxe de templates (C++) : la généricité passe par des paramètres comptime ordinaires ;
  • Les erreurs sont des erreurs Zig normales, lisibles, pas les messages cryptiques des templates C++.

Pièges fréquents

Piège fréquent

Oublier que ce qui dépend d'un comptime doit être connaissable à la compilation. Tu ne peux pas choisir un type à partir d'une valeur lue au clavier : le type doit être fixé avant l'exécution. Si le compilateur se plaint qu'une valeur « doit être comptime-known », c'est que tu essaies de décider à l'exécution quelque chose qui doit l'être à la compilation. Sépare clairement ce qui est connu tôt (types, tailles) de ce qui ne l'est qu'à l'exécution (données).

Pour aller plus loin

Pour aller plus loin

comptime permet l'introspection de types via @typeInfo : on peut, à la compilation, parcourir les champs d'un struct, leurs types, et générer du code en conséquence (sérialisation automatique, par exemple). C'est de la métaprogrammation complète — écrire du code qui inspecte et fabrique du code — mais en Zig ordinaire, vérifié par le compilateur. Une poignée d'idées simples (le type est une valeur, le code s'exécute à la compilation) suffit à remplacer tout l'arsenal macro/template des autres langages.

Récap et vérification

  • comptime exécute du code Zig à la compilation ; le résultat devient une constante.
  • Un type est une valeur de type type ; un paramètre comptime T: type reçoit un type.
  • Les fonctions génériques prennent un comptime T: type ; une fonction peut renvoyer un type (génériques comme ArrayList(T)).
  • Une seule notion remplace macros et templates : du Zig normal, exécuté plus tôt.
