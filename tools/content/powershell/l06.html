Quand un script grandit, on en extrait des fonctions : des morceaux nommés et réutilisables. PowerShell pousse l'idée très loin avec les fonctions avancées, qui se comportent exactement comme des cmdlets natives — paramètres validés, prise en charge du pipeline, messages d'aide. C'est le cœur de l'écriture d'outils en PowerShell.

Définir une fonction

Le mot-clé function, un nom (idéalement Verbe-Nom avec un verbe approuvé), un bloc. Les paramètres se déclarent comme dans un script, avec param().

La dernière valeur produite est renvoyée automatiquement ; return existe mais n'est pas obligatoire.

Paramètres typés, par défaut, obligatoires

On type chaque paramètre, on lui donne éventuellement une valeur par défaut, et on le rend obligatoire avec l'attribut [Parameter(Mandatory)] — PowerShell le réclamera s'il manque.

Valider les entrées

Des attributs de validation rejettent les valeurs incorrectes avant même d'entrer dans la fonction. [ValidateSet] impose une liste de choix ; [ValidateRange] une plage ; [ValidateNotNullOrEmpty] interdit le vide.

La validation documente l'intention ET protège la fonction.

Les fonctions avancées : CmdletBinding

Ajoute [CmdletBinding()] avant le param() et ta fonction gagne les comportements d'une vraie cmdlet : les paramètres communs (-Verbose, -ErrorAction…), et l'accès à Write-Verbose.

Traiter le pipeline : begin / process / end

Pour qu'une fonction accepte des objets du pipeline, on marque un paramètre ValueFromPipeline et on découpe le corps en trois blocs : begin (une fois au départ), process (pour chaque objet reçu), end (une fois à la fin).

Sans le bloc process, seule la dernière valeur du pipeline serait traitée : un piège classique.

Pièges fréquents

Piège fréquent

Tout ce qui « tombe » dans le flux de sortie est renvoyé. Si une ligne comme $liste.Add($x) renvoie une valeur, elle pollue ta sortie ! Redirige-la vers $null ([void]$liste.Add($x)) ou capture-la.

Pour aller plus loin

Pour aller plus loin

Avec [CmdletBinding(SupportsShouldProcess)], ta fonction obtient gratuitement -WhatIf et -Confirm : l'utilisateur peut simuler l'action avant de la lancer pour de bon. Indispensable pour les opérations destructrices.

Récap et vérification

  • function Verbe-Nom { param(…) … } définit une fonction réutilisable.
  • Les attributs [Parameter(Mandatory)], [ValidateSet], [ValidateRange] contrôlent les entrées.
  • [CmdletBinding()] transforme une fonction en quasi-cmdlet (-Verbose, etc.).
  • process est indispensable pour traiter chaque objet du pipeline.
