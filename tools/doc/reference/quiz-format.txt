                  The Syntaxe Quiz Block Format (data-quiz)


Abstract

   This document specifies the JSON format carried by the "data-quiz" and
   "data-quiz-bilan" script blocks of the Syntaxe course pages, and the
   behaviour a conforming reader must implement.  The format is already in
   use in every published lesson of the site; this note describes what is
   deployed, not what is planned.

Status of This Memo

   This is an internal working note.  It is not a standard of any kind and
   it is published by no standards body.  It is written in the shape of one
   on purpose, so that it can be read as an exercise.

1.  Introduction

   A lesson page carries its self-assessment quiz inline, as JSON, in a
   script element that the browser does not execute.  A reader (see
   Section 3) picks the block up at load time and builds the interactive
   quiz from it.  No network request is involved at any point.

   The format is deliberately small.  It has four members, one of which is
   optional and one of which may be omitted entirely.


2.  Requirements Language

   The key words "MUST", "MUST NOT", "SHOULD", "SHOULD NOT" and "MAY" in
   this document are to be interpreted as follows:

   MUST        An absolute requirement.  A block that violates a MUST is
               not a conforming block, and a reader is not required to do
               anything sensible with it.

   MUST NOT    An absolute prohibition.

   SHOULD      A recommendation.  There may exist valid reasons in
               particular circumstances to ignore it, but the full
               implications MUST be understood and weighed before doing so.

   SHOULD NOT  The same, in the negative.

   MAY         Truly optional.  An author may include the item or leave it
               out; a reader MUST be prepared for both.

   Note the asymmetry: violating a MUST is a bug, violating a SHOULD is a
   decision.  This distinction is the entire point of the vocabulary, and
   it is the reason a specification is worth reading at all.


3.  Terminology

   Block       One script element carrying a JSON array of questions.

   Question    One object of that array.

   Option      One element of a question's "a" array.

   Author      Whoever writes a lesson page.

   Reader      The code that turns a block into an interactive quiz.  On
               this site, the reader is initQuiz() and initQuizBilan(),
               which locate the block and parse it, together with
               buildQuiz(), which renders the parsed questions.  Note that
               the reference implementation locates the block by attribute
               alone: it does not check the type given in Section 4.

   Bilan block A block marked "data-quiz-bilan", scored as a whole at the
               end of a course.  It uses the format described here without
               any change.


4.  Block Syntax

   A block MUST be a script element whose type is "application/json" and
   which carries either the "data-quiz" or the "data-quiz-bilan"
   attribute.  Its content MUST be a JSON array.  Each element of that
   array MUST be a question object as defined in Section 5.

   A page MAY contain both kinds of block.  A page MAY contain no block at
   all.  Only the first block of each kind is read.

   The "data-quiz-bilan" attribute MAY carry a value.  If it is non-empty,
   the reader uses it as the heading of the generated section.  The value of
   "data-quiz", if any, has no meaning.


5.  Question Object

5.1.  The "q" Member

   Required.  MUST be a non-empty string.  It is displayed as written; the
   reader escapes it, so it MUST NOT contain markup intended to be
   rendered.

5.2.  The "a" Member

   Required.  MUST be an array of at least two strings.  Every option MUST
   be a non-empty string.

   The options MUST be distinct from one another.  Two identical options
   would be displayed as two identical buttons, only one of which would be
   accepted, which no learner can be expected to understand.

   A question SHOULD offer exactly four options.

5.3.  The "correct" Member

   The zero-based index of the correct option.  If present, it MUST be an
   integer, it MUST be greater than or equal to zero, and it MUST be less
   than the length of "a".

   It MAY be omitted.  A missing "correct" member means zero: the first
   option is the correct one.

5.4.  The "explain" Member

   Optional.  A string shown once the learner has answered.

   It SHOULD be present.  An answered question without an explanation
   teaches the score and nothing else.


6.  Display Order

   The reader MUST shuffle the options before displaying them, and it MUST
   do so independently for every question and every page load.

   It follows that an option MUST NOT refer to its own position, nor to
   the position of another option.  "All of the above", "none of the
   previous answers" and "answer B" are meaningless in a shuffled list:
   they were written against an order that the learner will not see.

   This requirement is checkable on the data alone, but its
   justification is not: it exists only because the reader shuffles.  Two
   other requirements of this document cannot be checked on the data at
   all -- the two MUSTs above, which bind the reader, and the prohibition of
   markup in Section 5.1, which turns on intent rather than on form.


7.  Authoring Recommendations

   A distractor SHOULD NOT be shorter than 70% or longer than 130% of the
   correct option.  A learner who has understood nothing can otherwise
   score well from the shape of the options alone: the question then
   measures reading habits rather than knowledge.  Equal lengths are of
   course allowed; the band constrains distance, not order.

   This recommendation does not apply when the correct option is shorter
   than 20 characters.  Below that length the band admits, for most
   lengths, a single integer value -- at three characters, from 2.1 to
   3.9 -- and Section 5.2 already requires the options to be distinct.
   Such questions offer code tokens, not sentences, and their options are
   held together by kind rather than by size.

   Across a whole course, the correct option SHOULD fall at each length
   rank about one time in four.  This is the only requirement in this
   document that cannot be checked on a single question: a block is not
   conforming or not with respect to it, a course is.  It is stated all
   the same, because the two recommendations above are worthless without
   it -- see the revision note.

      Revised 6 September 2026.  Until this revision, this section read
      "The correct option SHOULD NOT be strictly the longest of the four",
      and that single sentence was the whole of it.  It is withdrawn, and
      the rank recommendation above is what replaces it.  Measured on the
      doc course, which had been written to satisfy the old wording
      without exception: the correct option was strictly the longest in
      0 of its 64 questions, and it was the second longest in 39 of them,
      that is 60.9%.  The tell had not been removed; it had moved down
      one rank, where nothing was looking for it.

      How much of that is the old wording's doing was measured too, and
      it is less than it looks: on the 1835 questions of OTHER courses
      that already satisfied it, rank 1 stands at 38.4%, not at 60%.  The
      rule accounts for 13 of the 36 points of excess; the rest is a
      writing habit -- making the correct option ALMOST the longest --
      that no per-question rule reaches.  The lesson is not that the old
      wording was wrong to exist.  It is that a per-question rule was
      being asked to carry a property of a population, alone, and that a
      band on distance does not carry it either: 572 questions of this
      site satisfy the band and yet have the correct option as the
      longest, every single time.

   Distractors SHOULD be defensible.  An option that no one would ever
   pick reduces a four-option question to a three-option one.


8.  Conformance

   A block is conforming if, and only if, it satisfies the MUSTs of
   Section 4 and each of its questions satisfies those of Sections 5 and 6.

   The two MUSTs of Section 6 that bind the reader are deliberately outside
   this definition: a block cannot be held responsible for what the reader
   does with it.  They are stated here because the rest of Section 6 follows
   from them.

   A conforming block MAY violate any SHOULD.  Such a block is valid; it
   is merely worse.  Tools reporting on this format SHOULD report the two
   levels separately, because they call for different actions: a MUST
   failure is fixed, a SHOULD failure is discussed.


9.  Security Considerations

   Block content is authored, not user-supplied, and the reader escapes
   every string before insertion.  The threat model is therefore limited
   to a mistaken author rather than a hostile one.

   Scores are stored locally and are not transmitted anywhere.  They MUST
   NOT be treated as an assessment of anything by anyone but the learner.


10.  Known Limitations

   The format carries no notion of partial credit, of multiple correct
   options, or of a question whose answer depends on an earlier one.
   Adding any of these would be a breaking change for existing readers.

   The format has no version member.  A future revision would have to
   infer the version from the members present, which is exactly the kind
   of decision a specification is supposed to prevent.  This is a known
   defect, recorded here rather than hidden.

   Three behaviours of the reference implementation are worth knowing and
   are not required by this document.  An empty array is conforming and
   renders nothing.  Invalid JSON is ignored silently, with no message.  The
   order of the questions themselves is never shuffled -- only the options
   within each question are.
