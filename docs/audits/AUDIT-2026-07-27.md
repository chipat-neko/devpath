# Audit complet du site Syntaxe — 27 juillet 2026


76 cours · 1336 leçons · 1425 fichiers `lecon-NN.html` · 79 scripts · 5 CSS.
Six dimensions auditées puis contre-vérifiées. **Aucun constat n'a été réfuté sur le fond** ; plusieurs gravités ont été revues (à la baisse comme à la hausse) et 12 constats supplémentaires ont été rattrapés par la contre-vérification. Ce qui suit est dédupliqué et classé par gravité réelle **pour la personne qui lit le site**, pas par dimension.

## NIVEAU 1 — Pages réellement cassées dans le navigateur (à corriger en premier)

Une seule cause : **un `<` non échappé à l'intérieur d'un `<pre><code>`**. Le navigateur le lit comme du vrai HTML. 13 fichiers concernés, 4 gravement. Vérifié dans Chrome headless (`--dump-dom` + console) par les deux passes.

### 1.1 `pages/html/lecon-46.html` ligne 301 — la page ne charge plus aucun script
`// setHTMLUnsafe INTERPRÈTE le <template shadowrootmode> :` crée un vrai `<template>` jamais fermé. Dans le DOM rendu, `data.js`, `main.js` et `lecon.js` se retrouvent **à l'intérieur** du template (positions mesurées : template à l'octet 26254, les trois scripts à 31761/31816/31871) donc jamais exécutés. Console : « This element does not support attachShadow (301) ».
**Ce que ça casse :** 0 QCM (vs 29 sur la leçon témoin), 0 exercice (vs 30), 0 sommaire, 0 navigation précédent/suivant, 0 bouton Copier, 0 coloration, 0 progression enregistrée, pas de pied de page. C'est **la seule page du site où les moteurs JS ne tournent pas**.
**Correction :** ligne 301, écrire `&lt;template shadowrootmode&gt;`.

### 1.2 `pages/securite/lecon-04.html` lignes 111, 134, 152 — la leçon XSS exécute la charge d'attaque
Trois `<script>` bruts. Console reproduite : `Uncaught ReferenceError: volerLesCookies is not defined (111)` puis `Uncaught SyntaxError (134)`. Le script de la l.134 avale **12 584 caractères / 107 lignes** jusqu'à la l.241.
**Ce que ça casse :** 9 `h2` → 2, 9 `figure` → 3, 3 exercices → 0, QCM → 0. Et la page qui enseigne à ne pas laisser s'exécuter du code injecté… l'exécute.
**Correction :** `&lt;script&gt;` / `&lt;/script&gt;` aux trois lignes.

### 1.3 `pages/securite/lecon-02.html` ligne 189 — moitié de leçon avalée
`// "<script>" devient "&lt;script&gt;"` : le premier est brut, le second échappé. Le script court jusqu'au `</script>` de la l.238, **qui est la fermeture du bloc `data-quiz`** (5 809 caractères, 49 lignes).
**Ce que ça casse :** 8 `h2` → 4, 9 `figure` → 5, 3 exercices → 0, QCM → 0 ; l'antisèche et le glossaire réapparaissent en texte brut colorisé dans un bloc de code.
**Correction :** `// "&lt;script&gt;" devient "&amp;lt;script&amp;gt;"`.

### 1.4 `pages/securite/lecon-02.html` lignes 184-187 — la fonction de référence affichée est FAUSSE
*(rattrapé par la contre-vérification ; indépendant du 1.3 et survivrait à sa correction)*
(a) `.replace(/</g, "&lt;")` : le `</g` ouvre une balise fermante orpheline qui avale la suite de la ligne. (b) Les chaînes de remplacement sont écrites `"&lt;"` au lieu de `"&amp;lt;"`, donc le navigateur les décode. Texte réellement affiché à l'écran :
```
    .replace(/&/g, "&")
    .replace(//g, ">")
    .replace(/"/g, """);
```
**Ce que ça casse :** sur la leçon qui enseigne l'encodage de sortie, la fonction d'échappement de référence est un no-op, deux lignes sont fusionnées et une regex est vide. Le site sait pourtant double-échapper ailleurs (11 leçons le font, ex. `php/lecon-03.html:406`).
**Correction :** double-échapper les 4 chaînes de remplacement et écrire `/&lt;/g`. Même bug latent en `securite/lecon-04.html:138-139`, aujourd'hui masqué par 1.2.

### 1.5 `pages/clojure/lecon-11.html` ligne 142 — la fin de la leçon est absorbée dans un bloc de code
`;; ... et la récupérer ailleurs (<!!)` déclenche un *bogus comment*. Effet mesuré : 12 `h2` → 2, 11 `figure` → 3, 3 exercices → 0, QCM → 0, glossaire → 0.
**Nuance de mécanisme (le vérificateur corrige l'auditeur) :** le commentaire n'avale que 82 caractères et le `<pre>` est bien fermé ; la destruction vient de ce que `<code>` est un *active formatting element* reconstruit après `</figure>`, que Prism prend ensuite pour un bloc `language-clojure` et dont il réécrit l'`innerHTML`.
**Correction :** écrire `(&lt;!!)` — le reste de la leçon utilise déjà `&lt;!!`.

### 1.6 Huit fichiers où seul le contenu de l'exemple est perdu (pas la page)
Confirmés dans le DOM, gravité ramenée à **mineure** par la contre-vérification :
- `dart/lecon-13.html:293` → affiche `context.watch()` au lieu de `context.watch<Compteur>()`
- `js/lecon-52.html:403` → `"$"` au lieu de `"$<tag>"`
- `llm/lecon-08.html:172` → `"raison": ""` au lieu de `"raison": "<courte>"`
- `ux/lecon-11.html:169` → un vrai `<label>` est créé (5 `<label` pour 4 `</label>` dans le DOM)
- `wasm/lecon-11.html:255 et 261` → un vrai sélecteur de fichier et deux `<canvas>` apparaissent au milieu d'une arborescence de projet
- `markdown/lecon-05.html:183,185,186,189,191`, `lecon-03.html:133`, `lecon-02.html:190` → **7 commentaires `<!-- … -->` deviennent de vrais commentaires HTML** : les annotations qui expliquent chaque piège du Markdown sont invisibles (le paragraphe suivant les reformule, d'où la gravité mineure)
- `nosql/lecon-04.html:251` *(rattrapé)* → `SET cache:accueil "<html>...</html>"` : les deux balises disparaissent de l'exercice

**Correction commune :** échapper tous les `<` ouvrants. **Et écrire la règle noir sur blanc** (voir manque M2) : les 13 fichiers viennent de 9 cours différents, c'est une convention implicite jamais documentée.

## NIVEAU 2 — Défauts visibles par tout le monde, sur des milliers de pages

### 2.1 Double numérotation dans la barre latérale des 1336 leçons
`css/components.css:1277, 1311-1319` stylise `.coursenav`, mais le HTML pose `class="coursenav-panel"` (vérifié à l'instant : `pages/js/lecon-01.html:85`) et `js/lecon.js` n'émet jamais `class="coursenav"`. Sonde DOM : `.coursenav` → **0 élément**, `.coursenav-panel` → 1.
**Ce que ça casse :** `list-style:none` ne s'applique pas, donc chaque entrée du plan affiche **le marqueur natif « 1. 2. 3. » ET la pastille « 01 02 03 »** — et les deux se contredisent dès le module 02 (« 1. » face à « 04 »). Le panneau perd aussi son cadre, son fond `--surface` et son padding (mesurés à 0).
**Correction :** remplacer le préfixe `.coursenav ` par `.coursenav-panel ` aux lignes 1277, 1312, 1318 de components.css (ne touche aucun des 1336 fichiers HTML).
**Attention, effet de bord positif à connaître :** les règles `li[data-level]::marker` (1363/1370/1377) sont aujourd'hui **actives** (marqueur natif coloré, mesuré `markerColor rgb(30,127,79)`), contrairement à ce qu'affirmait la dimension « js ». Après correction elles deviendront inertes — la coloration de niveau reposera alors sur `.coursenav__num` et le filet latéral, déjà en place.

### 2.2 Menu principal : 23 variantes, 1346 pages de cours sur 1412 proposent un cours étranger
Le 3ᵉ élément du menu est un lien figé copié du gabarit : **1154 pages affichent « Cours JavaScript »**, y compris `pages/cobol/lecon-01.html:40`, `pages/ada/cours.html:39`, `pages/prolog/lecon-05.html:40`. Pire, il change **à l'intérieur d'un même cours** : api {JavaScript 12, HTTP 1, Sécurité 1, GraphQL 1}, securite {JavaScript 7, API REST 5, Observabilité 3}, sass {JavaScript 8, CSS 7}, solidity {JavaScript 13, Rust 5}, vue {JavaScript 14, React 1}.
**Ce que ça casse :** rien n'est mort (0 lien cassé), mais la navigation principale n'est plus un repère : un lecteur de Rust ou de Prolog voit en permanence « Cours JavaScript », et l'entrée change en passant d'une leçon à la suivante. À l'écran c'est le 4ᵉ item, `main.js:408-437` insérant « Fils rouges » avant.
**Correction :** supprimer cet élément du gabarit et le remplacer par un menu unique (Accueil · Catalogue · Fils rouges · Parcours · Projets · Ma progression · Recherche) construit dans `main.js` sur le modèle exact de `initFilsRougesNav()`. Si un raccourci vers le cours courant est souhaité, le générer depuis `document.body.dataset.course` (correct sur 1336/1336).

### 2.3 Fil d'Ariane périmé sur les 89 leçons rapatriées par la fusion
`pages/js/lecon-43.html` : ligne 6 `<title>… Leçon 43`, ligne 76 `kicker … Leçon 43`, mais **ligne 61 `<li aria-current="page">Leçon 01</li>`**. Contrôle exhaustif : 89 pages exactement — js/lecon-43..65 (23), python/lecon-29..50 (22), html/lecon-26..47 (22), css/lecon-26..47 (22). Rien ne le corrige à l'exécution (le mot « breadcrumb » n'apparaît nulle part dans `lecon.js`).
**Ce que ça casse :** sur toute la moitié experte des 4 cours vitrines, l'onglet, l'en-tête, la barre latérale et l'URL disent « Leçon 43 » pendant que le fil d'Ariane dit « Leçon 01 ».
**Correction :** réécrire le dernier `<li>` de ces 89 fichiers avec le numéro réel ; plus robuste, le faire générer par `lecon.js` depuis `flat[currentIndex].lesson.num`.

### 2.4 Le site n'est pas hors ligne : 8440 requêtes réseau, dont Prism
Sur les 1475 pages réelles : 24 602 références de ressources, **0 locale cassée**, mais 8440 externes réparties sur 3 hôtes — cdnjs.cloudflare.com 4014, fonts.googleapis.com 2951, fonts.gstatic.com 1475 (5,7 requêtes par page). Aucun repli local : ni `assets/vendor/`, ni `@font-face`, ni fichier `.woff2` dans le dépôt.
**Ce que ça casse :** en `file://` sans connexion — le mode d'usage annoncé — **aucun bloc de code n'est coloré nulle part** (`grep -c 'class="token' pages/js/lecon-01.html` = 0 : rien n'est pré-rendu, les 55 lignes de thème `.token.*` sont totalement inertes). Les polices retombent proprement sur le système.
**Aggravant :** même en ligne, **137 pages** chargent Prism sans la grammaire du langage utilisé (155 couples manquants : bash 124, json 8, c 7, toml 5…), donc des blocs gris à côté de blocs colorés dans une même leçon (ex. `pages/js/lecon-37.html`).
**Nuance honnête :** `assets/fonts/README.md` documente explicitement le choix du CDN Google Fonts et le repli système comme un compromis assumé. Les polices sont donc un manque documenté ; **seul Prism est une régression non documentée**.
**Correction :** déposer prism-core + les grammaires réellement utilisées dans `assets/vendor/prism/`, pointer les `<script>` en relatif, et régénérer la liste des composants page par page à partir des classes `language-*` présentes.

### 2.5 Mobile : le site défile horizontalement sur une leçon sur trois
Mesures Chrome headless, iframe à largeur exacte :
- **En-tête, 320 px :** `scrollWidth` 352 sur *toutes* les pages (+32). Coupables : `.header-actions` (148 px, `margin-left:auto`) et `.brand` (`white-space:nowrap`), tous deux incompressibles. Débordements : index +32, lecon-01 +81, progression +122.
- **Leçons, 390 px :** 24 des 76 leçons testées débordent (32 %), moyenne +124 px, **max +457 px** (`pages/c/lecon-01.html`). Cause **prouvée par contrefactuel** : injecter `:not(pre) > code { white-space: normal; overflow-wrap: anywhere }` corrige 8 pages sur 10 en direct (python 505→390, c 847→390, ruby 676→390…). Origine : `base.css:164-172` (`white-space: nowrap`) combiné à `.callout { grid-template-columns: auto 1fr }` (`components.css:1070-1072`), dont la piste `1fr` a un minimum au min-content.
- **Catalogue, 390 px :** +140 px (`scrollWidth` 530), et la barre étant `sticky` elle reste décalée pendant tout le défilement. `pages.css:827` n'a pas de `grid-template-columns` ; le garde-fou `width:100%` de la ligne 929 est inopérant (largeur calculée : 481,5 px).
- **23 pages de premier niveau sur 63 débordent à 390 px** *(rattrapé)*, dont **les 13 pages « fil rouge »** : fil-rouge-frontpro +255, fil-rouge-fiabilite +216, fil-rouge-scripting +200, revision +138, examen +104, glossaire +79… Même erreur qu'au catalogue : `pages.css:2149-2152` passe `.projets-layout` en `1fr` sans `minmax(0,1fr)`, l'aside `.projets-list` reste à 548 px.

**Corrections :** (a) `base.css:171` → `overflow-wrap: anywhere` ; (b) `components.css:1072` et `pages.css:2150` → `minmax(0, 1fr)` ; (c) `pages.css:827` → `grid-template-columns: minmax(0, 1fr)` ; (d) un palier `@media (max-width: 400px)` réduisant le padding du `.container` et masquant le libellé de `.brand`.

### 2.6 Bouton hamburger réduit à 14 px, icône à 0 px sous 375 px
`.nav-toggle` (`layout.css:119-129`) est un enfant flex sans `flex: none` : 320/360/375 px → bouton **14×44**, svg **0×22** (donc rien de peint) ; 390 → 28×44 ; 412 → 44×44. Concerne tous les iPhone SE/mini et les Galaxy à 360 px.
**Correction du diagnostic :** l'affirmation « la navigation devient inatteignable » est **fausse** — `elementFromPoint` au centre retourne bien le bouton et `click()` ouvre le menu. Il reste un rectangle vide de 14 px, échec WCAG 2.5.8 (cible 24×24) mais pas un blocage.
**Correction :** `flex: none` (ou `min-width:44px; flex-shrink:0`) sur `.nav-toggle`, et par cohérence sur `.theme-toggle`, `.lang-toggle`, `.accent-toggle`.

### 2.7 Deux pages n'ont aucun bouton de menu : `imprimer.html` et `certificat.html` *(rattrapé)*
Ces 2 pages sur 1475 ont un `<nav class="primary-nav">` mais **pas de `data-nav-toggle`**. Or `layout.css:144-170` met la nav en `position:fixed; opacity:0; pointer-events:none` sous 860 px, et seule `.is-open` la révèle — classe posée uniquement par `main.js:44-47`, qui sort immédiatement s'il n'y a pas de bouton (`if (!toggle || !nav) return;`).
**Ce que ça casse :** sur mobile, **aucun lien de menu n'est atteignable** sur ces deux pages. Aggravant : `imprimer.html` est aussi la seule page du site sans `<footer class="site-footer">` — il ne reste que le logo pour en sortir.
**Correction :** ajouter le `<button class="nav-toggle" data-nav-toggle>` du gabarit standard dans les deux en-têtes, et le pied de page à `imprimer.html`.

## Verdict global

**Le contenu est solide, l'outillage ne l'est pas.**

Ce qui est sain, mesuré et sans réserve : le noyau de données (`data.js` — 76 cours × 3 tables parfaitement alignées, 1336 leçons annoncées = déclarées = présentes sur le disque, 0 trou, 0 orphelin, 0 doublon) ; l'intégrité des liens (15 387 liens, 24 695 références de ressources, **0 cible relative cassée, 0 ancre morte, 0 erreur de casse**) ; les 93 redirections (toutes valides, sans chaîne ni doublon) ; la structure HTML (0 BOM, 0 doctype manquant, 2744/2744 blocs JSON valides, 0 id dupliqué, 0 saut de niveau de titre, 18 409 SVG appariés) ; les 79 scripts (79/79 passent `node --check`) ; le thème sombre (1 seul défaut de contraste sur 1775 nœuds) ; et la couverture pédagogique par leçon (glossaire 1336/1336, schéma 1336/1336, antisèche 1335/1336, QCM 1334/1336, exercices 1332/1336, capstone et projet 76/76). La fusion des 4 cours en 3 niveaux est **correcte sur les données** : niveaux monotones, redirections 1:1, aucun fichier perdu.

Ce qui ne va pas se répartit en trois familles, et **aucune n'est un accident isolé** :
1. **Quatre pages sont réellement détruites** dans le navigateur, dont deux sur le cours Sécurité, à cause d'une convention d'écriture jamais documentée que le vérificateur maison est structurellement incapable de contrôler.
2. **Les index dérivés ont décroché du contenu** — 15 cours totalement invisibles pour l'examen, la révision et le glossaire, 27,8 % des questions absentes de la banque, 95,6 % des termes absents du glossaire général, 20 leçons HTML introuvables par la recherche — parce qu'**aucun générateur rejouable n'existe**.
3. **Le chantier de fusion a laissé six séquelles** visibles : fil d'Ariane périmé sur 89 pages, progression `localStorage` perdue sans migration, filtre « Avancé » qui n'atteint plus 89 leçons expert, 4 QCM bilan mal placés, coloration de niveau portée par la couleur seule et sous le seuil de contraste, `.coursenav` qui ne cible rien.

Aucune de ces trois familles n'aurait survécu à un script de vérification de quelques dizaines de lignes. Le site a dépassé la taille où l'on peut le maintenir à la main : c'est le seul vrai problème structurel, tout le reste en découle.
